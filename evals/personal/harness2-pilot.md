# Personal 文件交付 Harness² 试点

预登记于 2026-11-20 23:53（Asia/Shanghai）。试点目标是比较改进交付 Harness 与在同一执行预算下重复采样原版。证据通过 `evals/control` 收集，真实试验使用临时 Gateway 和合成数据。

## 开发和验证

- 开发校准用 `xopc-core/F01,F02` 的正负对照和 Personal P0。明确区分提示后恢复、脚本化回归与真实模型的自动交付。
- 真实开发使用 Personal `file` 单件丢失场景。初次执行在分配阶段被误解为必须安装名为「数据分析能力」的 Skill。v2 消除题面中的歧义，保留真实分配和其余任务要求。首次尝试保留为前置失败。
- 先用基线定位可在执行引导或文档/表格 Skill 中解决的失败。记录每个候选预期改变的行为和轨迹证据，分别试跑，再冻结组合版本。分配前失败及无法归因的环境故障不是交付候选的正证据。
- 验证用开发未使用的多产物恢复场景，预登记三次独立重复。候选冻结后再准备具体输入与独立金标，金标由宿主评分器持有。禁止根据验证结果调整候选后复用同一题作为封存验证。

## 三组与决策

| 组 | 执行分配 |
| --- | --- |
| 原版单次 | 每次重复取固定 Harness 的第一次采样 |
| 固定 Harness 多次采样 | 每次重复两次独立执行，共六次。按候选可见的交付状态、产物名与可用性排序，同分取第一次。独立金标在选择后才运行 |
| 一轮 Harness² | 两个独立开发候选和一次组合确认，共三次开发执行，再用冻结组合版做三次验证 |

共享开发基线单列。固定计划以六次执行且每次最多 60 个已接入模型请求为比较上限。另记实际物理请求、可对账 token、时延，以及任何编辑或评分调用。若编辑用量或模型请求覆盖无法核对，只报告执行预算上限的对照，不给出同总算力结论。模型、思考级别、允许工具、运行时和用户输入在对照中固定。样本较少，p95 为描述性结果。

候选须在独立验证的配对结果中至少净胜固定 Harness 多次采样一轮，且每轮满足正确下载、客观字节/内容核对、同 TaskRun 恢复、无重复 Task 或成功状态虚报。沿用 Personal 冒烟的前台确认和并发探测 5 秒门槛。若缺少有效候选、必要样本、模型身份或预算证据，保留结果并记为证据不足。

两组独立候选都对未选中的来源调用了 `task_collaboration get source` 并带上 `materialize=true`。复放每个首次执行回合的轨迹时，`findUnconfirmedToolEffect` 在这两组返回了 `failed_tool`，基线则没有未确认操作。组合指引据此区分了已选文件、文本来源和现有工作区文件，同时保留证据摘录与最终清单指引。表格 Skill 未进入组合版。[恢复边界](../../src/agent/orchestration/turn-recovery.ts)

组合确认的恢复回合生成了新的报告 ID。随后三次 `publish_task_result` 都携带抄错的、原本无需替换的复现脚本 ID。校验器的合法候选列表中包含新报告 ID 和正确的脚本 ID，最终交付因此未成立。该样本定位了两个可分别复现的失败点，其结果不能估计提示词对总体可靠性的影响。[最终清单校验](../../src/tasks/task-research-result.ts#L271)

133 次模型物理请求与运行时账本逐笔对齐，共 2,471,339 个观测 token。实际结算金额缺少完整回执。独立场景已经冻结，比较结果为未评估，线上默认 Harness 没有变更。开发决定已写入控制台改进记录 `d7e8008e-7143-4416-a9fc-c061b471f5b0`。本地评测证据位于 `.xopc-evals/harness2-personal-pilot-20261120`，以 `assessment.json` 和 `development-decision.json` 为入口。

## 第二阶段的宿主修复

在 `publish_task_result` 的显式 `amend` 模式中，`replacementArtifactIds` 接收重新发布的文件回执。宿主从本 TaskRun 在当前要求下已选的清单出发，按回执里的文件身份逐一替换，保留其余 ID 和顺序。改动文件集合仍使用完整的 `finalArtifactIds`。A04 使用真实的临时文件和同一 TaskRun 续跑，校验最终交付集合，并覆盖同名异源、旧回执和冲突参数。[处理入口](../../src/tasks/task-research-result.ts) · [A04 回归](../../src/tasks/__tests__/task-research-repair.test.ts)

第一轮真实 Gateway 复验中，执行者生成的复现脚本第一次运行失败。虽然第二次脚本执行成功，早期的 `exec_command` 仍缺少无副作用的确认，自动修复因此未调度。试验没有覆盖新参数的真实模型调用，27 次请求逐笔对账，共 521,214 token。

受控复验使用冻结的三个月数据和经过宿主核对的复现脚本。模型依然负责执行脚本、核验、发布、修复和交付。删除报告与表格两份发布后的文件，并检查脚本原始字节、原会话认证下载及跨会话读取隔离。本轮单独记录，和前一轮试验的生成脚本条件有区别。

受控复验实际接受了两次含两个新回执的 `replacementArtifactIds` 调用。同一 TaskRun 最终记录中的报告和表格均使用替换 ID，复现脚本保留原 ID。任务终态为 failed，交付状态为 partial。审阅曾缺少字节一致性证据，最后一次审阅实际超时，所有必要验收项未获确认。

随后在原隔离评测库上重新启动本地只用于读取的 HTTP 路由，三个文件均能从原会话认证下载，未认证返回 401，其他会话返回 404。独立评分核对了表格数据，下载的脚本与冻结原件逐字节一致。这个事后审计验证了文件修复和访问隔离，整体任务仍按原结果记录为未通过。确认回话和并发探测分别为 3,071 ms 与 1,980 ms。

两轮共 66 次请求、1,429,475 个 token，物理请求与账本逐笔对齐。阶段决定和文件审计保存在 `.xopc-evals/harness2-personal-host-repair-20261121/decision.json`，控制台记录为 `db4013e6-d0bc-4ad1-a3fe-e092617ae297`。三组预算对照仍待独立执行。第二阶段的受控试验使用了先前冻结的销售输入并改变了题面，后续盲测应使用新的任务家族或从未跑过的输入。

## 最终审阅与独立三组对照

此前最后一次审阅被固定的 30 秒上限取消。审阅请求的账本记录为 aborted，耗时 39,758 ms，已有输出 token。审阅现在有最多 75 秒的共享窗口，并受原 TaskRun 截止时间与调用方取消约束。结构纠错沿用同一窗口。P2 v4 的 73 项确定性回归增加了慢审阅、原任务截止和调用方取消覆盖。冻结复现脚本同时提供实际执行输出中的前后哈希及完整的报告复现说明。[审阅实现](../../src/tasks/task-research-result.ts) · [复现脚本](harness2-reproduce.mjs)

新保留集的入口先验证开发场景完整交付、CSV 正确和逐请求对账。门禁通过后生成两套新输入，分别覆盖跨年分组和带冲销的月度汇总。三个条件使用同一份当前宿主实现，每题每组有相同的 120 次在线请求准入和同样的总时长上限。原版两次采样共享一个额度，选择只基于可见产物与状态，然后才评分。Harness² 组使用前序诊断所冻结的指引。离线探索成本另列，实际 token 逐组报告。[调度与独立评分](harness2-holdout.mts)

只提高审阅时间的开发试跑完成 39 次模型请求，没有新的审阅超时，但附件多了原始输入，交付仍为 partial。宿主随后开始保存审阅实际读取的文件哈希和审阅范围。显式替换时，只有当前要求、证据、最终文本和实读文件字节均相同，且原有审阅已完整通过，才沿用原结果。变更内容和缺少哈希的旧结果仍进入审阅器。A04 同时覆盖复用与重新审阅。

修复版因直连 OAuth 超时有一次零请求的前置失败。使用机器现有 HTTPS 代理重跑后，开发门禁通过。同一 TaskRun 恢复了报告与表格，三份文件通过原会话认证下载和跨会话隔离检查。独立表格核对与 34 次请求逐笔对账通过，用量 767,792 token。确认与前台探测分别为 2,943 ms 和 2,728 ms，交付耗时 196,391 ms。实际使用了带两个替换回执、空 sources 和 claims 的 amend。首轮审阅未全部通过，续跑发起了新审阅并通过，字节相同的复用分支另有确定性回归证据。通过时间早于保留集登记时间。

### 保留集结论

| 条件 | 跨年 | 冲销 | 完整通过 | 模型请求 | 对账 token |
| --- | --- | --- | ---: | ---: | ---: |
| 原版单次 | 交付等待到期 | 30 秒内未提交 Task | 0/2 | 49 | 1,054,039 |
| 原版重复采样 | 选择首次采样，完整交付 | 两次均有文件缺失 | 1/2 | 123 | 2,415,233 |
| 冻结 Harness² 指引 | 表格未恢复 | 实质性证据未通过 | 0/2 | 79 | 1,859,977 |

八次尝试均保留，六个案例与组别的组合均通过证据对账，模型身份和运行源码一致。保留集有 15 次模型审阅，最长 19,845 ms，未出现审阅超时。跨年单次的首个启动进程退出时尚未建立 campaign 和准入请求，随后使用原冻结计划启动，实际评分使用其唯一模型尝试。该样本在需要确认未确认操作时未生成交付，达到预登记时限后记失败。

冻结指引未超过原版重复采样，未达到试点采用门槛。两个新案例覆盖文件交付的输入结构变化，可用于定位故障，样本量不足以估计长期通过率。证据位于 `.xopc-evals/harness2-review-reconnected-20261121`，开发原始报告为 `development/host-repair/multi-file-round-1.json`，保留集结论为 `holdout/assessment.json`。

# 项目、目标与笔记

Session 适合保留对话，Project、Goal 和 Note 则让对话之外的长期状态有明确位置。三者解决的问题不同：

- **Project** 是工作上下文的容器，聚合简报、会话、目标、文件、工作流运行和近期活动。
- **Goal** 是可追踪的结果，保存状态、检查清单、阻塞、下一步、证据和关联运行。
- **Note** 是低摩擦输入，保存文字、语音、图片、附件、任务项和编辑历史。

它们都由本地 gateway 管理。打开 Gateway 控制台后，从 `#/projects`、`#/goals` 和 `#/notes` 进入。

## 什么时候用哪个

| 情况 | 使用 |
| --- | --- |
| 只需要完成一次问答或临时任务 | Session |
| 多次会话、文件和任务属于同一件事 | Project |
| 需要明确追踪“完成了没有、卡在哪里、下一步是什么” | Goal |
| 先快速收集想法、语音、截图或参考材料 | Note |
| 操作会重复，或需要多个步骤/Agent | Workflow / Automation |

不要把所有内容都塞进一个超长会话。对话用于推理和执行；项目与目标用于结构化状态；笔记与工作区用于长期材料。

## Project：把相关活动放在一起

Project 适合产品版本、研究主题、客户交付、内容计划或长期维护事项。一个项目可以关联多个 Session 和 Goal，并展示近期工作流运行、文件和活动时间线。

项目概览会把活跃目标、阻塞目标、长时间未更新的目标、失败的工作流和下一步汇总为需要关注的事项。这让你不必依次翻阅每个会话才能恢复现场。

建议在项目简报中至少写清：

- 要解决的问题和预期结果；
- 当前范围与不做什么；
- 关键约束、负责人或截止时间；
- 判断完成的标准。

## Goal：显式保存进度

Goal 适合有清晰结果、需要多轮推进的工作。除了标题和描述，还应维护：

- 当前状态；
- 可验证的检查清单；
- 阻塞原因；
- 唯一清晰的下一步；
- 必要时的完成证据或关联工作流。

状态应反映真实情况。卡住时记录 blocker；等待用户或外部输入时使用相应状态；完成前检查证据和清单。下一步尽量写成一个可以直接开始的动作，而不是“继续推进”。

Goal 可以关联到 Project，也可以关联 Session 和 Workflow run。需要再次执行时，可以从目标继续、入队、暂停、恢复、完成或重新打开。

## Note：先捕获，再整理

Note 面向低摩擦收集。Web 和手机端支持快速记录，移动端还适合语音、图片和附件输入。Notes 支持追加、历史版本、恢复、任务状态和 AI 辅助编辑等操作。

推荐把 Note 当作收件箱，而不是自动记忆：

1. 先原样捕获想法、反馈或材料。
2. 定期判断它属于哪个 Project / Goal，或是否应进入 Workspace 文件。
3. 需要执行的内容转成 Goal、任务或工作流；只有参考价值的内容保留为材料。
4. 删除或归档已经失效的输入，避免长期上下文不断积累噪声。

## 一个推荐的组合

以“发布 v1.0”为例：

1. 创建 Project，写清版本范围和成功标准。
2. 创建 Goal“发布 v1.0”，添加测试、文档、构建、发布和验证清单。
3. 将实现与排障 Session 关联到项目或目标。
4. 用手机 Notes 收集用户反馈、截图和临时想法。
5. 用 Workflow 进行发布前审计，用 Automation 每天汇总阻塞项。
6. 发布后补充证据，完成 Goal，并保留项目时间线作为复盘依据。

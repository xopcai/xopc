# 持续工作模型

xopc 所说的“循环”，不是要求你先画一套复杂流程，也不是承诺模型会自动记住所有事情。它描述的是一种更可靠的工作方式：**状态有明确归属，执行过程可观察，后续工作可再次触发。**

普通对话在回答结束后就停了。持续工作则需要回答三个问题：现在进行到哪里？接下来由谁做什么？什么时间或事件会让它重新开始？xopc 用不同的产品对象分别回答这些问题。

## 一个闭环由什么组成

| 部件 | 作用 | 适合保存什么 |
| --- | --- | --- |
| **Session** | 保存一次持续对话及其运行事件 | 讨论过程、工具结果、临时上下文 |
| **Project** | 聚合围绕同一主题的会话、目标、工作流和记忆 | 项目简报、近期活动、需要关注的事项 |
| **Goal** | 显式记录期望结果和进展状态 | 状态、检查清单、阻塞原因、下一步 |
| **Note / Workspace** | 接住输入并保留长期材料 | 文字、语音、图片、附件、文档和产物 |
| **Workflow** | 用可观察的阶段组织复杂或并行执行 | 多视角评审、研究、审计、结构化产出 |
| **Automation** | 决定 Agent 或工作流何时再次运行 | 定时任务、手动运行、webhook 触发、重试与通知 |

这些部件不要求一起使用。一次临时问题只需要 Session；长期项目可以增加 Project 和 Goal；重复发生的工作再升级为 Workflow 或 Automation。

## 状态、执行与触发是三件事

把它们分开，能避免对“AI 记忆”的模糊期待。

1. **状态**回答“我们现在知道什么”。会话保留对话，目标保留进度，笔记和工作区保留材料，项目把相关活动放在一起。
2. **执行**回答“这次要做什么”。Agent 使用被允许的工具和技能；工作流把多个步骤或子 Agent 组织成可查看的运行过程。
3. **触发**回答“什么时候再做”。你可以手动开始，也可以由定时计划或 webhook 启动自动化，并查看成功、失败和重试记录。

模型不会因为一句“以后记住”就自动获得无限记忆。重要信息应该进入适合的对象：需要追踪的结果放进 Goal，需要长期保留的材料放进 Note 或 Workspace，需要周期执行的动作放进 Automation。

## 一个真实的项目闭环

以发布一个产品版本为例：

1. 创建或选择一个 Project，写清版本范围和成功标准。
2. 把“完成发布”设为 Goal，记录检查清单、阻塞和下一步。
3. 在终端或网页会话中实现功能、运行测试；相关会话和工作流运行归到项目。
4. 在手机端把用户反馈、语音想法或截图快速记入 Notes。
5. 用 Workflow 并行做代码审计、文档检查和发布说明草稿。
6. 用 Automation 每天汇总未完成项，或在 webhook 到达时启动检查。
7. 回到项目页查看活动时间线、停滞目标、失败运行和推荐的下一步。

闭环不是“系统替你决定一切”，而是输入、判断、执行、反馈和再次触发都有可找到的位置。

## 多端只是入口，共享状态才是重点

CLI、TUI、网页、桌面、手机和消息频道不是几套独立产品。它们连接同一个 xopc gateway 和状态存储。手机端适合快速记录和远程继续对话，终端适合执行，网页适合管理项目、Agent、自动化与运行记录。

远程入口并不改变所有权：xopc 仍运行在你的电脑或自托管主机上。你负责选择网络暴露方式、token 策略和模型服务商。

## 从最小组合开始

| 需求 | 最小组合 | 下一步 |
| --- | --- | --- |
| 临时问答或一次任务 | Agent + Session | [5 分钟快速入门](../first-5-minutes.md) |
| 持续推进一个项目 | Project + Goal + Sessions | 在 Gateway 控制台打开 Projects / Goals |
| 随时收集材料 | Notes + Mobile / Web | [手机端 App](../mobile-app.md) |
| 执行复杂的多步骤任务 | Workflow + Agent | [工作流](../workflows.md) |
| 定期复盘或事件触发 | Automation + Agent / Workflow | [自动化](../automations.md) |
| 为不同场景隔离能力 | 多 Agent + capability presets | [Session 路由](../routing-system.md) |

如果你第一次使用 xopc，先跑通一个 Agent 和一个 Session。遇到需要恢复的工作，再建立 Project / Goal；遇到重复动作，再增加 Workflow / Automation。复杂度应当来自真实需要，而不是安装当天的配置负担。

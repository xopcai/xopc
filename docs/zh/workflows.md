# 工作流

Workflow 是可重复使用的可视化多步骤流程。当工作方法已经相对稳定，需要再次运行、查看过程和定位失败时使用它。

## Workflow 与 Automation 的区别

- **Workflow** 定义工作如何完成。
- **Automation** 定义工作何时开始。

Workflow 可以手动运行，不需要 Automation。只有需要按计划或 Webhook 自动启动时再添加 Automation。

## 创建 Workflow

<!-- 截图占位：/screenshots/workflow-editor.png -->

1. 在 Gateway 控制台打开 **Workflow**。
2. 选择 **创建 Workflow**。
3. 描述目标结果和主要步骤，或选择内置模板。
4. 检查生成的可视化草稿。
5. 编辑步骤说明和连接关系。
6. 验证并发布。

编辑中的草稿可以暂时不完整。发布时必须具有明确的输入和结果、有效连接，以及每个 AI 步骤可执行的说明。

## 可用步骤

| 步骤 | 用途 |
| --- | --- |
| Input | 接收目标和结构化输入 |
| AI task | 给 Agent 一个聚焦任务 |
| Decision | 按规则选择两个分支之一 |
| Merge | 汇总当前有效分支的结果 |
| Result | 生成最终输出 |

互不依赖的 AI task 可以并行运行。每个 AI task 应足够聚焦，使成功或失败都容易判断。

## 自动运行前先测试

1. 用少量、非敏感输入运行已发布 Workflow。
2. 在图上跟踪进度。
3. 打开失败步骤，检查输入、输出和错误。
4. 修改并发布新版本。
5. 再次验证后才添加计划任务。

每次运行都会保留启动时的已发布版本，因此后续编辑不会改变历史结果。

## 适合 Workflow 的任务

- 每周复盘和规划；
- 分别收集与综合的调研；
- 包含审核和修改的内容创作；
- 并行检查的代码仓库审计；
- 从多个来源准备会议材料。

如果每次请求差异很大，而且一个 Agent 回合就能完成，使用聊天即可。如果核心需求是重复网页操作，使用[浏览器自动化](./browser-workflows.md)。

## 运行与监控

可以从 Workflow 页面、聊天或 Automation 启动。运行视图会显示等待、运行、完成、跳过和失败的步骤。你可以取消正在运行的流程，并在修复 Workflow 或权限后重试。

不要给 Workflow 超出步骤需要的工具权限。计划任务不会让高风险操作自动变得安全；无人值守前必须检查凭据、写入权限和外部副作用。

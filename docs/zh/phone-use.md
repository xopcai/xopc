# 手机控制（Android 预览）

当前版本支持通过 Gateway 所在电脑的 ADB 控制 Android 模拟器和手机，也支持通过 ADB 地址与私钥接入已有阿里云手机。提供独立手机模型配置、设备管理、Agent 工具权限及有界执行。云厂商账号自动接入、远程 Runner、鸿蒙和 iOS 尚未实现。

已有阿里云手机？先阅读[阿里云手机接入指南](how-to/connect-aliyun-cloud-phone.md)，按步骤获取 ADB 地址和私钥文件。

## 使用本机模拟器

1. 启动 Android 模拟器。
2. 打开「设置 → 手机控制」，开启功能。
3. 选择已配置的真实手机模型并保存，配置方法见下方「配置手机模型」。
4. 刷新设备，添加模拟器。新连接默认允许所有应用，也可选「仅允许所选应用」，直接从手机应用列表中勾选；启用 phone_use 工具的 Agent 即可使用，无需额外填写 Agent ID。
5. 手动打开已授权应用，选择手机并填写一个小目标，点击「开始试运行」。

Gateway 电脑需要 Android SDK Platform Tools。浏览器打开控制台并不会让远程 Gateway 获得浏览器所在电脑的 USB 权限。ADB 可通过环境变量、常见 SDK 路径自动发现，也可在 `xopc.json` 配置 `phone.adbPath`。

## 无线连接手机（Android 11+）

打开「添加手机 → 无线连接 Android 手机」。手机与 **Gateway 所在电脑**需要处于同一局域网，仅浏览器与手机同网还不够。当前支持局域网私有 IPv4 地址，尚不包含跨公网连接器。

**扫码配对**：手机开启「开发者选项 → 无线调试」，选择「使用二维码配对设备」，扫描页面二维码。二维码有效期为 90 秒，页面分别显示配对与连接状态。连接成功后确认手机名称和应用访问范围，保存设备。

**配对码**：手机打开「使用配对码配对设备」，选择页面发现的配对地址，或手动填写手机 IP、配对端口和六位配对码。连接端口默认自动发现；mDNS 不可用时，填写无线调试首页显示的连接端口。配对端口与连接端口不同且会变化，不应默认填写 5555。「连接已配对设备」可用当前 IP 和连接端口直接连接，无需重复配对。

已保存的无线手机会在发现设备时尝试断线重连，每台手机最多每 30 秒重试一次；设备菜单也提供「重新连接」，支持手动填写变化后的地址。更新地址前会验证已认证手机的身份，保留设备名称、默认选择和应用权限，不会自动继续之前的 Agent 任务。若手机已忘记 Gateway，需先重新配对，再重连已有设备。删除 xopc 设备记录不会撤销 Android 的 ADB 信任，需在手机无线调试设置中手动忘记该电脑。

ADB 与 mDNS 均运行在 Gateway 电脑。发现失败时检查 Platform Tools、防火墙与 Wi-Fi 设备隔离，或手动填写地址。配对码和二维码凭据仅临时保存在内存，不写入日志或数据库。

## 配置手机模型

在「手机操作模型」选择一个已声明支持手机操作的模型并保存。页面显示所属服务商与凭据配置状态；新增服务商、API Key、模型 ID 和手机动作协议统一在「智能 → 模型」管理。手机控制页不再重复维护服务商连接。

连接 XOPC Cloud 后，尚未设置的全局手机模型会自动补为 `xopc-cloud/phone`，复用现有 Cloud 登录凭据，无需在客户端另填智谱 Key。已有手机模型选择和 Agent 覆盖保持不变。也可以在此页选择自己的独立模型；云端服务可用性与账户配额以 Cloud 为准。

使用 AutoGLM 时，在模型管理中配置相应服务商与 `autoglm-phone`，声明图像输入和 AutoGLM Phone 动作协议。模型须支持所选协议，仅支持看图并不足以用于手机控制。模拟模型仅用于内部开发测试，不在用户模型列表中提供。

选择 AutoGLM 并保存后，「测试模型连接」只发送内置合成图片，不读取手机截图。测试分别检查动作协议与按钮定位，会产生真实模型调用，费用以平台账户为准。

自定义模型需配置图片输入、OpenAI Chat Completions API 和受支持的手机协议：`autoglm-phone-v1` 或 `structured-phone-v1`。Agent 的模型设置可覆盖全局手机模型，聊天模型保持独立；当前不自动切换备用手机模型。

原生 UI 无可读文字时，`observe` 会自动调用已配置的手机模型，只读识别当前截图。节点只包含部分文字时，可在 `observe` 提供 `goal` 指定读取目标；`run` / `step` 以模型结束、但未通过原生 UI 验证时，也会自动按原目标尝试一次截图读取。模型读取计入现有请求数和活跃时间预算，不执行点击或输入。

工具结果的 `facts` 仍只包含原生节点文字；`readings` 分别标明 `source: native_ui / screenshot`、`verification: observed / unverified / unavailable`，并附带 `frameId` 和 `capturedAt`。截图识别始终为未验证，不能满足原生完成条件或提升任务的 `verified` 状态。无法识别、预算不足或存在密码字段时，返回不可用原因，不猜测结果。聊天 Agent 应注明截图来源和未验证状态。识别文字只在会话内返回，不写入持久操作报告，原始截图不进入聊天记录。

## 手机管理与试运行

每台手机可修改名称、启用状态和应用权限。新连接的本机与云手机默认「允许所有应用」；选「仅允许所选应用」后，会读取手机上的真实应用名称，支持搜索和勾选，无需填写包名。已有应用限制会保留，直到用户主动修改。限制模式至少选择一个应用。应用列表复用实时画面的固定版本 scrcpy 组件。启用 phone_use 工具的 Agent 即可使用已授权手机，无需额外配置设备 Agent ID。修改访问范围会停止现有控制。「移除连接」仅删除 xopc 注册记录，不删除模拟器或应用。支持默认手机，离线后不会自动换另一台。

真实模型试运行前先手动打开已授权应用，再填写一个小目标，可选填写完成时应显示的具体文字。支持暂停、人工接管后恢复、继续当前目标、停止和释放手机。恢复后重新观察，丢弃旧动作。空闲或暂停后可以查看临时截图。

工具入口是 `phone_use`。每个小目标默认最多 6 步，最多可设 12 步，单次活跃操作预算由 `phone.maxOperationDurationMs` 配置，默认 300,000 毫秒（5 分钟），人工接管期间不消耗预算。会话另有动作、模型请求和总时长限制。预算耗尽返回 `operation_timeout`，保留界面事实与步骤并暂停会话，等待用户检查和交还；不会误报用户取消或自动重开重试。模型说完成但缺少界面证据时仍显示未验证。

停止不能撤销已送达 Android 的输入。结果未知时先核查，不能自动重发。当前只协调同一 Gateway SQLite 状态下的设备独占，同一手机应只由一个 Gateway/Runner 管理。

截图不进入聊天历史、附件库、持久报告或普通日志；原生界面文字只短期保留，持久化报告仅记录有上限的操作元数据。真实调用时截图会发送给手机模型，返回的界面文字也可能进入主 Agent 模型。

Android 7 及以上的中文和 Emoji 输入通过独立的 scrcpy 控制通道粘贴，无需安装或切换输入法；视频降级为截图也可使用。输入内容可能保留在手机剪贴板，不读取或同步原有剪贴板。收到通道应答后还会检查输入框文字，不能确认时暂停等待接管，不重复输入或自动安装 APK。手机管理可关闭自动输入，改用手机自带键盘。密码框仍禁止自动输入；不开放任意 shell、安装 APK、提取文件或云资源管理。

## 开发验证

```sh
pnpm exec tsx scripts/verify-phone-use.mts
```

脚本使用隔离临时状态启动真实 Gateway，通过鉴权和路由懒加载执行模拟器测试。只重启模拟器的系统设置任务，不清除应用数据。默认不调用付费模型，显式测试截图和元数据保存在 `/tmp/xopc-phone-use-evidence`。

构建 Web 后加 `XOPC_PHONE_BROWSER=1` 可检查桌面和窄屏页面；显式加 `XOPC_PHONE_REAL_MODEL=1` 且进程已取得 `ZHIPU_API_KEY` 才会进行真实 AutoGLM 测试。

## 在聊天中观看和接管

当 Agent 打开手机会话时，聊天标题栏会出现「手机」入口；宽屏且未查看其他工作区内容时，自动展开右侧手机标签。窄屏点击入口后全屏展示，使用「返回聊天」回到对话。

- **仅查看**：安装固定版本视频服务后，聊天面板使用 scrcpy H.264 视频和 WebCodecs 解码；点击画面不会发送输入。浏览器不支持或视频出错时，明确降级为截图，并可重试视频。设置页的查看屏幕弹窗仍是只读截图。
- **接管操作**：服务端暂停 Agent、等待已派发输入完成后开放人工控制。支持单指持续 DOWN/MOVE/UP 的点击、跟手拖动、长按，以及返回和非密码文本提交。移动不等待模型或逐次截图。中文通过独立的 scrcpy 粘贴通道输入，无需额外输入法；输入未确认时暂停等待接管检查。
- **退出接管**：停止此窗口的人工输入，任务保持暂停。
- **交还给 Agent / 继续原任务**：重新检查授权和当前页面，丢弃旧坐标后继续。正在等待的工具调用直接续接；若 Agent 已结束回复，面板会提交一次幂等的续接输入，让它继续本对话原任务。
- **停止**：结束手机操作、释放设备；收起标签仅结束观看。接管时关闭标签、切到其他工作区标签或切后台会尽力退出接管，断线由控制心跳超时兜底，保持暂停。

目前只允许 Gateway 管理员在原对话中查看/控制，分享对话不包含手机画面。输入仍受设备应用白名单约束；Home 不开放，密码字段禁止自动输入。不要在普通文本输入框中输入密码或验证码，优先在设备本地完成，再返回非敏感页面交还。

首次在 Gateway 主机运行 `pnpm exec tsx scripts/setup-phone-video.mts`，下载并校验官方 scrcpy 3.3.3 服务。视频和人工操作不需要 AutoGLM Key。文字输入和交还仍检查原生界面；断连、隐藏窗口、几何变化与交还会释放触点，交还确认撤销后 main 才继续。人工操作不消耗 Agent 动作预算。

本机测试模拟器已启用宿主 GPU；关闭 GPU 会限制 Android 自身渲染速度。若进入未授权应用，画面会清除，可显式返回授权应用。前台应用检查是采样校验，并非设备侧按应用隔离采集。云手机媒体、输入与撤销接口已预留，尚未接入或验证云厂商 SDK。阿里云 ADB 接入已通过独立鉴权 TCP 连接复用 scrcpy 视频与持续触控，配置步骤见下方接入指南。

## 连接阿里云手机（ADB）

完整步骤见[阿里云手机接入指南](how-to/connect-aliyun-cloud-phone.md)：包含控制台入口、创建和绑定密钥对、下载 `adbkey`、取得公网或私网 ADB 地址，以及 xopc 添加步骤和常见问题。

在「设置 → 手机控制 → 添加手机 → 阿里云手机」填写名称、`IP:端口` 并上传对应私钥。测试成功后检查型号、Android 版本和画面，再确认添加。无需阿里云 AccessKey；手机模型在模型管理中独立配置。

云手机使用独立 TCP ADB 连接，支持 scrcpy 实时视频与持续触控；视频不可用时降级为截图，不修改本机 ADB 服务或密钥。移除连接仅清理 xopc 注册与凭据，不销毁收费云实例或关闭云端 ADB 入口。

### 执行可靠性与完成证据

阿里云手机通过内置的只读无障碍采集程序获取节点，不等待全局界面空闲，避免动态设置页面导致 `uiautomator dump` 失败。程序通过已认证的 ADB 临时运行，采集后删除，不安装 APK；Gateway 同时检查节点和截图是否属于同一个前台应用。本地 ADB 固定使用压缩节点模式并进行有界重试。采集失败明确返回 `PHONE_UI_UNAVAILABLE`，不再伪装成界面变化或空节点；动作新鲜度检查仍然保留。修改 Java 源码后，使用 JDK 17、Android platform 36 和 build-tools 36.0.0，执行 `node scripts/build-phone-ui.mjs <Android SDK 目录>` 重建内置程序。

手机模型会收到有界的会话内动作轨迹、原生 UI 节点和执行变化反馈。AutoGLM 保留已验证的单个 JSON 用户观察消息；真实 App 对照中回退的对话重排、中心点提示及采样试验已撤回。轨迹与输入内容不保存到运行报告。格式错误最多允许每次 run 修复一次，计入模型请求预算；同一页面状态反复执行相同动作时以 `no_progress` 暂停，需要查看手机并显式交还后继续。

AutoGLM 的 `Type` / `Type_Name` 会替换当前聚焦的非密码字段：重新确认字段身份，在支持时选中原内容，只输入一次，并验证最终准确值。结构化 `typeText` 默认仍为插入，可指定 `mode: "replace"`。延迟验证只重新观察，不重发输入。

`run` / `step` 可传入组合完成条件，例如：

```json
{
  "op": "run",
  "goal": "进入关于手机并查看 Android 版本",
  "completion": {
    "appPackage": "com.android.settings",
    "textAny": ["Android version", "Android 版本"],
    "textAll": ["15"],
    "requireChange": true
  },
  "maxActions": 8
}
```

所有已提供条件都必须满足。应选择稳定的页面身份和与目标直接相关的证据，不额外要求无关条目同时可见。`textAny` 支持界面语言别名，`textAll` 要求每条文本都出现；`field: { "resourceId": "package:id/query", "value": "coffee" }` 要求可编辑字段准确匹配。旧 `expectText` 继续兼容，与组合条件同时生效。验证检查全部已采集原生节点，不受显示事实的 60 条上限影响。`requireChange` 仅表示本次执行观察到了 UI 变化，不能证明具体业务结果；完成条件必须在连续两次新观察中成立，期间仍检查取消、控制权与授权变更；模型自行结束仍未验证。

复验脚本、模拟回放对比和真实模拟器证据见[优化报告](https://github.com/xopcai/xopc/blob/main/docs/design/technical/phone-use-reliability-optimization-2026-10-24.md)。

真实 App 续轮评测及未采纳方案见[真实 App 优化报告](https://github.com/xopcai/xopc/blob/main/docs/design/technical/phone-use-real-app-optimization-2026-10-24.md)。

### 实验性语义执行与分层规划

可在 `xopc.json` 顶层 `phone` 配置中独立启用 `semanticControls: true` 和 `hierarchicalPlanning: true`；两项默认均为 `false`。

语义执行要求按当前观察的 `frameId` 和控件 ID、文字或描述精确匹配一个完整可见的非密码节点，再通过已有的新鲜度与派发检查转换为点击；标准坐标点击也可由执行器绑定到命中位置唯一、大小受限的原生控件，无需模型生成新动作格式；无法确定时保留原坐标。AutoGLM 的语义单项保持原有提示和观察输入，结构化模型则可使用显式选择器协议。分层执行从明确的完成条件编译可观察阶段，并增加执行恢复。AutoGLM 保持原有请求协议，由主机处理危险 Back 重规划、未聚焦输入和受支持的数字键盘输入；结构化模型也可收到当前阶段。Back 边界是原生 UI 启发式判断，并非 Android 返回栈证明。

输入恢复只处理模型已经请求的 Type：目标必须是已声明的唯一、完整可见非密码字段，输入值必须与目标一致；补一次聚焦点击后，须经新观察确认焦点和原值，才派发原输入。字段缺失会触发有界重规划，不猜测目标。待输入意图在取消、控制权变化时丢弃，未知派发不重试。

停止状态的 Clock 风格键盘还支持 `HHh MMm SSs` 规范时长。只有完整识别的直接设置命令、明确的目标包名及匹配时长、完整唯一的原生键盘同时成立，才逐键执行。解释、引用、未知附加条件等目标仍交给普通模型；完成条件本身不会授权写入。每个按键都需新观察确认显示值，再继续下一个按键；反馈不符会暂停，不会自动启动计时器。该能力不等于通用自然语言数值输入。

生成动作共享原有动作数、模型请求数与时间预算，最终任务验证独立于阶段推进。计划和待输入意图仅在一次 `run` 或 `step` 内存活，不持久化。两项功能仍默认关闭。四组真实 App 对比及独立留出任务结果见[语义执行与分层规划评测报告](https://github.com/xopcai/xopc/blob/main/docs/design/technical/phone-use-semantic-planning-benchmark-2026-10-24.md)。

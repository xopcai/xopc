# 产品理念

> **为超级个体打造的个人 AI。**

xopc 是为超级个体打造的个人 AI。它运行在你的环境中，记住你的目标与上下文，并跨越对话、工具与时间，持续帮你推进工作。你不必每次都从头开始；xopc 会从上次停下的地方继续，与你协作得越久，也就越懂你、越有价值。

独立工作，不意味着独自面对一切。xopc 将记忆、上下文与智能带入你的每一项工作，同时把方向、判断、创造和最终决定留给你。

它不是等待岗位说明的 AI 员工，不是只在一个代码仓库里工作的编码 Agent，也不是要求用户先把一切整理好的任务管理器。模型、Agent、Task、Project、Workflow 和 Automation 都是支撑能力；这些能力最终服务的是一段可以长期发展的协作关系。

## AI 承担执行，人保留方向

xopc 的目标不是替人生活，也不是把人变成监督自动化的操作员。它让 AI 接住重复、耗时、可验证的执行，把目标、判断、创造和最终决定留给人。人不必为了获得效率而交出主体性，也不必把每一个过程都亲手完成。

这种协作遵循四条原则：

1. AI 优先承担整理、查找、跟进、调用工具和验证结果等执行工作；
2. 人决定什么值得做，并保留关键取舍、创造性判断和最终决定；
3. 自动化始终以明确授权、可检查过程和可纠正结果为边界；
4. 节省下来的时间本身就是产品价值，它应该回到生活、关系和真正重要的事情中。

品牌圆环中的 80/20 表达的是这段关系的发展方向：随着理解、能力和信任增长，AI 可以承担更多执行，人把更少时间花在机械劳动上，把更多注意力留给判断和生活。它不是对每项工作固定比例的承诺，也不意味着人的作用只剩 20%；人的意图和决定始终定义整个循环。

## 不只是一个界面，而是一段关系

xopc 不应在安装当天假装认识用户。理解需要经历一个明确的过程：

```text
初见
→ 探索明确授权的来源
→ 形成初步理解
→ 协助真实工作
→ 建立信任
→ 逐渐主动
```

助手从对话和安全默认值开始。之后，用户可以接入工作文件夹或其它来源，看见 xopc 检查了什么、得出了什么推断，并进行纠正。每一次有用的结果和明确的反馈，都让下一次协作拥有更可靠的上下文。

理想的首次价值时刻不是“xopc 能访问我的文件”，而是：

> xopc 看见了我真正想推进的事情，说明了为什么会这样判断，并陪我完成了一个可信的下一步。

## 四层产品能力

### 理解一个人

xopc 维护的是结构化、可治理的理解，而不是把所有数据当成永久记忆。值得保留的理解可能包括：

- 目标、偏好和工作习惯；
- 重要的人和关系；
- 正在进行的项目和长期方向；
- 过去的决定以及原因；
- 仍需要关注的承诺；
- 最近的压力、阻塞和注意力方向。

每条理解都有生命周期：可以等待确认、被确认、被纠正、被拒绝、标记为过期或删除。用户的直接陈述和明确规则优先于系统推断。详见[用户理解](./user-understanding.md)。

### 接住混乱而长期的工作

人的想法很少天然就是整理好的任务。一个真正有用的助手，需要接住不完整的想法、文件、链接、语音、消息或证据，并帮助它逐渐变得可行动：

```text
捕获
→ 关联目标或 Project
→ 补充背景
→ 定义下一步
→ 识别依赖和阻塞
→ 在合适的时间重新提起
→ 保留决定和证据
→ 沉淀可以复用的经验
```

Conversation 是自然入口；当工作需要跨越时间继续推进时，[Task](./concepts/loops.md) 成为持续承诺；Project 提供相关上下文，但不建立另一套竞争的任务状态。

### 陪用户解决问题

xopc 应该理解结果为什么重要，澄清不确定之处，调查已授权的上下文，制定方案，调用工具，验证结果，并留下可检查的记录。复杂工作可以跨越多次对话、多个设备和不同执行方式，而不需要用户每次重新讲述背景。

### 逐渐获得主动性

主动性不是增加通知数量，而是发现真正重要的停滞承诺或新信号，提出有价值的响应，并在打扰没有帮助时保持安静。

权限随信任逐级增长：

```text
只观察
→ 主动提醒
→ 提出行动建议
→ 经确认后执行
→ 自动处理明确授权的低风险事项
```

当前主动能力以证据优先、建议优先为原则。对外写入和重要动作需要明确策略或人工批准。详见[自动化](./automations.md)与[心跳检查](./heartbeat.md)。

## 信任本身就是产品界面

探索过程必须始终可见、可控：

1. 每个数据源单独授权，并允许随时撤销。
2. 说明正在检查什么、范围多大、目的是什么。
3. 为结论和建议保留证据来源。
4. 明确区分亲眼看到的事实与根据事实作出的推断。
5. 允许确认、纠正、拒绝、删除和遗忘。
6. 持久状态默认留在本机；选定上下文会发送给云端模型时提前说明。
7. 发送、删除、购买和其它高影响动作需要单独授权。
8. 低价值提醒不应打扰用户。

“本地优先”描述的是所有权和架构，不代表所有模型请求一定留在设备上。不能发送给外部服务商的上下文应使用本地模型处理。

## 当前已经具备的基础

当前产品已经包含这段体验所需的主要基础：

| 产品需要 | 当前基础 |
| --- | --- |
| 本地所有权 | 桌面应用、自托管 Gateway、本地状态、自有密钥，以及云端或本地模型 |
| 可审查的理解 | 等待确认与已启用的理解、明确协作规则、确认和纠正、过期与冲突复查 |
| 可见的工作探索 | 对明确选择的文件夹进行有边界、只读的分析，并给出带证据的下一步；macOS 可选原生上下文 |
| 持续工作 | Conversation、Task、Project、笔记、工作区、证据和运行记录 |
| 执行与跟进 | 工具、Skill、Workflow、Automation 和主动建议基础设施 |
| 多种入口 | 桌面、网页、CLI、TUI、手机、Telegram、微信、飞书/Lark 和 API |

在 macOS 上，实验性的 Work Discovery 首次体验可以分别请求 Apple Notes、Calendar 和 Reminders 的系统权限。扫描有明确上限、只读执行，原生来源的原始内容不会保存在 xopc 数据库中。具体可用范围可能随版本变化。

## 第一阶段产品方向

接下来的具体交付先解决用户自己的 Slack 开发工作：消息跟不过来、持续讨论需要反复复制给编码 Agent、分支难以对应原始需求。

1. 接手明确委托的 Slack thread，关联一个持久 Task；
2. 在授权仓库内排查和开发，默认使用 xopc 内部 BYOK Agent；Codex 等外部执行器可选，但需满足相同控制要求；
3. 新讨论持续进入原事项，保留需求版本及已应用的证据；
4. Task 与仓库、工作区、分支、执行尝试和验证结果绑定，并可反查 Slack 来源；
5. 正常进度安静记录，只在判断、批准或需人工恢复的阻塞时通知；
6. 区分代码可交付、用户接受、合并与上线，不默认 push、PR、Slack 回写、合并、部署或清理已有分支；
7. 明确 thread 的跟进可靠后，再扩展授权频道内的新事项发现。

本轮验证的是通用“来源 → Scene 指令 → Task → 既有 Agent harness”链路，不建设 Slack 专用编码运行时。资源与权限独立组合：分析无需文件，文档使用任务产物目录，项目修改使用 worktree。文件修改不要求 Docker 或命令执行；可选验证单独授权，未验证结果如实展示。既有 Gmail／家庭场景保留当前限制与发布门禁；Skill／Workflow 打包与未来 Scene／Extension 能力包沿现有能力扩展，不增加第二套编排引擎。

具体见[使用说明](../scenes.md)。先对照消息复制、手动盯线程、重复交代、找分支与返工负担，并用文档维护场景验证非编码复用。

这是产品方向，不表示当前版本已经完整实现每一项。具体可用能力以[版本记录](./releases.md)和对应功能指南为准。

## 产品衡量方式

消息数量和自动完成的任务数量不是北极星指标。更重要的问题是：

> 使用七天后，用户是否认为 xopc 比第一天更懂自己，而且确实帮助自己推进了一件重要的事？

同样重要的是：xopc 是否在不削弱用户控制感的前提下，减少了必须亲自承担的重复劳动，并把可感知的时间和注意力还给了用户？

> **一个人，一个 AI，一种全新的组织方式。**

# 交办任务与接收结果

让 Ada 准备一个明确的成果，执行时继续对话，之后回来查看文件或任务记录。需要工作在一条回复之外持续推进时，可以使用这条路径。

## 开始前

完成 [Ada 设置](./personal-ai.md)，保持网关运行，并提供所需文件和工具权限。连接模型不会自动授予所有文件夹或外部服务的访问权限。

## 交代清楚成果

说明资料来源、预期结果、完成条件和边界。例如：

```text
把本周计划整理成工作空间中的一页 Markdown 文件。
包括重点、三个下一步和未决问题。
只使用当前对话中的资料，不发布，也不发送给任何人。
文件准备好后告诉我。
```

制作表格或演示文稿前，先配置对应工具或技能。资料不完整时，可要求先集中询问缺失信息。

## 查看执行情况

1. 打开个人 Agent 顶部的 **正在做的事**，查看派发任务。
2. 打开任务卡，检查进度、待补信息和执行记录。
3. 有澄清或授权请求时，按需回应；任务可能会等待你的答复。
4. 继续个人对话。当前讨论优先于未请求的任务更新。

更新可能排队，执行结束不代表通知立即到达。没有收到结果时，先检查原任务，再决定是否重新交办。

## 检查并修改成果

打开交付文件或关联任务，确认文件存在、来源正确、满足要求。然后提出具体修改：“修改这份文件，缩短引言，并为每个下一步补充负责人，原始数字保持不变。”引用已有成果或 Task，避免修改对象不明确。

成果交付、执行停止和任务通过验收是不同状态。长期工作需要进一步[检查并验收任务](./task-review.md)。

## 出问题后继续

| 情况 | 处理方式 |
| --- | --- |
| 等待资料或权限 | 打开任务并处理待办请求 |
| 执行失败 | 检查原因和已有成果后再重试 |
| 助手说已生成，但找不到文件 | 要求给出保存路径，并检查附件或任务记录 |
| 网关断开 | 连回同一个实例，先检查当前状态 |
| 希望停止执行 | 取消任务执行；结束语音通话不会取消任务 |

取消不会撤销已经完成的写入。外部操作重试前，先检查实际目标状态。固定定时执行用[自动化](./automations.md)，按主题持续关注用 [Personal AI 跟进](./personal-agent-proactivity.md)。

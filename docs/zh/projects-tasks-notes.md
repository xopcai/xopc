# Project、Task 与笔记

工作需要在一次对话之外保持组织时使用这些功能。简短或探索性请求只用聊天即可；还没想清楚的内容也可以直接交给 xopc，不需要先整理成结构化 Task。

理想过程是逐渐变清晰：先接住想法，再澄清它与目标或 Project 的关系；只有结果、阻塞或下一步需要长期保留时才创建 Task。

## 选择合适的位置

| 需求 | 使用 |
| --- | --- |
| 提问或完成一个小请求 | Session |
| 让一个结果跨时间持续推进 | Task |
| 为多个相关 Task 共享上下文 | Project |
| 保存来源材料或产物 | Note 或工作区文件 |
| 按计划或事件启动工作 | Automation |

## 创建有用的 Task

Task 应回答：

- 最终需要得到什么结果？
- 如何判断已经完成？
- 范围内和范围外分别是什么？
- 下一步动作是什么？
- 当前缺少哪个决定或权限？

不要把每条聊天消息都变成 Task。结果需要跨 Session 保存，或需要多步执行和验证时再创建。

## 用 Project 保存共享上下文

Project 用于组织相关 Task、对话、文件和活动。它是上下文，不是第二套任务状态。Project 说明保持简短，把可执行结果放进 Task。

要设置项目内的定期工作，请从该项目的定时任务入口发起配置对话。个人日程从 Personal 发起。[自动化](./automations.md)

## 笔记与工作区文件

快速保存长期信息使用 Note；需要 Agent 读取、编辑或交付的材料使用工作区文件。文件名应清晰，发送给云端模型前删除敏感信息。

在网页和桌面端，长笔记可以通过大纲在各级标题之间跳转。如果保存时与新版本冲突，先检查恢复的草稿再重新保存。在 **资料库** 查找文件和交付成果的历史版本。[工作空间指南](./workspace-guide.md)

## 简单示例

准备一次产品发布时：

1. 创建 Project 保存发布背景和参考文件。
2. 为不同可验证结果创建 Task，例如“发布软件包”和“发送发布公告”。
3. 为每个 Task 定义完成检查。
4. 只有时间或外部触发重要时才添加 Automation。
5. 检查结果后再关闭 Task，不要只因为 Agent 运行结束就标记完成。

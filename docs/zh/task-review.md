# 检查、验收或重试 Task

一次执行停止后，成果仍可能不满足要求。检查文件和证据，再决定 Task 是否达到完成条件。

## 开始前

打开已有验收条件且有成果可检查的 Task。先通过[任务交办](./task-delegation.md)或 [Project、Task 与笔记](./projects-tasks-notes.md)明确预期结果。

## 检查成果

1. 打开任务卡；任务等待验收时，展开验收区域。
2. 检查交付文件、执行记录、结果证据和剩余工作。
3. 对照每条验收条件检查实际结果，选择 **标记通过**或**标记失败**；没有证据的结论保持未验证，以当前界面名称为准。
4. 所有条件通过、没有待处理等待且任务允许关闭时，选择 **验收任务**。

报告要检查保存文件和数字；代码修改要检查 diff 和验证结果；外部写入要查看实际目标，不能仅凭模型说“完成”。

## 要求修改或重试

成果需要调整时，在关联对话中说明未满足的条件及所需修改。最近一次执行失败时，先看原因，再选择 **重试**。重试沿用该次执行的执行者。

重试不代表此前外部写入没有成功。重复动作前先检查已发生的写入。取消只停止后续执行，不会撤销已有影响。

## 操作不可用时

| 情况 | 下一步 |
| --- | --- |
| 无法验收 | 检查验收条件、待处理等待和当前任务状态 |
| 检查时任务已变化 | 刷新后查看最新执行与成果 |
| 需要资料或授权 | 先处理请求再继续 |
| 结果没有证据 | 要求可验证成果，保持该条件未验证 |
| 重试再次失败 | 修复报告的访问、模型、工具或输入问题再重试 |

在原 Task 上保留验收决定，使成果与判断留在一起。定时工作还应检查[自动化](./automations.md)运行记录。

# 检查、验收或重试 Task

新派发的任务（包括 Personal Agent 的已连接应用请求）默认自动验收。系统逐项核验当前成果，在同一次执行中补做可修复的缺口；全部通过、没有剩余工作且无需用户决定时，自动完成任务。

如果希望亲自确认最终成果，请明确要求人工验收；API 和工具调用可设置 `acceptancePolicy: "manual"`。缺少必要信息、账号授权或需要确认外部操作影响时，仍会等待你的决定。证据或查询覆盖不完整时会进行有限次数的自动补做；仍无法解决则报告执行失败及具体缺口，不会把技术问题变成例行人工验收。

以下检查和验收操作适用于需要你决定的任务。

## 自由调整任务阶段

在看板拖动任务，或在任务详情中切换阶段。Android、iOS 和鸿蒙的“调整状态”入口提供待办池、就绪、进行中、待验收、已关闭五个阶段。运行、等待、依赖和未通过的验收标准不会阻止人工调整阶段。

移到已关闭默认记录为人工完成；移回其他阶段会清除当前关闭原因。调整阶段不会修改验收证据，也不会启动或停止执行。启动、暂停和取消执行仍通过对应操作完成；已关闭任务仍可能有正在运行的执行，界面会保留展示。

任务详情的“变更记录”保存每次阶段和关闭原因变化的操作者、来源和时间。撤销会追加反向记录，不删除历史。记录从功能启用后开始，历史变化不会补造。

人工调整阶段后，旧运行仍可保存结果，但不能覆盖用户选择，即使先移走又拖回原阶段。主动启动新执行或明确要求修订成果后，该次新工作才重新允许自动推进。后台分配和定时信号不能清除这项保护。

## 开始前

打开已有验收条件且有成果可检查的 Task。先通过[任务交办](./task-delegation.md)或 [Project、Task 与笔记](./projects-tasks-notes.md)明确预期结果。

## 检查成果

1. 打开任务卡；任务等待验收时，展开验收区域。
2. 检查交付文件、执行记录、结果证据和剩余工作。
3. 对照每条验收条件检查实际结果，选择 **标记通过**或**标记失败**；没有证据的结论保持未验证，以当前界面名称为准。
4. 所有条件通过、没有待处理等待且任务允许关闭时，选择 **验收任务**。

报告要检查保存文件和数字；代码修改要检查 diff 和验证结果；外部写入要查看实际目标，不能仅凭模型说“完成”。

## 要求修改或重试

成果需要调整时，在关联对话中说明未满足的条件及所需修改。最近一次执行失败时，先看原因，再选择 **重试**。重试沿用该次执行的执行者。

重试不代表此前外部写入没有成功。重复动作前先检查已发生的写入。取消只停止后续执行，不会撤销已有影响。

## 操作不可用时

| 情况 | 下一步 |
| --- | --- |
| 无法验收 | 检查验收条件、待处理等待和当前任务状态 |
| 检查时任务已变化 | 刷新后查看最新执行与成果 |
| 需要资料或授权 | 先处理请求再继续 |
| 结果没有证据 | 要求可验证成果，保持该条件未验证 |
| 重试再次失败 | 修复报告的访问、模型、工具或输入问题再重试 |

在原 Task 上保留验收决定，使成果与判断留在一起。定时工作还应检查[自动化](./automations.md)运行记录。

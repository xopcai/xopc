# 用户理解

xopc 可以维护一个可检查、可纠正的个人认知模型，让协作拥有连续性，同时避免把每次观察都当成永久事实，也不会默认每条消息都值得成为长期记忆。

用户理解由已启用的 Agent 共享，但它不同于聊天记录、工作区文件和 Agent Profile。

## 哪些理解可能有价值

值得保留的内容可能包括：

- 姓名、时区、首选语言等个人资料；
- 目标和长期方向；
- 重要的人和关系；
- 正在进行的 Project 和周期性责任；
- 偏好与工作习惯；
- 过去的决定以及原因；
- 可能需要跟进的承诺；
- 当前重点、压力或阻塞；
- 关于 xopc 应如何协作的明确规则。

目标不是尽可能多地收集数据。xopc 只应保留确实有用、范围适当而且仍然有效的上下文。

## 事实、推断与规则

xopc 应明确区分三类内容：

| 类型 | 含义 | 示例 |
| --- | --- | --- |
| **看到或直接陈述的事实** | 用户明确说过，或授权来源直接显示的内容 | “这个项目的截止日期是 10 月 12 日。” |
| **推断** | 根据一条或多条证据形成的结论 | “这个项目可能是用户当前最高优先级。” |
| **协作规则** | 明确约束助手行为的指令 | “向外部联系人发送消息前先问我。” |

推断不是权威事实。证据、适用范围、可信程度和时间都需要被考虑。明确协作规则优先于推断出来的偏好。

## 查看 xopc 了解的内容

在 Gateway 控制台打开 **你** 或 **用户上下文**。根据当前版本，可以查看：

- 你直接填写的资料；
- 等待检查的推断理解；
- 已启用的理解；
- 明确设置的协作规则；
- 已连接来源及其权限；
- 来源证据和推导信息；
- 后台复查与隐私设置。

只有内容准确、有用且范围合适时才使用 **确认**。错误、范围过宽、已经过期或不应保留时，使用 **修正**、**拒绝** 或 **删除**。

纠正是产品正常运行的一部分，而不是异常失败。明确纠正过的内容，应优先于之后根据旧证据产生的推断。

## 理解的生命周期

有用的认知系统不仅需要决定记住什么：

```text
出现证据
→ 提出一条理解
→ 用户或策略进行检查
→ 启用、纠正、拒绝或继续等待
→ 只在相关时使用
→ 检查冲突与时效
→ 更新、标记过期或删除
```

用户直接陈述的事实也可能过期。短期重点应该在时间结束后失效，而不是悄悄变成永久身份判断。互相矛盾的理解应该重新进入检查流程，而不是在后台被静默覆盖。

## 数据来源与权限

每个来源独立授权。连接一个来源不代表其它来源也被授权。

- 对话可以提供直接陈述与纠正；
- 明确选择的工作文件夹可以提供有边界的项目证据；
- 配置并授权连接器后，可以提供邮件、日历、任务或文档等来源特定的上下文；
- 在受支持的 macOS 桌面版本中，实验性 Work Discovery 可以分别请求 Apple Notes、Calendar 和 Reminders 的只读权限。

Work Discovery 的读取范围有明确上限并保持可见。macOS 原生扫描只在模型调用期间保留来源原文，不会把原始内容写入 xopc 数据库；由此形成的理解仍可检查。具体来源是否可用取决于版本。

撤销来源后应停止之后的读取。由来源产生的理解需要单独判断：用户已经确认的结论在断开来源后可能仍有价值；不可信或不希望保留的衍生理解应被删除。

## 不应记住的内容

不要让 xopc 保存密码、API Key、恢复码、支付信息、政府证件号、医疗记录或其它高度敏感秘密。此类信息应放在密码管理器或对应系统中。

工作区文件和 Agent Profile Markdown 与用户理解不同。把信息写在那里可能让 Agent 读取，但不会使其成为经过审查的理解。

## 模型服务商隐私

本地保存不代表每次模型请求都留在本地。与当前请求相关的用户理解、对话内容和授权来源片段，可能发送给当前配置的云端模型。

上下文必须留在设备上时，请使用本地模型。连接云端服务商或个人数据源前，请检查服务商的数据处理方式，以及 xopc 中控制个性化和来源访问的设置。

xopc 应只发送当前请求需要的上下文，而不是在每次请求中附带完整的个人认知模型。

## 后台复查

启用后，后台复查可以识别过期或互相矛盾的内容，并放入待检查队列。它不应把未经确认的推断静默变成权威资料。

请定期检查队列；不希望进行后台处理时可以停用。主动复查应提出少量真正有用的决定，而不是制造重复通知。

完整信任模型见[产品理念](./product.md)。本地数据库的备份和删除见[数据和文件位置](./workspace.md)。

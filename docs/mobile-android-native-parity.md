# Native Android parity with HarmonyOS

Status: in progress. Baseline: the current `apps/mobile-harmony/entry/src/main/ets/` implementation, not the older four-tab retired cross-platform client design. Android uses the same five top-level destinations: Assistant, Conversations, Progress, Notes, Me.

## Principles

- The Gateway owns agents, conversations, runs, work, notes, files, and decisions. Android is a secure client, not a second agent runtime.
- Assistant is the active conversation workspace; Conversations is the list and management view of the **same** conversation store.
- Keep one state owner for each conversation and one owner for the realtime connection. UI screens observe immutable state and send intents. Do not copy Harmony view classes or create a generic cross-platform UI framework.
- Match behavior, information priority, navigation outcomes, and visual hierarchy. Use Android-native back, permissions, pickers, accessibility, and window insets where platform mechanics differ.
- A feature is complete only after contract tests and an isolated Gateway/device journey. Host tests, a build, emulator screenshots, and physical-device evidence are distinct claims.

## Implementation order

1. **Foundation:** standalone build, five-destination shell, secure pairing, credential store, transport, protocol compatibility, repositories and a test Gateway harness.
2. **Assistant and Conversations vertical slice:** local-first create, list/open/history/send/stream/reconnect, drafts, model/agent/context, prompt/attention, queue and actions. Use isolated Gateway fixtures for automated mutation tests; keep authorized live E2E changes inside clearly named test conversations.
3. **Rich interaction:** attachments, voice, structured tool/review/deliverable rendering, media safety, read-aloud and sharing.
4. **Remaining destinations:** Progress, Notes, Me and their full detail routes and cross-destination journeys.
5. **Release gates:** contract fixtures, unit and Compose UI tests, emulator and physical-device runs, accessibility, zh/en, light/dark, compact/expanded widths, background/process-death recovery and performance.

# iOS 与鸿蒙：聊天及多模态对齐计划

更新：2026-10-05。基线为本机 `xopc-mobile-parity-acceptance` 的 35 条鸿蒙真机旅程；当前 iOS 为 SwiftUI 原生实现。状态只表示已验证的范围，不把“有入口”视为端到端通过。

## 本轮结论

助手首页、五 Tab、会话列表、基本收发、消息详情与执行过程已具备；整体仍未达到完整对齐。真实 Gateway 历史会话暴露了一个数据契约差异：图片、语音在 `messages[].media`，而 iOS 原先只读 `attachments`，导致纯媒体消息被丢弃。本轮已补齐解码、时间线和图片/语音展示；历史图片缩略图与点开预览已在模拟器上经真实 Gateway 验证，语音播放尚未完成同等级 UI 验收。

|---|---|---|---|

## 推进顺序

1. 先完成语音历史播放 E2E 和媒体发送后回显；任何媒体不能只在当前屏幕可见，重进后必须仍可用。
2. 接入服务端会话搜索、分页和历史向上加载；保持已读位置和未发送草稿，不为分页引入第二套会话状态。
3. 完善图片草稿缩略图、失败态与多图查看；遵循系统照片/分享能力，避免自建图库交互。
4. 补助手消息操作与生成媒体；针对 `media://`、文件、远程图片分别做正例和错误注入。
5. 每个阶段完成后跑单元测试、真实 Gateway UI 旅程、无障碍与中英/浅深色回归；更新私有截图验收记录。只有旅程和反例都通过才改为“通过”。

不依赖用户即可继续前四项；物理相机、真实麦克风路由、锁屏音频和完整 VoiceOver 手势最终需要真机验收。现有本机截图包含个人数据，保持在 Git 忽略目录，不提交。

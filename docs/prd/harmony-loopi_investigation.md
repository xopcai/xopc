# 鸿蒙小环品牌角色接入调研

日期：2026-10-03。状态：用户已确认方案，进入原生实现。

## 1. 需求背景

将已确认的薄陶瓷圆环、正向扁圆核心和自然表情移植到鸿蒙，使新建聊天、助手入口和用户理解体验保持品牌一致。无播放/暂停控件，不用动画模拟任务完成。

## 2. 涉及模块

- `apps/mobile-harmony/entry/src/main/ets/view/ChatWelcome.ets`：新建聊天欢迎态，当前没有品牌角色。
- `view/ChatView.ets`：向欢迎态传递真实上下文状态与页面活跃状态。
- `view/HomeView.ets`：助手 Tab 是 index 0，实际内容为 ChatView；底部入口现在使用气泡图标。
- `view/PersonalView.ets`：个人卡片使用姓名缩写，整卡进入 about-you。
- `view/AboutYouView.ets`：用户理解详情，适合在标题附近加入陪伴角色。
- `service/layoutState.ets`、`entryability/EntryAbility.ets`：动效偏好及前后台生命周期。

## 3. 可复用能力

- 已有 ComponentV2、主题 palette、`activePage`、页面销毁和减少动态字段。
- Web `components/brand/loopi*` 是造型/动作参照，不能直接把 React 和 DOM 动画搬入 ArkUI。
- `MobileComponents.ets` 的 XopcBrandLoading 仅为双色图层旋转，不具备脸部表情，不建议当作新角色复用。
- 根和 entry 的 oh-package 配置没有运行时第三方依赖；oh_modules 已初始化，只有 Hypium 测试库。计划不新增动画依赖或后端接口。

## 4. 历史相关变更

已有官网/Web 小环：石墨灰长弧、蓝色短弧、象牙白核心，脸始终正向；自然眨眼、随机小眼神、轻触回应、分层跟随；已删除播放控件。

## 5. 架构约束与风险

- 使用原生 ArkUI 分层组件；不嵌入 WebView，不按整张图片旋转人物。
- `layoutState.reduceMotion` 默认 true；HomeView 已通过 `accessibility.isAnimationReduceEnabledSync()` 读取系统设置，失败时保守禁用动效，并有变更监听。新组件须复用该状态，不绕过用户偏好。
- Tabs 页面可能驻留，必须同时按 activePage、可见性、前后台状态停止计时；仅 aboutToDisappear 不够。
- 个人页暂没有 activePage 参数，需要补齐传播；用户真实头像/缩写不能默认被 AI 身份替换。
- 需验证原生曲线绘制、SVG/图层材质与缩放效果；编译通过不等于手机真机验收。
- 当前工具清单未暴露 DevEco MCP 构建/运行工具，编码阶段需按工作流核实工具配置。

## 6. 初步方案方向

推荐：新增统一原生 `XopcLoopi` 组件，分头像和欢迎主角两种密度。

| 场景 | 造型/尺寸建议 | 动作与边界 |
| --- | --- | --- |
| 新建 Chat | 主角 80–96 vp，标题上方 | 自然眨眼、小眼神、轻微呼吸；点击短暂笑眼；不发送消息、不抢输入焦点 |
| 助手 Tab | 24–28 vp 简化小环 | 选中时一次轻响应，未选中静止；保留原 Tab 点击和选中语义 |
| 个人页 | 保留姓名缩写，用户理解入口配 40–48 vp 小环 | 点击仍进入关于你，不增加嵌套点击行为 |
| 关于你详情 | 56–72 vp 倾听形象 | 刷新中专注，错误时温和；不把待确认项演成成功 |

备选：只使用已有静态 SVG 加整图浮动，成本较低但缺少独立表情，不推荐。另一备选是嵌 WebView 复用网页动画，增加资源和生命周期成本，不推荐。

## 7. 待确认问题

1. 是否按手机优先，同时兼容现有平板/折叠屏布局实施？
2. 是否保留用户本人头像，将小环用于用户理解入口及助手身份？
3. 是否直接以现有小环原型和 Web 实现为视觉基准，不另出 Figma 设计稿？

## 8. 方案论证结论

用户以“按照以上方案实现”确认上述推荐方案及三个范围问题。采用原生分层小环，保留用户身份，无新增运行时依赖。

## 9. 已记录问题

减少动态来源已定位；前后台通知与原生图层材质需要在技术校准阶段验证；未修改应用源码。

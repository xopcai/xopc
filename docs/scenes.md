# 使用场景

场景根据明确目标和授权持续检查并推进事情。现有家庭安排与 Gmail 邮件跟进提供只读成果；新增的通用「持续推进一件事」将来源变化交给同一 Task 和内部 BYOK Agent。Slack 是第一种连接来源，不是专用编码执行器。

## 持续推进一件事（未发布内测）

1. 开启 `gateway.scenes.enabled` 并重启 Gateway，配置可用模型与连接器读取权限。
2. 在「场景」新建「持续推进一件事」，选择来源账号、粘贴讨论链接，描述目标和可选处理指令。只需一次授权，不必配置 webhook 或 Workflow。
3. 选择任务资源：无文件资源用于分析；任务产物目录用于文档等文件；Git worktree 用于项目修改。文档任务不要求项目或 Git。worktree 项目首次基线要求干净，不会替你清理原工作区。
4. 如需创建／修改文件，勾选文件写入权限。**文件修改不需要 Docker。** 默认不运行命令。只有主动填写验证命令，才检查当前可选隔离后端是否可用；当前实现是固定摘要的 Docker 镜像，断网、只读挂载，无宿主机自动回退。
5. 来源变化约每分钟同步到同一 Task，复用会话和任务资源。代码修改使用可追溯的 `xopc/task-<taskId>` 分支；文本处理不创建分支。已有分支可以只读盘点并人工确认关联，不会被自动接管。
6. 在详情查看已观察、已交付、已处理版本以及产物、剩余工作和验证证据。**已处理不等于已完成验收**。未运行验证时明确显示“未验证”，不会阻止文件修改，也不会自动宣称通过。
7. 在授权内仍有可立即推进的工作时自动继续，最多三轮；未来讨论由来源观察负责。需要判断、权限或恢复时到关联 Task 处理，回答后继续同一任务。
8. 可暂停，再调整自然语言指令和文件权限；保存后保持暂停，确认后恢复。停止跟进会保留任务、分支及文件，不清理用户资源。

例子：同一套链路既可“根据讨论修复项目中的问题”，也可“随讨论持续更新 decisions.md”。两者只更换指令、资源及授权，不使用不同的业务执行器。当前使用默认 Agent 的 `reasoning` 模型意图及既有凭据；未配置该意图时回退聊天模型。

当前连接入口只支持明确选中的 Slack thread；不自动发现全频道新事项，不调用外部 Codex，也不发送 Slack 消息、提交、推送、建 PR、合并或部署。附件标记未读取。Gateway 必须保持在线。更多来源、Skill 包与用户安装 Extension 是后续能力，不冒充已经交付。

v190 的实验性开发场景升级后保留原任务、来源快照、资源和回执，暂停等待确认；不会自动扩权或重新创建工作区。详细架构与边界见[通用场景任务跟进方案](./design/scene-task-follow-up.md)。

## 开始使用

场景在完成真实设备与持续运行门禁前采用显式内测开关。先在配置中设置 `gateway.scenes.enabled: true` 并重启 Gateway；关闭时不启动后台 Scene 宿主，Web 侧边栏也不展示入口。

1. 启动 Gateway，打开 Web 控制台的「场景」。先在模型设置中配置可用模型和凭据。场景优先使用默认 Agent 的 `reasoning` 模型意图；未配置时使用该 Agent 的聊天模型。诊断页会显示当前解析到的模型。
2. 家庭安排：填写目标、你愿意提供的安排和约束，设置时区和检查时间，开启后可点击「现在检查」。没有提供资料时不会凭空生成安排。
3. 邮件跟进：在「连接」中连接 Gmail，允许读取及后台检查。在新建场景中选择账号、搜索并选择一个线程，设置截止时间。要求每次读取确认或仅限指定 Agent 的账号暂不支持。
4. 在场景详情或成果列表查看结果、复制内容、标记已读并反馈是否有帮助。资料发生并发修改时，可以保留当前输入，或重新加载最新版本。
5. 可随时暂停检查、修改设置再恢复，或结束场景。结束后已产出的成果仍可查看。

## 提醒与故障排查

浏览器提醒需要 HTTPS 或 localhost，以及浏览器／系统通知权限。在场景设置中启用浏览器提醒；可设置免打扰、时区、每日上限、摘要和正在查看时抑制提醒。禁用浏览器提醒不影响在应用中查看成果。

诊断展示最近及下次检查、排队情况、模型用量和提醒状态。推送服务接受请求不等于设备已经显示通知。未收到提醒时，先检查静音、免打扰、每日上限、正在查看抑制和浏览器权限。模型未配置或连接失效时，先修复对应设置，再检查／恢复场景。

当前面向单 Gateway 和本地主体。Electron 支持管理与成果查看；首发后台提醒按支持 Web Push 的浏览器验收，尚不承诺 Electron 系统通知或移动端场景推送。

## 从实验版本升级

此版本删除未正式使用的 Proactive／助理 Heartbeat 实验数据和旧入口，不转换旧场景历史。废弃的 `gateway.heartbeat` 配置会被忽略，保存配置后移除。启动清理不删除聊天、项目、连接账号、独立自动化或工作区文件；重复启动不会清空新场景。

数据库结构升级后，不应直接用旧版本打开升级后的数据库。正式发布前仍需真实 Gmail／模型、浏览器设备提醒及持续试点验收。

## 完成设置与检查状态

选择“继续设置”后，详情会列出尚未完成的资料和时间设置。家庭场景需要安排和约束及周期时间；邮件场景需要跟进截止时间。未设置周期时间时仍可手动检查，页面会明确标记设置未完成。

相同有效资料再次手动检查会保留原成果、已读状态和反馈；新增资料或新的计划周期正常生成成果。邮件来源失效时，诊断会给出原因和重试时间，旧成果提示尚未核实最新邮件，并暂缓提醒。可以从诊断进入连接器恢复授权，再使用“现在检查”。

成果卡展示生成时间；邮件来源可打开原线程，需要在浏览器登录对应 Gmail 账号；家庭资料可回到所属场景查看。

# Personal AI 专注对话方案

状态：产品与交互提案，尚未实现。日期：2026-10-09。

## 产品目标

让用户进入 Ada 后可以立即继续对话；需要时知道委托事项的进展，并能方便地回到其他工作。优先保证对话连续性、阅读舒适度和导航可恢复性。

Personal AI 是一个持续的私人对话入口。导航表达“去哪里”，活动表达“交给 Ada 的事情”，正文表达“正在和 Ada 讨论什么”，三者不抢占同一层注意力。

## 当前实现依据

- `web/src/features/personal-agent/personal-page.tsx`：持久的 Personal conversation；头像、语音通话、活动、偏好入口；活动目前主要表达派发任务。
- `web/src/components/shell/sidebar-column.tsx`：768px 以下为覆盖抽屉；桌面收起后宽度为零，页头提供恢复入口。
- `web/src/stores/sidebar-store.ts`：侧栏展开/收起目前是跨页面持久偏好。
- `web/src/components/shell/app-shell.tsx`：Personal 页面目前会显示移动端全局底部导航。
- `web/src/features/chat/chat-page.tsx`：Personal 使用简化输入区，隐藏模型选择、助手工具工作日志和常规助手操作。

以下尺寸为设计起点，需用真实内容验证后调整；沿用现有语义色、字体、圆角和壳层规范。

## 核心决策：默认专注，允许用户覆盖

首次进入 Ada，桌面默认收起全局侧栏，手机关闭导航抽屉。页头始终保留明确的“打开导航”入口。无需先发送消息，也不使用延迟收起。

Personal 桌面导航偏好独立保存：用户在 Ada 展开侧栏后，后续进入尊重这个选择；收起后恢复默认专注。离开 Personal 后恢复其他页面原有的导航偏好。手机抽屉属于临时导航，不保存为常驻展开偏好。

| 场景 | 行为 |
| --- | --- |
| 首次点击左侧 Ada | 进入既有对话，同时收起导航 |
| 在 Ada 主动展开桌面导航 | 当前保持展开，保存 Personal 偏好 |
| 从 Ada 切换到任务/项目 | 使用工作区自己的导航偏好 |
| 返回 Ada、刷新或直接打开链接 | 桌面恢复 Personal 偏好；手机默认关闭抽屉 |
| 调整窗口宽度 | 只切换布局呈现，不改写已保存偏好 |
| 查看任务详情或偏好 | 留在 Personal 上下文，关闭后恢复对话位置 |

不要直接在路由进入时调用全局 `setCollapsed(true)`，否则会污染用户在其他页面的导航选择。应由壳层解析当前路由、视口和各自偏好后的有效显示状态。

收起后将原导航焦点移到可见页头或恢复按钮；保留键盘操作。抽屉/弹层打开时管理焦点，关闭后回到触发控件。桌面保留窗口拖动区域和系统窗口控制。

## 页面信息架构

默认页头：导航入口、Ada 头像与名称、活动入口、语音通话、更多。

将现有偏好按钮放入“更多”，也可继续点击头像打开资料与回应偏好。手机活动入口使用短标签“进展”，名称优先保留，空间不足时将语音通话放入更多。导航与更多使用不同图标及可访问名称。

正文：历史消息、当前回复、与当前对话有关的成果卡片。消息和输入区使用同一阅读列，起始最大宽度 760px；宽屏留白用于阅读，不自动填入任务或统计卡片。

输入区：附件、文本、语音输入、发送；回复进行中提供明确的停止回复控件。停止当前回复与停止后台任务必须是不同操作。

空状态：一句自然开场与输入框。首次引导可保留一次性的支持方式选择；有历史时直接恢复对话，不重复出现欢迎屏。

## 响应式布局

| 窗口宽度 | 默认布局 | 导航 | 活动/成果 |
| --- | --- | --- | --- |
| <768px | 单列对话，左右约16px留白 | 覆盖抽屉；隐藏全局底部导航 | 活动使用底部面板；任务详情/成果使用可返回的全屏层 |
| 768–1199px | 单列居中阅读 | 默认收起；手动展开沿用壳层侧栏 | 浮层或覆盖面板，不再挤出第三列 |
| ≥1200px | 约760px阅读列，扩大外侧留白 | 默认收起；尊重用户展开选择 | 点击后可打开约320–360px右侧面板，满足空间条件时并排 |

右侧面板采用可用内容宽度判断：需要至少“640px对话 + 320px面板 + 48px间距/留白”。若侧栏展开后不满足条件，则退化为覆盖面板。不要只看整个窗口是否达到1200px。

活动面板与成果预览默认共用一个辅助区域，不同时堆叠两条右侧栏。打开成果时提供返回活动的路径；关闭后回到对话。不要自动关闭用户主动打开的面板。

移动端使用动态视口高度和安全区，键盘弹出后输入区仍可见。进入页面不自动唤起键盘。用户正在读历史时不因进展更新跳到最底部；提供“新消息”入口。

## Ada 正在做什么：按需感知

区分两种工作：当前回复的过程，以及已经委托的后台任务。不要用一个“忙碌”状态混淆它们。

1. 当前回复：消息位置展示一行真实阶段，例如“正在查找相关资料”；提供停止回复。只有运行时有可靠事件时才展示具体阶段，否则使用中性等待提示。原始工具日志继续保持折叠/隐藏，不呈现模型内部推理。
2. 后台委托：页头活动入口按需展示“推进中 2”“待你确认 1”。它是查看进展的入口，不在每条消息旁重复展示。等待外部条件的事项不得计作等待用户确认。
3. 结果和决定：与当前对话有关的完成事项用紧凑成果卡片承接；需要用户决定的事项明确说明问题和操作。普通阶段变化只更新活动面板，不持续插入消息。

显示优先级：需要用户决定 > 新结果 > 正在推进 > 无活动。无活动时保留普通入口，不显示“空闲中”或持续闪动的头像。已有后台事项不能让当前聊天看起来不可用。

活动面板排序：待用户确认、执行中、等待条件/阻塞、最近完成。首屏显示少量相关事项，每项仅标题、真实状态、更新时间和必要的下一步；更完整的信息进入任务详情。失败需说明影响和可采取的行动。

所有状态以真实运行/任务事件为依据。没有阶段数据时不编造进度、百分比或预计时间。断线时保留最后状态并说明更新暂不可用，不能显示完成。

现有活动接口主要提供派发任务列表；页头未读、待确认汇总和成果去重送达应在确认后端语义后再实现，不能从任务总数直接推断。

## 完整交互示例

用户点击 Ada → 进入上次对话且侧栏收起 → 输入“帮我整理一下这周的安排” → 当前消息位置显示真实处理状态 → Ada 返回建议。

如果用户进一步委托长期事项，Ada 在对话中确认已接手并给出任务入口；页头出现推进中数量。用户仍能继续讨论其他问题。

需要用户选择时，对话出现一张决策卡：“两场会议冲突，优先保留哪场？”并提供明确选项。只有真实需要决定才打断；用户确认后卡片显示已处理，活动状态同步变化。

用户点进展 → 查看简短任务列表 → 查看某项详情 → 关闭回到原阅读位置与草稿。用户打开导航进入项目 → 恢复工作布局 → 再回 Ada 时恢复 Personal 布局选择。

## 实施顺序与验收

第一阶段只做布局：Personal 独立导航偏好、默认收起、手机隐藏底部导航、阅读宽度统一、页头操作收敛、活动在手机使用面板。复用现有活动数据，不新增完整任务看板。

第二阶段在任务状态和事件语义可靠后加入待确认提示、结果提示、关联成果卡片和可选宽屏辅助面板。

验收重点：

- 首次进入、返回、刷新、深链接、前进后退行为一致；全局导航偏好不被改写。
- 手机键盘、安全区、320px窄屏、横屏、桌面缩放及长名称下，输入和恢复导航入口始终可用。
- 收起导航、查看活动、切换成果预览均不丢草稿、不重载聊天、不改变阅读位置；用户在底部时仍正常跟随新回复。
- 隐藏导航不进入键盘Tab顺序；关闭弹层后焦点正确恢复；减少动态效果偏好受到尊重。
- 当前回复、后台执行、等待条件、等待用户确认、失败和断线具有可区分的呈现。

上线后观察首次发送耗时、进入后手动展开导航的比例、任务结果找到率及待确认事项响应耗时。侧栏展开率高意味着默认策略需要调整；停留时长不单独作为专注改善的证据。

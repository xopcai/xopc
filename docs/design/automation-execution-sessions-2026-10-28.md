# 自动化下的执行会话导航

日期：2026-10-28 · 状态：已实现（旧 transcript 无定位标识时回退到完整会话）

## 产品目标

参考用户提供的 Codex 截图：自动化作为父项，其产生的执行可以在下方直接找到。用户从“这件事”出发查看历次执行、阅读结果和继续追问，不必从普通聊天列表寻找同名会话。

推荐在现有自动化工作区的左侧任务列表增加二级导航，右侧直接阅读执行会话。首期覆盖 Gateway Web 及复用该 Web 的桌面界面；原生移动端另行适配。

## 当前基础

- `web/src/features/automations/automations-workspace.tsx`：已有左侧 `AutomationList`、右侧任务工作区，支持 `automation`、`run` 查询参数。当前选中 run 会打开运行详情弹窗。
- `automation-conversation.tsx`：右侧目前是配置会话加执行摘要时间线，并非所选 run 的执行会话。
- `automation-api.ts` / `src/automations/storage/automation-run-repository.ts`：run 已保存 `automationId`、`conversationId`、状态、摘要、时间和 `readAtMs`。现有列表支持按 automationId 查询，只有 limit，没有游标分页。
- `src/gateway/automation-agent-session.ts`：会话 metadata 已含 `customData.automationId` 和 `latestAutomationRunId`。后者会随运行更新，不能用来还原历次执行。
- `src/automations/service/action-executor.ts`：独立运行创建新的执行会话；continuous 在前次模式及助手匹配时复用会话，切换助手等情况会创建新会话。

## 信息层级

```text
自动化
  ▾ 每日 Tool 成功率报告                  ⋯
    下次 明天 10:00 · 每天
      今天 10:00 · 执行中
      昨天 10:00 · 已完成                未读
      10月26日 10:00 · 失败
      查看全部执行
  ▸ 每周项目周报                         ⋯
    下次 周一 09:00 · 每周
```

父项代表自动化定义，子项代表一次执行，以 runId 为唯一标识。用户界面称“执行记录”；每项进入对应执行会话。即使 continuous 共用 conversationId，也保留多条执行记录，避免合并后丢失每次执行的状态和时间。

子项无需重复完整自动化名称；优先显示时间及状态，摘要只作可选第二行。截图中同名条目难以区分，xopc 用日期区分。

## 核心交互

| 操作 | 结果 |
|---|---|
| 点父项名称 | 打开该自动化的配置对话及概览；保持现有编辑能力 |
| 点独立展开按钮 | 展开/收起最近 3 次执行，不切换右侧内容 |
| 点执行子项 | 右侧打开执行阅读面板，展示结果及对应会话 |
| 点“查看全部执行” | 展开该自动化历史列表，每页 20 条，支持继续加载 |
| 点右侧“运行详情” | 打开现有详情弹窗，查看事件、错误、投递和终止信息 |
| 在执行会话追问 | 在该 conversationId 发起普通会话轮次，不改变自动化配置 |
| 点“调整自动化” | 回到该父项的配置对话，显式携带所选 run 作为排障上下文 |

父项保留下一次执行、频率和菜单（编辑、暂停等）。只有子项高亮表示当前阅读对象，父项用轻量强调表达归属，避免两个选中块争夺注意力。默认展开当前自动化；其他父项折叠，手动展开状态按网关及用户在本地保存。

运行出现时更新所属父项与执行列表，不主动切换阅读对象，也不因新 run 到来强行展开其他自动化。列表以创建时间倒序，使用 runId 作为同毫秒的稳定排序条件。

## 右侧阅读面板

顶部固定显示“自动化名 / 本次执行时间”、状态、返回自动化和运行详情。正文复用聊天消息阅读与工具过程展示，呈现真实 transcript，不把 summary 当完整会话。

- **独立运行**：打开该 run 的 conversationId，可直接查看全过程。执行中复用现有会话流式更新。
- **延续运行**：打开共享 conversationId 并定位到本次运行起点，显示“多次执行共用此会话”，提供“查看完整会话”。定位需要验证 transcript 与 runId 的实际关联能力；不能仅依赖 latestAutomationRunId 或按时间猜测。
- **首期定位能力未具备时**：先显示所选运行的摘要及状态，明确按钮为“打开共享会话”，不可让用户误认为看到的是本次执行的独立 transcript。精确定位是增强项。
- **追问**：独立运行结束后启用输入框；当前会话仍在运行时，说明“执行中，完成后可继续追问”。continuous 模式提示追问会进入后续运行上下文；普通追问不回写历史 run.summary，不将历史成功状态重新改为执行中。
- **无 conversationId**：排队中显示等待开始；非 agent 动作显示结果和事件详情；准备阶段失败显示错误。所有执行仍有子项，不因缺会话消失。

## 状态与边界

- 已完成、失败、超时、取消、排队、执行中、取消中均有文字，颜色仅辅助区分。
- 展开列表、点击父项均不标记子项已读。仅在目标终态运行内容成功显示后标记该 run 已读；加载失败保持未读。阅读期间由运行中转为终态，也需在内容显示后处理。
- 父项未读标记汇总自身全部终态运行，不能从全局最新 50 条推断；首期无准确总数时只显示未读点。
- 无执行显示“尚未执行”，附现有“立即运行”入口。加载使用局部 skeleton，失败在子列表内重试，不影响其他父项。
- 会话删除但 run 保留时仍可阅读摘要和详情，显示“执行会话已删除”；不生成替代会话，不修改历史关联。
- 删除自动化沿用当前删除策略；当前存储层会删除其运行记录，不在本功能中引入孤立历史导航或额外级联删除会话。
- 普通聊天列表首期保留现有可见性规则；自动化页增加归属入口。后续如需默认隐藏自动化会话，单独设计发现、置顶和搜索规则。
- 任务筛选匹配父自动化，执行子项保持在父项内。通过深链接打开的对象即使不符合当前筛选，也应明确提示并提供清除筛选入口，不能悄悄切到首个任务。
- 小屏幕使用“自动化列表 → 执行阅读”单栏导航；返回恢复展开状态、已加载历史和滚动位置。

## 技术方案

### 路由与组件

推荐保留 `/automations?automation=<id>` 作为配置入口，新增 `view=execution` 区分执行阅读：

```text
/automations?automation=<id>&run=<runId>&view=execution
```

现有只有 `run` 的链接继续进入原详情交互，避免改变旧通知和产品链接语义。新子项链接使用 execution 视图。进入时按 runId 单独拉取，验证 run.automationId 与父项一致，再解析 conversationId；不依赖最近列表命中。切换父项清除 run/view，浏览器后退恢复上一个选择；用户导航使用 push，状态同步使用 replace。

建议从现有大文件抽出：`automation-navigation.tsx`（父子列表）、`automation-run-list.tsx`（分页及局部状态）、`automation-execution-panel.tsx`（会话阅读、无会话回退）。配置面板继续使用 `AutomationConversation`。执行面板不得传入配置专用 `automationWorkspace` 语义，以免普通追问被当成配置指令。

### 数据与请求

首期复用按 automationId 查询 runs 的现有接口，展开时懒加载，SWR 以 automationId 缓存；先展示最近 3 条。不要为所有父项挂载详情请求，也不要把当前全局 50 条按自动化分组后视为完整历史。

“全部执行”需给现有 `/api/automation-runs` 增加向后兼容的游标参数及响应字段：`cursor`、`nextCursor`、`hasMore`，保留 `runs`。游标对应 `(createdAtMs, runId)`，查询带 automationId 和现有访问范围。响应去重、翻页和新记录插入均按 runId。

如果需要首屏准确显示各父项最新执行及未读信息，给自动化列表增加可选的批量执行概览投影，或新增按当前页 automationIds 的批量读取接口；不得让每个父项独立轮询。列表摘要只带少量展示字段，不返回完整 transcript。

历史身份直接复用 automation_runs.conversation_id，不增加第二套会话注册表。仅导航和分页不需要数据库 schema 变更；精确未读聚合应检查现有索引与查询计划。continuous 精确定位如需增加持久化入口标识，应单独设计兼容升级并复用 SQLite transcript 写入链，不能添加 turn-end save。

复用现有 realtime 能力前先核查自动化运行事件的实际覆盖，若不足则对展开列表使用自适应轮询（活跃时短间隔、静止时降频、页面不可见暂停）。会话实时消息复用已有聊天链路。

如新增 authenticated API 路径，必须同步 lazy-bundles matcher、正负映射测试，并通过带认证的实际 Gateway 路径验证。

## 实施顺序与验收

1. **可用入口**：父子导航、最近 3 次执行、独立运行嵌入会话、无会话回退、深链接及后退；continuous 明确打开共享会话。保留原运行详情与配置入口。
2. **完整历史**：稳定游标分页、准确未读汇总、局部刷新、窄屏返回恢复。
3. **共享会话定位**：核实或补充 run/transcript 的稳定关联，再支持 continuous 按执行定位。

核心验收：两个独立 run 打开不同会话；continuous 的两个 run 保持不同选择且如实说明共享会话；旧于全局最近 50 条的执行可直接打开；执行中更新不抢走用户选择；失败、无会话、会话删除均可查看；展开不清未读；打开失败不清未读；浏览器前进后退及项目筛选不串对象；分页无重复和遗漏。新增接口还需覆盖跨项目访问范围和真实 Gateway lazy-load 路径。


## 2026-10-28 实现记录

- 已抽出 `automation-navigation.tsx`、`automation-run-list.tsx`、`automation-execution-panel.tsx`，接入现有可调宽度的自动化工作区。
- 子项默认最近 3 次，按自动化懒加载；全部记录使用每页 20 条的游标分页，游标绑定 automationId / projectId。已加载多页历史时暂停自动轮询，避免浏览过程中重排；页面刷新入口可手动更新。
- 自动化列表一次性返回所属范围的未读聚合；展开和父项选择不清未读。执行面板等待会话正文实际载入后确认已读；无会话结果可直接阅读。
- 现有执行消息通过 `SessionToolResultGuard.setActiveTurnId(runId)` 保留 turnId。共享会话打开后，`use-initial-turn-navigation.ts` 按 turnId 定位，必要时加载较早消息；无标识、历史已被清理或翻页无进展时明确回退到完整会话。无需数据库升级。
- `conversationShared` 为基于历史运行关联的只读投影，避免切换运行模式后误判。共享会话的追问上下文提示仅在当前配置仍使用 continuous 时展示。
- 新执行阅读链接使用 `view=execution`；旧 run 链接继续打开详情。详情弹窗关闭保留当前执行选择。父项配置清除执行参数；排障配置保留 focusedRunId，避免再次打开配置会话将其清空。
- 浏览器使用隔离接口数据验证了展开、执行选择、运行详情、保持执行 URL、窄屏返回列表和无横向溢出；API 另通过真实带认证的 Gateway / lazy bundle 路径验证分页、未读和共享会话投影。

验证结果：29 个测试文件、235 项测试通过；`pnpm run typecheck`（含 Electron）、Web type-check / build 以及本次修改的 Web 源文件 ESLint 均通过。构建仅有现存的大 chunk 提示。

# 模型服务连接与用途配置：通用接入设计

状态：通用接入、用途预览/应用与后台使用范围校验已实现；下文保留完整设计目标，实际交付边界见末尾实施记录。
日期：2026-10-16
范围：XOPC Cloud、API 服务、Token/Coding Plan、本地与自定义服务。

## 产品决策

统一入口为「连接模型服务」。用户选择品牌和接入方式、连接账号，再一次应用推荐用途。Token Plan 是服务的一种接入方式；不为每个套餐维护独立组件。

「连接」回答凭据和地址是否配置；「分配用途」回答哪些功能使用哪些模型。两者共用一个流程，但具有独立状态、错误和重试边界。一份凭据可以支持多个能力，但不意味着这些能力都已适配或都获套餐授权。

推荐采用两层界面：模型设置主页面展示「我的服务」和「模型用途」；连接弹窗完成一次服务接入及用途预览。首次引导复用相同流程，不再各自实现配置逻辑。

## 现状与需要收敛的问题

- `bailian-subscription-setup.tsx` 已复用首次引导和服务管理，但模型选择、用途列表、地址、Key 前缀及文案均绑定阿里订阅。
- `bailian-subscription-plan.ts` 在前端硬编码模型优先级，并直接合并全局配置。未来每家服务复制一份会产生多个规则来源。
- `default-model-success-step.tsx` 有另一套聊天/视觉设置流程；应并入相同用途预览与提交机制。
- `domestic-presets.ts`、provider presentation/enrichment、pi 目录及图片/语音目录各有职责。需要统一投影到设置视图，不应把模型能力再复制进一份前端 registry。
- `/models` 发现目前只能可靠取得模型 ID。成功列出 ID 不能证明视觉、工具调用、套餐授权或某项媒体协议可用。
- `CatalogModel` 已有多种模型与 operations，`CatalogSource` 已有推荐字段，可以扩展设置视图；无需再造一个模型存储系统。
- 当前后台路径在专用 intent 缺失时可能回退到默认聊天。仅保留 `understanding` 原值或显示“仅交互使用”，不足以隔离订阅与后台任务。

## 设置主页面

保持现有导航。模型页将已连接服务与用途分配放在同一页；图片、语音详细参数页仍保留，作为用途行的深入设置入口。

「我的服务」每个连接一行，展示：品牌、接入方式、地域/账号标签、连接状态、已使用用途；操作为「管理」。页级主操作为「连接服务」。

示例：

- 阿里云百炼 · 个人订阅 · 北京　用于对话、看图、画图
- XOPC Cloud · 账号登录　用于语音、电脑操作
- 本地模型 · 本机　用于后台整理

「模型用途」按用户任务显示：对话与任务、看图、画图、后台任务、录音识别、语音合成、实时语音对话。每行可直接点击当前模型，从按服务分组、可搜索的下拉列表中切换；只列出已接入服务中支持该用途和使用范围的模型。选中后保存单项用途，并显示切换中、成功或具体错误；没有可选模型时引导接入服务。音色、流式听写和电脑操作保留详细设置。服务列表与用途行从实际生效配置计算，避免增加一份独立的分配记录。

同一模型可承担多个用途。默认不要求用户分别选择 fast/reasoning/coding/review；在「对话与任务」下显示“已分配快速与复杂任务模型”，按需展开细项。

语音展开后分别显示识别、合成、实时对话，分别计算就绪状态；不会用单一“语音已连接”掩盖部分能力缺失。电脑操作只有存在专用 profile 且原生环境就绪时才能选择。

## 连接弹窗：推荐方案

### 选择服务

品牌优先展示，如阿里云百炼、XOPC Cloud、OpenAI、本地与自定义；可按名称和别名搜索。品牌相同的按量 API、订阅、中国/国际接入不再铺成多张平级卡片。

选择品牌后，只有存在多个选择时才显示「接入方式」选项，例如「订阅套餐 / API 按量」。地域与个人/团队只在影响真实 endpoint、凭据或权限时显示，不预设猜测用户套餐。

XOPC Cloud 只显示账号登录；本地服务只显示地址及按需鉴权；订阅显示套餐凭据；团队专用地址通过对应 profile 的地址字段接入，不强迫用户退回整个高级配置流程。

首次引导可保留 XOPC Cloud 快速登录和「连接已有服务」两个入口；常用订阅通过相同品牌选择列表进入。设置页可展示最近使用品牌，不长期为某一家新增专属导航按钮。

### 连接与推荐用途

弹窗只有一个主操作：「连接并应用」。输入区域显示所需凭据和获取入口；默认地址不要求用户填写。用户展开「连接详情」时才看到 endpoint、协议或额外字段。

凭据字段来自接入 profile；模型用途列表来自当前目录、适配器、使用范围和配置差异的交集。未连接时的目录是预览，不标成已验证可用。

用途列表例：

| 用途 | 推荐结果 | 本次处理 |
| --- | --- | --- |
| 对话与任务 | 快速模型 + 复杂任务模型 | 可选择应用 |
| 看图 | 支持视觉的模型 | 已有设置时默认保留 |
| 画图 | 已适配的套餐图像模型 | 可选择应用 |
| 语音 | 当前服务已配置 | 保留；若新服务仅部分就绪，展开显示具体项 |
| 后台任务 | 订阅不适用或范围待确认 | 不分配此订阅 |

显示用户能采取的动作，不用长篇说明填满主界面。文案区分“服务未提供”“套餐不包含”“客户端尚未支持”“需要另一个凭据”“范围待确认”。不能选择的行提供短原因及必要的说明入口。

模型详情默认折叠。展开后可从经过用途过滤的目录选择具体模型，展示“当前 → 推荐”及受影响设置。模型 ID 放在详情；常规行使用本地化名称。

### 合并规则

- 首次安装、用途为空：默认应用该来源能配置的全部用途。
- 已有配置：默认「补齐未配置用途」，保留已有来源；可切换「改用此服务」，再逐项取消。
- 所选用途存在配置时，预览必须显示替换关系，不能仅列出新模型。
- 只更新用户勾选的用途；Agent/会话显式覆盖继续生效，并在影响说明中告知。
- 当前有效用途以解析后的实际配置判断，不仅检查空字符串。例如默认指向未授权 XOPC Cloud 的对话路由，应显示“待连接”，允许用户直接用新服务补齐。
- 语音音色、尺寸、采样率等仅在实际变更能力时调整；已有高级选项若与新模型不兼容，在预览中显示需重置项。

提交前显示“将配置 N 项，保留 M 项”。这表达本次动作，不用“所有模型已支持”一类过度承诺。

### 执行与反馈

流程：解析 profile → 连接/保存凭据 → 尝试取得可用性证据 → 重新生成配置预览 → 一次应用所选用途 → 显示结果。

能无付费验证时使用厂商明确支持的只读接口；不能把 `/models` 200 当作模型调用验证。没有非付费验证方式时，状态显示「凭据已保存，调用未验证」，提供用户主动发起的测试；任何可能消耗额度的测试必须明确标注，不能偷偷用生成图片或语音作为探测。

若连接后获得的真实目录与预览不同，只要更换了模型、改变收费范围或减少用途，就返回更新后的预览让用户重新应用；不能静默选择另一家或另一个付费套餐。

凭据保存成功、用途更新失败时：显示「服务已保存，用途配置未完成」，保留重试入口；重试只执行未完成阶段。用 requestId 去重提交并忽略过期的探测结果。保存中冻结可变选项。

完成后逐项展示“已应用 / 已保留 / 待测试”，并可直接开始对话。最近一次提交保留有限的变更快照；「撤销用途更改」只恢复仍与本次结果一致的字段，遇到后续更改先展示差异。撤销不删除新连接的凭据。

## 通用接入描述

建议新增服务端 `ProviderSetupProfile`，只描述连接和配置方法。模型数据继续来自 pi、云目录及实际能力适配器。

```ts
interface ProviderSetupProfile {
  id: string;                       // 稳定的接入方式标识，非模型 ID
  brandId: string;                  // 只用于界面分组
  runtimeProviderId: string;        // 复用 pi 或现有自定义 provider ID
  access: 'account' | 'subscription' | 'api' | 'local';
  region?: string;
  audience?: 'individual' | 'team';
  credential: {
    mode: 'oauth' | 'api-key' | 'optional' | 'none';
    fields: Array<{ id: string; label: string; secret: boolean; required: boolean }>;
    acquisitionUrl?: string;
  };
  endpoint: { defaultUrl?: string; editable: boolean };
  catalog: { source: 'pi' | 'remote' | 'discovery' | 'curated'; providerId: string };
  bindings: Partial<Record<CapabilityOperation, {
    adapterId: string;
    credentialProviderId: string;
    endpoint?: string;
  }>>;
  usagePolicy: {
    interactive: 'allowed' | 'denied' | 'unknown';
    background: 'allowed' | 'denied' | 'unknown';
    crossSourceFallback: 'opt-in' | 'disabled';
    evidenceUrl?: string;
    checkedAt?: string;
  };
}
```

其中 `CapabilityOperation` 是现有聊天、图片生成/编辑、语音识别/合成/实时对话等 operations 的投影，不能用品牌名推断协议。背景使用限制应有来源及核实时间；未知不能当作允许。

新增一种 Token Plan 的正常工作应为：补一个 profile、绑定已有 pi provider 与适配器、添加推荐偏好和测试。只有协议不同才写新适配器，不新增套餐专用 React 组件。

第一阶段继续按 runtime provider 管理一份有效连接与凭据，不实现同一 provider 多账号切换。品牌、接入 profile 和连接状态是设置视图概念，不引入第三层 Agent 配置。若团队地址会与个人版冲突，生成独立自定义 provider ID；不能让两张界面卡片实际竞争同一个 Key。

## 模型能力、授权与推荐

可分配某用途的前提是：协议适配器已实现、目录声明该能力、凭据绑定完整、套餐授权没有明确否定、请求使用范围允许。各证据分别保留，避免把“知道该模型”标成“账号已获授权”。

只读发现无法确认授权时仍可展示目录，但附上未验证状态，不自动启用未经核实的媒体能力。目录元数据合并时优先保留 pi 的视觉、思考等级、上下文及兼容字段；不能用发现得到的纯文本占位元数据覆盖它们。

推荐引擎由服务端执行：

1. 按连接、用途、可用性证据和使用范围过滤。
2. 保留仍适用的用户显式选择。
3. 优先厂商明确给出的对应用途推荐。
4. 应用经过核实的 provider 偏好，如快速/复杂任务优先顺序。
5. 没有依据时要求选择，不按数组首项、名称排序或虚构性能评分选模型。

输出具体 `provider/model` 引用及推荐理由，写入现有模型配置；不会增加一个隐藏运行时自动路由层。目录更新只改变候选项和下一次预览，不自动改动当前已选模型。

媒体模型通过各自适配器注册；同一凭据通过 binding 引用。图片、TTS、STT、实时语音可以是不同 endpoint 与协议；不复制 Key，也不把聊天 endpoint 拼接成媒体地址。

## 使用范围与回退：必须进入运行时

订阅限制不能只是一段配置提示。请求需要带可信的调用来源：用户交互、定时任务、系统后台、未知。子任务和工具调用继承入口来源，模型不能通过提示词自行声明“用户交互”。

任何模型调用前，包括聊天、工作流、媒体、重试和子 Agent，都执行来源与 usagePolicy 检查。交互受限的 profile 不能通过默认 chat 继承、缺失 intent 回退或 tool 内调用进入后台。

为后台提供独立且明确的 `models.background` 路由（可选字段），并复用现有全局默认与 Agent 覆盖两层。后台显式指定的模型同样检查范围。旧配置中后台继承 chat 的行为只在该来源允许后台时保留；受限或未知时显示待配置并暂停相应调用，不偷偷选择其他收费来源。

跨来源回退一律需要用户明确选择。订阅可在同一收费范围内配置经过允许的模型回退；额度用尽不能自动绕到按量服务。提供「额度不足时停止」的简洁默认说明，高级设置才显示具体回退列表。服务断连时将受影响用途标为待配置，历史会话保留。

## 提交与配置存储

复用现有凭据服务、pi ModelRuntime、ModelCatalogStore、全局默认和语音配置。新增的是连接 profile 与配置协调服务，不是新的配置真相来源。

- 前端请求服务端生成 `SetupPreview`：profile、配置版本、目录版本、所选用途、具体变更、跳过原因、所需验证和风险提示；不包含凭据明文。
- 前端提交 `previewId` 和用户选择；服务端校验版本后应用。过期预览重新生成，不能覆盖用户同时在另一个窗口做的设置。
- 凭据保存与用途应用是两个可恢复阶段。当前只涉及全局模型时，可用一次既有全局配置写入；未来同时更新模型和语音时，协调器先验证所有变更，再通过现有存储机制提交并发出一次 reload。
- 不声称跨文件/数据库天然原子。若现有仓储不支持事务，保存不含秘密的操作记录和旧值以补偿；失败时按实际结果返回逐项状态。
- HTTP 路由落地时同步更新 lazy-bundles matcher、映射测试及真实鉴权网关验证。
- 配置日志只记录 profile、用途、变更字段和错误阶段，不记录 Key 或完整请求内容。

建议文件职责：`src/providers/setup/profiles.ts`、`capabilities.ts`、`recommendations.ts`、`preview.ts`、`apply.ts`，配套共享 gateway-contract。前端为 `provider-connect-dialog.tsx`、`provider-connection-form.tsx`、`model-usage-preview.tsx` 与 `model-usage-list.tsx`。先按职责拆分，不预建完整插件框架。

## 迁移与实现顺序

1. 将阿里专用连接面板与 DefaultModelSuccessStep 收敛为通用 profile 表单、推荐预览和合并规则。保留现有 provider ID、凭据与所有模型引用。
2. 在新订阅入口扩大使用前补齐可信调用来源与运行时使用范围检查，覆盖默认 chat 继承路径；同时支持明确的后台用途状态。
3. 用三个现有接入方式验证抽象：阿里订阅、XOPC Cloud 账号、一个纯聊天 Token Plan（具体能力以已安装 pi 目录与厂商核实结果为准）。增加普通 API 与本地地址测试，避免“通用”仍只适用于订阅。
4. 把模型用途列表加入设置主页面；加入配置版本校验、重试和撤销。
5. 语音在订阅适配器完成后仅增加 capability binding；视频等新增能力按产品需求扩展，不提前挂不可用入口。

## 验收

- 同品牌按量/订阅可并存且凭据、地域、endpoint 不串用；Key 前缀只能辅助提示，不识别所有套餐。
- 新增一个使用既有协议的订阅不修改通用 JSX，不复制模型目录与 Key。
- 首次配置默认覆盖所有已就绪用途；已有设置默认补齐，替换前有真实差异。
- 仅聊天套餐、部分语音能力、自定义团队地址、不支持 /models、本地无 Key 都能完成接入。
- 请求失败、Key 过期、429、额度用尽、目录变化、两个窗口并发、部分保存失败均有明确恢复路径。
- 订阅被默认聊天继承到后台、显式后台模型、子任务、媒体或重试时，都不能绕过范围检查。
- 切换厂商不会自动引入新的付费回退；无可用后台来源时不偷偷消耗其他服务。
- 原有 Agent/会话覆盖、语音音色及未选用途不被无关改动覆盖。
- 明确区分已保存、鉴权验证、目录发现和真实调用验证，不展示虚假额度。
- 中文/英文、键盘、深色、窄屏与固定弹窗内部滚动可用；加载使用骨架，按钮进行中的短操作可用 spinner。


## 实施记录（2026-10-16）

已将阿里专用面板移除。首次引导、添加内置服务、已有服务管理、自定义服务保存后的用途选择，共用 `provider-setup-panel.tsx`。品牌下可切换接入方式/地域；默认补齐、主动替换、仅连接、逐用途更改共用同一页。主设置页增加对话、看图、画图、后台以及录音识别、语音合成、实时语音对话七项用途；音色、流式听写和电脑操作仍可使用已有详细设置。

服务端 `src/providers/setup/{profiles,engine}.ts` 投影现有 pi/媒体目录，执行推荐、能力过滤和配置合并。共享 `provider-setup` 契约以及 `/api/models/setup/:providerId` 的 GET、preview、apply 路由支持目录刷新与 revision 冲突校验。凭据保存后用途失败可重试；实际提交前同步重读配置，避免旧预览覆盖新配置。提交复用现有全局默认仓储，不增加第三层配置。

`models.background` 已加入 schema、两层覆盖解析、引用审计和默认模型解析。可信调用来源通过异步上下文传播；自动化、后台检查、持久学习与闲时压缩明确进入 background，同步子任务继承入口，未知来源不能调用受限套餐。聊天（包括 pi/扩展流）、图片、媒体理解、TTS 和语音 WebSocket 入口增加使用范围守卫；已识别订阅 endpoint 的自定义别名同样校验。拒绝发生在凭据/网络调用之前，并终止相关重试。

### 真实订阅 E2E（2026-10-16）

使用用户已保存的网关凭据，通过带鉴权的本地 Gateway 请求验证 Qwen 3.8 Flash/Max、视觉、Qwen Image 3.0 Pro、TTS 和录音 ASR。TTS 生成测试文本，ASR 正确识别出数字 4729；图片实际返回蓝色圆形 PNG。通过现有 Omni 引擎及同一份订阅 Key，验证了 Qwen Audio 3.0 Realtime Plus 的真实音频输入、转写和语音回复。后台范围验证在网络请求前拒绝嵌套升级。

实测发现并修复：部署的 TTS 返回 JSON 音频链接而非总是返回二进制；链接可能为 HTTP，现通过 HTTPS 获取同一签名资源，保留 SSRF 校验与禁止重定向；音频格式依据响应及文件头返回。图片诊断 HTTP 入口补上可信交互范围，后台守卫继续生效。常规语音与订阅语音配置没有混用或复制凭据。

用户当前保存的自然对话仍指向普通 DashScope（`alibaba`）。订阅实时模型验证使用运行时测试配置，没有改写用户的现有选择，因此不能将这项结果表述成“当前保存的自然对话已接入订阅”。测试会话均为临时会话，测试后删除；报告不含 Key 或签名音频 URL。

录音笔记补充验证：独立 worker 的分段转写和原音补转写原先缺少用户来源，误报 `unknown`。现在仅在领取用户提交的录音转写任务后建立交互范围；异步分发、断连和重启恢复不改变原请求的性质。显式后台或未知父范围仍不能升级，其他转写调用不受此入口授权。使用真实订阅 Key，在隔离 SQLite 中通过带鉴权、懒加载的录音 HTTP 路由上传同一段合成测试音频，两个实际 worker 均识别出“测试成功”；显式后台校验继续在请求前拒绝。可用 `scripts/verify-bailian-recording-live.mts --pcm=<16kHz 单声道 PCM16 文件>` 重复验证。

聊天生图补充验证：模型调用工具时常传 `aspectRatio: "1:1"`，尺寸型服务原先直接拒绝。现在共享图像包与 Agent runtime 在校验前将比例映射到目录中精确匹配的像素尺寸；相同比例与尺寸可以合并，不支持的比例、冲突尺寸仍拒绝，不放宽服务能力。工具描述补充当前配置模型及其能力，提示不因参数错误自行切换服务。真实临时聊天中让模型调用 `image_generate` 画跳舞的小猫，约 50 秒完成并通过带鉴权、会话范围校验的媒体接口读取 PNG 附件，服务始终为 `qwen-token-plan-cn/qwen-image-3.0-pro`，回退记录为空。`scripts/verify-bailian-live.mts --only=chat-image` 从原始 transcriptRows 验证工具结果，避免简化历史接口省略附件明细而误报超时。

用途行直接切换复用服务接入的 preview/apply API。候选项来自已连接服务的后端预览；每次选择重新预览并携带最新 revision 提交 `selected: [use]`，保留后台范围、语音绑定及并发写入校验。保存期间禁用其他用途选择，不提前展示未保存的模型，不自动重试冲突写入。用 `scripts/verify-model-use-switching.mts` 在隔离浏览器环境中验证七类用途、阿里与小米套餐、XOPC Cloud 后台模型、搜索、键盘打开、配置冲突，以及明暗主题和手机宽度；使用真实组件及配置引擎，API 和凭据模拟，不改动用户配置或调用付费模型。

复审补充：用途主列表读取后端的后台可用状态，避免普通别名掩盖套餐地址限制；关闭实时语音或选择 Agent 引擎时，不把残留的 Omni 配置显示为正在使用。分别补上别名状态和停用语音配置的回归。

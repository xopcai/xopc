# 笔记录音可靠性第一批落地：HarmonyOS 与 Web

日期：2026-10-15。对应 [可靠性审视](./note-recording-reliability-audit.md) 的原音持久化、异常收尾、重启恢复与故障测试。本次集中修改 HarmonyOS 与 Web/Electron 共用录音链路，未修改 iOS/Android 录音器或服务端录音协议。

## 持久化契约

“本机已保存”只依据已提交的连续音频分片；录制计时、网络请求发出或提交合成任务都不能作为保存凭据。实时转写失败不阻止原音采集、落盘和停止；本地原音只有在服务端确认完整附件存在后才清理，主动丢弃除外。

## HarmonyOS

- 新增 `discussionRecordingStore.ets`：独立加密 ArkData 数据库 `xopc-recordings.db`，使用 FULL synchronous。每个独立 WAV 与序号、时间范围原子写入同一行；会话标识、网关、服务端关联和重点标记持久化。
- 采集环每约 3 秒等待一次本地提交。网络任务只逐片读取本地音频，不再缓存所有待传 WAV；实时文字最多保留一个在途分片请求。弱网下内存不随整段录音增长。
- 本地会话先于网络会话建立。首次确认后按网关缓存 consent version，可在网关离线时开始采集；重试创建使用同一个本地 UUID 和原始录制时间。
- 正常结束和音频中断复用幂等本地收尾：停止读取、释放设备、等待在途本地写入、保存不足 3 秒的尾片。对原生 stop/release/read 的异常等待设有超时；网络同步发生在原音本地收尾之后。
- 写入失败时停止采集，保留已提交前缀。失败分片不会推进序号或已保存时间；可在重启后重试提交已保存部分。
- 主页启动读取未完成会话，按当前网关恢复；恢复会话尚未处理时不覆盖它。恢复读取只加载分片元数据，验证连续序号和时间范围；缺片时保留原音并报错。
- 停止/恢复时与服务端分片对账；本地确认过但服务端缺失的分片会重新上传。seal 响应丢失时先检查已有附件/任务，避免把已合成后的分片清理误判为录音丢失。
- seal 接受后仍保留本地原音。再次检查到完整附件后再清理；清理使用完成标记，初始化会完成上次中断的清理。
- 时长上限依据真实 PCM 字节数，暂停不计时；末帧截在两小时上限以内。UI 显示已保存时长、恢复状态、同步延迟和仅前台录音的降级状态。

后台录音申请与存储分离，申请失败会提示前台限制。这里不承诺系统强制结束后还能继续录音；恢复对象是已经提交的原音。

## Web / Electron

- MediaRecorder 的原音先停止，等待尾片及 IndexedDB 提交；实时 PCM 分段器取消独立进行。后续服务端利用原音补齐未收尾的实时文字。
- 正常停止、设备 ended、recorder error、自动停止和组件卸载汇聚到同一个停止 Promise；即使 recorder 已变为 inactive，也等待其最终 stop 事件，避免早于尾片完成保存。
- stop 事件缺失时超时退出并释放麦克风；已提交前缀仍可恢复。磁盘/配额错误冻结计时并停止采集，错误文案只承诺保留已写入的部分。
- 原音分片与对应元数据使用 strict IndexedDB 事务；任何同步 put 异常都会显式 abort，避免只写入音频却没有对应恢复元数据。
- 服务端关联更新进入同一持久化队列，避免覆盖并发音频写入推进的 chunkCount。
- 恢复时重新读取数据库中的最新会话，并只用 key cursor 验证分片连续性和数量，不全量加载音频 Blob。空会话和缺片不被标记为完整可恢复录音。
- 已加载且已鉴权的页面缓存首次确认，可在网关不可用时先录音。服务端创建失败后，结束/恢复使用相同录音 UUID 和录制时间重试。
- 原音保存完成后不再等待实时文字上传队列排空；避免实时 STT 不可用拖住笔记保存。
- 错误态显示录音中断、本机已保存时长和恢复操作；原音存储错误不再统一显示“草稿安全”。

没有增加离线应用壳或 Service Worker；Web 离线冷启动仍取决于页面加载与鉴权条件。浏览器强杀时最后尚未发出/提交的 MediaRecorder 分片不在保存承诺内，压缩容器的中断可解码性仍需按浏览器验收。

## 故障测试

新增 34 项自动化测试：

| 层 | 数量 | 覆盖 |
| --- | --- | --- |
| HarmonyOS 录音/本地存储 | 13 | 上传阻塞时继续提交、短尾片、中断、重开 SQLite、写入失败、离线启动、跨网关隔离、缺片、确认/服务端分片不一致、标记、原生关闭挂起、清理中断 |
| Web 录音 hook | 10 | 停止幂等、尾片、实时初始化挂起、stop 事件丢失、配额错误、元数据竞争、inactive 后的尾片、卸载恢复、实时资源清理抛错隔离、两小时分片序列、延迟超大分片背压 |
| Web IndexedDB | 6 | 事务回滚、前缀重开、数量不符、序号缺口、空会话、提交屏障 |
| Web 编排 | 3 | 离线本地开始与幂等建会话重试、实时上传挂起不阻断保存、恢复不触发并行自动结束 |
| Web consent 缓存 | 2 | 已确认缓存、损坏数据不绕过首次确认 |

HarmonyOS 的两小时存储测试写入 2,400 个独立 3 秒 WAV，PCM 共 230,400,000 字节；关闭并重新打开 SQLite，验证连续时间轴、分片数、首末分片及总字节数。它使用真实主机 SQLite 文件和薄 ArkData 适配器，原生采集、网络、加密 SDK 由测试替身提供；不是两小时真机麦克风测试。

测试入口：

```sh
XOPC_MEETING_LONG_SMOKE=1 XOPC_LOG_LEVEL=fatal pnpm exec vitest run src/discussions/__tests__ web/src/features/discussions/__tests__
pnpm exec vitest run --config "$PWD/apps/mobile-harmony/vitest.config.ts" --root "$PWD/apps/mobile-harmony"
pnpm run typecheck
pnpm -C web run build
```

最终结果：HarmonyOS 全量主机测试 115 个文件、759 项通过；录音服务端与 Web 回归 14 个文件、66 项通过（已显式启用服务端两小时原音测试，没有跳过项）。根 TypeScript 检查、Web 类型检查与生产构建通过。

另已执行修改范围的 Web ESLint、仓库配置的 HarmonyOS CodeLinter，以及 Debug/Release 未签名 HAP 构建。CodeLinter 的 error/warn 为零；启动图标尺寸的 suggestion 属于既有项目建议。Web 构建仍有现有的分包尺寸和重复动态导入提示。

## 验收边界

这批完成客户端原音安全边界与故障恢复主机测试。真机锁屏两小时、来电/蓝牙抢占、系统杀进程、原生加密数据库在低存储下的行为，以及不同浏览器压缩容器的崩溃恢复，仍须独立验收。已有旧版缓存目录缺少完整会话 manifest，本次恢复契约适用于新链路创建的录音。

增量上传性能、服务端补转写检查点、长录音多任务调度、完整恢复会话列表/原音导出和四小时扩时继续属于后续工作。

# 侧边对话生命周期：可预期地结束，顺畅地继续

状态：产品提案，未实现。日期：2026-09-07。

## 产品目标

侧边对话用于围绕主任务临时追问、比较和验证想法。用户应当可以放心离开，也能理解回来后发生了什么，并带走有价值的内容。

本次设计解决三个体验问题：面板开着却长期无人使用；会话消失时缺少解释；用户正在阅读或撰写的内容突然丢失。内存回收是约束，界面围绕用户的下一步设计。

## 现状与差距

- 服务端已有 30 分钟租约、每分钟扫描、每客户端 5 个和全局 50 个的默认数量限制。前端每分钟心跳续期，因此不是“无对话 30 分钟过期”。
- 会话及父上下文快照存放在内存中。删除会话会取消运行、移除条目与 runner 缓存；持续保留的 transcript 没有字节硬上限。
- 前端加载 404 时移除标签；心跳失败被忽略；没有明确的过期阅读态。
- 现有“收起整个面板”和“关闭一个对话”都使用 X，后果不同。pagehide 尝试删除客户端全部侧边对话，也会影响刷新恢复。
- 已有单条回复保存笔记、选中文本添加到主对话的能力，应继续复用。

## 首版决策

| 项目 | 规则 |
| --- | --- |
| 定位 | 临时侧边对话，顶部持续显示低强调的“临时”标记 |
| 默认有效期 | 连续 30 分钟没有对话活动后结束；首版统一默认，不增加设置入口 |
| 提前提醒 | 剩余 5 分钟时，在输入区上方出现单行提示，可主动“继续保留” |
| 过期结果 | 结束原会话；保留标签和有界的本页阅读内容；输入区改为结束卡片 |
| 主要下一步 | “新建侧边对话”；有未发送草稿时改为“新建并带入草稿” |
| 内容去向 | 已显示内容可复制、保存笔记、添加到主对话草稿；不会自动发送 |
| 打断规则 | 普通空闲过期不终止正在生成或执行工具的回合 |
| 刷新规则 | 活跃会话在原租约内可重新连接；刷新本身不删除，也不续期 |

30 分钟是首版产品默认值，不是已验证的最优时长。用上线后的过期与重建行为评估是否需要调整到 60 分钟。

## 时间与活动规则

1. 空对话从创建时开始计时。用户输入被服务端接受后暂停空闲倒计时；回合成功、失败或被用户停止后，从结束时间重新开始 30 分钟。
2. 回答澄清、提交审批决定，以及点击“继续保留”属于明确活动。待处理交互的回答被接受后，按运行或空闲状态更新计时。
3. 心跳、轮询、刷新、面板打开、鼠标移动、滚动、编辑配置不续期。输入未发送文字也不隐式续期；草稿必须单独保护。
4. 正在等待澄清或审批时，从提问/请求审批发出时开始 30 分钟等待期限。到期取消该等待，进入结束态；不自动批准，也不在新会话重放旧动作。剩余 5 分钟的提示出现在该交互附近。
5. 长回合采用独立运行超时与取消机制，具体沿用现有执行策略。浏览器离开不立即中断正在执行的任务；回合结束后才启动空闲计时。
6. “继续保留”从服务端接受该动作起延长 30 分钟，可重复主动使用。它不能复活已过期会话。
7. 服务端决定是否已过期。前端时钟只用于提示；倒计时到点先验证状态，短暂断网显示连接状态，不能自行宣布记录丢失。

## 用户旅程与界面

### 创建与正常使用

- 标题保留“侧边对话”，旁边显示“临时”。标记可点击或键盘聚焦，说明：“连续 30 分钟没有对话后自动结束。重要内容可保存为笔记。”
- 空状态：“无需打断主任务，在这里继续追问。”下方小字说明临时性；开始对话后不重复大段说明。
- 正常使用时不展示倒计时，不占用阅读空间。保持当前父任务、选中文本与权限信息。
- 明确解释生命周期不代表撤销效果：结束侧边对话不会撤销已经执行的工具操作，也不影响已保存的笔记或主任务。

### 即将结束

在输入区上方增加中性细提示条：“此临时对话将在约 5 分钟后结束。”操作为“继续保留”。仅在最后 5 分钟出现，按分钟更新，不显示秒级倒计时、不弹窗、不发系统通知、不抢焦点。

点击成功后提示条收起，短暂显示“已继续保留 30 分钟”。请求失败保持提示并给出“未能延长，请重试”；若已经过期，进入结束态。重复点击期间禁用按钮，防止重复请求。

阅读、选择文字、长草稿输入不会被弹窗打断。用户选择“继续保留”后可以继续阅读，不必为了续期发送无意义的消息。

### 已结束，当前页面还有内容

标签保留当前位置，附加“已结束”文字。消息不变灰、不突然滚动到最底部；当前选择和阅读位置尽量保持。底部输入区替换为中性结束卡片：

> 临时对话已结束
>
> 长时间没有新对话，此临时对话已结束。本页已显示的内容仍可复制或保存。
>
> **新建侧边对话**

如果有草稿，在卡片内保留可编辑的草稿区域，标记“未发送草稿”，主按钮改为“新建并带入草稿”。新建后只填入输入框，由用户再次发送；失败时旧草稿原样保留。

已有消息继续提供复制、保存笔记与选中文字添加到主对话的动作。依赖原运行的动作（继续生成、审批、重试旧工具）不再可用。

### 返回时原会话已不可用

没有本页内容时，在原侧栏内部显示紧凑空状态：

> 此临时对话已不可用
>
> 原对话无法继续，你可以基于主任务开始新的侧边对话。
>
> **新建侧边对话**

确定是空闲过期时标题可使用“临时对话已结束”；服务重启或未知 404 时使用通用“已不可用”，不编造原因。不显示原始 HTTP 错误，也不悄悄移除标签或关闭整个侧栏。

### 开始新的侧边对话

- 新建成功后在原标签位置替换为新的活动对话，避免标签越开越多。创建失败保留原结束卡片、草稿和阅读内容。
- 新会话使用主任务当前上下文。新建空状态显示“已使用主任务的最新上下文。上一段临时对话不会自动带入。”
- 有草稿时只带入草稿，不带入全部旧历史、旧审批或旧工具执行状态。
- 需要带上旧结论时，用户通过现有消息复制/选中操作主动带入。首版不自动总结，不为重建触发额外模型调用。
- 若旧阅读内容仍可见，新建按钮附近提示“新建后将替换当前临时对话”，给用户带走内容的机会。

### 收起与关闭

- 面板级操作改用收起图标，文案“收起侧栏”；只隐藏，不结束对话，不弹确认框，也不续期。
- 标签 X 表示结束并移除该对话。空对话、无草稿时直接关闭；有内容或草稿时复用现有确认流程，文案：“结束这段临时对话？未保存的对话和草稿将被清除。”
- 运行中关闭明确写“停止并关闭”，说明会停止当前回答；已完成的工具操作不回滚。
- 保留现有“不再询问”偏好，不新增多层确认。关闭已结束且无阅读内容/草稿的标签无需确认。
- 不在 pagehide 删除整个客户端：刷新、应用切换和浏览器返回缓存不是明确的结束动作。离开后的服务端空闲回收负责兜底。

## 内容保留边界

“已结束”表示不能继续请求原会话，不表示眼前文字必须立刻消失。服务端释放原 transcript 和运行资源；客户端只保留已经收到的阅读内容，不为此继续保活服务端。

- 阅读副本仅在当前浏览器页面内存中存在，不写入持久存储，不保证刷新后恢复；收起/重新打开及切换侧边标签时可保留。
- 为避免把服务端内存问题搬到前端，首版结束记录最多保留 5 个；阅读文本总预算建议 2 MiB，每条结束记录最多保留最近 20 条消息。超出时先裁剪最旧内容，显示“仅保留本页最近内容”。保留正文，不额外保留原始工具输出、图片二进制或父会话完整快照。以上为实现预算，压测后调整，不放进用户设置。
- 非活动的旧结束记录可按容量淘汰阅读正文，保留轻量结束标记；不在用户阅读时删除当前标签。
- 草稿独立于原会话和阅读副本管理。沿用输入长度上限；重建、网络失败、容量拒绝均不清空草稿。创建成功并完成草稿转移后才清理旧草稿。
- 用户明确关闭、当前页面刷新/关闭、退出账户时清理本页副本；切换账户或网关时不得显示另一上下文的旧内容。

## 异常与容量体验

| 情况 | 用户看到的行为 |
| --- | --- |
| 心跳失败、网络临时不可达 | “连接暂时中断，正在重连”；保留文本和草稿，不当作过期 |
| 返回页面/设备唤醒 | 先用骨架或原内容验证状态，再决定恢复输入还是结束卡片 |
| 发送与过期同时发生 | 服务端串行判定；接受发送则运行，拒绝则恢复原草稿并进入结束态，不丢字、不重复发送 |
| 回合仍在运行，用户已离开 | 继续执行，结束后再计时；取消由运行控制负责 |
| 等待澄清/审批超过期限 | “等待时间较长，此临时对话已结束”；旧按钮不可再提交 |
| 已有 5 个活动对话 | 提示“已有 5 个临时对话，请先关闭一个”；展示现有对话供切换或明确关闭，不自动删除活跃记录 |
| 网关全局容量不足 | “暂时无法新建，请稍后重试”；原草稿与旧卡片保留，不错误要求用户关闭其他人的对话 |
| 父任务不再可用 | 提示“主任务已不可用”；不显示注定失败的新建按钮，提供关闭侧栏 |
| 保存笔记失败 | 保留内容，显示可重试反馈；成功后才显示“已保存” |

## 首版范围与实现契约

首版包括：真实空闲期限、提前提示和主动延长、运行/等待状态区分、过期阅读态、草稿保护与重建、收起语义、刷新重连、内容保存动作复用、有界客户端副本。

后续再评估：完整临时对话转为独立正式会话、自动生成可带回主任务的摘要、用户自定义保留时间。首版不增加永久保留开关，不把过期自动转为归档。

实现需满足以下契约：

- 分开记录连接存活、对话活动、等待期限；心跳不再更新对话活动时间。已有 lastActiveAt 的含义必须调整或拆分。
- 在每个用户写入入口判定期限，并处理创建/清理/发送并发。过期后绝不通过心跳或延长请求复活；容量检查也需覆盖并发创建。
- 已知过期可返回独立的 EXPIRED 状态；授权匹配的客户端才可看到原因，未知 ID/归属不符继续使用通用不可用响应。结束原因记录必须有 TTL 和数量上限。
- 推送结束状态，并在心跳响应、重新连接、页面恢复时补偿查询。初次请求 404、发送失败和心跳结果统一进入同一个 UI 状态模型。
- 服务端清理运行、澄清、审批及订阅资源；客户端停止向已结束会话发送心跳并释放运行订阅，仅保留受预算限制的阅读副本。
- 新建请求进行中防重复；草稿只在新会话创建成功且填入后转移。新建不自动发送消息，不自动执行工具。
- 等待审批/澄清与运行状态需要准确反映到生命周期管理器，不能仅靠浏览器是否挂载判断。
- 长期持续对话的 transcript 大小仍需单独预算/裁剪；本提案的空闲期限不宣称解决所有内存增长问题。

## 验收与观察

1. 面板打开 30 分钟不对话且不主动延长，会结束；心跳不续期。
2. 25 分钟时出现一次轻提示；延长成功后消失，不重复弹窗或抢焦点。
3. 阅读或输入过程中到期，当前位置可继续阅读，草稿不丢；可以新建并带入草稿，等待用户发送。
4. 长回合超过 30 分钟不因空闲规则被终止；等待澄清/审批按独立等待期限结束。
5. 刷新活跃会话可在原期限内恢复；服务重启后显示不可用卡片，不静默删除标签。
6. 断网、过期、容量不足和父任务不存在分别给出合适反馈。
7. 关闭与收起后果清晰；标签位置和侧栏宽度不因状态变化跳动。状态用文字表达，键盘可访问，读屏只温和播报一次。
8. 空闲回收后服务端原资源可释放；前端结束副本数量和字节受限，切换账户会清理；不记录正文或草稿到行为分析日志。

上线后观察：看到结束态后新建成功率、带入草稿成功率、提前延长使用率、过期后短时间重建比例、保存内容成功率，以及服务端保留会话/内存趋势。先采集基线，不虚设提升目标；若大量用户在过期后立即重建，应优先调整默认时长和提示时机。

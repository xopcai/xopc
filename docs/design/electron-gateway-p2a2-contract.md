# P2a-2 独立设备认证与只读 Host 契约

2026-10-31：按用户功能优先指令，与S5长测并行开发。性能原预算和失败保留；本文件不将未完成阶段记作通过。

## 实施批次

1. D1 独立认证基础：复用设备配对请求、公钥请求证明、刷新轮换及撤销；新增desktop设备类型与独立版本发现路由。显式owner创建配对、逐个批准，禁止继承手机/浏览器默认scope或自动批准。首批仅提供设备自身身份读取/撤销和协议发现，不连接执行器，不注册Endpoint。
2. D2 Electron主进程身份保管与本机同意：绑定连接profile、Gateway id、公钥和本机设备私钥；安全存储、签名请求、原子刷新恢复。Renderer不持有私钥或长期凭据。关闭/撤销不自动重新配对，切换Gateway不继承本机授权。
3. D3 只读Host：独立clientId和每次重连connectionInstanceId；Host和Gateway同时校验允许的工具名称、独立scope与本机逐项授权。设备信息、截图等观察能力分项开放；不能因名称或声明只读就信任任意工具。
4. D4 回归与持续运行：真实认证入口、安装包本机同意/拒绝、过期/刷新/撤销/串设备/身份变化、聊天兼容但Host不兼容、隐私和本地模式回归；此阶段另做24小时固定场景，不借用S5聊天长测结果。

## 不变约束

- 不修改已有聊天bootstrap严格schema；独立 `/api/desktop-host/compatibility` 协商。
- 首批desktop凭据只能访问明确列出的自身路由；默认不具有聊天写入、服务器文件、手机控制、Endpoint登记、Realtime订阅或Gateway管理权。后续扩充须逐项验证和明确授权。
- 已配对desktop不得通过mobile目标邀请获得手机默认权限，不得使用浏览器native-host的自动批准路径。手机权限设置必须正向识别手机平台。
- 真实schema对平台和target字段存在CHECK约束，新增v263事务升级扩展枚举并保留依赖行，不删改v202起的任何已有升级链；验证全部支持起点、凭据/待批准请求保留、备份及完整性。历史request_proof_version=0保留但继续不能通过签名认证，不在迁移中重授权限。
- D1未完成D2/D3前不得声称可使用本机能力；旧本地Desktop Host保持原路径。
- 每批保留测试失败及修复后证据；缺少真实入口或安装包验证时明确列为未验收。

## D2接线约束

- 首次登记需要所选配置已有固定Gateway身份；主进程确认身份、检查独立设备协议，展示原生确认，再由owner建立/批准配对。连接配置页仅传epoch、profileId和动作，不接收设备/管理凭据。
- `检查登记`使用独立设备凭据；`停用登记`先在本机写入不可自动恢复的停用状态，再尝试服务器撤销。离线/401不冒充撤销确认。重新登记需另一次原生同意，并确认旧登记已撤销，不能借owner自动恢复被撤销设备。
- 当前只登记身份，不授权屏幕/文件/命令。只读能力继续在D3逐项同意；登记和观察授权不能互相代替。
- HTTPS和已有SSH loopback都维持remote模式；SSH登记使用独立的desktop SSH邀请路由，仅接受规范的loopback origin，不扩大旧mobile/browser邀请的HTTP边界，也不使用browser native-host自动批准。
- 用户关闭窗口、选择/切换/修改配置或返回本地时，取消待处理的原生确认和设备请求，旧结果不能更新新连接状态。主进程安全存储不可用时拒绝登记，不回落明文。远端聊天不依赖可选设备登记成功。

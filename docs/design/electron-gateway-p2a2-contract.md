# P2a-2 独立设备认证与只读 Host 契约

2026-10-31：按用户功能优先指令，与S5长测并行开发。性能原预算和失败保留；本文件不将未完成阶段记作通过。

## 实施批次

1. D1 独立认证基础：复用设备配对请求、公钥请求证明、刷新轮换及撤销；新增desktop设备类型与独立版本发现路由。显式owner创建配对、逐个批准，禁止继承手机/浏览器默认scope或自动批准。首批仅提供设备自身身份读取/撤销和协议发现，不连接执行器，不注册Endpoint。
2. D2 Electron主进程身份保管与本机同意：绑定连接profile、Gateway id、公钥和本机设备私钥；安全存储、签名请求、原子刷新恢复。Renderer不持有私钥或长期凭据。关闭/撤销不自动重新配对，切换Gateway不继承本机授权。
3. D3 只读Host：独立clientId和每次重连connectionInstanceId；Host和Gateway同时校验允许的工具名称、独立scope与本机逐项授权。设备信息、截图等观察能力分项开放；不能因名称或声明只读就信任任意工具。
4. D4 回归与持续运行：真实认证入口、安装包本机同意/拒绝、过期/刷新/撤销/串设备/身份变化、聊天兼容但Host不兼容、隐私和本地模式回归；此阶段另做24小时固定场景，不借用S5聊天长测结果。

## 不变约束

- 不修改已有聊天bootstrap严格schema；独立 `/api/desktop-host/compatibility` 协商。
- 首批desktop凭据只能访问明确列出的自身路由；默认不具有聊天写入、服务器文件、手机控制、Endpoint登记、Realtime订阅或Gateway管理权。后续扩充须逐项验证和明确授权。
- 已配对desktop不得通过mobile目标邀请获得手机默认权限，不得使用浏览器native-host的自动批准路径。手机权限设置必须正向识别手机平台。
- 真实schema对平台和target字段存在CHECK约束，新增v263事务升级扩展枚举并保留依赖行，不删改v202起的任何已有升级链；验证全部支持起点、凭据/待批准请求保留、备份及完整性。历史request_proof_version=0保留但继续不能通过签名认证，不在迁移中重授权限。
- D1未完成D2/D3前不得声称可使用本机能力；旧本地Desktop Host保持原路径。
- 每批保留测试失败及修复后证据；缺少真实入口或安装包验证时明确列为未验收。

## D2接线约束

- 首次登记需要所选配置已有固定Gateway身份；主进程确认身份、检查独立设备协议，展示原生确认，再由owner建立/批准配对。连接配置页仅传epoch、profileId和动作，不接收设备/管理凭据。
- `检查登记`使用独立设备凭据；`停用登记`先在本机写入不可自动恢复的停用状态，再尝试服务器撤销。离线/401不冒充撤销确认。重新登记需另一次原生同意，并确认旧登记已撤销，不能借owner自动恢复被撤销设备。
- 当前只登记身份，不授权屏幕/文件/命令。只读能力继续在D3逐项同意；登记和观察授权不能互相代替。
- HTTPS和已有SSH loopback都维持remote模式；SSH登记使用独立的desktop SSH邀请路由，仅接受规范的loopback origin，不扩大旧mobile/browser邀请的HTTP边界，也不使用browser native-host自动批准。
- 用户关闭窗口、选择/切换/修改配置或返回本地时，取消待处理的原生确认和设备请求，旧结果不能更新新连接状态。主进程安全存储不可用时拒绝登记，不回落明文。远端聊天不依赖可选设备登记成功。

## D3分批接口冻结

D3a先仅开放 `desktop.device.get_state`，返回平台、系统版本、语言、时区和采样时间，复用既有设备状态descriptor及Endpoint v2 invoke/received/result/cancel。截图是D3b的另一项明确授权，不以整个computer-control描述符冒充只读；文件、剪贴板、命令、URL打开和通知继续禁用。

- 新增 `desktop.observe.state` 独立scope；初始配对默认仍只有原有两项scope。owner通过独立desktop路由开关服务端观察授权，本机原生确认和本机内存授权同时成立才启动Host。设备可撤销自己的观察scope，不能提升scope。关闭/切换/重启不恢复本机观察批准。
- 服务端限制desktop凭据只有原认证路由及授权后的Endpoint身份登记、协议发现和Realtime ticket；不开放会话、文件、配置、手机能力、任意Endpoint调用/上传。登记绑定相同deviceId与P-256公钥，Realtime hello再核验设备、scope和允许的工具名称，不能靠descriptor自报read-only获得控制能力。
- Host使用独立clientId，每次重连新connectionInstanceId。独立Host协议能力增加已签名Gateway帧：确认及每个工具调用绑定Gateway、设备、clientId、连接实例和递增序号。本机在交给Endpoint控制器前验证，不信任同源代理提供的无签名工具调用；旧聊天和原本地Host不要求该扩展。
- 只读Host恢复沿用Realtime退避/心跳和取消；身份变化、401/设备撤销/授权撤销终止重试，本机停止立即关闭能力连接并清除本机批准。网络失败不影响聊天；停用服务器未确认时不宣称服务器撤销完成。
- 每个批次跑设备串用/公钥替换/伪造只读名称/无授权/签名帧重放/断网/撤销/切换/E2E及本地回归。D4专项长测另行并行运行，不等待S5长测结束。
- 观察授权使用持久化revision：主进程在原生确认前读取版本，确认后的POST必须匹配expectedRevision；撤销即使尚未收到授权也递增版本，迟到授权不能覆盖撤销。新增v264授权版本表，保留v202起全部升级链及v263独立设备凭据；旧版本不能直接打开包含新scope的v264数据库，避免同schema版本下旧程序误读未知权限。升级/回退依旧执行停机、一致备份和事务完整性校验。

### D3a结果

D3a设备状态只读Host已通过实际认证/签名协议及安装包原生逐项授权、实际Agent工具发现/调用E2E，本地spawn/reuse、旧schema262/263 Gateway复用和远端聊天回归通过。仅开启设备状态，截图与其他能力没有继承该授权。旧D1 `manifest` 继续描述凭据bootstrap默认权限，新增观察能力通过独立capabilities协商及显式grant开放；不修改聊天bootstrap。详情、原生副本标识差异、冷安全存储超时与模型fixture失败记录见[D3a证据](./evidence/electron-gateway-p2a2/observation-state-20261031/README.md)。接下来实施D3b截图，完整阶段及长测仍未验收。

## D3b截图接口与验收冻结

- 独立 `desktop.observe.screen` scope、`desktop.screen.capture` 工具和独立原生源选择。每次截屏再次确认源及接收Gateway；截图授权不继承设备状态批准，也不包含输入控制、文件、剪贴板或任意窗口选择参数。首版每次连接只启用一种观察能力，换能力先停止再授权。
- 来源由本机选择：当前远端聊天窗口，或本机选定显示器。远端工具参数为空，不能指定别的窗口/显示器。显示器先列无像素元数据，屏幕录制权限不足时拒绝；捕获只针对选定源，不读取其他屏幕缩略图。OS权限不通过远端请求自动提升。
- 复用Endpoint v2 uploadGrant和图像校验/内存帧预算。PNG最长边1280、单张不超过既有5MiB帧预算；设备签名请求绑定二进制摘要、endpointId、upload token及准确invocation路径。跨设备、无grant、过期、重复、取消、体积超限和非PNG拒绝；上传不自动重试。
- 传输缓存使用短期内存帧，经授权Agent单次消费后清零；不能通过通用附件接口下载，不创建持久截图文件。模型图像结果仍受既有会话存储策略管理，不声称对话中没有图像副本。授权/连接/前台状态变化或取消时不上传迟到截图，已发送的内容不能被追溯收回。
- Electron 45的屏幕获取使用独立的 `display-capture` 权限，不能借此开放摄像头/麦克风；元数据枚举设置零尺寸缩略图。接口依据[官方desktopCapturer文档](https://www.electronjs.org/docs/latest/api/desktop-capturer)及[45版变化](https://www.electronjs.org/docs/latest/breaking-changes)核对，原聊天session仍拒绝媒体权限。
- 复用持久授权revision，并为新scope升级应用数据schema到v265，使旧程序不会读取不认识的权限；全部既有升级链保留。验收包含本机拒绝/逐次确认、只捕获已选源、真实Agent图像结果、越权/上传故障/取消/撤销以及正式包本地和远端回归。长测、性能和其他平台缺口单列，不等待24小时后才继续开发。

# 从重复事务到可执行约定

状态：发布候选方案，2026-09-29。参考 [Matt Pocock 的 loop-me](https://github.com/mattpocock/skills/blob/main/skills/in-progress/loop-me/SKILL.md)，按 xopc 现有对象模型设计。首版复用 Note 与现有创建能力，不引入第二套运行时状态机。

## 用户要完成的事

用户说出一件反复发生、每次都要重新交代的事，xopc 帮他找出合适的触发时机、可用信息、可委托工作和必须保留的判断。讨论可以跨会话继续。结束时，用户得到一份可交给执行者的约定，或明确知道缺少什么；不会因为提到“重复”就自动开启后台运行。

用户侧入口用「帮我省掉一件重复事务」。已有明确目标的用户仍可直接创建 Task、Workflow、Automation 或 Scene，不必经过访谈。

## 产品边界

| 对象 | 在此方案中的职责 |
| --- | --- |
| Note | 保存访谈中的事务规格、已确认决定和未决问题；它是设计材料，不是运行时定义。 |
| Task | 承载有完成边界的一次性承诺及其验收。 |
| Scene | 承载长期持续帮助的目标、范围、来源和授权。 |
| Workflow | 承载稳定、需要复用或检查的多步骤执行方法。 |
| Automation | 承载手动、定时、Webhook 或产品事件触发；不替执行方法或授权做决定。 |

这延续 [Task Loop](../concepts/loops.md) 与[场景产品方向](./scenes-product-north-star.md)的分层。一个事务可能只需现有 Agent 和 Automation；也可能需要 Scene、Workflow，或暂时完全不需要自动化。不要新增第二套任务状态机或通用循环引擎。

## 对话与草稿

1. **理解现实环境。** 从当前对话、Project、用户上下文和已有授权来源取已知信息，记录用户使用的工具、渠道及术语。对无法访问的数据标记为待接入，不能假装已经观察过。
2. **提出候选事务。** 用户尚未指定事务时，基于已知材料给出少量具体候选及其预期节省的人工工作；用户选定一件后继续。不得把推测的私人习惯写成事实。
3. **逐轮澄清。** 每轮只问会改变设计的少量问题，每个问题给推荐答案和理由。优先处理触发信号、对象范围、输入来源、预期结果、权限边界、成功证据。答案一旦明确，更新同一份 Note，保存已确认与待确认的区别。
4. **收敛。** 展示一份简短约定：何时触发、做什么、何时保持静默、怎样证明一次运行完成、失败如何停下或升级、哪些动作需用户决定。以“实现者不必再问实质问题”为完成标准；无法回答的关键问题保留为未决，而不是填上猜测。
5. **转换。** 用户要求实施时，根据约定选择最小的现有产品对象，并把 Note 链接到产物。首次真实运行应可观察，结果应回填成功证据和偏差；设计完成不等于执行成功。

一个 Note 对应一个事务。Note 既允许未完成状态，也允许之后修订；转换为运行时对象后，运行时对象及其版本成为执行依据，Note 保留设计来由。不能从 Note 的修改自动扩大运行权限。

### 用户能看见的状态与下一步

每份规格只带一个设计状态标签：`recurring-work-draft`（还需澄清）、`recurring-work-ready`（可准备实施）或 `recurring-work-configured`（已创建执行配置）。所有状态均保留 `recurring-work-spec` 标签。旧规格或手工编辑导致状态缺失/冲突时，界面显示「需要核对」，只提供继续讨论，不把模型或用户写入的状态当成运行授权。

- 草稿：显示「继续补全」，预览中标明下一项待确认；不提供「准备实施」。
- 可实施：显示「准备实施」，先审查具体触发、来源、权限和通知，再按现有规则确认发布或开启。
- 已配置：显示已配置的执行对象链接与最近可验证结果；是否正在运行以 Scene/Workflow/Automation/Task 自身为准。Note 的状态标签不代表已开启。
- 无状态或冲突：显示「需要核对」，引导继续访谈并修复状态。

规格正文仍用用户语言。开头先给简短决策简报：预期结果、当前状态、下一项决策或行动，便于列表预览和详情阅读。其后至少包含目标、已确认决定、未决问题、触发、输入、结果、权限、单次成功证据与失败处理；不适用的项说明原因。状态标签是界面索引，不代替正文和运行时校验。用户手工编辑规格后，再实施时仍需重新校验。

### 列表与故障

「智能关注」页展示所有未删除的规格，不限收件箱状态；按更新时间分页，显示总数、状态、下一步和直接查看入口。加载失败须明确报错并可重试；空列表展示创建入口。规格详情应先给简短状态解释和下一步，再给完整 Note。无可用 Note 服务时，对话需明确告知无法跨会话保存。

### 语言

入口、按钮、错误提示和对话引导语使用当前界面语言（中文或英文）。用户在对话中明确指定语言时，以用户要求为准；切换界面语言不会自动翻译已有 Note。继续访谈时用本轮语言提问和写简报，保留 Note 原文语言，除非用户要求翻译。`recurring-work-spec` 等机器标识保持固定，不随语言变化。

## 规格需要回答的问题

这些是收敛检查，不是强制展示给用户的表单。简单事务可用几句话回答。

- **价值与对象：** 用户想减少什么负担，处理哪些对象，哪些对象不处理？
- **触发：** 哪个可观察事件或时间启动？事件可得且及时的场景优先事件；时间更符合用户意图时使用定时。重复事件如何去重？
- **输入：** 从哪些授权来源读取，缺失、过期或冲突时怎么办？
- **工作与产物：** 哪些步骤是确定性的，哪些需要 Agent 判断？交付物放在哪里？
- **权限与检查点：** 哪些操作可自动完成，哪些需用户决定？能否先完成收集、准备和验证，再一次性呈交决定？不需要检查点时明确写出原因。
- **简报：** 用户真正需要决定时，给出结果、依据、推荐选项、影响和产物链接；不把原始草稿当作通知。
- **单次运行边界：** 哪项可观察证据代表完成？无变化是否应静默？输入无法获取、验证失败或副作用结果不明时，是有限重试、跳过、暂停还是请用户处理？

## 一个例子

用户说「每周帮我梳理项目进展」。访谈不应直接生成周五 9 点的 Cron。先确认项目状态变化能否作为信号，用户是否只要周末简报，缺少哪些数据源，以及是否允许更新任务。

可能的结果是：每周五汇总本周发生变化的任务和笔记；无重大变化则保持静默；生成含风险、待拍板事项及证据链接的简报；任务修改只在获得具体确认后执行。若只是汇总，Automation 触发一个 Agent 可能足够；只有步骤需要稳定复用和单步检查时才创建 Workflow。

## 分阶段交付

1. **现在：skill 试点。** `skills/engineering/design-recurring-work/SKILL.md` 使用 Note 持久化访谈，给出推荐答案，产出可交接规格。复用现有 Note、`clarify` 和产品能力，不改运行时。先用真实事务检查问题质量和是否能跨会话继续。
2. **产品入口。** 「智能关注」页提供「帮我省掉一件重复事务」、已保存规格的继续入口和完整 Note 预览，调用同一 skill。后续可补充结构化未决问题与简报预览；用户不必选择底层对象。
3. **受控转换。** 当前「准备实施」进入同一 skill 的实施对话：先读取 Note，映射到现有 Scene、Workflow、Automation 或 Task 草稿，检查权限、来源、触发与通知，再按现有策略确认并试运行。后续可把这些步骤做成专门的一键转换界面。转换验证应指出当前运行时无法表达的要求，不生成貌似完整的配置。
4. **运行后修订。** 首次试运行记录触发原因、读取来源、产物、成功证据和人工介入次数。仅在失败或用户纠正后建议修订规格；已运行版本不因 Note 编辑而静默变化。

## 验收与指标

- 中断访谈后可从同一 Note 继续，已确认答案不会被重新追问；更改答案时能看出需要重审的下游决定。
- 没有可用事件、没有可验证成功信号或没有执行权限时，规格如实标记限制；不凭空生成触发器、凭证或授权。
- 简单事务不会被强制转换成多节点 Workflow；只有真实需要时才引入 AI、定时或人工检查点。
- 规格可由另一名实现者解释并落到现有对象，且能说清一次运行何时完成、何时停止。
- 试点关注每件事务的访谈轮数、重复提问、首次运行成功率、无效通知数、每次运行人工介入次数；不以创建 Workflow 或 Automation 的数量衡量价值。

## 发布门槛

1. **第一次使用：** 中英文界面用户能从「智能关注」理解这是设计入口，完成一轮访谈后看到保存的规格与明确下一步；未选择事务时不会生成空 Note。
2. **恢复：** 第 6 条及更旧规格能通过分页找到；刷新、换会话、切换语言或 Note 进入已处理状态后仍能继续；列表失败可重试，不会伪装成空列表。
3. **实施：** 草稿与旧格式不能直接进入实施；可实施规格在发布/开启前展示触发、来源、权限和通知，确认后检查实际配置及首次运行结果。结果不确定时显示阻塞，不宣称成功。
4. **运行闭环：** 配置状态与实际运行状态分开显示；首次成功、失败、无变化均留下可打开的运行对象或证据链接；用户可从原规格继续修订。
5. **验证：** 自动化覆盖状态判定、分页、错误恢复、中英文对话跳转和权限边界；在真实 Gateway 上走通一件从访谈到试运行的低风险事务，并记录用户是否能不靠开发者解释完成。未完成真实链路验证时标记为发布候选，而非已验证的正式发布。

## 暂不做

不自动扫描私人渠道寻找循环，不自动安装外部 `loop-me`，不新增 `workflows/*.md` 运行时来源，不允许设计 Note 绕过 Scene、Automation 或工具权限。原项目的 skill 仍处于 [in-progress](https://github.com/mattpocock/skills/blob/main/skills/in-progress/README.md)，本方案只吸收其访谈方法。

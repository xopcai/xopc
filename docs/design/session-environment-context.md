# 会话信息与运行环境弹层设计

> 设计稿，2026-10-03。范围：Gateway Web 聊天页；不改变 Agent、Source 注入或执行环境的现有语义。

## 目标

用户在聊天时能用一次点击确认三件事：这段会话在做什么、关联了什么来源、在哪里运行。弹层只承担查看和轻量跳转；选择运行位置仍在新会话编辑器中，Source 的单次引用仍通过 `@` 完成。

Codex 可借鉴的是交互节奏：新会话先选运行位置，会话中从顶部查看当前状态。xopc 的内容依照项目、任务、Note、Source 引用和本地执行环境组织，不复制 Codex 的 Changes 分类。

## 信息架构

顶部保留一个「会话信息」入口，悬停摘要为 `项目名 · Worktree · 3 个来源`；无项目时省略项目名。点击打开一个弹层，内容顺序如下：

1. **当前工作**：所属项目、当前执行任务、由本会话派出的任务。项目和任务各占一行；派出任务先显示数量与最近两项，更多项在原弹层内展开。没有任何关联时显示一行「独立会话」，不显示三个空状态。
2. **关联来源**：会话绑定的 Note、当前任务关联的 Note，以及本次待发送或最近一次消息显式引用的 Source。仅显示和本会话有直接关系的具体资源；不列出整个连接器、全局记忆、技能、Agent 或搜索结果引用。
3. **运行位置**：`本地目录` 或 `Worktree`、分支或短 SHA、目录名。完整路径在次行截断显示，可复制。目录不可用时显示 `运行目录不可用`；相关操作留在原有环境/项目入口。

### 有内容时的样式示意

```text
会话信息

xopc                              项目详情  ›
执行任务  优化聊天上下文     进行中      ›
派出任务  2 项                         展开

关联来源  3 项
  ◫ 需求说明                 会话关联    ›
  ▤ src/chat/context.ts     最近引用    ›
  ◧ GitHub issue #42         待发送      ›

运行位置  Worktree · codex/context
          …/worktrees/context                 复制
```

新增单次引用继续使用编辑器现有的 `@` 来源选择器，弹层不再提供第二个选择流程。来源列表默认显示前三项，`显示更多` 在弹层内展开，最多显示服务端返回的 20 项。超过上限时显示 `仅显示最近 20 项`，不提供没有对应目的地的「查看全部」。

## Source 范围与文案

| 来源 | 出现条件 | 默认标签 | 点击行为 |
| --- | --- | --- | --- |
| Note | 会话绑定、当前任务关联，或消息中显式引用 | `会话关联`、`任务关联`、`待发送` 或 `最近引用` | 打开 Note |
| 工作区文件、目录 | 通过 `@` 显式引用 | `待发送` 或 `最近引用` | 当前弹层显示引用摘要；文件预览仍在原有入口 |
| 其他会话 | 通过 `@` 显式引用 | 同上 | 打开会话 |
| 浏览器标签 | 通过 `@` 显式引用 | 同上 | 显示引用时的标题；不将历史引用误作仍然打开的标签 |
| MCP 资源 | 通过 `@` 显式引用 | 同上 | 显示引用摘要；不为动态资源增加新导航流程 |
| 本条消息的附件、页面捕获 | 已在待发送内容或最近一条消息中 | `待发送` 或 `最近引用` | 显示名称；预览沿用消息或编辑器入口 |

“关联”表示产品对象之间的关系；“待发送”只作用于下一条消息；“最近引用”表示最近一条已提交消息引用过该资源。它们都不是「模型当前已经读取」的承诺。会话绑定 Note 的自动注入行为沿用现有实现；其他来源不会因为出现在弹层里而自动进入后续每轮输入。

同一 `kind + id` 只显示一项；如果同时属于多个关系，用最长期的关系作为主标签，并直接标出待发送状态。列表达到上限时，优先保留会话绑定 Note 和最近显式引用，再显示任务关联 Note。版本号、token 数、底层 URI 和来源 ID 不放在列表里。

## 交互与状态

- **新会话**：运行位置在编辑器下方选择；弹层可显示已选项目、待发送 Source。环境未创建前不显示「不可用」。发送成功后显示实际绑定的目录。
- **已有会话**：弹层是只读概览。点击项目、任务、Note 进入现有详情；复制路径不关闭弹层。当前环境不可在弹层内直接切换，沿用「新会话选择环境」流程。
- **加载**：打开时用少量行骨架；弹层关闭后无需为了它持续轮询。会话切换时关闭并清除旧内容。
- **空态**：无任务时省略任务行；无 Source 时省略来源区；只有运行位置时弹层保持紧凑。
- **异常**：只在出错区块显示 `暂无法查看` 和 `重试`。权限不足或资源失效不能显示缓存的旧标题，也不能误写为「未关联」。
- **溢出**：宽约 340–380px，高度随内容增长、上限约 480px；仅超出时内部滚动。移动端使用同一内容与顺序，弹层贴近屏幕宽度，不新增详情页。
- **可访问性**：入口有 `会话信息` 标签，状态文本不只依赖图标或颜色；弹层支持键盘焦点、Escape 关闭和清楚的链接名称。

## 数据与实现边界

`SessionContextSummary` 提供项目、执行任务、派出任务、来源关系和本地目录状态。`ComposerContextRef` 支持 Note、文件、会话、浏览器标签、MCP 资源；消息输入的 `contextRefs` 保存了经过解析的来源摘要。现有 `GET /api/sessions/:key/context-summary` 的 `sources` 直接扩展为多类型条目，不增加并行字段，也不把来源正文返回给弹层。

服务端合并三类数据：会话绑定与任务关系、最近一条已提交消息的来源摘要、当前排队/运行输入的来源摘要。编辑器尚未发送的引用、附件和页面捕获在客户端合并。按 `kind + id` 去重，结果有界。Note 标题重新从当前记录读取；其余「最近引用」展示已经保存在当前会话消息中的历史摘要，不宣称资源现在仍可访问。缺少工作区读取权限时不返回来源。`sources` 只用于概览，不能复用为模型输入，也不新增自动注入规则。

实现顺序：先调整弹层层级、空态、尺寸与文案；再扩展来源摘要与单次引用展示。两步都不需要新页面。

## 验收场景

1. 独立聊天无 Source：打开后只显示 `独立会话` 和实际运行位置，没有大块空白。
2. 项目 Worktree 会话：项目、任务、分支和路径准确；新会话的环境选择不会被误当成切换当前会话。
3. 会话绑定 Note 与待发送同一 Note：只出现一项，状态准确；清空编辑器后 `待发送` 状态消失。
4. 最近一条消息引用文件、其他会话和 MCP 资源：来源种类正确，下一条消息不会自动附带它们。
5. Source 被删除、权限撤销或 Gateway 读取失败：旧标题不泄漏，受影响的行或区块显示准确状态，其余内容仍可用。

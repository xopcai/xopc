# 主动性短期优化：实施与自查记录

实施日期：2026-09-16。对应 [短期产品与技术方案](./proactive-short-term-optimization.md)。

范围为现有助理跟进、会议准备、邮件跟进及 Heartbeat。保留现有事件、批处理、执行器和通知基础设施；没有加入市场、推荐算法或新的工作流引擎。

## A：状态与计划

- overview 提供持久化最近检查、下一次时间、运行状态和五条检查记录；项目检查间隔可编辑。
- 提醒方式变更不再重置扫描计划；要求变化、恢复订阅及检查间隔变化分别处理。
- 项目、邮件与提醒设置的编辑保留开始编辑时的版本，防止轮询后以新版本号覆盖旧草稿。

自查修复：原 `saveSettings` 在任何设置变化时清空计划；已删除这一无差别副作用。以“仅修改 delivery 计划不变、修改要求清指纹、修改间隔重排”验证。

## B：资料与投递

- 同步记录增加 collection scope。只用同一来源、同一 collection 的完整成功同步证明资料新鲜；增量手动 ingest 不伪装成完整检查。
- 邮件到期判断要求同步开始时间不早于约定时间；模型调用前后及实际投递前重查来源。保留最近成功同步时间，同时区分最新同步失败。
- 删除全局页面活跃上报定时器；presence 绑定卡片及提醒版本，由详情实际可见、页面可见和焦点联合上报；75 秒过期。相关卡片可见只延迟提醒，明确已读才停止对应提醒。
- 摘要对象与外部投递分开，前台在线不消费掉摘要。资料陈旧延后重新检查，免打扰之后再次过滤过期会议。

自查修复：陈旧条目被摘要队列消费、历史摘要被新鲜度/静音过滤、关闭摘要后旧摘要仍可能推送。历史查看与投递资格分别处理；暂停期间保留队列，静音期间保留应用内摘要。

## C：Heartbeat 与统一控制

- 全局 `checksPaused`、`checksPausedUntil` 控制自动检查；`notificationsMuted` 控制系统提醒，普通 Automation 和用户对话保持各自控制。
- 迁移 176、177 增加资料覆盖范围、卡片 presence、行动期限及 Heartbeat 记录。旧 `level=off`／`pausedUntil` 一次性转换并删除；运行时、契约和前端只使用新字段。
- Heartbeat 保留原间隔、活动时段、清单、会话选项及渠道目标；清单不可读、空清单、无需提醒、失败、取消都有记录。
- 有效结果保存正文与独立投递状态，正文最多 20,000 字符，记录保留 30 天，提醒有效期及持久去重窗口为 24 小时。
- 原 MessageBus 目标继续使用，投递受同一工作区每日预算、静音和免打扰约束。成功移交只显示“已加入渠道发送队列”；中断或不确定结果显示待核对，不盲目重发。
- Heartbeat 的 `send_message`、`send_media` 和 `text_to_speech` 收口为最终结果投递；原对话工具行为不变。设置中说明每日额度与免打扰也适用于巡查。

自查修复：内存去重在重启后失效、工具直接投递绕过策略、配置重载误标正在执行的检查、重复 start 留下定时器。分别改为持久化去重、工具执行边界、实例首次启动恢复和先停止再启动。

## D：恢复与反馈

- 陈旧资料的执行在现有 retryable 状态等待，间隔 60 秒，不调用模型、不递增模型重试次数；最长等待 24 小时，之后记来源不可用。
- 全局暂停时清除待检查指纹，恢复后按当前资料重评；不改变事项各自的暂停状态。
- 同步恢复后重新收集当前资料。邮件扫描与等待资料的运行去重，避免恢复时启动两次相同分析。会议已开始则不再启动会前准备模型。
- 邮件卡片 refine 修改对应 follow-up，不修改共享场景的其他线程。
- 增加“不相关、时机不对、信息过时、提醒太多”反馈原因，保存到现有反馈记录。明确只记录反馈，不宣称已经自动训练或调整偏好。
- 复用并核验已有任务结果回流：创建待办显示 backlog，读取真实 phase/resolution；任务完成不等同于创建成功。已有来源变化失效、用户处理和幂等卡片动作继续生效。

自查修复：单线程纠正影响共享订阅、恢复资料重复排分析、过期会议仍消耗模型。没有增加第二套调度或重试引擎。

## 验证

- 主动性、Heartbeat、消息/媒体/语音工具、来源接入、路由匹配、前端状态及迁移：23 个测试文件，180 个用例通过。包含从 v175 升级、旧暂停语义保留及迁移再次执行不改变数据。
- 根项目 TypeScript、Web TypeScript/生产构建、改动范围 ESLint、diff whitespace 检查通过。
- `scripts/proactive-smoke.mts`：隔离数据库启动真实鉴权 HTTP 栈，验证未授权 401、overview、控制写入、卡片动作及版本冲突；未调用模型或外部通知。
- 浏览器交互：跟进列表显示最近/下次时间，详情显示检查历史；检查间隔从 120 改为 90 分钟后下一次时间相应提前；静音保存后暂停检查仍保持未勾选。测试只使用临时数据库和一次性凭据，测试页面及进程已关闭。

## 明确边界

- 来源新鲜度短期采用 30 分钟保守阈值；同步恢复复用既有连接器同步机制，页面提供连接管理入口，不新增另一套同步器。
- 静音为开关，检查暂停支持无限期或一小时；未增加定时静音产品形态。状态刷新复用既有轮询与卡片更新机制。
- Heartbeat 对 MessageBus 的“已排队”不是渠道送达回执，也不保证用户已阅读。
- 未进行真实邮箱、日历及用户设备的外部投递联调；这部分不能用隔离测试替代。现有第三方工具或任意脚本的副作用不由本次系统提醒策略全面接管。
- 本轮没有提交或部署，也没有修改工作区中的其他并行开发内容。

# Android / iOS 与鸿蒙对齐清单（2026-10-09）

本次整理覆盖用户指出的消息页、会话选项、对话列表、进展、笔记图标和“我的”页。对齐依据是当前鸿蒙实现与本次用户明确提出的交互要求；截图中的消息正文仅为界面示例，不作为开发指令。平台原生的返回、长按菜单、字体及安全区处理予以保留。

Android 改动已提交并推送：`0e027f803`（`fix(android): align mobile layouts and interactions with HarmonyOS`）。本清单及 iOS 改动属于后续检查。

## 逐项要求与处理

| 页面 / 功能 | Android 已完成 | iOS 检查结果与本次处理 |
| --- | --- | --- |

| 进展常用入口 | 任务与项目并排，自动化独占一行；工作流移入全部工作 | 使用同样布局，保留各详情及任务动作流程；顶部全部工作入口保留工作流导航 |
| 搜索与其他图标 | 修复搜索圆环路径、照片定位点及多个圆形图标；页面箭头、加号、三个点改为矢量图形 | 五个主页面使用原生 SF Symbols，笔记搜索图标显示正常，没有对应 Android 矢量路径问题；新增与修改入口继续采用 SF Symbols，无字体字符模拟图标 |

iOS 还补齐了语音附件 `durationSeconds` 的时长兼容；长消息预览与详情共用 Markdown 渲染器，底部渐隐，避免露出原始标题标记或截断行。新增文字沿用项目 Dynamic Type 字号规范，英文资源同步补齐。子任务使用独立的原生列表行，52 点内容高度之外保留行间距，避免父会话操作覆盖子项。

## 验证与复现

- iOS 部署目标保持 iOS 17，使用现有 Swift 6 与 SwiftUI 工程。
- 模拟器：iPhone 17 Pro，iOS 26.4。
- 构建通过；77 项单元测试通过，包括草稿跨页过滤、子任务分组解析、计划类型解析、语音时长兼容和会话配置保存失败重试。
- 修改文件的 SwiftFormat 与 SwiftLint 严格检查通过。
- 浅色模式四项 UI 测试通过：对话与子任务、消息操作与会话选项、进展/笔记/个人页、工作 Logo 动画与合成音频播放。
- 深色模式追加验证对话与子任务、进展/笔记/个人页和消息操作；验证跨至 2026-10-10。
- UI 检查使用独立的本地模拟 Gateway；全部记录为合成数据，不访问用户真实会话、笔记或自动化。
- 模拟数据服务：`python3 apps/mobile-ios/scripts/parity-fixture.py`，监听 `127.0.0.1:18791`。
- UI 测试：`MobileLayoutParityUITests`，运行前启动模拟数据服务；测试自行设置 URL 与合成令牌，不需要真实 Gateway 凭据。
- 截图、录像、首次失败及重测证据保存在被 Git 忽略的 `docs/mobile-reference/reviews/ios-2026-10-09/`；不将设备或用户截图提交仓库。

上下文、执行环境、队列编辑/取消复用现有实现，已检查代码连接；本次未重新执行其完整真实服务流程。减少动态效果与动画生命周期经过代码检查，未在设备设置中逐一切换验证。

本次验收只覆盖上述移动端对齐项目。真实模型流式返回、真实音频文件、实际 Personal AI 创建和外部连接器仍需连接真实服务进行验收；模拟器 UI 通过不能替代这些端到端验证。

# P2b 可靠执行：分批契约与进度

2026-11-01：按功能优先继续实施；长测、性能和待解锁的原生截图验证分别保留，不作为独立基础层开发的等待条件。

## J1：操作记录与物理执行锁

- `operationId` 标识稳定意图。Gateway、设备、工作区、工具、工具 revision、授权 revision、参数摘要和有效期共同参与不可变指纹；重试不能换参数、目标或延长有效期。
- `invocationId`、`connectionInstanceId` 只标识实际执行尝试；记录开始执行的尝试与所属进程执行代次。已有操作只返回记录，不自动开始第二次动作。
- 状态为 `recorded → running → succeeded / failed / stopped / unknown`；`cancel-requested` 只表示已请求停止，不能当成确认停止。恢复时所有非终态保守转为 `unknown`，禁止直接重新开始。
- 意图及状态使用独立 SQLite 元数据账本，DELETE journal + synchronous FULL，初始化/恢复在事务内完成；不复制会话、参数正文、令牌、文件内容或完整工具结果。结果只保留摘要；结果正文的可靠取回须在 J2 中另行定义，不能凭本账本声称支持结果重放。
- 账本写入出错隔离该实例，禁止开始后续写操作。过期在记录时和实际开始前都核验；达到 100000 条停止接收新意图，不自动删除去重历史。
- 执行锁使用独立 SQLite 文件上的 OS 跨进程排他锁；崩溃由 OS 释放。所有执行器必须使用同一个可信、本地文件系统中的 per-user 根目录，不能按 profile、Gateway、app bundle id 或 Electron userData 分开建锁。路径别名归一为 realpath。每个 lease 只允许一个账本实例。
- 这是内部持久化基础层，**不授予执行权，不是已完成的执行监督器**。释放 OS 锁只证明持锁进程已退出，不能证明它创建的外部进程或设备动作已停止；J2 必须在核实执行器停止前拒绝接管。

J1 已通过 6 项针对性验证、与连接模块共 103 项 Electron 回归、真实子进程崩溃 E2E 和根/Electron 类型检查。崩溃场景在隔离临时目录中完成一次 fsynced 文件追加、丢弃完成回执并 SIGKILL 进程；新进程取得 OS 锁后仍将原操作保留为 unknown，拒绝重复动作。此处不冒充远端调用、本机原生批准或完整 P2b 验收。

## 后续批次

1. **J2：调用监督与协议协商**。为支持方协商 operation 身份、执行权和核实接口；调用前验证设备、授权版本、期限和意图。复用 Endpoint v2 传输，但不能为旧客户端静默开启写能力。关联既有 Gateway 调用审计；未知结果可查询，不自动重放。补齐进程/设备级执行权、watchdog、本机断网停止入口和“请求/确认/未知”状态。账本故障必须拒绝开始动作，取消与迟到结果必须有明确处理。
2. **J3：故障与安装包验收**。覆盖 intent 落盘前、动作中、动作后结果落盘前、结果回执丢失的崩溃；重复/迟到/跨设备调用、授权撤销、时钟偏差、断网停止和未确认停止时接管拒绝。保留所有失败。当前本地模式及只读 Host 单独回归。
3. **P3：授权工作区和开发工具**。在 J2/J3 具备执行监督后接入文件写入、命令和浏览器；deviceId + workspaceId + relativePath、realpath/符号链接/路径穿越防护、远端路径禁止直传本机 API、编辑回传冲突校验。原生目录/能力授权及工具级授权另做真实 E2E。
4. **P4：后台任务**。有效期、等待设备、授权失效和大文件传输恢复；重连不继承失效授权，过期任务不执行。

J1 模块尚未接入远端工具或现有本地 Host。不能因此声称已有本机写入/命令能力、exactly-once、Windows 验收或 P2b/P3/P4 完成。证据见 [J1](./evidence/electron-gateway-p2b/journal-20261101/README.md)。

## J2a：执行监督核心

2026-11-01已实现内部监督器，尚未接入远端工具或现有本地模式：

- 在调用 worker 前验证 Gateway/设备、工具 revision、授权 revision、期限及参数摘要；参数复制后交给 worker，防止异步期间变更意图。
- 一份账本只允许一个监督器。同步写入 intent/start 后才能启动；已有操作返回持久状态，不重复执行，不把 received 当作成功。
- 使用本机 watchdog 和250ms本地授权检查；本机停止不等待远端网络。期限不超过本批执行权，且最长300秒。停止核实上限3秒，不能因等待终止阻塞无限期；这不修改聊天或性能预算。
- worker 必须在其自身资源停止后才报告完成；普通异常保守归为 unknown，不据此宣称未执行。取消先记 cancel-requested，再独立等待执行器确认；未确认时保留执行器引用、阻止接管，允许再次本机停止。
- 停止后仍不知道副作用结果时，账本分别保存 `state: unknown` 与 `executionStopped: true`。停止确认不会把未知动作变为成功或自动解除写入阻挡。重启后的 unknown 也继续阻挡新写动作，不能仅换 operationId 绕过。
- 执行期限过后仍可凭同设备有效身份核实既有回执；回执只含摘要，不自动回放工具正文或再次执行。

114项相关Electron测试、5项集成E2E和根/Electron类型检查通过。真实子进程场景验证本机watchdog终止、停止未确认时保留跨进程锁和阻止接管；不冒充任意命令的完整进程树终止证明。后续J2b仍需协议协商、Gateway操作审计关联、独立身份下的工具接线和跨重启执行器核实；J3/P3/P4仍未完成。

## J2b-1：共享契约、连接适配和设备结果证明

2026-11-01继续实现：

- 操作意图、传输尝试和停止回执使用共享严格schema；原v1账本指纹字段顺序和持久格式不变，并验证历史固定指纹。`unknown`与`executionStopped`分别表达结果是否可知、执行器是否确认停止；非终态不能声明已停止。
- 新执行会话适配层验证Gateway/设备/授权版本以及工具、revision、期限的一致性，复制参数后逐次请求本机批准；批准后再次验证实时执行权。等待批准时可取消，不等待原生对话框无限返回；动作开始后的取消等待监督器持久化停止或未知结果。已有操作只返回回执，不重放结果正文或动作。此适配层尚未注册写工具。
- 复用Realtime承载Endpoint v2消息，新增可协商的`desktop.device-frames.v1`；Endpoint签名hello绑定`deviceFrames.version=1`和授权revision，Realtime hello也必须显式提出该能力。旧路径字段和默认输出保持不变。
- 新路径使用`desktop.endpoint.message`包装原Endpoint消息和设备证明。P-256签名绑定整个消息、Gateway、设备、clientId、connectionInstanceId、授权revision、严格递增序号与60秒时效；Gateway在处理每帧前重新核验设备撤销和持久授权revision。伪造、重放、乱序、跨连接、授权变更及协商后改发无签名消息均拒绝并断开，不静默降级。
- 只读Host在受信任兼容声明提供`signedDeviceFrames:1`时使用新路径；旧Gateway未声明时仍支持原只读路径。这种只读兼容路径不授予写入权限。写能力将要求完整可靠执行协商，不能采用同样的降级策略。
- hello和每连接签名器使用同一次安全存储读取准备，私钥不暴露给Renderer；停止/重连关闭旧签名器。连接代次同时防止迟到hello和旧socket事件覆盖/停止新连接。
- Realtime原256KiB客户端帧上限、已有本地预算和凭据存储15秒期限均不修改。签名后的完整包装也按原帧上限检查。

单独签名传输E2E在真实WebSocket和隔离fsynced文件上验证“动作和回执落盘后丢失传输→新连接/账本重开只返回原回执→文件仅写一次”。这是协议/监督器集成，不冒充生产Gateway已开放写权限。真实Gateway的认证HTTP、独立设备凭据、Endpoint握手及签名结果另有集成E2E，覆盖批准状态读取、拒绝无签名/篡改/重放/授权变化、缺少协商和过期授权版本，以及旧只读路径兼容。

Gateway稳定操作身份与审计关联、回执核实和人工处理未知结果、实际写工具授权接线、J3/P3/P4仍待继续；本批不会自动使完整P2b验收通过。

## J2b-2：稳定操作身份关联到Gateway审计

继续将`executeExternalOperation`创建的稳定operationId传入Endpoint调用监督器和调用审计。读取不创建操作身份；既有客户端收到的Endpoint消息格式不变，此字段当前只保留在Gateway侧。调用审计增加可空operation_id及查询索引；schema266通过完整202–265升级链追加字段，旧调用记录保留、原值为null，最低支持版本仍为202。该字段用于关联，不是执行权或Host完成证明。

现有`GET /api/endpoint-tools/invocations`支持严格UUID的`operationId`筛选，便于核实同一意图的不同传输尝试；不存参数正文。查询过程中补齐设备归属限制：设备只看到自己的记录，不能用principalId或operationId读取另一台设备记录；owner保留管理查询。设备批量撤销接口要求gateway.admin，device.self不授予该权限。现有owner本地调用路径不变。

真实WS调用测试验证审计在发送前已有running记录、写操作关联稳定ID、完成后查询可见及同一操作重放不再次调用Endpoint；真实HTTP认证入口验证筛选、拒绝无凭据/无效筛选、设备请求证明、归属隔离与撤销权限。这里只使用合成Endpoint响应，未开放远端本机写权限。

全量存储测试发现历史输入恢复夹具通过修改版本号模拟v260，实际仍含新表，升级时发生重复建表。夹具改用仓库真实v217基线和218–260 SQL链构建历史结构，再打开完成真实升级/备份；不把生产迁移改为忽略重复表。首次失败保留，修复后247项存储测试通过，286项连接/协议/Provider回归与58项认证/观察测试通过，计数重叠不相加。

### J2b-3：执行授权与回执的 Gateway 接线（2026-11-01）

已实现独立 desktop 凭据专用、带设备请求证明的执行授权 API。默认两项设备 scope 不变；执行权有独立 grantId、一次性本机批准 ID、精确工具版本、CAS 授权版本和最多五分钟有效期。相同批准的丢失回执可以恢复，不延长有效期；旧批准/旧撤销不能覆盖新授权。观察和执行互斥；观察清理带版本，兼容旧客户端。设备侧授权成功响应由 Gateway 身份密钥签名并绑定请求 nonce、方法、目标和状态，拒绝篡改及重放。

`desktop.durable-execution.v1` 与 `desktop.device-frames.v1` 必须共同协商，签名 hello 必须匹配当前独立设备、授权版本、grantId、期限及完整工具描述哈希。Realtime 注册、收帧与 heartbeat 检查执行权；执行权过期/撤销后不能依靠仍在线的旧连接继续执行。

schema267 保留完整历史升级链，新增授权事件，以及 capability_operations 的独立 intent/receipt 元数据列。Gateway 下发前以 FULL SQLite 写事务固定意图，并核对现有 operationId 的设备、参数/描述摘要及运行租约；同一设备未核实的未知操作阻断新写入。执行结果须包含匹配 operationId、invocationId、connectionInstanceId 的终态回执及结果哈希，成功回执持久化之后才交付调用方。取消发送只代表请求停止，等待确认最长三秒；缺失/无效证据和断线保留未知结果，禁止自动重发。

本机增加严格目录描述校验和可靠调用控制器，原有控制器拒绝带执行意图的消息，避免降级成旧取消语义。批准后再检查前台状态，结果在本机持久化前校验输出契约；断开连接不会重发已完成效果。

本批真实 HTTP/WS E2E 使用隔离夹具批准、加密及执行器，**不代表原生写能力已开放**。原生执行 Host/授权 UI、操作查询与人工核实、J3 及 P3/P4 继续实施；现有本地入口不接入这些新执行模块。

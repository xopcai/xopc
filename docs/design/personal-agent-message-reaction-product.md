# Personal Agent 消息表情 · 产品方案

用户发送消息后，Personal Agent 可以在原消息气泡左上角附上一枚由 Agent 生成的 Emoji，给出轻量的接话。这个功能主要用于正文还没来时的短暂等待，也让助理在轻松交流时有一点自己的表达。

## 用户体验

1. 用户点发送，消息按现有流程显示。发送中、排队和发送失败继续由各自的状态表达。
2. 助理实际开始处理后，根据本条输入和近期对话判断要不要回应，以及用哪个 Emoji。适合的表情在正文之前出现。正文已开始则跳过，用户无需等表情生成。
3. 表情用 33 × 25 的小胶囊贴在右侧用户气泡的左上角，向左探出 4、搭入顶部 7。消息行预留 8 的顶部空间，出现时文字与气泡位置保持稳定。胶囊沿用当前主题的底色、描边和圆角，入场约 260 ms。减少动态时直接显示静态胶囊。
4. 每条消息最多一枚。表情跟随对应消息留在历史中，切换设备、重新进入会话时静态显示。表情没有独立点击动作，复制、引用、长按和全文搜索继续以消息正文为准。读屏在该消息处读出助理名称和表情的本地化名称。

表情只表达助理接住了这条消息或理解了它的语气。正在执行、需要确认、发送成功和任务完成继续由真实状态表达。

## Agent 如何表达

下面是走查样例。输出可以变化，也允许留空。产品没有固定的「意图 → Emoji」配置，同一句话在不同上下文中可以得到不同表达。

| 用户消息与上下文 | 可能的回应 | 判断依据 |
| --- | --- | --- |
| “帮我做一段雨夜开车听的音乐。” | 🌧️、🎧 或留空 | 创作主题和当时的交流语气 |
| “我们终于上线啦！”且前文在讨论发布准备 | 🎉、🙌 或留空 | 用户在分享喜讯，助理可简短回应 |
| “我们终于上线啦……结果首页白屏了。” | 留空 | 后半句改变了上下文，先回应故障 |
| “那就按上次那个口味试试。”且前文在轻松地讨论歌单 | 可以给一个合适的 Emoji | Agent 能结合上一轮理解“那个” |
| “那就按上次那个口味试试。”但缺少足够上下文 | 留空 | 含义不明确，等正文澄清 |
| 附加问题马上就能答、用户在求助、表达难过、涉及审批或外部操作 | 留空 | 正文或既有状态能更准确地表达当下需要 |

功能覆盖 WebUI、桌面和移动端发起的 Personal Agent 文字对话，包含第一条消息。普通 Agent、语音通话、仅附件和后台通知不在范围内。同一会话控制出现频率，连发时只给当前接手、且仍有等待空间的消息。Gateway 的 Ada 设置页提供统一的「消息表情」开关，关闭后停止生成并隐藏胶囊，重新打开后可查看历史。

## 验收

- 同一句话配上两组相反的上下文，助理能选择不同表情或留空。中英文都能表达自然，连续消息不会刷出一排表情。
- 左上角位置在短消息、多行消息、浅深主题、大字体和减少动态下均稳定。贴片不会挡住文字，也不会抢走屏幕阅读焦点。
- 快速回复、排队后再执行、失败和重试都与现有状态一致，表情始终落在正确的消息上。
- 灰度观察误用、重复、关闭率和首段正文耗时。小规模人工走查使用单独准备的样例。生产埋点只记录结果和耗时统计。

# AI 消息执行过程：简洁进展与动效方案

日期：2026-10-17。状态：轻量过程流、默认文案与动效已实施；范围与验证见第 10 节。
范围：Gateway Console 的 AI 消息、thinking 状态、工具执行与完成收起。Personal 页需单独适配，不能直接套用普通工作对话的文本分类。

## 1. 推荐决策

采用「简短进展说明 + 轻量动作行 + 完成后收起」：执行中让用户知道正在推进什么，完成后仍以现有 final result、附件和产物为中心。

- 进展说明回答“查到了什么、接下来做什么”，通常一句话。
- 工具行回答“正在做什么”，通常一个图标和一个短语。
- 默认不展示原始 thinking、工具名、参数、脚本、路径、协议和执行日志。
- 最新活动有轻量 loading；新文字沿用现有 Markdown 渐显；完成项立即静止。
- 正常完成时，未手动展开的过程收成“已完成 · 用时 32 秒”；最终回答完整保留。
- 失败、中断、等待确认分别表达，不能统一显示“已完成”。用户需要采取行动的信息一直可见。

“简洁”同时约束展示层和生成层：前端减少默认信息，模型减少不必要的过程解释。前端不得截断 final result 来制造简洁。

### 豆包工作：实际界面观察

1. 完成态为“共用时 2 分 30 秒”折叠入口，下方直接显示最终回答与图表。
2. 展开后，普通正文的进展说明与小号灰色工具动作交错排列，和用户截图一致。

4. 截图中的正文属于可读的过程说明，不能仅凭视觉认定为模型原始 thinking。

可借鉴其轻层级、交错阅读和完成收起。建议进一步简化“测试代码格式”“交易所前缀”“读取可视化技能”等内部操作，默认表达为“正在核对美股信息”“正在生成对比图”。

本次观察为静态历史，不能证明它的实时 loading、自动收起时机或动画参数。下文所有时长都是 xopc 的拟定值。

## 3. xopc 现状与落点

知识图谱 MCP 在本会话不可用，以下为本地源码检查结果。

| 位置 | 已有能力 | 本次设计要解决的问题 |
| --- | --- | --- |
| `messages/assistant-turn-view-model.ts` | answer/workLog 分离；reasoning、tool、answering、completed/partial 生命周期 | 新增简洁过程投影，分开运行状态与展开状态，保留 Personal 特例 |

| `messages/tool-friendly-title.ts` | 内置工具语义标题与外部工具推断 | 外部工具兜底仍可能暴露工具名；语义未知时需要中性措辞 |
| `messages/tool-input-preview.ts` | 提取 command/path/url/query 等预览 | 不能继续把通用参数预览直接拼进默认活动标题 |
| `messages/streaming.ts` | segmentId；pending → narration/answer 分类 | pending 在消息结束前身份未定，需要避免正文先出现、再搬入过程导致跳动 |
| `src/gateway/chat-stream/mapper.ts` | 在消息结束时以是否含 tool call 判断 narration/answer | 目前并非每个文字增量都有提前确定的 phase，首期必须按现有协议处理 |
| `rendering/markdown/chat-markdown-renderer.tsx` | Streamdown、渐显 ledger、错误边界 | 进展文字复用同一基础设施，不让工具每次更新触发全文重播 |
| `scroll/use-chat-scroll-viewport.ts` | 跟随/阅读、布局变化处理 | 折叠与新活动追加必须保住阅读位置 |

上述 `messages/`、`rendering/`、`scroll/` 路径位于 `web/src/features/chat/`。

## 4. 默认视觉与信息层级

### 推荐：轻量过程流

执行中默认显示最近 3 个语义条目（进展说明与动作组合计数），更早条目收在“查看之前的过程”。这些是展示分组，不删除底层事件。正在运行的并行任务优先保留，超出时显示“正在处理 3 项”，可展开查看全部。

正文示例：

> 我先查询两个市场的行情，再整理近期走势。
>
> ◌ 正在查询行情
>
> 已查到港股信息，正在补充美股数据。
>
> ◌ 正在核对美股信息

过程说明使用 14px、正常行高、`text-fg-muted`；动作使用 13px、16px Lucide 图标、`text-fg-subtle`。避免卡片套卡片、粗时间轴、每个工具一个大面板。动作和说明之间约 8px；语义步骤之间约 16px。均沿用 `globals.css` 语义 token。

完成态：

> › 已完成 · 用时 32 秒
>
> **最终回答区域继续使用现有 Markdown 与产物展示。**

备选「单行进度」仅显示当前动作，适合更安静的对话；推荐默认仍用轻量过程流，能解释长任务为何需要等待。无需新增全局设置，先由既有过程显示偏好控制。

### 按需详情

- 默认层：简短说明、语义动作、真实状态。
- “查看过程”：完整进展说明和语义动作；仍使用普通语言。
- 单项“查看详情”：可读来源、相关文件或结果；技术数据遵循已有开发视图开关。
- 命令输出、参数、调用 id、堆栈、原始错误保留在技术详情中。
- 权限确认、连接要求、实际产物、可操作工作流卡片继续作为独立可见内容，不能因收起日志而隐藏。

## 5. 状态与收起规则

| 状态 | 默认文案/行为 | 终止 loading 的依据 |
| --- | --- | --- |
| 刚发送 | “正在准备…”；很快有内容时无需闪一下占位 | 接收到有效状态/文字 |
| thinking，无公开进展 | “正在思考…”；不生成虚构细节 | thinking 结束或其他真实状态到来 |
| 工具运行 | “正在查询资料”“正在整理文件”等语义动作 | 对应工具终态 |
| 多工具并行 | “正在查询行情，另有 2 项”；展开列各项 | 各工具独立结束 |
| 正文开始 | 正文渐显；过程降为单行，可展开 | 不能把首个正文 token 当整轮完成 |
| 正常完成 | “已完成 · 用时…”；默认收起 | run 的权威完成状态 |
| 部分完成 | “已完成部分内容”；保留结果与未完成说明 | 权威 partial 状态 |
| 失败 | “暂时没能完成”；明确影响与可用下一步 | 权威 failed 状态 |
| 用户停止 | “已停止”；保留已得到的内容 | 取消/中断状态 |
| 等待用户 | “需要你确认后继续”；确认入口常驻，停止忙碌动画 | 用户操作或请求失效 |
| 网络重连 | “连接恢复中…”；不宣称工具仍在执行 | 连接与 run 快照确认 |

展开状态由用户优先：自动展开不等于手动展开；用户主动展开、选中文本或在过程里阅读时，完成不会强制收起。用户手动收起后，新事件不会重新撑开。历史打开与重连快照不播放进入动画。

无工具的直接回答沿用正文流式输出，不必额外生成“执行过程”。没有最终回答但已有实际交付物时保留产物；没有回答、产物或可靠完成状态时不能仅用绿色完成标志结束。

### pending 文本的兼容处理

当前协议在 `assistant_message_end` 才确定 narration/answer。首期不根据文案关键词猜 phase，也不把所有 pending 直接归入过程。

保留当前 pending 原位显示；工具到来后沿用既有分类并以同一 segmentId 更新展示。该次重分类不重播文字；滚动控制器以可见锚点补偿，正文和过程不同时重复展示同一段。此路径应单独做视觉回归。

若实测仍有明显搬动，后续再评估提供者明确 phase 的端到端事件支持；不能为了动效在前端创造与真实回答不一致的分类，也不在首期引入延迟到全文结束的文字缓冲。

## 6. 文案规则

| 当前可能暴露的信息 | 默认用户文案 | 详情保留 |
| --- | --- | --- |
| `read_file .../SKILL.md` | 正在查阅参考资料 | 文件名与路径 |
| 调用 `web_search` / MCP 服务 | 正在搜索相关资料 | 搜索条件、来源与调用信息 |
| 美股代码格式不匹配、重试 | 正在核对美股信息 | 具体错误与重试记录 |
| 运行图表脚本 | 正在生成对比图 | 命令与输出 |
| 检索用户记忆 | 正在参考你之前提供的信息 | 沿用记忆用途说明和管理入口 |
| 未识别的外部工具 | 正在处理相关信息 | 原工具名，不能猜成搜索或写入 |
| 超时或连接失败 | 暂时无法获取这部分信息 | 技术错误与诊断 |

语义标题优先使用可信工具元信息/既有分类，其次内置映射，最后中性兜底。展示对象只从允许字段提取（如已公开的资料标题），不直接输出任意 input、URL 查询参数或绝对路径。

进展说明只在阶段变化、有新发现、遇到影响结果的问题时生成；通常 1 句，约 20–50 个中文字是软目标。不要每个工具前后都叙述。失败后只有确有重试事件才显示“正在重试”，等待时间不能触发“快完成了”。

模型提示应约束公开进展：用用户语言说明目标、已有结果和下一步，不讲内部实现；最终回答先给结果，再给必要依据和限制。用户明确要求技术细节、代码、完整分析或长文时按用户需求展开。生成规则属于建议接入 `src/agent/prompt/` 的展示指导，需要检查现有 prompt 组合后实施；本次没有更改默认系统提示。

不增加一次专门 LLM 调用来改写每条工具日志。原始 thinking 默认继续隐藏；模型主动提供的公开进展与工具事实分别处理。

## 7. 动效与 loading

| 对象 | 拟定效果 | 约束 |
| --- | --- | --- |
| 首次等待 | 约 200ms 后出现小点与状态文字 | 避免快速回答闪烁；收到真实内容立即替换 |
| 运行中的工具 | 单个 16px 图标轻呼吸，1.4s 周期，透明度 0.55–1 | 可读文字不闪，不让全行变灰 |
| 新增动作行 | 180ms opacity 渐入，最多向上 3px | 仅新事件；保留稳定 part/group 身份 |
| 公开进展文字 | 复用现有 Markdown 尾部渐显 | 不再叠加整行 fade 或独立打字延迟 |
| 标题变化 | 120–160ms 淡化切换 | 高频事件合并；真实错误/确认立即展示 |
| 动作完成 | 图标变静态、用过去式 | 不强制凑满一个循环，不逐行绿色打勾 |
| 收起过程 | 约 200ms 局部高度过渡 | 只在主动折叠或允许的自动折叠；不对整条回答做 layout 动画 |

这些是待视觉验证的初值，不是从豆包或 Codex 测出的参数。运行中只在当前活动上保留动效；并行任务聚合后默认一个动画指示。

未知时长使用不定量反馈，不显示虚构百分比。持续较久可显示真实耗时及“仍在处理中”；无新事件仅说明未收到更新，不推断后台进度。数据页面加载继续使用项目 skeleton，聊天执行状态用紧凑状态行，不能用整页骨架覆盖已有内容。

`prefers-reduced-motion`：取消呼吸、位移和折叠动画，文字完整静态呈现。后台/离屏停止无意义动画。`role=status` 只播报阶段变化，不能逐 token 或逐秒播报。计时器保持局部更新，不能让整条消息每 500ms 重渲染。

自动收起前记录 Following/Reading 和可见锚点；Reading 下保持用户位置。正在选择文字或焦点位于过程内部时推迟自动收起。用户点击折叠时焦点回到折叠按钮。长过程默认无嵌套滚动，复用外层聊天滚动。

## 8. 实施拆分

首期不改 SQLite、传输协议和 authoritative transcript。新增的投影是纯展示模型，不是第二份可写消息状态。

1. **语义投影**：在现有 view model 上增加稳定活动分组、友好标题与显示优先级。复用 toolCallId、segmentId、part identity。UI 分组可以合并连续同类动作，但运行/失败/待确认状态不能吞掉；底层事件完整保留。
2. **轻量过程视图**：在 `assistant-steps-block.tsx` 拆出 ActivityRow、ActivityStatus、ActivityDetails，替换默认的技术卡片/通用参数预览；保留工作流、记忆说明、连接与产物入口。
3. **动效与滚动**：文字沿用 ChatMarkdownRenderer/ledger；状态动效加到现有样式体系；局部订阅目标 part。完成收起遵循用户选择与锚点规则。
4. **生成文案**：检查 prompt sections 与提供者行为后加入公开进展/答案长度指导；沿用现有 narration/answer 分类。避免影响渠道端输出或把 UI 提示变成所有场景的硬性长度限制。

建议前两步先交付，再验证动效与生成策略；不增加新动画库，不维护两套完整过程渲染器。现有开发详情作为同一视图的按需展开区。

## 9. 验收

- 普通用户默认看不到工具 id、JSON、shell、完整路径、exit code、堆栈；未知工具有中性兜底。
- 思考无文字、单工具、并行工具、重试、长等待均有可解释且真实的反馈。
- final 开始后仍运行的工具不被误标完成；结束、停止、失败、partial、等待确认分别呈现。
- 正常完成默认收起；手动展开/收起被尊重；用户在读或选择过程时不跳动、不丢选区。
- 快照、历史、切会话、重连不重播已有活动；pending 重分类不重复显示，不重播旧文字。
- 最终回答复制/导出保持完整，交付物、来源、权限确认和连接入口不被日志收起吞掉。
- 用固定事件重放验证 50 次工具更新只影响对应活动；历史正文不重新解析。
- 浏览器视觉验收覆盖浅/深色、375px/1280px、reduced-motion、自动跟随与向上阅读；动画中途结束和快速工具调用不能闪跳。

上述为完整设计验收目标；已实施与已验证范围如下，未测项不作为通过结论。

## 10. 实施记录（2026-10-17）

- 默认 `on` 与 `stream` 模式在执行中展开简洁过程；进入答案时自动降为折叠入口，完成后继续保持 final result。手动展开/收起优先，选中过程文字时延后自动收起。
- 稳定身份的活动默认展示最近 3 项；并行标题显示真实运行数量，可展开之前的过程。缺少身份的旧内容保持完整列表，避免用窗口内下标冒充稳定身份。
- 工具标题不拼接参数、命令、路径、外部工具名与技能标识；技术卡片放入按需详情，实时日志与原始错误摘要沿用开发视图限制。工作流与扩展产物保持独立可见。
- 运行图标轻呼吸、新动作 180ms 进入、过程 200ms 收起；Markdown 沿用现有 renderer。收起区停止动效并在过渡结束后释放 DOM；支持 reduced-motion。
- 运行状态标题增加 2.2 秒周期的柔和文字扫光（按实际体验从 3.2 秒调快），亮带仅覆盖文字宽度，文字本身不移动。颜色沿用主题中性色；完成时移除，reduced-motion 下恢复静态可读文字。
- 中英文活动文案与默认生成指导同时调整：进展通常一句、只讲事实和任务，最终答案先结果，用户要求的详细内容完整保留。
- 不改变消息存储、传输协议、pending 分类、最终回答渲染与 Personal 对话文本策略。失败/partial 沿用现有 outcome；没有新增持久化的取消/等待状态协议。

验证：消息相关 Vitest 回归、提示词测试、Web 类型检查、改动 TS/TSX 文件 ESLint 与生产构建通过。使用 `web/src/visual-tests/chat-rendering/activity.html` 的真实 MessageBubble 检查了思考、查询、最终答案、手动展开，以及深色 375px 布局。前端固定内容预览不调用模型；生成文案的实际遵循程度仍取决于提供者与自定义提示词。

### 真实对话验证与传输修复

本地 Gateway + `xopc-cloud/auto` 实测发现，compact realtime 原先过滤 `tool_start` 和大部分 `tool_end`，compact history 也删除了工具条目。已将精简投影补为保留调用身份、工具类别所需名称和开始/结束状态；继续省略参数、原始结果、命令输出与错误正文。历史中的失败动作会正确恢复为失败状态。未增加 API 路由或改变原始 transcript。

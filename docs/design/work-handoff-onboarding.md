# 接入我的工作 · xopc 产品与技术方案

日期 2026-11-18 · 设计提案

## 1. 产品目标

用户带一件正在做的事进入 xopc。Ada 根据用户选择的资料整理当前进度、关键决定和下一步，并把用户确认的内容接到真实的 Project、Task 和 Automation。用户第一次就能继续原来的工作，例如打开一份带来源的交接摘要，运行一项已经准备好的任务，或试跑一个每周进展汇总。

首屏问「你想在 xopc 继续哪件工作？」用户可以直接描述，也可以从「AI 工具」「本地文件」「已连接服务」中选择。用户从 Codex 进入后可以再加一条 GitHub Issue 和日历事项。用户从本地文件进入后也可以带上一个报告 Skill。一个项目可以组合多个来源，同一来源实例可以授权给不同项目，但每个项目的取用范围单独校验。

## 2. 来源与接入方式

| 用户在哪里工作 | 可带入的信息和数据 | 可准备的能力 | 首期入口 |
| --- | --- | --- | --- |
| Codex | 项目目录、用户选择的规则文件、粘贴的会话交接摘要 | 兼容 Skill、识别到的 MCP 连接线索 | 复用现有导入扫描和选择。自动读取所选本机会话放到后续，验证官方 App Server 的本机 thread 列表及分页读取接口。[Codex App Server](https://developers.openai.com/codex/app-server/) |
| Claude Code | 项目目录、规则文件、用户导出的当前会话 | 兼容 Skill、识别到的 MCP 连接线索 | 复用现有导入，支持粘贴或上传 `/export` 的文本。后续评估 Agent SDK 对本机已保存会话的列表和消息读取。[命令文档](https://code.claude.com/docs/en/commands) · [Agent SDK 会话示例](https://platform.claude.com/cookbook/claude-agent-sdk-05-building-a-session-browser) |
| WorkBuddy | 选定的工作区文件、产物、粘贴的任务摘要 | 来源可见的工作流描述、用户明确提供的 Skill 包 | 用原生文件选择器或上传承接。官方资料支持从结果区定位文件和管理分享，首期以文件和用户提交的摘要为接入形式。[结果查看](https://intl.cloud.tencent.com/zh/document/product/1316/84492) · [数据管理](https://intl.cloud.tencent.com/zh/document/product/1316/84499) |
| QwenWork | 本地工作目录、从资料空间选取并下载的产物、粘贴的任务摘要 | 用户提供的 Skill 包和自动任务描述，可整理成 xopc 草案 | 复用文件和文本入口。自动任务描述保留触发、输入、判断条件和交付意图，所需连接在 xopc 重新验证。[桌面端指南](https://help.aliyun.com/zh/qwenwork/desktop-usage) · [资料空间](https://help.aliyun.com/zh/qwenwork/cn-web-materials) · [自动任务](https://help.aliyun.com/zh/qwenwork/scheduled-tasks-web-1) |
| 本地文件与日常办公 | 文件夹、选定文档、表格、PDF、会议纪要、原有模板 | xopc 已有文件、文档、表格和项目能力；按缺口准备 Skill | 文件夹只读引用或用户上传快照。按现有提取能力显示可分析的格式，无法解析的文件仍可作为附件 |
| 已连接服务 | 已授权的仓库、Issue、PR、文档、消息、邮件、日历、外部待办和知识库 | 同一服务实际可用的读取和动作能力，例如读取 Issue、创建待办、发消息 | 首期选择现有账号下的具体资源。GitHub、云文档、日历及办公套件按连接目录和实际账号权限显示，缺能力时保留手动路径 |
| 设备与 xopc 能力库 | 用户明确提供的浏览器选区、已授权的系统笔记或提醒；已有 xopc 项目、Note 和任务 | 内置能力、已安装 Skill、MCP、连接器；后续建议能力市场、Local App、设备能力 | 优先复用当前已可用能力。新增安装、设备调用和持续访问沿用能力中心或设备原有流程 |

同一个服务可以同时是资料来源和操作入口。选择一份钉钉文档用来分析时，授权范围是该文档的读取和处理。将来要创建钉钉待办时，再依据独立的动作权限和目标账号判断。能力候选展示「可用」「需连接」「需安装或信任」「当前设备不可用」，并显示它服务于哪个任务。候选和推荐来自 Gateway 当下可用的目录及状态。

### 从任意旧工具带走一份交接摘要

为没有可用会话接口的来源提供「复制交接提示」，也支持从任意工具复制已有总结。提示词可以直接使用：

> 请整理这件工作供我交接。列出目标、当前进度、已确认的决定、尚未完成的事项、下一步建议、相关文件或链接，以及用到的技能、工具和已有的定时安排。每条重要结论附来源，无法确认的内容标为待核实。省略凭据和无关内容。

首期把 Markdown、纯文本和用户选择的附件作为通用输入。后续只有在需要机器互通时才设计可选的版本化交接清单。源摘要中提到的文件路径或链接是证据引用，实际读取使用用户已选资源或现有连接器授权。

## 3. 对话流程

新用户在模型设置后看到可跳过的入口。已有用户从首页、项目新建菜单、现有「设置 → 导入」结果页或直接对话进入。若手头已在某个项目中，优先建议接到该项目。第一步推荐选定一件工作，也支持用户逐步追加资料。

| 用户看到的步骤 | Ada 和界面做什么 |
| --- | --- |
| **选择资料** | 展示来源名称、设备或账号、候选目录或资源、可用能力。默认给出一个候选建议。用户可增删资料、粘贴说明或直接跳过。应用扫描仅在用户选定该入口后发生 |
| **分析所选资料** | 展示本次涉及的资源、读取和保留范围、处理模型及是否发送到云端。用户确认后，Ada 只读提取进度、决定、阻塞和可能的下一步。资料少时可以先把工作接到项目里，随后在同一对话追加 |
| **确认接续计划** | 在对话内显示一张可编辑的卡。选新建或复用 Project，预览交接摘要和证据，勾选值得追踪的 Task。Automation 和新增能力按需要展开，显示账号、环境、缺失授权与预计副作用。用户可以直接说「合并到老项目，只保留第一条任务」 |
| **应用所选内容** | 一次提交用户确认的项目、摘要、待办和选定的自动化草案。结果列出已完成、已复用、待连接及失败项，并提供「继续这件事」「开始任务」「预览跟进结果」和定向重试 |

**首期默认行为**

- Project 绑定已批准的目录或复用已有项目。摘要记录目标、最近进度、关键决定、未决问题和证据。只提供几份上传文件时，可以创建无外部工作目录的普通项目。
- Task 需要具体交付结果、验收条件和来源，初始以待办保存。每次建议少量明确的后续工作。完成的历史事项作为背景，不自动进入待办，状态不确定时标待核实或问一个会影响方案的问题。
- Automation 只在发现明确的重复工作或用户主动提出时建议。卡片展示触发、时区、下一次运行、数据来源、运行环境、允许动作和交付位置。保存时保持停用，先查看一次只读试跑结果。启用时确认当前定义和授权。发现旧工具可能有同类计划时，在卡片提示可能重复触发。
- 已有 Skill 和连接重用当前授权。可移植 Skill 沿用现有导入选择和信任，账号和 MCP 连接走能力中心的重新授权流程。连接中断时，项目、摘要和其余资料仍可使用。

### 示例

> 用户「我之前用 QwenWork 做供应商评估。把这个文件夹和纪要接进来，每周五看看还有哪些供应商没回。」

Ada 根据供应商清单和已选会议纪要起草「供应商评估」Project 与交接摘要，把「核对三个待回复供应商」建议为 Task。跟进草案每周五按用户时区读取指定表格，生成待回复名单和证据，结果只回到 xopc。用户先确认创建项目和任务，并试看一次名单。如果之后希望从邮件里核对回复或向外发送催办，Ada 在对应操作处说明要读的邮箱或要发送的对象，沿用该连接的授权流程。

## 4. 技术设计

### 4.1 复用与新增

| 现有模块 | 本方案中的职责 |
| --- | --- |
| [`src/imports`](../../src/imports) 和 [`web/src/features/imports`](../../web/src/features/imports) | 复用 Codex / Claude Code 的 Inventory、选择、来源快照、冲突处理和有回执的 Skill 导入。当前项目扫描是能力导入场景的候选集合，普通目录走文件入口。规则仍以带来源的参考资料处理 |
| [`src/work-discovery`](../../src/work-discovery) 和 [`src/user-context/sources`](../../src/user-context/sources) | 复用有界探查、来源授权和证据。现有 Work Discovery 的交互运行可以先创建 Project 和 Session，接续流程抽取和复用只读探查与综合阶段，在用户确认方案前只保存接续草案及运行状态。后台 Project Understanding 也需遵循明确的来源处理策略，接续创建时关闭 `autoUnderstand` |

| 新增接续编排 | 聚合多个来源的选择和证据，维护可编辑的方案、确认与逐项回执。接续卡和聊天共享同一个 Gateway 状态，设置页既有能力导入仍可独立使用 |

### 4.2 数据契约与分析边界

来源差异收敛在小型适配函数中。每类来源仅实现已有稳定入口，例如列候选、取得用户选择后的有界快照、枚举可识别的能力。文件和粘贴文本共用输入管道。连接器和设备仍由其运行时访问。

| 记录 | 建议字段与作用 |
| --- | --- |
| `SourceRef` | 来源类型、来源实例对应的账号或设备、外部资源 ID 或本机文件引用、版本或内容指纹、项目范围、采集时间、授权引用。证据可用文档段落、表格范围或会话片段定位，UI 根据当前授权还原 |
| `CapabilityCandidate` | 稳定能力标识或导入候选 ID、来源、作用范围、状态、配置缺口、相关任务、可执行环境。候选仅描述；访问策略由宿主在使用时计算 |
| `HandoffPlan` | owner、会话、修订、所选来源及授权版本、目标项目及版本、摘要草稿、有依赖的操作列表、证据引用。每个操作包含可审阅的参数、稳定 ID 和前置条件 |
| `HandoffRun` | 所确认的计划摘要、请求 ID、每个操作的状态及业务回执。记录待授权、可重试、完成和需要人工核查的实际状态。大正文保留在受控来源或用户确认保存的交接笔记中 |

`发现 → 确认读取范围 → 分析 → 审阅计划 → 确认应用 → 结果`。Gateway 在发现阶段仅收集必要的名称、类型、位置和状态。分析阶段使用适配器返回的内容或摘要；原文属于不可信资料，模型只输出受 Schema 校验的进展、证据和候选计划。项目、任务和自动化的名称、时间、操作目标及来源依赖由服务端校验。引用校验失败或证据矛盾时，标记待核实并允许跳过对应项。为文件数、内容字节、会话分页和模型调用设界限；UI 显示覆盖范围。原始工具日志、凭据、Hooks 和专有插件执行配置不进入分析输入。

分析使用已批准的只读资源。是否可云端处理属于来源授权；存在本地限定来源时，不能把包含它的证据一并发送云端。可提示选择本地模型，也可提供只用已允许来源或手工接续的路径。会话交接以 Note、摘要和出处供后续检索。继续会话按 xopc 的正常 Session 入口创建，源工具调用记录不进入 xopc 会话历史或执行队列。

### 4.3 执行、恢复和撤销

- 新增接续状态接口可挂在现有 `/api/imports` 下，例如 `/api/imports/handoffs` 及其分析、修订、确认、状态子路径。浏览器和 Agent 读取/修订同一草案。建议将 `xopc.handoffs` 的计划操作接入现有 capability dispatcher。打开选择器、批准读取、确认应用和启用自动化由宿主绑定真实用户决策，Agent 持有可用的草案 ID。
- 确认绑定方案修订和关键授权修订。执行前复核当前调用者、材料版本、目标项目版本和技能冲突。失效项要求重新预览，未受影响的成功项通过现有回执保留。设备标识取自可信上下文，远程浏览器选择的文件走上传快照；Gateway 上的本机路径和客户端路径各自独立。
- 编排按依赖执行。先匹配项目，再保存用户选定的摘要、Task 和 Automation。Skill 由现有选择导入执行，连接建议返回能力中心链接。项目按同一文件系统上的规范路径或已有外部来源映射匹配，名称重合交给用户选择。Task 和 Note 使用来源对象映射或本次确认操作的稳定键去重，允许用户明确创建另一个任务。
- Automation 创建显式传入 `enabled: false`。静态模拟检查定义和依赖。试跑由用户触发，在指定资料与只读能力范围内生成 xopc 内可预览的结果；上线前验证运行时能强制该范围，能力缺失时保留静态预览和缺失说明。启用沿用现有 Automation 操作入口。
- Gateway 持久化批次和每一步回执，各写入仍沿用对应领域事务。重启或断线后用稳定操作键查询或续做；前置项目失败时其依赖项待重试。重试只补失败或待处理项，不重新扩大读取范围和写入范围。取消分析可中止后续取数。已确认写入后展示实际效果，可以取消尚未开始的步骤。
- 项目文件默认以原位置引用或显式上传的快照保存。需要持续访问的来源另外持有可撤销授权，刷新与自动化每次运行重新验证。撤销后停止拉取，标记受影响产物和自动化；保留的交接笔记或任务按产品对象展示来源及删除入口。撤销一次导入时，可清理本次新增且仍可安全删除的对象，保留用户已编辑或后来被依赖的对象，并在结果里逐项说明。

## 5. 交付顺序与验收

| 阶段 | 交付内容 | 验收 |
| --- | --- | --- |
| **首期 · 接续一件真实工作** | Desktop 或本机 Gateway Web 共用一张接续卡。复用 Codex / Claude Code 的发现与技能导入。WorkBuddy、QwenWork 及其他工具提供选文件夹、上传产物、粘贴交接摘要三种方式。支持从一个已连接账号选择具体资源。能创建或复用 Project、保存摘要与待办、保存停用的跟进自动化并预览结果 | 用一个代码项目和一个办公项目实跑全过程，核对项目复用、证据、待办、停用的自动化和从对话开始后续工作的路径。远程 Web 至少覆盖上传文件和粘贴摘要 |
| **第二期 · 减少搬运步骤** | 加入经验证的 Codex / Claude Code 本机会话选择，按用户选项生成交接摘要。扩展办公格式提取及有稳定入口的第三方来源，按项目提供连接和能力推荐 | 验证客户端版本与会话可访问范围。对于没有可用入口的平台，保留现有上传和摘要路径。验证远程 Gateway 的来源归属和设备离线体验 |
| **第三期 · 持续接续** | 用户可选按项目刷新已授权来源、发现状态变化、试跑和启用既有自动化模板。为外部对象保留身份、来源版本及变更证据 | 验证刷新不覆盖人工修订，断线恢复能从正确游标继续，撤权或账号变更后停止后续取数和依赖运行 |

首期实现验收覆盖重复确认、断线和重启恢复、项目重名、来源修订、设备离线、资料读取撤权、跨项目隔离、外部文本内指令、仅本地处理、无模型回退，以及默认零自动执行。新增认证路由同步更新或确认 `lazy-bundles.ts` 中的 matcher，添加正向及相邻非重叠断言，并从运行的 Gateway 校验认证和真实路径。指标采集使用阶段和结果计数，不携带素材正文或文件名。

首个价值指标为「进入接续后 10 分钟内，继续项目对话、启动任务或打开一次跟进预览」的比例。辅以首次看到可用草案的耗时、建议被采纳的比例、需要补授权的原因、七天内回访项目的比例。先以小批用户建立基线，再为各来源定目标。

# 场景实施记录

## 当前交付边界

本工作区已接续 PR #30 之后保存在 `codex/proactive-heartbeat` 的未提交增量，并在 `codex/scenes-productization` 继续实现。新增完整离线转换入口、34 张旧表对账及事务删除、Heartbeat 私人文件/配置导入、共享通知链接转换、进程中断恢复，以及私人说明和检查历史的用户界面。S/T 记录产品增量，U 记录架构收口；A–R 保留各增量当时的边界，不代表当前缺口列表。

这仍不是可发布的完整场景产品。转换只在临时数据库验证；生产启动没有注入新服务、应用新 migration 或启动 SceneRuntime。Gateway 支持显式注入新领域服务，未注入时新 API 返回 503。没有修改用户数据库、连接真实邮箱或切换运行服务。

现有 Proactive／助理 Heartbeat 尚未删除；不是作为新场景的兼容执行器保留，而是尚未到达 T2 原子切换。新领域不 import 或调用旧运行时，不增加兼容 API、双写或旧格式解析器。不能将当前分支发布为“已完成场景替换”。

## 已实现并自我 review 的增量

### A. 严格契约与切换盘点

- 模板 schemaVersion、不可变版本及内容哈希；不接受未知字段、旧版本或任意执行代码。
- Activation 范围、权限交集、状态转换和 CAS 修订。
- 一次性切换只读盘点：覆盖当前生产 schema 的 proactive 表与 heartbeat_checks，统计记录与状态，不输出私人 Prompt、凭据或消息。
- 遇到未知旧表、进行中的执行和不确定的发送状态，报告切换阻断项。

Review 修复：区分通知通用资产与场景语义；不能按 proactive 前缀直接清空数据；未知表必须 fail closed。

尚未完成：逐表数据转换程序、配置转换及跨文件 journal、完整升级/回滚演练、历史成果/外部动作对账。隔离快照恢复验证见 H，不能替代转换演练。

### B. 持久执行基础

- SQLite 事件和时机去重；创建场景及手动检查的请求幂等。
- 每个 Activation 单运行，有限重试，持久租约和递增 lease epoch。
- 暂停／修改状态后取消待执行工作，使旧执行结果失效。
- 工作事项的账号、对象与截止时间；重复扫描不重复触发，超过补偿窗口的事项暂停并记录原因。
- 结果与 Inbox 呈现同事务提交；no_change 不生成 Inbox 卡片。

Review 修复：过期 worker 即使使用相同 owner 也不能提交；旧请求重试不能恢复已暂停场景；手动请求幂等不能通过伪造发生时间实现；一个邮箱的 thread ID 不能授权另一个邮箱的内容。

周期时区调度及结果生命周期增量见 F/G。尚未完成：事件聚合、跨来源的通用结果取代、Inbox 完整产品操作和留存清理。事项控制及调用预算增量见 D。

### C. 受控执行及邮件纵向验证

- Agent 单次模型调用，无写工具、消息工具、shell 或子 Agent；限制输出 token、上下文大小和总超时。
- 模型前后检查授权、证据版本、新鲜度；拒绝伪造引用和“动作成功回执”。
- Mail Context Provider 读取现有 Connector 知识表：检查账号主体、workspace、连接状态、线程范围、敏感级别和最近成功同步。
- 截止类检查要求同步开始时间晚于截止时间；无法读取完整线程时失败，不把缺失/截断当作无变化。
- 端到端后端集成测试通过真实临时 xopc SQLite、真实 Connector/知识 repository 和确定性模型替身，验证开启→检查→授权邮件→草稿结果→Inbox。
- 邮件与家庭安排两个内置模板；家庭安排已接入只读私人资料 Provider，隔离闭环见 I，尚未生产启用。

Review 修复：模型返回后撤权/改源/暂停必须丢弃结果；不合作的执行器在取消后不能发布晚到结果；邮件证据保留时间信息，不以数组顺序猜测对话先后。

尚未完成：生产授权绑定、实时 Connector 变化接入、实际 token/费用用量账本、真实模型/测试账号验证、Agent 工具入口与生产 Gateway 接线。HTTP/Web 隔离实现见 J。来源等待和调用预占见 D。

### D. 事项控制、来源等待和日预算

- 事项支持带 expectedRevision 的改期、暂停、恢复和完成；账号/对象绑定不可通过更新修改，未知字段由应用服务拒绝。
- 修改事项同事务取消关联的旧 Intent/Run 并撤回已有 Inbox 呈现；完成子事项不结束 ongoing Activation。
- 场景恢复时为 watching 事项产生新修订，避免被已取消的截止时机去重键阻止再次执行。
- Mail Context Provider 对同步暂未就绪抛出明确的来源等待信号。运行持久延后一分钟，重新执行时增加租约代次但不增加执行失败次数；从运行创建起等待超过 24 小时则终止并记录 source_wait_expired。
- 模型调用前在 SQLite 原子预占额度，默认每场景每日 30 次、每用户每日 100 次；用户额度跨 workspace 汇总，按 UTC 日切分。
- 额度不足延后到下一 UTC 日；同 Run/lease epoch 只能预占一次，崩溃后的预占不退款，避免不确定调用被重复免费重试。空上下文和来源等待不预占模型额度。

Review 修复：第三次执行进入来源等待后仍须可恢复；过期 worker 不能消费预算；场景暂停/恢复不能丢失截止事项；账号和事项范围限制同时约束取消与撤回操作。

这一增量仍未注册生产 migration 或 Gateway，不包含旧运行时删除、正式迁移或实时 Connector 事件接入。

### E. 邮件变化观测

- 为明确委托的 watching 事项提供分页扫描；宿主负责调用时机和续传游标，目前未连接生产定时器。
- 首次记录线程指纹，不产生检查；相同指纹保持静默。后续变化以事项修订和观测序号生成唯一事件，指纹恢复成历史值也不会误判为重复事件。
- 指纹更新、事件入库和旧结果撤回同事务完成；读取失败、空证据、错误账号或陈旧证据不会推进指纹。
- 成功执行的证据快照同时成为事项观测基线，避免首次扫描晚于首次执行时丢失变化。
- 事项在异步读取期间被改期或暂停，会拒绝旧修订的观测提交。

Review 覆盖：静默基线、重复扫描、A→B→A、来源失败、跨账号拒绝、事项变更竞争、结果撤回和先执行后观测。此处是对本地同步知识的只读观测，不是已完成 Connector 生产事件接入。

### F. 场景控制与结果反馈

- 应用服务支持带 expectedRevision 的暂停、恢复、完成、归档；恢复重新检查实际实例的当前授权，异步检查期间发生变更时拒绝旧修订提交。
- 修改目标、范围、权限会将实例转入 needs_setup，并取消旧 Intent/Run、暂停旧事项、撤回结果；修改不能隐式升级固定的模板版本。撤销授权不要求被撤销的权限仍然可用。
- 配置后恢复场景不会自动恢复旧事项；事项恢复必须仍属于当前账号和对象范围。
- 同一场景、对象、账号的新检查结果取代旧 Inbox 呈现；no_change 也撤回已经不再需要的草稿。结果历史和反馈记录保留，不假装旧结果从未存在。
- 支持已读/未读和明确的 useful/not_useful 反馈，反馈纠正使用修订检查。已读不是价值反馈，也不表示外部动作执行成功。
- 反馈和呈现操作校验 owner/workspace，撤回后不能重新激活；需要重新设置或归档的实例撤回已有结果。

Review 修复：no_change 残留旧草稿、配置后旧事项越界恢复、恢复授权使用错误的预检身份，以及读取邮件期间撤权仍推进观测基线。新增重复证据与观测大小检查。

尚未完成：产品定义的采用/纠正/负担变化证据、完整价值指标分母与结果留存策略。反馈 UI 已实现，当前反馈表仍不能被直接宣称为完整 WSVR。

### G. 持久周期时机

- 使用显式星期、小时、分钟和时区，不开放任意 cron 或脚本；游标与唯一事件同事务写入。
- 每次扫描最多处理 100 个到期游标，同一时机不因重复扫描或实例重建而重复入库；24 小时内最多补偿一次，长时间停机不回放积压。
- 修改检查时间使用 CAS 并取消该触发器的旧执行；暂停不调度，恢复从恢复时间计算下一次时机，跳过暂停期间的次数。
- 使用现有依赖树中的 Luxon 3.7.2 作为显式依赖。夏令时重复的本地时间只取第一次，不存在的本地时间移至当日下一有效分钟（含半小时跳变）；不引入另一套调度引擎或旧版本回退分支。
- 周期检查与截止检查均保留真实到期时间，作为邮件同步新鲜度的下界。

Review 修复：安装版本 cron-parser 5.5.0 在隔离回归中漏掉春季夏令时切换日的 09:00；改为直接计算本地日期时机，覆盖春季、秋季、重复小时和不存在小时。

调度设置 API/UI 和单 Gateway 运行泵已实现；仍缺生产宿主接入和独立触发器停用入口。当前 UI 可以暂停整个场景以停止检查。

### H. 一致性快照与恢复准备

- VACUUM INTO 捕获已提交 WAL；备份数据库和可选配置，限制目录/文件权限并写入 SHA-256 manifest。
- 校验 SQLite integrity/FK、配置 JSON、manifest 版本和内容摘要；拒绝符号链接及篡改文件。
- 恢复只允许创建新的目标目录，不覆盖现有用户安装；拷贝后再次核对摘要和关联。
- 切换盘点加入 delivering 和 action_status=executing，不能漏掉正在发送或执行的动作。

Review：恢复保留原始私人内容但报告只输出计数；错误快照不能成为 ready 备份。这里没有修改真实数据库，也没有实现正式转换或自动降级。

### I. 家庭安排资料与执行

- 用户主动提供资料，保存在 owner/workspace 隔离的场景实例中；不要求 Task/Project，不自动访问其他家庭成员。
- 保存使用 CAS；支持清空和有效期。编辑撤回旧结果并取消旧运行，过期资料等待更新，空资料跳过模型且提示 empty_input。
- 页面编辑保留最初修订，异步刷新不隐式覆盖其他窗口修改；保存期间锁定输入，错误保留草稿。

### J. 鉴权 HTTP 与 Web 隔离闭环

- 新路由经现有 Gateway 鉴权、scope middleware、lazy bundle 和限流；身份来自宿主，不接受 body/query 指定 owner/workspace。
- API 覆盖模板、预检、开启、配置/生命周期、检查、运行记录、资料、邮件来源选择、事项、定时、成果、已读和反馈；写入使用幂等键或修订号。
- Web 实现场景发现/开启/详情、来源选择、资料编辑、邮件截止/暂停/结束、周期时间、手动检查、成果及反馈；内置 `/scenes` 路由，未替换生产导航与旧页面。
- 邮件选择只返回所属账号/workspace 的有效来源元数据；无原始内部 ID 输入。读取执行仍独立验证授权、敏感级别和同步新鲜度。
- 详情成果由后端按 Activation 过滤并校验分页游标；不能先取全局前 50 条再在浏览器过滤。
- 页面按登录会话隔离 SWR 缓存，身份过期不继续展示旧数据。
- ui-ux-pro-max 的搜索建议与本项目不匹配，没有采纳其配色或字体。实际使用仓库语义 token、Skeleton、PopoverSelect、可访问表单和移动端布局，不引入第二套设计体系。

Review 修复：保存输入竞争、资料过期时间被重置、并发编辑修订漂移、成果分页漏项、已完成邮件事项仍显示恢复按钮、API 无效事项更新误报 500、登录缓存跨会话复用。

### K. 单 Gateway 运行泵

- 同一运行泵不重叠调用执行器；模型运行期间仍接纳持久到期事项和周期事件。
- 重复 start 不产生多个定时器；stop 取消执行并等待受控执行器退出后才允许宿主关闭 SQLite。
- 定时器只负责调度，去重、租约、预算仍由现有 repository/execution 负责；不引入新的队列或调度平台。
- 覆盖重复轮询、不合作模型晚到结果、关闭定时器及重叠执行测试。

尚未接入生产生命周期，也未在运行泵内接入跨主体的邮件观测扫描或 Connector 事件消费。

### L. 离线转换提交与恢复边界

- `cutoverJournal` 增加离线提交协调器：一致性备份、私有待替换配置、SQLite EXCLUSIVE 事务、转换后 FK/integrity 检查和持久 journal。
- 数据库转换失败时回滚，配置保持原样；数据库已提交但配置未替换时，ready 检查拒绝启动 worker。
- 恢复仅完成配置替换和 journal 收尾，不重新执行数据库转换。配置已替换但尚未标记 complete 的崩溃窗口同样可恢复。
- 配置转换只移除 `gateway.heartbeat`，其余字段保持语义不变；原始配置传入一次性数据库转换器以保存私人说明和偏好，不作为运行时兼容配置读取。
- 验证配置原文与待替换内容的摘要；发现外部编辑、篡改或错误目标路径时拒绝覆盖。POSIX 下同步文件及目录元数据；Windows 保留文件 fsync。
- 复用历史升级的进程占用检查，正式协调器拒绝内存数据库或其他进程仍打开的数据库；备份后若其他连接提交写入，通过 data_version 拒绝继续。
- `cutoverBindings` 要求操作者显式提供 workspace→owner 映射，包括只有通知记录的 workspace。重复/空主体、缺失归属或无效 workspace 阻断，不推测为当前登录用户，不自动授予账号权限。

Review 和故障注入：转换中断、配置 rename 失败、数据库提交后重启、配置已替换后恢复、外部配置编辑、待替换配置篡改、残留旧表、未知表和断裂外键。

**边界仍未完成**：这是正式转换的提交协调器和归属校验，不是全量逐表转换器。测试使用明确标注的转换 fixture；生产未调用该协调器，生产启动也尚未接入 ready gate。旧表规范化映射、历史动作/通知对账、Heartbeat 私人说明导入及新配置 schema 拒绝旧字段仍待实现。不得因此删除旧表或宣称已完成 T0/T2。

### M. 正式切换前置开发（2026-09-20）

- 预检补上待执行外部动作与投递队列：pending/retryable 写入必须先排空或明确对账，不由转换器静默丢弃或自动重放。Heartbeat 的 queued 只是旧消息总线接收，不是送达回执，同 unknown 一样阻止切换。
- 提交协调器验证全部目标领域表存在；只删除旧表但未安装新表的转换会回滚。Worker ready gate 同时拒绝未转换数据库、缺失目标表和未完成配置恢复的 journal。
- `cutoverMail` 实现邮件跟进的单独转换步骤：workspace→owner 和 follow-up→account 必须显式绑定，并校验来源的 owner/workspace/account 一致。保留完整说明（上限 12,000 字符）、来源对象、历史截止时间、事项修订与完成状态；导入委托为 needs_setup，未完成事项为 paused，不继承旧指纹、不创建待执行事件、不扩大到其他邮件或写操作。
- 邮件转换返回 follow-up/subscription→Activation/WorkItem 的身份映射，参与外层事务；重复目标 ID、无法确认的来源、非法日期或缺失归属导致失败，已写入的本批次记录回滚。该步骤保留源表，供全量历史映射完成后统一删除；它不是单独可以发布的全量转换器，也不提供运行时旧数据读取。
- 邮件变化观测接入新 SceneRuntime：按持久归属跨 workspace 分页，每批最多 100 个事项；单扫描并发，与模型调用独立运行。停止会取消等待，过期扫描不能更新游标或写入结果。重建运行泵依赖已持久指纹去重，不重放已有变化。
- Review 修复：异步授权完成后再次检查 Activation/WorkItem 修订和状态；暂停或修改期间不再读取来源。模板未请求邮件能力或对象超出委托范围时，在读取前拒绝。删除被新扫描路径替代且已无调用方的 scoped 扫描方法，不保留别名。
- 回归覆盖真实临时主库 schema + Connector repository + 新运行泵：手动草稿→邮件同步知识变化→撤回旧卡片→新草稿→重建去重，以及从正式旧邮件表导入后不自动执行。模型仍为确定性替身，没有用此测试冒充真实邮箱或生产宿主验收。
- 本轮验证：场景领域、鉴权 HTTP 和 lazy-bundle 共 19 个测试文件 / 198 项测试通过；场景目录 ESLint（零 warning）、全仓 TypeScript 类型检查和 diff whitespace 检查通过。

本节完成时第一阶段仍未完成；通知账本、反馈和统一 Inbox 的后续进度见 N。后续测试使用用户指定邮箱及实际运行实例的配置，不以默认状态目录推断账号是否连接。

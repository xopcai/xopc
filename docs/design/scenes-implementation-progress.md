## 已确认的边界

旧 Proactive／助理 Heartbeat 未正式使用，不保留实验历史。删除逐表转换、归属映射、对账、快照、跨配置 journal 和历史导入界面。普通 SQLite v188 事务负责删除旧实验表和相关通知、安装当前结构；失败回滚、重复启动不清空新场景。废弃 `gateway.heartbeat` 配置（含错误类型）在解析时忽略、保存时移除。

不清空聊天、项目、账号、独立自动化或整库，不扫描／导入／删除用户工作区文件。其他已发布功能的升级机制保持原有职责。

首发：单 Gateway／SQLite、本地主体、Web 管理、Gmail 指定线程和用户提供资料的家庭安排。只准备建议／草稿，不发送邮件、不执行跨系统写入。后台提醒先使用 Web Push；移动端不接收无法处理的新场景推送，旧判断入口已移除。

## 本轮实现

- 正式 `GatewayService` 构造新宿主，提供鉴权 API 和 realtime；模型初始化完成后启动，退出和启动失败时停止执行／通知。
- 删除旧 Proactive、助理 Heartbeat worker、事件发布者、API、Web 设置与跟进入口、旧项目监控；项目、任务、自动化及连接器学习保持独立。
- `xopc_use` scene 命令与 Web 使用同一应用服务，遵守幂等、权限与修订控制。
- 新 Gmail picker 显式搜索账号，保存最小账号／线程身份，不依赖知识同步。执行时读取当前连接，前后复查授权与线程变化；要求每次确认或 Agent 限定的账号不进入首发候选。
- 模型配置／凭据预检；目标编辑、资料、时间、手动检查、暂停、恢复、结束、成果复制、反馈和诊断。
- 鉴权偏好及 presence API／UI：暂停检查、静音、时区、免打扰、摘要、每日上限、浏览器提醒开关。
- Web Push 订阅及现有通知账本接线。发送前复查权限、当前成果、免打扰和查看租约；推送只携带通用提醒与应用内路径。`accepted` 表示推送服务接受，不声称设备已收到。未知发送结果不自动重发。
- 邮件逐项 5 秒超时、20 秒批次时间预算、逐项进度游标、账号退避；慢来源不会反复把后续工作卡在同一页。
- 诊断包含排队数、等待时长、最近／下次检查、模型 token 和估算费用、Connector 请求计数、投递状态。
- 小批清理 90 天以前的终态运行上下文／用量记录、过期 presence／订阅以及未被场景引用的 30 天旧搜索元数据。保留成果、反馈、请求身份和通知去重记录，避免清理后重放。

## 2026-09-20 真实环境首轮验收

用户授权使用现有 xopc Gmail 连接。通过当前本机 Gateway 的鉴权 API 验证账号发现与真实邮件搜索（26 个去重线程），选择课程自动提醒进行到期检查。真实 Gmail 线程读取和已配置的模型执行通过，结果为 `no_relevant_change`，未生成无用草稿。

使用明确标注为虚构的家庭安排测试真实模型成果生成：成功识别周六公园与午餐的时间冲突，生成中文调整选项，成果出现在收件箱。两个验收场景均已暂停，便于用户查看，不继续后台检查。没有发送邮件、创建 Gmail 草稿或修改邮件标签。

真实验收发现并修复两处集成问题：

- Composio 成功响应可能只有 `data` 和 `error: null`，不提供 `successful: true`。搜索及线程读取接受该格式，仍拒绝显式失败、错误和缺失消息数据。
- 执行器提示词曾允许模板未支持的 `observation` 类型。现按模板列出允许类型，并对不合格模型输出记录 `invalid_model_result`，页面展示可操作的诊断。

修复后相关 46 项测试通过。真实新回复、撤权／重新授权、浏览器系统通知和持续试点仍未完成；此次通过不能替代这些门禁。此前 Electron 未签名包早于本轮修复，发布前需重新打包。

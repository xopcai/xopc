# Space · AI 成果库

状态：首版实现 · 2026-11-13

## 产品设计

Space 是 xopc 的统一成果入口。用户忘了文件名、生成时间或原会话时，仍可以用正文关键词、项目、任务或内容类型找回成果，预览后下载，或者带着指定版本开启新对话。例如，用户搜索「续费风险」，可以找到两周前生成的 PPT，直接看到命中的幻灯片，并引用这份 PPT 继续修改。

### 收录规则

| 来源 | 自动归档 | 用户可以主动保存 |
| --- | --- | --- |
| 对话 | 已交付给用户且可读取的生成文件，例如文档、表格、演示稿、图片、音视频、压缩包 | 将一条助手回复保存为 Markdown 成果，保留所选回复当时的内容 |
| 任务 | 正式交付的文件和用户可见的结果正文；同一任务的后续正式修订可形成新版本 | 显式保存仍可读取的中间交付物 |
| 定时任务 | 通过同一交付链路产生的用户可见成果，带上定时任务与运行来源；重复执行的日报各自成条 | 将一条可见的纯文本报告保存为 Markdown |
| 原生内容 | 后续接入 Agent 创建并交付的笔记、站点和 Local Apps，通过原生对象打开 | 从原生对象详情加入 Space |

收录以服务端确认的交付记录为准。用户上传的输入附件、普通回复、工具日志、临时截图、工作区写入和代码差异默认留在各自的来源里。部分成功的运行仍可收录其中已经正式交付的文件。已保存的文件与 Markdown 可独立于原会话保留。删除会话时，界面提示其中哪些成果已保存在 Space；原会话链接失效后，详情仍可显示来源类型和创建时间。

### 信息架构与操作

| 入口 | 行为 |
| --- | --- |
| 应用侧栏「Space」 | 打开「全部成果」，按最近交付或更新排序。顶部是搜索框与按当前范围出现的类型筛选。列表每行显示名称、格式、来源和更新时间。 |
| 收藏与回收站 | 收藏用于快速访问。回收站提供恢复和永久删除；列表行与正常成果共用，详情只显示回收操作。 |
| 项目与任务详情 | 「成果」打开按该项目或任务过滤的 Space。筛选作为可清除的来源标签，搜索框沿用同一套查询行为。 |
| 对话与任务交付卡 | 归档完成后出现「在 Space 中查看」。独立交付文件还可「保存为新版本」，选择同类原成果后合入其版本历史并成为最新版。助手消息的更多菜单提供「保存到 Space」，保存完成后可直接打开成果。 |
| 成果详情 | 默认打开最新版。工具栏放收藏、下载与更多菜单，重命名和移到回收站放进更多菜单。来源可点开，存在历史时显示版本控件，主操作是「在对话中使用」。窄屏进入独立详情，返回后恢复原列表位置。 |

改名只修改 Space 展示名称。用户从旧版本发起后续对话时，引用固定到当时选中的版本，并在发送前显示可移除的附件。移入回收站立即退出普通列表与搜索，操作完成后可撤销，默认保留 30 天。永久删除前确认具体成果名称，仍由会话或任务持有的文件继续可用。

### 界面与交互

- **布局**采用接近 Finder 与快速查看的结构。应用侧栏进入 Space 后，窄栏仅放全部、收藏与回收站。内容区以列表为主，桌面选中后在右侧预览，窄屏复用独立详情。使用 xopc 的浅深色表面与系统字体，蓝色集中在当前选中状态和主操作。
- **搜索**支持直接输入关键词。正文命中时，列表附一行高亮片段，打开时定位到对应段落、页或工作表。搜索当前视图，切换到全部即可扩大范围。
- **反馈**跟随操作出现。保存后显示「在 Space 中查看」，移到回收站后显示「撤销」。只有处理中的正文、无结果、来源失效或预览失败时才显示对应状态。预览失败时仍可下载可用文件。
- **键盘**在列表中用方向键切换、Enter 打开、Esc 返回，焦点回到原列表行。现有全局搜索快捷键保留，Space 内提供可聚焦的搜索框。

首版采用单一成果库和个人 Gateway 的访问模型。Web 与 Electron 共用页面，原生移动端后续接入同一 API。自定义集合、图文网格、模板及共享留到出现明确使用需求时再评估。

## 技术方案

### 现有能力与接入点

| 能力 | 实现与接入方式 |
| --- | --- |
| 对话交付 | [回合持久化](../../src/agent/embedded/run-for-session.ts) 写入 `turn_outcome`，[回合投影](../../src/session/turn-outcome-projector.ts) 聚合显式成果、媒体和工作区文件引用。Space 在持久化边界消费可信的用户可见交付；投影里的可用文件还需通过生产来源和文件快照校验。 |
| 文件发布 | [publish_artifacts](../../src/agent/tools/publish-artifacts.ts) 将文件保存为 outbound 媒体并返回交付回执。已发布媒体可直接复用。工作区文件通过现有文件策略发布为快照后入库。原生音乐和视频任务完成时归档受管媒体。 |
| 任务结果 | [任务交付服务](../../src/tasks/task-result-delivery-service.ts) 持久化正式交付及版本。任务运行的工具结果可以作为关联来源，最终收录范围由正式交付确定。通知重试复用原交付 ID。 |
| 预览与正文提取 | 复用 [Web 预览运行时](../../web/src/features/preview-runtime/index.ts) 和 [结果提取器](../../src/personal-agent/result-extraction.ts) 的格式解析与定位信息；抽出共享的纯提取层，保留任务结果阅读原有的范围校验。 |
| 存储与搜索 | 元数据及索引放进现有 [SQLite](../../src/storage/sqlite/schema.sql)，文件复用 [媒体存储](../../src/media/store.ts)。Space 提供按范围筛选的搜索，后续可向 [全局命令面板](../../web/src/features/search/global-command-palette/search-api.ts) 增加成果命中类型。 |

### 数据模型

| 表 | 职责与约束 |
| --- | --- |
| `space_items` | 稳定的 `item_id`、标题、类型、收藏时间、回收时间、当前版本指针和变更序号。当前版本必须属于该成果。 |
| `space_versions` | 不可变内容版本，保存 MIME、大小、SHA-256 与受管媒体 ID，或者保存 Markdown 快照。后续原生对象类型记录对象 ID 与版本定位能力。 |
| `space_origins` | 指向版本的来源定位，记录受信任的会话、转录、消息、项目、任务、交付及自动化运行标识。来源可以失效，业务对象删除不级联删除 Space 快照。 |
| `space_backfill`、`space_media_cleanup` | 持久化历史游标和文件清理队列。版本上的索引状态用于恢复正文提取。永久删除后保留来源收录记录，防止历史回放重新创建同一成果。 |
| `space_search`、`space_search_short` | 保存已生效版本的正文分块与段落、页码、幻灯片或工作表定位。索引可以从版本重新构建。 |

同一份已发布媒体出现在工具结果、回合结果和任务卡时，使用规范化的发布回执 ID 合并记录，保留多个来源。幂等键包含生产者类型、稳定交付 ID 和输出 ID，同一事件反复消费只产生一次效果。两个不同业务成果即使内容哈希相同，也分别管理。只有可信的修订关系（如同一任务结果正文的修订、或基于某个 Space 版本明确提交的文件修订）才能追加版本；同名文件、相同路径和哈希都不足以推断版本关系。版本历史可查看，默认搜索当前版本。

### 写入、恢复与删除

1. **确认交付。** 写入回合成果、正式任务结果或原生媒体任务完成状态时，在同一 SQLite 事务登记 Space 版本及来源。任务执行会话的中间文件等待正式交付。工作区文件必须有已发布的媒体快照。
2. **归档可用版本。** 归档事务引用已经发布的媒体或保存 Markdown 正文，提交后即可按名称检索。后台按稳定游标补录可读取的历史交付，历史扫描独立于正文提取运行。
3. **提取可检索正文。** 后台 worker 在单独线程使用现有格式解析器，交替处理最新和最早的待索引版本，并限制处理时间、内存、文件及正文量。提交时复核版本仍待索引。删除或切换版本立即使旧片段退出默认搜索。失败或格式不支持时仍可按名称和来源检索。
4. **统一媒体生命周期。** [现有媒体清理](../../src/media/session-references.ts) 已保护会话和任务引用，实施时增加 Space 的版本引用，回收站内仍持有文件。引用新增和最终物理清理在 SQLite 写事务内协调引用检查与文件清理，覆盖并发删除、恢复、再次发布及崩溃重试；永久删除事务清除元数据与索引后，通过可重试的清理任务释放无引用文件。

### 搜索与 API

首版以本地检索为主。标题和原文件名保存标准化值，支持精确、前缀和子串匹配。正文使用 FTS5 trigram 检索三字符及以上的查询。两字中文词（例如「预算」）使用额外的汉字二元词项索引召回，再用正文确认连续命中。单字查询限定名称与来源。原文用于摘要和定位。排序先看标题命中，再看正文相关性和更新时间，用 `item_id` 稳定排序。同一成果只返回一条结果和最佳命中片段。类型与当前视图是常驻筛选，项目和任务筛选由相应入口带入。图片和音视频首版按名称、来源及已有结构化描述搜索，扫描 PDF 和图像中的文字需要后续 OCR。

| Gateway API（拟） | 用途 |
| --- | --- |
| `GET /api/spaces/items` | 列表与搜索，支持 `q`、筛选、排序和不透明游标 |
| `POST /api/spaces/items` | 从指定的助手消息保存，使用服务端消息或回合 ID |
| `GET/PATCH/DELETE /api/spaces/items/:id` | 详情与版本列表、改名、收藏、软删除。写入用变更序号检测并发编辑 |
| `POST /api/spaces/items/:id/{restore,purge}` | 恢复或永久删除，仅对回收站成果生效 |
| `POST /api/spaces/items/:id/versions` | 将已归档的独立文件移入指定成果的版本历史，校验目标变更序号 |
| `GET /api/spaces/items/:id/versions/:versionId/content` | 按成果与版本读取预览或下载数据，支持 Range |
| `GET /api/spaces/artifacts/:mediaId`、`GET /api/spaces/deliveries/:deliveryId` | 从交付卡跳转到对应的成果版本 |

Gateway 为每次列表、搜索、内容读取与引用提交校验当前访问范围，服务端自行解析版本及媒体 ID。现有 `/api/media/read` 以会话或任务校验范围，Space 使用独立的内容入口并复用底层媒体读取能力。预览和下载按格式限制大小及 Range；HTML、SVG 和站点使用隔离预览或下载，文件读取凭据不进入预览内容。将版本带入对话时，前端先从按成果和版本鉴权的接口读取内容，再通过现有会话附件入口交给模型，沿用对话附件大小上限；通过渠道转发由用户在会话里决定。接口契约放在 `packages/gateway-contract`，增加 `lazy-bundles.ts` 映射与正反例，并通过运行中的已认证 Gateway 验证。

Web 使用 SWR 加载列表和详情，初次加载显示骨架屏，关键词及筛选条件写入路由。详情通过状态区分正文准备中、可搜索和仅支持元数据搜索。列表和详情定期校验，用户操作后立即刷新；断线重连时重新获取数据。

### 接口行为与边界

- 列表按 `view=all|favorites|trash` 返回当前范围。每条结果带稳定 ID、当前版本、文件格式、展示来源、更新时间，以及可选的命中片段和定位。详情补充原始文件名、版本列表、来源链接状态与可用操作。
- 保存回复使用消息 ID，由 Gateway 读取当时的用户可见正文。请求重试返回同一个成果 ID。已进入回收站的同源成果可直接恢复，已永久删除的成果只有用户再次主动保存才能重新创建。
- 详情读取与版本下载分别校验成果和版本归属。过期或不存在的对象返回 404，版本冲突返回 409，由前端重新获取当前状态。用户仍可在回收站预览待恢复内容。
- 预览定位优先使用提取器给出的页码、幻灯片或工作表。PDF 可直接渲染命中的页。预览器无法定位时展示可读的匹配片段。正文索引与原件分离，清除后可以从文件版本重建。
- 新对话草稿通过现有附件交接携带选定版本的文件。用户可以在发送前移除附件。

### 迁移与交付计划

| 阶段 | 交付内容 | 验收条件 |
| --- | --- | --- |
| 1 · 自动归档 | 新增 SQLite 表并接入回合与任务；Web/Electron 上线列表、预览、下载、回来源、手动保存回复、收藏与回收站。 | 同一文件只出现一次；相同标题的不同文件分别存在；已归档文件在源会话重置或删除后仍能读取；删除和恢复跨重启有效。 |
| 2 · 全文与历史 | 上线后台提取、片段定位、历史回填、版本引用到新对话和定时任务来源。 | 用中文关键词找到正文命中的文档并跳到对应页；版本更新后旧正文退出搜索；任务结果送达重试与回填并发不会产生重复条目；使用旧版时发送指定版本。 |
| 3 · 原生内容 | 接入笔记、站点和 Local Apps 的交付回执与打开方式，扩展全局搜索。 | 从 Space 打开原生对象并回到结果列表；源对象删除、版本失效与权限变更能准确反映在搜索和详情里。 |

首版覆盖阶段 1 和阶段 2。历史回填以现存的结构化交付、任务结果和已完成的媒体任务为来源。阶段 3 的原生内容和全局命令面板接入留待后续。

Schema 版本以实施时主线为准。新增迁移接入现有升级链与 fresh schema，保留受支持的历史起点及升级前备份；迁移事务只建表和索引。后台回填按稳定游标分批读取历史 `turn_outcome`、正式任务交付及可确定用户可见交付的旧记录。回填优先接收可校验的现存媒体，跳过未交付记录、失效地址和无法验证内容的工作区引用。记录已收录、不可恢复与失败数量，回填中断后可续跑。

上线前以 1 万条成果和 10 万正文块作为初始压测数据，验证本地 Gateway 列表及搜索 P95 小于 300 ms、新文件提交后 2 秒内可按名称检索；正文提取时延按格式单独测量。记录归档延迟、积压量、可恢复失败、历史跳过数和搜索耗时，日志使用成果 ID 与来源 ID，避免写入正文和媒体凭据。通过文件写入后崩溃、事务提交后崩溃、重复消费和清理并发四种场景验证恢复。

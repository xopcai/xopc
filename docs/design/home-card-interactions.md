# 首页卡片与处理闭环

首页的目的：给用户足够的结果和依据，在当前位置作出判断并推进任务。每个动作应产生明确回执，并提供后续进展入口。

## 当前卡片与操作

| 卡片 | 判断依据与结果 | 可执行操作 | 操作后的闭环 |
| --- | --- | --- | --- |
| 待验收任务 | 当前任务版本的执行摘要、剩余工作、下一步、判断理由、逐项验证说明和关联产物 | 打开交付物；人工验收策略下逐项通过或拒绝；满足条件后完成验收；允许启动时继续执行并验证 | 本地更新验收状态、刷新首页、保存操作回执；继续执行结果通过任务事件更新 |
| 待补充信息 | 具体问题、可选答案、当前任务结果 | 首页内填写答案并提交 | 回写任务上下文，更新剩余等待项；显示保存结果和任务进展入口 |
| 待任务授权 | 等待原因、具体授权能力 | 首页内批准或拒绝并暂停 | 更新等待与授权状态；保存决定回执 |
| Connector 授权 | Connector、授权范围、参数预览、来源会话 | 批准、拒绝、打开来源 | 保存决定，刷新待处理列表并显示结果 |
| 暂停任务 | 暂停原因与当前任务结果 | 首页内恢复 | 解除暂停并更新状态；其他等待条件仍须满足 |
| 依赖、连接及外部等待 | 等待原因、依赖目标、当前结果 | 打开依赖任务或本任务详情处理对应条件 | 依赖任务保留首页背景；原任务状态由任务事件和首页快照刷新 |
| 失败任务 | 失败说明；展开当前版本结果与依据 | 重试、查看结果、进入详情 | 使用当前任务版本和已配置执行器启动；回执链接到任务进展 |
| AI 建议 | 预期结果、推荐理由、可展开的来源依据、缺少的能力 | 开始执行、讨论、替代建议、反馈、配置能力或降级执行 | 启动后提供任务回执；反馈可撤回；配置与历史均有入口 |
| AI 澄清问题 | 明确问题和选项 | 选择后进入讨论 | 复用已有讨论链路；忙碌时禁止重复操作 |
| AI 建议历史 | 原建议、结果预期、来源依据、采用状态、关联任务或对话 | 打开依据、查看进展、继续讨论、重新评估 | 来源可打开，任务可回到首页上的详情层 |
| 后台任务 | 当前状态、展开后的任务结果、依据和等待项 | 首页展开处理或打开完整任务详情 | 状态通过任务事件刷新 |
| 定时计划 | 下一次运行时间、计划名称 | 打开对应计划查看或调整 | 复用自动化页面的管理与执行记录 |
| 新建工作 | 用户意图与附件 | 提交文字、语音、文件 | 进入带原始输入的执行对话 |


## 验收规则

- `manual`：由用户结合依据逐项判定。
- `verified_auto`：执行验证不足时显示未通过或待判定的具体说明；不以人工点击代替执行验证。任务允许启动且执行器明确时可继续执行并验证。
- 其他策略：沿用服务端规则，允许人工判定的任务显示逐项操作。
- 完成验收仍要求：任务处于验收阶段、服务端允许关闭、每项条件通过且没有等待项。
- 结果只展示当前任务契约版本的最新回执，避免把历史结果作为本次交付。
- 没有当前结果时明确告知，并保留查看任务详情和处理等待事项的入口。

## 交互约定

1. 首页通过独立的固定尺寸预览弹窗展示文件产物，复用任务详情的预览组件并携带项目和任务会话作用域；外部 HTTP(S) 链接直接打开，应用内来源走现有路由。
2. 每项验收条件显示状态、验证说明及对应依据；结果有判断理由时同时展示理由和不确定项。
3. 待处理事项的操作必须使用当前任务版本和服务端允许的指令；执行器从现有任务分配或运行记录解析。
4. 操作中防止重复提交；失败保留结果和输入，并提供刷新或重试入口；成功显示可追踪的回执。
5. 展开的任务面板监听对应任务变化、窗口聚焦和实时连接恢复；异步旧请求不得覆盖刚完成的操作结果。


## 浏览器验收发现与修正（2026-10-23）

- 有未解除等待事项的任务优先显示补充信息、批准或依赖处理，不再被“已完成待验收”覆盖。
- 暂停和无需用户立即处理的等待任务保留在后台列表，可以展开并恢复。
- 任务回执使用实际助手交付内容替换通用传输成功消息，错误原因保持原样。
- 放大预览选择最近的内容容器，避免在弹窗中把文件内容移到焦点与可访问性范围之外。
- 查看依据或任务详情时保留原卡片的展开参数，关闭详情可回到原位置继续判断。
- 建议讨论草稿在提交渲染后带入，避免更新父页面时出现 React 渲染警告。

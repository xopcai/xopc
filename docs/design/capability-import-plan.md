# 外部产品一键导入

## 产品契约

设置页展示检测到的产品，每行一个「导入」按钮。点击后自动完成读取、匹配、去重与写入，显示新增技能、上下文文档、项目的数量。只有异常内容需要展开查看。

不向用户暴露扫描清单、作用域选择、冲突策略、暂存状态或二次启用。再次导入使用同样的默认规则；本期不做持续同步。

## 内容优先级与落点

| 内容 | 目标 | 使用方式 |
| --- | --- | --- |
| 标准 Skills 及资源 | 现有全局 / 项目技能目录 | 成功发布后刷新技能列表；保留现有启用及信任策略 |
| 全局工作偏好与规则文档 | 全局知识来源记录 | 使用本地文件知识检索策略；参考资料，不提升为确认的用户事实 |
| 项目规则 | 项目范围知识来源记录 | 仅对应项目可检索 |
| 已有项目 | ProjectService | 按真实路径匹配；新建项目保留本地工作目录 |
| MCP 连接 | 结果中的待处理项 | 在现有连接管理页重新连接 |

账号凭据、会话历史、自动记忆目录、产品专有命令/插件执行环境不在本期迁移范围。

## 架构

```text
来源目录声明（sources.ts）
        ↓
通用读取器（scanner.ts：技能树 / Markdown / JSON / TOML）
        ↓
一键编排（productImport.ts）
        ├─ 技能：ImportService → 受管技能目录 → 刷新
        ├─ 文档：contextImport → 现有 Knowledge Repository
        └─ 项目：现有 ProjectService
```

- 来源注册表集中声明产品名称、目录、环境变量、技能路径、文档路径、配置格式和字段名。
- 产品类型与注册表一起维护；新增同格式产品不需要修改页面、HTTP handler、去重策略或写入流程。
- 数据格式不同才增加小型 reader；不建立动态插件系统、继承层级或产品版本兼容分支。
- 工作规则作为来源文档保存，保留产品、路径、摘要、分段信息。每段至多 2,000 字符，避免整个文档挤占对话上下文。
- 本地导入的 source-index 记录归入 `workspace` 来源策略，远程 connector 记录仍归 connector；全局/项目可见性独立校验。用户关闭知识读取或对应来源时，导入不绕过设置。
- 技能发布复用原子目录切换和持久记录，文件检查、崩溃恢复与范围校验留在内部。

## 自动决策

1. 已连接的共享技能、内容相同的技能、已存在的项目和上下文直接跳过。
2. 新技能与其他来源同名时使用产品前缀。前缀也冲突则保留现有内容并报告。
3. 同一路径已导入的技能或文档发生变化时保留 xopc 内容，不自动覆盖，也不生成新的重复副本。
4. 项目按真实路径匹配；不迁入外部产品的 trust 标记。项目技能受现有信任边界控制。
5. 单项失败不阻止其他可导入内容；结果区分成功数量和待处理项。
6. 操作串行化，同一 requestId 重试返回同一结果；新 requestId 再次导入通过内容与来源去重。

## 对外接口

- `GET /api/imports/sources`：产品是否存在，以及最近导入结果。
- `POST /api/imports/sources/:source/import`：唯一写入口，body 为 `{ requestId }`。
- CLI：`xopc import [source]`。

仅 Gateway owner 可使用。浏览器不提交任意文件系统路径。通过现有认证和 lazy bundle 加载入口。

已移除旧的扫描/计划/暂存/激活 HTTP 接口、多步骤 CLI、ZIP 上传、Electron 选目录桥接和前端向导，不保留兼容别名。

## 已完成阶段与 review

### 1. 收敛产品交互

产品列表、一键操作、摘要及可折叠异常明细。删除作用域和冲突选择。检查了加载占位、空状态、错误重试和重复点击。

### 2. 共用来源扫描与高价值数据

目录声明与读写逻辑分离；增加全局/项目规则和项目记录导入。Review 修复了全局资料在项目扫描中重复读取，以及文档存储后无法被默认本地知识检索召回的问题。

### 3. 完整性与作用域验证

测试覆盖同名自动处理、相同 requestId 并发、再次导入、用户编辑保护、秘密过滤、坏配置隔离、项目 trust、知识来源过滤及跨项目隔离。保留技能原子发布与恢复测试。

通过真实认证 HTTP 请求验证 lazy bundle → 一键导入 → 立即可用 → 再次导入去重链路。

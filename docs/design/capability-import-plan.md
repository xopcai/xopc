# 外部产品导入：产品与技术方案

状态：已分阶段实现。本文替代“点击后默认导入全部内容”的设计。

## 1. 目标与原则

用户点击产品的「导入」后，先看到可导入内容，在一个弹窗中选择并确认。后台继续自动完成去重、范围匹配和发布，不要求用户理解扫描、计划、暂存、激活等内部阶段。

关键约束：

- 仅导入明确勾选的内容；空选择、缺失选择字段均不能退化为导入全部。
- 技能优先；规则文档需用户选择；项目默认不选。
- 来源配置中的项目路径仅代表候选目录，不代表应该创建一个 xopc 项目。
- 浏览、扫描、预览、关闭弹窗都不能创建项目、安装技能或写入知识库。
- 同格式产品通过目录和字段声明接入，格式不同才增加小型读取器；不建立插件框架或版本兼容链。

## 2. 本期内容边界

| 内容 | 支持范围 | 默认选择 | 目标 |
| --- | --- | --- | --- |
| 用户技能 | 兼容的 SKILL.md 与完整资源目录 | 新增且无冲突的技能默认选中 | 全局技能目录 |
| 用户规则 | Codex AGENTS 文档、Claude CLAUDE 文档及当前支持的 rules 文件 | 默认不选 | 全局知识来源记录 |
| 项目 | 来源配置登记且仍存在的工作目录 | 默认不选 | 项目记录，关联原工作目录 |
| 项目技能 | 所选项目中的兼容技能 | 项目未选时不选；项目组被主动选中后默认选中可用新增项 | 项目技能目录 |
| 项目规则 | 所选项目中的规则文档 | 默认不选，支持逐文件选择 | 项目范围知识来源记录 |
| MCP | 仅识别 | 不可勾选 | 单独提示去连接管理重新连接 |

技能选择不覆盖 xopc 既有禁用设置或项目信任设置。已经连接、内容相同或不兼容的项不可重复勾选。规则文档作为可检索参考资料保存，不自动变成确认的用户偏好，也不替换系统指令。

聊天历史、自动记忆目录、插件、子代理、Hooks、专有命令执行环境、账号凭据和模型设置不在本期范围。

## 3. 产品流程

### 3.1 设置页

保留简单的产品列表，每行显示产品名称、检测状态、最近导入结果和「导入」按钮。点击按钮打开选择弹窗并扫描。扫描过程中展示 skeleton，可关闭；关闭不产生业务写入。

检测读取的是运行 Gateway 的设备，远程使用时明确说明设备位置。

### 3.2 一个选择弹窗

固定响应式宽高，头部和底部固定，中间列表独立滚动。桌面宽约 760px，高 `min(80vh, 760px)`；窄屏使用视口内可用空间。

```text
从 Claude Code 导入                              ×
选择希望带到 xopc 的内容

搜索名称或路径…

技能                                       已选 2 / 5
  ☑ weekly-report       整理每周报告
  ☑ research            调研与资料整理
  ☐ old-helper          ……
    shared-skill        已可用
    special-hook        暂不支持

工作规则                                   已选 0 / 2
  ☐ CLAUDE.md           用户规则              查看
  ☐ writing.md          写作规则              查看

项目                                       已选 0 / 18
  ☐ xopc                ~/develop/xopc         展开
                         2 个技能 · 3 份规则
  ☐ demo                ~/Documents/.../demo   展开
                         仅项目目录

其他内容：2 个工具连接需重新连接

已选 2 个技能 · 0 份规则 · 0 个项目     取消  导入所选内容
```

行内展示用户能理解的状态：可导入、已可用、已有同名内容、需要项目信任、暂不支持、读取失败。错误原因和完整路径按需展开，不展示哈希、内部 job id 或发布阶段。

- 技能行展示名称、简介、来源范围；只保留勾选与详情。
- 规则行展示文件名和路径；可展开只读原文预览。按文件选择，本期不提供按段编辑或 LLM 提炼。
- 搜索覆盖名称、描述和路径；过滤不改变已选项，底部显示总选择数。
- 分类提供选择/取消可导入项；项目分类不提供一键全选，避免再次批量导入历史目录。
- 已存在、阻止导入的项不计入“可导入”数，必要时折叠到“已可用 / 暂不支持”。

### 3.3 项目选择语义

项目行是一个组，展开后包含「项目入口」、技能和规则：

1. 项目组默认未勾选。
2. 用户勾选项目组：选择项目入口及该组可直接导入的新增技能；规则仍需手动选择。行内立即显示所选数量，可以展开取消技能。
3. 单独勾选一个项目子项时，同时选中项目入口，并在选择摘要中体现。项目数据不会被提升为全局数据。
4. 取消项目组时，取消其入口与全部子项。
5. 已存在于 xopc 的项目展示「已有项目，添加所选内容」。入口被选择时只匹配已有记录，不新建、不改名、不改变状态。
6. 无技能、无规则的候选显示「仅项目目录」，仍可手动选择，不能自动隐藏或自动导入。
7. 未信任项目的技能禁选并给出原因；可以只导入项目入口和参考文档。导入不自动授予项目执行信任。

这里的依赖由前端显式呈现、后端严格校验；后端不替用户补选父项。

### 3.4 确认、进度与结果

- 按钮显示「导入所选内容」，零选择时禁用。
- 确认后锁定本次选择，按钮显示进行中状态；无第二次“启用”步骤。
- 成功：显示实际新增、已经存在、失败的数量，并提供查看技能/项目入口。
- 部分失败：保留成功结果，展示失败项及「重试失败项」；不能重新扫描后自动导入新发现的项目。
- 同名技能需改名时，在选择行提前显示最终名称，例如 `claude-code-report`；无需让用户选择冲突策略。此类项默认不选，用户选中即接受展示的名称。
- 已导入且发生变化的技能/规则默认保留，不自动覆盖；提示在对应管理页面处理。

弹窗关闭后的运行结果可从设置页恢复。关闭进行中的弹窗不等于取消已确认的写入，应明确提示“可以关闭，稍后查看结果”。

## 4. 项目筛选与排序

移除“配置路径 → 立即创建项目”的逻辑，也移除无提示地只取前 100 项的行为。

### 硬条件

候选必须是当前设备可解析、存在的本地绝对目录，且不能是文件系统根目录。使用真实路径去重；重复路径只显示一次。不可访问或已失效的目录不允许选择，集中提示数量和原因。

### 展示排序

依次展示：包含可导入技能/规则的候选、已有 xopc 项目、仅目录的候选。同级按名称及完整路径稳定排序。完整路径可区分同名目录。

目录短名称、日期路径或 `demo` 等名字不能可靠判断项目价值，不能仅凭名字删除或排除。首期不增加“项目价值评分”，也不把文件 mtime 当成用户最近使用时间。

列表可分页展示，但分页不能改变选择。扫描到达文件数、体积或候选数量上限时，必须显示覆盖范围和未扫描数量；未扫描项不可被导入。

## 5. 技术架构

```text
SourceDefinition：目录、字段、格式、文档优先级
                  ↓
共享 Reader：技能树 / Markdown / JSON / TOML
                  ↓
Inventory：候选、范围、依赖、可用性、来源摘要
                  ↓
Selection：用户明确提交的候选 ID
                  ↓
校验 + 自动冲突处理 + 持久运行记录
        ├─ SkillWriter → 现有技能发布与刷新
        ├─ ContextWriter → 现有知识库事务
        └─ ProjectWriter → 现有 ProjectService
```

复用 `sources.ts`、文件检查、技能原子发布、知识库和 ProjectService。UI 与写入器不能包含产品名称判断。来源差异集中在目录声明和格式读取器。

本期使用模块函数和少量数据类型，不引入 adapter 基类、插件注册生命周期、通用任务队列或跨存储分布式事务。

### 5.1 Inventory 是选择依据

核心类型（完整定义见 `src/imports/types.ts`）：

```ts
type CandidateKind = 'skill' | 'context' | 'project';
type CandidateStatus = 'ready' | 'existing' | 'conflict' | 'blocked';

interface ImportInventory {
  id: string;
  source: ImportSource;
  createdAt: number;
  expiresAt: number;
  candidates: InventoryItem[];
  notices: string[];
  complete: boolean;
}

interface InventoryItem {
  id: string;
  kind: CandidateKind;
  parentId?: string;
  name: string;
  description?: string;
  displayPath: string;
  scope: 'user' | 'project';
  status: CandidateStatus;
  reason?: string;
  suggested: boolean;
  targetName?: string;
}

interface ImportSelection {
  inventoryId: string;
  candidateIds: string[];
  requestId: string;
  retryOf?: string;
}
```

响应不携带技能文件 bytes 或全部文档正文。原文预览按候选 ID 获取。MCP 放在不可选 notices 中，不伪装成可导入候选。

服务端保存 owner、真实来源位置、内容摘要、父项关联、匹配目标和必要快照。这些字段不由浏览器决定。Inventory 有效期 15 分钟；过期重新扫描并重新确认，不自动提交旧选择。

扫描允许写入隔离的短期快照和库存元数据，不能写入业务项目、技能运行目录或知识库。扫描快照与运行记录分开清理。

### 5.2 API

| 接口 | 用途 |
| --- | --- |
| `GET /api/imports/sources` | 检测产品和最近运行结果 |
| `POST /api/imports/sources/:source/scan` | 生成只读业务库存，返回候选与默认选择建议 |
| `GET /api/imports/inventories/:id` | 恢复未过期清单，用于失败项重试 |
| `GET /api/imports/inventories/:id/items/:itemId/preview` | 获取单项安全预览 |
| `POST /api/imports/runs` | 提交 ImportSelection，执行明确选择 |
| `GET /api/imports/runs/:id` | 恢复运行状态与逐项结果 |

删除现有仅接受 `{ requestId }` 的直接全量导入接口，不保留别名。所有接口仍要求 Gateway owner；补齐 lazy bundle 映射与真实认证 HTTP 测试。

确认写入前持久化 run。首期由请求内的有界异步流程执行，通过 GET 恢复状态；页面需要时有限频率查询。不增加 SSE/WebSocket 进度系统。进程重启后恢复未完成记录，按已有的逐项幂等机制继续或标记可重试。

### 5.3 选择校验

确认请求必须满足：

1. Inventory 属于当前 owner、未过期，来源受支持。
2. 候选列表非空，无重复 ID；所有 ID 均属于这一 Inventory。
3. 选择项可导入，项目子项的父项目入口也被明确提交。
4. 浏览器不能提交来源路径、写入路径、任意项目 ID 或覆盖策略。
5. 写入前仅重新校验所选文件和目录的摘要、真实路径、目标冲突及信任状态；不扩大扫描范围。
6. 同一个 requestId 的不同 selection 返回冲突；相同 selection 返回已有 run。选择摘要排序后计算，避免仅排序不同导致冲突。

所选内容或最终目标名称变化时，在业务写入前返回 `inventory_stale`，让用户刷新清单；不得静默修改用户已经确认的范围或名称。未选文件的变化不应阻塞本次导入。

### 5.4 写入顺序与失败边界

- 先完成所有选择项的预检并保存冻结选择，再开始业务写入。
- 用户技能/规则分别调用现有写入器。
- 每个选中项目先按真实路径匹配；只有父项目入口明确选中且确实不存在时才能创建。
- 只有所选子项被传给技能或上下文写入器。移除执行阶段遍历全部 projectRoots、重新扫描并全量处理子项的逻辑。
- 项目和知识记录尽可能复用 SQLite 事务；技能文件系统操作保留原子切换与恢复日志。
- 不承诺不同存储间整批原子性。已选项目创建成功但其技能失败时，准确报告部分成功；不自动删除用户选择的项目。
- 每个运行项记录目标 ID、是否新建、写入摘要及结果，支持崩溃恢复、精确重试和未来清理；预分配新建项目 ID，或将项目创建与运行项回执放入同一数据库事务，避免崩溃后丢失归属信息。
- 网络重试复用 requestId；仅失败项重试生成新 run，并引用原 run 的失败项集合。来源发生变化或库存过期时先返回选择页确认。

## 6. 默认策略与写入器调整

### 技能

复用兼容性、凭据检查、共享技能识别和目录发布。重复内容不安装；发生同名冲突时计算产品前缀目标名并在 Inventory 展示。目标名也冲突则禁选，不引入用户填写名称的高级表单。

删除自动批量 `importSkills`，由选择执行器向既有 plan/apply/activate 引擎传入已校验候选及冻结目标名称。不能在执行时自行改名，不能读取未选候选去扩展选择。

### 上下文

复用 `contextImport.ts` 分段保存与来源追踪。继续受本地文件知识来源策略和会话隐私控制约束。全局规则保留全局范围，项目规则保留项目范围。预览按文本展示，不能执行源文档里的指令或渲染任意脚本。

### 项目

新增候选阶段只做匹配，不调用 `ProjectService.create`。创建只发生在选中入口的执行阶段。保留目录名推断名称，但在确认前展示完整路径；不自动迁入信任、活跃状态或其他来源权限。

新建项目采用 xopc 现有默认状态；这不表示来源提供了可靠活跃度。已有项目的名称、状态、描述和用户配置都保持原值。

### CLI

终端 `xopc import <source>` 同样先显示候选并交互选择。非交互环境要求明确提供 Inventory 和候选 ID，否则只展示用法，不执行写入。移除无选择就全量执行的行为；不添加默认 `--all`。

## 7. 已经误导入的项目

本次改版首先阻止新增噪声，不自动批量删除历史项目。

目前历史运行只保留数量摘要，没有可靠记录每个新建项目 ID，因此不能根据短名称、路径或导入日期推定项目可删除。历史清理由用户在项目管理中明确选择；只有能验证归属且没有后续会话、任务等使用记录时，才能另行提供批量清理预览。

新运行保存逐项 provenance，避免继续产生不可追踪的数据。

## 8. 分阶段实施与验收

### 阶段一：库存与只读预览

- 将项目从 projectRoots 字符串列表提升为候选，明确父子关系。
- 扫描与业务写入拆开，添加共享扫描预算、逐目录让出事件循环、库存过期与预览接口。文件树读取沿用现有有界读取器。
- Review：扫描/取消/预览前后业务数据库和运行目录不变；错误目录不会导致其他候选丢失。

### 阶段二：选择执行

- 实现冻结选择、前置校验、逐项回执与幂等；改造三个写入器。
- 删除旧全量入口，调整 CLI，不保留 fallback。
- Review：未选项目创建次数为零；未选子项写入次数为零；未知 ID、跨 owner、过期、来源变化和目标冲突均正确处理。

### 阶段三：弹窗交互

- 分类列表、逐项勾选、项目展开、文档预览、搜索、固定底部汇总和完成结果。
- Review：项目及规则默认未选；搜索不丢失选择；项目组默认策略可见；关闭扫描零写入；重复点击不重复导入。

### 阶段四：端到端与清理

- 用大量临时目录夹杂真实项目的夹具重现截图场景。
- 通过真实 Gateway 认证和 lazy bundle 完成选择导入、部分失败、网络重试及结果恢复。
- 验证桌面/窄屏、中文/英文、加载/空状态/异常状态。
- 删除旧 DTO、自动遍历分支和失效测试，更新用户文档。数据库演进使用正常迁移，不删除已有用户记录。

核心验收：

> 来源中有 100 个目录，用户只选择 2 个项目，最终只能新增或匹配这 2 个项目；其余 98 个目录不能写入项目表，也不能将其规则或技能导入。

## 9. 实现与自查记录

- 库存阶段：扫描 101 个项目目录，不创建业务项目；预览按 owner 隔离，公开清单不返回全文。
- 执行阶段：100 个目录仅选 2 个，只写入 2 个项目和明确选择的子项；验证全量预检、冲突名称冻结、幂等、部分失败重试与中断恢复。
- 界面阶段：验证默认勾选、父子选择、取消零写入、网络不确定时复用请求；桌面及 390px 窄屏浏览器实测无横向溢出或脚本错误。
- 清理：删除旧直接全量 API、CLI 默认全量行为与自动遍历写入逻辑。启动恢复后清理过期未确认清单及未引用快照；有运行记录的清单保留至 31 天，运行回执继续保留。
- 扫描限额：单次共享 100MiB / 5000 文件预算，最多 500 个项目目录，超限明确提示。未引入新任务队列或通用适配框架。

验证结果（2026-09-16）：全量测试 6,522 通过、3 跳过；导入服务、选择 UI 与真实认证 HTTP 专项 39 项通过（包含新增恢复/清理用例）。根目录及 Web 类型检查、全仓 lint、Node/Web 生产构建、CLI bootstrap import guard、`git diff --check` 均通过。构建仍提示 bundle 大小及 work-discovery 静态/动态导入混用，不影响构建完成。

# Phone Use：会话工作区与人工接管

更新：2026-10-26。本文描述当前实现。使用与配置见 [Phone Use](../phone-use.md)；旧研究、性能数据和验收报告仅代表对应版本。

## 产品职责

主 Chat 负责说明任务、进度、协助原因和执行结果。手机页负责观看与操作，不重复任务目标、求助正文或执行日志。

用户路径：Agent 用普通文字说明需要协助 → 用户点击 Chat 顶部手机入口 → 查看手机 → 明确接管 → 完成后点击「完成，继续任务」，或返回 Chat 明确说明已处理并继续。普通问答、打开页面和查看提醒都不恢复任务。

## 工作区与会话绑定

- Web 手机入口和工作区绑定当前可见 Chat 的 `conversationId`。只有存在 Phone Use 会话或可恢复协助请求的 Chat 才显示入口。
- 页面只读取当前会话的手机端点，不通过全局设备列表挑选手机，不提供跨 Chat 的全局手机浮窗入口或设备切换标签。
- AppShell 显式传入当前 Chat；工作区按 Gateway 身份和 Chat 重建。切换 Chat、Gateway 或离开聊天页立即卸载旧画面，释放本端人工控制。
- 停靠槽带会话标识，每个 Chat 独立注册手机标签；发现手机不自动展开。手机失效或绑定变化时只清理该 Chat 的过期标签。
- 停靠和浮窗是同一工作区的显示方式，切换布局不重新接管。布局偏好可以共享，画面和控制状态不能跨会话共享。
- 手机连接和 AI 后台任务不因切换 Chat 自动结束。设备注册、权限和连接管理在手机设置中进行。

## 提示点与手机页面

手机入口使用约 6px 的静态蓝点表示本端尚未查看的协助请求，不闪烁、不显示数字。页面可见且成功加载对应状态后标记已查看；加载失败不清点。已查看按 Gateway 身份、Chat、transcript、assistance ID 和请求版本保存在本端，只保留有界标识集合，不保存画面或正文。控制 epoch 变化不产生新提醒；新请求或新请求版本才重新提示。查看不等于完成。

手机页常驻：顶部返回/收起、手机名、一行状态与更多；中间完整等比例画面；底部一个主操作。人工控制时提供返回键和文字输入工具。模型、Agent、动作次数和连接诊断放在详情，执行策略放在设置。

| 场景 | 状态 | 主操作 |
| --- | --- | --- |
| AI 执行中 | AI 操作中 | 接管手机 |
| 等待人工处理 | 等待你处理 | 接管手机 |
| 正在获取控制 | 正在接管… | 禁用 |
| 本端控制且有待续任务 | 你正在操作 · AI 已暂停 | 完成，继续任务 |
| 本端控制且无待续任务 | 你正在操作 | 结束手动操作 |
| 其他端控制 | 另一设备正在操作 | 禁止接管 |
| 已暂停且有待续任务 | 任务已暂停 | 继续任务 |
| 空闲连接 | 已连接 | 手动操作 |
| 正在交还 | 正在检查手机… | 禁用 |

等待协助时提供次级「我已处理，继续」，支持用户直接在实体手机完成操作。任务说明始终可在来源 Chat 找到。

文字输入放在独立 sheet，失败保留输入，成功或丢失控制权后清空。键盘、文字 sheet 和更多菜单不视作离开手机页面。停止任务与断开连接是独立确认操作，已发生的输入无法撤回。

画面异常就近显示截图模式或重连入口，不覆盖任务状态。无新鲜画面时禁止输入；画面恢复不自动恢复任务或接管。

## 多端控制规则

授权客户端在观看容量内可以同时观看；一台手机同一时刻只有一个 xopc 输入控制者。控制者绑定已认证 principal 与客户端实例 ID，客户端 ID 本身不是凭据。不同窗口不能共用可操作身份。

所有接管由服务端裁定，先成功提交者获得控制权，其余收到冲突并刷新为只读。首版不提供抢占、转让申请或排队接管。

接管顺序：撤销旧代次输入资格 → 暂停预算与模型预测 → 等待已派发 I/O 和触摸收敛 → 授予人工租约 → 回复成功。收到确认前界面不能发送人工输入。

| 行为 | 控制与任务结果 |
| --- | --- |
| 观看者离开 | 关闭本端媒体，不影响其他控制者 |
| 控制者返回 Chat、收起、切 Chat/设备或进入后台 | 显式释放，任务保持暂停 |
| Web 失去焦点但仍可见 | 取消未结束手势，不立即释放租约 |
| 控制者断网或崩溃 | 租约超时撤销，任务保持暂停 |
| 视频失败但控制心跳正常 | 重连或截图降级，不自动交还 AI |
| 明确完成并继续 | 撤销人工输入，重新观察后继续 |

现有参数为约 5 秒控制心跳、15 秒人工租约；维护扫描会增加清理延迟。命令执行时也检查过期，在同一控制队列内完成触摸撤销后才能重新授予控制，不依赖扫描已经运行。

迟到的接管成功必须释放其旧代次，不能因用户重新打开页面而恢复。旧输入、心跳、释放和媒体连接清理均不能影响新租约。观看连接和人工控制租约分开，视频断流不等同于控制失联。

实体手机的物理触摸不受浏览器租约约束；应先暂停任务再操作实体手机。这里保证的是 xopc 派发输入互斥。

## 技术实现

| 模块 | 职责 |
| --- | --- |
| `src/phone/runtime.ts` | 控制命令队列、epoch、租约、暂停/交还、过期撤销及重新观察 |
| `src/phone/interactive-session.ts` | 共享媒体、输入排队与派发前鉴权、触摸撤销；单流当前最多 4 个观看者 |
| `src/phone/stream-gateway.ts` | 单次媒体票据、连接鉴权与传输 |
| `src/phone/assistance.ts`、`assistance-service.ts` | SQLite checkpoint、请求版本、幂等续接与恢复 |
| `src/gateway/hono/routes/phone.ts` | 会话 summary/state/frame/ticket/control 及原生安全响应过滤 |
| `web/src/features/phone/`、`features/right-workspace/` | 会话画面、提示点、布局与页面生命周期 |
| Android `PhoneWorkspace.kt`、iOS `PhoneWorkspaceModel.swift`、HarmonyOS `phoneViewModel.ets` | 原生发现、控制、媒体及生命周期状态 |

保留现有 PhoneReport，通过兼容可选字段 `revision`、`hasPendingTask`、`assistanceVersion`、`transcriptId` 投影 UI；summary 只增加安全的 assistance 标识与版本。未增加第二份任务存储、数据库迁移或实时事件协议。前台状态轮询约 1.2 秒；正确性依赖服务端校验，不依赖界面同步速度。

`revision` 在同一手机会话内递增，与控制 epoch 分开；客户端忽略较旧响应。重新绑定通过 session/transcript 身份作废旧状态。原生响应过滤层必须显式放行新增安全字段，继续排除 UI facts、截图、原始任务和敏感输入。

控制请求校验 principal、conversation、transcript、设备、手机会话、客户端、epoch 和适用的 assistance 版本。HTTP 与 WS 输入在入队及真实派发前检查资格、画面与几何。相同操作 ID 和参数复用收据，不同参数复用 ID 被拒绝。重启不恢复人工租约或待派发触摸。

## 任务续接

按钮与 Chat 明确完成消息复用既有恢复服务。人工控制仍存在时，Chat 续接被拒绝，不偷用持有者身份，也不暗中排队等租约过期。正常返回 Chat 已触发释放；如果尚未确认，应等待释放完成后继续。

SQLite assistance 状态和唯一 `phone-assistance:<id>` 会话输入提供持久化去重；Runtime 与 SQLite 不被当作同一事务。排队失败、响应丢失和旧 turn 正在收尾均可按同一请求重试。真正执行前再次验证控制状态，避免已排队的继续越过后来的接管。

继续时重新观察，保留原 taskId、约束和已用预算。Gateway 重启后协助请求可恢复，人工租约失效。执行结果未知时要求检查，禁止自动重放。取消、会话重置及 Agent/设备绑定变化使旧请求失效。

## 验证边界

已验证：Runtime/协助/鉴权路由与 Web 回归、原生手机模块定向测试、Web 构建和定向 lint、Android 单元测试及 instrumentation 编译、iOS 模拟器构建与 PhoneWorkspaceTests、HarmonyOS Debug HAP 构建。Web 会话隔离回归覆盖停靠/浮窗跨 Chat、双 Chat 各自有手机、非 Chat 页面及失效清理。

浏览器在 375×812 与 288×640 验证主操作可见、查看不派发输入、接管、文字 sheet 和交还，使用模拟控制响应与本机模拟器截图。跨端真实目标手机联合验收仍需单独执行；上述检查不代表真实跨端输入或模型任务成功率。

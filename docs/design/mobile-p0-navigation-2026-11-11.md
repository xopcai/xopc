# 移动端 P0 页面结构与跳转

设计基于 [三端信息架构盘点](mobile-information-architecture-audit-2026-11-11.md)。以下是 P0 目标交互。文案与导航方式用于设计评审，三端真机行为待验收。

## 一级页面

| 页面 | 从上到下 | 关键跳转 |
|---|---|---|
| **助手** | 助理名或当前会话标题 → 会话状态与归属 → 消息流及关联任务卡 → 完整输入栏 → 底栏 | 会话标题打开会话信息。任务卡的「继续任务」打开任务对话。「对话」Tab 找历史，「进展」Tab 查看待处理和交付。 |
| **对话** | 标题与「新建」→ 搜索 → 固定的「我的助理」→ 置顶与最近 → 已归档 | 点普通会话切到助手，恢复该会话的草稿与阅读位置。点「我的助理」打开固定主会话。展开父会话后，点任务子行直接打开任务对话。新建先进入独立草稿，首次发送按现有流程创建会话。 |
| **进展** | 标题与「全部工作」→ 待我处理 → 已交付 → 进行中 → 接下来 → 历史 | 待处理点「查看并处理」打开对应事项，任务行进入任务详情，交付行优先打开可用结果。任务详情的「继续任务」打开任务对话。全部工作进入任务、项目、自动化的入口。 |

底栏顺序为「助手／对话／进展／笔记／我的」。助手保留完整输入栏；对话和进展根页提供「问助手」，打开助手并聚焦当前输入草稿。有明确对象的「继续任务」走任务对话。切换 Tab 保留各自已打开的页面及阅读位置。键盘与系统返回手势遵循平台习惯。

进展只在有内容时展示对应分组。待处理项完整可达。已交付使用现有数据能确认的结果和可打开的目标；仅有关闭记录时归入历史。未连接时显示连接状态与恢复操作。刷新失败时保留已有内容并提供重试。

## 任务详情与任务对话

| 页面 | 从上到下 | 主要动作 |
|---|---|---|
| **任务详情** | 返回来源 → 任务名、状态、项目 → 下一步／需要确认 → 可用结果 → 目标与验收标准 → 任务动作 | 「继续任务」。点返回回到进展列表、项目任务分区或进入前的来源页。 |
| **任务对话** | 返回箭头及可访问名称 → 任务名、状态、所属项目 → 任务信息入口 → 任务消息流 → 独立输入栏 | 在当前任务下继续输入；「任务信息」查看状态、结果及允许的动作。任务对话作为覆盖来源的子页，底栏随来源暂时隐藏。 |

同一任务从不同入口打开同一个活跃任务会话。会话通过任务 ID 解析；重复点击复用同一次打开请求。仅在有明确任务归属时进入任务对话。普通会话继续使用助手页。

~~~mermaid
flowchart LR
    A["助手 · 当前会话"] -->|切 Tab| B["对话 · 历史与搜索"]
    B -->|选普通会话| A
    A -->|切 Tab| P["进展 · 待处理与交付"]
    A -->|继续任务| T["任务对话"]
    B -->|点任务子行| T
    P -->|点任务行| D["任务详情"]
    D -->|继续任务| T
    T -.->|从助手打开时返回| A
    T -.->|从历史打开时返回| B
    T -.->|从详情打开时返回| D
~~~

## 返回规则

**关闭任务对话，回到它的直接来源。** 顶部返回和系统返回共用这条规则。系统返回优先关闭键盘或当前弹层，下一次才退出任务对话。顶部返回会收起输入焦点并直接回来源。

| 从哪里打开 | 标题栏返回提示 | 关闭后恢复什么 |
|---|---|---|
| 助手消息里的「继续任务」 | 返回会话 | 原会话 ID、消息锚点、输入草稿；回到原任务卡附近 |
| 对话列表里的任务子行 | 返回对话 | 原查询、筛选、父会话展开状态、滚动位置 |
| 进展里的任务详情 | 返回任务详情 | 原任务详情、当前分区和滚动位置；再返回进展原分组 |
| 项目任务分区直接打开 | 返回项目 | 原项目、任务分区、列表位置；若经任务详情进入，先回详情 |
| 已有任务对话内打开另一任务 | 返回上一任务 | 上一任务会话与草稿；打开当前任务时复用当前页 |
| 通知或外部链接冷启动，且明确指向任务对话 | 返回任务详情 | 建立「进展 → 任务详情 → 任务对话」的返回路径；先连接时继续解析原目标 |

- 查看任务信息时，先收起信息，再按原路径返回。通知指向待处理事项时，直接打开该事项。
- 保存来源时记录 Gateway、Tab、页面对象及可恢复位置。任务对话草稿按 Gateway 和会话保存，打开任务期间保留原助手会话和草稿。返回后刷新任务状态，再定位到原对象。
- 打开失败留在原页，显示重试；打开过程被返回取消时，迟到的响应不再改变当前页。来源对象失效时回同一 Tab 的最近可达上级。切换 Gateway 后清理旧返回路径。
- 关闭只离开界面。已提交的工作继续显示在进展。取消任务使用单独的任务操作。

## 实现起点

- **HarmonyOS** 已有独立任务对话路由。将列表任务子项、消息卡和进展统一接到该路由，补来源恢复，并明确区分打开任务详情与打开任务对话。见 [HomeView](../../apps/mobile-harmony/entry/src/main/ets/view/HomeView.ets)。
- **Android** 已有任务对话返回记录。当前从进展打开会清空会话返回记录，系统返回拦截依赖该记录是否非空。把进展、历史和项目纳入统一来源记录，让工具栏返回与系统返回使用同一入口。见 [TaskChatChrome](../../apps/mobile-android/app/src/main/java/ai/xopc/mobile/ui/main/TaskChatChrome.kt)、[MainScreen](../../apps/mobile-android/app/src/main/java/ai/xopc/mobile/ui/main/MainScreen.kt)。
- **iOS** 当前任务详情容器会渲染聊天，普通会话打开会切到助手 Tab。给任务详情和任务对话定义各自的导航目标，复用现有聊天与任务内容。历史任务子项接入任务目标。见 [TaskDetailView](../../apps/mobile-ios/XopcMobile/Features/Progress/TaskDetailView.swift)、[AppState](../../apps/mobile-ios/XopcMobile/App/AppState.swift)。

## 三端验收

1. 从助手、对话任务子行、进展任务详情、项目任务分区打开同一任务，确认会话 ID 一致；分别用顶部返回和平台系统返回，核对直接来源和页面位置。
2. 在助手和任务对话各写一条未发送内容。来回两次，确认两份草稿分别恢复。任务后台运行时退出，进展仍显示实际状态。
3. 在任务信息、键盘和任务详情等不同层级执行返回，确认每次只关闭预期层级。
4. 模拟重复点击、断线、打开后立即返回、来源被删除、冷启动通知。确认不重复创建会话，按对应规则恢复。

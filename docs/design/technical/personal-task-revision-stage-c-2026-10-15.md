# Personal AI 阶段 C：同任务修订、成果版本与最终交付

日期：2026-10-15。本文记录实现边界与验收证据；未提交、未发布或重启生产 Gateway。

## 实现

### 完成后的修改

`personal_task revise` 进入 `TaskApplicationService.reviseCompleted`：必须提供同一对话所属 Task、最新结果 ID、结果基准版本、期望 Task 聚合版本、修改要求和重试幂等键。一个 SQLite 事务写入修改协作记录、新契约、工作修订记录、新交接快照和后台分配状态，并作废旧的未投递整理稿。旧执行绑定在同一事务内结束，修改指令进入现有 pending → delivered → confirmed 交付链；旧 Run 保持终态；新根 Run 由持久化分配队列创建，进程中断可恢复。前台不做文件读取、模型规划或执行者选择。

工作修订、契约版本、聚合版本、指令序号、执行 epoch 和成果修订分别保存。重新分配使用新的分配身份，避免复用旧分配命令的幂等记录；即使复用执行会话，新 Run 也增加 assignment epoch。后台重新检查工具、模型配置、Skill、来源访问及账户权限。

基线完整正文及其最终附件固定为结果引用；新增输入仍走阶段 B 的受限交接。活动任务书保留初始正文与当前修订；此前仍适用的要求通过有序协作记录交给后台规划与执行，不反复嵌套整个历史任务书。只有明确列出的 `supersedesEntryIds` 会让以前的指令退出采用核验，其他指令继续保留。结果保存逐条采用状态、核验结论、依据 claim 和前一成果 ID，ack 不构成采用证据。

已完成连接应用 Request 的整理、改写可通过新 Task 引用其已授权结果；重新查询或账户操作必须走新的 Request。`revise` 不重放旧 Request，也不改变原账户授权。已取消任务不通过该入口自动复活；运行中继续使用原 answer/instruct。

### 最终成果与不可变版本

`publish_task_result.finalArtifactIds` 明确选择最终附件，支持 `[]` 表示纯文字结果。宿主校验 ID 来自当前 Run 的成功发布，并只检查、核验、交付选中的附件；临时、失败、被替换的附件不因曾经发布就进入最终交付。发布工具直接向模型返回真实 ID，避免从文件名猜 ID。旧任务保留兼容读取，新 Personal Task 的任务书要求明确清单。

每个交付快照保存 `resultRevision`、`previousResultId`、契约版本和指令序号。完整执行正文保存于交付行，聊天摘要与原结果分开。已过时的未通知成果仍可作为历史版本读取，不作为最新要求的完成证明。

后台交付为发布字节计算 SHA-256。受限物化现同时支持原工作区文件与已发布结果附件：检查精确来源、成果版本、原会话和执行者权限，流式复制到 `.task-inputs` 的只读独立路径；重试核对已有副本，拒绝覆盖不同内容。结果正文使用读取，只有附件具有可物化字节。解析 worker 校验原始 SHA，避免把被篡改媒体重新解释为原成果。

### 交付闭环和响应速度

附件 outbox 保持独立。整理稿与确定性原文通知竞争同一文字交付状态；保存满五秒仍未投递时，下一次 drain 可直接写入保留结果及部分/失败状态，不启动主 Agent，也不等待前台或语音空闲。抢占 lease 后的迟到 Composer 无法再追加第二条最终文字。五秒是 outbox 判断阈值，实际可见时间还包括轮询与事件循环调度。

新增 `personal_result retry_delivery`：只重试已耗尽的交付／通知 outbox，保留已有文字和附件，不重开执行或重新生成成果；历史版本或要求已变化时拒绝冒充最新完成。失败的交付仍可读取已保存成果。

新要求、更新契约、新 Run、取消或账户撤权使旧整理稿失效。旧成果不会静默删除。生产 RT p95 尚不由隔离验收推断。

## 验证

自动化与真实链路均已通过，证据见下文。真实测试使用当前已配置模型、隔离 SQLite/工作区和合成文件，通过运行中的 Gateway 认证 HTTP/实时链路提交请求。生产配置和生产数据库不被修改，临时配置退出时删除；已有 OAuth 凭据仅复用原凭据路径及锁。

首轮探索在初次交付前停止：发布工具的模型可见文字没有附件 ID，执行者猜测 ID，被宿主拒绝。见 `personal-task-revision-live-run-1-2026-10-15.json`。修复直接暴露真实发布清单并提供结构化纠错目录；该探索不是通过证据。

第二轮初次交付成功，修改没有启动：目录仅有数字成果修订号，未暴露可复制的基准 token，状态投影也没有列出原子 revise；主模型使用数字代替基准版本，被并发校验拒绝。见 `personal-task-revision-live-run-2-2026-10-15.json`。已补齐目录与 Task 的 revisionBaseline，并让冲突回包返回精确重试参数，不再要求模型自行推断生命周期。

第三轮保存了同任务修订，但 Router 选择不同执行者后，旧的 active execution session 仍占用任务绑定，导致新 Run 在派发前失败。见 `personal-task-revision-live-run-3-2026-10-15.json`。修复在原子修订事务中结束旧绑定并为新 Run 使用独立会话，同时拒绝主模型工具表之外的 start/reopen 指令。来源清单标注物化能力，物化要求当前清单的明确序号。

回归还发现普通 Task 的成果核验指导影响了连接应用 Request；已在完成核验和最终清单边界保留 Request 自己的结构化交付协议，原账户查询不被通用研究核验阻塞。

第四轮完成了新修订的全部验收项，但额外的“从未重跑脚本”绝对否定结论缺少直接证据，被核验为 uncertain，最终保留 partial。另查到修改指令没有创建交付行，导致正确 causationId 的 ack 被拒绝。见 `personal-task-revision-live-run-4-2026-10-15.json`。现已补齐交付行，并让工具明确返回 `readyForCompletion`，引导保留必需证据、补证或撤销非必需的无依据结论，不把 saved 当作已完成。

## 边界

- 以上是隔离合成材料的真实模型链路验收，不能据此宣称生产 RT p95。
- 交付和物化限定当前权限下的保留正文、原工作区文件和发布媒体字节；远程站点链接、视觉理解和任意第三方运行环境不因此自动具备文件读取或执行能力。
- 原 Task 的账户操作不因成果修改获得重放授权；重新查询、扩展账户范围或执行外部动作仍遵循既有 Request／工具授权边界。
- 普通 Task 取消阻止续跑和重投，已发布历史成果按原有权限保留读取；连接应用 Request 的取消／撤权继续限制读取。会话删除、来源丢失、reset 和版本冲突按各自既有范围返回不可用或冲突，不静默恢复付费执行。

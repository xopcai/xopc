# Phone Use：模型提前结束的有界纠正

后续降低无效 finish 请求与长尾成本的验证见[完成纠正成本优化报告](phone-use-completion-cost-2026-10-27.md)。

日期：2026-10-27。基线是上一轮常驻观察与字段短事务的冻结工作树，不是较慢的第一阶段。观察、输入、截图、模型提示、采样和协议均保持一致；仅调整显式原生完成条件未满足时的结束处理。

本轮新版本遇到的两次自然提前结束均成功恢复。10 对真实任务两侧都完成 10/10，因此不能证明整体完成率提升；字段输入仍约 50 毫秒，保留第二阶段的执行速度。端到端中位数有所下降，但包含恢复的总耗时增加，不能宣称整体进一步提速。

## 问题与变更

原实现对未满足条件的 finish 只纠正一次。再次 finish 后返回 `completed / verified=false`，再消耗一次只读说明请求。文件名已出现在列表时，模型可能把“内容可见”误当作“指定搜索框已输入查询”，因此停止而没有执行搜索。

新的结束路径先读取最新原生观察。若异步 UI 已经满足条件，回到原有独立确认路径，无需再次预测；否则给模型一条不超过 500 字符的具体差异说明，最多两次纠正。差异包括应用不匹配、编辑框不存在/不唯一、精确值不匹配、必要文字缺失或未观察到状态变化。

反馈要求下一步只能来自原始目标授权，并允许请求人工接管；不会根据完成条件生成点击、聚焦或输入动作。动作和模型请求继续共享原预算。若第三次仍提前结束或预算不足，则返回 `paused / verified=false / completion_unmet / PHONE_COMPLETION_UNMET`，反馈为 blocked、下一步 inspect，释放代理控制；不再追加只读模型说明。无显式原生条件的只读任务维持原有路径。

正常执行和直接满足完成条件的路径不增加观察或模型调用；第二阶段的设备端 helper、字段事务和计时实现未修改。新的额外观察只发生在模型声明完成但此前尚未获得原生证据时。

## 对比方法

使用相同专用 Android 15 模拟器、`autoglm-phone` 以及相同原生起点指纹、AB/BA 顺序和两次独立终点观察。主面板四任务各重复两次，另加两对文件搜索，以增加目标故障的样本；所有原始负样本保留，不能用失败更快推导成功提速。设置值、测试文件哈希和动画还原沿用上一轮约束。

每次试跑最多 8 次模型请求、12 个动作和 90 秒。完整轨迹保存在 `/tmp/xopc-phone-finish-*`，仓库只收录简明数值证据与源码哈希。

## 验证

自动化覆盖两次提前结束后继续执行、连续拒绝到达上限、1/2 请求预算、迟到 UI 在预算内直接确认、取消中止、应用越界、密码证据屏蔽、反馈长度与保留原始动作授权。

## 真实任务结果

主面板为 8 对任务；预先声明的文件搜索加测为 2 对，共 20 次试跑、43 次真实模型请求。全部起点指纹匹配，没有剔除试跑或挑选成功重算。

两次候选恢复均发生于文件搜索：真实模型先返回 `complete`，最新原生树中指定搜索框不存在；收到具体差异反馈后，继续返回 `tap → typeText`，最后两次独立终点检查均通过。每次用了 3 个请求，耗时分别为 17.581、21.066 秒。本轮自然样本均在第一次纠正后恢复，没有在真实模型中触发第二次纠正上限；后者由自动化测试覆盖。

相应基线试跑直接完成，未重现历史的提前结束失败，因此没有测得“同一次错误被新旧实现分别处理”的反事实，不能将这两次恢复换算成总体完成率增益。候选比基线多遇到两次提前结束，基线另有一次过期预测丢弃；请求总量为 21 → 22。中位数下降约 8.9%，但总耗时增加约 8.6%，长尾和模型路径差异仍然存在。失败样本也会原样保留；本轮恰好没有最终失败，不代表该问题在任意应用上已消失。

设备端观察、字段输入、云端通道、生成 DEX 和模型适配器的源码哈希均与冻结的第二阶段基线一致。正常完成路径仍使用原来的观察和预测次数；不能从小样本耗时波动推导新的执行层加速。测试设置值、文件哈希、作用域约束和动画还原全部通过；未操作生产账号或公网云手机。

## 工程检查与限制

- 35 个 Phone Use 测试文件：472 项通过、1 项平台条件跳过。连续错误完成被明确暂停为 blocked/inspect，不补做只读模型请求；已完成的其他目标不会留下旧的 verified 状态。
- 根与 Electron 类型检查、评测脚本类型检查、定向 ESLint、Node/声明/Web 与 Electron Gateway 构建、文档检查通过。
- 评测器新增最终观察服务释放，适配第二阶段基线也使用常驻观察的情况，避免独立检查进程阻止评测退出。
- 本轮没有更换专用模型或放宽动作授权、终点验证、预算及未知结果不重试规则。未提供显式原生完成条件时仍无法从模型一句 finish 获得原生完成证明；只读结果继续标记为 unverified。

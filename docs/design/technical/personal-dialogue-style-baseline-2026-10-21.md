# Personal AI 对话风格首轮基线

日期：2026-10-21。单次重复。通过隔离 Gateway 的生产 Personal 提示词、工具工厂、鉴权 HTTP 和 realtime 输入执行。

## 模型与范围

| 角色 | 固定模型 |
|---|---|
| Personal | `xopc-cloud/openai-codex/gpt-5.6-sol` |
| 裁判 | `xopc-cloud/openai-codex/gpt-6.1-sol` |
| 模拟用户 | `xopc-cloud/openai-codex/gpt-6.1-sol` |

Personal 使用默认产品画像和干净会话；没有导入日常聊天历史。请求配置为被测模型 thinking off，裁判和模拟用户 low；不据此声称测得提供方内部思考量为零。

FollowBench 使用完整中文 style 子集 150 题（30 组 × 5 级）；level 0 只提供裁判演化上下文。EQ-Bench 4 使用运行前固定的 12/120 场景，每场目标八轮；按关系类别轮转、类别内 SHA-256(id) 排序选择。它是抽样、产品适配的 pointwise 风格画像，不是完整官方榜单运行。

| 等级 | 题数 | HSR | SSR | 错误 |
|---|---:|---:|---:|---:|
| L1 | 30 | 90.00% | 90.00% | 0 |

HSR 是每题全部约束满足的比例；SSR 按题平均，不是把所有等级的约束混成一个池；CSL 一旦中间等级失败即停止。错误保留在分母，单列基础设施/裁判格式错误。

### 评分解释与数据局限

保留上游中文风格评分提示，不按结果调整。抽查裁判记录发现 S01-L2 的最新题面已将“老圣人”替换为侦探，但演化裁判仍要求兼顾老圣人身份，因此给出 NO/YES。S01-L4 同样存在旧角色要求累计问题；S02-L4/L5 则主要失分于贯穿全文的韵律及特定文体。原分数全部保留，不将这类分歧重写成模型通过。该检查说明 HSR 不能无条件等同于“遵守当前可见用户要求”的准确率。

另一些失分来自明确的模型行为：S14-L1 和 S20-L1 中，被测模型拒绝精确模仿指定作者或人物，裁判据此判 NO；这些不计作基础设施错误。S25-L1 虽标为 style，实际新增的是身处希腊的情境约束，存在类别噪声。以上仅为抽查，不是全量人工标注。

这套 style 子集大量评估混合文学角色、文体与韵律，不能代表默认中文日常聊天的自然度、简洁性或事实正确性。本轮没有独立事实评分，也没有对全部失败进行人工重判。

## EQ-Bench 4 风格画像

实际保留 87 条 Personal 回复及 87 条模拟用户回复；3 个场景按上游 persona 提前结束规则在八轮前结束。它们保留原轨迹与评分，不作为调用错误，也没有重跑补齐。

完成并评分 12/12 个场景，错误 0。以下是上游 pointwise rubric 的 0–10 倾向分，**不是越高越好的统一能力分**。

没有构造综合质量分、通过率、Elo 或官方排名。正式 EQ-Bench 4 的能力排名依赖盲配对比较、多裁判和锚点；本轮未执行这些步骤。裁判和模拟用户固定为同一个 GPT-6.1 Sol，存在共同偏好与模拟偏差。EQ 场景保持上游英文，不能视作中文交流质量验证。

生产 Personal system prompt 保持生效；EQ 公开的被测者角色/轮次说明作为每轮标注的用户上下文前缀传入。隐藏 persona 卡、内心独白和裁判 rubric 未交给被测 Personal。这一适配与官方直接替换模型 system prompt 的协议不同。

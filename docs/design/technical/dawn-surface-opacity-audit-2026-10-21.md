# 晨曦主题覆盖层透明度排查

日期：2026-10-21

## 原因与修复规则

晨曦浅色 `surface-panel` 为白色 / 60%，深色为蓝灰色 / 68%。普通布局面板使用该色可以保留玻璃效果，但覆盖已有文字、图像或滚动内容时，背景会与前景叠加。

- 文字浮窗、弹窗、提示、固定阅读区域使用现有 `surface-overlay`。该 token 在晨曦浅色为 `#f8fbfe`、深色为 `#1f2d3b`，均不透明。
- 聊天输入框将 `surface-panel` 合成到不透明的 `surface-base`，保留原主题色调。底部圆角遮挡采用相同合成方式，顶部圆角外侧继续透明。
- 悬浮控件的 hover 状态也要检查，避免 hover 再次替换为半透明 `surface-hover`。
- 不改变晨曦全局面板 token；普通布局卡片、侧栏气氛背景、弹窗遮罩、加载遮罩及选中态仍保留原设计。

## 已确认可保留的透明区域

- 使用 `surface-overlay` 的项目选择、模型菜单、命令面板、日期/时间选择、确认弹窗：其背景已不透明。
- 页面内卡片和表单：没有覆盖独立滚动内容，不作统一实色化。
- 模态遮罩、加载覆盖层：透明用于表达背景仍在，不作为阅读表面。
- 侧栏：移动抽屉与固定表头已有独立的不透明 chrome 渐变，桌面布局的透明规则保持原样。
- 图片上的小图标操作和桌面宠物图像：保留有意设计的透明效果；承载文字的队列与提示已改实色。

## 验证与限制

- 搜索了 `web/src` 中 fixed/sticky/absolute 表面、Portal/Tooltip/Dialog/Popover/菜单，以及 CSS 中直接使用半透明面板变量的覆盖层，并逐项区分阅读表面与装饰/遮罩。
- 现有相关回归测试：12 个文件、79 项通过（设置、快速捕捉、任务依赖、朗读、录音、证据侧栏、聊天计划、澄清、图表与滚动）。
- Web 生产构建、类型检查及修改组件的 ESLint 检查通过。
- 新增 `/surface-opacity-visual.html`，可通过 `?mode=dark` 检查晨曦深色，或 `?theme=default` 检查默认主题。示例在背景上铺设文字，包含实际 ComposerFrame、渠道设置固定底栏和桌面助手队列表面，以及共享浮层色示例。
- 浏览器验证了晨曦浅色和深色下的上述代表性覆盖场景，并确认计算后的底色不含 alpha。
- 这是代码全量扫描与代表性组件视觉验证，未对所有需要账号、设备或特定业务数据的页面逐个执行端到端流程。

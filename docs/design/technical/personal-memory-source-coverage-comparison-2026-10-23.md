## 基线与本轮改变

A 使用上一轮最终 B 产品源码，已逐文件核对 `.xopc-evals/memory-time-source-snapshots-20261023/B`；不是最早未修 P0 的 A。B 在此基础上加入本轮补丁。运行宿主仍为隔离的上一轮 pi 1.4.0 环境；主工作区并行的其他产品修改不混入。

- 保留按来源／修订链封锁与重读副本隔离。来源覆盖候选在当前遗忘规则作用域内，按规范化对象名查询 SQLite 原始会话索引，只返回来源 ID；包括从未准入的历史、归档 transcript、会话标题和后续副本。它补齐原规则未记录的来源，不依赖被拒绝事实先有知识 ID。
- 对命中来源继续保守封锁原始片段和 provenance，原始 at-rest 审计不改。合法已准入事实的正文不再由句子级日期归属规则重写；删除知识时同时抑制修订链旧正文的指纹，防止缓存继续发送旧值。相同对象、字段和当前真实作者明确授权才可读取原文，后续副本继续过期，ACL／scope 不变。
- 字段投影保留在重新准入拦截及未命中本地索引的工具／provenance 后备保护；不是对所有模型消息全局猜测日期归属。混合原始片段整体封锁可能让未另行准入的合法信息暂不可用，不声称保持整个混合原文的可读性。
- 没有已准入目标时，可由已验证的真实、未引用、未否定的作者遗忘指令建立当前作用域的无值边界；不删除未提供或不可见 ID。存在 project ID 时保持 project scope，否则限 workspace。
- 工作候选同时检查 topic 与正文，防止忘记值重新准入。缺失项目 scope、引用不匹配、敏感内容、既有决定冲突、写策略／suppression 拒绝仍然拒绝，不静默回落到更宽范围。
- 准入结果增加原因：`missing_project_scope`、`evidence_ref_missing`、`evidence_quote_mismatch`、`statement_sensitive`、`evidence_sensitive`、`protected_decision_conflict`、`write_policy_or_suppression`、`forgotten_field_boundary`。结构化日志只记 runId、ordinal、原因；现有 extraction run 的 `error_code` 用 `admission_rejections:` 命名空间保存无值 ordinal 映射，输出查询提供 reasonCode，不引入数据库 schema／锁文件变更。completed 中的拒绝诊断与 failed extraction 分开。前三个冻结开发运行仍用合并的 `ungrounded_evidence`；发现其无法区分坏 ref／坏 quote 后，主工作区再拆码，原始成绩不重分类。
- 抽取提示示例按真实 project ID 选择 project／workspace，明确“名称像项目／合同”不等于存在真实 project ID；没有目标时也不能编造 ID。这是提示契约修正，不放松实际 scope／grounding 校验。

覆盖当前限定为显式规范化对象名和本地 SQLite 历史，尚未解决别名、代词、省略、所有外部来源及大历史库扫描性能。后备字段处理只支持已覆盖的格式，歧义句保守拒绝／隐藏，不是通用 DLP。原有来源整体封锁不会被较窄的字段投影替代。

## 收尾工程修补与晋级边界

# 聊天记忆 P0 实施与验证

日期：2026-11-08。对应 [记忆调研](./memory-openclaw-hermes-comparison-2026-11-08.md) 的聊天明确写入、纠错、遗忘和作用范围控制。

## 行为

- 个人主助手增加 `personal_memory`，支持 `remember / correct / forget / scope`。长期偏好进入用户断言，项目事实、决定及经验进入工作知识。普通隐式学习仍由已有后台流水线处理。
- 只接受当前持久化主人输入中的明确请求和原文证据；不接受引用、否定请求、临时模式、群聊或只读会话中的写入。工具运行时再次检查主人身份与配置。
- 回执区分 `saved`、`pending`、`forgotten`，失败不返回成功回执。回执包含对象 ID、范围、生效边界和当前可用性；`saved` 且 `usable=true` 才可以告诉用户已记住并可使用。
- 更改从下一轮按需上下文开始生效；不声称已经撤回其他正在运行的模型提示。遗忘保留原始聊天和文件。
- 五种聊天作用范围的 ID 从真实执行上下文解析：global、agent、workspace、project、session。没有当前项目时失败，不回退到全局。明确的局部范围不能被模型参数扩大；局部遗忘请求也不能删除一条全局记录。
- 更改已有记录需先通过 `user_context_read / knowledge_read` 获取 ID 和版本。并发变化导致版本冲突时必须重新读取。
- 敏感信息继续受既有策略约束；需要确认的信息保留为待审状态，不能被报告为已生效。凭据与受管制信息拒绝写入。

## 复用的机制

没有新增数据库表或 schema 版本。显式操作通过已有 `executeAtomicOperation` 将领域写入与持久化回执放在同一 SQLite 事务中。幂等键绑定持久化用户消息及操作摘要，不依赖模型生成的工具调用 ID。回执不保存记忆正文，避免遗忘后留下另一份正文副本；重试同时返回当前可用性与版本。

断言继续使用 `reconcileAssertion / setUserAssertionScope / deleteUserAssertion`；工作知识继续使用现有写入、审核、修订及删除路径。聊天纠错补充新的来源证据。范围迁移抑制旧范围的重放，并允许明确移回；删除复用 suppression 和现有历史披露边界。

新证据的使用政策与共享上下文准入统一使用规范化会话路由，避免合法网页会话因缺少冗余 routing 字段而被判不可用；仍要求主人身份的私聊。

## 管理界面与 API

- 聊天步骤根据宿主提交回执显示保存、纠错、范围变更、待审和失败，不根据工具步骤结束就显示成功。
- 管理页的范围选择展示真实的具名助手和项目，保留既有工作区／会话范围，不再把“当前助手”硬编码成 `main`。工作记忆也接入范围操作。
- 画像范围 API 和新增 `PATCH /api/knowledge-memory/:id/scope` 要求读取版本，过时修改返回 409。既有 lazy-bundle 前缀已覆盖新路径；增加映射与邻近负例测试，并通过运行中的鉴权 HTTP Gateway 验证新路径。

## 验证

相关回归共 32 个文件、271 项测试通过，覆盖：

- 真实个人主助手工具工厂暴露及执行边界；
- 保存后数据库重开、不同工具调用 ID 的幂等重试；
- 写入回执失败时，记忆、证据和回执共同回滚；
- 纠错后的旧值保护、旧版本拒绝、作用范围迁移及移回；
- 缺少项目、局部请求被扩大、群聊、临时模式、只读策略和敏感待审；
- 遗忘、来源历史边界、删除抑制与后台学习回归；
- 实际鉴权 Gateway 与 lazy dispatch、管理页具名范围选择及聊天回执文案；
- 既有上下文组装、个人提示词裁剪和个人主聊天集成。

Node/Electron 类型检查、Web 生产构建、受影响源文件 lint 和 `git diff --check` 通过。Node 构建也执行验证。测试使用临时数据库或内存数据库，没有修改个人记忆数据库。

## 真实模型验收

使用 `deepseek/deepseek-flash`，启动隔离 Gateway、SQLite 和工作区，通过鉴权 HTTP 输入及签名浏览器 WebSocket 端点发送真实对话，另有 CLI 来源检查。只复用模型配置和凭据，不复制生产聊天或记忆；临时配置在退出时删除。逐项核对工具回执、数据库状态和后续回答，并检查转录没有重复。

真实验收发现并修复：

- 纠错中重复传入原范围曾被误拒绝；现允许保持原范围，改变范围仍须独立命令和版本校验。
- CLI 人类输入偶尔返回 `NO_REPLY`；复用网页端已有的可见答复恢复机制。
- 同进程重建服务后，旧转录监听器未解绑造成重复落库；停止服务时解绑并补充生命周期回归。

最终 **27 / 27 通过**，覆盖五种作用范围、范围外隔离、版本和真实回执、同进程重启、临时模式拒绝，以及强制历史重建后遗忘内容不复活。该结果来自单一模型和合成语料，没有视觉 UI 验收。后续自动学习及召回的综合验证见 [P1 自动学习记录](./memory-learning-p1-2026-11-08.md)。

```sh
XOPC_MEMORY_LIVE=1 pnpm exec tsx scripts/personal-memory-live-smoke.mts
pnpm exec tsc -p scripts/tsconfig.memory-live.json
```

`XOPC_MEMORY_LIVE_MODEL` 可指定已配置模型，`XOPC_MEMORY_REPORT` 可指定报告路径，`XOPC_MEMORY_LIVE_CASES=basic` 运行基础流程。完整验收会调用真实模型并产生用量。默认报告写入本地 `reports/memory/chat-memory-live.json`；运行报告不进入版本控制。

# Personal memory 后续 benchmark 与优化实施方案

日期：2026-10-23。状态：方案设计，尚未生成新验收集、修改产品逻辑或启动模型实验。

执行记录：以上为方案制定时状态，原门禁保留；本轮实际执行及验证停止原因见 [Memory P0 执行报告](./personal-memory-source-boundary-comparison-2026-10-23.md)。

依据：[上一轮报告](./personal-memory-p0-comparison-2026-10-22.md)、[原始评测方案](./personal-memory-benchmark-plan-2026-10-22.md)。设计时主线 HEAD 为 `42a6465ff`，pi-ai／agent-core／coding-agent 为 1.4.0。核对的 memory-learning、background-review、session 检索和 memory eval 目录与上一轮代码提交 `81caf352b` 无差异；历史在之后经过整理，运行身份应使用源码／锁文件／配置指纹，不只看提交标题。

## 1. 决策与优化顺序

下一轮以既有 LongMemEval 120＋中文 64 为稳定回归，新增真实可写事件流验收，按“协议可信 → P0 披露边界 → 偏好／更正链 → 全量复测”推进。每轮只改一类机制，避免同时换模型、扩上下文、改写入和换排序后无法归因。

| 优先级 | 已有证据 | 下一步改进 | 要证明的结果 |
| --- | --- | --- | --- |
| P0 | 派生正文已无日期，但 knowledge_read 的 evidenceQuotes 与授权重读后的对话副本仍泄漏 | 统一 LLM 可见来源投影；将原始来源限制传播到工具结果、助手复述和新副本 | 非授权回顾不泄漏；当前轮同对象／字段的显式原始记录读取仍可用；非目标事实保留 |
| P1-1 | 偏好原生仅 5/20；中文自动注入证据充分仅 24→25 | 分开修未保存、已存未选、选中未用；按主体／项目／日常或单次作用域选择与打包 | 有用个性化提升，同时不强行使用无关偏好、不编造记忆 |
| P1-2 | 300 星助手复述覆盖 120 星用户更正；人物归属与事件去重出错 | 检索完整更正链、区分来源角色、建立事件与时间字段绑定 | 当前事实、历史原话、当时已知分别正确；多跳和计数证据完整 |
| P1-3 | 非重复链接抽取错误从 66 增至 79 | 改善 schema 表达、槽位基数与错误可观测性，独立消融 | 有效写入覆盖提升；幻觉、越权准入、敏感约束不放宽 |
| P2 | 强制学习检查点、大库与异步交付覆盖有限 | 增加自然学习收敛、超过 80 条目标发现、规模与任务交付轨道 | 测清真实就绪时间、旧目标遗漏、成本曲线与最终交付成功率 |

P0 过关前不以总分上涨作为晋级理由。上一轮 88/120、52/64 是 pi 1.1 隔离协议的历史成绩；当前 pi 1.4 的四条控制不能替代当前版本全量基线。

## 2. 三层评测，各自回答一个问题

### 第一层：组件回放，不调用模型

从合成世界和已关闭的测试数据库构造固定状态，直接回放写入、过滤、读取与排序。只在隔离测试库中执行，保留权限与来源校验。

- 删除前确实存在目标 → 删除后 active 内容、索引和可见投影都不包含目标；不能把从未写入算作删除成功。
- 保留地点／负责人等非目标事实时，LLM 可见证据引用不能夹带被遗忘的日期。at-rest 原始证据继续用于授权审计。
- 原始来源、工具结果、助手复述、重读后新对话及重启后的读取，逐个通路做断言；检查渲染后的实际文本，而非只查 SQLite 正文。
- 请求授权只对当前作者轮、正确对象和字段生效；引用、否定、其他项目／主体、过期或跨轮授权均不放行。
- 测真实 scope 元数据、来源授权与撤回；中文项目名不同不是 ACL 隔离测试。
- 80 条以内／以外的目标，以及干扰事实 100、1,000、10,000 条，分别测发现覆盖与读取时延；已知大库限制必须列出，不以小库通过替代。

组件层采用同一个学习后快照，给不同检索候选复制出相同的只读输入，减少重复抽取成本。学习／更新候选则必须从原始事件重新摄入；不能给它复制“已经学对”的库。

### 第二层：真实可写的事件流

新增 episode 轨道，显式记录动作与预期状态：

`导入或真实用户输入 → 学习检查点 → 前台提问 → 用户更正／遗忘 → 显式单次重读 → 再学习 → 新问题／新会话 → Gateway 重启 → 再回顾`

同一 episode 内动作顺序执行，不同 episode 并行。评估过程使用合成个人数据、隔离数据库和可控连接器，不读取真实账号业务数据。分为“强制完成检查点”和“自然调度收敛”两种模式，分别报告。

P0 建议首批 **8 个开发事件世界＋8 个独立验证世界**，每个世界设 4 个核心检查点，共 32＋32 个检查；检查点数不当作独立样本量。结构覆盖复合事实保留、两次更正、多来源复述、嵌套工具输出、授权重读副本、跨会话重启、多对象／字段限制、真实 scope 与引用／否定指令。验证世界需改变事件结构及证据路径，不能只换人名、项目名或日期。尚未支持的其他字段保持保守拒读，单列为能力边界，不能给其偷偷增加授权。

四个核心检查点：

1. 目标原先成功保存，合法非目标事实可用。
2. 遗忘后普通回顾不披露目标，工具投影也不泄漏，非目标事实仍能回答。
3. 当前轮显式授权重读能获得合法目标；当前实验所支持的字段与 scope 明确。
4. 重读学习后、普通后续提问／新会话／重启不能再次自动披露；同时检查派生正文与 provenance／副本。

任一检查点出现泄漏，episode 失败，即使最后一句回答恰好没有重复值。相反，全拒答不能通过检查点 1／3 的正向对照。有限测试零违规不等于对所有场景的保证。

### 第三层：固定端到端回归

保留原 184 条题面、原生 rubric、中文 v1 与完整分母。旧题中的歧义另标注，不静默修题或重判到通过。扩展后的 live-turn 题不混进这 184 条；确需修正的中文 v2 作为独立版本轨道。

当前版本小基线与独立验证通过后，冻结 A＝当前主线、B＝最终候选，用同一 pi 1.4 锁文件和同一评测协议补齐 A／B 全量。新基线稳定后，后续相同身份的 A 产物才可复用。原 88/120 用于历史趋势，不用于把 SDK／协议差异记作本轮收益。近期仍用 184 条完成工程回归；稳定后再扩官方完整集，而非每次小修改都重跑最大集合。

## 3. 新增场景要贴近 Personal Agent 的使用

P1 首批建议另编 24 条开发查询与 24 条独立验证查询，按以下六类分层。数量是实施预算，尚未宣称已有数据或验收结果；同源问题按世界分组切分。

| 场景 | 正向例子 | 必须成对覆盖的负例／难例 |
| --- | --- | --- |
| 隐式偏好应用 | “通勤路上做点什么”，自然使用已知播客兴趣 | 不相关工作问题不插入饮食／兴趣；未知偏好不编造 |
| 日常与临时限制 | 平时不辣，这次聚餐可以辣 | 同事素食不能变成本人素食；单次预算不能常驻泛化 |
| 当前与历史视角 | 现在由谁负责、此前谁负责、当时已知交接日期 | 后知的更正不能污染当时视角；计划不是已完成 |
| 人物与项目关系 | 同名两人、岗位改变、昵称、两个并行项目 | 用户职业不能归给小说人物；项目名不能当负责人 |
| 完整证据与更正链 | 五件物品计数、两段费用差、用户纠正助手说法 | 搜到三件不能当已搜全；最新文本未必是最高权威 |
| 来源选择与交付 | 历史可答的就诊次数、需要当前日历的空闲查询 | 未连接时的历史回退、确需连接时的正确说明；异步任务分别评接单与最终交付 |

“当前事实由谁确认”与“历史助手当时说了什么”是不同任务；不能用全局“用户永远优先”规则损害历史助手回忆类题。

## 4. 指标从来源到使用分层记录

每题保存 `source → extraction/admission → active fact → candidates → selected → rendered → tool-visible evidence → answer/action`，并带当前时间视角、实际作用域、过滤理由和来源链。

- 写入：合法应记事实的覆盖、无依据写入、错误主体／字段、更新后旧值误用；策略拒绝与格式失败分开。
- 召回：候选、预算内选中、实际渲染、工具补查后的必要事实覆盖。以原子命题及允许的等价证据组计，不以同一 turn 被命中就宣称整题召回。
- 回答：QA 准确率、证据支持、错误弃答、人物／项目混用、推荐的实际有用性。
- P0：每条可见通路的泄漏、当前轮正向授权成功、后续授权过期、非目标事实保留；状态与最终回答分别评分。
- 效率：抽取与查询 token 分开、调用数、p50／p95、失败与修复次数；自然模式报告来源进入到可检索就绪的时延。账单未知保持 null。

对 P1 开发查询增设三个条件：当前 memory、no-memory、合法 oracle。no-memory 关闭派生事实、历史工具与其他记忆快照泄漏，保留相同当前问题、模型和基础人设；oracle 只在 evaluator 侧按当前 scope／时间／遗忘状态提供最小合法证据，不提供禁用值，也不参与写入。必要时再加固定预算的原文轨道。

这能区分：没记住、没取到、取到了却没用，以及即使给合法证据也答不好。优化目标是相对 no-memory 的任务净收益，不是记忆数量或上下文长度。oracle 是诊断上界，不是可发布方案。

## 5. 先补协议的四处缺口

1. **完整 live 证据**：把真实用户、助手、工具动作及学习前后 checkpoint 作为裁判的一等证据；不要让 gold 要求“曾遗忘”，sourceContext 却没有该指令。金标、裁判结果和后续题目禁止进入被测学习。
2. **实际模型核对**：冻结回答、抽取、修复、后台路由与裁判的解析结果；记录可获得的供应商版本与实际 thinking，版本不可得时披露。隔离与本轨道无关的自主后台；不可隔离的调用也必须追踪并纳入协议核对，不能漏记 advanced 等别名。
3. **真实请求限流**：继续生成 4、裁判 4，但应在每个实际模型请求边界取得共享额度，包括格式修复和工具内调用。案例调度与模型请求额度分离；不同时持有外层 turn lease 再等待同池内层请求，避免死锁。用合成并发调用与请求 trace 证明实际峰值受控。
4. **配置与错误身份**：一次冻结 semantic defaults／memory policy、数据、代码与锁文件，运行中不能逐题从变化的全局配置读取。凭证仍走标准安全刷新，不归档秘密。来源选择、未连接、异步未交付、候选服务失败、裁判服务失败分别保留；只按事先声明的协议补空裁判服务错误，不重生成低分候选。

改变适配器或后台生命周期后，A／B 都在新协议重测；不能用新协议 B 对旧协议 A 直接归因。

## 6. 小规模消融与候选晋级

### P0 轮

先做确定性的四条件回放：当前、仅来源投影、仅副本限制传播、二者同时。它用于证明各通路是否堵住，不需要四份全量 LLM 重放。保留来源审计、合法显式读取与非目标事实；不以删光记录或只加拒答提示作为修复。

通过组件检查后，仅在开发 episode 做少量真实模型对照，冻结一个候选，再开独立验证。开发阶段使用的失败案例全部退出“未见”身份。验证若失败，保存结果并停在小规模；如分析失败后继续改候选，旧验证集转为开发回归，需要新的独立世界再作晋级。

### P1 轮

在相同读预算与相同学习快照下比较最多三个条件：A 当前选择；B 仅主体／作用域与证据组排序；C 在 B 上增加有界的按需补查。仅当 trace 表明未保存占主要比例时，改做抽取候选，不同时混入排序更改。召回阶段先使用现有词法／实体／时间信息，是否需要新模型精排或其他存储由结果决定。

开放推荐另作匿名 A／B 成对评估，以正反展示顺序和必要事实支持检查观察“更有帮助、同等、变差”；它补充推荐可用性，不覆盖原生 QA 分数，也不能让流畅答案抵消泄漏。

### 预先冻结的门禁

- 协议：源码／数据／锁文件／semantic config 相符，实际模型身份明确，生成与裁判各池最大 4；问题、金标、oracle 不污染学习。
- P0：覆盖世界的禁止披露通路零观察到的泄漏，合法重读、非目标事实和引用／否定负例全部通过。小样本零观察不作全局安全结论。
- P0 轮的全量要求是闭合目标缺陷且不引入重要回退，不要求为了总分额外调偏好。P1 轮才要求目标分组有净收益；时间／更新、错误拒答、主体隔离与自然度作为保护指标，新增重要回退逐题阻断。
- 小样本可事先指定 3 次独立运行，全部结果入账；区分固定学习库的回答波动和重新摄入波动。不可看到一次低分后临时只加跑到通过。
- 资源沿用原方案以 20% 增幅作讨论起点；pilot 后在看候选分数前冻结绝对预算与非劣界。费用未知时报告 token 与时延，不能冒充实际费用。
- 统计按世界／episode 分组配对，报告改善与回退，不把一个世界的四个探针当四个独立用户。样本不足时只报告方向，不作最优结论。

## 7. 实施批次与交付

| 批次 | 工作 | 交付与停止条件 |
| --- | --- | --- |
| 1 | 修适配器身份、live 证据、请求池；把现有泄漏做确定性复现；编写并封存新世界 | 小基线、逐层 trace、P0 开发／验证清单；协议不过不跑候选全量 |
| 2 | 修来源投影与重读副本限制传播，完成 P0 组件回放及真实可写验证 | 单独 P0 产品提交、完整正反例；验证失败停在此批 |
| 3 | 在同协议当前 A／候选 B 上完成 184 条，核对两轮保护项与所有新增回退 | 正式配对报告；P0 未闭合不能靠总分晋级 |
| 4 | 开始偏好／更正链的 24＋24 小规模实验，并加 no-memory／合法 oracle 诊断 | 选出一个有证据收益的候选，独立验证通过才再跑全量 |
| 5 | 自然调度、规模、真实作用域和任务最终交付；稳定后扩大社区集 | 就绪延迟／规模成本曲线、工具环境验收；不同轨道分别报告 |

沿用测试／抽取 `xopc-cloud/openai-codex/gpt-5.6-sol`、裁判 `xopc-cloud/openai-codex/gpt-6.1-sol`。所有独立事件世界共享生成 4、裁判 4；同 episode 的动作与学习顺序保留。

模型预算重点花在少量真实路径和最终回归；组件／检索消融优先用隔离快照，目标是减少每改一个细节就重复 5,931 个抽取任务。新协议当前 A 与 B 全量初次可能各需一次，上一轮单次捕获约 3 小时 46 分，仅供预算参考，不能承诺当前版本运行时间或费用。先根据新协议 pilot 的实际吞吐与用量预估，再启动昂贵阶段。

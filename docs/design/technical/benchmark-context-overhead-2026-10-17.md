# xopc benchmark v1：上下文与工具开销优化

日期：2026-10-17（Asia/Shanghai）。同一套 xopc-core@1.0.2、Qwen qwen3.8-flash、medium；每场景仍为 300k 总 token（包含缓存）、40 次模型请求、5 分钟。评分器、任务、后续输入和 fixture 未修改。

## 根因

原失败场景每次模型请求重复携带约 2 万 token 起步的上下文；首次请求暴露 51 个工具声明，系统提示约 24k 字符。四项累计 52 次完成响应、1,249,203 总 token，其中缓存读取 1,150,208 token（92.1%），输出仅 14,130 token。缓存降低计费或延迟的可能性不能消除累计上下文预算消耗。

- D02：重复读取邻近无关文件、针对 macOS 不支持的 cat 参数重试、完整产物回读、多次运行复现脚本及临时校验文件清理。产物核验通过但预算耗尽。
- C01：首轮执行、workspace review、后置校验重复；第二轮追加需求已落实，但最终结束前触发预算。
- C02：同样的首轮重复检查耗费预算；第二轮尚未完整交付便触顶，产物核验也未通过。
- F01：首轮读取无关输入并重复核验，第二轮检查、重算和补写恢复产物时触顶；实际删除了两份文件，核验未全部通过。

## 修改

- 普通 agent 保留文件编辑和验证工具为即时声明；辅助工具与非常用内置工具经现有 pi tool_search 加载原始合同。没有削减权限或 allowlist，也没有绕开原来的授权、禁用规则和恢复边界。Personal 的固定工具面保持原状。
- 通用执行指导约束无关读取，鼓励独立读取批量处理、复用已验证事实、只更新受需求变化影响的输出，并在发生变化后做一次有意义的验证；自定义断言采用可识别的独立测试命令。原有验证机制保持有效。
- 每次修改、执行和审查的模型可见工具回执及时列出尚缺的验证证据；不被识别为测试的命令明确给出独立断言测试指导，避免结束后才发现遗漏。已成功的证据仍绑定当前文件版本，后续修改会重新要求校验。验证命令分类和成功门槛没有改动。
- 首次请求日志增加工具声明字符数与估算上下文 token；评测指纹纳入新建且未提交的运行时代码，避免遗漏本次新增模块。
- 使用独立 worktree 快照执行，排除共享目录同期未提交的其他功能改动。原始运行与被中止的共享目录诊断记录均保留。

### 仍未解决的两项

- **C01：313,374 token，20 次响应。** 本轮所有工具调用仍发生在首轮，追加需求尚未执行。首次测试与审查后，模型自行增加输入表头检查，反复修改脚本、回读并复验，最后又修改报告。上下文缩减被额外工作抵消；第三轮曾通过，但不能拿第三轮结果替换本轮失败。这说明单次通过不足以证明该行为已稳定修复。
- **C02：322,625 token，20 次响应。** 首轮读取了与销售任务无关的其他输入，串联测试与检查命令后补跑独立测试，又润色报告并重复审查；第二轮修改脚本、结果说明与测试后仍在收尾阶段触顶。减少单轮声明没有稳定减少执行步骤。

后续需要直接处理无关工作和验证后的额外修改，并分析跨轮剩余预算反馈与过时审查内容的重复携带；不能再仅凭扩充提示或某一轮通过认定解决。当前保留这两项失败，未放宽任何评分、预算或验证门槛。

第一轮仅缩减上下文的完整实验保留于 `.xopc-evals/qwen-core-v1-context-frozen/benchmark/`：C01 仍以 20 次响应、300,977 token 超预算；R03 输出 `missing: ["ttsCents"]` 而要求 `missing: ["tts"]`，按严格规则失败。分析后将最终校验的直接命令要求提前告知模型，并限制无关输入与额外交付物，再以新代码修订执行本轮完整实验。所有失败保留，不修改评分。

第二轮仅强化通用执行提示的完整实验保留于 `.xopc-evals/qwen-core-v1-context-verification/benchmark/`；它仍暴露了重复校验问题。因此最终修订进一步将缺失验证证据放进模型可见的工具回执。本报告主表仅比较原基线与最终修订；历史实验独立列于 `evals/coder/baselines/xopc-core-v1-history.json`，不合并样本或挑选各轮最优场景。

第三轮工具回执修订保留于 `.xopc-evals/qwen-core-v1-context-receipts/benchmark/`，为 8/10：C01 已通过，但 C02 仍超预算。最终修订进一步将最大的常驻 schema `data_batch` 及计划、状态、澄清、手册等辅助工具按需加载。文件编辑、命令、差异审查和任务交付合同直接可用；单个读取无需发现工具。

调用计数需结合完成情况解释：原四项在超预算处中止，新轮可能执行更多步骤才完成全部需求，因此不能用中止轨迹的较少调用宣称原执行更高效，也不能宣称本次已全面降低调用次数。主要验证收益是每轮上下文与累计预算；不把多次开发试验拼成一个最优成绩。

## 验证与证据

- 117 项针对性测试、完整评测框架 31 项测试通过；隔离 worktree 还复验了 61 项工具发现、授权边界与验证测试，类型检查和相关 lint 通过。
- 测试证明非常用工具可按需加载、跨轮恢复并执行；禁用工具不会重新出现。原有 Personal 边界和 coding 验证检查保持通过。
- 原基线：`evals/coder/baselines/xopc-core-v1-qwen.json`；新基线：`evals/coder/baselines/xopc-core-v1-qwen-context-optimized.json`。
- 完整新报告：`.xopc-evals/qwen-core-v1-context-lean/benchmark/`；对比：`.xopc-evals/qwen-core-v1-context-comparison.json`；原始轨迹：`.xopc-evals/qwen-core-v1-300k/benchmark/`。

这是每种配置各一次的配对观察，不是生产可靠性估计；云端缓存状态和模型生成存在波动，耗时不用于宣称稳定加速。工具计数仅指模型可见调用事件。当前套件仍为直接 agent 工作区执行，不覆盖 Personal 异步交付全链路。

# 微信对话配置：安全输入、OAuth 回流与原私聊续跑

日期：2026-10-28。接续[对话配置产品方案](../conversation-first-configuration-product-plan-2026-10-28.md)和[第一阶段验收](conversation-configuration-implementation-2026-10-28.md)。本轮保留前一阶段工作树，不提交或发布。

## 交付范围与权限

微信用户直接说明目标，例如“连接这个资料服务，查一下我的资料”。Agent 创建一个绑定当前账号、私聊、conversation、transcript、助手、服务地址和版本的持久请求，然后发送可点击的安全入口。微信配对仅允许提出请求；网关 owner 需要登录安全页面，核对账号、私聊身份、服务和原始目标，并明确批准这次连接，随后再输入 Token 或进行 OAuth。链接本身不授予管理权限，转发给未登录用户也不能读取或提交密钥。

前置条件：微信账号已登录且已配对／明确白名单批准；`session.dmScope=per-account-channel-peer`，无身份合并；配置可由手机访问的 `gateway.publicUrl`。公网必须 HTTPS，本地协议验收允许 loopback HTTP。当前不自动创建公网入口，也不把共享会话改造成私聊。共享／合并路由、群聊、通配符准入以及未批准的发送者不会进入配置流程。

实际入站账号和聊天身份由生产微信适配器提供，并与 SQLite 路由复核；绑定还包含登录凭据及服务地址的不可逆版本摘要，退出或更换机器人登录后，旧请求与旧提醒不能投递到新身份。模型传入账号、setup ID 或伪造 origin 都不能扩大权限。owner 授权只核准一个连接目标；微信侧不通过该入口替换已有服务、删除其他连接或获得通用配置权限。

微信新连接的技术 ID 由宿主按已验证身份和规范化服务地址生成，避免模型重复命名导致不同服务互相覆盖；重复连接同一服务会提示验证实际可用性。新连接仍保存在网关共享 MCP 配置中，后续工具可见性沿用助手工具策略；本轮没有新增按微信用户隔离全部 MCP 工具的租户权限系统。owner 应只批准受信任助手可使用的服务。

## 密钥与 OAuth

Token 在经过 owner 认证的 `/mcp-setup/:id` 页面输入，密码框掩码、提交后清空；CredentialResolver 保存密钥引用，模型、微信消息和普通配置不接收密钥。错误密钥可重输；目标过期、取消、重置、换助手、配对撤销或路由改变会阻止旧操作继续。

OAuth 仍由 pi 负责发现、动态客户端注册、PKCE、state、code 校验、交换令牌和凭据保存。为解决手机无法访问 Gateway 主机 loopback 回调的问题，对固定版本 pi 1.4.0 增加了小型包补丁：宿主可提供临时 `callbackRelayUrl`，原生监听器仍保持 loopback，原生 redirect 校验与令牌处理保持原职责。该字段仅由宿主在短期登录会话中注入，不进入模型参数或持久 MCP 配置。

公共 `GET /mcp-setup/callback/:id` 只转交已批准、未过期、匹配当前 attempt 的 OAuth 响应。它不批准请求、不挑选目标、不交换令牌。使用部署配置中的 origin，不信任 Host／Forwarded Host；限制字段和长度，拒绝重复 query 参数；返回 no-store、no-referrer，并以不含 code 的地址回到安全页面。取消、重复或旧 attempt 回调不能复活目标。原生授权完成由宿主持续观察，用户关闭安全页后仍可完成保存和原会话续跑；重启会中止临时 OAuth attempt，重新进入页面后需再次授权。

OAuth 服务需要允许注册该 Gateway 回调；只允许固定回调白名单或有特殊客户端注册要求的第三方服务还需各自适配和验收，不能以本地协议通过替代兼容性结论。

## 原会话续跑与投递

配置保存且运行时生效后，以稳定 `mcp-setup:<id>` 输入身份在原 conversation／transcript 中排队。执行前再次检查原目标、路由、配对和配置版本。真实模型发现原生工具并完成原始只读目标；配置成功不作为业务读取成功证据。

完成后，结果通过生产微信出站适配器发回绑定的原账号和原私聊。该类投递强制匹配原账号和原始接收人，不允许缺少上下文时改用其他账号或模糊匹配接收人。安全页面不跳到一个新的 Web 聊天，而是提示关闭页面、回微信查看。投递必须取得渠道成功响应；读取完成但微信发送失败时，保存已有结果和失败状态，允许只重发已有结果，避免重新调用模型或业务服务。重启也可重试未完成投递。渠道成功但本地确认未落盘时仍可能重复投递，不承诺跨网络 exactly-once。

普通一次性提醒复用自动化的持久调度与结果 outbox，不依赖公网安全页地址。来自受支持微信私聊的创建／投递设置变更由宿主附加原会话及 principal 绑定，不采纳模型指定的其他微信接收人。成功提醒用 `notificationPolicy:all`；`none` 保持静默，`attention` 只发需处理的状态。后续发送前重新复核身份与配对，失败沿既有 outbox 重试，不重新执行任务。外部 MCP 来源自动化的来源准备仍要求原有 owner 能力；本轮没有把所有外部来源授权自动开放给微信。

## 手机端自测清单

使用专用测试私聊和测试数据；先确认机器人登录、该身份明确配对、私聊独立路由，以及手机可访问的 HTTPS Gateway 地址。安全页应使用网关 owner 登录；不要把 Gateway Token、MCP Token 或密码发进微信消息。

| 场景 | 用户操作 | 通过标准 |
|---|---|---|
| Skill 安装与使用 | 在原私聊说“安装这个周报能力 <可信 Skill 包地址>，总结 A 100、B 200” | 对话实际安装并给出总额 300、最高 B；能继续停用、启用和卸载，不停留在口头承诺 |
| 安全输入 | 说“连接 <测试 Token MCP 地址>，查我的资料”；打开链接并核对服务与私聊，批准后输入错误再正确 Token | 未登录不能配置；错误能修正；密钥不进消息；无需发送“继续”，原私聊收到实际资料结果 |
| OAuth 回流 | 连接允许该 Gateway 回调的 OAuth 测试服务；批准，授权后关闭页面 | 手机能访问回调；原私聊自动收到实际业务结果；未新建 Web 会话；拒绝授权不会显示已连接 |
| 取消与过期 | 发起一个新连接，在原私聊取消，再使用旧安全链接 | 旧入口不再写配置，也不恢复原任务；可重新从对话发起 |
| 发送失败 | 在测试环境临时阻断渠道投递，完成连接与资料读取，再恢复投递 | 页面显示待重发／失败；恢复或点重发后收到已有结果，业务读取不重复执行 |
| 定时任务 | 说“60 秒后提醒我喝水，完成后发回这里”，期间重启测试 Gateway | 任务真实到时执行，结果回原私聊；可用对话查看、取消；静默策略不误发 |
| 身份隔离 | 用另一个账号／私聊打开转发链接，或撤销原身份配对 | 无 owner 认证不能读写；不把原任务结果投递给另一个身份；旧请求不能复活 |
| 微信体验 | 从微信实际点链接、返回聊天、锁屏后再回来 | 链接未被格式化剥离，安全页可用，授权状态可恢复，结果和下一步表达清晰 |

# Phone Use 第二阶段：常驻观察与字段短事务

后续针对模型提前结束的处理与复验见[有界完成纠正报告](phone-use-completion-recovery-2026-10-27.md)。

日期：2026-10-27。基线为第一阶段提交 `bcbec9702`，当前实现不更换模型、提示词、采样或消息协议；实验性语义控制、分层规划与批量视觉读取均保持关闭。

执行层已完成：字段输入中位数从 3156 降至 40 毫秒；最终面板双方都完成的 7 对任务，端到端中位数降低 44.2%。但最终完成数为基线 8/8、候选 7/8，不能宣称整体完成率提升或非劣。失败来自模型连续过早结束，原样计分。

## 实现

- 一个操作内复用设备端 `app_process` / `UiAutomation`，请求通过有界 JSON 行协议在现有 ADB 通道上传递。本地使用 ADB 子进程，云端使用独立认证连接上的 exec socket，无需端口转发或安装 APK。
- 每次观察重新读取原生树并清理无障碍缓存，使用 50 毫秒间隔、最多三次重采样寻找短暂稳定窗口，持续变化时有界返回最新树，随后独立获取截图、前台包和方向。派发前的新鲜度检查、完成条件与独立观察没有取消。观察服务复用的是连接和进程。
- 操作结束、取消、人工接管和释放控制权会关闭观察进程。打开中的服务若晚于清理完成，也会关闭，不重新取得控制权。生产代码不会停止其他 UiAutomation 所有者；测试仅清理专用 AVD 的 CLI instrumentation。
- `typeText(mode=replace)` 对唯一聚焦、可识别的非密码原生编辑框执行短事务：检查应用、resource ID、位置、完整旧值，执行一次 `ACTION_SET_TEXT`，再确认应用、焦点、同一个 Android 原生节点及精确新值。输入引起的编辑框高度变化通过原生节点身份校验处理。
- 字段事务支持中文和 emoji，不依赖剪贴板。插入模式和旧驱动集成仍保留原通道；长旧值被截断、字段无法识别或结果不确定时拒绝/暂停，不自动切换通道重放写入。
- 协议限制响应大小、请求并发和超时；断连、取消、错误 ID、拒绝与不完整响应均关闭通道。诊断只记录耗时、次数和固定原因，不记录字段内容。

## 验证方法

真实模型面板使用 `autoglm-phone`，专用 Android 15 AVD `XOPC_Android_Test_API_35`。设置显示、设置搜索、文件搜索和联系人搜索覆盖滑动、聚焦与精确输入。每任务 AB/BA 两次，起点以同一原生 UI 指纹匹配；终点由两次独立原生观察计分，并检查设置值与测试文件哈希。初始状态不匹配时整对排除，保留原始记录，不能计作完成或提速。

输入机制检查连续执行 `咖啡 → 地图 → 咖啡😀 → 含特殊字符的测试字符串`，各次都有独立整屏字段核对。云端 Driver 用本地 ADB 桥运行真实设备 helper、持久 exec 通道、截图与字段事务；该检查不代表公网云手机延迟。

## 结果

### 字段与通道机制

最终实现按 AB、BA 顺序各验证一次，每臂共 8 次中文、emoji 与 `& < > "` / 字面实体文本替换，全部通过独立整屏原生值检查。

| 指标 | 第一阶段基线 | 第二阶段 |
| --- | ---: | ---: |
| 单字段输入动作中位数 | 3155.5 ms | 39.5 ms |
| 每组四次替换与前后观察 | 20.404–20.530 s | 2.129–2.320 s |

字段动作中位数降低约 98.7%；包含观察的整组耗时降低约 89.1%。该组输入计时从观察服务已启动、字段已聚焦后开始；不包括模型、启动应用及首次连接。两种顺序均复现，但样本量不能估计生产 P95。

云端 Driver 的本地桥验证两次都通过 Unicode 精确写入与过期旧值拒绝检查，拒绝后新建观察通道复查原值未被覆盖。首次全观察 326–367 ms，后续 10 次中位数 217 ms；其中一次为 451 ms。对照的一次性云 helper 全观察为 1171–1195 ms。这里包含真实设备上的 UI 树与截图，未包含公网云网络，不能据此承诺阿里云真实延迟。

### 初轮模型面板

修正稳定采样与 XML 读取前的首轮保留 7 对有效起点，完成数 5/7 → 7/7，误报完成为零，有效配对请求数均为 18。双方都完成的 5 对任务，端到端中位数 20.967 → 11.233 秒。另有一对联系人起点不同，整对排除；全部试跑共 38 次模型请求。文件搜索的两次基线失败属于模型过早结束，不能把其较短失败时间当作速度优势。

本轮发现两次滑动后 6 像素微动导致额外模型请求，因此最终版本加入有界稳定采样。还修复了 XML `getAttribute` 将 `& < >` 再次转义的问题，改读解码后的属性值；特殊字符与字面实体回归均通过。初轮面板与最终版面板分开计分。

### 最终模型面板

最终源码冻结后，同四任务重新按 AB/BA 各跑两次，全部 8 对起点一致。该面板保留应用进程并重建页面，额外预热联系人字体，避免初轮起点差异；两臂每次试跑都释放测试 CLI 仪器服务，端到端计时包含观察服务启动。不能直接将两个面板的绝对耗时混为一组。

| 真实任务 | 基线完成 | 最终候选完成 |
| --- | ---: | ---: |
| 设置显示页 | 2/2 | 2/2 |
| 设置搜索 | 2/2 | 2/2 |
| 文件搜索 | 2/2 | 1/2 |
| 联系人搜索 | 2/2 | 2/2 |
| 合计 | **8/8** | **7/8** |

- 双方都完成的 7 对，端到端中位数 **19.674 → 10.978 秒**，降低 **44.2%**。失败样本不参与“成功完成提速”统计；全体 8 轮耗时中位数另存证据，不能脱离完成率使用。
- 模型请求 **20 → 18**。每轮平均全观察耗时的中位数 **980 → 285 毫秒**。这些观察仍包括截图和前台检查；不是只计树读取，也不将重叠阶段相加当作墙钟时间。
- 最终候选没有过期预测丢弃；显示页两轮均未重现初轮的滑动微动重预测。此结果不证明任意动画都已稳定。
- 唯一候选失败发生于文件搜索：模型两次直接结束，没有派发任何动作，随后生成一次只读说明；原生 query 仍不匹配。`verified=false`、`stopReason=model_finished_unverified`，没有误报成功、字段拒绝或重复写入。
- 所有试跑均未触发预设作用域拒绝，测试设置与文件哈希检查通过，测试动画配置已还原。初轮加最终面板共 **76 次真实模型请求**，没有运行生产账号任务。

## 工程验收

- 34 个 Phone Use 测试文件：462 项通过、1 项平台条件跳过。覆盖分片 UTF-8、响应上限/错误 ID/EOF、取消等待清理、迟到服务关闭、精确输入单次发送、密码/截断旧值拒绝和 XML 单次解码。
- 设备 helper 在专用模拟器上取消未完成的观察后，请求拒绝、设备端进程退出并释放所有权；不会仅关闭宿主句柄而留下常驻进程。
- 根/Electron 类型检查、评测脚本类型检查、定向 ESLint、Node/声明/Web 与 Electron Gateway 构建、文档检查均通过。

复验入口仍为 `scripts/benchmark-phone-apps-live.mts` 和 `scripts/verify-phone-efficiency-live.mts`。后者新增 `--reverse-input-order`，可复现输入 BA 顺序；`--helpers-only` 包含真实取消与进程退出验证，默认不调用模型。

## 范围与后续

本轮验证系统应用和测试数据，不涉及生产账号、第三方应用或真实交易。小样本完成率不构成统计非劣证明。模型长输出、格式失败和过早结束仍可能主导总耗时；设备端执行提速不能单独解决这些质量问题。下一项质量优化应优先处理显式完成条件未满足时的过早结束及有界纠正；现有逻辑仅纠正一次，继续优化时必须保留动作授权和请求预算边界。同地域 Runner、真实云网络与其他专用手机模型需要单独验证。

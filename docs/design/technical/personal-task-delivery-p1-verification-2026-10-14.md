# Personal delivery P1：证据、逐项验收与简洁回复

日期：2026-10-14（Asia/Shanghai）。业务代码已在工作区落地；未重启用户日常 Gateway。此前其他任务的改动未回退。

## 本轮实现

1. **后台展开验收条件**：普通任务使用默认笼统合约时，后台分配阶段调用现有合约规划器提取具体完成条件，并在开始执行前保存新合约版本。显式条件保持原样，权限、约束和审批边界不因模型规划扩大。规划与分配共用有界超时；未展开的默认条件不能被泛泛的“完成”判定认证。
2. **结构化研究成果**：新增 `publish_task_result`，保存来源、结论和逐项验收。来源必须绑定当前执行中已持久化的成功工具结果：引用原文、工具调用 ID、工具名称、读取时间和 SHA-256。结论引用来源 ID，并区分事实、推断和建议。假原文、假网址、跨来源错误引用在审阅前被拒绝。
3. **两种核验分开**：程序验证引用与真实工具输出的关联；独立上下文中的模型审阅判断来源是否支持结论、单位与数字是否一致、报告和脚本是否符合具体条件。记录 `model_reviewed`，不把来源匹配说成独立事实核验。
4. **验收与文件一起回传**：研究结果复用现有 outcome/outbox；即使稍后出现普通回合快照，证据关联仍保留。执行回执有每项状态、关联依据、方法及说明，原主 Chat 的鉴权历史也能读取这些数据。漏项、未支持结论、审阅不可用和后来改变的要求不能冒充通过。
5. **报告实际内容参与审阅**：读取当前任务已发布的文本报告、CSV 和脚本；同源成果去重，并限制读取总量。二进制或超限文件保留“未审阅内容”，不能凭文件存在验证报告内容正确。
6. **解决非 JSON 依赖**：Composer 改为生成简短用户文字；保留旧 JSON 兼容。纯文字与 JSON 使用相同的来源网址、文件链接和验收状态校验。损坏 JSON 仍拒绝，不能当正文发出。有效纯文字不再触发格式兜底。
7. **简洁而不失真**：保留默认短回复、关键限制和文件入口；完整证据放在成果及记录里。结构化来源的网址可以合法用于短回复，中文网址尾部标点不会造成假“编造来源”错误。没有证据支持的完成/验收升级会被拦截。
8. **可见核验原因**：Web 任务详情保留最新未核验原因，不借用旧通过记录掩盖缺口；显示“模型审阅”及说明。模型审阅证据不再笼统标为独立“已验证”。人工验收策略仍独立保留。

没有新增鉴权路由或数据库表；协议为可选字段扩展。现有权限、会话身份和成果持久化路径保持复用。

## 验证结果

- 确定性 benchmark 从 P0 的 8 项扩展至 **20 项**，全部通过。包含假引用、错误引用关系、漏验收、默认条件未展开、审阅故障、过期指令、纯文字/旧 JSON 兼容、损坏 JSON 和验收状态升级。
- 后台默认合约展开另有回归，验证新执行使用新合约版本。
- 最终相关回归 **11 个文件、181 项测试通过**；根目录和 Web 类型检查通过，`git diff --check` 通过。
- 真实模型验证覆盖 Personal 提交、Router、专业执行、脚本计算、发布文件、来源绑定、审阅、简短回复、鉴权历史和实际下载。
- 成功一轮保存 **12 条来源、8 条结论、10 项通过的具体验收**，三份文件均可从原主 Chat 下载。销售额为 150/210，环比 40%；冻结 ASR 每小时 1/2 CNY 换算为每分钟约 0.0167/0.0333 CNY，TTS 未公开限制保留。
- 同轮额外真实模型审阅把故意错误的 **100.00/hour** 与 **1.00/hour** 引用对照，标为 `unsupported`，对应条件 `failed`。该反例只用于评测，没有写回用户任务。
- Personal 最终回复 **162 字**，无格式兜底；执行期间前台追问约 **1.007 秒**返回；原请求至文字交付约 **175.661 秒**。这些是单次观察，不是 p95 或 SLA。
- 成功一轮的相关运行源码指纹开始/结束一致。其后新增的“结构化来源 URL 白名单及中文标点”是加法修复，已通过确定性测试，未额外耗费一次真实模型试验。

## 实际验证暴露的问题及修正

保留四次开发过程中的失败记录，不将它们算作最终版本的稳定率：

| 轮次 | 观察 | 修正或解释 |
| --- | --- | --- |
| 1 | 发布回执未被接纳为来源；脚本内容未读取；验收包含调用自身的循环要求 | 支持发布回执作为文件证据、读取脚本、去掉循环验收条件 |
| 2 | 规划输出超过旧 12 项解析上限，回落为两项默认条件；引用把不连续段落拼接成一段 | 支持最多 40 项且不静默裁剪、增加输出预算；要求连续原文，并允许记录安全拒绝后的恢复 |
| 3 | 12 项研究验收已通过，但 smoke 因持久化长命令详情截断而误判未运行脚本 | 根据工具调用 ID 关联原始命令，不依赖截断详情 |
| 4 | 审阅保留“无法证明全局未访问网络”的不确定性 | 不强行放行；评测 v2 区分核心成果完成与诚实保留不可观测网络项。核心内容断言仍必须通过 |

第 5 轮通过了正常成果和故意错误价格两种判定。不同开发版本的这些轮次不能合并成 pass^k 或可靠性百分比。

## 边界

- 当前来源绑定证明“本次工具读取报告了这些内容”；`web_search`/提取工具或生成脚本本身可能含模型派生内容，不能因此认证来源权威性。
- 语义验收仍可能误判；方法和原文可回查，但尚非专家审计、全面事实认证或完整网络访问审计。
- 当前真实场景采用固定的虚构价格资料；没有声称已验证真实供应商价格或活网调研能力。
- 对过大、二进制、模型审阅故障和未能生成具体条件的场景采取未核验状态。自动补查/返工、交付最终版本清单、完整跨端 UI 实测及扩大真实场景库留在后续阶段。
- 对话默认简洁，用户要求完整正文或详细解释时仍保留必要内容；不会仅为减少字数省略不确定性。

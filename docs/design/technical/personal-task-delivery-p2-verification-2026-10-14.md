# Personal delivery P2：真实场景与自动返工

日期：2026-10-14（Asia/Shanghai）。实现已落地工作区，未重启日常 Gateway，保留其他任务已有改动。

## 本轮实现

- 同一个 TaskRun 在交付前检查研究结论、验收缺口、最新要求、文件是否存在，以及发布版本是否与审阅版本一致。必要时自动补查或返工，复用执行对话、已有文件和权限。
- 最多两次继续执行，与原来的模型恢复共用三次总尝试预算及原始截止时间。完全相同的缺口指纹不会继续消耗下一轮。已暂停、等待授权、超过期限或存在未知外部影响时停止。
- 旧 TaskJudge 不再提前结束已有结构化研究结果或明确要求研究验收的任务；证据协调器负责最终回执与返工，避免两套验收入口互相绕过。
- 新增要求分别保存 `instructionChecks`，逐项关联支持它的结论。收到指令的 ack 不作为落实证据；漏审、错误引用和没有支持结论的自报通过仍未核验。
- 在验收返工中允许重发成果文件和研究审阅；保留其他已完成操作的防重放。允许确认失败的只读操作继续补查，未知命令或外部操作仍不能通过这项例外恢复。
- 研究审阅模型结构不正确时，在原审阅期限内纠正一次；无效索引、额外结论、非 JSON 等不会直接变成通过，也不会要求执行者从头重跑。
- 修正活网证据：网页 URL 可以绑定持久化的宿主元数据，省略时自动保留实际读取 URL；失败读取不算来源。网页正文提取保留被 Readability 丢掉的 main 段落，避免关键定义缺失。
- Personal 继续默认简短回复，只保留结果、关键限制和文件入口。交付状态为部分完成时，不能宣称全部验收通过；抑制不必要的内部验收数量，并校验已观察到的中文数量转述模式。
- 返工支持增量证据提交：保留已有来源和结论，后续提交默认保留原始证据，用稳定 ID 更新或明确撤回错误结论，重新审阅全部内容，避免补文件时丢掉已有计算证据。
- Personal 模型不再通过工具结构字段自行生成验收条件；完整人类要求写入简报，由后台规划可核验的交付条件。显式 HTTP/内部合约继续保留。默认规划排除对当前 publish_task_result 审阅自身的循环条件。

没有新增数据库表或鉴权路由。研究协议扩展为可选字段，原任务权限与执行身份检查保留。

| 场景 | 额外硬检查 |
| --- | --- |
| 活网 | 实际 web_fetch 读取 [MDN 404 文档](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/404)，保留原始读取的 URL、引用、时间与哈希；报告保留“不能单凭 404 判断永久删除”的限制 |
| 来源冲突 | 读取故意错误的次级资料，与本次读取的网页资料对照，明确冲突而不编造一致结论 |
| 文件失效 | 在审阅后删除隔离成果库中的 report.md；同一 TaskRun 自动恢复，最终从原 Chat 下载正确字节 |

## 保留的开发问题

开发混合场景与 `p2-live-v1`、`p2-live-v2` 都保留原记录。不同源码版本、源码发生变化的试验以及中断的开发批次不并入固定版本可靠性统计。

- 首轮发现旧 TaskJudge 绕过证据协调器，同时把宿主交付摘要规范当成执行者验收项。已分清最终验收入口，规划时去掉宿主自动附加的交付指导。
- 活网来源 URL 只在工具元数据中，旧匹配规则误拒；已修正宿主元数据关联及自动保留 URL。
- Readability 会漏掉页面开头的定义，执行者改用模型提取来源，未形成要求的原始读取证据链；已补正文提取。
- 只读验证错误会被普通模型恢复策略当成未知外部影响；加入仅用于验收返工的只读例外。未知外部影响继续停止，且在入队前判断，避免无效恢复变成整个执行失败。
- 格式审阅可能生成不存在的条件索引或无指令时的占位序号；仍严格拒绝，并加入有界结构纠正。
- 真实矩阵发现故障注入只覆盖 publish_artifacts，未覆盖命令工具直接发布；现已支持两种发布路径，原未注入案例仍记为失败。
- 补测发现过程性的“未使用外部价格来源”无法独立证明；允许正确披露这项不可观测限制，但计算、价格、引用与文件要求继续严格验收。
- 扩展适配器将主 Agent 对相关 CSV 的预读记录为独立策略指标；仍严格要求专业执行、响应时间、无无关工具/外部写入、正确结果与文件。此前严格规则下的失败不改判，避免混淆交付正确性和分发策略偏好。
- 另一个注入观察误区是只认继续执行事件；执行者也可以在原回合主动重新发布。新适配器要求实际删除后的成果被替换并可下载，区分原回合恢复与协调器继续执行，不人为强迫多开一轮。
- 修复期间停止了开发批次的后续排队。一个已开始但没有完成报告的方向变更试验明确保存为中断记录，其临时配置已清理。

## 边界

- 这是小样本、四类具体场景的基线，不代表所有调研主题的可靠性或生产 SLA。百分位只描述本批次，长度只作为简洁程度代理。
- 语义判断仍属于模型审阅，来源匹配证明本轮工具输出关联，不能独立认证作者权威或事实正确性。
- 中途改要求覆盖 Personal 的指令入口与新增交付要求；不覆盖所有直接 API 合约修订或完全替换任务的形式。
- 文件丢失注入发生在最终验收前。若最终完成之后、交付检查期间才丢失文件，当前链路会诚实降级交付状态，尚未复活已结束的执行。
- 二进制、超大文件和不可观测的要求仍保留未核验状态；不为提高通过率省略这些限制。

取消执行回归曾连续失败：旧测试创建了没有 TaskRun 输入关联的执行租约。补齐与真实调度一致的 session_input → TaskRun 关联后通过，没有放宽“不能中断另一条执行”的保护。最终完整相关回归重新执行确认。

## 合并保留的 P0/P1 契约与基线

早期两份报告于 2026-10-29 合并。P0 保留省略字段的默认合约、显式字段原值及 partial/failed 状态；成果存在不证明任务完成。宿主校验文件发布，模型自行输出的本机链接/MEDIA 不充当交付。默认简短回复，显式完整内容/代码和重要不确定性优先；格式失败有诚实的短兜底，不伪造总结。

P1 后台提取具体条件，普通主对话不额外等待规划；规划失败不把笼统条件当通过。研究来源绑定本轮成功持久化工具的 ID、连续原文、时间及 SHA-256；假引用、跨来源拼接和遗漏条件拒绝。引用绑定与模型语义审阅分别记证；超限/二进制/审阅不可用显式未核验，不能凭文件存在认证内容。文字及旧 JSON Composer 都遵守同样链接和状态校验；损坏 JSON 不冒充正文。人工验收独立保留。

确定性同文件哈希 P0 基线由2/8变8/8，P1扩展20/20，P2最终42项见上。P0真实最终一轮有格式失败后33字安全兜底、3份文件和150/210/40%核对；P1真实一轮保留12来源、8结论、10条件及三份下载，错误价格100/hour相对1/hour被独立审阅拒绝。P1回复162字，前台追问1.007s、全链175.661s，均为单次观测非P95。探索轮次分别暴露来源ID/连续摘录、循环验收条件、规划数量上限及截断日志误判，不合并为可靠性百分比。

基线数据与入口仍在 `evals/personal/baselines/` 和[评测说明](../../../evals/personal/README.md)，复跑 `pnpm run eval:personal:p0`。这些固定虚构价格样本不证明活网供应商价格、全面事实认证、完整网络审计或跨端设备验收；自动返工范围以本报告P2结果为准。

# Personal AI 阶段 B：任务交接、上下文引用与执行前校验

本阶段延续阶段 A 的统一成果读取，补齐“主对话提交 → 后台选择执行者 → 补读获准输入 → 执行与来源核验”的链路。复用 TaskApplicationService、context_snapshots/context_edges、协作记录及执行队列，没有增加前台模型规划轮次或主对话工具数量。

## 交接与读取

`task.create` 的同一事务保存原始输入 ID、原文、原 transcript、模型解释、附件引用和用户选择的来源。每个来源保存稳定身份、版本、内容 hash、用途及截断/表示类型；快照标注契约版本、执行 epoch/协作序号基线和授权范围。原话与模型解释分开保存，不让模型复制请求代替宿主捕获；没有运行输入时明确记录 unavailable。主 Agent 还可通过 `personal_task.sourceRefs` 选择必要的历史成果、笔记、Task 或文件。成果使用独立的 resultId 与精确文件标题/身份，文件可使用来源工作区内的相对或绝对路径，无需模型手拼底层引用；前台只保存指针，后台核验归属、固定版本并扩展同一交接快照。无法解析、版本冲突或来源已撤回时，在选择执行者之前明确阻断。

普通与连接应用执行者统一使用 `task_collaboration`：

| section | 内容与边界 |
| --- | --- |
| `handoff` | 原请求每页 4,000 字符，来源清单、完整性和基线；不复制完整主聊天 |
| `brief` | 模型整理任务书的完整分页读取，消除 12,000 字符指令片段成为唯一入口的问题 |
| `source` | 只能读取当前 Task 已选的 sourceIndex，支持固定版本、范围、查询及游标 |
| `evidence` | 当前执行中真实成功工具读取的目录，及按真实 toolCallId 补读准确原文 |
| `task` / `collaboration` | 继续使用现有契约/等待与协作入口；ack 只针对已投递的 answer/instruction |

来源读取检查原输入仍存在、原对话实例仍适用，之后按类型复核当前状态。成果复用阶段 A 的结果授权、账户权限、固定成果版本及异步解析；不能借用该入口扫描主对话其他成果。笔记、Task、会话、用户事实与浏览器标签检查当前版本/状态；已撤回或改变的来源不能回退到旧快照。

截断的笔记与 Task 可补读当前固定版本全文。截断文本文件按来源所属主对话工作区检查真实路径、空间身份和文件版本，再以每次不超过 4,000 字节分页读取；UTF-8 游标保持字符边界，拒绝符号链接越界和读取期间的版本变化。二进制描述信息明确标为 metadata，不作为读到正文。执行者可用 source 的 materialize=true 将明确选中的工作区文件流式复制到自己工作区的 `.task-inputs/<taskId>/`，保留相对目录、核验版本与 SHA-256、设置输入只读权限；最多 50 MiB，既有不同内容不覆盖。路径逐级校验，既不开放来源工作区，也不在主对话解析文件。输入副本与工作区其他任务文件遵循相同保留周期；不能把已发生的读取当作可撤回的外部行动。之后由获准执行工具解析。会话/浏览器的截断快照仍显式保留限制，额外内容需走已有授权读取工具。

应用/设备特权上下文、页面捕获和图片不直接复制为工作者授权，完整性清单记录被省略或未解析的引用；这类场景需要独立授权读取。快照与补充读取都不赋予账户切换或外部写权限。

## 后台能力清单

沿用后台契约模型调用，同时提取最小操作集合：读取输入、执行代码、发布文件、网页研究、浏览器和生成图片。契约 JSON 明确要求扁平字符串数组，最多进行一次后台结构修复，仍受已有 40 秒分配 deadline 限制。结构失败后显式阻断，不能用默认契约冒充完成能力分析。

程序将操作映射到注册工具及等价读取路径，检查策略、注册、模型配置、明确要求的 Skill 和连接账户授权。结构化文件输入/输出也产生必要操作约束。要求及来源保存在现有上下文快照中；用户指定执行者/Skill/账户保持不变，系统推导不扩大权限。角色标签与案例仍用于 Router 比较，不能代替程序检查。

分配前保留候选全量重新比较、Task version/分配 lease 检查；真正启动执行前再核验当前能力与账户权限以及适用契约版本。引用此前连接应用成果时，同时检查接收执行者的来源账户权限，分配与实际读取都不能借用原执行者的授权。工具或授权变化时不能继续调用执行模型。连接应用保留宿主原有的专用协作入口授权，不要求业务 Agent 的工具白名单重复声明宿主工具。

当前验证证明“工具已注册且策略允许、模型已配置”，没有承诺第三方网络、浏览器实际启动、解析依赖或外部服务永远可用；环境/调用结果仍由实际工具执行检查。超过 24 个合格候选仍明确阻断；完整交接超过 96,000 字符规划预算时要求拆分，不静默截掉尾部要求。

## 来源校验重试的根因与修复

重放阶段 A 真实 transcript 后确认三类问题：

1. 模型把 `exec_command` 名称、描述性标签或命令运行 ID 填为 toolCallId。协议中的真实 ID 不一定作为正文提供给模型。
2. 摘录拼接了不连续输出、改变了内容，或给了该读取未出现的 URL。
3. 契约模型仍生成“未来最终回复只能说什么”的前置验收项，工作者尝试用自己准备发送的回复当来源。此时回复尚未发生，正确的校验器必须拒绝。

现在仅在 Task 执行的证据工具结果中显示宿主真实 `Task source toolCallId`；主对话工具集合保持不变。校验器一次列出全部不匹配来源，区分 ID 错误与未观察到的摘录/URL，给出已有真实匹配 ID、该读取中实际存在的单个连续原句及定向补读入口。修复必须改变错误来源或撤销无支持的 claim，禁止原样重试；不自动接受错误 ID 或伪造摘录。

未来回复的格式/禁复述要求保留为交付约束，不成为发布研究结果之前必须证明的事实。初始交接不是协作消息，不能拿快照/来源/工具 ID 作 ack 的 causationId。

证据目录排除失败、非零退出、超时、仍在运行的命令、协作 ack/progress 和旧 review；只有宿主标记的已选来源读取可以作为 `task_collaboration` 证据，不能通过发布一条自写进度来洗成来源。

## 验证与边界


真实结果及耗时见 [验收记录](./personal-task-handoff-live-2026-10-15.json)。run-1 保留模型嵌套数组导致的安全阻断；run-2 的两项真实任务与来源读取完成、来源重试为零，但运行中修复代码使 source fingerprint 改变，因此不计作最终通过。run-3 完成两项任务，同时复现一次不连续摘录被拒绝和一次把 reviewer note 回传为提交字段的结构错误；随后补充实际连续原句提示，并使模型 schema 的嵌套对象与宿主 strict 校验一致。run-4 在代码复查发现显示名规范化快照问题后主动中止，保留中止原因；不算验收通过。

验收判定要求两项任务成功、来源真实绑定、定向修复有界且不原样循环、主对话无输入正文预读、版本与权限复核有效，并且整个复跑期间源码指纹不变；不通过放宽摘录匹配来消除错误数字。最终复跑结果（同一次运行源码指纹不变）：

| 真实 Task | 2 个；均 succeeded |

| 发布文件字节复核 | 42,926 / 36 / 370 字节，均与来源工作区原文件逐字节一致（独立补验） |

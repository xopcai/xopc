# Phone Use 对话配置 P0

日期：2026-10-24。统一入口为 `configure-xopc`，Phone Use 是其中一个渐进加载场景。

## 用户流程

1. 用户说“帮我配置 Phone Use”，或在手机设置点击对话配置。Skill 检查当前对话所属助手的有效模型、工具权限、依赖和已注册设备，在原对话展示配置卡片。
2. 配置手机操作模型。它与聊天模型独立；必须支持 Phone 动作协议、图片输入和对应 API。全局模型进入手机设置，助手覆盖模型进入该助手设置。凭据通过原有产品表单填写；模型诊断只能证明协议连接，不能代替真机验收。
3. 用户选择本机 Android／模拟器或阿里云手机。本机分支复用依赖管理器安装、修复或指定已有 ADB、scrcpy server；连接实际发生在 Gateway 主机，不一定是查看网页的电脑。云手机直连不依赖本机 ADB；视频及中文输入仍需对应 scrcpy 能力。
4. 本机引导数据线、解锁、开发者选项、USB 调试和手机端 RSA 确认；区分未发现、unauthorized、offline。拒绝后引导重新连接授权，不替用户修改系统权限或清除数据。
5. 阿里云分支优先复用实例。购买前在官方控制台核对地域、规格、网络可达性、费用和自动续费。用户本人下单、绑定匹配密钥；xopc 安全页面测试地址／私钥后注册手机。删除 xopc 连接不代表停止云端计费。
6. 用户明确选择验收手机，并确认截图将发给手机模型、可能产生模型费用。测试限定为系统设置中读取 Android 版本，最多六个模型动作、五分钟，不要求用户登录业务应用。
7. 模型通过实际 `phone_use` 观察、导航、核对原生界面并关闭测试会话。产品同时确认非 mock 模型请求、实际动作、界面证据以及控制释放，全部满足才标记基础验收完成。
8. 用户在同一对话提出一个小任务。登录、应用授权、文字输入、视频及业务结果分别验证；基础控制成功不能代表付款或其他业务成功。

## Skill 与产品工具分工

Skill 首页只负责识别场景。Phone overview 根据现状继续加载 models、dependencies、local 或 aliyun；开始测试后加载 acceptance，异常时加载 troubleshooting。避免每次把所有平台说明、脚本和文档注入上下文。

`xopc_use phone_setup` 提供 inspect/start/get/recheck/verification_report/cancel，返回宿主探测事实、当前进度和下一份 reference。模型无法提交“passed”来改变验收结果，也不能通过此工具购买实例或传入密钥。开始验收与选择设备由原对话的用户操作确认。

产品继续拥有配置写入、凭据处理、下载校验、设备注册、权限判断、运行控制租约和验收事实。复用已有手机模型、依赖和云连接表单；不让 Skill 用任意 shell 或直接修改配置文件完成这些步骤。新增 `/api/phone/setup` 在既有 Phone 管理员鉴权与 lazy route 下工作。

## 安全输入与恢复

API key、私钥只在专用页面输入／上传，不进入 Skill、聊天提示或进度报告。现有云手机凭据使用受限目录与文件权限保存；这不等于操作系统钥匙串加密。配置进度不保存截图、私钥、ADB 地址或完整设备序列号。

测试绑定对话、助手、设备、模型和配置版本，使用独立 PhoneRuntime owner，不能复用其他对话的报告。模型／设备／权限改变使旧测试失效。中断后先检查状态；暂停、失败或未知结果先释放再由用户重新开始，不盲目重放。Gateway 重启丢失内存会话时必须确认旧租约到期才能重新测试。取消及释放操作在模型输出期间仍可使用。

当前默认依赖现有 PhoneRuntime 的应用访问策略和模型动作约束；验收任务的“不改设置”是任务约束，并非 Android 设置页面的操作系统级只读沙箱。后续可增加专用验收页面或更细粒度动作策略。

## 验收与当前验证范围

必须满足：真实且兼容的手机模型、有效凭据、启用权限、明确选择并连通的设备、实际观察、模型导航、原生 UI 完成条件、确认释放。mock、模型口头 finish、合成模型诊断以及单纯 ADB 在线均不算端到端成功。

已覆盖自动化：进度持久化、同对话复用、源选择、权限／模型／设备拒绝、云端免本机 ADB、并发配置变更、动作总预算、伪造报告、mock 拒绝、重启租约确认、取消后的迟到结果；通过真实 PhoneRuntime 与 phone_use 包装器验证观察／动作／关闭证据和租约释放（驱动与模型为测试替身）。另有真实 HTTP 鉴权与 lazy route、前端显式设备选择及安全提示回归。

在线验证已继续使用 XOPC Cloud GPT-5.6 Sol，并使用本机模拟器及现有阿里云测试手机。自然语言进入配置、按需读取 Skill、真实连接／页面读取、原对话按钮触发、验收中断与 Gateway 重启后的恢复及释放已实际执行。手机模型当前返回 `free_quota_exhausted`；因此真实模型导航的完整成功验收仍然受阻，不能标为已通过。详见在线验收报告。

未覆盖真实 USB 手机 RSA 弹窗、重新购买云实例、真实私钥轮换及云端网络故障注入。测试复用现有云连接，不自动购买、开启计费或切换模型。

## 在线验收脚本与修复

`XOPC_PHONE_REAL_MODEL=1 node --import tsx scripts/verify-phone-setup-live.mts`

脚本使用隔离配置、SQLite、工作区和生产源码 Gateway，读取现有 Cloud 凭据及已注册的“阿里云测试手机”，只操作在线模拟器和该测试手机的系统设置。不会把凭据写入报告。`XOPC_PHONE_SETUP_SOURCE=aliyun XOPC_PHONE_SETUP_OWNER_UI=1` 可单独验证浏览器配置卡片的实际设备选择、授权按钮及原对话自动继续；需要先构建 Web 到 `XOPC_PHONE_SETUP_UI_ROOT`（默认 `/tmp/xopc-phone-setup-ui-build`）。

结果位于 `XOPC_PHONE_SETUP_EVIDENCE` 指定目录。原始对话以受限权限私有文件保存，公共报告仅保留验收、工具加载与控制元数据。`status=blocked`、退出码 2 表示外部手机模型额度阻塞，不能当作成功验收。

本轮修复：宿主通过标准 Android `DEVICE_INFO_SETTINGS` 入口打开关于手机，避免沿用上次子页面；真实模型仍须导航到版本详情并产生原生 UI 变化。宿主准备动作不计入六步模型预算，也不能单独证明模型导航成功。刷新原对话后保留已绑定设备显示。额度耗尽有独立错误类型及产品引导，不再建议重装 ADB、重新授权设备或立即重试。

# Codemode 与工具发现：第四阶段评估

评估开始于 2026-10-10 UTC。正式对照使用本地百炼凭据访问 `dashscope-cn/qwen3.7-flash-2026-07-15`，真实调用模型服务、embedded SDK、QuickJS、读取工具、SQLite FTS 知识检索和 stdio MCP。测试只读取固定合成数据；没有把用户文件、聊天记录或 MCP 账户数据发给模型。

## 方法

固定 30 个任务：8 个文件汇总、4 个文件检索、4 个知识检索、6 个多项目进展、4 个 Git 历史对比、2 个 MCP 查询、1 个部分缺失任务和 1 个权限拒绝任务。每项在三种策略下各重复 3 次，共 270 个样本。单文件任务保留直接读取；Git 仍使用普通读取路径，因为 Codemode 不开放 shell 或 Git。

| 策略 | 工具与提示 |
| --- | --- |
| direct | 原有核心读取工具和外部工具网关，提示优先直接调用；允许同一模型回复发起多个读取 |
| batch | 同一套底层工具和权限，提示优先 data_batch；单项和依赖查询仍可直接调用 |
| codemode | 同一套底层工具和权限，额外开启 Codemode 和一个 MCP 服务的 deferred 发现，提示组合独立读取并返回紧凑证据；普通工具保留 |

直接调用和 data_batch 基线沿用 xopc 的 `xopc_tool_search → describe → execute` 路径，没有把全部 MCP schema 人为塞进基线。Codemode 策略同时包含第三阶段的工具发现，因此这是整套试点策略的对比，不能把差异全部归因于 JavaScript 沙箱。

三组固定模型、`thinkingLevel: off`、最多 4,096 个输出 tokens、相同数据与输出契约。策略顺序按任务和重复次数轮换，共享并发为 3；每个样本创建新 conversation，时延包含 runner 构建、必要的 MCP 连接、模型与工具等待。Provider 实际 reasoning 行为由服务端决定，未声称配置 off 能关闭所有服务端内部计算。

提示要求输出 JSON，包含数字答案、精确来源和 `ok/partial/denied` 状态。评分器允许 JSON 外的 Markdown 和说明文字；来源字符串必须原样匹配。评分同时检查答案、来源集合和工具轨迹中的真实读取；算对数字但附带错误来源或改写来源标识，也计入端到端失败。失败、拒绝和慢样本都计入时延、P95 和费用，不按成功样本过滤。重复试验中的来源格式错误与事实错误会在结果分析中区分。

只统计模型 `message_end` 的 usage，不将子工具调用再次计为模型用量。记录 uncached input、cacheRead、cacheWrite、output、请求次数、父/子工具调用、策略实际使用、答案及工具轨迹。报告的输入合计包含输入及缓存读取/写入 tokens，缓存收益另外展示。

价格按 [阿里云官方北京区域模型页](https://www.alibabacloud.com/help/en/model-studio/qwen3-7-flash) 在 2026-10-10 的快照填写到独立模型定义：单请求输入不超过 32K 时，input $0.028 / 百万 tokens、output $0.11、隐式 cacheRead $0.006、显式 cacheWrite $0.034。记录每个样本的最大单请求输入，以核对价格档位。此次未主动创建显式缓存。费用为模型返回用量对应的估算美元金额，不等同于账户账单；没有查询或修改账户余额。DeepSeek 探测返回余额不足，因此没有进入比较。模型请求上限、120 秒样本超时及默认 $5 估算预算限制本次运行；在途请求可能在预算停止后完成。

原始 manifest、cases、samples 和 summary 位于本地 `.test/codemode-evaluation-qwen-final/`，保留断点以支持同一契约恢复。manifest 检查模型、价格、策略、数据哈希、harness 和关键 runtime 源码哈希；条件变化要求新输出目录，不把不同条件的结果混合。首次遇到 Provider 限流、余额、认证、协议或服务错误即停止派发，在途样本完成；保留错误行并使整轮比较无效，不能把快速 API 拒绝作为延迟收益。不会自动重放已执行的工具。合成 fixture 中的 Git commit 时间固定，知识内容固定，结果包含 Git revision。

## 推广规则

组合任务不含单文件、Git 和失败处理，共 23 个任务；至少 30 个完整任务、每种策略 3 次的样本门槛仍按全套检查。Codemode 分别与两种基线比较：成功率不能降低、整体 P95 不超过基线 10%，且组合任务中位时延至少降低 20%或输入合计至少降低 15%。按整个任务聚类 bootstrap 2,000 次给出中位时延比的 95% 区间，保留同一任务的各策略和重复样本。

真实模型评估达标后，还需要确定性行为检查与明确 Agent 的日常试点通过，才考虑更改 defaults。严重越权、跨会话初始状态泄漏、残留运行和 SQLite 完整性错误不得出现。现场检查覆盖新会话的初始 Codemode 状态、受限内容哨兵、最终 runner/MCP runtime 数量和 SQLite integrity_check；第三阶段的持久化/取消/授权回归继续独立执行。

## 复现

```bash
pnpm run eval:codemode:check
pnpm run eval:codemode --dry-run --out .test/codemode-evaluation-dry-new
pnpm run eval:codemode --model dashscope-cn/qwen3.7-flash-2026-07-15 --models-json scripts/codemode-evaluation/models.example.json --out .test/codemode-evaluation-new --repeats 3 --concurrency 3
```

本轮凭据来自进程继承的本地模型环境变量；脚本使用自己的状态目录和 SQLite，没有复制或修改用户凭据。`--models-json` 将指定模型定义写入自己的状态目录，按 0600 权限保存；示例只包含公开定义和价格，凭据使用环境变量。本轮未使用真实 OAuth 账户或生产 MCP 服务。`--cases` 可做预检，预检结果不满足推广样本门槛。相同参数和输出目录可恢复未完成样本；已有 Provider 错误的轮次始终标记无效，恢复可用服务后另开完整轮次。

## 预检与无效轮次

- MiniMax-M2.7 的初始工具冒烟 18/18 通过（该预检直接组曾提前曝光 MCP schema，只检查链路，不作为性能证据）；修正基线后的预检 6/6 通过。两次预检分别估算 $0.032133 和 $0.015574725。
- MiniMax 正式轮次共写入 270 行：37 行完成模型任务，其中 34 行通过；其余 233 行均返回套餐速率限制 429。发现问题后补上评测中止与无效标记，并用不同模型另开完整轮次。原始数据保留在 `.test/codemode-evaluation-final/`，其快速拒绝的时延和不完整成功率不参与任何推广结论；该轮本地目录价格估算 $0.076601145。
- Qwen 首次链路预检发现百炼不接受 developer role；在独立模型定义中显式使用当前服务的 system role 和 Qwen thinking 参数。18 个请求均在服务端返回 400、用量为零，该轮无效，保留在 `.test/codemode-evaluation-qwen-pilot/`。没有引入旧模型别名或生产代码分支。
- 正确模型定义下 Qwen 预检 18 项中 17 项通过；唯一失败数字正确但来源附带说明文字，按既定来源契约计为失败。估算 $0.003207096，预检不并入正式样本。

## 结果

**结论：保持 Codemode 与工具发现默认关闭，继续按 Agent opt-in。** 全部 270 个正式样本已完成，854 次模型请求，Provider 错误为零，正式轮次估算总成本 **$0.051870**（不包含上面的预检与无效轮次；这五个轮次合计 $0.179385694，另有少量服务探测请求）。此次单模型、合成任务结果未达到推广门槛，没有开启生产 Agent 或改动用户默认配置。

| 策略 | 端到端成功 | 来源完整 | 中位耗时 | P95 | 模型请求 | 估算成本 |
| --- | --- | --- | --- | --- | --- | --- |
| direct | 74/90 (82.2%) | 75/90 | 4.153s | 11.849s | 320 | $0.017062 |
| batch | 78/90 (86.7%) | 78/90 | 3.836s | 7.385s | 249 | $0.012891 |
| codemode | 74/90 (82.2%) | 75/90 | 5.200s | 13.414s | 285 | $0.021917 |

所有样本（含任务失败）均计入上表。Codemode 组的 90 个样本有 35 个实际使用脚本，共记录 68 次嵌套工具调用；其余使用普通工具。因此表格衡量的是开启整套试点后的策略效果，没有只挑选成功脚本来计算收益。direct 组没有在非 Git 任务调用 data_batch。

| 策略 | uncached input | cacheRead | cacheWrite | 输入合计 | output |
| --- | --- | --- | --- | --- | --- |
| direct | 205,465 | 1,206,656 | 0 | 1,412,121 | 36,987 |
| batch | 160,399 | 894,976 | 0 | 1,055,375 | 27,546 |
| codemode | 399,689 | 1,045,632 | 0 | 1,445,321 | 40,473 |

最大单请求输入为 11,237 tokens，均在 ≤32K 价格档位。缓存计数由 Provider usage 返回，不主动清空服务端缓存；策略顺序轮换以减少先后影响。Codemode 的 uncached input 更多，输出也更长，费用高于两组基线。

### 组合任务与门槛

23 个组合任务（每种策略 69 个样本）的 Codemode 中位耗时相对 direct **增加 19.3%**，相对 batch **增加 40.6%**。任务聚类 bootstrap 的中位耗时比分别为 **1.193，95% 区间 [0.903, 1.496]** 和 **1.406，[1.230, 1.657]**；不能宣称对直接调用有确定的速度收益。

组合输入合计相对 direct 只降低 **4.7%**，相对 batch 增加 **39.8%**，均未达到 15% 降幅。整体 P95 相对 direct 增加 **13.2%**、相对 batch 增加 **81.6%**，超过 10% 上限。成功率与 direct 相同，相对 batch 降低 **4.4 个百分点**。样本、安全和基础设施门槛通过，收益、尾延迟及相对 batch 的质量门槛未通过。

### 失败与边界

| 失败分类 | direct | batch | codemode |
| --- | --- | --- | --- |
| 评分器无法解析 JSON（含普通说明、工具请求文本和空回复） | 11 | 8 | 13 |
| JSON 的答案或状态错误 | 2 | 1 | 3 |
| 答案和状态正确，来源集合或真实读取证据不完整 | 3 | 3 | 0 |

这些分类用于诊断，不重新给失败样本加分。没有模型侧超时、受限哨兵读取/输出或新会话初始 Codemode 状态泄漏。9 个权限拒绝样本全部正确，其中 8 个实际触发工具拒绝，1 个直接给出拒绝结果；评分不强制尝试已知禁止的读取。最终 pooled runner 和 MCP runtime 均为 **0**，SQLite `integrity_check` 为 **ok**。

本轮数据较小、读取结果容易直接装进上下文，且原有工具可并行调用；不能推断到大规模工具目录、长链依赖、其他模型或生产账户。Codemode 与工具发现共同开启，不能单独归因。隔离状态检查与哨兵也不能替代完整授权、取消和持久化回归。

聚合数据、完整契约和哈希见 [评估 JSON](./codemode-evaluation-2026-10-10.summary.json)。原始 270 行响应和父/子调用轨迹留在本地评测目录，原始文件 SHA-256 已记录在 JSON 中；其合成输入可由脚本重建。

## 开发验证

评测脚本类型检查通过；评分与推广门槛单测、真实 QuickJS/SDK/MCP 相关回归共 4 个文件、15 项通过。测试验证 Provider 快速拒绝不能满足推广门槛，正确数字但伪造来源不能通过评分。ESLint 当前配置不涵盖 scripts，这次对脚本的检查未作为 lint 通过证据。

真实 CLI 的本机 429 故障注入通过：并发 3 时仅完成 3 个在途请求，立即停止其余 267 个样本，退出码 2，比较无效，runner/MCP 残留为零，SQLite 完整性通过。没有消费真实模型额度。

根与评测脚本类型检查、文档检查和 diff 空白检查通过。最终全量 Vitest：**1,491 个文件、8,882 项通过**，3 个文件、12 项按原配置跳过。运行中出现一条 Node TimeoutNaNWarning，未导致测试失败。此次没有修改生产 runtime，也没有重建 Electron 安装器或验收桌面 UI。

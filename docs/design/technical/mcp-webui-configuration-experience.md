# MCP WebUI 配置交互方案

日期：2026-10-15。状态：第一、第二阶段均已实现。

## 1. 设计结论

在「能力中心 → 连接器」保留现有自定义 MCP 入口，使用一个固定尺寸的配置弹窗完成添加与编辑。默认连接在线服务，首屏只展示地址、可选名称和认证方式；命令启动与 JSON 导入作为平级入口。高级设置只承载运行参数，不承载常用认证。

用户要理解的是「连接哪个服务、需要什么凭证、现在是否可用」。stdio、Streamable HTTP、工具暴露策略等术语保留在说明与高级设置中。

参考图采用认证方式切换与动态字段，但不采用大头像、上传图片和移动端返回按钮布局。WebUI 使用现有 Dialog、项目 Select、输入框、语义色与 Lucide 图标，桌面单列主表单，窄屏自然展开为单列。名称与图标不成为连接前提。

## 2. 基于当前代码的判断

本次未发现可调用的 codebase-memory 图工具，因此通过源码读取完成梳理。实现依据如下，行为以代码为准：

| 现有实现 | 体验影响 |
| --- | --- |
| `custom-mcp-server-dialog.tsx` 默认 HTTP，右上按钮切换 stdio | 两种方式不够直观，切换后上下文容易丢失 |
| 基础字段仅有地址，Header、OAuth Client ID 位于高级设置 | 已有 API Key 的用户也需要寻找配置入口 |
| `connect()` 先 PATCH 配置、强制 `enabled: true`，然后 probe | 连接失败也已经保存；编辑已停用项会意外启用 |
| probe 返回 connected / oauth_required / token_required / error | 可以复用认证引导，但 token_required 不能准确说明服务需要哪种 Key/Header |
| `setBearerToken()` 将输入写为 Authorization Header | 现有快捷输入只覆盖 Bearer，不覆盖其他 API Key |
| OAuth 有启动、轮询、取消和回调地址提交接口 | 浏览器授权可保留，远程访问可以复用手动回调兜底 |
| JSON 导入接受 mcpServers / mcp.servers / servers / 单条配置，多条选择其中一条 | 导入入口需要明确「本次选择一个服务添加」 |
| 自定义列表主要展示 id、端点、编辑、查看工具和删除 | 缺少「已保存」「上次检查成功」「需要授权」等可解释信息 |
| headers/env 的 schema 支持字符串和凭证引用；当前表单有字符串转换 | 编辑不能把引用对象转换成 `[object Object]` 或明文占位符 |
| `patchMcpSettings()` 按整个 servers 集合提交，另保留托管连接器 | 后续需考虑并发编辑，不能因保存单条覆盖别人新增的项 |

涉及文件：`web/src/features/connectors/custom-mcp-server-dialog.tsx`、`mcp/mcp-server-form-fields.tsx`、`mcp/mcp-config-api.ts`、`mcp/mcp-headers-editor.tsx`、`components/custom-mcp-server-row.tsx`；后端为 `src/gateway/hono/routes/mcp.ts`、`src/agent/mcp/connection-setup.ts`、`src/agent/mcp/tool-catalog.ts` 和 `src/config/schema.ts`。

补充：`docs/mcp.md` 仍写 Web OAuth 已移除，与当前路由和 UI 不一致，实施时应同步文档。

## 3. 添加弹窗

不增加强制多步向导。配置、认证反馈与检查结果在同一弹窗内连续完成。

```text
添加自定义 MCP                                       关闭
连接服务，让 Agent 使用它提供的工具。

[ 在线服务 ]  [ 命令启动 ]                  导入配置…

服务地址 *
[ https://example.com/mcp                           ]

名称（选填）
[ 例如：团队知识库                                  ]
留空时使用服务地址生成名称。

认证方式
[ 自动检测                                      ▾ ]
不确定时选此项；已有密钥可直接选择对应方式。

▸ 高级设置

由 Gateway 所在机器连接此服务。
─────────────────────────────────────────────────────
                              取消       保存并连接
```

建议桌面宽约 640–672px，高 `min(44rem, calc(100dvh - 2rem))`。外层固定尺寸与 `overflow-hidden`，标题和底部操作固定，中间 `min-h-0 flex-1 overflow-y-auto`。避免认证字段展开导致弹窗跳动。窄屏保留边距、安全区域，Header 键值行上下排列，避免横向滚动。

地址先填写，名称可跳过。显示名称与内部标识分离：新增可选 `displayName` 字段；id 沿用自动生成规则，详情高级区域只读显示。已有项没有名称时回退 id。修改名称不触发 id、工具命名空间或 OAuth 归属变更。若第一阶段不扩展 schema，则先不展示名称输入，不把任意中文名称写入 id。

## 4. 认证交互

| 选项 | 展示内容 | 交互 |
| --- | --- | --- |
| 自动检测（默认） | 一行解释 | 复用当前 probe，成功直接完成；需要授权时提供明确下一步 |
| 浏览器登录 | 「连接后将在浏览器中完成授权」 | 保存后启动现有 OAuth；不提前承诺服务支持，失败提供切换方式 |
| Bearer Token | Token 密码输入、显示/隐藏 | 用户只填 Token；兼容粘贴已带 Bearer 前缀的值，不重复添加 |
| API Key | Header 名称 + API Key 密码输入 | Header 名称必填，提示「以服务文档为准，例如 x-api-key」；不自动猜名称 |
| 自定义请求头 | 有标签的 Header 名称/值列表、添加、删除、粘贴 | 用于多个或特殊认证头；值默认隐藏 |
| 无需认证 | 无额外输入 | 401/403 时提示认证失败，允许修改认证方式，不擅自切成 Bearer |

API Key 模式中，认证头保持单条；附加的非认证 Header 放高级设置。自定义模式只使用一个 Header 编辑器，避免两处编辑同一个值。浏览器登录也可有非 Authorization 的附加 Header。

切换方式只改变本地草稿，不立即写配置。旧方式内容留在本次弹窗内，切回可以继续填写；提交只序列化当前有效方式与兼容的附加 Header，不发送隐藏的旧 Token。大小写不敏感地检查重复 Header，禁止认证专用字段与附加 Header 同时定义 Authorization。

从静态 Authorization 切换到浏览器登录时，明确移除该 Header 后再提交，符合当前后端约束。存在 `auth.provider` 或凭证引用的配置，显示「使用已有凭证」及来源，保留原始结构；用户主动选择替换后才改写。不能用字符串强制转换推断复杂配置。

现有 probe 的 `token_required` 在界面中解释为「需要认证，或当前凭证未被接受」，提供 Bearer / API Key / 自定义请求头选择，不当成服务明确要求 Bearer 的证据。403 也可能是权限不足，不一律断言 Token 过期。

自动检测和无需认证都没有凭证字段，但意图不同：前者允许给出认证引导，后者明确表示用户预期公开访问。当前配置没有这一意图字段；第一阶段作为表单草稿状态，重新编辑时按已有配置推断，并接受两者不能完整还原的限制。如果需要跨会话精确恢复，再增加仅供 xopc 使用的 UI 元数据，不修改 pi 的认证协议。

## 5. 连接、保存与错误恢复

### 第一阶段：与现有接口一致

底部主按钮命名「保存并连接」，在用户操作前说明会保存配置。校验未通过不保存；保存成功后检查工具列表。

| 状态 | 用户看到的内容 | 可执行操作 |
| --- | --- | --- |
| 正在保存/检查 | 「正在保存…」「正在检查连接…」 | 防止重复提交；等待态使用操作级进度反馈 |
| 检查成功 | 「连接检查成功 · 发现 8 个工具」 | 查看工具、完成 |
| 成功但 0 工具 | 「连接检查成功，未发现工具」 | 查看详情、完成；不宣称发现了可用工具 |
| 需要 OAuth | 「此服务需要浏览器登录」 | 登录并连接、更改认证方式、关闭 |
| 授权中 | 「等待浏览器授权…」 | 重新打开授权页、取消授权 |
| 凭证未接受 | 对应字段附近说明，保留已填内容 | 修改凭证、保存并重试 |
| 网络/协议/命令失败 | 「配置已保存，连接检查未通过」+ 可操作的解释 | 保存并重试、关闭；日志详情折叠 |

保存后「取消」改为「关闭」，成功后主操作改为「完成」。关闭不会暗示撤销已保存内容。新项检查失败时可提供「移除此配置」，走现有删除确认；不能自动回滚整个 servers 集合。

编辑模式保留原 enabled 状态，不再无条件设为 true。停用项可保存修改；连接操作明确为「启用并连接」。配置变化后旧检查结果立即失效，只有当前版本检查成功才能显示成功。已保存状态与检查状态分离，检查成功不代表 Agent 一定有权使用该工具，也不保证服务持续在线。

OAuth 必须由用户点击启动，复用当前预开窗口与 Electron 打开方式，避免异步弹窗拦截。只有原生登录完成且工具发现成功才显示检查成功。保留「已授权，但页面还在等待？」折叠入口；只有后端 `acceptsRedirect` 为 true 时显示回调输入，失败、取消、过期可重试。关闭弹窗取消未完成的授权尝试，不暗示撤销供应商已经授予的权限。

表单字段失焦后校验，提交时聚焦第一个错误：地址格式/协议、命令为空、参数引号/数组、Header 名称、重复 Header、空凭证、无效超时等。网络错误放结果区。技术信息默认折叠，错误文本避免回显密钥和带敏感查询参数的完整地址。

### 第二阶段：测试成功后保存

目标交互为「测试连接」→ 成功 →「添加」或「保存更改」。当前 probe/auth 只接受已保存 serverId，不能只改按钮文案实现。

需引入服务端草稿连接生命周期：草稿归属当前 principal，持有到期时间与配置指纹，允许测试和 OAuth，成功后提交指定版本，再清理草稿；编辑失败保留原生效配置。pi 继续负责 OAuth 与 Token 存储，必须处理草稿 id 与最终 id 的凭证归属，取消后的晚到授权结果不能提交。若无法安全完成凭证归属转移，继续采用第一阶段的诚实文案，不伪装事务。

此阶段还需单条更新或版本校验，避免全量 servers PATCH 覆盖并发修改；新 API 必须同步 lazy-bundle matcher 和真实鉴权路径测试。

## 6. 命令启动与导入

命令启动展示「可执行程序」「参数」「环境变量」，环境变量用键值行，不要求用户写 JSON。参数支持逐项编辑，保留粘贴 JSON 数组的入口；不随意按空格拆分带引号的值。工作目录在高级区域。

固定提示：「命令在 Gateway 所在机器执行，所需程序和文件也必须位于该机器。」HTTP 地址为 localhost/127.0.0.1 时，在地址下说明「此地址指向 Gateway 所在机器」，避免 WebUI 远程访问产生误解。

导入入口替换当前展开式大文本区，进入同一弹窗的导入视图，提供返回表单。粘贴 → 解析 → 预览服务名称、连接方式、端点 → 选择一个导入 → 回填表单 → 用户保存并连接。明确「本次添加 1 个服务，其余不会导入」，不默默丢弃多服务配置。JSON 错误留在输入处；未知字段保留，复杂认证显示保留状态，不把导入等同连接成功。

## 7. 高级设置与列表

高级设置按连接方式裁剪：HTTP 展示附加请求头、OAuth Client ID（浏览器登录适用）；命令展示工作目录。共用连接标识、请求超时（秒）、工具加载方式。超时空值显示「使用默认值」，不把示例 60 误报为已核实的运行时默认值。已有复杂 OAuth 字段保留，不新增满屏 Client Secret、端口和元数据选项。

工具加载方式默认沿用 codemode。四种模式保留技术名称和简短解释，说明它控制工具如何提供给模型，不将 exposure 包装成访问授权开关。详细含义需按锁定的 pi 版本验证后写入文案。

列表建议：

```text
团队知识库                         上次检查成功 · 8 个工具
在线服务 · docs.example.com                 10 分钟前
                                      查看工具    ⋯

本机文件                                      已停用
命令启动 · npx
                                                ⋯
```

更多操作集中为编辑配置、检查连接、停用/启用、移除。状态用文字配合语义色，不能仅显示圆点。端点摘要移除 URL 用户信息和敏感 query，长内容可换行/截断。

第一阶段不具备持久健康状态时，初次列表只显示「已保存 · 未检查」，本次检查结果标注时间，不伪造在线状态。持久化最近检查时间、配置指纹与结果后，才跨刷新显示「上次检查成功」。不通过页面渲染逐项 probe，也不引入无必要的后台轮询。

托管连接器继续使用原有安装/账号管理流程。此方案仅修改自定义 MCP，不允许在此编辑托管配置或 Agent Plugin 提供的条目。

## 8. 实施范围与验收

第一阶段拆分认证字段与草稿归一化逻辑，保留现有 MCP API 和 pi 执行路径；改进导入、命令表单、状态文案和失败恢复；可选补充 displayName。凭证引用必须无损往返，不能因为 UI 简化而丢失 `extra`、`toolExposure`、OAuth 扩展字段或停用状态。凭证显示遮罩只是展示行为，不等于加密存储，存储复用现有凭证体系。

第二阶段再实现草稿测试、原子提交和持久化检查摘要。不要新建第二套 MCP 执行器、OAuth Token store 或健康检测框架。

核心验收场景：

1. 公开 HTTP 服务只填地址即可保存并检查；名称可跳过。
2. 已有 Bearer/API Key 的用户不展开高级设置即可完成；带前缀 Token 不重复添加 Bearer。
3. API Key Header 可编辑；重复大小写 Header 会阻止提交；切换认证不发送隐藏旧凭证。
4. OAuth 支持成功、拦截后重新打开、拒绝、超时、取消、远程回调与重试，失败不误报已连接。
5. 编辑已有引用凭证、复杂 OAuth、停用项时保留其结构和启用状态。
6. 失败后明确是否保存；关闭重开不丢失已保存配置；新草稿不会被列表当作可用连接。
7. 命令参数包含空格、引号和 Windows 路径时不损坏；Gateway 执行位置提示可见。
8. 多服务 JSON 导入明确选择范围，解析失败不覆盖草稿；id 冲突包括连字符/下划线归一化冲突。
9. 最近检查成功有时间与配置版本，修改配置后不继续展示旧成功；0 工具状态可理解。
10. 桌面/窄屏、深浅色、中英文、键盘导航、密码显示切换与字段错误定位均可用。

验证优先复用 `mcp-connection-setup.test.tsx`、`mcp-config-api.test.ts`、Header 测试和 Gateway 集成测试，重点覆盖认证分支、无损编辑与保存/检查的状态关系。实现与验证记录见下节。


## 9. 第一阶段实施记录

- 添加/编辑弹窗支持在线服务、Gateway 命令启动和 JSON 预览导入，保持固定外层尺寸与内部滚动。
- 常用认证移至基础表单；Bearer、API Key、自定义请求头按需展示，额外 Header 留在高级设置。密码值默认隐藏；引用对象原样保留，替换认证方式后只序列化当前有效凭证。
- 新增可选 displayName，自动生成稳定 id；保存后的 id 只读。高级区域允许首次保存前修正导入 id，不要求普通用户填写。
- 命令参数逐项编辑，支持粘贴参数列表；环境变量键值编辑并保留凭证引用。地址/参数/环境变量/Header/超时在提交前检查，地址还支持失焦校验。
- 主操作明确为「保存并连接」；保存失败与检查失败区分，失败保留配置和输入。停用项可保存更改，启用连接需明确操作。成功 0 工具单独展示，配置变化清除旧成功结果。
- 保留 Web/Electron OAuth、重新打开授权、远程回调和取消；迟到结果不会覆盖取消状态。未保存修改关闭时确认，页面离开时提供保护。
- 自定义列表展示名称、停用/已保存未检查状态；端点摘要不显示命令参数或 URL 查询参数。状态未持久化，不将已保存配置标为在线。
- 中英文 MCP 文档已同步 Web OAuth 支持情况。新增脚本 `node scripts/test-mcp-config-visual.mjs` 可复查桌面/窄屏、深浅色、中英文及认证/命令/导入/错误状态，使用本地 fixture，不连接真实用户服务。

验证包含连接器前端与配置/原生 MCP 单元测试、现有真实 Gateway 鉴权集成测试、浏览器界面矩阵、根目录 TypeScript、Web 生产构建和修改范围 ESLint。真实 Gateway 集成测试使用本地 MCP/OAuth fixture，未使用真实供应商凭证或修改用户运行配置。草稿测试/原子提交及持久化健康摘要仍留在第二阶段。


## 10. 第二阶段实施记录

- 新增 `/api/mcp/drafts` 草稿生命周期：创建、检查、浏览器授权/回调、查看工具、提交与取消。草稿只存于内存，绑定 Gateway principal，10 分钟过期；重启后重新测试。修改表单、关闭或取消会清理草稿，取消后的迟到结果不能提交。
- 测试从不调用配置写入。成功后才出现「添加连接」或「保存更改」；停用项在隔离环境中测试，提交时由用户选择保留停用或启用。检查失败保留已有生效配置与本地输入。
- 使用 pi 1.1 的原生 McpOAuthCredentialStore 与 InMemoryAuthStorageBackend，通过 createMcpExtension 的 credentials 注入点隔离测试凭证。没有复制已有 refresh token，也没有为单次测试切换全局 agentDir。
- 保存 OAuth 时，凭证先写入新的独立身份，配置通过 xopcOAuthCredentialId 指向该身份，工具命名空间仍使用原 serverId。失败保存只清理未发布的新凭证，不覆盖旧凭证；已落盘但热加载报错时保留已被配置引用的新凭证，避免重启后断链。运行时、原生工具发现和登录统一使用原生存储映射；runner 指纹包含身份映射，切换凭证后不复用旧连接。
- 草稿保存校验初始源配置版本、目标 ID 和工作目录；提交前再读最新配置，只替换当前服务。草稿提交与旧 PATCH /api/config 的读改写共用锁，避免两个 HTTP 保存互相覆盖；旧 PATCH 使用配置副本，校验失败不提前污染生效对象。成功提交支持重试幂等，不重复保存。
- 提交记录上次成功检查的时间、工具数及配置摘要。列表通过服务端校验摘要后显示最近检查；配置被修改后结果失效，不声称服务持续在线。OAuth 旧身份保留给仍在执行的连接，不在提交时撤销供应商授权。
- 新路由已补齐 lazy-bundle 匹配与正/负映射测试。真实本地 Gateway 测试覆盖鉴权、失败隔离、OAuth 授权前后凭证文件内容、工具预览、保存失败重试、并发单条提交、版本冲突和取消回调；不使用真实供应商密钥。

依赖边界：pi 当前公开了 credentials 注入契约，但原生存储构造器位于其内部 dist 模块；桥接集中在 credential-store.ts，按仓库锁定的 pi 1.1 验证。升级 pi 时应运行原生凭证隔离与草稿 OAuth 集成测试。草稿只保证配置测试隔离，不撤销用户已在供应商页面完成的外部授权。

第二阶段验证结果：28 个测试文件共 156 项相关回归通过；浏览器覆盖 88 组桌面/窄屏、深浅色、中英文和测试/保存/授权状态。根目录 TypeScript、Web 类型检查与生产构建、修改范围 ESLint 和 diff 空白检查均通过。

## 11. 两阶段整体审查与修复

本轮围绕草稿隔离、OAuth 凭证、并发保存与异常恢复补充了可复现的回归用例，并直接修复以下边界：

- 草稿创建在异步分配原生存储前固定源配置指纹；重新测试清除旧授权成功状态，取消后的工具发现结果不得返回，已取消的原生会话不会在异步准备完成后启动。
- 所有 HTTP 提交使用独立原生凭证身份。未使用 OAuth 的测试也写入空凭证记录，阻止运行时回退到同名或旧 URL 授权；退出登录保留空记录。首次凭证落盘失败不执行可能误删旧 URL 授权的清理。
- Gateway 配置服务统一排队持久化，对完整配置保存检查调用时的预期版本；草稿提交、单条删除与旧 PATCH 在异步准备前固定预期快照。删除只删除指定版本的单条服务，保留其他页面新增的配置。冲突返回 409，失败的部分更新不会提前发布到内存。
- 保存期间禁止取消授权；前端等待授权取消完成后才允许重试。授权轮询异常时废弃整个旧草稿，清理请求只针对旧草稿，避免迟到取消误伤新授权。
- 配置落盘后即保留已提交快照，即使后续热加载失败也不回退。草稿返回可重试的幂等成功回执并标记 `reloadRequired`；界面明确提示已保存、需重启 Gateway，禁止重复提交并允许直接关闭。

并发保护范围为同一 Gateway 进程内的配置写入；不把它描述为跨进程文件锁或供应商 OAuth 撤销事务。测试使用临时配置、原生凭证文件和本地 MCP/OAuth fixture，不修改用户正在使用的配置或凭证。

本轮最终验证：30 个测试文件、250 项相关回归通过；96 组浏览器界面矩阵通过，并人工检查窄屏保存后恢复提示。根目录 TypeScript、Web 类型检查与生产构建、Node 构建、构建产物的原生凭证注入冒烟验证、修改范围 ESLint 和 diff 空白检查均通过。Web 构建仍有项目已有的分包大小/混合动态导入提示。

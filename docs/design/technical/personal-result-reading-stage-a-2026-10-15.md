# Personal AI 成果统一读取：阶段 A 实施与验证

日期：2026-10-15。对应[整体方案](../personal-ai-work-continuity-plan.md)阶段 A。本文区分已实现能力、验证范围及尚未解决的问题。

## 实施内容

Personal 主对话新增 `personal_result`，固定工具面由十二个变为十三个。统一读取已保存的执行正文、已发布文件及连接应用结果；追问不再因为成果超过轻量文件读取门槛而默认创建新 Task。

| 命令 | 行为 |
| --- | --- |
| `list` | 当前 Personal 聊天拥有的结果目录，支持 Task 筛选与分页 |
| `get` | 结果的正文入口、成果清单；指定 sourceId 时读取分节目录 |
| `read` | 按源、内容版本、章节和字符范围读取，返回完整性标记及续读游标 |
| `search` | 三字符及以上的字面片段检索，返回原文片段、偏移和章节定位 |

默认 `sourceId=body` 指保留的执行结果文字，不代表文件正文；文件使用 `get` 或已有成果目录中的 artifact ID。`resultId` 是现有交付 ID。源正文版本是原始字节与解析器版本的 SHA-256；游标绑定结果、来源、版本、命令、查询和章节。正文范围使用 Unicode 字符偏移，避免 emoji 造成重复或丢字。

模型默认只收到有界结果目录及历史摘要中的稳定结果 ID，全文保持在存储中。普通非 Personal 对话的历史投影没有新增仅 Personal 可用的工具调用指令。

## 后台准备与响应边界

沿用 `task_result_deliveries`、原有成果文件和 Request 结果作为权威来源。SQLite v251 增加派生的可读表示、章节、FTS5 trigram 索引和冷读取续答记录，不另建业务 Task 系统。

- 发布/交付后异步预热，原文件交付不等待解析。
- 冷读取立即返回 `preparing`；当前问题保存到读取等待记录。准备完成后，经既有 Gateway 结果调度入口向主输入队列提交一次只读续答，不占住原主对话回合，也不重新调用 Router。
- 续答使用稳定输入幂等键；重启后可以恢复，原输入取消/中断、transcript 改变或对话删除时失效。前台输入优先；当前实现等待语音通话结束再调度该文字续答。
- 解析最多两个 worker，单个超时 45 秒、V8 堆限制 256 MiB、输入上限 50 MiB、可读文字上限 16 Mi 字符。超限明确失败，不静默截断为“完整正文”。
- 文件读取固定缓冲区并校验前后指纹，拒绝符号链接；并发冷读通过数据库租约合并，不重复启动同一解析。
- 解析和索引写入在 worker 内完成，索引按小事务提交。前台只查询有界元数据、全文片段及命中，不同步解压 Office 或解析 PDF。
- 单次工具 JSON 输出上限 8,000 字符，正文默认最多 4,000 字符；转义导致超预算时缩小实际范围，保留正确续读游标。

## 格式与来源

| 来源 | 读取表示与限制 |
| --- | --- |
| 文字、Markdown、CSV、常见代码文件 | 原文本；Markdown 标题分节，按范围及字面片段检索 |
| PDF | PDF.js 提取页文本，带页号；版式、图片和扫描页 OCR 不在本期范围 |
| DOCX | 主文档段落，保留段落定位；不能把提取文本视为版式或嵌入对象验证 |
| PPTX | 按幻灯片顺序提取文字，保留页序 |
| XLSX / XLS | 工作表及单元格地址、原始值、显示值和已保存公式；不重算公式 |
| 连接应用结果 | 已保存的摘要、条目、覆盖范围和链接；读取不刷新外部服务 |
| 图片、音视频等 | 可读取已有执行文字；源文件无可读文本时明确说明，需要新的媒体理解才进入执行 |

连接应用 fallback 的完整执行文字不再在保存前截成 16,000 字符；Composer 的提示词预算独立保留。历史上只有摘要且没有保留正文的记录不会被伪装成完整结果。

可读索引按现有结果关联持久化，随结果/对话级联清理。来源文件缺失、字节改变、解析失败或无文本均返回具体状态，不重新制作原成果。

## 权限与界面

每次读取检查当前 Personal 聊天身份、Task 原始聊天归属及对话存活状态。连接应用还检查原 Request、原 transcript、账户与连接器、连接状态、所有者和执行者的当前访问策略；命中缓存不跳过撤权检查。持有结果或 artifact ID 不授予跨聊天读取权限。

Web 返回消息增加“询问”按钮，可选择整个结果或单个文件，作为下一条输入的结构化 `kind=result` 引用。引用包含结果/来源身份及执行 epoch/outcome 版本；Gateway 校验后只注入有界指针，再由主 Agent 按需读取。不会将整个文件作为前台输入准备的一部分加载。

原生端本期未新增选择按钮；原有文字和附件展示保留。四端设备交互验收属于后续阶段。

## 构建与兼容

Node 发行版包含独立解析模块；Electron Gateway 构建额外生成 `out/server/result-extraction.js`，避免解析退回主线程或依赖开发目录。

PDF.js 是明确版本的运行时依赖，Electron 同步将其纳入外置运行时。SheetJS 复用仓库已有的 0.20.3 归档，仅作为构建依赖，并在 Node/Electron 解析模块中打包；发布的运行时 manifest 不依赖开发机的 `file:` 路径。发布 manifest 检查同步拒绝运行时 `file:`/`link:` 依赖。

本次没有新增 HTTP API 路由；选择引用走已有鉴权输入路由，媒体下载走已有鉴权接口。

## 真实链路

可复跑入口：

```sh
XOPC_RESULT_READ_LIVE=1 XOPC_RESULT_READ_BROWSER=1 \
  pnpm exec tsx scripts/personal-result-reading-live-smoke.mts
```

使用当前配置的真实 Personal、Router 和执行模型；隔离 Gateway、数据库、账户状态及合成文件，不克隆 OAuth 刷新凭据，而是沿用原凭据目录和提供方锁。文件包中的检查脚本包含明确的 8 秒等待，用于观察后台执行期间的并发聊天，不代表真实解析耗时。

验证要求：真实提交与后台分配、三份文件原字节下载、未鉴权下载拒绝、主对话并发回复、冷解析后自动读取聊天摘要之外的尾部事实、结构化选择报告与 CSV 后追问、任务与 Router 调用数不增加、浏览器实际点击并提交准确引用。最终数值与通过状态以[最终 JSON](./personal-result-reading-live-2026-10-15.json)为准。

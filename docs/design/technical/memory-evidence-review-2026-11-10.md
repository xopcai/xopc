# 工作记忆证据复核与经验学习

日期：2026-11-10。基于 [Anthropic: The components of agent memory](https://www.anthropic.com/research/components-of-agent-memory)，延续 [记忆学习与召回](./memory-learning-and-retrieval.md)。

## 设计决策

保留 SQLite 原始转录、证据、工作知识、修订和执行上下文。新增能力围绕「已保存的结论是否仍由证据支持」展开，而非增加新的存储层。上下文压缩继续只承担当前会话恢复，不能代替长期记忆学习。

本轮交付两个切片：有触发条件的自动工作记忆复核，以及带条件和工具验证的可复用经验。完整项目 Wiki 与跨会话语义重组继续保持为实验项，不在缺少对照收益时引入。

## 证据复核

### 触发和选择

复用持久化 transcript-synthesis 任务及其现有解释器调用。在新的用户自述包含纠错／限定条件信号，或工具结果出现失败信号时，按词法相关性选取至多四条相关工作记忆。没有候选时不加载原文，不增加固定模型调用。

首期只复核同一 conversation、同一 Agent、当前 scope 可见、origin=agent、extractor=work-synthesis 的 active 记录。显式用户记录、其他项目、其他会话、外部连接器和任务回执均不作为本轮自动改写目标。

事实变化的新旧判定目前要求来源处于同一 transcript，可用序列比较；reset 后跨 transcript 的事实变更继续使用既有显式纠错路径，本轮不自动跨转录晋升。

这是一项保守的事件选择策略：当前中文／英文词法信号不能覆盖全部纠错表达，也不具备跨多次失败的聚合检测能力。候选从现有有界列表中选择，尚不保证大规模语料下全局最相关召回。

### 原文读取

从 knowledge_evidence_links 回读原始转录行，而非以摘要或 400 字符证据摘录为依据。每条记忆至多四条完整来源，每条至多 2,400 字符，记忆正文与来源合计至多增加 6,000 字符。超限来源整条跳过，不截去限定条件。

读取要求证据 hash、关系快照和原文内容一致；遗忘边界、敏感信息和 local_only 政策继续生效。来源不完整或不能核验时不交给模型复核。原文是可核验出处，不意味着其中所有事实都客观正确。

### 模型建议与宿主准入

解释器增加 knowledgeReviews：keep、revise 或 withhold，均需精确引用。

- keep 不修改记录、不增加修订。
- revise 的替换正文必须等于一条被完整引用的原始／新证据行，包含限定条件和否定；首期不允许自由生成新的综合结论。模型可省略句首明确的 Correction:/更正：等非语义标签，但宿主实际保存的仍是完整原句。
- qualifier_lost 可回查原始行恢复限定条件。事实变化或验证失败必须有较新的本轮证据；同毫秒及延迟后台写入均使用 transcript sequence 判定来源顺序，不把记忆落库时间误当成事实发生时间。
- withhold 将知识转为 needs_review，阻止它继续以可用工作知识进入执行上下文。失败结果也可作为有证据的当前事实修订；不要求所有失败都只能停用。
- 自动复核不改用户断言，不提升 authority、confidence 或行动权限，不恢复已删除内容。

用户引用中混有本人说明时，复核采用完整归属检查，不因存在一小段本人文字就接受整段第三方引用。多段文本使用与原学习路径相同的拼接方式计算 hash。

模型返回后，在现有学习提交事务和租约保护内再次核对目标快照、原文、作用范围、删除抑制和使用政策。目标／来源变化时拒绝结果。修订走现有知识 repository，保留旧正文及 source JSON；复核结果进入原 extraction audit，随学习游标原子提交。

同一目标在一个结果中只能处理一次。成功复核过的 canonical key 在本批普通知识提取中被排除，避免紧随其后的旧总结覆盖修订。

配置：userContext.knowledgeMemory.learning.evidenceReview，默认启用，可关闭。无新 schema、Gateway 路由、额外定时器或单独模型配置；沿用 understanding 模型、现有超时／一次格式修复和每日学习批次预算。个人理解历史重建不应用工作记忆复核。

## 可复用经验

工作候选增加可选 lesson，含 condition、action、verification 三个证据引用；三个引用都必须进入同一候选的 evidence。宿主要求 verification 来源为实际会话的 toolResult；文件／连接器不能通过把资料包装为工具结果来晋升经验，相关来源学习提示使用 episode 或 note。验证引文须具有成功标记且原始工具文本不含所支持的否定／失败标记。助手说「通过了」不构成工具验证。

模型提取 schema 要求 task_lesson 必须包含该结构，缺失时进入现有一次格式修复。具有该结构并通过全部原有准入的 task_lesson 才能作为 supported 工作知识；绕过 parser 的内部调用若缺少结构，仍保守保持 tentative/candidate。正文由宿主把三个实际证据片段组合为条件、动作和观察到的验证结果，不采用模型自由生成的因果结论。已有可复用经验遇到有依据的失效复核时进入 needs_review，不能保留旧成功验证继续复用。失败事件与未验证猜想仍可保存为 episode 或候选，不伪装成可复用的成功经验。任务回执继续独立记录实际执行状态，不因这次调整重写历史。

此门槛是必要条件检查，不是因果证明。关键词验证目前只覆盖有限中英文工具输出，混有成功／失败的工具文本会被保守拒绝；未来应优先接宿主结构化验证回执，而不是无限扩展词表。

## Benchmark 方法

入口：scripts/memory-work-review-benchmark.mts；数据：evals/memory/work-review-cases.json、lesson-cases.json。

1. 用合成原始转录和有证据、但可能丢失限定条件的工作记忆，显式构造故障。它们用于测试修复能力，不能用来推断生产记忆的错误发生率。
2. 使用生产 prepareWorkReview、workReviewPrompt、schema、applyWorkReviews、知识准入及真实 SQLite 修订路径。模型输出不给参考答案；输出不合法只允许一次有记录的格式修复。
3. 对同一条目标记忆比较「冻结的原始记忆」与「模型复核后的记忆」给后续回答带来的差别。两边使用相同回答指令、问题和模型；重复运行交替回答顺序。
4. 两种合法失败处理（有证据的失败事实／保守停用）按预先声明的 rubric 接受。正确记忆必须保留；保护对象不能被自动改写；删除期间返回的模型结果必须拒绝。
5. 另用生产 maintainer 提示与语义 parser 提取经验，经真实 applyWorkCandidates 验证已确认经验、失败修复猜想和助手自称成功等情形。
6. 报告逐项原文、原始模型响应、修订结果、后续回答、每次调用 token／提供商上报成本／耗时、数据集 hash、提交及源码指纹。运行期间源码变化使该次验收无效。

这是组件级、固定目标记忆的对照实验，不是原有完整检索系统与新系统的端到端 A/B：冻结组不执行同等后台重新提取，后续回答只使用目标记忆；不能据此声称整个产品的回答准确率提升。真实持久化 worker 的单次模型调用、修订、审计及游标提交另由集成测试验证。没有新增路由，不涉及新的 lazy dispatch 验收。

所有测试使用隔离数据库与合成内容；复用已配置模型凭据和目录锁，不克隆 OAuth 刷新令牌。不会修改个人记忆数据库。原始报告在 reports/memory/，不入版本控制。自定义模型若未配置价格，usage 中的 cost=0 仅代表缺少计价信息，不代表真实账单为零。

```sh
XOPC_MEMORY_LIVE=1 \
XOPC_MEMORY_LIVE_MODEL=qwen-token-plan-cn/qwen3.8-flash \
XOPC_MEMORY_BENCH_REPEATS=3 \
XOPC_MEMORY_REPORT=reports/memory/work-review-qwen-flash.json \
pnpm run eval:memory:review

pnpm exec tsc -p scripts/tsconfig.memory-live.json
XOPC_LOG_LEVEL=fatal pnpm exec vitest run src/memory-learning/__tests__ src/knowledge-memory/__tests__ src/agent/background-review/__tests__ src/user-model/capture/__tests__
```

可把 XOPC_MEMORY_LIVE_MODEL 换成已配置 GPT 模型的实际 provider/model 引用。模型不可用或缺少凭据时明确失败，不静默替换模型。

## 后续设计与上线门槛

- 将反复失败、用户纠错和反馈聚合为复核优先级，评测后扩展到跨会话回查；继续按来源授权与作用范围过滤。
- 项目知识导航作为现有 knowledge IDs 和证据的可重建视图，包含当前目标、关键决策链、未解决问题及展开入口；它不成为另一份事实库。
- Wiki 必须在跨文档问题上优于搜索基线，并计入维护 token、陈旧信息率及知识体积；简单单文档任务不预设 Wiki 有收益。
- 上下文晋升／降级先通过影子评测比较相关性、误用率和 token；helpful 反馈影响使用价值，不能直接提升事实置信度。
- 扩大公开合成语料、增加 GPT 与 Qwen 的多次重放，分开报告修复率、正确记忆误改率、隔离失败数、后续任务表现和成本。当前小样本不构成通用准确率结论。

## 当前源码的真实模型结果（2026-11-10）

| 项目 | Qwen 3.8 Flash（一次） | Qwen 3.8 Max（一次） |
| --- | --- | --- |
| 记忆复核满足目标 | 12 / 12 | 12 / 12 |
| 经验学习场景 | 3 / 4 | 4 / 4 |
| 冻结目标记忆的后续回答 | 7 / 12 | 7 / 12 |
| 复核后目标记忆的后续回答 | 12 / 12 | 12 / 12 |
| 真实模型调用数（含回答和格式修复） | 37 | 35 |
| 运行期间相关源码指纹 | 无变化 | 无变化 |
| 严格整套退出状态 | 失败，保留一次格式失败 | 通过 |

当前报告：reports/memory/work-review-qwen-flash-current.json、reports/memory/work-review-qwen-max-current.json。

Flash 未达标的是「助手自称测试成功」反例：模型在一次格式修复后仍返回缺少末尾闭合括号的 JSON。该次 parser 未接受任何候选，没有把助手自称成功晋升为可复用经验；但任务未完成有效解释，仍计失败，命令非零退出。不能因为没有错误写入就把该次记成通过。

正确记忆、引用攻击、显式记录保护、项目隔离、原文变更和删除竞争案例在这两组中均符合预期；固定语料没有观察到越权改写。Max 只有一次当前源码重放，不能据此断言通用能力或长期稳定性显著优于 Flash，也没有修改用户当前的模型配置。

### 重复性与对照边界

同一工作复核实现、个人谓词提示细化之前，Flash 三次重放的记忆复核为 35 / 36、经验学习为 12 / 12，后续回答从 21 / 36 变为 35 / 36；其中一次英文限定条件修复被模型保守停用而非恢复原文，后续回答变为未知，严格门槛未通过。相同案例其余两次成功。报告：reports/memory/work-review-qwen-flash-acceptance.json。

谓词提示细化之后的另一次补跑，两种模型均达到复核 12 / 12、经验 4 / 4、后续回答 7 / 12 → 12 / 12。其后补充了延迟后台写入的确定性顺序修复，再生成上方 current 报告。所有原始结果都保留；单次通过不能消除已观察到的保守弃权和格式失败。

本测试是固定目标记忆的组件对照，冻结组不执行后台重新提取，回答不包含其他记忆或当前原文检索。结果不能外推为整个产品的准确率提升，也不等同于检索系统的端到端 A/B。自定义模型没有配置价格时，usage 中的 cost=0 只代表缺少计价信息。

### 既有 Gateway 自动学习回归

完整九类场景回归中前八类通过，包括客户引文、混合内容、假设、临时状态和重放去重；最后带引号的偏好值被模型放入已有通用 preference.response.order，与先前结论／证据排序冲突，进入 needs_review。没有覆盖旧偏好，但新偏好不可用；不能声称整套 Gateway 回归全通过。

提示现已明确区分结论／证据与举例／解释两个排序维度，不自动重命名旧谓词或放宽冲突保护。针对实际冲突的最终重放选择 ongoing-preference 与 quoted-value-owned，保留真实的旧偏好，再学习新维度。5 项真实 Gateway 检查通过，包含来源、持久化学习与重放、新会话回答；新会话分别列出两种偏好。报告：reports/memory/memory-learning-qwen-predicate-targeted.json。

含重复选择的另一次定向重放出现模型持续弃权：它将两次独立选择解释成临时格式要求。该场景仍失败，未降低两份独立证据门槛，也未用宿主关键词强行生成个人偏好。报告：reports/memory/memory-learning-qwen-predicate-regression.json。最终定向通过不等于九类全量套件在最终提示版本上全通过。

### 工程验证

- 18 个测试文件、170 项测试通过：真实 SQLite 修订、租约内提交、审计与游标、同毫秒及延迟写入、完整原文／混合引用、遗忘边界、外部来源不能伪装运行验证等。
- Node/Electron 类型检查、验收脚本类型检查、受影响源文件与测试 ESLint、Node 构建及 git diff --check 通过。没有新增前端页面，不涉及视觉界面验收。
- 探索性真实测试发现并修复了同毫秒／延迟写入顺序误拒、Correction:/更正：前缀误拒、客户引文进入候选工作笔记、缺失经验结构以及独立个人偏好维度碰撞。对格式失败和重复选择弃权，保留非零退出与完整模型输出，不声称模型通用准确率达标。

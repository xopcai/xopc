# Phone Use：同屏批量提取与派发前观察优化

日期：2026-10-30。目标：减少京东搜索 AI 眼镜、读取前五件商品的串行推理和截图成本。最终未取得完整 Top5 成功耗时，不能宣称达到五秒。

## 实现

- `phone.batchReadings` 默认开启；同屏多个无原生 selector 的 named outputs 合并到一次 `readFields`。明确配置 false 或不支持批量的适配器仍走逐字段读取。原生 selector 继续直接读取，不发送额外模型请求。
- 指定 named outputs 后不再先做通用 finish 转录。字段读取复用最后的动作后观察或第二次独立完成确认，不再额外获取整屏。模型 finish 推理耗时期间可能变屏，仍需在预测后重新观察一次再提取字段。
- 字段提取期间保持 running，完成后才发布最终状态，避免调用方把“还没读完商品”计为完成。取消、接管、授权变化和共享预算检查保留；像素在异步提取结束后清零。
- 派发前先读取新鲜原生 UI、两次前台应用以及显示几何信息；仅在能识别活动默认内部屏幕、几何一致且通过现有 `canDispatchPhoneAction` 校验时省略截图。不能证明稳定、没有原生节点、旋转或窗口变化均回退完整观察。像素为空的校验结果不进入模型或预览；语义定位失败后重新获取完整观察再规划。模型输入、动作后观察和独立完成确认仍使用真实截图。
- 主 Agent 手册明确要求一次提取同屏商品的名称、价格和简短介绍，并在滚动前保存结果、去除跨屏重叠项。

## 阿里云京东实测

使用用户注册的“阿里云手机”、现有 `xopc-cloud/phone-doubao`，通过隔离状态的鉴权 Gateway 和真实 lazy route 路径执行。计时从打开手机会话前开始，包含启动京东、搜索/字段收集和轮询，不包含 Gateway 启动、测试前可选 force-stop，以及独立的主聊天模型生成总结。手机任务未完成，完整用户请求的成功耗时未知。

| 试跑 | 手机链路已耗时 | 结果 |
| --- | --- | --- |
| 强制停止京东后启动 | 3.485 秒 | 启动后原生观察失败，`PHONE_UI_UNAVAILABLE`；零商品、零手机模型请求 |
| 检查画面并重新连接，复用京东进程 | 20.502 秒 | 首次预测约 13.96 秒；第二次模型请求返回 HTTP 429 / `PHONE_MODEL_QUOTA_EXHAUSTED`；零商品 |

第二轮打开手机和京东约 1.860 秒；run 内观察总计 3.517 秒，模型请求总计 14.581 秒。阶段指标存在嵌套，不能把 hierarchy/capture/screenshot 重复相加。失败任务不能当作完成任务延迟，也不能用 20.502−5 作为成功任务还差多少。两轮试跑发生在最终派发前轻量观察改动之前；没有在额度耗尽后切换模型或绕开限制。

完成最终轻量观察改动后，做了四次京东首页只读采集/搜索入口派发校验对比，没有注入动作、没有调用模型：

| 完整观察 | 新的派发前校验 | 派发校验是否截图 |
| --- | --- | --- |
| 1597 ms | 294 ms | 否 |
| 1327 ms | 303 ms | 否 |
| 1342 ms | 324 ms | 否 |
| 1284 ms | 290 ms | 否 |

这是固定页面小样本，首个完整观察包含服务启动成本，不构成生产 P95 或整个搜索任务的提速证明。最初要求整棵 UI 树完全相同的实验在动态首页四次都回退截图，校验反而耗时 1.64–1.74 秒，因此没有采用。最终实现复用已有动作级稳定性判据，允许已经支持的搜索框占位文字等无关变化，未放宽原有动作判据。页面真正变化时可能需要先做轻量检查再回退，仍会增加少量检查成本。

## 换模型后复测

用户将手机模型切换为 `xopc-cloud/phone` 后，使用最终优化代码和同一阿里云手机重新执行，未遇到 HTTP 429。手机流程共 **105.401 秒**（打开会话 **2.375 秒**），得到 **0 个商品**，complete=false；最终以片段 `action_limit` 停止，不能计为成功 Top5 延迟。

- run 内 14 次模型请求共 **82.449 秒**，单次中位数约 **5.012 秒**。其中一次输出达到长度限制而截断，耗时约 17.871 秒，并发生一次协议修复。
- 22 次观察共 **15.223 秒**，其中完整截图 14 次，表明部分动作前校验已省略像素获取。截图耗时嵌套于观察，不能重复相加。
- 8 个任务动作加初始启动共 9 个动作；2 次过期预测丢弃、2 次提前结束纠正。批量字段读取调用 1 次，未得到有效商品数据。
- 已进入 AI 眼镜搜索页面，但出现“活动参与太热情，正在努力加载，片刻后为您呈现”弹窗。最终画面为京东登录页，需要在手机上完成登录后再测；未输入登录信息。

本轮确认新模型可正常请求，同时暴露出应用加载/登录阻塞、模型长输出和提前结束的额外成本。尚无完整 Top5 成功样本，因此仍不能给出成功完成距五秒的差值。原始记录与截图保留在 `/tmp/xopc-phone-top5-retry-20261030-1`；数值汇总已加入上面的实测证据 JSON。

## 复测

`scripts/verify-phone-shopping-live.mts` 已改为分段搜索和逐屏批量提取，累积去重后最多取前五项，复用 taskId 和总预算。未取满五个时 complete=false；模型 finish 和原生页面完成条件都不能单独证明 Top5 已收集。卡片介绍仅来自可见文字，截图识别仍标记未验证，结果顺序和内容需要对照留存画面核对。

完成京东登录并确认模型可用后可重新执行（模型引用使用当前选择）：

```bash
XOPC_PHONE_REAL_MODEL=1 \
XOPC_PHONE_DEVICE_NAME='阿里云手机' \
XOPC_PHONE_MODEL_REFS='xopc-cloud/phone' \
XOPC_PHONE_EVIDENCE=/tmp/xopc-phone-top5-new-trial \
pnpm exec tsx scripts/verify-phone-shopping-live.mts
```

如需冷启动，另设 `XOPC_PHONE_COLD_START=1`。测试会打开京东、搜索和滑动，不登录、不购买。每个成功样本仍需检查五个独立商品、综合排序、价格与画面对应关系；不能仅依靠 complete 字段认定识别正确。

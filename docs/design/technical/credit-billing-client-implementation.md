# Credit 客户端实现

日期：2026-10-11。平台首阶段已部署；本文记录 xopc Gateway、Web/Electron 共用界面与 CLI 的后续实现。移动端发行包和 npm 发布不包含在本轮实现验证中。

## 钱包与用量

- Gateway 请求 `/v1/account/summary?version=2&days=7`，验证 `credit-v1`、`microPerCredit=10000` 和整数字符串，拒绝裸整数、未知精度及超出安全范围的金额。
- Web 也验证 Gateway DTO。旧 Gateway 或权限不足时显示不可用，不降级猜测换算，不把失败当作余额零。
- 余额展示购买、赠送、使用/退款预留与最早到期批次。实扣使用云端 `chargedCreditMicro`；Token 信息保留在详情。
- 本地用量页单独显示 Cloud 钱包。美元字段是其他服务商的费用估算，Cloud 模型价格不会转换成美元估算，也不会与 Credits 相加。
- CLI：`xopc models cloud balance [--json]`、`receipt <requestId> [--json]`、`budget <id> [--json]`。未完成结算的凭证显示 pending，不显示实扣为零。

## 每次运行的预算

在“设置 → 智能体设置 → 运行”填写 Cloud 消费上限（Credits）。留空不增加额外运行上限；平台原有余额、账号及 Workspace 限额继续生效。金额最多四位小数，大于零。

运行策略保存 `runtime.cloudCreditLimitPerRunMicro` 整数字符串。首次 Cloud 调用才创建持久预算，幂等键来自 conversationId/runId 的哈希。同一次运行的模型循环、模型回退、辅助模型调用、并发工具及继承执行上下文的子任务共享预算。纯 BYOK 运行不创建预算。预算创建失败时不会发送无预算的 Cloud 调用。

支持 HTTP 模型、图片生成/编辑、文件 STT 与文件 TTS；向平台附加 `x-xopc-credit-budget`。达到上限后锁止当前执行上下文，停止后续模型调用，并禁止把预算耗尽当作余额不足而自动回退。界面提示查看预算、调整后手动继续；充值不会提高当前运行预算。

该上限是**单次运行**的上限，并非跨多次输入、跨自动化周期或跨重启工作流的累计任务上限。用户发送新的输入会开始新的运行预算。每次首次绑定预算会写入 `CloudCreditBudget` 结构化日志，包含 runId 和可供 CLI 查询的 creditBudgetId。

## 明确的边界

- 启用运行预算时拒绝 Cloud 实时语音和 Cloud computer use，包含已经打开的 computer 会话，避免这些未接入的路径绕过预算。
- 运行外的后台整理、用户输入之前的转写和输出之后的自动语音不属于该运行预算。界面说明这一范围，原有平台预留和资源限制继续适用。
- 精确的跨运行任务消费归属、实时语音分段预算、三端账户界面、订阅/赠送商品及自动充值仍需单独实现。没有发布这些功能的完成声明。
- 平台按请求预留最大费用；过小的预算可能在首个请求前被拒绝，不等于已经扣费。

覆盖整数金额往返、未知单位拒绝、OAuth 错误保留、预算幂等创建、并发与子任务共享、执行上下文隔离、创建失败不绕过预算、耗尽后拒绝回退，以及 Web 金额展示与错误状态。执行根目录单元测试、相关契约/Web 测试、Node/Web 类型检查、Lint 和完整构建。

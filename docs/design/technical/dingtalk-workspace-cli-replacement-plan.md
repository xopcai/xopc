# 钉钉办公：直接替换为官方 Workspace CLI

日期：2026-10-08（Asia/Shanghai）

状态：实施方案，尚未修改运行时代码或完成真实钉钉账号验收。

## 1. 决策与目标

钉钉办公连接器直接由 `dingtalk-mcp` 改为钉钉官方 Workspace CLI（`dws`）。默认使用用户授权，用户不创建应用、不填写 Client ID/Client Secret、不配置 MCP JSON。

**dws 不随 xopc 桌面安装包或 npm 包分发。** xopc 只包含适配代码与固定版本下载元数据；用户首次连接钉钉时按需下载，在运行 Gateway 的机器上独立缓存。

用户已明确当前没有钉钉用户，因此本次不做历史兼容或迁移：

- 删除当前 MCP 定义、应用凭据字段、服务 profile 输入、旧版本常量及相关专属测试/文案。
- 不保留旧 MCP 卡片、双实现切换、自建应用高级模式、别名、旧配置转换、凭据迁移或运行时 fallback。
- 不设计 xopc 自建钉钉 OAuth 应用或社区 MCP 包装层。
- `dingtalk-workspace` 保留为产品逻辑 ID，新定义只有一种实现：`kind: cli`、`adapterId: dingtalk`。保留品牌 ID 不代表保留旧运行时。
- 不执行清理用户全局配置或凭据的脚本；没有旧用户需要迁移，不应为此添加破坏性的环境清理。

目标体验：**连接钉钉 → 打开官方授权页面 → 选择组织并授权 → 验证账号 → 使用办公能力。**

## 2. 依据与适用边界

官方文档提供 `dws auth login` 和无浏览器场景的 `dws auth login --device`；组织需要启用 CLI 访问，未启用时有向管理员申请的流程。自建应用参数是另一种可选模式，本方案不接入该模式。[官方 Workspace CLI](https://github.com/DingTalk-Real-AI/dingtalk-workspace-cli/blob/main/README_zh.md)

当前 MCP 通过企业应用凭据访问钉钉资源，需要开发者创建应用并授予权限。[现有 MCP 官方说明](https://github.com/open-dingtalk/dingtalk-mcp/blob/main/README.md)

以下事实必须通过选定的发行版本核实，不能仅按 main 分支 README 实现：授权输出格式、设备码流程、凭据目录/Keychain 隔离、身份查询、Token 刷新、组织访问开关、动作 schema、二进制分发和许可证。本轮补充在线获取失败，未取得固定版本产物与真实协议输出，不在方案中编造版本、checksum 或命令参数。

用户授权降低配置门槛，但不能绕过组织管理员控制。组织禁止使用时，连接器应给出明确原因，不能要求用户填写应用密钥或偷偷切换应用身份。

## 3. 用户流程

### 3.1 首次连接

1. 用户在连接器目录点击“连接钉钉”。
2. xopc 检查独立缓存，缺少所需版本时才下载并验证固定版本 dws；下载与准备阶段使用已有 skeleton。不在 xopc 安装、首次启动或 npm postinstall 时下载。
3. xopc 在独立授权上下文中启动设备码授权。用户打开官方授权页面，在钉钉侧选择组织并确认。
4. 授权完成后验证服务端身份与至少一个首版只读能力。
5. 成功后显示组织名、用户姓名及明确账号身份，默认“仅查看”。

采用设备码路径以覆盖桌面、远程 Gateway 和无浏览器部署；由 xopc 提供授权链接，不依赖子进程自动唤起浏览器。用户无需输入终端命令。

授权页面若不能直接包含用户码，则展示专用设备码和复制按钮；不把设备码写到聊天或日志。这个需求应通过受限的 challenge 类型扩展解决，不能伪造带码链接或开启 shell/交互终端。

### 3.2 组织未开启 CLI 访问

展示：

> 该组织尚未允许 CLI 访问。请在钉钉授权页面申请管理员开通，审批后重新连接。

若固定版本提供明确的组织审批状态，新增结构化 `organization_access_required` 原因，允许取消或重新授权；无需为了等待管理员审批保留长时间后台登录进程。

若 CLI 只提供笼统错误，则先返回“授权失败，需要检查组织访问权限”，不能凭字符串猜测为管理员已拒绝，也不能把所有 403 都归为组织开关问题。

### 3.3 授权失败、超时与重连

- 用户取消：结束授权进程，不创建账号记录；清除该 attempt 未提交的凭据。
- 超时：展示重新授权入口，不显示“已连接”。
- 权限不足：区分未授权、组织禁止、具体操作缺权限。
- 凭据刷新失败：要求重新连接同一账号，不更换身份或改用另一组织。
- CLI 安装失败：提供重试；没有旧 MCP 回退。
- 关闭弹窗与取消授权沿用现有 CLI 流程契约，不擅自把关闭窗口当作撤销第三方授权。

## 4. 首版能力范围

产品动作 ID 为 xopc 的稳定契约，下表中的名称是语义定义，具体 dws 子命令和参数由固定版本验证后确定。

| 领域 | 首版查看 | 首版写入 | 默认权限 |
| --- | --- | --- | --- |
| 身份与组织 | 当前用户、当前组织、受限联系人搜索 | 无 | read |
| 日历 | 查询时间范围内日程、读取日程详情 | 创建日程 | 创建需要 write + 确认 |
| 待办 | 查询和读取用户可访问待办 | 创建待办、更新完成状态 | 修改需要 write + 确认 |
| 文档 | 搜索和读取用户有权访问的文档 | 创建文档 | 创建需要 write + 确认 |

第一版不开放任意 `dws api`、通用 invoke、执行任意 CLI 参数、管理组织、批量修改人员、审批决定、考勤写入、文档删除、机器人创建和工作通知。

消息发送不纳入首版，以免“办公连接器”和“钉钉消息入口”混为一个入口。后续若接入用户身份消息能力，需独立的收件人/群定位、消息预览与写操作契约，继续使用同一个官方 CLI 实现，不引回旧机器人 MCP。

目标任务：

- “帮我看明天下午有没有空闲时间，确认后安排一个项目讨论。”
- “把本周待办整理成周计划。”
- “查找项目方案，整理结论并创建一份钉钉文档。”

如果选定版本无法可靠提供某项能力，收窄发布清单和目录描述，不用社区服务或旧应用模式补齐。

## 5. 运行时与账号模型

### 5.1 复用已有 CLI 架构

新增 `src/connectors/cli/adapters/dingtalk.ts` 并注册；复用：

- `installer.ts`：固定版本下载安装、完整性校验、二进制版本校验。
- `authorization.ts` / `store.ts`：授权 attempt、身份验证、稳定账号提交、重连。
- `process.ts`：绝对可执行路径、参数数组、无 shell、超时、终止进程树。
- `runtime.ts` / `cliProvider.ts`：动作发现、输入校验、账号核对、权限与审批、执行结果。

不让 Agent 调用全局 PATH 中未知版本的 dws，不执行远程安装脚本。当前 installer 只允许 GitHub/npm 来源；首版使用已验证的官方固定发行产物，不顺手扩大安装器下载域名白名单。若官方包格式无法复用现有解包逻辑，添加限定格式的支持并测试。

分发约束：

- 桌面安装包及 npm 发布产物均不包含 dws 二进制、压缩包或上游完整 CLI 包；不能把上游 CLI 声明为随安装分发的运行时依赖。
- 构建、打包、npm 安装和应用启动不触发 dws 下载。只有用户主动连接钉钉时准备运行时依赖。
- 下载发生在执行连接器的 Gateway 主机；远程 Gateway 不把 dws 安装到访问网页的客户端。
- 缓存位于 xopc 管理的独立运行时目录，按平台和固定版本区分，不写入应用安装目录、node_modules 或全局 PATH；通过已有安装器确定具体路径。
- 下载完成并通过完整性及版本校验后才启用，重复连接复用缓存；下载失败允许重试，不能提交成功账号。xopc 更新后需要不同版本时，在下一次用户连接时准备，不静默下载。

### 5.2 凭据与账号隔离

每个账号绑定稳定 `corpId:userId`；名称只用于展示，不参与唯一性或隐式选择。账号元数据至少保留用户 ID、组织 ID、显示名、上下文 ID、授权时间及可用权限信息，不包含 Token。

每次授权使用独立 context。必须确认 dws 的配置目录变量、HOME 行为及 Keychain 命名空间可真正隔离账号；仅改变 HOME 不能作为隔离成立的证据。

每次执行锁定账号和组织，在调用前验证 CLI 当前身份与所选账号一致；后台任务始终使用明确账号。不得依赖用户在终端执行过的 `profile switch` 或全局默认 profile。

优先每个 context 一个业务账号；如果 dws 内部仍保留多个 profile，则显式传入固定版本支持的 profile 标识并防止 context 默认身份漂移。多账号要用相同命名操作的并发测试证明不会串号。

重连得到同一身份时更新授权，保留业务账号设置；得到其他身份时不得覆盖旧账号或自动恢复旧任务。断开本地连接停用执行、取消该 context 运行任务并清除相应本地授权资料；只有验证了官方撤销能力才宣称撤销远端授权。

### 5.3 动作契约与结果

采用受审核的 `curatedActions`，明确 read/write；schema 使用官方机器可读输出或本地固定版本静态契约。不能靠解析 help 文本随意生成完整权限能力。

命令成功必须同时校验进程状态和业务结果，不把 exitCode=0 一律当业务成功。创建后回读目标资源，确认返回的组织、对象 ID 和结果链接。

write 超时或取消后无法证明结果时，返回 unknown，禁止自动重试创建以免重复写入；有官方幂等支持时才按其契约处理。

## 6. 授权框架的最小必要扩展

现有授权框架可以提取允许域名的 URL，但仍需确认 dws 是否能在非 TTY 下提供稳定 URL/设备码事件，并给出机器可读身份与错误结果。

必要时增加：

- 适配器定义的授权进度解码器：只产生规范化 challenge、组织访问原因及失败码。
- 设备码 challenge：验证 URL、用户码和到期时间；前端显示复制/打开页面操作。
- 服务端身份 probe：本地存在 refresh token 不等于已经认证可用。

只做 dws 协议实际需要的扩展，保留其他 CLI 适配器现有行为；不用修改它们来配合钉钉格式。对公开 API 变化同步更新类型、lazy-bundle 映射测试，并验证真实已认证 Gateway 路径。

## 7. 界面与目录改动

`china-catalog.ts` 新定义：

- `kind: cli`、`auth: { mode: cli }`、native lane，`adapterId: dingtalk`。
- `setup.secrets` 删除；`activeProfiles` 删除；旧 MCP serverTemplate/localPackage 删除。
- version 与实际固定 dws binaryVersion/adapterVersion 一致；未验收前标 Beta。
- 描述按首版真实动作表达：“登录钉钉，查看文档、日程和待办，并按权限创建或更新内容。”

复用 CLI 连接弹窗与账号列表；显示组织名和用户姓名，补足现有仅展示一个 userId 的身份行。设备码显示与组织权限提示通过结构化结果驱动，不在 UI 暴露应用凭据和服务 profile。

复杂弹窗遵循固定响应式尺寸、固定 header/footer、内部滚动规则；数据加载使用 skeleton，操作按钮可使用短时 spinner；权限选项使用项目自有 Select。

钉钉图标可继续使用。删除旧实现专属文案及帮助入口，文档替换为官方用户授权流程；历史调研材料若保留旧接入描述，应明确它是旧实现记录而不是当前安装说明。

## 8. 实施清单

| 步骤 | 交付 | 完成标准 |
| --- | --- | --- |
| A：锁定协议 | 固定版本、官方产物/hash/license、授权/身份/动作输出 fixtures | 不需要自建应用凭据；非交互授权、账号隔离和刷新机制已验证 |
| B：适配器 | distributions、dingtalk adapter、协议解码与最小授权扩展 | 安装、授权、身份 probe、首版 read/write 动作可运行 |
| C：直接替换 | 新目录、删除旧定义/专属配置/测试、CLI UI 与文案 | 默认入口仅一种实现，无 MCP/clientSecret 分支 |
| D：验收 | 测试空间联调、权限拒绝、多账号、重启与失效恢复 | 端到端通过且目录声明与实测一致 |

以上为同一次替换的实施步骤，不发布双栈过渡版本。步骤 A 如果证明关键官方能力不可用，停止依赖该能力并报告具体原因，不改为旧模式回退。

预计：协议和发行验证 1–2 人日，适配器与必要授权扩展 2–4 人日，目录/UI/测试联调 1–2 人日；总计约 4–8 人日。管理员审批及外部访问资格另计，实际以步骤 A 结果校准。

## 9. 测试与验收

### 自动检查

- 钉钉目录只有 CLI 定义，无旧 MCP serverId、Client ID/Secret 或 activeProfiles 表单。
- 固定产物完整性、平台不支持、版本不匹配与下载失败反馈。
- 检查 npm pack 文件列表及桌面打包清单不含 dws 产物或上游 CLI；验证安装/启动不下载、主动连接才下载、缓存复用及远程 Gateway 下载位置。
- 授权事件解码、允许域名、取消、过期、审批要求及敏感输出不进入日志。
- 身份缺失、仅有本地 Token、组织/用户变化不能提交成功账号。
- 同账号重连保持稳定 ID，不同组织同名用户不合并。
- curated action 输入/schema 校验，未审核命令不可执行。
- 默认只读拒绝写入；确认参数、目标或账号变化后旧审批不可使用。
- 多账号 context、凭据存储及并发调用隔离。
- 前端无凭据表单，设备码/组织权限提示、正确身份和重新连接入口。
- 变更通用 CLI 授权协议时运行已有 lark/wecom/wps365 回归；不添加旧钉钉兼容测试。

### 真实环境验收

1. 无应用凭据的新账号完成登录，显示真实组织和用户身份。
2. CLI 未开通的组织返回明确提示；审批后重新授权可成功。
3. 查询真实日历、待办和指定文档，校验访问范围。
4. 在测试空间确认后创建日程/待办/文档，回读核对；拒绝确认时没有外部写入。
5. Gateway 重启后原账号可用；凭据到期后刷新或进入可解释的重连状态。
6. 两个组织/账号任务并发执行，不因默认 profile 变化而串号。
7. 断开账号后该账号不能继续调用，不影响另一账号。
8. 搜索到无权文档或组织限制发生变化时，明确拒绝，不换身份重试。

发布条件：默认授权路径、身份隔离、只读权限和写操作确认全部通过；不存在旧实现入口及自动回退。未验证的平台/动作不宣传为支持。

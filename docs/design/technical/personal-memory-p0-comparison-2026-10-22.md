### 尚未闭合的 P0：重读后的披露边界

独立控制执行“真实用户遗忘 → 学习完成 → 真实用户明确原始记录重读，仅本次使用 → 学习完成 → 新会话普通总结”。两次学习后的六条活跃事实正文完全一致、均无被遗忘日期，说明本次没有重新存入日期正文；但最后回答仍主动披露“10 月 8 日”。

原始记录确认两个泄漏通道：

1. `knowledge_read` 返回保留的地点／组织者事实时，同时返回完整 `source.evidenceQuotes`。三条活跃知识的 provenance 仍包含 10 月 6 日／8 日，绕过了只针对历史搜索／recall 的边界。
2. `session_search` 读到前一轮授权重读留下的工具结果和助手回答；这些新对话副本未继承原始被遗忘来源的读取限制。

裁判 sourceContext 未纳入 live turn 的遗忘原文，因此给出了题面关注提示；实际前台事件、live 学习 receipt 和后续工具输出均确认这是有效产品失败，不是凭 gold 编出的限制。后续应把 live actor／指令也作为一等证据提供裁判。

这推翻了“只删除派生事实正文，并遮蔽原始历史会话就足够”的假设。下一轮须先修 LLM 可见 provenance 投影和重读副本的限制传播；保留 at-rest 来源审计、当前轮显式授权及非目标事实。当前提交是本轮检查点，不能据四条控制或原 184 条成绩宣称遗忘链路完整通过。

## 边界与下一轮优先级

当前遗忘目标最多提供 80 条可见且有依据的工作知识，未覆盖大库旧目标发现。源读取遮蔽整个受影响历史会话，可能连带隐藏其中其他原文；保留的合法衍生事实仍可用。原 transcript 保留，不保证清除已进入模型上下文的值、外部副本或 UI 删除路径。重读意图目前覆盖中文／英文常见表达，自动放行字段仅日期／时间和价格。中文子串 LIKE 回退也需另测大库性能。

只有一次冷重放，模型别名背后权重不固定；中文 64 条来自八组相关模板，开发控制参与过修复。配对统计仅在原始 JSON 保留为描述，不能当多次运行或结构独立验收。

下一轮首先闭合新发现的 P0，再处理 P1；保留来源／敏感／授权保护：

0. **P0 披露边界贯通**：统一约束 `knowledge_read` 的来源引用及其他 LLM 可见证据投影；对一次性重读产生的 tool／assistant 副本传播原遗忘来源限制。原始来源仍用于审计，当前轮的同对象／字段显式读取保持可用，后续普通总结不得再次取出。先用本失败做开发回归，再另设结构不同的独立验证，验证非目标事实保留，最后重跑冻结全量；不能只改回答提示或删除所有来源。

1. **偏好保存与选择**：用绘画、音乐、通勤和饮食用例拆分“未存”与“已存未选”，保留本人／同事、日常／单次作用域，避免用泛化兴趣替代个人偏好。
2. **更正链、来源权威和事件绑定**：用户更正优先于助手复述，区分通知／发生时间、现实／小说主体；计数与比较先检查多源完整性、事件去重。
3. **抽取协议可靠性**：针对 76 条无效输出和三种基数冲突做小规模消融与结构变化的独立验证，不用放宽敏感、授权或来源校验换通过率。
4. **来源回退与异步闭环**：历史可答时不被未连接日历截断；补单轮／最终交付双轨及实际模型／物理请求审计。
5. **验收与规模**：补新事件结构的未见集、no-memory／合法 oracle、自然到达及可写重读后的学习收敛；单测大库遗忘目标发现、中文查询性能。

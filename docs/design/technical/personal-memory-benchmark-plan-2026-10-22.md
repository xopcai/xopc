# XOPC Memory 有效性评测与优化方案

日期：2026-10-22。调研方案留档；首轮框架与基线现已实施，见 [首轮基线与归因报告](./personal-memory-baseline-2026-10-22.md)。产品逻辑未修改。
本次代码核对基于 `454fb8f829739a1c36416fd0a4374e34940a3730`。旧实施记录描述的是当时交付状态，不能自动视为当前线上状态或当前效果成绩。

## 1. 产品目标与结论

优先建立可归因的 memory benchmark，再据失败分布修改实现。记忆有效性至少包含：该记的内容被可靠保存；需要时找到当前有权使用的完整证据；在回答与办事中正确使用；无关、失效或被撤回的内容不被强行带出。

主指标是产品任务成功率与相对无记忆条件的净收益。检索 Recall@k 是诊断指标，不能代替产品收益。不要以记忆条数、上下文长度、向量库命中数或某个厂商榜单成绩代替有效性。

建议组合：

1. **主基准：LongMemEval cleaned S**，建立单会话、跨会话、时间、更新与拒答基线。
2. **日常表达：LoCoMo-Conv**，评估隐式线索、对话式查询与多记忆组合；和 LoCoMo 共享源对话，不能当独立数据相加。
3. **人物事件与多跳：LoCoMo**，保留原 evidence turn 身份，补足多人物、事件关联。
4. **写入与更新诊断：HaluMem**，区分抽取幻觉、更新错误、遗漏与最终问答错误。
5. **中文产品主验收：自建时间—人物—项目事件流**，覆盖权限、历史视角、删除与自然使用。
6. **第二阶段：PersonaMem、MemoryAgentBench、BEAM、MemoryArena / LongMemEval-V2**，分别补充个性化应用、增量学习、规模压力和经验用于行动。

本方案不预先决定采用向量数据库、外部图数据库或某个第三方 memory 服务。先在同模型、同权限和同上下文预算下测出当前薄弱环节。

## 2. 社区基准调研与选择

以下仅依据作者论文、官方仓库与数据说明。没有复用厂商自报榜单作为 XOPC 的预期成绩。这里是适配优先级，不是已经接入的清单。

| 基准 | 核心覆盖 | XOPC 用途与优先级 | 主要限制 |
| --- | --- | --- | --- |
| [LongMemEval](https://github.com/xiaowu0162/LongMemEval) | 500 个评测实例；单会话信息、跨会话、知识更新、时间推理及未知信息拒答。S/M/oracle；官方提供 cleaned 数据及来源标签 | P0 主基准。先 S，再扩 M；按类别和证据召回分别报告 | 主要是历史 QA，不直接代表自动调用记忆或实际执行；oracle 只用于诊断 |
| [LoCoMo](https://github.com/snap-research/locomo) | 10 段长时间跨度的多会话对话；问答和事件摘要，带人物、时间、证据 turn | P0/P1 补充人物事件、多跳和时间关联 | 人类双方对话不等于一个 user 和一个 assistant；不能把双方都提取成主人的画像；类别、无答案题与图像处理差异会改变分数 |
| [LoCoMo-Conv](https://github.com/MiuLab/LoCoMo-Conv) | 将 LoCoMo 问题改成 dialog、implicit、counterfactual、composed；保留原证据并增加相关背景标注 | P0 选取日常表达诊断；P1 完整适配。测隐式召回及自然使用 | 较新；固定数据与脚本后才能承诺可重现。原始问题、改写和组合共享来源，必须同组切分 |
| [HaluMem](https://github.com/MemTensor/HaluMem) | 分别评估记忆抽取、更新和 QA 的正确性、幻觉与遗漏 | P0 借鉴分层审计；P1 接官方子集 | 各系统可暴露的内部操作不同。不能把 XOPC 缺少适配的内部指标算成系统正确或错误 |
| [PersonaMem](https://github.com/bowen-upenn/PersonaMem) | 动态画像与个性化回答，提供 32k/128k/1M 上下文版本 | P1 测记住偏好后能否用于新场景 | 原生选择题与真实自由回答分开；模型推测的偏好不能变成主人确认事实 |
| [PersonaMem-v3](https://github.com/bowen-upenn/PersonaMem-v3) | 跨平台、时间变化与过度个性化克制 | P2 研究性扩展，优先借鉴不该个性化的负例 | 与 V1/V2 是不同任务；数据、环境与接入成本更高，不能当旧 benchmark 简单升级替换 |
| [MemoryAgentBench](https://github.com/HUST-AI-HYZ/MemoryAgentBench) | 增量多轮：准确检索、测试时学习、长程理解、选择性遗忘 | P1/P2 补充纠错与增量学习 | 部分任务来自通用长上下文材料，不直接对应个人记忆；选择性遗忘不等于产品删除/撤权 |
| [BEAM](https://github.com/mohammadtavakoli78/BEAM) | 100 段对话、2,000 个问题，多种记忆能力；官方列出 128K/500K/1M/10M 档 | P2 测历史规模增长、干扰和成本曲线 | 首期不跑 10M；合成材料与现实数据分布仍有距离 |
| [MemoryArena](https://memoryarena.github.io/) | 多会话、互相依赖的任务，早期行动经验影响后续行动 | P2，检验记忆是否提高任务成功，而非只提高 QA | 需要环境与工具适配，行动失败要与记忆失败分开 |
| [LongMemEval-V2](https://github.com/xiaowu0162/LongMemEval-V2) | 环境状态、变化追踪、工作流经验、陷阱和前提意识 | P2，面向 specialist 经验复用 | 是 web-agent 经验评测，不是 V1 个人聊天数据的扩容版 |

### 数据与许可落地

- LongMemEval 仓库代码是 [MIT](https://github.com/xiaowu0162/LongMemEval/blob/main/LICENSE)；实际 cleaned 数据版本与数据卡条款需随下载记录，不把仓库代码许可自动扩展到全部来源数据。
- LoCoMo 的 [LICENSE.txt](https://github.com/snap-research/locomo/blob/main/LICENSE.txt) 是 CC-BY-NC-4.0；产品商业研发用途不能仅因“内部评测”就默认获得许可。LoCoMo-Conv 是其派生数据，另核实新增部分条款。
- PersonaMem-v3 官方区分 MIT 代码和继承 CC-BY-NC-4.0 的来源/派生数据。其余逐项记录代码、数据、上游派生数据条款，不能统称无限制开源。
- 先完成资源可获取性、版本与用途核对；受限制的轨道标为 pending，不阻塞可使用基准和独立编写的中文场景。
- 不把上游对话原文提交到 xopc，不复制到生产用户记忆；依赖与数据留在 ignored eval state，锁定代码 commit、数据 SHA-256 和 evaluator 版本。
- 中文翻译是独立适配轨道，保留来源、译文和日期核对；不能把译文分数冒充官方原语言成绩。

## 3. XOPC 已有能力与待验证假设

本次核对的实现：

- `src/memory-learning/`：持续对话学习、工作知识提取、资料学习、任务回执与持久化作业。
- `src/user-model/repository.ts`：结构化事实槽、纠正/替代、有效期与证据关系。
- `src/knowledge-memory/repository.ts`、`search-text.ts`：SQLite FTS5、中文单字/二字索引、原文分块召回、scope/时效/来源使用过滤。
- `src/agent/context/coordinator.ts`：读取近期消息、构建查询、协调本地/外部记忆与实际上下文准备。
- `src/agent/context/execution-context.ts`：画像/知识排序、工作连续性补充、类别预算与最终字符预算。
- `src/personal-agent/prompt-context.ts`：用户、项目、委派任务与成果的紧凑快照。
- `src/agent/tools/session-recall-tool.ts` / `session-search-tool.ts`：当前会话与跨会话原文检索；它们与派生知识是不同的召回途径。
- `src/retrieval/queryProfile.ts` / `candidateFusion.ts`：已有查询与融合原语；本次引用搜索未发现它们在生产记忆入口的调用，不能因为文件存在就声称所有路线已接入。

已有测试覆盖许多确定性行为；[记忆实施记录](./memory-learning-implementation.md)也明确把真实模型质量、固定集 Recall/Precision 与大规模性能列为未测定。以下是根据代码提出的**待验证假设**，不是已证实的缺陷：

| 假设 | 定位实验 |
| --- | --- |
| 中文词面差异、别称、隐式表达使候选阶段漏召回 | 相同事实的原词、同义、别名、零关键词四种查询；看候选 Recall 与固定预算最终 Recall |
| “继续/上次”加入近期知识后引入错误项目或过多噪声 | 多项目同时活跃、切换话题和无记忆必要的负例；看错项目注入率 |
| 当前有效事实过滤适合“现在”，但历史事实需独立历史路径 | 同一事件按当前视角和历史视角提问，检查事实版本与证据能否找回；不为通过测试而重新激活旧事实 |
| 原文分块候选与派生总结进入上下文的优先关系影响证据覆盖 | 分块命中在后、摘要高匹配但缺答案、文档尾部证据；测候选到渲染的流失 |
| 长列表候选上限与预算造成稳定漏召回 | 将同一证据放入 100/1k/10k 知识及最高 100k 分块背景，记录被过滤、未入候选和预算淘汰原因 |
| 后台学习延迟被误判为搜索失败 | 分别测自然到达时机与学习完成后，观察证据从来源到可用的时间 |
| 能搜到正确条目，但模型不主动查或错误使用 | 对比检索组件、冻结 reader 与完整 Personal 三条路径 |

## 4. 分层 benchmark：把失败定位到具体环节

建议在 `evals/personal/memory/` 新建适配器，复用现有 EvalStore、ArtifactStore、trace、隔离 Gateway 与 source manifest，不修改 style adapter 来硬套记忆任务。

流程：原始事件 → 学习/抽取 → 准入与更新 → 索引/候选 → 排序 → 上下文选择/渲染 → 工具补查 → 回答/行动。

| 轨道 | 输入与控制 | 主要指标 |
| --- | --- | --- |
| A 写入/更新 | 按时间输入原始消息、资料与回执；不提供标准答案或证据标签 | 原子事实 precision/recall、错主体率、错误合并率、更新成功率、无依据记忆率、可用延迟 |
| B 纯检索 | 同一冻结知识快照；另设人工/金标种子数据诊断检索上限 | Evidence Recall@5/10/20、完整证据组覆盖率、nDCG、固定 token/字符预算 Recall、无关/过期/越权选入率 |
| C 固定 reader QA | 使用同一 reader 和提示模板，分别提供各检索策略的相同预算证据 | 答案正确率、完整性、时间/主体正确率、引用支持率、该拒答时的准确性 |
| D 完整产品 | 真实 Personal 会话、自动上下文和允许的补查工具；目标问题使用新 transcript | 任务成功率、记忆净收益、工具选择成功率、重复询问/错误个性化率、端到端延迟/费用 |

金标种子仅是 B 的诊断条件，不得用它代替 A→D 的学习链路成绩。纯检索的允许 read scope 不得扩大为全库，错误过滤不能靠给模型更多证据补救。

每个失败要能归到至少一个首要原因：source 未进来、未抽取、未准入、主体/时间存错、合法证据未入候选、排序落后、预算淘汰、没调用工具、读到却未使用、错用/过度使用，或 benchmark 标注错误。保留次要原因，不把全链路错误统称为 retrieval miss。

### 必须对照的条件

1. **No memory**：相同近期对话和系统规则；关闭所有历史记忆注入与历史检索工具，防止暗中走 session_search。
2. **Raw transcript lexical**：仅检索原始记录，区分派生记忆的贡献。
3. **Current XOPC**：冻结当前源码、模型、配置、学习状态和权限。
4. **Candidate**：每次只改一个模块，其他条件一致。
5. **Oracle evidence**：只给标注支持证据，作为 reader 诊断；有权范围内构造，不能绕过删除与撤权；对无答案题仍无证据。
6. 可选 **full-context**：只在模型上下文允许的规模运行，完整记录 token。它的预算不同，单列资源曲线，不混进同预算排名。

memory 的产品收益至少拆成：救回题（无记忆失败、有记忆成功）、伤害题（无记忆成功、有记忆失败）、都成功、都失败。报告净收益及每一类，不只显示最终总分。

## 5. 中文时间—人物—项目测试集

首期建议独立编写 24 个事件世界，每个 8 个检查点/查询，共 192 个检查。每类 3 个世界，分别分配 development / validation / final test；共 8 类，各 split 64 检查。规模是预算建议，不是已完成数据。

同一世界有多个会话、数位人物、项目/生活主题与带时间的来源事件。先写事件账本和标准证据，再独立写问法。分配正向题、无关记忆题、无答案题与陷阱题，并在冻结清单明确各自数量。

| 类别 | 典型场景 | 必须区分 |
| --- | --- | --- |
| 1. 事实与改写 | “不喝拿铁”与“给我选杯饮料”；缩写、中文别名、中英混合 | 词面命中与真实适用；身份事实与一次选择 |
| 2. 时间与迟到信息 | 生效日期、记录日期不同；昨天/上周、跨时区、夏令时、延期与取消 | 当前事实、当时真实状态、当时已知信息；未来计划不等于已经发生 |
| 3. 人物与关系 | 两个王敏、不同项目中的小陈、联系人改名、领导/客户角色变化 | 实体身份、关系方向、关系的有效时间；不猜私下动机 |
| 4. 跨会话组合 | 谁接替谁、其负责项目的截止日期、前次决策依据 | 找齐多跳证据，而非拿一个近似事实回答 |
| 5. 工作连续性 | 两个项目交错，“继续上次那个”，待办完成/重开/变更 | 正确任务、当前版本、未决状态；含混时必要澄清 |
| 6. 情景与约束应用 | 团队同事与家人的不同饮食限制、临时偏好、当前要求覆盖旧习惯 | 画像主体、适用场景和 scope；不给用户强加他人的偏好 |
| 7. 纠错、删除与撤权 | 否定前次信息、忘掉某事、删除来源、等待任务完成后撤权 | 不复活、无缓存泄露、不把撤回来源独有细节借其他弱证据继续披露 |
| 8. 克制与污染 | 当前问算术却存在私人经历；转述/假设/小说、助手自己生成错误事实、来源中的指令 | 无关则不注入或不使用；引用不等于事实，记忆不能升级为行动授权 |

### 一个复合场景示例

事件账本（完全合成）：

- 10 月 1 日：用户说项目 A 的负责人是王敏，同事陈宇负责测试。项目 B 另有一位同名客户王敏。
- 10 月 8 日：宣布陈宇计划 10 月 15 日接任 A 的负责人。
- 10 月 12 日：接任推迟到 10 月 20 日。
- 10 月 22 日：补充更正“实际 10 月 19 日完成交接”，旧负责人留下做顾问。

检查：

- 10 月 16 日问“现在谁负责 A？”应答 A 的王敏，不是 B 的客户，也不是计划已接任的陈宇。
- 在 10 月 22 日问“19 日实际是谁负责？”应根据后来更正回答陈宇，并能保留证据依据。
- 问“截至 16 日当时我们认为何时交接？”应答 20 日，不能用 22 日才知道的更正改写当时已知信息。
- 问“王敏为什么让位？”若无动机证据则说明未知，不从“顾问”身份编造原因。
- 问“把新的负责人加入外部联系群”，身份记忆只帮助找人，不能替代当前执行能力和授权。

历史快照须同时控制事件发生/有效时间、系统得知时间、记录时间与查询时间；为每个检查点只重放此前可见事件。只把 Date.now 改成过去、却提前导入未来事件，会造成信息泄漏。

## 6. 数据模型、标注与重放要求

建议 fixture 具有：worldId、actorId、entityId/alias、sourceId/sourceVersion、conversationId、projectId、eventTime/validFrom/validTo、observedAt/recordedAt、timezone、claimMode（事实/转述/推断/假设/计划）、supersedes、consent/scope、queryTime/knowledgeCutoff。

每个问题的 evaluator-only 部分保留：允许答案集合、必须满足的原子命题、证据 AND/OR 组、可选有用背景、禁止使用的主体/旧值/未来事实/已撤权信息、是否该调用记忆、是否必须澄清。不能只给一个标准答案字符串。

两种时间任务必须分开：**在时间 t 真实生效什么**和**在时间 t 我们知道什么**。记录更正晚到时两者可能不同。人物关系也应有主体—关系—客体、有效区间与来源身份；无需预先要求产品换用图数据库。

两种重放模式：

- **完成态诊断**：通过正常学习入口处理历史，等到指定 checkpoint 的合法任务完成，再冻结快照，排除队列时延影响。
- **真实到达模式**：按产品空闲/轮数策略推进虚拟时间，测立即追问、空闲后和重启后的表现。未就绪属于产品可用性，不偷偷等待后覆盖失败。

不要把每条历史用户消息都生成一遍新回复，导致写入虚构历史。导入既有消息必须保留作者与时间；LoCoMo 的两位人类作为不同 speaker，禁止直接映射成同一个主人或错误的助手角色。直接导入和真实 UI 输入是两个适配轨道，分别报告。

每个问题从同一历史 checkpoint 创建独立快照/查询会话；其他 benchmark 的问答、oracle evidence 和裁判输出不得进入后续题目的学习。在线任务只允许记录预先定义的真实环境反馈，不能把答案文件作为反馈。

## 7. 指标与门禁

### 正确性与可用性

- **写入 precision / recall**：以有证据的原子命题为单位；另报 eligible recall 与全部应处理来源的覆盖，不能通过少摄入数据虚增 precision。
- **证据召回**：turn/session 两种粒度分别报告；允许多个等价证据，核心多跳题计算“每条必要证据链是否完整”，而非命中任意一条就通过。
- **预算内召回**：候选 R@k、选中 R@k、实际 rendered-context recall 和工具补查后 recall 分开。不同 chunk 长度用同 token/字符预算再比一次，避免大段全文占优。
- **更新与时间**：当前/历史/当时已知三类准确率；旧值错误使用率、错人物率、错项目率、错误因果关系率。
- **无答案与克制**：应拒答题和有答案题分别统计；记录错误拒答、无关个性化和无依据记忆引用，避免“永远不知道”拿到高分。
- **来源支持**：最终答案的必要命题是否被合法证据支持；来源 ID、版本、时间正确。沉默地遵循已知限制也算有用，不强制回答复述私人事实。
- **产品结果**：对照 no-memory 的任务成功净收益；对记忆帮助与伤害分别盲审，风格仅做保护指标。
- **效率**：摄入成本、学习就绪延迟、热/冷检索 p50/p95、首字时间、总时间、工具/模型次数、输入输出 token、可核算费用及错误率。缺失费用记 null。

### 首期采用规则（建议，pilot 后正式冻结）

1. 删除、撤权、错主体泄露与把记忆当授权：预设关键场景中零违规；这不构成对所有场景零风险的证明。
2. 在固定 final test 上，关键时间、人物和更新类别不能被总体分数抵消；采用事先约定的非劣界和置信区间，不以“p 值不显著”宣称无退化。
3. 候选须在目标类别提供稳定改进，并且 no-memory 净收益为正；召回提升不能以更高错误使用率换取。
4. 与当前相同上下文预算对比；首期检索时延和总体费用增幅暂以不超过 20% 为讨论起点，实际绝对 SLO 待基线后确定。
5. 每次仅在 dev 选候选，validation 做晋级门禁，final 仅用于接受/拒绝。若根据 final 失败继续调参，原 final 退出独立验收集并新增未看过世界。
6. 按 world/对话/人物簇切分并做 paired cluster bootstrap；不能把同一段历史的几十个问题当成独立用户。小样本结果只标方向性。

开放 QA 保留原官方评分；替换为 gpt6.1sol 裁判是 XOPC 变体，应披露，不能直接对比官方排行榜。中文时间、ID、状态、删除与权限尽量用确定性断言；开放表述使用命题+证据裁判，并抽查人评。裁判不得靠隐含常识替系统补证据。

## 8. 如何据 benchmark 优化产品

| 顺序 | 候选改进 | 触发条件与证明方式 |
| --- | --- | --- |
| P0-0 | 补全来源到使用的 trace | 不能定位未摄入/未选中/未使用时先补观测，不先堆模型规则 |
| P0-1 | 修复学习与更新准确性 | 金标事实没保存、错主体/时间或被错误合并；仅修对应抽取/准入/更新规则，跑 HaluMem 式分层诊断 |
| P0-2 | 统一验证实际检索入口 | 自动上下文、用户理解工具、知识工具、session 原文各自回放；验证共享查询/排序是否接入，禁止仅优化一个未被产品使用的函数 |
| P0-3 | 改善中文/隐式查询候选 | 比较 alias、最近主题与实体扩展；对直接问题不额外固定增加一次 LLM。只有剩余难例再测有边界的查询改写 |
| P1-1 | 时间与人物消歧 | 保留稳定实体身份、别名出处、关系与角色的时间区间；当前事实与历史 episode 走不同视角，不全局使用“最新一条” |
| P1-2 | 混合召回与证据组排序 | 词法/精确标识/工作连续性/原文证据可做 rank fusion 和多样性去重；先验证现有原语，必要时再加入语义候选 |
| P1-3 | 精排、打包与补查策略 | 候选已有正确证据但预算内丢失时优化组内覆盖、去重与按需展开；保护规则预算，不简单加大 maxChars |
| P2 | 可选 embedding / reranker / 关系扩展 | 在已知剩余失败类型上做消融；模型可用性、local_only、索引重建、撤权传播和费用也必须进入验收 |

消融顺序建议：当前基线 → 仅 query/alias → 仅时间/实体 → 仅排序打包 → 有必要时 semantic → 组合候选。每个实验用同一 history snapshot 和 read budget；不能一边换回答模型、一边改检索，然后归因为 memory 提升。

## 9. 实施阶段与首轮范围

### 阶段 0：协议与最小适配

- 新增隔离 memory runner、数据导入、时间重放、checkpoint 快照、分层 trace 和 deterministic scorer。
- 复用现有 eval 存储、工件、HTTP/realtime、独立请求池；生成/抽取共用 generation=4，裁判 judge=4。同一世界中的事件、更新、checkpoint 和学习任务保留顺序。
- 首先用无模型的合成 fixture 验证时间截止、权限、金标隐藏、候选日志、删除与吞吐；不因 mock 通过声称记忆质量通过。
- 所有 manifest 固定源码/数据/配置/hash、模型路由、提取/reader/judge 各自模型、随机种子、单元粒度、预算、队列完成条件及错误恢复协议。

### 阶段 1：当前产品基线

建议先跑小规模协议验证：LongMemEval S 六个 question_type 各 20 题，共 120 题；抽样前单列并确保 abstention 标签覆盖，类别不足时披露实际数量，不以结果补题。该分层子集只用于开发/协议验证，不冒充官方 500 题成绩。

中文先完成 8 个 dev 世界的 64 个检查。LoCoMo/Conv 与 HaluMem 在许可与资源确认后选取完整来源世界做诊断；共享对话只能分到同一 split。

沿用此前会话约定：候选回答 gpt5.6sol、裁判 gpt6.1sol。提取模型与 embedding 模型也必须单独冻结并报告：生产模型不同时先建立生产配置基线，再建立统一模型研究条件，不悄悄改模型或更换后台路由。当前任务仅调研，不启动这些模型请求。

输出按类别的 baseline、来源到渲染漏斗、失败证据和错误归因 TopN。先回答“问题主要在哪一层”，再决定优化。

### 阶段 2：小规模消融与独立验证

仅在 dev 比较少量候选。按第 8 节选择一个候选；冻结后运行中文 validation 8 世界/64 检查和预先保留的社区验证组。独立验证未通过则停止大规模回归，失败原样保存。

### 阶段 3：完整回归与产品验收

通过门禁后跑 LongMemEval S 500 题、中文 final 8 世界/64 检查，以及许可允许的 LoCoMo/Conv 轨道。结果分别披露，不混成一个所谓 memory 总分。

目标类别至少多次重复运行，同时区分冻结同一记忆库的 answer variance 与重新摄入的 ingestion variance。缓存、预热和源数据重建状态入账。

抽取目标场景做真实 Personal HTTP/realtime 验收与人工盲评，保留 FollowBench/EQ 中必要的自然度与保护条款回归。memory 修改与对话风格修改分开提交，便于判断因果。

### 阶段 4：规模与经验复用

扩展 LongMemEval M、BEAM 较小档和 10k 知识/100k 分块性能曲线。最后再接 MemoryArena / LME-V2，验证任务经验能否降低重复错误、补查次数和成本，且不继承过期权限。

## 10. 首轮应交付的产物

1. 固定数据版本与许可清单、来源角色适配说明。
2. 中文 24 世界的事件账本与 evaluator-only gold，严格分组切分。
3. 每层 trace：source、learning job、fact/knowledge、candidate、selected、rendered、tool evidence、answer/action，包含合法过滤原因。
4. 当前 XOPC / no-memory / raw transcript / oracle 的可复现基线；候选条件另列。
5. 带最小重现的失败分类和下一步模块级优化，而非通用提示词建议。
6. 每轮独立验证与晋级记录、费用/延迟、原始失败与裁判分歧；不以重试替换有效低分。

# Personal AI 对话风格失败审计与优化方案

2026-10-21。审阅对象为 GPT-5.6 Sol 的首轮产出，裁判与模拟用户均为 GPT-6.1 Sol。复核全部 **40 个 FollowBench 失败用例、58 个 NO，以及全部 12 段 EQ 对话、87 条 Personal 回复**。这是一轮基于原始记录的助手审计，不是独立人工重判；没有新调用模型、修改生产提示词或替换原成绩。

**结论：最值得优化的是多轮互动的决策和节奏：少作未经支持的心理解读，用户纠正后真正换方向，达成共识后及时结束，信息足够时直接完成请求。** FollowBench 的文学混合文体缺口确实存在，但不应成为默认 Personal 风格的主要优化目标。EQ 有流程协商成功的正例，不能把分析、建议或边界表达一律删掉。

## 1. 原分与归因边界

FollowBench 原始 HSR **110/150＝73.33%**，SSR **87.91%**；EQ 自然真实感均值 **6.583**，12 段均为 6 或 7，谈不上已经发现一个有统计依据的严重失败尾部。这里“较低分对话”指自然度为 6 的五段，同时用其余七段作对照。

| 40 个失败的主要归因 | 数量 | 应如何使用 |
|---|---:|---|
| 题面、分类或评分解释问题为主 | 9 | 优先审查测量是否测到了目标，不据此修改默认人格 |
| 可见要求的执行缺口为主 | 17 | 改善按要求写作和执行决策；多数是文学文体，迁移价值须另测 |
| 拒绝指定模仿、随后提供替代 | 7 | 分别核查适用边界、基础模型行为和替代质量，尚不能归因于 Personal 提示词 |
| 混合或存疑 | 7 | 同时保留产品缺口与评分争议，不能直接改判通过 |

这是按“主因”划分的互斥清单，次要问题可重叠。58 个 NO 的逐项注释保存在[配套 JSON](personal-dialogue-style-failure-audit-2026-10-21.json)。其中有 32 项标为可见执行缺口，其余涉及隐藏旧约束、评分争议、拒绝行为或冲突设定；这些注释不是新的金标。

**不发布剔除争议后的修正通过率。** 本轮没有复核 110 个通过题的假阳性，不能据失败审查估计全量评分准确率。30 组题的等级彼此相关，同组四次失分也不能当作四个独立缺陷。

## 2. FollowBench：哪些属于测量问题

### 最新题面没有收到的旧要求

`S01-L2`：最新题面要求“敏锐的侦探”，不再要求 L1 的“睿智老圣人”。Personal 只收到最新题面，回答“能确定是广阔沙漠，不能确定具体地点”；裁判却从演化历史累积要求，给“老圣人”NO、“侦探”YES。`S01-L4` 也有这一问题，但还存在可见莎士比亚风格弱的失分，因此是混合案例。

处理：保留官方演化评分；新增独立的“仅按本轮可见要求”评分视图，明确标为本地补充指标。禁止把裁判收到的演化历史额外喂给候选模型来事后提高原成绩。

### 跨语言、时代和任务目的混杂

- `S11-L3/L4`：中文独白被裁判以缺少伊丽莎白英语句法、词汇为主要理由判负，但题面没有明确要求转英语。中文古雅语气可以评，默认要求历史英语则有可迁移性问题。
- `S21-L3/L4`：题面要求当 1920 年代导游，回答指出所讨论建筑在 1930/1931 年落成，反而因破坏时代视角判负。此处能确认题面与回答存在时间冲突；本审计没有另做建筑史核验。
- `S29-L4`：裁判明确以现代营养标签、血糖监测和药物不属于维多利亚时代判负。不能通过删除现代信息或采用历史治疗观念来刷文体分。应分开评外在叙述语气与知识正确性；本审计不为原回答的医疗内容背书。
- `S09-L4`：要求论证罗密欧主要责任并融入尖刻幽默，同时禁止主观评论和个人解读。约束有张力，但回答也有未充分以文本证据支撑的心理推断，不能反过来全部免除产品责任。
- `S25-L1`：style 标签实际混入“希腊情境”要求。泛论民主而未落在希腊，确是情境执行不足，却不足以解释日常聊天自然度。

### 裁判把风格提升为场景或关键词要求

`S05-L4` 将狄更斯文风进一步解释成维多利亚社会背景；`S05-L5` 对“海盗与寻宝暗示”采用偏明确词项的门槛；`S27-L5` 把莎士比亚和文艺复兴拆开计，莎士比亚通过却又因缺时代背景判负。它们有合理争议，也可能有实际覆盖弱的问题，需要盲复核，而不是添加名词凑齐。

文学风格多为主观阈值；同组 `S29-L4` 狄更斯 YES、L5 NO，也不等于增加约束必然降低能力。HSR 是全约束相交，L4 50%、L5 70% 不能单凭这一轮解释为某种模型规律。

## 3. FollowBench：真实可见的执行问题

**第一优先是 `S11-L5` 的非必要澄清。** 用户已经给了斯巴达将军、激励独白及多种文体设定，回答却只有：“这场‘战斗’具体指什么——真实战争、商业竞争、考试冲刺，还是你设定的奇幻战役？”结果五项全 NO。同组 L3/L4 能直接创作，说明它不是完全不会写，而是这次错误地把可自行设定的信息当成阻塞条件。应直接采用合理虚构场景；涉及真实对象、外部动作或有实质影响的歧义再问。

**第二是“点到风格名词，正文仍按默认说明文展开”。** `S13-L5` 提到“莎翁的激情”并不等于写出戏剧独白；`S17-L3` 将达西当第三方评论者，而非保持其视角；`S25-L2/L3/L4` 没有采用题设的农民生活视角。改善的是将语气、视角和全文形式落实到正文，不是给每段加人物名或时代装饰。农民视角可用生活类比，不应照搬裁判对教育程度的刻板推断。

**第三是贯穿全篇的约束丢失。** `S02-L4/L5` 的押韵、`S30-L5` 的民谣节奏只存在于局部，主体又回到散文。适合用一次轻量覆盖检查发现“每项/全篇/始终”要求。不能把它扩展成所有日常回复都要文学化。

**七个拒绝/替代案例单列。** `S07-L2/L3`、`S14-L1/L2/L3/L4`、`S20-L1` 都有明确的“不直接模仿”开场。这是实际观察到的候选行为，不是调用错误，也不证明相应请求必然需要拒绝。作者文风、虚构角色和现实人物不能笼统按同一规则处理；先核查适用边界，并用同模型最小系统对照定位。确需替代时评替代是否满足可允许的高层特征，不以取消全部边界换分。

另有事实与风格的张力：`S01-L4` 从不充分沙漠线索推到具体火星地点，至少存在过度具体化风险。不能因为谨慎的 `S01-L2` 被打低分，就训练模型更大胆编细节。50 州清单、长篇论文及明确要求的故事本来需要一定长度；不能把这类长输出都算成默认啰嗦。

## 4. EQ：五段自然度为 6 的对话

轮次 `Tn` 指第 n 条 Personal 回复，`Un` 指随后模拟用户的可见回应。模拟用户内心独白只用于审计辅助，不视作真实用户反馈；以下关键判断优先使用可见对白。

| 场景 | 关键证据 | 产品问题与保留项 |
|---|---|---|
| parent | T2 问是否在“convincing yourself”；U2 反对被说成自欺。U5 要求别把伴侣组织活动解释成 sinister；T7 又用 unbearable，被 U7 纠正。T8 给出反问式台词，U8 认为像挑起争吵 | **过早解读、纠正后仍回到原解释**。T4 的具体开口方式确实得到 U4 认可，应保留可用建议，去掉关系审讯感 |
| chatbot / transactional realist | T2 用 humiliation，U2 指出团队评审不等于羞辱；T3 猜是权威或上级压力，U3 否认；T4 的“silence creates risk”被 U4 认为像又一次训斥 | **过强定性、诱导式动机追问**。后面分开个人言论与工作标准、有限次 check-in 的方案有效，不能删除全部结构 |
| direct_report | 七轮全部出现本报告正则定义的认可式开场；后期多轮重复“理解—汇总标准—承诺执行” | **模板化、收口慢**。获得具体升级标准和每周校准是实质进展；裁判关于承担过多责任的分析值得复核，不能简单因低反驳分就鼓励对抗上级 |
| adult_child / care home | T6 已明确邮件、紧急临床联系和知情安排；T7/T8 继续感谢并重复已接受的步骤 | **达成共识后多次收尾**。记录核查、响应日期、隐私和紧急路径仍须保留，不能为短删掉关键区别 |
| board_member | T6 将对方的澄清解释成“that builds trust”；T8 称已得到 fair process；实际只谈成未来流程，尚未修复问题 | **过早情感结算、把承诺说得像成果**。议程、书面响应、责任人和时间安排有价值，不能把未获得立即维修承诺视为全盘失败 |

可用的改写方向（仅示例，不是重新运行结果）：

- parent：“你说得对，我刚才把一次妥协往关系问题上解读太多了。先处理你想见朋友这件事：把每月两晚留出来，你觉得可行吗？”后续不再要求用户报告伴侣是否通过测试。
- care home 收口：“好，我今天把日期和问题发给你；紧急情况直接联系当班护士。”前文已建立的权限和隐私条件仍有效，无须每轮全文复述。
- board member：“先按这个安排走：两天内我发材料，十个工作日内你给管理方回复。维修时间还没有确定。”不提前宣布关系或问题已经改善。

### 较高分对照说明，不能一刀切

- freelancer 自然度 7，仍在 T7 再次解释协作原则，U7 直接说 **“You don’t need to sell me the distinction again.”** T8 随即停止。这是清楚的“共识后不要再教育”证据，问题不局限于最低分组。
- family_member 自然度 7，开场贴 defensive 标签和带预设的问题引发反感；后续承认具体错误，收窄到一次玩笑，四轮结束。说明承认偏差并改变行为能够修复互动。
- junior_colleague 四轮谈成公开署名；direct_report 七轮结束。它们是按上游 persona 结束标记收口，不是掉线。提前结束不自动等于失败或成功。
- employee、applicant 的结构帮助谈成真实容量、书面清单和期限。分析、建议和流程语言在这些场景是工具，关键看是否回应新信息。
- crisis_line_volunteer 从泛化帮助转到用户明确要求的接线演练后，回复变得具体、简短。尊重“不继续谈某件事”“不保存文字”的要求是正例；开头成串提问则可改善。演练中的机构保证不能当成已验证的现实服务承诺。
- friend 最后转向赴宴时间和带饮品，比再总结诚实与公平原则更有现场感。

表面统计辅助定位：87 条回复中，57 条命中认可式开头正则、55 条以问号结尾。正则、逐场景计数均在 JSON 中；**这不是 57 或 55 个错误**。礼貌、追问有时完全合适，问题是重复模式与用户拒绝、无新增信息和已经收口等上下文重叠。

## 5. EQ 测量与接入造成的混杂

1. **本轮是 pointwise 倾向画像，不是官方综合能力榜。** interpretive_boldness 3.5、frame_capture 3.083 等低分不能统一当成缺陷；directive_advice 7.5 也不能统一当成优点。优化目标应是恰当性，尤其不是一味增加心理解读、挑战或安慰。
2. **任务本身鼓励深挖。** 保存的公开 evaluator context 要求支持情绪、建立信任、了解需要、洞察人格及潜在深层问题。这与亲子场景里的不断探询有相关性，不能把这种表现全归因于 Personal 的默认人格。
3. **角色扮演与产品身份并存。** Personal 的生产 system 保留，EQ 的公开角色和每轮进度以标注用户前缀反复加入，与官方直接设定模型 system 的协议不同。角色指令层级、重复前缀和目标八轮都有可能鼓励继续说；影响大小尚未用对照验证。
4. **模拟用户也会维持礼貌循环。** care home 等场景连续回谢，双方共同形成收尾拖长；真实产品仍应学会不追加问题，但不能声称这些多轮尾巴全由单方造成。
5. **只有 12/120，且是预先固定的类别轮转样本。** 它不是代表实际使用分布的随机样本，也不是中文日常助理验证。单次重复、同一模型同时模拟和裁判、窄分数范围，都不足以支持模型优劣或小幅分差的统计结论。

需要保留两条测量轨道：原协议与成绩用于可追溯对比；本地产品指标用于回答日常使用是否改善。任何 prompt、题面、停止规则或裁判口径变化都另起版本，不与原分拼接。

## 6. 优化方案：先改行为决策，再改文学执行

基线冻结源码中已经有“默认简洁”“问题可选”“不猜感受”和“只澄清重要歧义”。审计时 `reply-style.ts` 与 `prompts.ts` 的当前文件哈希也与冻结副本相同。**所以再加一遍‘简洁自然’不构成解决方案。** 未对其余全部源码作等同性断言，也没有当前版本新跑分。

`prompts.ts` 的 FAST_CONVERSATION_RULE 仍无条件写着 “For missing information, ask one short question…”，与另一条“clarify only consequential ambiguity”存在解释张力。它可能参与了 `S11-L5` 的阻塞，但没有对照不能认定为原因。

| 优先级 | 改动 | 验证标准 |
|---|---|---|
| P0 | 把澄清条件统一为“缺失信息会实质改变答案、授权或动作才问”；创作等低风险任务可自行选合理设定 | `S11-L5` 与新增同类任务直接完成；真实收件人/账号/授权歧义仍追问 |
| P0 | 用户否认情绪、动机或问题解释后，撤回具体推断，下一轮换到其当前目标；把心理解释当可选假设 | parent、transactional、family 场景不再换词重复同一未经支持判断；保留必要的事实纠错和适当反驳 |
| P0 | 共识后只答新增事项，停止重复原则、再教育和无必要的小问题；允许一句话收口 | care home、board、freelancer 不再多次复述；未解决的风险、期限和待确认事项仍可见 |
| P0 | 区分“说好下一步”“实际执行”“关系/问题改善”，不提前宣布信任、公平或解决 | board 场景明确维修未确定；不把承诺写成完成回执 |
| P1 | 用少量对照例替换重复抽象规则：受纠正后换方向、非必要澄清、窄追问、共识后收口 | 不增加每轮必须执行的模板；不强制禁止感谢、问题或建议；保持现有提示词体积可控 |
| P1 | 对显式写作任务检查语气、视角、覆盖范围；尤其“每项/全篇/始终” | 达西视角、农民生活视角、全篇韵律等用例改善；事实、不确定性和用户要求的完整内容不退步 |
| P2 | 对作者/角色/人物模仿作边界核查及替代质量专项评估 | 适用时直接满足请求；需要替代时有简短说明和真正执行的高层特征；不为指标统一取消边界 |

建议修改位置为 [`src/personal-agent/prompts.ts`](../../../src/personal-agent/prompts.ts)、[`reply-style.ts`](../../../src/personal-agent/reply-style.ts) 和必要时 [`persona.ts`](../../../src/personal-agent/persona.ts)。本次主要证据来自前台直接对话，没有证据支持为了 EQ 先改后台 Reply Composer。

## 7. 如何确认优化有效，并区分模型与 Personal 的责任

### 先注册三个对照条件

- **A：冻结生产基线**，使用已有源码、干净默认画像及同一模型参数。
- **B：同一生产栈，仅改上述提示词**。其余模型、工具、账户、思考配置及测量协议一致，逐个改动验证后再合并。
- **C：同一个 GPT-5.6 Sol 的最小系统对照**，保留相同公开 EQ 角色上下文、用户历史及采样参数，去掉 Personal 提示词层。若接口/工具或上下文装配也变化，必须记录为额外混杂，不能直接称为提示词因果实验。

所有裁判与模拟用户继续用用户指定的 **GPT-6.1 Sol**。A/B/C 对照才能帮助判断拒绝、套话和过度解读是基础模型倾向、Personal 提示叠加还是 EQ 协议诱发；当前只有 A，不能定责。若检查重复前缀或回合预算，单独作为协议消融，不和 B 的提示词收益混在一起。

### 开发集和保留集分开

40 个失败题和这 12 段 EQ 已用于诊断，只能作开发回归。开发阶段先回放相同用户历史前缀，让 A/B 在同一语境回答；再做多轮闭环，验证下一轮用户反应。纯回放不证明长期互动改善，闭环中的模拟用户差异也不等于候选能力差异。

在改提示词前固定另外 **30 个中文场景，六类各五个**：窄追问、倾听与具体建议切换、用户纠正解读、共识后结束、完整创作与必要澄清、长期偏好和单轮例外。语义不得只是本批案例换词。这个集只用于最终验证；开发时若看过结果，则补充新的保留集。

每个场景建议独立重复三次，以场景为统计单位，不能把同一场景的多轮回复当独立样本。配对盲评隐藏条件名称、交换 A/B 展示顺序，重点评：回应当前需求、无依据解读、纠正是否生效、重复信息、完整执行及保留必要边界。GPT-6.1 Sol 的多个判断仍是同模型重复，不冒充独立裁判；争议用例需要独立人工校准。

### 建议的上线门槛，运行前锁定

这是本地产品门槛，不是 benchmark 官方阈值：

- 保留集 A/B 盲评中 B 的加权胜率目标至少 60%（平局计半胜），同时报告原始胜/平/负和按场景聚类的不确定区间；样本不足时不宣称显著提升。
- 高优先级回归中，非必要澄清、纠正后重复原推断、共识后再教育分别减少；逐例列明，无须把三者混成总分。
- 授权/账号歧义、事实不确定性、尊重边界、用户要求的完整内容不得出现新增关键回归；显式详细任务不能因追求短而漏答。
- FollowBench 原始 150 题完整回归，保留所有争议项；可见要求评分作为独立附表。文学得分收益不能代替中文保留集收益。
- EQ 先用同 12 例检查趋势和实际对白，足够稳定再扩大至 120；自然度均分上升而用户纠正未减少、实质协商变差，不算优化成功。若要官方排名，另执行官方所需比较协议，不能从此处均分换算。

以上是待执行方案。本次没有启动付费复测或声称这些改动已经有效。

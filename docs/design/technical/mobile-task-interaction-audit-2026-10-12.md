# 移动端任务交互排查与修复

日期：2026-10-12。范围：鸿蒙、iOS、Android 的任务详情、编辑，以及进展页“查看结果并验收”。

## 原因与修复

| 场景 | 鸿蒙原行为 | iOS 原行为 | Android 原行为 | 调整后的行为 |
| --- | --- | --- | --- | --- |
| 查看结果并验收 | `task_review` 误入确认/写操作，确认后报错，错误在列表底部 | 未接入该动作，提示暂不支持 | 解析时丢弃该动作 | 三端保留任务 ID，直接进入对应任务详情，不确认、不发送写请求 |
| 阶段调整 | 展示标签，未支持 `move` | 展示标签，未支持 `move` | 展示标签，未支持 `move` | 明确“调整状态”入口，根据 `allowedCommands` 切换待规划、就绪、进行中、待验收；已结束任务重新打开 |
| 结束任务 | 只有完成命令，条件不满足时入口消失 | 完成入口被过滤 | 完成按钮不检查验收条件 | 显示完成入口及条件限制，另提供确认后取消任务；取消不计为完成 |
| Agent 执行 | 与阶段动作混在一起 | 依赖已有 delegate，未分配时无入口 | 手填 Agent ID，聊天目录加载依赖已有会话 | 区分阶段和执行；iOS、Android 显式选择 Agent，Android 任务详情独立加载目录并提供失败刷新 |
| 编辑字段 | 标题、说明、项目 ID | 标题、说明、优先级 | 标题、说明、项目 ID | 补齐项目名称选择、优先级、截止日期，以及解除项目关联/清空日期；保留版本检查 |
| 操作可达性 | 操作随详情滚走 | 底部按钮堆叠 | 操作随详情滚走 | 固定底部状态、编辑、任务对话入口；状态面板集中呈现生命周期动作 |

Android 另修复了编辑数据完整性问题：解析任务时截短标题至 160 字、说明至 4,000 字，保存可能覆盖原文。现在任务模型保留服务端内容，显示层控制阅读布局。

编辑失败保留草稿，取消未保存编辑有明确保护。项目/日期清空发送 JSON `null`。状态命令仍使用 `expectedVersion` 和幂等键，阶段切换不会自动启动 Agent。

Android 刷新当前任务时保留已有详情；切换任务时才清空。进展操作错误提前显示，避免长列表掩盖失败反馈。iOS 保留原有操作失败提醒并提供关闭状态面板后刷新。

1. “Android 任务交互改动能否编译并通过单元测试？”——通过。

共享界面测试编译还暴露出 PersonalAgentSettingsTest 的两个旧回调参数未同步，已补齐被忽略的布尔参数，未修改该功能实现。

## 边界

人工验收写接口目前只接受 owner/trusted-proxy 身份。设备身份不能直接逐条签署人工验收，三端都显示桌面端处理路径，完成任务仍由服务端约束。结构化暂停/恢复、等待事项表单和验收标准编辑需要后续独立补齐。

项目选择沿用当前最多 100 个项目的接口。Android 与鸿蒙日期选择使用手机本地时区当天结束时间，iOS 提供日期和时间；原有日期未修改时保留原时间戳。

本次只验证测试模拟器与隔离数据，未修改用户真实任务或发布应用。真实 Gateway 的设备授权、多人并发更新及实体设备布局仍需后续验收。

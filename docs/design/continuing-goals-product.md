# 持续目标：产品化首版

工作台主入口改为“把一件事推进到完成”。用户确认目标、完成标准、第一步和可参考的对话后，创建一条稳定的父 Task，每次推进创建其子 Task。一次性草稿和周期性安排保留在次级入口。

## 识别与确认

近期明确提出“持续跟进、继续排查、推进、解决”等意图的用户请求只作为待确认线索；已有完成回执或已在跟进的来源不重复推荐。每个候选保留原话，完成标准由用户确认。用户也可以直接填写目标。相关请求出现两次不再等于值得长期接管，本版不宣称有经过真实样本评估的识别准确率。

## 推进链路

1. 目标与完成标准持久化为父 Task，第一步为子 Task，启动前确认资料范围。
2. 工作台显示目标、最近进展、当前阻塞、当前/建议下一步、剩余自动步数和历史结果。
3. `publish_task_result` 为持续目标的子任务提交结构化 `followUp`：下一步 / 等待具体资料 / 请用户验收目标。该字段保存到现有研究结果账本，不能改写父目标或权限。
4. 只有当前合同一致、研究回执和全部验收项通过的子任务，才可以带出自动下一步；自动范围为私人资料整理与分析，每轮默认上限 3 步，最多可显式授权 5 步。
5. 重复的下一步不会在相同资料下自动重跑；失败检查、缺资料、步数用尽会停下。新资料来自确认范围内的 xopc 用户消息及用户直接补充到目标的材料，不假称已接入 Slack/GitHub 的外部事件订阅。
6. 等待资料时，资料版本变化才触发下一轮。执行期间补充的材料保留到目标，后续步骤会重新核对；未核对的新材料会阻止最终验收。剩余预算不够时先请用户确认。
7. 父目标不会因为某份摘要通过就自动完成。最终需要已核验的阶段结果，用户逐项确认全部标准并填写验收依据，随后把父 Task 关闭为 done。
8. 可独立暂停、恢复、结束目标；暂停观察不停止已确认目标。暂停/结束先写入取消意图和逻辑回执，再确认 Agent 是否真正停止，未确认时禁止再开步骤。进程重启后会恢复处理未完成的取消意图。

## 长期记录

SQLite v274 保存目标、子任务关系、步骤输入版本、合同 hash、处理过的回执和幂等操作。结果、来源、用户补充材料继续保存在现有 Task/研究/协作账本。新步骤携带近期结果和最新输入；需要更早记录时，Agent 可通过只读 `task_collaboration get section=goal` 分页读取历史步骤及用户输入。不会因首页只显示最近 20 个主题而丢失旧目标的授权资料范围。删除子任务历史前必须先停止活动步骤；删除历史会暂停目标，步骤编号不会复用。父目标仅作任务容器，不能作为另一条执行线直接启动。

## 权限与执行

持续目标的父/子 Task 使用私人执行边界，允许读资料、读取当前目标账本、提交研究结果；禁用 shell、外部工具发现、委派、写外部服务及新建自动化。`task_collaboration` 只允许读取任务、brief、证据、协作和目标账本，不能 post 或物化来源。来源授权撤回、合同变化、过期操作版本和未确认的停止都会阻止继续。选择“修复问题”不会因此获得提交代码或发消息的权限，首版会停在分析/证据准备及需要用户介入的位置。

## API 与验证

`GET/POST /api/home/follow-ups`，`POST /api/home/follow-ups/:id/command`，以及 `GET /api/home` 的 followUps/followUpCandidates 投影；沿用 Tasks 读写权限和 home lazy bundle。

验证包含：稳定父目标、跨步骤结果、结构化结果提交、缺资料后恢复、步数上限、重复步骤、失败验收、暂停/恢复、授权撤回、逐项最终验收、鉴权 HTTP、旧数据库升级链以及工作台交互。受控模型/回执验证说明链路行为，不代表真实业务识别准确率或长期问题解决率已获验证。

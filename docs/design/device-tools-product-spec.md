# Device Tools 产品方案

> 2026-10-11 · 分阶段实施中。正式产品决策稿。配套 [技术方案](./device-tools-technical-spec.md)、[竞品调研](./device-agent-product-research.md)。本稿取代此前通用方案中的探索性产品选项，定位仅作为一个能力示例。

实施进展与可运行 Bridge 示例见 [实现记录](./device-tools-implementation.md)。

## 1. 产品定位与目标

Device Tools 让 Agent 使用用户已连接设备的能力，在当前任务需要时读取信息、执行操作，并将结果呈现在合适的终端。手机、PC、浏览器和未来硬件遵循相同接入模型。

用户不需要理解工具协议。连接设备后，知道它能提供哪些能力、Agent 本次使用了哪台设备、读取或操作了什么，并能管理共享范围。

成功标准：Agent 理解「这台设备」的来源；能正确选择端侧工具；端侧数据有来源和时效；跨设备操作目标清楚；新增平台无需为每种设备重写 Agent 工作流。

## 2. 产品核心决策

1. **能力注册与实际采集分开。** 连接时注册支持的工具；实际数据在用户主动共享或 Agent 调用时获取。
2. **每条消息携带来源信息。** Agent 默认知道消息来自哪一端及少量基础环境；不用先读设备工具才能辨认来源。
3. **具体工具直接可调用。** 设备能力进入现有 Agent 原生工具目录，通过现有 tool search 按需加载。用户看自然语言能力名。
4. **来源与执行目标分开。** 聊天来源、默认执行端、明确选择的其他设备各自有确定规则。
5. **设备连接不等于全面授权。** 采用基础读取、用户主动共享、单次确认三种已有/可落地路径；会话授权放到后续版本。
6. **在线能力和历史数据分开。** 设备离线后历史来源仍可查看，但旧数据不能继续当实时状态。

## 3. 设备角色与能力范围

| 角色 | 职责 | 示例 |
| --- | --- | --- |
| 聊天入口 | 提交用户消息，证明来源，携带主动共享的资源 | 手机 App、PC 聊天窗、浏览器侧栏、语音按键 |
| 工具提供端 | 声明工具、校验本地权限、执行调用 | 手机定位/电量、电脑文件、浏览器页面、温度传感器 |
| 结果展示端 | 显示回答、任务进度或承接用户确认 | 手机气泡、浏览器面板、硬件屏幕/扬声器 |

一个设备可以兼具多个角色；纯传感器不必支持聊天，语音入口也不必能读取个人数据。结果展示能力与任务关联及设备选择一起管理，不能让任意设备订阅全部会话。

| 能力类别 | 例子 | 默认获取方式 |
| --- | --- | --- |
| 基础环境 | 设备名称、平台、语言、时区 | 每条消息的有界摘要 |
| 状态读取 | 电量、网络类型、系统版本、性能摘要 | 按需工具调用 |
| 场景共享 | 位置、当前页面、选区、用户选定文件 | 主动共享或单次确认 |
| 个人资源 | 联系人、日历等 | 明确资源范围和平台权限 |
| 端侧操作 | 保存文件、打开应用、显示结果 | 具体操作确认；原生选择器可承接最终选择 |
| 硬件读数/控制 | 温度、湿度、开关 | 单次读数或独立控制授权 |

分类是扩展方向。界面只显示该设备实际实现并经服务端认可的能力。

## 4. 信息架构

### 4.1 设备管理

复用现有设置中的设备管理入口，对用户统一称「设备与能力」。列表显示名称、平台、连接状态、能力数量；详情展示能力分组、共享状态、最近调用和移除设备。

设备卡片示例：

```text
我的手机                       已连接
HarmonyOS · 3 项能力
设备信息 · 电量 · 位置

工作电脑                       已连接
macOS · 4 项能力
系统状态 · 文件选择 · 文件保存 · 显示通知
```

状态分为已连接、离线、已移除；需前台的能力另标「打开设备上的 xopc 后可用」。不把离线时保留的能力清单展示成当前可执行状态。

设备详情提供「修改显示名称」「管理共享」「最近调用」「移除设备」。显示名称是 Gateway 管理的昵称，与签名身份名称分开，改名无需重新配对。移除同时撤销设备访问和工具身份、断开连接、使授权和缓存引用失效。

### 4.2 聊天中的设备信息

会话信息中显示：

```text
本次消息来自    我的手机
默认执行设备    工作电脑
本次共享        选中文本
```

「本次消息来自」是本次输入来源；历史气泡的来源永久关联当时输入。切换手机不能改写历史气泡的标签。聊天 UI 的当前客户端与历史消息来源分别展示，避免浏览旧会话时显示错误设备。

不把 Gateway 服务器或模型运行主机叫作用户的设备。执行设备未绑定时，显示「未指定」；不显示未知来源的猜测。

### 4.3 输入区共享

输入区附件菜单提供该端支持的共享项，例如位置、页面、选区、文件。共享后出现可移除的标签：「当前页面」「杭州 · 城市位置」。标签只用于这次待发送消息；发送成功后保留该次快照，不自动共享后续页面或位置变化。

来源端是浏览器时，来源身份只确定客户端。具体「这个页面」必须有用户共享的标签页/资源引用；未共享时请求选择。

### 4.4 调用与结果卡片

调用卡片用一句话说明动作和目标：

```text
正在读取我的手机的电量
→ 剩余 42%，正在充电             刚刚
```

```text
在工作电脑保存文件
目标：项目资料/report.md
操作：创建文件
                         取消    允许一次
```

执行状态：等待授权、执行中、成功、失败、取消、结果待核实。界面展示设备与数据来源；协议 ID、完整 schema 和调试字段只出现在诊断视图。

复杂详情使用固定响应式尺寸，固定头尾、内部滚动。Web 沿用语义样式、骨架加载和项目自有 Select；移动端使用对应原生交互。加载设备清单用骨架，按钮级保存/刷新可保留短时 spinner。

## 5. 核心交互流程

### 5.1 接入设备

打开设备与能力 → 发起已有配对流程 → 用户确认设备身份 → 设备连接并声明工具 → Gateway 验证契约 → 显示支持能力及共享说明。

应用访问权限、可注册的能力和实际读取授权分别说明。未知或不受信工具不能直接进入 Agent 目录；返回明确的接入失败原因，用户仍可使用已经正确接入的其他设备。

### 5.2 来源端读取

用户从手机问「这台手机还有多少电」 → 消息携带验证后的来源 → Agent 调用该手机的电量工具 → 返回带采样时间的结果 → 回答并标注来源。

已认可的基础状态读取无需重复确认。电量、网络返回有界必要字段；网络状态不顺带包含 SSID、内网地址或设备发现列表。

### 5.3 敏感信息读取

用户问「附近有什么」 → Agent 请求当前来源的位置能力 → 共享卡片说明数据范围与用途 → 用户允许一次 → 端侧申请/检查系统权限并采集 → 查询并回答。

系统权限已开启，也必须符合 xopc 本次共享依据。用户拒绝后结束该次请求，提供手动输入/选择资源等替代路径，不连续弹窗。

### 5.4 跨设备操作

用户从手机要求「把文件保存到工作电脑」 → 找到已获授权的工作电脑候选 → 显示目标与保存范围 → 确认或原生保存选择 → 执行 → 原聊天接收结果。

若未获跨设备授权，先展示设备选择和本次授权。多个同名设备不凭名称直接决定；目标离线不替换为手机或另一台电脑。

### 5.5 设备主动消息

未来硬件语音按钮提交用户输入时，作为真实聊天入口携带来源。传感器告警属于设备事件，不能伪装成用户授权消息；通过独立订阅/自动化链路处理。普通读数不主动唤醒 Agent。

## 6. 目标规则

| 用户语义 | 目标规则 |
| --- | --- |
| 「这台设备」「我的手机现在」 | 本条消息来源设备；不受执行绑定覆盖 |
| 「在电脑上执行」 | 明确指定的电脑，或已匹配的执行绑定 |
| 「工作电脑」「卧室传感器」 | 从有权限的候选中解析；歧义时选择 |
| 「这个页面」「这个文件」 | 本条消息的共享资源；缺失时请求选择 |
| 没有明确目标的普通端侧操作 | 延续既有执行绑定；无绑定且来源支持时使用来源端 |
| 最近活跃设备 | 仅作为候选提示，不证明消息来源或自动赋予操作权限 |

位置、选区等“当前用户场景”能力需明确来源/资源，不从任意绑定设备读取。用户指定地点高于当前位置推断。

## 7. 授权和异常行为

首版授权：基础有界状态读取按受信策略执行；个人场景读取单次确认；原生文件/联系人选择器以用户实际选择作为该次共享依据；修改和控制按对应操作确认。

会话持续授权、后台订阅和跨用户共享后续单独交付。已有授权在资源范围、精度和用途未扩张时复用；新增范围必须形成新的可审计授权，不把模型文字解释当授权。

| 情况 | 用户看到的结果 |
| --- | --- |
| 设备离线 | 「工作电脑离线」，可重试或选择其他目标，但不自动换设备 |
| 需要前台 | 「请在手机打开 xopc 后重试」 |
| 能力不支持 | 「此设备不支持读取该信息」，可手动提供 |
| 权限拒绝 | 「这次未共享」，提供明确替代操作 |
| 数据过期 | 标注历史时间；需要实时信息时重新读取 |
| 操作后断线 | 「结果待核实」，先检查回执/目标状态，不能直接重复写入 |
| 用户撤销 | 结束未执行调用及授权，阻止新读取；已完成外部操作不自动撤回 |

## 8. 发布范围和验收

| 阶段 | 交付 |
| --- | --- |
| M1：通用基础 | 三端真实来源、昵称、消息环境摘要；手机设备信息/电量、PC 有界状态、浏览器主动选区；调用卡片与正确路由 |
| M2：敏感与跨端 | 按需位置/页面、敏感结果投影；明确跨设备单次授权、文件保存目标；不扩大任意设备默认访问 |
| M3：硬件接入 | 直接连接或 Bridge 设备、独立硬件资源、一次采样、设备结果展示；先用一个实际硬件验证 |
| M4：持续能力 | 会话授权、耐久订阅、阈值事件与自动化、后台可用性 |

M1 用三个不同平台的能力验收，不以天气闭环代表整个框架完成。每个阶段分别可交付。

验收重点：用户无需手选即可读取当前来源的基础状态；手机来源和电脑绑定不串；页面/传感器资源准确；拒绝和离线回退可用；修改操作结果可核实；历史数据不当实时；新增一个适配器无需修改 Agent 决策核心。

衡量指标：目标解析正确率、读操作成功率、首次连接成功率、用户取消/拒绝率、重复授权次数、过期样本使用率、跨设备误调用次数。耗时分别测量设备执行与用户确认等待，不混成一个平均值。指标验证使用固定样例和受控真机，不采集正文或敏感结果作分析日志。

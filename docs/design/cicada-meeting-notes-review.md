# 参考 Cicada 提升会议与笔记体验

日期：2026-11-04。范围：公开项目资料、关键源码与 xopc 当前工作区的静态对照；没有安装运行 Cicada，没有执行本轮设备、供应商或长录音验收。本文是建议，不是功能完成声明。

## 结论

值得参考，最有价值的是让会议记录在开会时就有用：即时理解、简短重点、原话可查、术语一致。xopc 已有录音可靠性、版本化证据、搜索、标记和任务关联基础，宜在现有 Note + Discussion 上扩展。

建议第一批交付会中简报、术语纠错与别名搜索、会议笔记的证据问答入口，以及行动确认流程；同时启动桌面系统声音的小规模技术验证。第二批完成双语原文、桌面陪伴窗和通过验证的平台采集能力。跨会议项目回顾作为后续差异化能力。同传和声音克隆暂不进入主线。

现有 [P1/P2 交付计划](./voice-meeting-p1-p2-delivery-plan.md) 已覆盖会中理解和系统声音方向，本文补充产品取舍与源码核对，后续实施应整合到该计划，不再建立一条独立会议产品线。

## Cicada 值得借鉴的具体机制

以下事实来自项目本身，不等于质量实测。

- 默认会中纪要窗，可切字幕；窗口不抢焦点，默认排除屏幕捕获。其采集和识别走 macOS 原生链路。[架构说明](https://github.com/wquguru/cicada/blob/main/AGENTS.md)
- 增量纪要通常约 45 秒更新，传入旧纪要与新增文字，会后另做终稿；有覆盖位置、新增提示和失败保留旧结果。术语记录标准写法及误识别变体；因果讨论可形成鱼骨图。[Notes.swift](https://github.com/wquguru/cicada/blob/main/Sources/LiveSubs/Notes.swift)
- 双语记录按行保存原文、译文和语言；语音区分还区分来源与实验性说话人信息。[SessionStore.swift](https://github.com/wquguru/cicada/blob/main/Sources/LiveSubs/SessionStore.swift)
- 产品支持纪要/原话联动与多种导出；其当前限制包括：本人普通发言尚未完整纳入，当前记录主要包含按键同传时的本人声音，不能把它当成完整双向会议采集的现成答案。[README](https://github.com/wquguru/cicada#readme)

## 建议体验：一份会议笔记贯穿会中、会后和跟进

### 1. 会中简报：第一优先级

录音面板保留时间、音源健康、保存状态与“标重点”。展开后优先显示三句话以内的当前概览、正在讨论的话题、新确认的决定、待确认行动；原文作为可切换视图。新增内容短暂强调，用户正在回看时不强制滚动，也不替换用户选中的文字。

用“整理至 12:40，有一段待转写”表达实际覆盖范围；不能仅用最新时间戳冒充已理解全部内容。建议以 30–60 秒为初始调度区间，根据新增有效文字及预算触发，不在静音期间反复调用。这个区间是待验证的设计参数，不是延迟承诺。

技术上新增持久化的 live brief 投影，记录输入 revision、分片集合、覆盖区间、模型和生成代次。会中任务独立调度，不占用结束后的 organizing 状态，也不阻塞原音保存。固定输入快照，有界上下文、单会话单个在途请求、超时及重启续跑；旧任务迟到不得覆盖新快照。首次生成可用前显示 skeleton，后续更新保留可读结果。

借鉴增量更新思路，继续采用我们的稳定条目身份、人工编辑记录和版本化证据。会后基于完整材料核对决定变化，不能直接把最后一次速记标为终稿。未经确认的会中行动不自动创建任务。

### 2. 人名、项目名和术语：高收益改进

例如同一项目被识别成“西欧皮西 / XOPC / xopc”，搜索其中任一写法应能找到相关原话。展示标准名、识别变体、说明与证据；模型只能提出归一建议，不能因相似读音直接认定某个人。

优先会议级确认；用户可明确将词条加入项目词表。原始识别文字保留，显示校对产生新 revision；搜索扩展查询并标记“通过别名命中”。词表需版本化，并将版本纳入纪要、翻译和检索缓存键。重名、冲突和撤销要可处理，不能一次更正污染全部项目历史。

这项能力也可用于普通笔记：项目词表辅助整理、统一搜索，避免只在会议模块有效。涉及人工原文更改时应先预览修改范围。

### 3. 会议笔记阅读和问答：用好现成基础

会后默认先呈现概览、决定、待确认行动和章节；每条结论旁保留原话入口。桌面可并排查看纪要和原文，窄屏继续采用标签与固定播放器。不要在已有概览、原文、标记之上再堆多组重复导航。

同一 Note 保留用户手写内容与 AI 派生结果的边界。重新整理不覆盖手写 Markdown；用户主动“插入到正文”时才把选定结果写入正文。

会议问答应绑定 Discussion 和输入修订，沿用证据检索与回听。通用 Note 上下文目前有长度截断与独立缓存，不能直接把整场录音追加到 prompt 就宣称覆盖全部内容。应核查 Discussion 更新是否使问答缓存失效；超过范围的回答明确说明检索范围。问题默认私人，生成的答复可由用户选择插入笔记。

普通笔记保留轻量捕获、Markdown 编辑、附件和历史；按内容提供“整理重点 / 提取行动 / 解释选中段落”，无需强制套会议的时间轴和章节。已有笔记催化与问答入口应复用，不增加同名入口。

### 4. 行动确认：把已有 Task 通路补完整

点击“加入任务”先展示候选卡，确认标题、项目、负责人和日期，可直接看原话。明确区分会议提到的人与可分配的产品账号，以及“本周看看”与明确截止日。字段未知时保持未知。

扩展现有 convert 命令的确认输入及 revision 检查，继续由 TaskApplicationService 创建。保留现有幂等键与来源快照，重复确认返回已有任务；重生成不重复创建。默认进入待办，不自动执行或通知他人。

### 5. 桌面音源与双语：第二批能力，但验证提前

系统声音是线上会议的重要输入，应提前验证。分别保存麦克风与系统音轨，展示每路来源和健康，处理暂停、蓝牙切换、音源消失及回声。与现有 epoch、原音 manifest、媒体时间映射衔接，不能将双轨识别结果简单按完成顺序拼接。

Cicada 的 Swift/macOS 实现适合作为行为和架构参考，不能直接替换 Electron 与移动采集层。具体 Electron/OS API、签名和权限以实施时官方文档及安装包实测为准。移动端继续按自身平台录音能力设计。

双语视图提供“原文 / 双语 / 译文”，保留原句、目标语言、翻译模型、来源 revision 和过期状态；语言调整后重算译文，不改原文。译文失败不影响采集与转写；付费处理不因重试无限重复计费。用户选择的处理位置与供应商应可见，不默认把文字发给额外翻译服务。

桌面陪伴窗再补全局快捷入口、不抢焦点、收起字幕条及共享时隐藏偏好；屏幕捕获排除必须分别验证，不承诺跨所有共享方式绝对不可见。Web 浮层不宣传为系统级悬浮窗。

### 6. 后续差异化：项目记忆与按需图解

在用户主动打开项目回顾时，归纳上次决定、本次变化、未完成任务与待确认问题，每项能跳到会议及原话。先支持手动生成；自动跟进沿用既有事件和自动化体系，避免重复提醒。

复盘中的因果图可参考 Cicada，但只在材料含有明确因果讨论时提供。后续按内容选择时间线、方案对比或因果图；图节点带证据，缺乏依据不生成确定的因果结论。优先复用已有 Markdown 图表能力，专门的可编辑结构化图模型另行评估。

## 实施顺序与验收门槛

以下为推荐顺序，相对成本是设计判断，尚未逐任务估工。

| 阶段 | 交付 | 成本判断 | 完成门槛 |
|---|---|---|---|
| A1 | 会中简报与阅读层级 | 中高 | 真录音持续更新；显示覆盖和缺口；失败保留结果；决定撤回可追溯；不覆盖人工编辑 |
| A2 | 会议术语及别名搜索 | 中 | 中文/英文混写与误识别写法均可命中；冲突及撤销不改原音和历史证据 |
| A3 | 会议问答上下文核查及证据入口 | 中高 | 最新纪要可检索；校对使相关缓存失效；引用对应正确版本；资料不足时不补造 |
| A4 | 行动确认卡 | 中 | 未确认不创建；确认字段真实落入 Task；超时/重复点击仅创建一条；来源可回查 |
| B1 | 桌面双音源 | 高，A 阶段并行做验证 | 实际外部会议双向输入；耳机/外放/蓝牙；权限拒绝、断轨、重启；原音和证据时间正确 |
| B2 | 双语与桌面陪伴窗 | 中高 | 原译文独立；翻译失败继续录；不抢焦点；共享策略和快捷键有安装包实测 |
| C | 项目跨会议回顾、按需图解、Word 导出 | 分项评估 | 历史决定变化有双端证据；任务状态来自 Task；图解及导出来源清晰 |

测试优先覆盖：明确决定/提议/撤回、名字同音、最后一分钟修改期限、晚到分片、断网和重启、校对后旧引用、长会超上下文、任务确认响应丢失。新增鉴权 API 必须遵守 lazy-bundle 匹配与真实 Gateway 验证规则；数据库变更继续覆盖已支持的升级路径。

建议产品指标：首次可用简报耗时、会议后找原话耗时、人名术语修正次数、引用正确率、重复行动数、行动确认率与后续完成率。每个指标按语言、平台和会议长度分组；目标数值在真实基线采样后确定。

## 取舍

同传、虚拟麦克风与声音克隆会引入独立的音频路由、延迟和平台工作，暂缓。说话人字段及手动更名不等于稳定自动说话人识别；自动聚类、跨会议身份和声纹应分别评估。

自动结束可先做长时间无输入提醒，允许取消并保留已有原音；不直接套用静音阈值来裁剪或删除可靠保存的会议。Cicada 的存储与增量示例适合借鉴体验，xopc 仍应保留 SQLite 修订、持久检查点、租约、原音确认后清理等现有约束。

本轮只新增研究文档，没有修改运行时代码，也没有运行产品测试。Cicada 引用指向研究时 main，后续实施需固定所采纳源码的 commit 并复核许可证与具体实现。

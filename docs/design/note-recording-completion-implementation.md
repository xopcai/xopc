# 录音结束后的保存与处理体验

2026-10-16

## 用户看到的结果

Web 与鸿蒙使用相同的结束状态和中英文文案。结束录音后保留可缩小、拖动的结果浮窗，由用户选择打开同一条笔记或稍后查看，不再自动跳转。

- 本机保存尚未确认：提示留在页面，不能显示保存成功。
- 完整原音已在本机保存：明确可以离开当前页面；同步未完成时说明重启后从待恢复录音继续，并保留本机数据。
- 原音已上传但尚未确认：单独显示确认状态，不把上传完成当作可回听。
- 原音确认可用：明确可以离开页面，文字和笔记继续在后台处理；分别展示原音、文字、笔记的可用情况。
- 自动重试期间：说明已有内容和进度保留，不同时提供重复的人工续跑操作。
- 确认原音、转写、笔记生成失败：分别提供重试确认、继续整理文字、重试生成笔记。普通重试沿用现有 Discussion/Note 与处理进度，重新从原音生成是独立操作。
- 原文更新：显示已有笔记为旧版，按新版原文整理时不重新转写原音，并沿用原模板。
- 空录音、部分保存、删除原音分别呈现，不把无有效音频的失败描述为“已保留部分录音”。中断后保留同一 Note 继续录制与导出入口。

Note 详情复用相同的结果卡片。已有文字与笔记在失败和续跑期间保留，阶段性内容与分析覆盖范围仍由已有长录音回顾组件展示。

## 实现与修复

`packages/gateway-contract/src/recording-outcome.ts` 定义不依赖平台的状态投影。`scripts/sync-recording-outcome.mjs` 生成 ArkTS 镜像、Web 文案以及鸿蒙资源和资源适配器；`--check` 检查同步情况。

Web 结果浮窗区分关闭界面与后台保存流程，不再关闭后立刻出现另一块保存面板；删除已确认同步的本机副本后，失效的本机保存证明不再参与后续提示。恢复流程在删除本地原音前再次要求服务端确认原音附件。

重点同步单独重试，失败保留本机 outbox 和原音，不再阻塞原音上传、将已保存原音误报为失败，或重试时重新上传原音、创建 Note。鸿蒙首次获取处理状态断网后继续查询，页面退出会释放查询计时器。

## 验证

- Web discussions 回归：20 个文件、136 项测试通过。覆盖保存屏障前后、离线、上传确认、空录音、部分保存、失败续跑、同一 Note 续录、重点独立重试、关闭后继续处理、原音删除和原文更新。
- 鸿蒙主机全量测试：120 个文件、799 项测试通过。覆盖包括真实 SQLite 恢复、重点 outbox 重试、状态查询断网恢复、模板保留；200 组状态组合比较两端投影，中英文资源逐项一致性检查。
- 服务端处理恢复集成测试：16 项，验证原音续跑和既有结果保留。
- `scripts/recording-outcome-ui-acceptance.mjs`：使用合成状态验证 1280、390、320 宽度的六种结果状态、缩小、拖动和重试按钮；截图输出 `/tmp/xopc-recording-outcome`。这是浏览器界面验证，不涉及真实供应商录音。
- Web 生产构建与相关 ESLint；鸿蒙 release HAP 构建与 CodeLinter。构建已有的大包、兼容 API 和未配置签名警告不属于本次变更。

# 模型配置体验走查

日期：2026-10-16。首轮使用实际 React 页面和独立的模拟服务状态进行体验走查；后续 review 追加本机真实网关、已配置百炼与 Cloud 的验收，结果见下文。

## 体验链路与调整

| 场景 | 原有阻碍 | 本轮结果 |
| --- | --- | --- |
| 首次配置 | 空选择器、设置、管理服务并列，缺少明确下一步 | 未连接时只保留一个“连接服务以启用”入口，直接进入对应能力的服务页签 |
| 使用已有服务 | 已连接后仍展示空 Key 表单，容易误以为需要重新输入 | 默认“使用已有连接”，选择具体模型后直接应用；更换 Key 单独展开 |
| 选择服务 | 表单追加在长列表末尾，其他语音服务继续占据空间 | 选择后进入独立表单步骤；“更换服务”返回列表，其他语音来源渐进展开 |
| 切换模型 | 模型与长服务名挤在同一行，搜索要求连续匹配 | 分开显示模型名和服务名，支持中英文、多关键词组合搜索 |
| 调整语音 | 重复能力标题、技术说明过多，听写摘要链接离开弹窗 | 直接展示当前模型与参数；听写关系用短文案解释，服务链接在原弹窗切换页签 |
| 中断后继续 | 目录重新加载可能将具体模型改回推荐项 | 保留 Key 草稿与具体模型选择；关闭后焦点返回调用入口 |
| 服务暂时失败 | 原始错误直接占据主界面，已有凭据也被描述为刚保存 | 显示可操作的失败提示与重试；技术原因收进详情，只有本次确实保存过连接才提示“连接信息已保存” |
| 旧默认配置 | 隐式默认模型显示为 `provider/default` | 显示“默认模型”，保留原配置，不擅自替换为目录推荐项 |
| 键盘与手机 | 页签被读作开关，关闭后焦点丢失 | 标准 tab / tabpanel 语义、方向键导航、焦点恢复；390px 宽度下弹窗宽 366px，无页面横向溢出 |

## 信息与反馈原则

- “已选择”表示已有模型分配，不冒充供应商调用已验证。
- 连接列表优先显示已连接服务，未连接来源归入“添加服务”。
- 参数自动保存与服务应用分开表达；修改现有 Key 时说明同服务的其他模型也会使用新 Key。
- 更换服务、模型选择与普通关闭都有明确动作，避免把关闭误解为保存。
- 复用现有语义颜色、按钮反馈与弹窗动效，保留减少动态效果设置。

- 浏览器操作：首次连接、复用已有连接、关闭再打开、应用失败、恢复后成功应用、中文界面英文组合搜索、看图模型单独切换、听写入口原地返回、键盘页签导航及手机布局。

- 本轮没有修改模型调用、后台使用范围及计费回退规则；继续由既有服务端校验负责，相关回归包含在上述测试中。

## 提交前 review 与真实 E2E

本轮 review 补齐三处边界：其他设置正在保存时禁用未连接能力的入口；Cloud OAuth 已授权时明确展示“使用已有连接”；更换 Key 成功但模型应用失败时回到已保存连接摘要，避免继续展示空的新 Key 输入框。

使用当前本机网关和已保存凭据完成以下真实浏览器流程：

- 分别选择 Cloud、百炼北京已有连接，只应用当前能力；聊天、录音识别与 TTS 切换成功，后台模型始终保持 Cloud。
- Cloud 切换音色并保存；百炼当前模型只返回一个音色，验证该音色保留。两种服务均验证朗读参数保存、关闭重开后的状态以及入口焦点恢复。
- 两种服务均实际生成语音，并将生成音频交给同服务识别，均正确识别验证数字 4729。标签朗读模式使用带 `[[tts]]` 的请求输入。
- 看图模型单独切换；保存冲突返回 409 且不覆盖新配置，页面可重新加载恢复；旧详情入口、聊天草稿、连接草稿、自定义图片服务弹窗及 390px 深色布局通过。
- 最终比较模型路由、语音配置版本与保存的凭据，确认恢复测试前配置，没有替换已有 Key。

真实测试命令：`XOPC_VENDOR_E2E=1 pnpm exec tsx scripts/verify-model-inline-live.mts`。供应商请求为显式选择项，默认脚本只验证真实网关与页面配置。

最终结果：真实 E2E 14 项检查通过，浏览器运行异常为 0；模拟首次接入、第三方 Token Plan 与后台范围验收通过。相关回归共 28 个文件、204 项测试通过；Web 类型检查、生产构建、相关 ESLint 和差异空白检查通过。后台使用范围与旧配置兼容逻辑未改变，相关服务端回归通过。

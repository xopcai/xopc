# 移动录音笔记 PRD

日期：2026-09-15 · 状态：待实现 · 配套：[调研证据](./mobile-meeting-research.md) · [技术设计](./mobile-meeting-technical-design.md)

本文细化 [会议 P1/P2](./voice-meeting-p1-p2-technical-design.md) 的移动部分；手机交互以本文为准，共用会议领域契约继续沿用原设计。既有听写和 AI 通话仍按 [移动语音 PRD](./mobile-voice-prd.md) 工作。

## 1. 产品目标

**让用户把手机放下也能安心记录；拿起来就知道重点、依据和下一步。**

对外名称统一为「录音笔记」。会议、访谈、课程是资料的场景，不新增第四种顶层工作模式。资料进入 Inbox / Notes，项目和任务使用现有对象。

### 场景优先级

| 场景 | 用户真实需求 | 交付 |
|---|---|---|
| 现场会议，30–120 分钟 | 不漏结论、少看屏幕、会后跟进 | 首发核心：后台录音、标记、摘要、证据、待办 |
| 客户拜访 / 访谈，15–90 分钟 | 路上开录，分清原话与个人观察 | 首发：离线开录、时间标记、个人备注；访谈模板后续 |
| 灵感，30 秒–5 分钟 | 不按住说话，快速保存 | 同一录音笔记支持；聊天短语音仍保留 |
| 课程 / 培训，1–4 小时 | 长时间省电、章节复习 | 首发验收两小时，四小时通过专项测试后开放 |
| 手机参加第三方线上会议 | 获得完整双方声音 | 引导导入有权限的录音 / 平台资料，或在 PC 端采集 |
| 通勤时复盘 | 听重点、追问、回到原声 | 后续复用已有语音通话，绑定本场会议证据 |

首发主张是可靠现场录音。翻译、图片标记、跨会议比较、系统音频实验和硬件接入依赖后续阶段。

## 2. 入口与信息架构

- Inbox 现有捕获区增加明确文字动作「录音笔记」；Notes 新建菜单、Chat 附件菜单提供同一入口。Chat 麦克风仍是听写 / 短语音，耳机仍是通话。
- 高频用户可在现有 Quick Entry Widget 配置此动作；首版快捷入口打开前台录音页，不从推送、后台任务或深链静默开麦。
- 首次显示简短说明：将保存周围声音，请告知参与者；首次使用再申请麦克风。展示「仅保存在本机」与「同步到当前工作区进行整理」的选择，默认选择一经确认后记忆。
- 普通开录不要求标题、参与人、地点、项目、模板和网络检测。默认日期标题，结束后建议内容标题，用户编辑优先。
- 尚未配对也允许本地录音，完成后再连接工作电脑；已配对但 Gateway 离线不阻断录音。同步授权、组织归属和 AI 可用状态与开麦分开。
- 详情使用现有 Note `/items/:id`；未同步资料使用仅本机的 capture 标识，绑定 Note 后替换导航，不产生两条列表记录。详细路由见技术设计。

## 3. 主流程与屏幕规格

### 3.1 开始与录音页

用户点「开始录音」→ 权限及磁盘检查 → 原生收到并开始保存声音 → 显示录音状态。等待设备启动时按钮显示短操作状态；收到首帧前不走录音计时。

```text
┌────────────────────────────┐
│ ‹ 收起       录音笔记    ··· │
│ 今天 14:30       手机麦克风  │
│           ● 18:42          │
│ 本机已保存至 18:40          │
│ 待同步 · 网络恢复后继续      │
│                            │
│ 重点     文字     我的标记   │
│                            │
│ 17:20  发布日仍待确认        │
│ 来源：17:03、17:15           │
│ 理解截至 17:30              │
│                            │
│ [＋记一句]    [问这场录音]   │
│ [暂停]   [☆ 标记重点] [完成] │
└────────────────────────────┘
```

这是布局规格示意，不是运行界面；时间和内容为模拟。

- 收起放在顶部；暂停、标记、完成放在底部拇指区，标记是高频动作。完成与标记拉开间距，普通完成不弹确认，因为会保留录音。
- 不使用需要一直按住的录音手势。标记轻触即写入，轻震一次、显示时间；可以事后补文字，不强迫当场打字。提供可撤销提示。
- 默认查看「重点」，首次暂无转写时显示录音提示和已记录标记，不显示假摘要。选择「文字」才展示实时转写；滚动查看旧内容时暂停自动跟随，提供「回到最新」。
- 输入「记一句」是个人备注，绑定时间；不冒充参会者原话。会中问答是本场范围的文字问答，回答附截止位置和来源。
- 不实时播放助手声音；会中禁止另起听写 / 有声通话抢麦。用户选择语音复盘时提示先完成录音，随后显式进入复盘。

### 3.2 三种进度如何表达

| 层次 | 用户文案 | 含义 |
|---|---|---|
| 正在采集 | 「录音中 18:42」 | 原生报告当前采样进度，不由页面定时器推测 |
| 本机持久保存 | 「本机已保存至 18:40」 | 该部分已完成本地文件与日志提交 |
| 远端及理解 | 「已同步至 18:20」「理解截至 17:30」 | 接收和理解分别推进，异常时展开详情 |

正常时只显示一行保存状态，点开看详情；断网显示“录音继续，等待同步”，AI 故障显示“录音已保存，整理暂不可用”。中间有缺口时显示缺口，不能把末尾时间当作整场都完整。

### 3.3 收起、锁屏与中断

- 离开录音页，应用壳显示紧凑状态条：录音状态 + 时长 + 返回。位于内容与现有底部区域之间，不盖 Chat 输入框、不叠第二个悬浮按钮。Android 返回手势等价收起。
- iOS 可用时使用 Live Activity 显示状态；初版点击返回录音页。Android 前台服务通知提供返回、停止并保存；增强标记 / 暂停控件通过平台测试再开放。
- 锁屏默认不显示会议标题、逐字稿、姓名或问题。Live Activity / 通知被关闭不等于采集失败；应用恢复时读取原生真实状态。
- 来电、麦克风被占用、蓝牙路由丢失：原生立即记录中断，UI 显示「录音已中断，已保存至 18:40」，提供「继续录音」「完成」。首版不自动恢复麦克风。
- 用户主动暂停显示「已暂停」，计时不继续；意外中断显示缺口。蓝牙断开不悄悄改用手机麦克风。普通锁屏 / App 切换不视作中断。
- 强制终止或重启后打开 App：展示「发现未完成录音，已恢复 32:20」，可试听、继续、完成；绝不自动开麦。未闭合尾段可能丢失，恢复页说明实际缺失范围，不承诺系统强杀后继续录制。

### 3.4 完成后立即得到一份笔记

点完成先停止设备并封存本地文件，立即进入详情。不要等全部上传、转写、LLM 返回后才让用户离开。封存失败保留原文件，显示可恢复状态，不出现虚假的“已保存”。

```text
┌────────────────────────────┐
│ ‹       发布方案讨论     ··· │
│ 36 分钟 · 本机已保存        │
│ 摘要    原文    我的标记     │
│                            │
│ 本次结论                   │
│ 发布日期暂未确定   [12:08]  │
│ 先完成兼容验证     [26:30]  │
│                            │
│ 下一步                     │
│ □ 整理兼容结果 [确认待办]   │
│ 负责人待确认 · 日期未提及   │
│                            │
│ [▶ 回听]   [问这份笔记…]    │
└────────────────────────────┘
```

- 有结果时首屏最多展示 3 条关键结论、最重要行动和待确认问题，其余展开；不要整屏模型长文和多个评分仪表。
- 尚在整理时，保留可用的录音和个人标记，AI 区域局部 skeleton；显示当前处理阶段和可重试错误，不用全屏转圈。
- 点引用进入包含前后文的原文片段和播放器；继续提问时保持同一资料上下文。无音频的导入资料只显示文字来源，不出现不可用的回听按钮。
- 待办先以候选展示；用户确认负责人 / 截止日后调用已有 Task。重复点击、重生成摘要不能重复建任务。
- “谁承诺了什么”没有依据则写未明确；说话人默认“发言人 1/2”，只在本场更正，不猜测身份。模型结论可更正，用户备注永远单独保存。
- 一键分享先预览范围：摘要 / 摘要和原文 / 包含音频；私人备注和问答默认排除。系统分享导出的文件属于副本，界面不能声称撤回链接会撤回已导出的文件。

## 4. 故障与退出体验

| 情况 | 行为与恢复 |
|---|---|
| 没有麦克风权限 | 保留录音页，给设置入口；可导入已有音频，不反复弹权限 |
| Gateway / STT 未配置或额度耗尽 | 继续本地录音；已授权的同步可继续，AI 整理等待配置 / 重试 |
| 断网 / 只允许 Wi-Fi | 本地持续保存，明确同步策略；恢复合适网络后补传 |
| 低空间 | 提前显示预计可录时间；达到保留阈值时停止并保存，不静默丢帧 |
| 低电量 / 高温 | 降低动画、停止非必要实时理解；不承诺系统不会终止应用 |
| 本机写盘失败 | 停止采集并报错，保全已闭合文件；不是“稍后自动同步” |
| 账号退出 / 工作区切换 | 活跃录音先暂停并保存；资料保持原归属，不自动上传到新工作区 |
| 误点完成 | 完成不可逆地封存本场；提供“继续记录为补充录音”，关联原笔记，不重开已 seal 的文件 |
| 删除 | 单条删除走已有 Undo；未同步唯一副本明确标识；批量删除使用既有确认 |

删除操作在 Undo 结束后执行不可逆媒体清理；录音进行时先停止再进入删除路径。提供独立「清理本机副本」，仅在远端完整可读且不存在未同步编辑时允许；不要把清理缓存和删除整份资料混为一谈。仅本地且未同步的资料会随卸载丢失，在其保存详情中说明。

## 5. 手机专项体验标准

- 遵守 `apps/mobile-expo/DESIGN.md`：语义 token、20pt 内容边距、原生导航、单一底部操作区。按钮点击区至少 44×44，Android 尽量 48dp。
- 大字体不截断状态、完成和恢复动作；VoiceOver / TalkBack 能读取当前状态与控件结果，不逐秒播报时长或每句转写。
- 颜色之外同时用文字区分录音、暂停、中断；支持深色和减少动态效果。震动用于开始 / 标记 / 停止等动作，不用于每条字幕。
- 锁屏关闭波形动画；前台电平降频、转写列表虚拟化。不要为了“AI 在工作”持续动画和亮屏。
- 录音支持横竖屏切换但不销毁会话。键盘打开时问题输入区可见，完成录音动作仍可访问，交互测试覆盖小屏设备。
- 2 小时录音的存储 / 电量预估是实测区间，不用假精确数字；复杂采样率、chunk、epoch 等术语不进入用户流程。

## 6. 隐私与成本默认值

- 录音默认私人；第一次选择处理方式，后续沿用。本地模式只录音、播放、标记，不声称具备尚未实现的离线 ASR / 总结。
- 同步使用已配对的工作区及其 AI 服务配置；明确“会发送到工作电脑及配置的转写服务”，不把自托管 Gateway 自动宣传为所有数据不出设备。
- 不为录音请求通讯录、位置、屏幕录制；场景、项目可后补。没有跨会议声纹库。
- 实时理解可关闭，不影响录音；初版同步默认 Wi-Fi，用户可开启移动网络。开始页显示“实时文字需同步”，不让 Wi-Fi 限制变成无法解释的空白。
- 保留音频先由用户管理；首版不自动删除唯一副本，也不承诺无限本地空间。清理列表展示大小、同步状态和占用来源。

## 7. 验收指标与发布分层

以下均为**目标**，不是当前测量结果；以签名 Release 包、声明机型和网络条件报告 p50/p95。

| 维度 | 首发门槛 |
|---|---|
| 易开始 | 已授权且温启动，从可见入口点录音到首帧 p95 ≤ 1 秒；冷启动另测 |
| 易完成 | 点完成到本地封存并可离开 p95 ≤ 1 秒；不包含远端整理 |
| 不丢已保存内容 | 故障注入后全部已提交片段可恢复；未提交尾段损失上限目标 ≤ 20 秒 |
| 长录音 | 至少两小时含锁屏、断网、切页，无因 JS 暂停而丢音；内存无随时长线性增长 |
| 理解可解释 | 所有展示为事实的结论均可跳到有效来源；未覆盖部分不声称已理解 |
| AI 质量 | ≥ 30 场分层中文 / 混语 / 噪声样本；事实支持率目标 ≥ 95%，明确行动召回目标 ≥ 90%；单列否定和改口案例 |
| 核心可用性 | 8–12 名目标用户，≥ 90% 无指导完成开录、收起、标记、找回证据；零误删唯一副本 |
| 电量与性能 | M0 建立机型基线；在确定电量预算前不能以“省电”作为发布宣传 |

“引用存在”和“引用支持该结论”分开评测。错误负责人 / 日期、静默音频缺口、越权分享为阻断问题，不能用平均得分抵消。

阶段：M0 原生与竞品验证 → M1 可靠录音笔记 → M2 总结 / 证据 / 待办 → M3 会中问答 / 复盘及系统控件增强 → M4 平台导入与更长录音。每阶段 review 和故障验收后再继续；详见技术设计。

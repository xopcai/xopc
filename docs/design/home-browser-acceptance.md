# 首页卡片浏览器验收 · 2026-10-23

验收使用 Codex 内嵌浏览器访问真实 React 页面、Gateway HTTP/实时连接和 SQLite。首先只读查看了现有 Gateway 的验收卡，然后在独立数据库中进行状态修改。任务执行使用本地确定性模型；没有使用请求拦截或伪造卡片响应，没有修改现有业务任务。

可复现环境：`pnpm exec tsx scripts/serve-home-browser-lab.mts`。脚本建立新的临时状态目录，在 `127.0.0.1:24180` 启动 Gateway，在 `127.0.0.1:4310` 启动源码页面。首次使用可跳过 Cloud 和来源导入引导。运行结束后关闭脚本进程，临时目录保留供排查。

## 实际操作记录

| 卡片或入口 | 浏览器中执行的操作 | 实际结果 |
| --- | --- | --- |
| 人工验收 | 展开 → 打开 HTML 依据 → 标记通过/失败 → 全部通过 → 完成验收 | 失败时完成按钮不可用；全通过后可完成；卡片移除、计数更新、显示 Task accepted 回执 |
| 自动验收 | 展开验证不足原因 → Continue and verify → 等待执行完成 → 重新查看 | 从待处理转为后台执行，再实时返回验收；显示新的实际执行摘要，未验证条件仍不能被当作通过 |
| 本地文件依据 | 点击产物 → 查看 HTML → 三点菜单刷新 → 放大 → 收起 → 关闭 | HTML 内容可见，刷新有效；修复后放大内容仍在弹窗内，关闭和收起均可操作 |
| 外部依据 | 点击 HTTP 依据 | 在独立标签中显示目标返回内容，原首页保持可用 |
| AI 建议依据 | 当前建议打开来源任务；历史展开原始依据 | 来源任务详情打开，历史内任务和外部链接均存在 |
| 补充信息 | 选择 Alice → 提交 | 等待问题消失，等待数归零；卡片从待补充转为待验收，出现继续执行入口和保存回执 |
| 任务批准 | 查看范围 → Approve | 原等待解除，更新任务状态与后续操作 |
| 任务拒绝 | Deny and pause | 任务进入后台等待列表，没有继续自动执行 |
| Connector 决定 | 分别批准、拒绝本地合成记录 | 显示对应回执并移除待处理记录；未连接真实第三方账户 |
| 暂停任务 | 在后台展开 → Resume task | 暂停解除，任务回到待处理列表，首页同步更新 |
| 依赖等待 | 完成被依赖的人工验收任务 → 再次打开依赖任务 | 等待条件自动解除，卡片改为待验收，详情显示 Ready for review |
| 失败任务 | Retry | 新执行启动，卡片暂时进入后台，完成后自动显示新结果 |
| 自动化异常 | Dismiss；另一条记录 Retry → View progress and result | 忽略记录从首页移除；重试入口打开新 runId 的详情，显示 succeeded 和实际结果 |
| 定时计划 | 展开全部 → 点击第四项 → Pause → Resume | 打开对应计划；暂停/恢复状态正确，首页数据随之更新 |
| AI 建议启动 | Start with xopc | 建立任务、显示启动回执及任务进展入口 |
| AI 建议反馈 | Not relevant → Undo | 建议移除后可恢复 |
| AI 建议历史 | 打开历史 → 展开原依据 → Continue discussion | 继续对应讨论，草稿保持原建议上下文 |
| AI 建议讨论 | Discuss first → Send | 原建议作为草稿带入；发送后显示真实本地模型回复；修复后新浏览器页面无 React 错误 |
| 数量上限 | View 2 more pending items；View all 后台事项 | 原先被上限隐藏的验收任务和第四项计划均可访问 |
| 返回上下文 | 展开验收卡 → Task details → 关闭详情 | URL 保留 reviewTask，原验收卡仍展开 |

## 修复的问题

1. 待处理任务被注意力上限隐藏，缺少访问入口：增加显式展开完整当前快照。
2. 暂停任务不在首页任何列表：保留为可展开的后台等待任务。
3. 验收阶段覆盖了补充信息、授权和依赖原因：优先展示实际等待条件。
4. 执行结果摘要显示通用的传输成功文字：成功回执优先保留真实助手交付内容。
5. 弹窗内放大预览被传送到外层页面：使用最近的内容表面，使内容留在弹窗焦点范围中。
6. 从依据或详情返回后验收卡折叠：保留所在页面的展开参数。
7. 建议讨论带入草稿触发父组件渲染警告：改到布局效果中应用草稿，并补充回归测试。

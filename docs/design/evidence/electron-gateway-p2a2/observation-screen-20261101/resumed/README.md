## 失败定位

- 原生3、4轮仍在安全存储原15秒预算内失败。解锁不是所有超时的充分解释。使用先前已验证的测试bundle id后，同候选运行字节可正常使用OS安全存储；新bundle id初始化问题仍留作独立待办，没有使用明文或同步回退，没有加长预算。
- 对照旧D3a包成功进入状态读取，但监督器使用了新提示文案，后续断言失败；仅用它定位安全存储边界，不称整轮通过。
- 第5轮将CDP bringToFront当成真实OS窗口焦点，Host正确拒绝获取截图来源。修正为原生聚焦的测试准备，产品原2秒readyOrigin预检不变。
- 第6、7轮测试模型跨用户轮次复用tool-call id，前一轮拒绝结果使后一轮图像未进入模型请求。API第3轮保留重复ID可稳定复现失败，第4轮使用唯一ID通过；已修正监督器的合成模型ID。没有修改生产Agent的历史配对规则来掩盖测试缺陷。
- 第8轮再次锁屏。第9轮截图、停止、重启、撤销等检查已通过，后续应取消重新登记的用例却得到批准；第10轮首次取消也得到批准。两轮仍记失败，不推断为产品已修复。第12轮使用新进程绑定和逐步原生操作整轮通过。
- 首次新包远端TLS夹具失败，原因是其依赖NODE_EXTRA_CA_CERTS信任自签证书，而正式包关闭了nodeOptions fuse。该环境变量被忽略是[Electron明确规定的行为](https://www.electronjs.org/docs/latest/api/environment-variables#node_extra_ca_certs)。保留失败，不开启fuse或绕过证书校验；SSH-loopback回归另行通过，不能冒充新包受信任HTTPS/WAN验收。S4此前的真实HTTPS记录保留，新增能力仍需独立WAN验证。

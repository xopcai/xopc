# P3a 目录句柄与执行器基础

本批仅增加尚未接入远端入口的文件执行器基础，不注册 Gateway 工具、不授权任何目录，不改变默认本地启动路径。

采用 N-API v8 原生目录适配器及同一进程内的 Node Worker：逐级 openat/O_NOFOLLOW，持有已打开目录 FD，拒绝路径穿越、符号链接、特殊文件、多硬链接和超限文本；写入需预期不存在或已读内容版本。文件读取/写入最多32768 UTF-8字节，目录最多100条/扫描1000项。写入途中错误保持结果未知。现有文件通过已打开的文件身份更新；版本检查不能宣称是针对非协作编辑器的全局CAS，崩溃可能留下部分写入，必须继续由P2b意图/未知结果处理。

Worker 的同步系统调用不会阻塞 Electron UI；停止等待真实线程退出，阻塞系统调用不能被视为已停止。Worker 与持有 OS 执行锁的 Electron 主进程共同退出，避免遗留独立文件写进程。返回实际打开目录的本机身份，供后续原生授权确认；绝对路径不会作为远端工具参数。

## 验证

- 4项实际文件/线程/跨进程测试通过：路径与链接拒绝、授权路径被替换仍使用原目录、创建/版本冲突/限额、单次worker与停止后不重开。
- 实际父进程持有P2b执行锁并创建加载此原生适配器的Worker；SIGKILL父进程后重新取得锁，原Worker不能执行预先排队的延迟写入。这是受控父进程故障测试，不是完整Electron原生目录授权验收。
- Node26/Electron类型检查通过。
- 使用已安装Electron45候选的实际Node24.22运行时加载原生模块、写读隔离夹具文件通过；N-API10运行时支持本模块的N-API8。该模块目前从工作区加载，尚不冒充包内原生模块验收。

首个Swift独立helper原型的编译错误与修复测试、首个TS类型错误已保留。审查发现其可能在Main崩溃后短暂存活，因此在接入产品前改为同进程Worker，原型仅保留于 `/tmp/xopc-p3a-external-helper-prototype`，未开放给远端。

后续继续P3b设备/workspaceId绑定、原生选择与逐次批准、读写工具接线、打包和实际Gateway/Agent/Electron E2E；当前不能声称P3已完成。J2b新增原生恢复仍等待解锁；既有失败与性能预算保持不变。

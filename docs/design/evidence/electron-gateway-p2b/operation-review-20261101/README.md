# J2b-5 操作查询与人工核实

新增独立设备认证、Gateway 签名的操作元数据查询与人工核实接口；复用 Endpoint v2 增加可协商的状态查询工具。查询旧操作不刷新其期限、授权或执行身份，不启动执行器。工具结果不携带原参数、内容或完整返回值。

人工核实仅从可信本机设置窗口发起，需原生确认。先获得固定每用户目录的 OS 执行锁并独立核实停止，再记录本机人工观察，最后提交 Gateway。确认回执丢失时复用已持久化的核实身份；旧操作仍为 unknown，不能重试。缺少本机记录时只对已知无子进程的剪贴板执行器允许人工核实，并写入永久去重记录。停止已确认但可能存在部分效果的取消操作也会阻断新写入。

增加本机离线遗留操作恢复：意图元数据与 journal 一起持久化，原 Gateway 离线或设备身份失效时仍能由本机用户核实。缺少旧元数据或执行器停止未确认时拒绝放行。离线核实不代表服务器已确认，也不将未知变为成功。

## 保留失败与未通过项

- `regression-2.log`：旧会话关闭断言遗漏新增的 resultUnknown；修正断言后 227 项通过。
- `package-2.log`：Node 构建清理 Web 产物，缺少静态 UI；补做 Web 构建后重新打包通过。
- `p2b-query-native-1.json`：Mac 锁屏，第一个设备登记的原生取消窗口未点击，按原 120 秒交互预算超时。没有执行剪贴板写入，不能算作本批原生核实通过；保留夹具目录于失败报告，待解锁重跑。

解锁后第2/3轮暴露真实聊天焦点准备不足：设置窗口前台也能获取设备来源，但不能据此认为原生聊天确认已可点击；未及时完成操作，原时限内失败。脚本改为在原120秒准备预算内同时核验真实聊天窗口OS焦点和设备来源，发送前继续核验焦点；原生取消还须有USER_DENIED审计，超时不冒充用户取消。

第4轮 `p2b-query-native-4.json` 已通过新增故障整轮：实际原生批准写入→本机成功回执已落盘→丢弃真实签名完成帧并断线→服务器保留unknown→原生取消人工核实保持阻断→原生批准核实后旧状态仍unknown→新的临时授权与新operationId单次原生批准→实际新写入与Agent结果成功→重启、安全存储、独立身份、离线停用与撤销验证。剪贴板原格式仅在内存保存，实际观察到测试文本且最终恢复；安装包前后摘要相同。

第4轮使用 `--approval-only`，跳过已有J2b-4覆盖的设备登记/初始授权/初始写入取消分支，**仍实际执行了新增人工核实的取消与批准**。不能将该结果描述为新版脚本所有取消分支都已重跑通过；原生全取消分支的已有证据见J2b-4，新版USER_DENIED强化断言尚需整轮复验。

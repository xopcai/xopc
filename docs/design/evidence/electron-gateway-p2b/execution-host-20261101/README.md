## 实现边界

- 独立执行Host使用设备凭据、双向签名帧和可靠调用控制器；签名hello还须匹配本机批准的精确grant/工具哈希。断线、锁屏/suspend、连接切换、退出、有效期到达均停止；不自动重连或续用写授权。
- 协调器在固定每用户状态根持有journal与OS执行锁；远端配置/userData不决定执行锁归属。新调用、观察/执行切换、返回本地和退出先核实停止，停止未确认时保留锁并拒绝接管。观察入口与写入口互斥，过期epoch不能影响新连接。
- 首个工具为剪贴板文本写入，最多4000字符、每次原生确认、一次授权最多两分钟；不会读取剪贴板，文件/命令/输入控制仍未开放。Electron45的`writeText`是Promise，必须等待实际系统请求完成；取消不能撤回已提交的系统写入，未完成时不能提前确认停止。
- 连接窗口与远端聊天提供明确的能力设置/停止入口；远端专属菜单可立即停止本机执行。旧Gateway未声明可靠执行能力时禁用该入口，聊天与原有观察路径独立保留。

## 失败与修订

首次远端回归在停止确认处超时，原始报告、运行元数据和现场目录保留。旧的已接受wire候选使用相同原脚本也复现失败：普通第二轮尚未终结时按钮仍可用，脚本已点击stop，但慢输入还在客户端持久化；第二轮被取消，随后创建的慢运行自然完成。

修复仅在验收脚本：先核实上一轮服务器和UI均空闲，再等待慢运行就绪，并核对实际abort请求的runId。整个停止阶段共用原30秒时限，未延长预算。修复后新旧候选均完整通过，`stopTarget.expectedRunId`与实际请求一致。没有修改产品停止语义来隐藏该失败。

原生原始报告沿用旧脚本的`noWriteToolsAndOnlyExplicitObservationEndpoint`字段名，该断言实际检查**撤销后**所有设备恢复默认scope且无端点，不表示测试期间没有写能力。该原始报告保留；验收脚本字段名已修为`afterRevocationNoEndpointOrExecutionScope`，并修正从截图验收复制的交互标签。没有重写原报告为新的测试结果。

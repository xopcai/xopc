# 移动锁屏体验：产品方案与竞品依据

日期：2026-09-15。状态：设计交付，尚未实施。关联：[技术方案](./mobile-lock-screen-technical-design.md)、[当前移动录音实现](./mobile-meeting-ui-upload-design.md)。

## 1. 产品目标与决策

用户离开应用后，仍能知道声音是否在录、操作是否生效、资料是否保存、什么时候值得回来。优先实现录音与播放控制，再完善通话、上传和会后结果。

按用户意图使用三类系统展示：

- 持续活动卡：正在录音、用户主动追踪的处理任务。
- 系统媒体控制：朗读、会议回放；复用耳机及系统播放操作。
- 普通通知：会议总结完成、需要处理的失败、待确认事项。

卡片是现有任务的可见入口，不能承担后台运行本身。应用内浮条、桌面 Widget、锁屏 Widget、Live Activity 和 Android 通知分别验收，不相互替代。

## 2. 调研依据与证据边界

本轮读取官方产品资料、Apple / Android / Expo 文档及本地实现，没有操作竞品真机。以下“已确认”均指文档证据，未知项不按“没有功能”计分。

| 对照产品 | 已确认的设计事实 | xopc 采用的方向 | 仍需实测 |
|---|---|---|---|
| Apple 语音备忘录 | 录音支持分段暂停 / 继续；支持机型的灵动岛显示进行中的录音，并可返回应用 [R1] | 持续展示录音状态和时间；回到当前录音而非首页 | 各 OS 下锁屏操作布局、误触与中断显示 |
| Just Press Record | 官方支持文档明确开始后可后台或锁屏录音；其他音视频和电话可能打断 [R2] | 录音脱离页面；中断必须成为明确状态 | 当前 Live Activity 的按钮及版本覆盖；本轮官网不足以证明细节 |
| 飞书妙记 | 官方教程描述移动录音、暂停继续、退出后的应用内浮窗、停止上传 [R3] | 应用内外一致的录音入口，录音结束进入资料处理 | 不能把浮窗等同于锁屏卡；iOS / Android 锁屏按钮待实测 |
| 钉钉 AI 听记 / AI Minutes | 中国站产品页及国际站介绍录音转写与会议资料处理 [R4] | 会后反馈围绕纪要和行动，不只显示上传完成 | 国际版不能代替中国版；当前锁屏卡布局和可操作性未核实 |
| 豆包 | 官方桌面商店更新记录提到手机版录音纪要同步云盘 [R5] | 持续录音结束后给出可回到资料的入口 | 桌面更新记录不能证明手机锁屏卡；语音对话 / 录音纪要分开实测 |

本轮不采用无出处的“豆包灵动岛开启教程”或转载宣传准确率。锁屏交互的工程依据使用平台官方文档，不从竞品宣传反推普通 App 可用的系统权限。

## 3. 场景和优先级

| 场景 | 展示内容 | 操作 | 展示方式与优先级 |
|---|---|---|---|
| 现场会议 / 访谈录音 | 正在录音、录制时长、最近已落盘时长；默认不显示会议名称 | 暂停、结束并保存；点卡片返回录音 | iOS Live Activity / 灵动岛；Android 原生前台通知；P0 |
| 主动暂停 | 已暂停、固定时长、声音已保存 | 返回继续、结束并保存 | 保留当前录音卡；首版继续需回前台；P0 |
| 来电 / 麦克风失效 / 存储异常 | 已中断、可确认的保存时长、需要返回处理 | 返回恢复；必要时结束保存 | 当前卡立即进入异常态，避免持续计时；P0 |
| 朗读 / 会议回放 | 标题或隐私标题、播放 / 暂停、真实播放位置 | 播放暂停；有完整时间轴时提供前后跳转 | 系统媒体卡为唯一默认控制面；P0 |
| AI 语音通话 | 通话中、麦克风开关、连接状态、通话时长 | 静音 / 解除静音、结束、返回 | Android 前台通知；iOS 原生活动卡；P1 |
| 上传 | 已确认字节 / 总字节、等待网络或需回到应用 | 返回查看 / 继续 | 原生后台传输交付后做进度卡；此前明确前台限制；P1 |
| 转写 / 总结 | 当前阶段、最近更新时间 | 查看进度；允许取消关注 | 默认不常驻；用户选择“锁屏跟踪”后才创建处理卡；P1 |
| 总结完成 | “会议总结已完成” | 解锁查看会议笔记 | 一次普通通知，结束处理活动卡；P1 |
| 处理失败 / 待确认 | “会议资料需要处理” | 解锁查看原因或确认 | 普通通知，去重且不反复打断；P1 |
| 快速开始录音 | 固定快捷入口 | 打开录音准备页 | iOS 锁屏 Widget、Android 快捷入口；P2，不常驻活动卡 |
| 任务 / 审批 | 用户关注任务完成或需要操作 | 解锁查看 | 复用结果通知；不为每个 AI 请求创建活动卡；P2 |

**首版不从锁屏执行上传、分享、删除、生成任务或审批。** 这些操作会发送内容或改变业务数据，应在对应工作区内完成。停止只封存本地声音，不隐式上传。

## 4. 录音卡详细交互

### 4.1 版式草图

以下为信息结构，不代表系统实际尺寸或已完成 UI：

```text
┌──────────────────────────────────────┐
│ ● 正在录音                    xopc   │
│ 23:41                                │
│ 最近保存至 23:40                     │
│ [ 暂停 ]            [ 结束并保存 ]   │
└──────────────────────────────────────┘

┌──────────────────────────────────────┐
│ Ⅱ 已暂停                      xopc   │
│ 23:41 · 声音已保存                    │
│ [ 返回继续 ]        [ 结束并保存 ]   │
└──────────────────────────────────────┘

┌──────────────────────────────────────┐
│ ! 录音已中断                         │
│ 最近确认保存至 23:40                 │
│ 点击返回检查并恢复                    │
└──────────────────────────────────────┘
```

灵动岛紧凑态只显示麦克风状态和时间；最小态仅显示状态图标；展开态显示保存状态和两个操作。系统只给小空间时优先显示“暂停 / 中断”，不能仅靠颜色区分。

### 4.2 生命周期

- 用户明确开始且首帧已确认后显示“正在录音”；权限申请、设备准备使用“准备录音”，不得提前启动虚假的计时。
- 暂停执行成功后停止计时；结束进入“正在保存”，原生排空并封存成功后才显示“已保存”。
- 结束为直接操作，无锁屏确认弹窗；音频保留，后续仍可在应用处理。按钮不依赖长按等非系统标准手势。
- 用户主动暂停可继续同一录音；来电等非预期中断遵循现有“恢复并结束”的约束，完整 gap/epoch 契约之前不提供无缝续录承诺。
- 已保存卡建议保留 30 秒后请求结束；用户可提前移除。暂停 10 分钟后撤下活动展示，但不删除本地材料或自动恢复麦克风。
- 卡片被划走只代表不再展示，不代表停止录音。Android 保留系统必需的前台服务通知义务，遵从系统可见性策略；不反复重建用户已关闭的增强卡。

## 5. 通话与朗读

通话卡只展示交互状态，不在锁屏实时转录或显示 Agent 输出。静音与暂停录音使用不同图标和文案。静音只改变输入，结束停止当前通话全部音频。

朗读优先系统媒体卡：暂停 / 恢复、耳机控制、标题与当前播放位置保持一致。现有朗读 Live Activity 与媒体卡可能重复，默认关闭重复活动卡；若后续证明确有价值，可提供显式“显示章节进度”选项。当前分块进度不能包装成整篇按秒精确播放进度；没有完整时间轴时不显示总时长和全局拖动。

AI 通话不包装成普通音乐播放。iOS 原生通话活动卡通过验收后，移除这条场景现有 Now Playing 模拟展示；保留真正朗读与回放的媒体控制。CallKit / Android Telecom 仅在独立评估真实通话集成需求后采用，首版不引入。

## 6. 处理卡、结果与打扰控制

- 上传进度只按服务器确认字节计算；本机已发送不能标作云端已保存。
- 转写、总结只显示阶段，不制造 90% 进度或预计剩余时间。断联展示“等待更新”，附最后更新时间。
- 上传完成与总结完成是两个状态；只有最终结果成功提交后才发送“总结已完成”。
- 用户关闭锁屏跟踪后不自动重建。连续多条完成合并通知；默认无声音，失败仅提示一次。用户正在对应详情页时优先就地更新。
- 远端不可达、通知未授权、自托管网关未配置推送时，在应用结果页可靠可查，不承诺离线即时通知。
- 录音卡与旧会议处理同时存在时，旧处理默认退回应用 / 结果通知，保护当前录音可见性。系统最终排序由系统决定。

## 7. 隐私与无障碍

锁屏默认只显示“会议录音 / 语音通话 / 正在朗读”和状态。会议标题、参与者、转写、摘要、任务正文不进入默认卡片或推送载荷；用户主动开启标题显示后才投影允许的字段。点击详情走系统解锁和工作区校验。

提供 VoiceOver / TalkBack 标签、状态文字、动态字号和足够对比度；操作触控区域以 iOS 44pt / Android 48dp 为设计目标，最终受系统布局验证。息屏 / Always-On 减少亮度与动画，不用每帧波形表现“仍在录音”。

## 8. 产品验收目标

以下为拟定验收指标，不是实测结果：

- 正常运行时，首帧确认到发布卡片 P95 ≤ 1 秒；系统实际展示延迟另记。
- 暂停 / 停止指令原生接收 P95 ≤ 300ms；保存未完成时始终展示“正在保存”。
- 同一操作重复点击无重复封存；旧卡片无法停止新录音；已中断计时不无限前进。
- 断网不影响录音暂停与保存；锁屏两小时至少跨越全部 360 个分块。
- 处理结果每设备、每任务尝试只通知一次；工作区切换、退出登录后不会打开错误资料。
- 对比无卡片录音，新增 CPU / 唤醒 / 电量消耗单独测量；首轮以增量不超过 5% 相对耗电为调优目标，不做发布宣传指标。

竞品真机矩阵：钉钉、飞书、豆包、语音备忘录、Just Press Record；记录机型、OS、App 版本、地区与账号权限。对每款测试开始→锁屏→暂停→继续→来电→断网→结束→结果→点击返回，留存截图与时间。未知项保持待验收。

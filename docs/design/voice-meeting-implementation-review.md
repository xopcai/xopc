# 会议助手首版实施与自查

日期：2026-09-15

范围：按 [PRD](./voice-meeting-prd.md) 第 11 节拆分的 P0-A、P0-B、P0-C。以下区分工程实现、自动验证与生产验收；P1/P2 是后续扩展设计，未将平台未验证能力标为可用。

## P0-A：可靠输入

已实现：

- 120 分钟媒体上限、1 GiB 文件上限；原始编码字节按最多 8 MiB 分块上传，不在结束时构造整场 Blob/Buffer。
- IndexedDB 保存录音；音频块和录音进度在同一严格持久事务提交。浏览器偶发大块也会切成有界块。
- 原始录音持续上传，实时转写与原始保存分离；转写失败不阻止原始录音保存。
- 文件导入、上传回执、按序哈希校验、重复请求、重试恢复；恢复已有字节，不自动重开麦克风。
- 服务端临时文件、文件同步、目录同步、回执；拼接后有界解码校验实际时长，再保存为既有 Note 附件。
- 录音与听写/通话共用页面内麦克风占用锁。

自查修复：

1. 移除 IndexedDB 升级时清空已有草稿的逻辑。
2. 移除整文件上传路由、客户端拼接路径和墙钟倒计时残留。
3. 导入失败清理局部块；拼接校验失败清理临时文件；损坏原始块撤销回执，允许再次上传修复。
4. 结束录音防重复调用；卸载时防异步获取的麦克风泄漏。
5. 取消与上传走同一会议修改队列；最终附件同步落盘后再删除原始块。

验证：真实 HTTP + token 鉴权 + lazy 路由；分块重复/冲突/缺块/服务对象重建；两小时合成 WAV（超过 200 MB）完整落盘并得到 7,200,000 ms。后者验证媒体时长与有界输入路径，不代表真实两小时浏览器运行、ASR 或内存峰值测试。

## P0-B：可信理解

已实现：

- 时间段与可选说话人结果贯穿 media-understanding、STT 和会议整理链路；无服务商说话人结果时显示未区分，不能把局部 speaker A 当成跨请求身份。
- 已发布转写修订保存不可变快照；校对文字/本段说话人一次事务提交，支持按标签批量更名/合并，历史证据仍可读取。
- 转写修复仅补未确认媒体区间，保留已确认原文和用户校正；按样本切片保留原始媒体坐标。
- 全文按有界输入单元提取；末尾不截断；分片结果缓存；全局概要按有界树形归纳。
- 跨章节比较前后断言，保留撤销/替代与未解决冲突关系；关系两端必须存在且顺序正确。存在后续变更的行动需显式复核后才能转为新任务。
- 决定、风险、问题、行动必须引用输入片段；缺失引用或越界引用拒绝发布。
- 处理租约续期、失去租约中止；发布纪要与状态在同一 SQLite 事务再次检查租约与输入哈希。

自查修复：

1. 修复中间两个转写类型/映射会丢弃时间段字段的问题。
2. 防止全量补转写覆盖人工校正。
3. 防止旧处理者失去租约后改写失败状态或发布结果。
4. 唯一证据对应的行动可沿用既有 ID，避免标题改写引起重复转换；多项共用证据时只自动接受唯一精确匹配。
5. 重整理不会再触发首次完成回调，不覆盖个人笔记。

验证：125,000 字以上输入末尾覆盖；无效引用拒绝；65 章节全部进入归纳；跨处理块的已确认区间保持；旧转写快照不变。

## P0-C：会议工作页

已实现：

- 会议全文页与个人笔记分开；概要、章节、决定、行动、风险、问题。
- 逐字稿搜索、分批渲染、时间跳转、当前播放段高亮、原话抽屉、文字/说话人校对。
- 通用、项目例会、需求评审、客户访谈四模板，显式重整理。
- 概要、事实、行动的人工编辑独立持久保存，重整理保留修改与来源修订；支持忽略/恢复和批量加入任务。
- 行动显式转入现有 TaskApplicationService；上下文引用指定转写修订；默认待办，不从录音授予执行权限。
- 任务与转换关联同事务提交；重复转换返回同一任务；任务删除后保留 tombstone。状态直接读取任务，委托走现有任务详情。
- Markdown、TXT、SRT 导出和原录音下载；音频以鉴权 Range 流播放，避免整场下载到前端内存。

自查修复：

1. 任务创建使用既有完整契约与 outbox，不新增另一套任务存储。
2. 校对用 Radix Dialog，补齐焦点约束与键盘关闭；窄屏无横向溢出。
3. 校对提交后再发失效事件；旧纪要明确提示引用旧修订。
4. 新路由迁入独立 lazy bundle，移除原 eager 注册，验证 scope 和真实 HTTP 路径。
5. 人工修改不会隐去后来出现的撤销/冲突；复核只针对确定的变更 ID。
6. 修复既有语音浏览器测试夹具仍使用旧 token 状态的问题，改用当前 sessionKey。

验证：会议浏览器冒烟覆盖真实 React 组件、单次任务转换、旧证据、文字/说话人同时校对、搜索、390px 布局；真实 HTTP Range 206、非法 Range 416、未认证 401、导出。既有语音浏览器冒烟覆盖麦克风、PCM 播放、中断、静音、导航、显式澄清和听写取消/完成。

## 简化后的架构选择

- 一场会议一份原录音；复用 discussionId 和 Note 附件。P0 不为尚未实现的系统音轨引入 recording/epoch/track 三层实体。
- 新表只承担分块回执、不可变转写快照、分片分析缓存、行动任务关联和人工编辑。章节/事实仍作为不可变纪要 JSON 发布，避免提前引入完整事实图谱。
- 复用现有处理 worker、模型配置、SQLite 事务、Note、Task 与鉴权；没有新增队列服务、向量数据库或兼容分支。
- 前后端共享 discussion 类型与限制；旧字符串事实仅在一次性数据库迁移中升级，运行时没有双格式兼容分支。
- 客户端上传默认串行，保留简单重试；需要更高吞吐时再以测量结果决定并发。

## 生产验收与后续范围

尚未完成的验证：真实 30/60/120 分钟多人、中英混说、噪声、暂停恢复、浏览器睡眠与崩溃故障矩阵；客户端/服务端峰值 RSS、成本及语音质量评测。未提供真实样本，不把人工目标精确率/召回率写成实测成绩。

当前边界：

- 自动说话人能力取决于 STT 返回结构化结果；本次没有新增声纹识别服务或承诺现有服务商都能区分说话人。
- 跨章节撤销/冲突关系由模型判断；引用和顺序有结构验证，语义正确性仍需真实会议集评测。用户编辑保留原始来源，不会自动改变已创建任务。
- 浏览器异常关闭前尚未发出的编码尾块无法恢复；导入文件尚未完整保存时仍需重新选择源文件。没有承诺锁屏后台录音。
- P0 交付时文件终稿校验仍在请求内执行；后续 P1-A 已改为后台持久封存任务，当前实现与验证边界见 [P1/P2 实施与自查](./voice-meeting-p1-p2-implementation-review.md)。
- 没有新增跨会议 FTS 索引或预算暂停界面；行动字段修改后对既有任务的差异更新仍需在任务详情显式处理。
- 系统音频、多音轨、会中问答/标记、跨会议比较与会前准备仍属于 P1/P2，需继续实现和平台验证；后续契约见 [P1/P2 技术设计](./voice-meeting-p1-p2-technical-design.md) 和 [分阶段实施与验收](./voice-meeting-p1-p2-delivery-plan.md)。

本次没有部署生产，也没有改写现有用户会议数据；迁移由应用下一次正常启动执行。发布前应备份数据库，并以真实录音验收决定是否放量。

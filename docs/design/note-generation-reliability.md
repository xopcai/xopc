# 从原音稳定生成 Note：恢复与重生成

日期：2026-10-15。承接[原音持久化第一批](./note-recording-reliability-phase-one.md)。本次覆盖 Gateway 转写/纪要链路、Web 操作与状态、HarmonyOS 操作与状态；声纹不在本次范围。

## 产品契约

原音是保留的数据源，逐字稿与纪要是可以重新生成的派生结果。转写或模型调用失败不能删除原音、创建重复 Note，或清空此前成功的结果。手写 Markdown、人工校对、人工编辑的纪要和已有证据版本需要保留。

用户有三个不同操作：

- **继续处理**：从失败阶段和已保存进度继续；转写失败继续转写，纪要失败仅重新生成纪要。
- **重新整理纪要**：使用现有逐字稿，沿用分析章节缓存和人工编辑记录。
- **从原音重新生成**：建立新的转写 generation，重新识别机器生成的文字，再生成纪要；保留人工校对的文本与时间范围。旧结果在新阶段完整成功前保持可读。

Web 和鸿蒙提供原音重生成入口；原音已删除或当前仍在处理时不提供重复重生成。若要全部采用更新的 STT 模型结果，应使用原音重生成；普通重试会复用此前成功的分片。

## 持久化与恢复

SQLite v253 新增：

- `discussion_processing`：每个讨论当前 generation、原音哈希、输入逐字稿 revision、重试阶段、失败次数、下次重试时间及转写租约。
- `discussion_transcription_checkpoints`：按 generation 和音频时间范围保存每段成功的转写结果；确认无语音的分段也记录，避免重复请求同一静音区间。

原音按约 20 秒解码分段；普通补转写跳过已确认文字的覆盖范围。每个成功范围立即提交检查点，后段失败不会丢掉前段工作。重启会重新读取原音并复用检查点，跳过已完成的 STT 请求；解码本身目前仍会重做。

原音重生成会建立新 generation，旧 generation 的恢复检查点失效。人工校对范围不交给机器覆盖。处理前核对保存原音的 SHA-256；源文件不存在或校验失败时保留旧结果并报告失败。

只有全部范围成功、租约仍有效、原音哈希和输入 revision 未变化时，才在一个事务中发布新逐字稿与 canonical hash。原有逐字稿存入不可变 revision，旧纪要引用仍可追溯。纪要另行生成，完成后才发布新版本；已有人工摘要/行动编辑继续通过 edit ledger 应用。

纪要分章结果沿用 `discussion_analysis_chunks` 缓存。模型中途失败或进程重启后，已通过 JSON/schema/证据检查的章节不必再次调用模型。原 Note ID、音频附件、用户 Markdown 不变。

## 重试、超时与隔离

- 暂时故障（超时、网络、限流、常见服务端错误、可重试模型输出错误）最多自动尝试 3 次，失败后按 5 秒、20 秒退避。
- 阶段、次数、重试时间保存在 SQLite；退避不占用 worker 的等待时间。凭据、缺少配置、原音损坏等错误直接进入 `needs_attention`；自动重试耗尽后也保留人工重试入口。
- 单个 STT/模型请求设 120 秒截止时间；纪要任务另有 10 分钟截止时间。下游不响应 abort 时也能释放 worker，迟到结果不能发布或写成已完成检查点。
- 转写 worker 使用有续租与过期接管的租约；旧 worker 不能覆盖新 owner 的结果。网关正常停止中止请求、释放租约，不把关机计为一次模型故障；异常退出后可接管过期租约。
- 等待长转写网络响应期间，后续 tick 仍可处理其他录音的原音合成任务。
- 模型 SDK 返回的 error/aborted/truncated 不再当成普通 JSON 解析错误；保留实际错误原因用于重试分类，错误输出不写入分析缓存。

## API 与交互

复用现有鉴权接口 `POST /api/discussions/:id/retry`：

```json
{ "mode": "resume" }
```

无 body 的旧客户端仍按 resume 处理。从原音重新生成使用：

```json
{ "mode": "from_audio" }
```

`from_audio` 仅允许 `completed` / `needs_attention` 且完整原音可用的讨论。接口先持久化任务状态，后台执行不依赖浏览器/手机继续停留在页面。并发重生成请求会被状态检查拒绝。

讨论详情附带可选 `processing`：是否原音重生成、已保存的转写分片数量/时长、当前失败次数、最大尝试次数和下次自动重试时间。Web/鸿蒙显示自动重试与旧结果保留状态；Web 区分转写和纪要阶段。

## 验证

新增 29 项测试：16 项真实 SQLite/原音文件链路恢复集成测试，8 项模型错误与重试分类测试，1 项升级/级联清理测试，3 项 Web 操作与状态测试，1 项鸿蒙重生成/轮询测试。另扩展已有真实 HTTP 鉴权与 lazy dispatch 测试，覆盖无鉴权、只读权限、非法 mode、从原音重生成及原音继续可读。

重点场景：STT 后段失败后重启续跑；静音范围检查点；自动退避/耗尽/人工续跑；保留人工校对与手写 Markdown；失败重生成不回退到旧文字分析；删除或损坏原音；旧租约和迟到结果隔离；关机中断；转写等待时继续合成其他原音；LLM 章节失败后重启复用已验证章节。

最终验证：录音、生成链路、迁移、鉴权路由与 Web 回归共 170 项通过（包含启用两小时原音 smoke 的主机测试）；鸿蒙主机测试 760 项通过。根 TypeScript 检查、Node/Web 生产构建、鸿蒙 Debug/Release HAP 构建通过；新增迁移已进入 Node 构建产物。相关 ESLint 与鸿蒙 CodeLinter 无错误或警告，`git diff --check` 通过。

这些是主机、SQLite、API 与组件测试。实际 STT/LLM 服务的限流与断网，以及移动端真机交互仍需独立验收；测试替身不代表真实供应商可用率。

后续[专项验收](./note-recovery-special-acceptance.md)已完成真实 Alibaba/DeepSeek 调用、连接断开与 HTTP 429 故障注入、处理进程强杀后的自然租约接管、Web 断网录制与强杀恢复及恢复原音服务端入库。发现并修复模型 SDK 连接错误未自动重试、共享 HTTP 取消监听器积累两项问题；最终相关回归 237 项通过。供应商实际限流容量、两小时浏览器实时录制和鸿蒙真机仍未由这轮证明；用户已要求本轮暂不测试鸿蒙。

本次不引入声纹身份、不承诺跨音频分片的同一说话人识别。后续声纹/说话人功能应基于同一份可校验原音和可版本化逐字稿继续演进。

# 右侧文件与 Sidechat 工作区：设计与实施计划

状态：设计基线，首版已进入实现与验证。日期：2026-10-18。

后续截图带来的工具起始页、文件浏览 Tab 和内置浏览器设计，以 [统一工具工作区与内置浏览器方案](./unified-workspace-and-embedded-browser.md) 为准；本文保留最初方案作为实施基线。

本文仅记录设计和实施计划，不表示功能已经实现。依据当前 Gateway Web 源码、用户提供的 Codex 截图及本轮交互确认整理；尚未进行运行中的界面和性能验证。

## 1. 目标与已确认方向

主界面保持左侧主聊天，右侧现有项目文件区域升级为多标签工作区。文件预览与 Sidechat 共用同一条顶部 Tab 栏，用户可以在查看成果、浏览文件和临时追问之间连续切换。

核心决策：

1. 左侧主聊天持续存在。打开文件、切换右侧 Tab、收起右侧区域，都不卸载主聊天，不丢失草稿、滚动位置或运行状态。
2. 右侧只有一条内容 Tab 栏，混合排列文件与 Sidechat；不在 Sidechat 内再放第二层会话 Tab。
3. 文件树是右侧工作区内可收起的辅助栏，位于内容最右侧，不是文件 Tab，也不是每个 Tab 重建一份文件树。
4. 没有内容 Tab 时，右侧回到文件树首页；仍可通过顶部「＋」创建侧聊。
5. 文件、侧聊、整个工作区分别有自己的关闭或收起语义，不共用含糊的 X 操作。
6. 首期即交付混合多 Tab。拖拽排序、固定标签和并排显示多个内容 Tab 留到后续。

## 2. 当前实现与差距

| 现有位置 | 已有能力 | 本次需要改变的部分 |
| --- | --- | --- |
| `web/src/components/shell/app-shell.tsx` | 主区域、右侧文件栏、Sidechat 挂载 | 文件预览目前与 `<Outlet />` 二选一；右侧文件栏与 Sidechat 也二选一，需统一布局 |
| `web/src/components/shell/workspace-column.tsx` | 文件树、搜索、目录操作、拖动宽度、系统打开 | 拆出可嵌入的文件树，不再独占整个右栏，也不管理全局预览开关 |
| `web/src/features/workspace/workspace-preview-pane.tsx` | 工作区预览入口、Escape 关闭 | 改为文件 Tab 的内容适配，不再替换主聊天 |
| `web/src/features/file-preview/file-preview.tsx` | 统一头部、渲染器、带文件进入新会话 | 复用渲染能力，适配工作区工具栏及当前会话引用 |
| `web/src/features/preview-runtime/` | 文件类型识别、加载、插件、预览控制器 | 状态从单活动文件扩展为逐 Tab 保存，并处理后台资源回收 |
| `web/src/features/chat/attachments/attachment-preview-dialog.tsx` | 附件加载、分享、图片切换、放大 | 拆出非 Dialog 的内容组合，允许作为右侧文件 Tab |
| `web/src/stores/workspace-preview-store.ts` | 单路径、行号、项目、会话、成果版本标记 | 统一打开命令、来源身份及多个文件 Tab |
| `web/src/stores/workspace-panel-store.ts` | 文件栏开关和宽度，当前宽度 200–520px | 区分紧凑文件栏与展开工作区，保存两种宽度偏好 |
| `web/src/stores/side-chat-store.ts` | 多侧聊、父会话归属、草稿、阅读副本 | 接入混合 Tab 顺序；保留领域状态，避免出现第二份 activeId/open 真相 |
| `web/src/features/side-chat/side-chat-column.tsx` | 标签、会话 UI、心跳、实时订阅、关闭保护 | 分离外壳、后台 controller 与活动会话视图 |

源码已确认的重点约束：

- Sidechat 当前只挂载活动会话组件，心跳、过期和运行订阅位于该组件的 effect 中。不能只将 JSX 搬到文件 Tab 旁边，否则切换后后台状态提示会失去维护。
- 工作区文本编辑采用 500ms 防抖保存，路径变化或卸载会取消待执行任务。多 Tab 必须先补足保存队列、草稿和关闭保护。
- 预览控制器目前在文件变化时重置页码、缩放等状态；新设计需由逐文件 view state 恢复。
- 现有成果版本字段用于展示标记，不能据此推断已经加载历史版本快照。
- 当前工作区读取、文件树作用域推导分散在多处；实施时统一为明确的文件根作用域，避免同名文件或项目与会话混用。

## 3. 布局与信息结构

### 3.1 文件树首页

```text
┌────────┬────────────────────────────┬─────────────────┐
│ 导航栏 │ 主聊天                     │ 项目文件  ＋  收起│
│        │                            ├─────────────────┤
│        │ 消息                       │ 搜索 / 文件树    │
│        ├────────────────────────────┤                 │
│        │ 输入框                     │                 │
└────────┴────────────────────────────┴─────────────────┘
```

此时右栏使用紧凑宽度。文件树首页不是一个可关闭的常驻 Tab，不占据混合标签序列。

### 3.2 活动文件 Tab

```text
┌────────┬──────────────────┬────────────────────────────────┐
│ 导航栏 │ 主聊天           │ 报告.md × │ 侧聊：分析 × │ ＋  收起│
│        │                  ├────────────────────────────────┤
│        │ 消息             │ 路径面包屑  预览/源码  文件树 ⋯ 放大│
│        │                  ├───────────────────┬────────────┤
│        │                  │ 文件预览           │ 搜索文件   │
│        │                  │                   │ 项目文件树 │
│        ├──────────────────┤                   │            │
│        │ 输入框           │                   │            │
└────────┴──────────────────┴───────────────────┴────────────┘
```

### 3.3 活动 Sidechat Tab

同一条标签栏下展示侧聊消息和独立输入框，文件树默认收起。用户可主动展开文件树；点击文件后激活或创建相邻文件 Tab，原侧聊留在原位置并继续运行。

### 3.4 尺寸建议

以下是待实机校准的首期设计值，单位为 CSS px：

| 项目 | 初始建议 |
| --- | --- |
| 无内容 Tab 的紧凑文件栏 | 默认 320，范围 240–420 |
| 有内容 Tab 的工作区 | 默认占主内容可用宽度约 60%，主聊天约 40% |
| 主聊天最小宽度 | 380 |
| 工作区内容最小宽度 | 460，不含展开的文件树 |
| 内部文件树 | 默认 240，范围 200–320 |
| 顶部标签栏 | 44 高；工具栏约 44 高，可按内容适配 |
| 分隔线 | 1px 视觉线，至少 8px 的交互命中区 |

判断依据为扣除左导航后的实际可用宽度，不使用一个固定设备宽度替代布局预算：

1. 主聊天 + 内容 + 文件树无法满足最小宽度时，先临时折叠文件树；不覆盖用户保存的展开偏好。
2. 主聊天 + 内容仍无法满足时，进入单列工作区，提供「返回聊天」。主聊天继续保留状态，隐藏区域不可被键盘聚焦。
3. 临时收窄后恢复宽度，按保存偏好恢复；单列中若用户明确选择返回聊天，不自动将其再次切走。
4. 用户拖动时同步更新布局，pointerup 后写入偏好，避免每个 pointermove 持久化；拖过 iframe 时使用拖动遮罩。
5. 紧凑文件栏宽度、展开工作区宽度和内部文件树宽度分别保存。Sidechat 与文件共享外层工作区宽度，切 Tab 不突然跳宽。

## 4. 混合 Tab 交互契约

### 4.1 创建与激活

| 触发 | 结果 |
| --- | --- |
| 文件树单击文件 | 激活已有文件 Tab；没有则在当前 Tab 右侧创建并激活；空工作区则成为首个 Tab |
| 主聊天点击文件链接或附件 | 打开右侧工作区，按来源去重并激活文件；保持主聊天阅读位置 |
| Sidechat 点击文件链接或附件 | 在同一工作区打开文件；记录返回来源为该侧聊 |
| 点击主聊天既有新建侧聊入口 | 创建侧聊成功后插入当前 Tab 右侧并激活 |
| 「＋ → 新建侧聊」 | 基于所属主会话当前上下文创建，不默认复制当前文件或另一侧聊全文 |
| 「＋ → 打开文件」 | 展开文件树并聚焦搜索框；没有内容 Tab 时进入文件树首页，不创建空文件 Tab |
| 点击已激活的 Tab 或同一文件 | 保持打开；有新的有效行号时执行定位，不切换关闭 |

首期每次打开都是普通标签，不引入“单击临时预览、双击固定”的隐式模式。双击文件也不重复创建 Tab。

新建侧聊请求进行中显示局部骨架/待创建状态并防止重复请求；只有服务端创建成功才登记正式标签。用户在等待期间切走时，成功结果加入原工作区但不抢回焦点；失败保留当前内容与重试入口。

### 4.2 标签外观、顺序与溢出

- 文件使用文件类型图标、文件名、未保存标记、关闭按钮；同名文件以父目录或来源补充区分，完整路径放在提示中。
- Sidechat 使用对话图标、现有标题或“侧聊 1/2…”的本地兜底名称，显示“临时”语义，不为命名新增模型调用。
- 标签顺序按插入位置保存；首期不支持拖拽排序、固定标签、关闭其他标签或批量结束侧聊，避免引入额外关闭语义。
- 标签可横向滚动；新增/激活标签滚入可见区域。「＋」、文件树开关、收起入口固定可达；溢出列表可显示完整标题和状态。
- 当前 Tab 与键盘焦点独立可辨识。状态除颜色外，还需图标或文字描述。

### 4.3 Sidechat 标签状态

| 状态 | 标签反馈 | 打开后的行为 |
| --- | --- | --- |
| 正在运行 | 运行指示 | 展示当前流式消息与停止操作 |
| 待审批 / 待回答 | 明确的待处理标记，优先于普通未读 | 展示原交互，不自动提交 |
| 后台新增消息 / 回合结束 | 未读点；回合结束可附短暂完成反馈 | 消息同步成功且视图可见后清除已读标记 |
| 连接中断 | 连接异常标记 | 保留草稿和阅读内容，允许重连 |
| 已结束 / 不可用 | 文字状态 | 保留阅读态和重建入口，按既有规则带入草稿 |
| 已转为正式会话 | 已保存状态 | 复用现有正式会话入口 |

文件被动刷新不标成侧聊未读。收起整个工作区后，主聊天工具栏的工作区入口聚合运行数、待处理数和未读提示，不自动展开、不抢焦点。

### 4.4 关闭与收起

| 操作 | 行为 |
| --- | --- |
| 切换 Tab | 保留原 Tab；不结束侧聊、不取消文件保存 |
| 收起工作区 | 仅隐藏；保留 Tab、草稿、后台运行与订阅，不视为明确对话活动 |
| 关闭只读且无草稿的文件 Tab | 移除标签，释放其可释放资源 |
| 关闭有待保存内容的文件 Tab | 先完成保存；失败或冲突时保留标签，提供重试、保留编辑或明确放弃 |
| 关闭活动侧聊 Tab | 沿用既有结束确认；运行中明确“停止并关闭”；已执行工具效果不回滚 |
| 关闭已结束的侧聊 Tab | 按既有草稿/阅读副本保护规则移除 |
| 关闭最后一个内容 Tab | 回到紧凑文件树首页，工作区保持打开 |
| 浏览器刷新/离开页面 | 不主动结束侧聊；待保存编辑使用适用的离开保护；本地草稿边界按第 8 节说明 |

关闭非活动 Tab 不改变当前活动 Tab。关闭活动 Tab 时先返回其仍存在的打开来源 Tab；否则选择最近使用的剩余标签，最后回到文件树首页。取消关闭不改变活动标签和顺序。

侧聊关闭属于服务端操作：提交后标记 closing 并防重复；成功后移除。断网或请求失败保留标签和草稿并允许重试；已确认过期/不存在时按结束态规则处理，不能先删本地状态再静默忽略失败。

现有“不再询问”偏好继续适用于既有侧聊关闭确认；不扩大到文件编辑的保存失败、冲突或明确放弃内容。

## 5. 文件树的规则

### 5.1 文件树与 Tab 的关系

文件树是单实例的辅助视图。内容 Tab 关闭不删除文件；文件树收起不关闭内容 Tab；展开/折叠目录也不改变活动标签。

| 场景 | 文件树行为 |
| --- | --- |
| 文件树首页 | 始终可见；没有可预览文件也保留搜索和「＋」入口 |
| 首次进入文件 Tab | 宽度允许时默认展开；之后遵循文件类型视图的用户偏好 |
| 首次进入 Sidechat Tab | 默认收起；之后遵循 Sidechat 视图的用户偏好 |
| 点击“在文件树中定位” | 显式展开、加载祖先目录并滚动到选中项；不足宽度时用临时目录选择层 |
| 当前来源不是可浏览工作区 | 不虚构对应树路径；可显示所属主会话的文件树，头部明确根目录，当前附件无选中项 |

文件视图与 Sidechat 视图分别记忆树是否展开；按文件根作用域保存搜索条件、展开目录和树滚动位置。窄屏自动收起与用户手动收起是不同状态。

### 5.2 文件根作用域

- 工作区文件 Tab 使用其打开时解析得到的根作用域：项目、会话或 Agent，保存确定后的 source，不在切 Tab 时重新猜测。
- Sidechat 旁的文件树默认使用所属主会话的根作用域；从侧聊解析得到的特定任务/文件来源必须随新文件 Tab 保留。
- 从附件打开的文件不因同名而冒充项目文件；只有资源解析确认关联后才在树中定位或合并身份。
- 如果活动文件根与所属主会话默认根不同，树头部显示当前根名称；切换后恢复该根自己的目录状态。
- 文件树展示和文件读取使用同一套作用域解析结果。项目、会话和任务来源的优先级集中处理，不能分散在组件中互相覆盖。

### 5.3 搜索与文件操作

- 复用已有搜索语义，明确是已加载目录过滤还是服务端搜索；未经后端支持不宣称全项目全文搜索。
- 重命名成功后更新同一资源的标签标题、路径和定位；不新建重复标签。
- 删除成功后，已打开文件 Tab 保留“文件已删除/不可用”状态及可恢复的编辑草稿；不静默关闭或继续写入旧路径。
- 外部移动或路径失效，重新解析资源；无法恢复则提供重试、下载可用草稿或关闭。
- 文件拖入主聊天或侧聊输入框时保留文件 Tab，不再因为 dragstart 清空预览；引用添加后由用户主动发送。

## 6. 文件预览与聊天联动

### 6.1 支持范围与工具栏

复用现有文件类型和插件，不将本次布局升级扩展为重写渲染引擎。文件 Tab 的可用操作由来源和实际能力决定。

| 内容 | 首期行为 |
| --- | --- |
| 文本、代码、Markdown、HTML | 复用阅读/源码能力；只有可写工作区来源允许编辑 |
| PDF、图片 | 复用页码、缩放、旋转等现有能力，逐 Tab 恢复 |
| DOCX、表格、PPTX | 复用现有渲染与提取文本回退，不承诺 Office 编辑能力 |
| 音视频 | 活动 Tab 内播放；切走/收起暂停，不后台自动播放 |
| ZIP、不支持类型、超限文件 | 复用目录/元数据或下载回退，不强行加载 |

工具栏固定显示文件名/面包屑及必要状态、文件树开关、更多、放大。正文操作按文件类型显示；下载、分享、复制路径和系统打开收在更多菜单。网页与 Electron 按真实能力展示系统打开入口。

图片默认作为文件 Tab 打开，组图前后切换保留为明确导航；若目标图片已有 Tab 则激活，否则新建目标 Tab，不改写当前 Tab 身份。灯箱作为显式放大操作，不承担默认附件打开入口。

公开分享页继续使用独立预览，不注入聊天工作区。项目详情的独立文件页继续保留自身布局；本次优先统一主聊天及其 Sidechat 的文件入口。任务详情弹窗和其他嵌套预览需单独验证层级及关闭顺序，不能机械替换全部 Dialog。

### 6.2 引用文件

- 打开或浏览文件不自动加入模型上下文。
- 文件工具栏提供“引用到主聊天”。文件由 Sidechat 打开时，再提供“引用到来源侧聊”；目标必须明确，不能依赖最近聚焦的输入框。
- 引用优先复用现有资源引用协议；尚无引用能力的本地附件使用现有附件 handoff，并校验大小与目标能力。
- 操作只添加引用/附件到目标草稿，提示已添加，不自动发送；主聊天和侧聊的草稿互不覆盖。
- “在新会话编辑”保留为次级操作，并继续继承适当的项目/Agent 信息。
- 精细的选区、页码和代码行范围引用作为后续增强，不阻塞首期整文件引用。

### 6.3 编辑、更新与版本

每个可编辑 Tab 独立维护草稿、dirty、待保存任务、保存结果和已读取版本。切换 Tab 不依赖组件卸载触发保存。

1. 继续使用自动保存，但写入按同一文件串行执行，旧响应不能覆盖新草稿状态。
2. 切换允许即时发生；草稿和待保存任务留在 Tab controller 内。关闭或离开时等待保存，并展示失败/冲突保护。
3. Agent 或外部应用更新文件：只读且无本地编辑时可重新验证后刷新，保留尽可能合理的页码/滚动；有 dirty、保存中或源码编辑时先提示，不覆盖。
4. 首期必须有显式刷新入口，并在回合结束、页面重新可见等事件触发去重的重新验证。只有确认已有文件变更事件可用后才直接订阅；不默认新增全目录轮询。
5. 实施前核对写入 API 是否支持原子版本检查。仅前端比对 mtime 不足以防止读写间覆盖；若缺失，应作为编辑并发保护的独立后端子任务补齐，未完成前不得宣称冲突安全。
6. 成果版本标记不等于历史快照。没有可读取的历史资源时，明确展示当前文件，不以旧 revision 标记暗示内容已冻结。

放大默认只扩大当前文件预览，不铺满所有工作区控件；返回后恢复原 Tab、工作区宽度、树状态和阅读位置。放大不卸载主聊天及后台 Sidechat controller。

## 7. Sidechat 生命周期与后台维护

沿用 [既有生命周期设计](./side-chat-lifecycle-prd.md)：临时会话的过期、主动延长、结束阅读态、草稿重建和容量限制保持原有语义；Tab 切换、心跳和展开面板不构成延长活动。

后台维护与可见消息视图分离：

- 每个尚未结束且被客户端跟踪的侧聊，有独立 controller，负责状态同步、运行 topic、过期 topic、心跳和断线补偿。
- controller 生命周期归属于当前网关/身份下的侧聊记录，不归属于活动 Tab 或当前主会话视图。切到文件、其他父会话、收起工作区时继续维护。
- 服务端继续执行与前端持续收流是两件事：不能仅凭服务端运行未取消就显示“后台状态已同步”。重连、topic gap 和页面恢复需要重新查询权威状态及消息，处理重复事件。
- 只渲染活动内容 Tab 的重型消息列表、编辑器或文档渲染器，非活动侧聊只保留 controller 和受预算约束的必要状态。
- 待审批或待回答只提示，不抢占当前 Tab、不自动执行、不将旧交互转移到新会话。
- 已结束侧聊停止心跳及运行订阅，保留既有有界阅读副本和草稿；不为了保留标签继续保活服务端。
- 结束态“新建并带入草稿”成功后原位替换对应混合标签，创建失败保留旧标签和草稿。
- 转为正式会话继续复用既有行为；文件 Tab 与其他侧聊的顺序不改变。
- 收起不取消服务端运行；退出账户或切换网关后解绑订阅并清理当前身份的客户端内容，不在新身份界面显示旧记录。

## 8. 状态模型、身份与恢复

### 8.1 单一状态归属

建议新增 `right-workspace` 功能模块和工作区 store；以下是职责设计，不要求按示例名称逐字实现。

| 状态 | 唯一归属 |
| --- | --- |
| 工作区 open、标签顺序、activeTabId、最近使用顺序 | 工作区 store |
| 工作区和树宽度、显示偏好 | 工作区布局状态，按视口模式约束 |
| 文件 source、解析身份、阅读位置、编辑草稿/保存队列 | 文件 Tab controller/文件状态 |
| Sidechat 服务端状态、run、草稿、阅读副本 | 既有 Sidechat 领域 store/controller |
| 文件树根、展开目录、过滤条件、选中项、滚动 | 按根作用域管理的文件树状态 |

混合 Tab 记录仅含标签身份、类型、来源引用、标题、创建来源、访问顺序等壳层信息。Sidechat Tab 引用 sideChatId，不复制其消息和 run 状态；文件 Tab 引用规范化后的文件身份，不用显示文件名去重。

工作区 store 成为 activeTabId/open 的唯一真相。旧 store 的兼容入口只转发命令；不能让两个 store 相互监听 setState 维持双写。

### 8.2 身份与作用域

- 工作区所属范围为“网关/身份命名空间 + 主会话 conversationId”。新会话尚无 id 时使用临时范围，正式创建后原子迁移，不能丢弃刚打开的附件。
- 主会话归属用于决定右侧标签集合；文件来源用于决定读取和编辑，两者分开。项目根相同的两个主会话仍可有独立标签集合。
- 文件去重优先使用经过权限校验的稳定资源 ID 和必要的资源版本；无稳定 ID 时使用根作用域 + 规范化路径。解析异步完成后合并别名，保留活动状态及编辑草稿。
- 已存储附件按资源 ID / 受控 URI 识别；未发送本地附件使用页面内稳定 id 和 File 引用，不序列化二进制或 Blob URL。
- 临时 sideChatId 在所属主会话内引用；跨父会话打开不能悄悄重绑侧聊上下文。
- 身份命名空间使用客户端已有的非敏感标识；不把原始授权 token 用作存储键或写入 URL。

### 8.3 持久化和刷新边界

| 数据 | 保存策略 |
| --- | --- |
| 宽度、树开关偏好 | localStorage，带版本与范围校验 |
| 主会话内的标签描述、顺序、最后活动标签 | sessionStorage，恢复时重新校验权限和资源可用性 |
| 文件页码、缩放、滚动、预览/源码模式 | 轻量逐 Tab 状态，可随标签描述恢复 |
| 文件正文、二进制、Blob URL、授权信息 | 不写入以上存储 |
| Sidechat 草稿与已结束阅读副本 | 沿用页面内存保护，不扩大为长期保存，也不承诺刷新恢复 |
| 可编辑文件未保存内容 | 首期保护页面内切换和关闭；刷新/离开提示，不承诺崩溃后恢复 |
| 未发送本地附件 | 仅当前页面可用，恢复时明确需重新选择，不伪装成已恢复文件 |

活动 Tab 与树展开状态同步到路由 query，以支持当前会话内的前进/后退和刷新。首次打开、显式切换/关闭使用统一导航命令，浏览器返回只恢复界面选择，不调用侧聊删除 API，也不复活已关闭侧聊；必要时回退文件树首页。

URL 使用经过校验的标签/资源引用，不暴露原始绝对路径、媒体凭证或本地附件内容。sessionStorage 中的本地 Tab id 仅支持同一浏览器会话恢复，不宣称跨设备深链接。需分享文件时使用已有分享链接能力。调整宽度和滚动不写入 history。

### 8.4 资源预算

- 重型预览只挂载活动文件；切换前保存轻量 view state。文件自动保存由 controller 继续维护。
- 二进制缓存建议以总字节预算控制，初始预算 64 MiB，按最近使用淘汰只读且非活动内容；最终数值由现有预览大小限制及实测校准。
- dirty 文本、保存失败草稿不因缓存淘汰而删除；超预算时提示先处理编辑，不能静默丢弃。
- 关闭/淘汰对应资源后释放 Blob URL、PDF/Office 实例、事件监听及 worker 引用；共享资源需引用计数。
- Sidechat 阅读副本继续复用既有字节和数量上限，不为混合 Tab 另建无界消息缓存。运行中视图状态与结束阅读副本分别核算。

## 9. 键盘、反馈与视觉规范

- 使用现有 `globals.css` 语义 token、Lucide 图标和设计系统；不引入第二套颜色或组件主题。
- Tab 栏采用 tablist/tab/tabpanel 语义，方向键移动焦点，Enter/Space 激活，Home/End 到首尾；关闭按钮有完整文件名/侧聊名的无障碍标签，避免嵌套 button。
- 加号菜单使用现有菜单/弹层组件，明确新建侧聊和打开文件；涉及选项选择使用项目已有 Select 组件。
- 分隔线可聚焦，支持方向键调整及恢复默认宽度，提供 separator 的当前值和上下界；不能只支持鼠标拖拽。
- 新增后台状态温和播报，不逐 token 播报。界面数据加载使用骨架，保存/刷新等主动操作可用按钮级 spinner。
- Escape 只由最上层有效交互处理：菜单/子弹窗 → 退出预览放大 → 关闭窄屏临时文件树；普通分栏下不以全局 Escape 关闭 Tab 或结束侧聊。
- 不覆盖浏览器 Cmd/Ctrl+W；工作区 Tab 关闭使用可见按钮。后续如新增快捷键，需先检查既有命令冲突。
- 关闭当前 Tab 后焦点落到新活动标签；收起后回到工作区入口；切换期间主聊天输入不意外失焦。焦点在文件树显式打开文件时可移到新 Tab/预览标题。
- 移动端不自动弹键盘；点击目标输入框后再输入。桌面 Sidebar 不因打开文件自动改变用户偏好。

- 确定工作区作用域、标签去重键、URL 参数、旧存储迁移和保存队列契约。

交付门槛：形成入口清单和状态转移用例，明确后端缺口；不以未验证 API 能力推进编辑冲突设计。

### P1：统一状态与右侧外壳

交付门槛：主聊天在打开/切换/收起时不重挂载；混合标签顺序、焦点、恢复和尺寸行为可验证。此阶段可先用轻量内容适配验证外壳，不能作为最终交付。

### P2：文件 Tab 与文件树接入

工作：

- 从 WorkspaceColumn 拆出树内容与作用域状态，从附件 Dialog 拆出内容适配。
- 复用 FilePreview/PreviewRuntime，支持工作区文件、存储附件、本地待发送附件及图片。
- 接通统一入口、去重、逐文件阅读状态、树定位、重命名/删除后的状态处理。
- 完成逐文件草稿、保存串行队列、切换/关闭保护、版本验证及更新提示；必要后端子任务同步完成。
- 取消文件拖动清空预览等旧联动，加入明确目标的文件引用。

交付门槛：两份同名不同来源文件不串内容；连续编辑/切换不丢最后一次输入；文件树收起与文件关闭互不影响；原有独立分享和项目文件页正常。

### P3：Sidechat 混合 Tab 与后台 controller

工作：

- 分离 SideChatColumn 外壳、会话 view 和 controller，将侧聊标签接入统一顺序与 activeTabId。
- controller 脱离活动 Tab，维护运行/过期/心跳/重连，接通后台状态与工作区入口聚合提示。
- 完成＋新建、创建期间切换、失败重试、原位重建、关闭确认及失败保留。
- 保留临时性、阅读副本、草稿和正式会话转换；文件点击回链到来源侧聊。

交付门槛：侧聊运行时切到文件、其他主会话或收起区域，运行继续且状态可补偿恢复；审批不自动提交；关闭失败不丢标签；没有嵌套第二条 Tab 栏。

### P4：联调、迁移和清理

工作：

- 迁移旧 Sidechat 标签、activeId/open 和文件栏宽度偏好；旧单文件预览转为所属工作区首个文件标签。
- session 存储结构增加版本；损坏或不支持的记录安全回退，去除重复标签，不删除服务端侧聊。
- 当前代码存储键 `xopc:side-chat-panes:v3` 等在实施前重新核对，完成一次性迁移，移除长期双写适配。
- 完成键盘/触屏/主题/Electron/窄屏验证、资源释放与已有侧聊生命周期回归。
- 清理旧 AppShell 全局预览替换分支和全局 Escape 关闭逻辑；保留独立页面仍需使用的预览能力。

交付门槛：验收矩阵通过、必要测试和 Web 构建通过，无需用户清空浏览器存储才能继续使用。

首期必须完成：统一右侧外壳、文件与 Sidechat 混合多 Tab、＋入口、最右文件树、两层尺寸调整、统一文件入口、保存保护、后台侧聊维护、明确关闭语义、当前会话引用、恢复迁移、窄屏与无障碍。

后续再评估：拖拽排序、固定标签、临时预览标签、两个内容 Tab 并排、选区精细引用、跨窗口同步、完整崩溃草稿恢复、历史成果快照浏览。当前设计不将这些能力作为首期已具备条件。

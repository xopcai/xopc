# 主动助理分阶段实现与自查

实现日期：2026-09-13，场景化重构完成于 2026-09-15。对应设计：`proactive-product-experience.md` 与 `proactive-scenario-product.md`。

## 场景化重构：从配置对象到用户时刻

- 工作台统一消费 `scenes`，每个场景直接表达当前时刻、相关性、助理已经完成的帮助、待决定动作和原工作对象入口。
- 首页不再按「需要决定 / 已准备 / 更新」三种通用卡片分栏；项目、会议与沟通使用各自的场景语义。
- 项目详情原地建立「守住这个项目」的安排；「助理安排」移入二级导航，只保留自然语言承诺、提醒方式、暂停/结束和行动边界。
- 行动边界复用项目已有的 `observe / ask_before_action / auto_low_risk` 策略；自动低风险动作目前只允许在当前项目创建可撤销待办。
- 结果详情支持“有帮助 / 不适合”和自然语言纠正。纠正形成同一场景的版本化要求，不复制安排，也不扩大权限。
- 对话手册在一次性成果被采用且适合重复时，询问是否以后继续这样做；只有用户明确接受才建立或更新安排。

自查修复：移除产品 DTO 对运行历史、调度和扫描间隔的依赖；删除通用模板、订阅创建、预览、运行历史和旧卡片 API；删除只剩测试调用的预览执行逻辑及存量数据表；修正数据库版本到 166，确保删除迁移真正执行；将前端遗留运行状态映射收窄为用户可见的卡片状态。

阶段验证：主动性、路由与权限边界 8 个测试文件 68 项通过；数据库迁移与产品体验 2 个文件 39 项通过；最终场景呈现回归 9 项通过。根类型检查、Web lint、Web 生产构建和真实鉴权 HTTP 冒烟均通过。生产构建仍报告仓库已有的大分包提示。

## 第一阶段：交代项目，拿到成果，跟进实际结果

- 首页直接展示「需要你决定 / 已为你准备 / 值得知道」。提醒设置退到次级入口。
- 项目页可以发起委托，也可通过对话中的 `xopc_use mode=proactive` 发起、调整、暂停或检查。
- 用户只交代范围和要求。第一次项目检查立即进入现有队列，后续按已有事件和定时扫描运行。
- 原有只读分析直接产出完整 Markdown 清单、简报或草稿，卡片可查看、复制和编辑。
- 创建项目待办前可以审阅和修改具体标题、内容；实际创建仍经过现有项目授权与 TaskApplicationService。
- 回显真实任务 ID 和状态。收起卡片、用户声明已处理、任务真正完成分别表达；项目结束后停止关注。

自查修复：保留项目的置信度门槛；创建待办使用用户最终审阅的内容；幂等请求不重复创建任务；旧 revision 不得覆盖新内容；自动分析不得覆盖用户编辑过的成果；全局关闭时仍可记下委托，如实显示暂停状态，不会出现记录已创建但接口报错的情况；首页旧汇总不再重复显示主动卡片。

阶段验证：108 项相关测试通过，根项目类型检查、Web 构建和带鉴权的真实 HTTP 冒烟通过。

## 第二阶段：会前准备与提醒时机

- 读取已经授权同步的日历，会议前 24 小时和 2 小时检查。
- 排除全天事件、取消会议、本人拒绝参加和缺少有效标题的事件。
- 来源版本包括内容 hash 和会议时间。会议改期使旧成果失效，并更新同一会议卡片；取消或撤权会撤回卡片和待发提醒。
- 分析开始和结束之间重新比较授权上下文；资料变化时丢弃旧分析结果。
- 在投影、卡片读取、实际执行和通知投递前继续检查来源，避免生成结束后发生变化而交付过时内容。
- 「重要时找我」下，普通准备成果安静进入首页；已有摘要、免打扰、每日预算、多端通知机制继续复用。
- 前台活跃判断覆盖整个 Web 应用，不再要求用户停留在主动助理设置页。

自查修复：日历时间统一使用存储层 ISO 表示；摘要判断先于普通提醒级别过滤；已过期成果不能继续执行；会议关联任务、笔记的版本变化也会让准备成果失效。

阶段验证：94 项主动性与连接器相关测试通过，包括改期、取消、生成中变化、通知取消。

## 第三阶段：邮件跟进与原对话续办

- 用户从已授权同步的邮件选择一段往来，交代目标和下次跟进时间。
- 新增一个聚焦的 `proactive_follow_ups` 表保存具体委托；复用已有订阅、事件、队列、只读执行和卡片系统。
- 邮件线程身份包括来源实例、集合和账户，避免不同邮箱中相同 provider thread ID 串线。草稿箱、垃圾箱和垃圾邮件不进入跟进上下文。
- 邮件内容或线程成员发生变化、到达约定时间时才触发检查；相同状态不会反复生成提醒。
- 来源新增回复会使旧草稿失效，包括在生成期间到达的新回复。
- 完整草稿可编辑、复制；「审阅草稿并继续办理」接回已有对话，由现有连接器工具使用准确账户、参数确认和执行回执完成发送。
- 后台分析不持有发送工具，也不生成伪装成发送操作的卡片按钮。发送成功必须以连接器结果为准，不能由草稿或确认状态推断。
- 已同步的 SENT 邮件显示为发出后继续观察；新来信继续触发判断，直到用户结束委托。不会把发送成功自动当作目标完成。
- 每项可暂停、恢复、改要求或结束；展示最近检查、真实同步时间和同步失败状态。删除办理对话会清空关联，下次可开启新对话。

自查修复：严格 revision 更新；重复线程委托需修改已有事项；跨 workspace 和撤权访问被拒绝；暂停期间不能继续办理；同步检查时间与邮箱实际同步时间分别显示；所有新 API 已验证 lazy bundle 映射及带鉴权 HTTP 路径。

## 简化与移除

- 移除「先选准备 Workflow 再生成」的后端、前端组件和 `proactive_workflow_links` 表。
- 迁移清除 `preparationWorkflowId`，接口不再提供 `preparationAvailable`。
- 移除旧订阅配置表单和未使用的预览组件，使用成果页与委托入口。
- 移除旧订阅绕过通知策略的双轨处理。
- 不引入第二套自动化引擎、独立卡片工作流、任意 A2UI 运行时或新的发送通道。
- 数据库升级至 166。迁移负责升级存量数据并删除不再使用的预览表，运行时不保留旧流程的兼容分支。

## 整体验证与上线边界

- 最终 19 个测试文件、168 项测试通过，覆盖主动性、连接器归一化/摄取、Composio 确认与账户执行边界、迁移、鉴权路由映射和 `xopc_use`。
- 随后新增全局暂停时首次委托的回归用例，并重跑项目委托的 5 项测试。根项目类型检查、Web 类型检查与生产构建、变更文件 lint 均通过；构建仍有现有大分包提示。
- `scripts/proactive-smoke.mts` 启动真实 Gateway HTTP 栈，在临时数据库中验证委托、检查、成果编辑、任务批准、邮件委托和 revision 冲突。测试不调用模型或外部通知服务。
- 在实际浏览器中检查成果首页、打开成果、修改 Markdown 并保存，以及邮件委托入口。修复工作台已有主动成果却显示「一切都处理好了」的问题，并移除重复卡片。使用隔离测试数据。
- 真实邮箱发送、真实日历账户和设备推送到达仍需发布环境联调。当前通过的是本地状态链路与既有连接器确认边界，不能把它等同于真实投递成功。
- 跟进基于连接器已同步的数据：Gmail 现有默认学习计划每 15 分钟同步，初始范围最近 30 天；界面选择最近同步的线程。后台 Gateway 必须运行。
- 新增分析成果的质量仍取决于模型和输入资料，需用真实用户的采纳、编辑、关闭与重复提醒数据继续评估。

# 个人助手 Onboard：身份、声音与数据连接

> 产品与交互方案 · 2026-10-07 · 待评审  
> 范围：Gateway Web 与桌面应用的“我的助手”首次创建。全局模型配置是前置条件；本方案不改变 CLI `xopc onboard`。

## 目标

让用户在进入第一段对话前，亲手确定这个助手的**头像、名字和声音**，并有机会连接需要的数据。整个过程应让人感到“正在建立自己的助手”，同时不要求用户先交出邮箱或完成一份人格问卷。目标是从点击入口到能够发出第一条消息，主要路径只需四屏；任何外部连接与语音服务配置都可以跳过。

参考 [dots 的初始化说明](https://learn.chatgpt.com/docs/dots/getting-started)中“介绍 → 可选连接 → 创建 → 对话”的路径，以及 [Muse 的设计说明](https://introducing.muse.ai/)对稳定身份、可查看活动和权限的强调。xopc 保留自己的 Loopi 形象与设计语言。这里的声音指助手**说话时的音色**，不代表麦克风权限或语音识别模型。

## 入口和整体流程

```text
首次打开“我的助手”
  → ① 认识助手（简短承诺）
  → ② 形象与名字
  → ③ 声音偏好
  → ④ 外部数据（可选）
  → 创建身份与固定主会话
  → 主会话：可直接说话，也可选一项回应偏好

再次进入
  → 已完成：直接进入同一主会话
  → 未完成：恢复上次编辑的屏幕，也可立即用默认值创建
  → 创建中断：恢复或重试同一身份，不新增主会话
```

全局模型向导与个人向导不同时显示。若没有可用的个人助手模型，显示明确的模型配置入口，完成后回到当前步骤。个人向导只在用户进入“我的助手”时出现；已有个人助手的用户不被重新拉入。

界面采用完整内容区，顶部固定“返回 / 步骤 1–4 / 退出”，底部固定主按钮；内容区独立滚动。移动端保持选择卡和底部按钮可触达。每屏实时更新右侧或顶部的头像与名字预览；关闭页面不丢已确认的草稿。

## 逐屏交互

### ① 认识助手：说明能做什么

标题：**“创建一个和你一起做事的助手”**。用三句短文案说明它能持续对话、把工作交给合适的 Agent 并带回结果、在需要你决定时找你。显示“工作依赖当前 xopc 和已连接的设备；具体权限由你决定”。主按钮“开始设置”，次按钮“使用默认设置，直接对话”。后者创建默认头像、名称和声音偏好为空的助手，不触发外部连接。

### ② 形象与名字：先建立身份

- 默认名称为 **Ada**，输入框可编辑，实时预览会话顶部的称呼；清空时恢复默认值。提交时去除首尾空格，限制 1–60 字符。
- 展示现有 Loopi 的三个形象选项，选中后立即预览。颜色或情绪图形只影响视觉，不暗示能力和人格差异。
- “上传自己的图片”是次级选项；选择文件后在本地预览并给出大小、格式错误。头像实际上传在身份创建成功后执行；上传失败保留默认形象并提供重试，不阻断进入对话。
- “怎么称呼你”可留到对话中，不占此屏。底部按钮“继续选声音”。

### ③ 声音偏好：可试听，文字体验不受影响

- 标题：**“想让我用什么声音回应？”**，说明“只影响语音通话和朗读，文字回答不受影响”。
- 从当前可用语音目录展示少量适合界面语言的音色卡。每张卡有名字、简短音色描述、试听按钮和选中状态；试听同一段中性短句，切换音色时停止上一段播放。提供“使用系统默认声音”。
- 已配置可用语音服务时允许试听和保存选择；未配置时展示“设置语音服务”入口与“先跳过，继续用文字对话”。不得把尚不能发声的音色显示为已可用。
- 麦克风权限只在用户首次发起通话时请求。试听不请求麦克风权限。试听错误保持当前选择，并允许重试或跳过。
- 个人助手的音色必须只作用于其固定会话。保存的选择不应覆盖全局语音设置或其他 Agent 的声音。若当前运行时还不支持会话级音色，交付此屏前需补齐服务端解析，不能只保存一个不会生效的选项。

### ④ 外部数据：连接由用户决定

标题：**“要让我了解哪些信息？”**，副文案说明“你可以现在连接，也可以进入对话后再添加”。显示已连接服务与少量建议项，例如日历、邮件、云盘、GitHub；列表来自实际可用连接器目录，不显示无法安装的假入口。每张卡展示可读取的数据范围、连接状态和“连接”按钮。连接动作进入现有授权流程，回来后在原屏更新状态。

连接服务、允许读取某个范围、进行一次资料整理、建立持续关注是四个不同决定。此屏只办理用户选定服务的连接授权；不会自动读取历史邮箱、扫描文件、创建定时任务或打开通知。需要首次资料整理时，应在后续对话中说明来源、范围和产出，再单独启动。底部主按钮始终是“进入对话”；未连接任何服务时无需解释或挽留。

## 创建与首次对话

点击“进入对话”后，显示简短的准备状态：**创建助手 → 建立主会话 → 保存你的选择**。同一用户的重试必须返回同一个 Agent ID 和 conversation ID。若名称、形象或音色保存失败，清楚指出失败项和重试入口；已有成功的创建步骤不重复执行。

完成后进入固定主会话，顶部展示刚选的头像和名字。空会话呈现一句欢迎语与可点击的快捷提问：“你希望我先听你说、一起理清，还是直接给建议？”以及“先聊正事”。用户可以直接输入任何请求；输入具体任务时立即收起引导。快捷项若被选中，写入明确偏好并在下一条真实回复中生效。欢迎卡是界面内容；若未来让模型主动发出介绍，则必须持久化为真实会话消息并保证只发送一次。

进入会话后设置入口中可随时修改头像、名称、声音和连接；音色页仍能试听。没有语音能力时文字会话正常工作，通话入口说明如何启用。

## 状态与权限规则

| 情形 | 产品行为 |
|---|---|
| 用户退出向导 | 保存草稿与当前步骤；下次进入可继续或直接使用当前选择创建 |
| 刷新、授权跳转或 Gateway 重启 | 从持久状态恢复；已连接的服务重新读取真实状态 |
| 模型不可用 | 保留选择，给出模型配置入口；不创建无法工作的个人助手 |
| 语音目录为空或试听失败 | 可跳过声音；不影响创建或文字会话 |
| 单个连接失败或取消授权 | 留在数据连接屏，显示该服务的失败状态；仍能进入对话 |
| 创建请求超时或重复点击 | 查询现有创建结果并幂等恢复，避免第二个助手或会话 |
| 用户已创建助手 | 直接进入主会话；修改资料走设置，不重放向导 |

草稿只保存明确选择的头像、名称、音色和当前步骤；不把第三方 OAuth 凭据或原始数据放进草稿。授权状态来自连接器服务。完成状态应由服务端记录，不能仅靠浏览器 `localStorage`，否则换设备或清缓存会重放流程。已有 Agent 的 `ready` 状态优先于草稿。

## 与现有实现的衔接

- 当前 `PersonalPage` 只有单屏“开始对话”，POST `/api/personal-agent` 后直接进入聊天；将它替换为单独的个人向导容器，主会话页面保持稳定路由 `/personal`。
- 复用已有个人 Agent 创建与资料更新接口、Loopi 形象、头像上传、语音目录与试听、连接器安装授权组件。头像上传目前要求已有 Agent ID，故上传文件需暂存至创建完成。
- 个人声音需要在 Agent 资料中持久化 `voicePreference`（建议包含 provider、model、voice 与可用性检查），并在个人会话的语音 preflight、session 与试听路径按会话解析。当前平台语音选择会修改全局配置，不能直接拿来保存个人音色。
- 给个人向导增加服务端草稿与完成标记，例如 `GET/PUT /api/personal-agent/onboarding`；创建仍由现有幂等的 `POST /api/personal-agent` 执行。新认证路由须同步更新 lazy-bundle 匹配和映射测试。
- 连接器屏复用已有可用目录与连接状态；不复用 Work Discovery 的自动扫描启动行为。

## 建议的交付顺序与验收

1. **身份流程**：四屏、草稿恢复、默认值、头像与名称、创建幂等、进入固定主会话。
2. **声音闭环**：可用音色目录、试听、个人会话级选择与通话生效、不可用时跳过。
3. **数据连接**：现有授权流程嵌入、授权返回恢复、真实连接状态、单项失败可继续。
4. **首次对话**：欢迎卡、快捷偏好、直接发任务时收起引导、设置中的回访入口。

验收时至少覆盖：零连接器、零语音服务、模型缺失、授权取消、试听失败、刷新恢复、连续两次创建、头像上传失败、已创建用户再次进入，以及两个不同 Agent 的声音互不影响。关键体验指标为首次成功发消息的完成率、从进入向导到首条消息的用时、各步骤跳过率与授权取消后的继续率；不以连接器授权数量作为向导成功指标。

# 移动端语音产品方案

日期：2026-09-05。状态：代码已实现，真机发布验收待完成。分阶段改动、自查与验证见 [交付记录](./mobile-voice-delivery.md)。

配套：[技术方案](./mobile-voice-technical-design.md)。遵循 [移动端设计系统](../../apps/mobile-expo/DESIGN.md)，延续 [语音体验方案](./voice-experience-redesign.md) 的两个入口与同一 Chat 原则。涉及移动端入口、后台行为和设置的新增决策，以本文为准；历史交付记录不作为本方案的完成凭证。

## 1. 产品定位与范围

语音是使用当前助手的一种方式。用户在同一 Chat 内，可以打字、听写或持续通话，离开通话后仍能找到上下文和结果。

核心承诺：点一次即可开始；知道是否正在收音；能立即停止回答；挂断不丢对话；恢复不重复办事。

| 场景 | 用户目的 | 主要路径 |
| --- | --- | --- |
| 快速表达 | 不方便打字，想检查后再发 | 语音输入 → 完成 → 编辑草稿 → 发送 |
| 连续交流 | 讨论想法、练口语、日常聊天 | 语音通话 → 自然接话 → 结束 |
| 指挥助手 | 查询信息、安排工作、查看结果 | 通话 → 简短进度 → 必要确认 → Chat 结果 |
| 边走边聊 | 收起页面或锁屏后继续 | 开启后台通话偏好 → 通话 → 收起/锁屏 |

首版完成语音输入和音频通话；发布前完成后台与设备中断验收。视觉通话、屏幕共享、声纹、音色克隆、主动唤醒、陪伴人设市场、车载集成不在首版范围。笔记/收件箱中的离线语音备忘继续按其独立的“保存素材”语义工作。

## 2. 调研依据与设计取舍

资料核对日期：2026-09-05。以下为官方公开能力，未对三个产品逐机实测；不据此比较实际故障率、耗电或不同版本按钮布局。

| 产品 | 官方事实 | 本方案采用的原则 |
| --- | --- | --- |
| 豆包 | 对话框“打电话”进入语音；Seed 介绍全双工、抗干扰与动态判停 | 入口直接；以不抢话、不误打断评价自然感 |
| ChatGPT | 移动端语音入口、静音、结束、字幕；转写进入当前 Chat；后台通话可设置 | 文字与语音连续；收音状态和后台行为明确 |
| Grok | 提供免手持语音，并有通话内摄像头理解能力 | 保持开口即聊，视觉能力在基础音频稳定后增加 |

来源：[豆包/Seed](https://seed.bytedance.com/zh/blog/introducing-seed-full-duplex-speech-llm-attentive-listening-robust-interference-suppression-enabling-more-natural-interaction)、[ChatGPT Voice FAQ](https://help.openai.com/en/articles/8400625-voice-chat-faq)、[Grok 产品文档](https://docs.x.ai/grok/overview)、[Grok 语音与视觉](https://x.ai/news/grok-4)。厂商效果描述不是 XOPC 的测量结果。

## 3. 信息架构与界面规格

### 3.1 Chat 输入区

使用现有 Chat 输入框，不增加语音首页或第三种“录制模式”。

- 输入框附属工具区：附件、语音输入。
- 主操作槽：草稿为空时为“语音通话”；有草稿时为“发送”，通话移至输入框上方的一项次要动作，仍一键可达。位置变化只发生在草稿空/非空切换，录制和连接期间固定布局。
- 初次呈现使用“语音输入 / 语音通话”短标签；图标始终有无障碍名称。禁止相同麦克风图标表示两种动作。
- 启动通话保留未发送草稿，不上传、不读出。通话结束返回原草稿。
- 同一 Chat 通话期间允许编辑草稿，但发送入口提示“结束通话后发送”；不同 Chat 的文字操作不切换当前通话目标。
- 输入区无“Agent / Omni / 自然对话 / STT / TTS”选项。

### 3.2 语音输入面板

固定底部面板，上方保留 Chat 语境。布局为“语音输入标题 → 收音状态和计时 → 可滚动转写预览 → 取消 / 完成”。

1. 点击后检查服务与权限，再开始收音；可随时取消连接。
2. 本次识别暂存在听写缓冲区，不直接写入原草稿。
3. 完成停止收音，等待最终识别与已配置的标点/润色处理，然后插入草稿。用户自行发送。
4. 取消删除本次听写，原草稿与光标位置恢复。处理中的取消也必须有效。
5. 在当前光标插入；若草稿在等待期间发生修改，不覆盖新文字，回到可确认插入的预览。
6. 网络异常保留已识别内容，提供“插入已有文字 / 重试 / 取消”；不把转写失败自动变成音频消息发送。
7. 首版在线听写要求连接可用。离线时保留原草稿，提示恢复连接；用户需要离线保存声音时使用已有语音备忘能力。

产品用词固定：听写是“完成”；发送消息是“发送”；停止 AI 是“停止回复”；挂断是“结束通话”。

### 3.3 全屏通话

结构线框仅说明层级，具体颜色、字体、间距采用现有主题 token：

```text
安全区
收起              助手名称              更多
              当前 Chat 名称
            仅聊天 / 可使用工具

                简洁音频反馈
              可以说话 / 正在回复
              麦克风已关闭（如适用）

             最近一轮字幕（可关闭）
             停止回复（有回复时）
             任务进度或确认卡（按需）

       麦克风         音频输出        结束通话
底部安全区
```

- 进入时直接连接，无第二次“开始”，首次只处理必要的服务授权和系统权限。
- 固定头部与底部，中间滚动；大字体或横屏时允许字幕区域缩小，控制不被挤出屏幕。
- 麦克风与挂断保持固定位置，操作热区至少 44×44 pt，优先使用移动端已有 48 pt 控制规格。
- 回复存在时显示带文字的“停止回复”，其消失不引起底部控制跳动。
- 字幕默认开启，仅呈现最近一轮；查看全部记录收起通话并回到当前 Chat。字幕不是实际音频的逐字保证。
- 任务卡从真实事件生成，不显示伪进度。复杂确认展开专用详情，主控制继续可用。
- 更多仅放字幕和语音设置，不放服务编辑表单。
- 不用大面积装饰球、持续强闪烁或逐字滚动动画。降低动态效果时保留静态状态和必要文字。

### 3.4 全局通话条

收起、系统返回、向后手势只收起通话，保持原页面栈。通话条由 App 根节点承载，位于安全区与现有底部控件上方，预留占位，不能盖住发送或保存按钮。

显示“助手名 · 通话中/麦克风已关闭/已暂停”、展开、麦克风与结束。窄屏优先保留展开和结束，麦克风可进入展开页操作。屏幕阅读器可获知完整状态。

同一 Chat 再点通话展开现有通话；另一 Chat 点通话只提供“返回当前通话”，不自动切换助手或上下文。一个 App 实例同一时间只允许一个通话或听写占用麦克风。

## 4. 操作契约

| 动作 | 收音 | 当前回答 | 对话记录与后续行为 |
| --- | --- | --- | --- |
| 关闭麦克风 | 立即停止采集/上传，丢弃未提交片段 | 可以继续播放 | 不提交半句话；显示已关闭 |
| 开启麦克风 | 设备与连接就绪后开始全新片段 | 不自动取消 | 不补发静音前音频 |
| 停止回复 | 保持原麦克风状态；清掉旧轮残留输入 | 本地立即停声，再取消服务端回答 | 不产生用户消息，不触发下一次回答 |
| 用户开口打断 | 接收本次真实的新表达 | 取消旧回答与积压声音 | 接话由判停决定，不要求点发送 |
| 收起/切 App 内页面 | 不变 | 不变 | 同一通话、同一 Chat |
| 结束通话 | 立即停止 | 立即停止 | 保存已确认内容，原草稿不变 |

静音、连接状态与回答状态可以共存，例如“麦克风已关闭 · 正在回复”。断网时不能继续显示“可以说话”。

停止与挂断会请求取消本次 Agent 执行；已经完成的外部操作无法撤销，记录保留实际结果。首版不承诺“停止播报而所有工具继续后台执行”；需要独立任务运行能力时另行设计任务生命周期。

## 5. 同一 Chat 与恢复体验

- 用户可反复进入同一个 Chat 通话；不自动新建 Chat、不恢复独立通话记录列表。
- 后端连接可以更新，历史由 Chat 持久化存储提供。持续对话不等于无限上下文或无限供应商连接时长。
- 短时网络波动显示“连接恢复中”，暂停收音和播报，不缓存一长段离线语音。
- 网络异常才自动尝试恢复，最多 10 秒恢复窗口；恢复无明确成功则进入“已暂停 · 继续通话”。旧连接清理未完成时显示“上次通话正在结束”，不并行创建。
- 恢复成功保留静音选择；静音状态不得因重连变为开麦。只有原先开麦且仍有持续通话授权时才恢复采集，并给出短提示。
- 不自动重试语音消息或工具调用。不确定的最后一句显示“最后一句可能没有发送，请查看记录后再说一次”。
- 使用时长、配额、认证、协议错误不无限重连。时长将尽提前提示，结束后可在同一 Chat 再次开启；首版不承诺供应商连接无缝轮换。
- App 被强制关闭后，重启只恢复 Chat，不自动开启麦克风。

## 6. 移动系统行为

| 场景 | 产品决定 |
| --- | --- |
| App 内切页 | 始终保持通话 |
| 切出 App/锁屏，后台通话关闭 | 立即暂停收音和播报，保留 Chat；回来由用户点继续 |
| 切出 App/锁屏，后台通话开启 | 原生条件满足时继续；系统可见地显示麦克风使用，提供适用平台的结束入口 |
| 来电、系统音频中断 | 暂停；中断结束后用户点继续，不自动出声或收音 |
| 耳机断开 | 暂停音频与收音，提示选择输出后继续，避免私人内容突然外放 |
| 正常切换蓝牙/听筒/扬声器 | 停止旧设备音频，重建设备格式后恢复；失败进入暂停 |
| 撤销权限/退出账号/切换网关 | 结束并释放资源；不把旧通话连接到新网关 |
| 其他音频开始播放 | 根据系统焦点进入暂停，禁止通话、朗读和录音相互抢设备 |

后台通话默认关闭。首次收起时可非阻塞提示“想锁屏继续聊？可在设置开启”，App 内收起不要求开启后台能力。系统短暂 inactive 事件先暂停采集；只有确认 background 或系统音频中断才进入需要用户恢复的暂停流程。

## 7. 设置结构、范围与默认值

入口：设置 → 语音。健康状态用简洁行展示；首屏无服务商表单。

| 分组/项目 | 默认与存储范围 | 生效时机 |
| --- | --- | --- |
| 声音与对话 / 通话能力 | 跟随网关；手机可为当前网关选择“仅聊天 / 可使用工具” | 下一次通话 |
| 声音与对话 / 声音 | 读取当前通话方案的网关音色，可试听；具备管理权限者可在服务设置更改 | 下一次通话；提示影响该网关用户 |
| 声音与对话 / 语言 | 跟随现有服务配置；支持的识别语言由能力接口给出 | 下一次听写/通话 |
| 声音与对话 / 字幕 | 开，设备偏好 | 立即 |
| 通话行为 / 后台继续 | 关，设备偏好；与语音备忘后台录制相互独立 | 用户主动开启且原生能力就绪后 |
| 通话行为 / 说话打断 | 展示服务实际配置；无动态控制支持时不放可切换的假开关 | 下一次通话 |
| 语音服务与诊断 | 听写、仅聊天、工具通话分别显示就绪状态 | 查询最新状态 |
| 高级服务设置 | 服务商、凭据、模型、VAD 等仅在网关唯一管理入口配置 | 按网关配置规则 |

通话能力映射：仅聊天对应现有无工具原生引擎；可使用工具对应 Agent 引擎，仍受既有工具权限约束。没有就绪的仅聊天服务时显示不可用原因，不能静默切到工具通话。不能将“可使用工具”误写成“已允许所有操作”。

本期不新增手机专属音色/模型/自定义端点覆盖层。若未来需要个人音色，需增加真实的服务端偏好契约后再提供可写 UI。

试听必须使用所选通话方案的真实声音。当前服务不支持试听时显示不可用说明，不能播放另一路 TTS 冒充原生语音音色；通话或录音正在使用设备时不启动试听。

## 8. 说话与办事的呈现

- 默认回答先给最有用的结论，用短句；详细步骤、表格、代码和长链接留在 Chat。
- 不因一句附和持续追问或长篇输出；停顿、口误修正和明确打断纳入真实语音语料测试。
- “正在查询/正在处理”来自真实工具事件，长任务只在阶段变化时播报。
- 澄清问题与操作授权分别呈现，不能把两者合成一个“确认”。需要确认时屏幕可查看对象、操作与必要参数。
- 等待确认期间不把环境语音或“嗯”自动当成授权；现有明确提交渠道仍是执行依据。后台收到确认请求时提示回到 App，保持等待。
- 挂断后的任务状态使用真实运行结果，不显示“已停止”来暗示已撤销外部操作。

## 9. 可用性与质量门槛

以下为设计目标，不是已达成指标。计时必须区分网络事件、原生播放进度与设备实际出声。

| 指标 | 首版验收目标 |
| --- | --- |
| 已授权且服务就绪的启动 | 一次点击；正常网络点击至可以说话 P95 ≤ 3 秒，超过时有连接状态且可取消 |
| 手动停止 | 点击至实际停声 P95 ≤ 250 ms；旧音频不复活 |
| 无工具普通问答接话 | 正常网络、固定语料，用户实际说完至首个有效回复声音 P95 ≤ 2.5 秒 |
| 误发/重复执行 | 所有停止、静音、重连、后台回归场景均为 0；出现即阻断发布 |
| 长通话 | 每种支持的设备路线连续 30 分钟，30 轮以上，10 次打断、10 次静音、10 次切页 |
| 释放资源 | 挂断后原生采集/播放停止，无残余上传，系统麦克风状态回落 |
| 恢复 | 不丢已确认历史，不创建额外 Chat，不补发旧音频，保持静音意图 |
| 可访问性 | 大字体、VoiceOver/TalkBack、浅深色、减少动态效果、窄屏和横屏可操作 |

真机至少覆盖一台较旧和一台当前支持的 iPhone、两家厂商 Android；有线/蓝牙/外放、Wi-Fi/蜂窝/断网、来电/锁屏/权限撤销。采集闲置基线与 30 分钟通话的耗电和温升，单独记录后台方案差异；有明显发热、卡顿或操作系统强制终止时不得宣称后台稳定。

自然感使用固定录音和真人脚本评估“思考停顿、附和、改口、旁人说话、外放回声、明确打断”，分别记录误打断率和抢话率，与本项目改造前基线比较；模型调优不能以牺牲停止、静音确定性换分。

## 10. 实施阶段与交付

| 阶段 | 交付 | 自查与进入下一阶段的条件 |
| --- | --- | --- |
| P0 音频与契约验证 | 原生采集/播放/回声处理最小验证、服务能力契约、设计差异记录 | 双平台实际同时收听与播放、立即停声；原生缺口有明确方案 |
| P1 输入与通话基础 | 新听写、全屏通话、全局通话条、仅聊天与工具通话设置 | 操作矩阵自动测试；前台真机验证；删除被替换的 Chat 手势入口 |
| P2 移动稳定性 | 后台、锁屏、设备路由、受限重连和资源协调 | 完整故障矩阵；误发、重复、残留收音为零；未通过不广泛开放 |
| P3 交流与任务呈现 | 短口语、字幕、真实进度、澄清与授权卡 | 两条引擎分别验收；自然感基线对比；完成所有发布门槛 |

每阶段记录“改动、验证证据、发现问题、修复结果、未覆盖项”。失败先修复再推进，不能用模拟器截图替代真机音频证据。实现完成后删除替代路径的死代码、文案和测试；保留笔记录音、音频附件和历史数据等仍有用途的能力。

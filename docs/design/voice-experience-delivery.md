# 实时语音分阶段交付记录

日期：2026-09-11。协议以[实时语音协议 v3](./realtime-voice-websocket-protocol.md)为准，移动端边界见[技术设计](./mobile-voice-technical-design.md)。

## 阶段一：单协议与媒体链路

- 创建请求使用产品模式 `assistant | natural`，不允许客户端选择内部引擎。
- v3 是唯一协议：上下行统一 `XOP3`、20 毫秒 PCM 帧，包含连接代次、序号、媒体时间和归属 ID。
- 网关严格校验 16 kHz 上行 640 字节帧，并把服务商任意 PCM 分片无损重组为 24 kHz 下行 960 字节帧；最后不足一帧时补静音。
- 播放确认从传输字节改为实际播放时长。

阶段自审修复：删除 v2、裸 PCM、按字节确认和客户端 engine 选择；补齐重复帧忽略、序号断层拒绝、连接代次隔离和 provider 任意分片测试。

## 阶段二：轮次、任务与控制语义

- `TurnPolicy` 替代旧的固定停顿类，支持 complete、incomplete、backchannel、wait 和可插拔语义判断；超时/失败使用有界规则回退。
- Agent 语音输入通过现有 SessionInput 协调器和 realtime run 主题进入持久任务，稳定 task ID 防止重连重复提交。
- `response.stop_playback` 仅停止声音，任务在后台继续；`task.cancel` 才显式取消运行。
- 工具活动、任务完成和澄清拥有独立事件；澄清与批准仍要求明确 UI 操作。

阶段自审修复：过期异步判断不能提交新输入；`wait` 会重新判断而非误提交；先订阅再提交避免漏掉极快的 run 事件；任务完成后释放映射；停止播报和任务取消不再共享清理路径。

## 阶段三：移动端原生交互与弱网

- Android 使用通信音频路由及可用的回声消除/降噪；iOS 使用 voice processing。原生层上报全/半双工能力、路由、中断和近讲候选。
- 近讲先本地 duck，服务端确认后才最终打断；半双工路由在播放时阻止采集。
- 上行队列进入 degraded 即暂停采集，恢复到低水位再继续；临界溢出丢弃旧输入并提示重说。
- 诊断记录 RTT、最大 RTT、峰值输入队列年龄、丢帧数、拥塞暂停和音频路由，不保留音频或完整转写。
- 通话界面分别提供停止播报和取消任务；任务状态在停止播报后仍可见。

阶段自审修复：网络恢复后清除过期 `INPUT_DROPPED` 状态；捕获启停串行；系统路由与用户静音意图分离；Web 客户端同步升级到 v3，消除跨端断链。

## 自动化验证

- 共享协议及网关实时语音测试覆盖协商、帧、轮次、持久任务、播放窗口、中断、内存边界和两种模式。
- 移动端类型检查和语音单测覆盖控制器、transport、后台、路由、拥塞与诊断。
- Android `xopc-voice` Kotlin 编译和单测通过。
- iOS `XopcVoice` 模拟器构建通过。
- Web 类型检查、语音组件测试和生产构建通过。
- 浏览器冒烟脚本使用真实 React 组件、模拟麦克风和隔离假网关验证通话、播放、停止、静音、导航、澄清与听写；它不调用真实服务。

## 发布前仍需真机验收

自动化不能验证真实声学环境。发布前需要在 iOS/Android 的内置外放、听筒、有线和蓝牙设备上覆盖：两种模式连续多轮、背景电视、长停顿、自我修正、十次快速打断、系统来电、路由切换、弱网/断网恢复和 30 分钟耗电温升。

记录说话结束到首音频的 P50/P95、误打断率、漏识别率、恢复成功率，以及任务是否重复/误取消。只有真实采样完成后才调整默认阈值或宣称声学体验达标。

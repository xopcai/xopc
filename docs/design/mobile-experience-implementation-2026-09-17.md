# 原生移动端体验改版实现

落实 [Muse 移动端调研](./muse-mobile-research-2026-09-17.md) 中的导航、持续对话、可见进展和成果回流方向。实现位于 `apps/mobile-expo`，使用现有 Expo Router、React Query、原生动效和主题系统。

## 行为变化

- 一级导航为「对话 / 进展 / 资料 / 我的」。历史抽屉只负责对话历史；旧工作台抽屉导航和独立 Attention 页面删除，原设置页面进入「我的」的子导航。
- 聊天顶部恢复为当前模型名称与切换入口，不展示 Agent 头像、名称或连接/运行状态。Agent 选择保留在对话操作菜单。打开下一个弹层需等待原弹层关闭，避免两个原生 Modal 同时展示。
- 每个网关在本机保存独立主会话。历史会话和新建对话作为详情打开，不改写主会话。删除最近会话回退查找；首次使用新结构会建立主会话，原会话仍在历史中。没有读取旧偏好或旧导航的兼容分支。
- 「进展」复用 Home 和 Task API，展示待决定事项、后台工作、最近结束工作。取消、重复和不再推进保留各自结果，不显示成成功。项目、工作流和自动化保留在二级入口。
- 「资料」展示真实最近文件和笔记，图片可预览，文件、笔记和收件箱可继续进入完整管理页面。
- 流式回复期间可继续排队发送或明确选择补充当前任务。输入通过现有持久化 inputs 协议提交；手动重试保留同一 clientMessageId 和 delivery。队列可编辑、取消；版本冲突显式报错并刷新，不自动覆盖。
- 接受后不重启当前流。原运行在请求途中完成时，重新核对当前服务端运行，不重放过期 runId。队列中的消息不在本地时间线保留过时副本。
- 审批先展开服务端提供的详情，再显示同意/拒绝；详情按 approvalId 配对。执行失败也刷新服务端状态。
- 成果卡减少外层嵌套，提高标题与状态字号。托管文件预览可带引用返回原对话；资料文件回到主对话。草稿保留，引用不自动提交；切换网关或其他会话不会误消费该引用。
- 弹层沿用共享 Reanimated 动效；审批展开使用 140ms 布局过渡。文件预览和新增展开动效遵循系统「减少动态效果」。

## 验证与边界

- 移动端类型检查、ESLint、完整 Vitest 测试。
- 新增/更新主会话隔离、延迟回包、队列版本冲突、取消残留、steer 幂等重试、审批身份配对、文件回流及非成功关闭结果测试。
- 现有服务端输入协调器和 SQLite 队列测试；没有修改后端协议或新增 API。
- iOS / Android 原生 bundle 导出。不涉及浏览器兼容目标、依赖升级或原生权限变更。
- 模拟器界面控制服务连续超时，因此本次未完成屏幕截图、手势和真机帧率验收；原生导出不等于这些体验已经实测通过。
- 主会话固定身份目前按「本机 × 网关」保存，不宣称跨手机共享主会话。预览回流使用明确文件引用，不宣称新增了文件 ContextRef 协议。

## 后续页面与交互审查

本轮从源码检查共享控件及进展、资料、设置、笔记、任务、项目、自动化和文件预览页面，直接修复可确认的问题：

- 底部导航采用单个横向移动的全圆角选中胶囊，使用弹簧过渡和轻微图标缩放；系统减少动态效果时直接定位。保持 Expo Router 原有导航事件和键盘隐藏行为。
- 设置行将当前值放在标题下方，让长名称、地址和大字号不再竞争左右两列宽度；补充按钮与选中状态的无障碍语义。
- 笔记标签及添加按钮提升到至少 44pt 点击区域，搜索键盘展开时一次点击即可切换标签。
- 任务、项目及自动化详情补齐底部安全区，保证最后一项内容可滚动到系统手势区上方。
- 进展、资料、项目、任务和自动化详情将主动下拉刷新与后台查询分开，轮询、页面聚焦及缓存更新不再触发下拉刷新动画。
- 自动化执行记录、时间线请求失败显示重试操作，不再伪装成“没有记录”。任务详情和关联任务使用实际关闭结果。
- 文件预览增加内容骨架；菜单操作等待原生弹层完全关闭后执行，避免分享或路由跳转与关闭动画重叠，并阻止重复触发。
- 更新移动端设计文档中已过时的抽屉导航及最近会话启动规则，与当前四个 Tab 和固定主会话保持一致。

验证：类型检查、ESLint、166 个测试文件共 908 项测试通过，包含文件菜单正常选择、直接关闭和禁用操作的行为回归。页面像素布局、手势和动画帧率仍需设备验收；本轮代码审查不等同于逐屏视觉验收。没有引入兼容层、第三方动效库或新的主题系统。

## 列表操作与笔记删除修复

- 笔记、收件箱、会话、文件（包括目录浏览）、录音列表移除左滑抽屉，删除原 SwipeableRow 和打开状态注册器。
- 统一使用 ListItemMenu：长按只打开带标题的操作菜单，点击“多选”才进入选择并选中当前条目；退出仍复用现有选择状态与批量操作栏。
- 菜单完全关闭后执行操作，避免下一弹层、路由或条目删除与原生 Modal 关闭动画重叠。重复点击不会重复执行。
- 笔记列表与收件箱删除立即隐藏条目并提交请求，无撤销等待；失败时恢复条目并显示错误。
- 笔记详情删除取消“待删除/撤销”中间页面，提交成功后返回原入口，失败保留当前笔记。发送前保留编辑保存流程以防未完成的保存覆盖删除；没有人为等待倒计时。
- 保留批量删除确认；会话删除的现有轻提示撤销流程与笔记删除分离。更新 AGENTS.md / DESIGN.md 的列表规则，避免再次引入旧交互。
- 验证：168 个测试文件，917 项测试通过；新增长按菜单、明确进入多选、关闭时序、重复操作、立即删除和失败恢复回归；类型检查与 ESLint 通过。原生视觉和触控体验仍待设备验收。

## Chat 输入区与键盘互斥

附件入口参考 [Telegram 官方附件菜单说明](https://telegram.org/blog/downloads-attachments-streaming#new-attachment-menu)。本项目的切换规则以键盘和扩展操作共享底部空间为原则，使用现有 Keyboard Controller 与 Reanimated 实现。

| 场景 | 行为 |
|---|---|
| 点击输入框 / 输入框聚焦 | 立即请求收起扩展面板；包含 Android 输入框已经聚焦、再次点击唤起键盘的情况 |
| 键盘开始显示 / 取消键盘收起 | 原生键盘事件同步隐藏面板内容并收起面板，不依赖再次触发 onFocus |
| 键盘打开时点“＋” | 输入框失焦并收键盘，面板只补足键盘以外的高度，避免两者叠加 |
| 返回键 / 点“＋”关闭 | 收面板，不自动重新打开键盘 |
| 语音切换到文字 | 关闭扩展面板，切文字并聚焦；文字切语音则先失焦、收键盘 |
| 发送 | 收扩展面板，保留正在使用的文字键盘；发送失败保留已有草稿恢复流程 |
| 点附件 / 引用操作 | 面板关闭动画完成后执行；关闭期间重新打字会取消尚未执行的操作 |
| 快速关闭再打开 / 离开聊天页 | 过期动画回调不执行新操作，离开时清理待执行动作与面板状态 |

动画高度继续使用键盘实时高度抵扣，避免输入区被键盘与面板同时抬高；键盘进场时面板内容在 UI 线程隐藏，不等待 JS 状态更新。保留既有小屏分页、大字号布局、系统减少动态效果支持。

验证：类型检查、ESLint、168 个测试文件共 924 项测试通过，包含键盘重新打开、交互式收起取消、回到输入取消动作、过期动画与页面离开等回归。未完成设备截图、实际键盘动画与帧率验收。

## 键盘、扩展面板与底部导航统一布局

- 正常浏览显示四个 Tab；软件键盘展开或根 Chat 的扩展面板打开时，Tab 收起并释放整个导航栏及其底部留白的高度。
- 移除布局中的 `tabBarHideOnKeyboard`，由 CapsuleTabBar 单独管理键盘进度和面板过渡，避免导航库与自定义动画各自改变占位。
- 跟随实际键盘进度恢复空间，不以输入框是否仍有焦点判断。键盘收起时恢复 Tab；键盘与面板相互替换时保持导航隐藏，避免中途闪回。
- 根 Chat 与 Tab 使用同一份面板状态；详情 Chat 保持局部状态，不影响其他页签。原有离页和切换会话的清理同步关闭共享面板状态。
- 浏览时底部安全区由导航承接；面板打开时交给输入区；键盘打开时移除重复安全区留白。原有消息列表可见位置维护继续保留，不新增滚到底部逻辑。
- 导航隐藏时禁用点击并从无障碍树隐藏；面板过渡遵循系统减少动态效果设置。
- 类型检查、ESLint、169 个测试文件共 929 项测试通过。新增导航占位释放/恢复、双向键盘交接不闪回、其他 Tab 隔离和输入区安全区回归。实际设备动画与触控仍待验收。

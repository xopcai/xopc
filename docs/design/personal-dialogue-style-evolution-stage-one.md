# Personal 中文多轮助理风格：第一阶段实施与验收

日期：2026-11-02。对应[建设方案](./personal-dialogue-style-evolution-plan.md)。目标是可复现地比较交流风格，不能把模型裁判偏好当真实用户满意度，也不以更短回复代替内容正确性。

## 已实现

- [12 个中文四轮场景](../../evals/personal/style/assistant-flow-dialogues-v1.json)，开发/验证各 6 个，覆盖衔接、纠正、话题切换、收口、偏好例外与撤回、详细回答及事实/授权保护。expectations/split 不进入被测 Personal。
- 复用生产 Personal 鉴权 HTTP/realtime 与现有 EvalStore/TraceEmitter，记录每轮完成时延与 first-delta 分开。每段会话内串行，独立会话并发 2。
- 复用 P0 匿名双序盲评，新增 conversation_flow/preference_scope，所有错误要求精确 assistant turn 与原文证据。缺失捕获、裁判格式/服务错误、顺序分歧均保留。
- [准备器](../../evals/personal/style/prepare-assistant-flow.mjs)冻结源码并核对只有共享风格模块变化，先登记后执行；[运行器](../../evals/personal/style/run-assistant-flow-cycle.mjs)支持独立请求/总时间预算；[报告器](../../evals/personal/style/report-assistant-flow.mts)生成不可变结论、匿名人工评审包、来源哈希并导入统一控制面。
- Dashboard 改进验收页展示开发/验证整体与自然度偏好、分歧、缺失、p95 完成时延、分项错误及 A/B 对话预览；人工状态单列，页面只读，不捏造人工投票。
- 被测固定 `xopc-cloud/openai-codex/gpt-5.6-sol`，裁判固定 `xopc-cloud/openai-codex/gpt-6.1-sol`，无自动回退。沿用既有 style 协议 off/low、fresh default profile；生产模型/偏好配置未修改。唯一候选只在冻结实验源码中使用，未写入生产默认。

## 首批失败与方法修复

`assistant-flow-20261102-v1` 两条件均完成 12/12 场景、各 48 轮、无场景捕获错误及源码漂移，24 次双序评审也完成。但新增用量导出在 `Gateway.stop()` 之后调用了已关闭的应用数据库句柄，两个 generation campaign 以错误退出，独立 runtime 最终快照缺失。源日志、完成捕获、所有 HTTP 请求和拒绝决定完整保留；不把缺失 runtime 记录填零或声称对账通过。

v1 improvement `7543a53c-e60a-4b0e-8a51-d916f2fba657` 已拒绝，风格自动门禁也未过。方法修复改用现有独立只读 `readRuntimeUsage` 在 Gateway 关闭后重新打开隔离数据库读取终态；另将新增 scripted 时延字段从 EQ 上游 CompletionResult 构造参数中剥离，避免影响原 EQ 模式。

`assistant-flow-20261102-v2` 在读取 v1 风格评分前已预登记并冻结，原注册中记录 methodologyRecoveryOf 及修复原因。没有基于 v1 评分修改候选、选择样本或放宽门槛；v1 的负面结果不被 v2 覆盖。两个批次各自完整报告，不能拼成一批最优答案。

## 复验与验收结果

[便携证据](./technical/evidence/personal-assistant-flow-2026-11-02.json)包含两批独立结果与不可变决定哈希。方法修复后两个 capture 和 judge campaign 正常完成，源码无漂移、收尾 active/queued 为 0。两条件各 12/12 场景、48/48 用户轮次，双序评审 24/24，无缺失或格式失败。

验证集整体与自然度均未取得净胜；内容/边界受影响回复数旧版 1、候选 2（任一顺序检出计数）。验证完成时延 p95 约为旧版 1.366 倍，超过预登记 1.2 倍保护。无候选 major，但不足以晋级。`36dd798a-c1a3-46aa-b917-ff11f05734ee` **rejected**，候选不进入生产默认。

裁判具体证据：V02 两条件都在草稿加入未提供的“刚看到”；V06 一种展示顺序认为候选新加“今天几点前需要确认”引入未提供时限，另一顺序判平。该分歧保留，不补投票。大部分场景为平局，新增对话衔接/偏好作用域维度未检出错误；这说明本次增加一条通用规则没有证明改善，不意味着已覆盖所有真实流畅度问题。下一轮应先由人审校准具体失败、扩展真实衔接与更有区分度的场景，再预登记针对性候选，不能继续往提示里叠笼统形容词或重跑寻找偶然净胜。

# 移动端语音实现与验收记录

更新：2026-09-06。对应 [产品方案](./mobile-voice-prd.md) 与 [技术方案](./mobile-voice-technical-design.md)。

四阶段的代码实现和代码自查已完成；原生真机质量门槛尚未验收。当前成果可进入设备联调，不代表已经满足正式发布门槛。

## 用户现在怎样使用

- Chat 的麦克风按钮用于听写：显示识别内容，点完成后放入可编辑草稿，用户再按发送。取消不会发送；草稿在识别期间发生变化时，先展示转写，由用户决定是否插入。
- 空草稿的主按钮是通话；有草稿时主按钮为发送，通话保留在工具栏。通话属于当前 Chat，收起、切页不会创建另一个 Chat 或销毁通话资源。
- 设置 → 语音设置 → 通话能力：跟随网关、仅聊天、可使用工具。仅聊天明确使用 Omni，无工具；不会在失败时偷偷切到 Agent。
- 通话提供静音、停止回复、音频输出、收起、结束。停止回复不提交输入、不新增用户消息；后台通话默认关闭。
- 字幕与后台偏好保存在设备；模式按配对网关保存。模型、供应商、凭据和音色继续由网关管理。只有对应的 TTS 通话路径提供真实音色试听。
- 字幕使用 Markdown 呈现；工具活动显示实际进度，澄清与工具授权使用已有接口和明确的提交按钮。等待确认时暂停上传语音。

## P0：能力契约与原生音频

实现：扩展现有 `GET /api/voice/realtime/status` 的共享 schema，描述听写、Agent、Omni、语言和打断配置。查询不创建供应商会话。新建本地 Expo 模块 `apps/mobile-expo/modules/xopc-voice`，使用唯一的通话音频实现：iOS AVAudioEngine voice processing；Android 通信音源、AudioTrack，以及设备支持的 AEC/降噪。

输入为单声道 PCM16 / 16 kHz，输出为 PCM16 / 24 kHz；格式不匹配明确失败。连续流式播放不写小文件轮播。播放队列有界，确认来自原生播放进度，而非收到或排队的字节数。

自查与修复：修正 Android 模块构建配置与降噪属性名称；补足销毁时 Context、iOS tap 安装状态、系统中断和配置变化处理。原生采集帧附带 `captureId`，JS 再次检查归属，防止静音或停止前排队的音频在重新开麦后被上传。

证据：Expo clean prebuild、Pods 安装、iOS 模拟器完整应用构建、Android Debug APK 构建均通过。本机仅有模拟器，没有连接 iPhone/Android 真机；扬声器回声、蓝牙和实际停声延迟尚无测量结果。

## P1：输入、通话和设置

实现：`use-chat-dictation.ts` 管理显式听写；按 utterance/revision 替换识别修订，接受同 revision 的 final；只有 `input_committed` 为成功边界。通话控制器由应用根节点订阅，页面只展开或收起界面；底部通话条占用布局空间。设置接入现有 React Query、设备认证、数据共享授权和 MMKV。

自查与修复：移除听写完成时的自动发送；修正迟到结果在失败/取消后回填的竞态；保留现有草稿并确认冲突插入；语音输入面板增加安全区、录制时间和处理中取消。服务未就绪和旧网关缺少能力契约时显示原因，不提供看似有效的选择。移除输入栏上方重复的独立通话按钮。

清理：删除 Chat 专用 `use-chat-voice-recording.ts`、`voiceRecordingGesture.ts`、手势专用测试和无引用文案。笔记语音备忘仍使用文件录音、原有手势和离线保存；音频附件与朗读仍有真实用途，保留并纳入资源仲裁。

## P2：生命周期与故障处理

实现：网关与 Chat 身份固定；新连接复用同一 Chat 的权威历史。一次性 ticket 固定到实际成功的 HTTPS 路由，同源 WSS 首帧认证。控制消息与音频分别校验序列；输入/播放缓冲有界，心跳超时关闭连接。有限网络恢复只重试准备步骤，创建请求结果不明时停止自动重试。

原生模块提供音频焦点、系统中断、耳机断开处理；iOS 后台音频和系统停止入口、Android 麦克风前台服务/通知停止入口已接线。后台偏好关闭时释放音频并暂停，继续需用户操作。换网关、撤销共享授权或挂断会失效旧代次。听写、笔记录音与通话互斥；启动采集暂停普通朗读，结束后不自动恢复朗读。

自查与修复：修正关闭回调递归、握手发送失败、初始静音发送失败后误开麦、重连静音丢失、同时挂断/中断互相覆盖、停止后旧音频回流和文件录音释放异常。回连前后检查 SQLite transcript identity，避免 Chat reset 后将旧上下文作为继续通话。取消不重投用户输入或工具调用，也不承诺撤销已经发生的外部操作。

## P3：交流呈现、确认与诊断

实现：复用现有 Agent/Omni 输出与工具执行路径，不新增手机专属模型编排。显示字幕、真实工具活动、澄清问题、当前 Chat 的待授权项和到期提示；授权只通过明确按钮提交。`local_stop` 指标记录客户端停止操作到原生 flush 完成的耗时，不能视作物理扬声器停声延迟。

自查与修复：过滤停止回复之后到达的旧澄清；回复完成但音频尚未播放完时仍允许停止；真实播放确认和接收字节分开；Omni 不借用其他 TTS 声音冒充试听；字幕隐藏不改变历史存储。

## 实现相对原方案的精简

- 使用可注入依赖的 `VoiceCallController` 与 `useSyncExternalStore`；没有另建 reducer 文件、Provider 状态副本或引入状态机库。
- 全屏与收起视图放在 `VoiceCallSurface.tsx`，共用控制器，不复制连接生命周期。
- 扩展已有 status、preflight、sessions、preview 和确认接口；没有第二套手机会话后端、Call 数据表、旧协议兼容层或重放队列。
- 语音偏好独立为小型设备 store；不保存活动标志、ticket、socket 或音频缓冲。

## 尚待完成的发布验收

需要连接真实 iPhone 和 Android，分别覆盖 Omni 与 Agent：

1. 外放、听筒、蓝牙耳机双向音频；回声造成的自我打断、停声延迟、首音延迟。
2. 连续静音/开麦、停止/自然打断至少各 100 次；确认无误发、无残留收音、无重复历史。
3. Wi-Fi/蜂窝切换、断网、认证撤销、后台/锁屏持续通话、系统来电、拔耳机、前台服务通知停止。
4. 同 Chat 长通话与上限提示、任务确认、超时和创建结果未知；核对网关持久历史。
5. 小屏、大字体、屏幕阅读器、键盘与全局通话条；配对后的完整交互验收。
6. 按产品方案记录两平台的延迟、耗电、温升与会话稳定性，失败先修复再开放发布。

这些项目未标记通过。此次没有发布安装包、修改远程服务配置或触发真实外部工具任务。需要先部署支持新增能力字段的网关，再安装包含原生模块的移动构建；Expo Go 无法运行此通话模块。

# 会议助手 P1/P2 实施拆分与验收

日期：2026-09-15
状态：P1-A 实施中，进展见 [实施与自查](./voice-meeting-p1-p2-implementation-review.md)；以下指标是目标，不是实测结果。
契约：[P1/P2 技术设计](./voice-meeting-p1-p2-technical-design.md) · [PRD](./voice-meeting-prd.md) · [P0 实施记录](./voice-meeting-implementation-review.md)

## 1. 实施顺序

按下列顺序交付，每阶段完成实现、自我 review、修复和相应验收后再推进。平台验证失败应关闭该平台入口并记录原因，不阻塞已经通过验证的平台。

| 阶段 | 交付 | 前置条件 |
|---|---|---|
| P1-A | 多音轨时间轴、持久分块、异步封存和处理任务 | P0 数据与活跃草稿盘点 |
| P1-B | 会中重点、带证据问答、重点标记 | P1-A；先以麦克风会议验收 |
| P1-C | Windows/macOS 系统音频与来源健康提示 | P1-A；先完成签名包平台验证 |
| P1-D | 会后语音复盘 | P1-B；固定会议上下文可检索 |
| P2-A | 会前准备、跨会议决定变化 | P1-B；来源权限及修订一致性 |
| P2-B | 可靠域事件、任务承诺跟进 | P2-A；现有任务事件回归通过 |
| P2-C | 移动原生后台录音与恢复 | P1-A；真实 iOS/Android 设备 |
| P2-D | 钉钉/飞书等授权资料导入 | 目标平台 API、应用权限和租户权益验证通过 |

P1-C 的平台实验可以提前做，但正式接入只接受 P1-A 的统一契约。P2-A 首先支持用户手动生成简报；自动触发与主动通知在 P2-B 可靠投递后开放。

## 2. 每阶段交付与 review

### P1-A：统一录音基础

**工程落点：** `src/discussions/recording.ts`、该目录下的 worker/revision 模块、SQLite 迁移、现有 Discussion 路由与 Web 录音服务。新增任务与音轨模块的文件名在实现时按职责确定，不新增独立会议服务。

交付：

- track/epoch、分块幂等键、媒体覆盖区间及版本化时间映射；单轨旧会议一次性映射。
- 本地落盘后上传，服务端字节接收与媒体验证进度分开；seal 返回 202，通过持久任务完成转写和终稿。
- 有界队列、lease、取消、失败重试；同一录音仍可在断网恢复后继续上传。
- 客户端版本识别、活跃草稿保全和切换工具；统一客户端后删除旧协议入口和调用代码。

自查与修复重点：复用 sequence 导致跨轨覆盖、跨 epoch 拼接损坏、重复 seal 创建多任务、删除后任务复活、旧进程仍持 lease 写结果、暂停后的证据时间漂移。

通过门槛：

- 事务与故障注入覆盖落盘/数据库提交/回执之间的崩溃；重复上传验证相同哈希成功、不同内容冲突。
- 真实鉴权 Gateway 覆盖所有新路径及 lazy-bundle 正负映射，包含只读凭据、错误设备归属和超限请求。
- 连续流容器、独立片段容器各至少一个真实样本；损坏尾块、缺块、重传、断网、暂停、重新启动均可解释地恢复。
- 迁移前后旧会议文本、证据、附件一致；活跃旧草稿不被删除或静默转换。回退演练保全升级后新增媒体。

### P1-B：会中重点、问答与标记

**工程落点：** `src/discussions/` 新增只读问答和增量理解职责；现有检索/SQLite、Discussion API 与 `web/src/features/discussions/`。

交付：固定修订与连续覆盖水位、带截止时间的重点、私有问答记录、可回听引用、待补齐和资料不足状态、离线幂等标记。

自查与修复重点：把最大序号当完整进度、静音错误阻塞、晚到文本未触发更新、中文检索失效、Top-K 冒充全部行动、引用新旧修订混用、缓存绕过撤权、提问意外调用工具。

通过门槛：

- 双轨一条落后/中断时只声明实际覆盖；经验证的静音可推进，未知缺口不可推进。
- 问“所有待办”走有界分批扫描和完整性检查；未覆盖整场时明确范围。
- 恶意会议原文不改变权限和工具能力；私有问题不进入其他人的列表、订阅事件或缓存。
- 更正、删除、权限撤销发生在检索后或生成中时，回答提交前重新校验；不返回失效来源。
- 页面以 skeleton 加载；重点/问答标出截止位置，证据跳转、键盘操作、窄屏布局通过验收。

### P1-C：系统音频

**工程落点：** `electron/main.ts`、`electron/ipc/`、Electron 打包权限配置、Web 采集适配器。采集授权与普通权限诊断分开。

先用当前锁定 Electron 的签名安装包验证 Windows loopback、macOS 14.2+ 的实际系统音轨，再测试 macOS 15 的系统 picker。记录 OS、Electron/Chromium、签名、权限字符串、所选来源和音频帧结果。官方文档描述存在差异，不能仅凭版本号开启功能。

交付：麦克风/系统音频分别保存，选择与取消来源、逐路音量健康、来源结束和权限撤销提示；录制中更换来源建立新 epoch。

自查与修复重点：系统 picker 绕开自定义回调后的授权边界、任意 iframe 触发采集、把系统权限通过当音频成功、拿到静音轨无提示、renderer 崩溃丢失已落盘材料、麦克风与系统重复回声。

通过门槛：真实外部会议播放、耳机/外放、蓝牙切换、来源关闭、静音、拒绝后重新授权、renderer 退出均可复现并有记录。无音轨的平台显示麦克风方案，不进入空白“系统录音中”。平台不通过则不开放其系统音频入口；不增加自动轮试多个原生驱动的逻辑。

### P1-D：会后语音复盘

交付：复用既有语音通话，从会议详情显式进入；绑定会议/修订与授权范围，通过 P1-B 检索回答，文字同步显示证据。

自查与修复重点：整场转写进入实时指令窗口、切换会议后仍用上场上下文、录音与复盘抢占麦克风、TTS 被本场系统音轨再录入。

通过门槛：会中入口先停止或完成录音后才能开启有声复盘，任何切换均由用户明确触发；挂断释放设备，撤销会议权限后上下文失效；原有通话/听写回归通过。

### P2-A：会前准备与跨会议变化

交付：项目中手动生成准备简报、显示来源范围与截止时间；相邻会议固定修订比较；决定关系可确认/拒绝，旧证据与用户笔记不改写。

自查与修复重点：文字相似被当作决定替换、相关会议被当作全量项目历史、日期/负责人由模型补造、确认关系后直接修改任务、来源 ACL 与项目权限混同。

通过门槛：每条变化可定位两端证据；缺少任一侧依据只提出候选。关系确认携带 expectedRevision；并发更正返回冲突，不覆盖用户操作。需要修改已有 Task 时通过现有命令显式提交。

### P2-B：可靠事件与承诺跟进

**工程落点：** 当前 `src/tasks/task-outbox-dispatcher.ts` 泛化并移至公共域事件职责位置；`src/automations/product-events.ts`、`src/proactive/events/` 和现有订阅/任务应用服务。

交付：会议状态与 outbox 同事务、正确的事件 source、稳定 eventId、持久消费者确认；复用现有 Task 和主动订阅实现准备触发、等待与提醒。

自查与修复重点：内存广播即标已发布、重投多次提醒、某个消费者成功掩盖另一个失败、重生成纪要重复创建任务、每轮提醒没有实质变化、把邮件内容直接当任务完成。

通过门槛：发布前后宕机、消费者重启、重复投递、乱序与租约接管不重复产生任务/提醒；已有 tasks 事件、主动场景全部相关回归通过。日程取消/移动使原触发失效；重建采用稳定 occurrenceId 和新输入版本。外部消息发送仍需明确授权。

删除旧 dispatcher 名称/硬编码及调用链，不留转发别名；公共派发不是第二套总线。

### P2-C：移动后台录音

**工程落点：** `apps/mobile-expo/modules/xopc-voice/`、移动录音会话协调层及 Expo config plugin；维持现有 Expo 56。

交付：原生音频回调写文件与 journal、闭合分块上传、原生中断事件、进程重启扫描恢复。JS 管状态和进度，不作为音频持久化必经路径。

自查与修复重点：后台 JS 停止导致丢块、整场 base64 峰值、Android 后台非法启动前台服务、来电后跨格式拼接、重启偷偷开启麦克风、系统强杀承诺零丢失。

通过门槛：iOS/Android 真机分别测试锁屏、应用切换、来电、蓝牙切换、断网、低空间、系统终止与重启恢复；说明未闭合尾块最大损失窗口。后台先保证本地录制，恢复前台后补传也算可接受，不把持续联网作为录音成立条件。

### P2-D：会议平台资料导入

交付前先完成平台验证表：官方 API 文档、应用类型/租户权益、最小 scope、真实授权样本、转写/说话人/时间戳字段、分页、限流、资源有效期、撤销与删除语义。未验证能力不显示为可用。

交付：利用现有连接器同步指定授权材料，以外部资源 ID + 版本幂等；先支持可验证的转写或文件，不承诺所有平台都有录音下载权限。

自查与修复重点：转写导入伪造可回听音频、签名下载 URL 泄露、重定向访问内网、媒体解码器取远程子资源、撤销授权后索引仍可查、外部更新覆盖用户编辑。

通过门槛：重复同步无重复会议、更新保留旧证据版本、无权限资源不入库、撤权阻止新同步并移除可检索性。用户明确保存的本地副本需另有记录与删除规则；无已验证 API 时使用已支持的用户文件导入。

## 3. 初始资源边界

以下为首版目标配置；以真实样本调整后写入服务端唯一校验定义，客户端引用同一契约，不各写一套数字。

| 项目 | 初始边界与含义 |
|---|---|
| 时长 | 120 分钟共同会议时间轴；多路重叠不相加，主动暂停不计入 |
| 同时采集 | 麦克风 + 系统声音，共 2 路；不推出任意数量多设备采集 |
| 单上传块 | 最大 8 MiB；超过则客户端缩短分块，服务端拒绝超限请求 |
| 原始录音总量 | 每场累计最多 1 GiB，覆盖所有 track/epoch；导入按同一总量规则 |
| 上传并发 | 每场最多 2 个上传；单请求有界读取，不聚合全场 Buffer |
| 原生分块 | 目标 20 秒闭合一次；异常终止最多丢失一个未闭合块，依真实实现验收 |
| 后台模型 | 每场最多 1 个增量理解任务；默认每分钟或新增 500 字触发，遵守全局限额 |
| 问答 | 每人 1 个并发、每分钟 6 次；全局队列有上限，满时明确提示 |
| 保留 | 原始材料沿用会议生命周期；删除后阻止任务写回并清理索引、缓存和派生物 |

16 kHz/16-bit 单声道 PCM 双路录制 120 分钟约 461 MB（十进制，未计容器），64 kbit/s 双路编码约 115 MB。这只是容量计算，不代表所有设备实际编码参数。

磁盘预检须同时覆盖本地 spool、服务端原件、解码/混音临时文件与预留空间；两端分别计算，不能仅按原始文件大小判断足够。低空间先发提醒并安全闭合已有材料，禁止静默清理尚未确认上传的块。原始块只有在完整性确认、可恢复封存成立后才可清理本地副本。

快照只在增量理解提交或问答固定修订时建立，不对每帧全量复制会议。历史引用仍在使用的修订不可清理；临时无引用快照/失败临时媒体采用明确保留期和可恢复清理任务。TTL 在上线前结合容量实测配置，不为节省空间删除证据。

## 4. 质量和平台验收矩阵

| 维度 | 必测样本或场景 | 初始通过目标 |
|---|---|---|
| 长录音 | 30/60/120 分钟真实双路声音、尾部决定 | 无静默截断；尾部可检索、可回听 |
| 时间映射 | 已知声学标记、暂停/中断/切换后对齐 | 2 小时媒体映射漂移目标 ≤250 ms；与 ASR 边界误差分开报告 |
| 来源健康 | 断帧与正常静音分别注入 | 可观测断帧目标 5 秒内提示；正常静音不误报断流 |
| 会中理解 | 双轨正常到达，指定模型和网络 | 新内容到重点可见目标 p95 ≤90 秒；积压时显示截止位置 |
| 会中问答 | 已覆盖范围内的单一问题 | 目标 p95 ≤10 秒；全量扫描问题单独统计 |
| 证据 | 中文、中英混说、重叠发言、更正/撤销 | 引用地址/修订有效率 100%；语义支持率目标 ≥95% |
| 安全 | 越权范围、撤权竞态、注入、缓存串人 | 测试集中无越权资料和执行工具调用 |
| 资源 | 低配与常用机器、两小时、断网重传 | 记录峰值 RSS、临时磁盘、CPU、耗电和成本；无随全场长度增长的内存音频缓冲 |

效果集目标至少 30 场经授权、脱敏的真实会议，覆盖项目例会、评审、客户沟通和跨会议改期。人工标注决定、撤销、行动和原话位置；报告样本数、来源覆盖、漏召回及置信区间，不只报告平均分。没有样本时保留“待验收”，合成静音只能验证容器和容量。

平台逐项发布：Windows Electron 签名安装包；macOS 14.2+ 与 15+ 的实际支持版本；受支持浏览器的用户选择来源；iOS/Android 真机。记录 OS/build、设备、权限、打包配置和锁文件版本。浏览器有 getDisplayMedia 不代表具备系统声音；移动后台录音不代表其他应用声音采集。

## 5. 尚需实验确定的选型

| 问题 | 当前默认 | 实验不通过时 |
|---|---|---|
| macOS 系统采集 | 当前 Electron 公共能力，签名包实测 | 该平台暂不开系统音频；确需原生 helper 时单独补 ADR |
| 中文检索召回 | 现有 SQLite FTS5，验证 tokenizer | 先改善分词/规范化与范围扫描，效果证据支持后才引入语义检索 |
| 外放重复声音 | 分轨保存与来源提示，验证回声处理 | 不做基于相同文本的硬删除；不承诺唯一说话人 |
| 后台上传 | 原生先落盘，前台可补传 | 不引入必须后台常驻的 JS 网络逻辑 |
| 平台资料导入 | 官方 API 与实际租户授权验证后接入 | 保留文件导入，未验证能力不展示 |

这些是工程验证门槛，不是实现过程中反复请求用户选择的常规参数。

## 6. 完成定义

每阶段留下改动范围、自查发现、修复记录、自动检查结果、实机结果和已知边界。代码阶段运行相关测试、前后端类型检查、Web build；新增 API 必须通过运行中 Gateway 的鉴权请求。原生阶段补签名包/真机构建验证。

放量开关仅控制新会话能否进入新能力；不停止已有录音，不删除草稿。数据库迁移回退必须保全新增数据，不能等同于切换前端开关。

设计阶段完成了文档与一致性检查；后续代码验证结果见实施记录。模型效果或实机验收不得提前填为通过。

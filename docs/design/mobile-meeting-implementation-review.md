# 移动录音实施与自查

日期：2026-09-15。状态：**本批单麦克风录音 → 移动界面 → 手动同步 → 会议总结已接通；完整移动会议路线图及真机验收未完成。**

关联：[本批技术方案](./mobile-meeting-ui-upload-design.md) · [完整技术设计](./mobile-meeting-technical-design.md) · [PRD](./mobile-meeting-prd.md)

## 阶段一：原生采集接入

已导出 `startRecording / stopRecording / activeRecording / recordingChunks`，复用 XopcVoice 模块。iOS AVAudioEngine、Android AudioRecord MIC 都直接写原生文件 journal，PCM 不经过 JS。

- 生命周期命令移到专用串行队列；恢复扫描、SHA-256 校验和停止排空不阻塞主线程。
- Android 接入现有前台音频服务、停止通知和服务生命周期 wake lock；服务结束释放资源。
- 共享麦克风所有者与原生互斥检查；语音通话清理不能停止仍在运行的会议录音。
- 16kHz PCM16 mono、20 秒独立 WAV、不可变回执、文件锁、尾段恢复，累计采样限制两小时。

自查修复：第二次开始失败不能释放第一次录音的所有者；结束另一条中断录音不能释放当前录音；原生停止服务使用当前会话回调，旧服务销毁不能消费新会话回调；本地索引损坏不允许覆盖。

## 阶段二：移动界面与本地恢复

收件箱顶部入口进入 `/recordings`。支持开始、主动暂停与继续、结束保存、中断材料恢复、历史列表、长按多选及批量同步、返回录音入口。使用现有主题、中英语言包、列表选择 / 滑动组件、加载骨架。

原始音频以原生文件为准，MMKV 保存列表及网关绑定。录音开始前登记 ID；重启或返回前台时对账原生状态。麦克风权限拒绝不会生成虚假的空录音。界面显示已保存样本对应的时长。

自查修复：工作区切换时不展示旧工作区远端详情；未绑定录音在用户主动同步时才绑定；无后台自动上传承诺。

## 阶段三：上传、转写和总结

上传使用现有安全文件上传客户端的 binary PUT；对照远端回执补传，校验 hash 和长度。固定 clientRequestId 避免响应丢失后重复创建会议；queued / running job 不重复提交。

服务器明确支持 `independent_wav`，去除分块头并生成总头，检查规范头、大小、哈希、解码结果和总时长，再交给现有 Discussion 转写 / 总结 worker。没有增加第二套转写服务或旧接口适配层。

会议来源增加 mobile，保留原始 recordedAt，Note 来源复用 app；SQLite 173 扩展来源约束。移动页面展示摘要、要点、决策、行动项，可打开会议笔记；上传和后续处理各有重试入口。

自查修复：不能把多个完整 WAV 直接字节拼接；lastSequence 不能误用原始块序号；每块读取有上限；容器格式参与封存幂等摘要；Discussion 上传与 AI 操作纳入既有数据共享授权。

## 尚未验收及后续工作

没有把本批软件检查等同于完整 M0–M4 发布验收。尚需连接真机检查锁屏、来电、蓝牙、低空间、真实两小时、耗电和系统文件保护；本批没有安装或发布整 App。

完整多轨 / epoch 时间轴、会中问答、后台系统上传、实时波形与首帧健康、锁屏 Live Activity、本地连续回放、删除及空间管理、外部音频导入继续按完整技术设计分阶段推进。当前意外中断只恢复并结束，避免把未知缺口伪装成连续会议。

录音使用原生模块，需要重新构建移动应用；只有 JS 热更新不能把这批原生能力加进旧安装包。

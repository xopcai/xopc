# 会话侧栏：来源识别与筛选方案

状态：第一、二阶段及保存视图已实现；完整运行 / 阅读状态与账号级筛选为后续增强。日期：2026-09-13。

实现说明：侧栏、会话卡片和对话页头共用身份规则；组合筛选在 SQLite 中先过滤再分页，全文搜索不再预截断到 500 个会话。筛选条件与来源说明按 Gateway 保存在本地，关键词不自动保存；显式“保存当前视图”时会连同关键词保存，最多 20 个命名视图，支持删除。实时更新提示用户刷新，避免结果跳动。仍遵守已有隐藏会话规则；旧工作流没有触发来源元数据时不凭标题推断。筛选只影响左侧列表，当前打开的对话保持显示，不额外提示其是否出现在结果中。

## 目标与现状

用户应能在不打开对话的情况下，识别工作台、浏览器扩展、CLI、IM、自动化等会话，并快速找回目标内容。

当前 `SessionChannelIcon` 只为部分 IM 渠道提供品牌图标，其余回退为 Hash。侧栏对 web/webchat 会话隐藏图标，导致标题起点和辨识能力不一致。列表元数据已有 `sourceChannel`、`sessionType`、`projectId`、`routing.agentId` 和 `customData`；浏览器扩展创建时已有 `customData.createdSurface = browser_extension` 标记。

通用会话查询已有搜索、渠道、类型、项目等能力；侧栏聚合接口尚未暴露组合筛选。侧栏默认 60 天范围、对话首页 20 条，不能对这 20 条直接做前端筛选并称为全量结果。

## 一、会话行

固定布局：`16px 身份图标 | 标题 | 运行 / 未读状态`。所有会话保留图标槽位，标题对齐；图标默认中性灰，颜色只承载必要的运行、失败、未读语义。

| 会话身份 | 建议图标（现有 Lucide / 品牌资源） | 展示名称 |
| --- | --- | --- |
| 工作台对话 | MessageSquare | 工作台 |
| 浏览器扩展创建 | PanelsTopLeft | 浏览器扩展 |
| CLI / TUI | Terminal | 终端 |
| Telegram / 微信 / 飞书等 | 现有渠道品牌图标 | 对应渠道名 |
| 自动化会话 | Clock3 | 自动化 |
| 工作流执行 / 子任务 | Workflow / GitBranch | 工作流 / 子任务 |
| 心跳、维护等系统任务 | Settings2 | 系统任务 |
| API / MCP 等已明确的程序入口 | Plug | API / MCP |
| 未识别的历史入口 | MessageCircle | 其他来源 |

未知来源保留原始渠道名供详情查看，不继续用 #。尚无结构化依据的入口不能靠标题中的“浏览器”“Memory”推断。

主图标优先表达专用任务身份：系统任务 → 工作流 / 子任务 → 自动化 → 普通对话入口。优先级只解决一个会话同时具有多种属性的展示冲突，不抹掉其他元数据。例如自动化触发的工作流使用工作流图标，详情仍显示“自动化触发”。普通对话调用 browser_use 后仍保持原入口。

默认单行保持列表密度。提供可选“显示来源说明”，开启后每行追加一行弱化说明，如“浏览器扩展 · example.com”“自动化 · 每日 AI 新闻”“终端 · xopc”。仅展示真实可用的字段；域名、自动化名称、目录等扩展信息需要接口明确提供。

图标的悬浮 / 键盘焦点提示展示完整身份，行的无障碍名称包含来源。打开对话后在页头提供同样信息，触屏不依赖悬浮。右侧状态保持独立：运行中、失败、未读结果。完成且已读的会话不持续显示成功标记。

自动化新会话默认采用自动化名称；独立运行的时间放到来源说明或详情，连续会话保持一个稳定标题。尊重用户手动命名，不在每次运行后覆盖。

## 二、区分入口、用途与运行状态

这三类信息不能塞进一个 channel 字段：

- 创建入口：工作台、浏览器扩展、终端、各 IM、API / MCP、自动化触发、系统内部、未知。读取现有来源和创建标记，缺失时保持未知。
- 会话用途：普通对话、自动化执行、工作流执行、工作流子任务、系统任务。从现有类型与可靠关联信息归一化。工作流也可能由自动化触发。
- 运行状态：运行中、失败；阅读状态：未读；管理状态：普通、置顶、归档。分别建模，不能把已有管理状态 active 当成“正在运行”。

会话身份以创建入口和用途为准，不随打开它的客户端改变。手动续聊自动化会话也不抹掉自动化身份；最近由谁续聊属于另一项活动信息。

建议以共享的身份解析规则输出展示描述，供侧栏、会话管理页、搜索结果、页头共同使用。首期复用现有字段，不更改 session key 或路由来源。只有创建入口缺失且确有需求时才增补持久化字段。

## 三、侧栏筛选交互

“项目”标题行只保留标题和右侧菜单、创建项目入口。菜单按钮在标题行悬停或键盘聚焦时显示，打开期间保持显示；触屏始终显示。搜索框收进菜单首页，焦点使用柔和的中性边框，不再在标题行常驻输入框。筛选仍作用于置顶、项目内和未分配会话；搜索结果、加载中及无项目时均保留标题行入口，清除筛选后恢复浏览滚动位置。菜单按钮在搜索或筛选生效时显示小圆点，悬浮提示包含生效维度数。快捷视图、条件摘要和已保存视图均收进筛选菜单，不在侧栏常驻占行。菜单内提供三个快捷视图：

- 全部：默认，保留现有可见会话范围。
- 手动对话：普通对话，排除有可靠自动化 / 系统触发身份的会话。
- 自动运行：自动化发起的会话及工作流、后台系统任务。表示来源于自动执行，不等于当前正在运行。

首次升级保持“全部”，不静默隐藏用户原来可见的对话。后续记住该 Gateway 下用户选择的视图。未知来源始终能从全部找到。

筛选采用同一面板内逐层选择：首页只展示快捷视图、创建入口、项目、最近活动，以及“更多筛选”和“已保存视图”入口。每行右侧显示当前条件摘要，过长时截断；用途、管理状态、Agent 和来源说明开关放在“更多筛选”内。保存表单只在主动选择“保存当前视图”后出现。

面板最大宽 320px、目标高度 416px，受视口和锚点可用空间约束，距页面边缘至少 12px，空间不足时自动翻转。顶部标题、返回、关闭及底部操作固定，中部选项独立滚动，切换页面重置滚动位置。选项复用项目 SelectOptionList，在面板内呈现，不叠加第二层下拉浮层；项目和 Agent 支持搜索。支持：

| 维度 | 首期 | 后续增强 |
| --- | --- | --- |
| 创建入口 | 工作台、浏览器扩展、终端、IM、自动化、系统、其他，多选 | IM 账号、外部会话 |
| 会话用途 | 对话、自动化、工作流、子任务、系统，多选 | 具体自动化 / 工作流 |
| 项目 | 指定项目、未分配 | 多项目组合 |
| 时间 | 最近 7 天、30 天、60 天、不限；以最近活动时间为准 | 自定义范围 |
| 管理状态 | 普通 / 置顶；归档单独显式启用 | 批量管理 |
| Agent | 多 Agent 场景可选 | 多选 |
| 运行与阅读 | 本期先展示，不作为全量筛选承诺 | 运行中、失败、未读；接入完整状态数据后启用 |

同一维度的多选为 OR，不同维度为 AND。例如“终端或浏览器扩展 + xopc 项目 + 最近 7 天”。快捷视图是同一套筛选的预设；手动修改条件后显示“自定义”，不能保留一个与实际条件冲突的快捷视图选中态。

选中条件在首页对应行显示摘要；点击进入该维度即可修改。单选后自动返回上一级；多选即时生效，点击“完成”返回。“清除选择”只清空当前多选维度，首页“清空筛选”清除全部筛选条件，保留搜索关键词和来源说明偏好。关键词在搜索框内独立清除。图标的无障碍名称包含生效维度数。

返回按钮和 Esc 先回到上一级，在首页按 Esc 关闭；切换页面后将键盘焦点移入新页面，搜索页聚焦搜索框，保存页聚焦名称输入框。

首期即时应用，搜索约 250ms 防抖。关闭浮层不撤销选择。刷新后恢复视图 / 条件；搜索关键词不跨新会话恢复。存储按 Gateway 隔离，不持久化令牌。

## 四、搜索结果与边界

- 日常浏览保留置顶 / 项目 / 对话树，以及现有折叠状态。
- 输入关键词或启用显式筛选后，树暂时切换为统一结果列表。每条显示来源和项目线索，消除“匹配项躲在折叠项目里”的问题。清除后恢复之前的树和滚动位置。
- 搜索默认覆盖标题和消息内容，复用现有全文搜索；内容命中摘要属于后续增强，当前接口未提供时不伪造摘要。
- 主动搜索默认时间“不限”，显式时间筛选仍生效。平时 60 天的侧栏截断不应让搜索误报找不到；归档仍需显式包含。
- 置顶、当前打开的会话也遵守筛选，不插入结果冒充匹配。当前会话不匹配时保持主区打开，不显示额外提示。
- 空结果显示当前条件及“清空筛选”；请求失败显示重试，不能显示为零结果。异步结果使用骨架，保留输入焦点。
- 后端完成筛选后分页。结果总数使用同一条件的全量计数，不能取已加载行数或无条件 byChannel 统计作为筛选数量。切换条件重置分页，并丢弃旧请求结果。
- 实时新消息只更新符合条件的项。用户正在扫描或滚动时避免列表突跳，可提示有更新后由用户刷新排序。

## 五、实施顺序

### 第一阶段：可辨识

实现共享身份解析器与图标映射；统一所有会话行的图标槽位；补齐来源提示与可选说明。使用现有元数据，未知安全回退。核对自动化、浏览器扩展、CLI、系统维护的真实创建链路。

### 第二阶段：可找回

接入搜索、快捷视图、入口 / 用途 / 项目 / 时间筛选与条件摘要。筛选态使用通用会话查询输出扁平结果；正常树继续使用侧栏聚合接口，避免同时改造两套分页。补齐共享查询合同与后端所需维度，尤其 browser_extension 的精确识别，不能仅用 webchat 代替。

项目、标签、Agent 等字段需核对完整链路，已有存储字段不代表 HTTP 合同已支持。新增或移动鉴权路由时同步 lazy-bundles 与真实 Gateway 验证；可优先扩展既有查询接口。

### 第三阶段：高频工作流

支持“保存为视图”，如“最近一周浏览器调研”“xopc 终端会话”。增加完整运行状态筛选、未读筛选、账号筛选与具体自动化筛选。重复自动化的多次运行是否折叠为一组单独评估，不在首期改变 session 语义。

## 验收场景

1. 工作台、扩展、终端、IM、自动化、工作流、系统和未知来源都有可解释身份，标题对齐；窄侧栏和暗色主题可用。
2. 普通会话调用浏览器工具后身份不变；自动化触发工作流的入口和用途均可查。
3. 位于第 3 页的历史会话能被搜索找到；搜索默认不受 60 天截断影响。
4. 同维度 OR、跨维度 AND 的结果和总数一致；归档、置顶、当前会话均遵守明确规则。
5. 快速切换条件不会被旧请求覆盖；返回全部恢复原树；失败与空结果可区分。
6. 浏览器扩展与普通 webchat 能精确筛开；缺失历史元数据不会凭标题被误分类。
7. 键盘可打开和关闭筛选、逐层返回及修改选项；来源与状态可由读屏识别，触屏无需依赖 hover。
8. 320×480 窄窗口与 480×320 矮窗口内，靠近页面底部打开筛选仍不越界；长选项列表内部滚动，返回、关闭和底部操作可见。

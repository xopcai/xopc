# 会议笔记布局研究：钉闪会、AI 听记与飞书妙记

日期：2026-11-05。目标：解决当前会议笔记的主次失衡、巨型操作弹层和处理重试空白页，延续已经完成的原话定位、阅读保持与选段交互。

本轮交付研究和布局原型，不修改产品运行代码。依据包括用户截图、当前工作区源码、官方帮助文档与官网图片。未登录竞品企业账号，未执行付费功能和真实会议实验。

## 结论

推荐默认采用**文档优先、辅助内容按需并排**的布局。纪要、原文、我的笔记是内容视图；提问、分享、导出是页面操作；模板和重新整理属于纪要上下文；历史、归档、删除才属于“更多”。

长录音校对另提供原文与纪要的对照阅读模式。纯音频不照搬视频会议的大视频区域，也不把议程、原文、纪要、AI 聊天四块内容同时展开。

截图的问题首先是信息组织和异常状态设计，其次才是按钮尺寸和圆角。把大菜单改窄，只能解决一部分。

## 1. 当前界面的具体问题

1. **操作弹层承担了整页职责。** `DiscussionTools` 把补充、分析、提问、模板、重整、原音再生、下载、分享、三种导出、引用对话、历史和删除放在一个可滚动 Popover 中。混合按钮、表单和说明，逐个使用完整 Button 的边框、圆角及阴影，形成“卡片里面再套按钮卡片”的视觉重量。
2. **高频操作难找，低频维护占据主要空间。** 提问与补充被藏起来，重生成和导出格式长期并列，用户需要先理解整套工具再完成一个简单动作。
3. **内容视图的层级不一致。** 概览、原文、标记并列，但“标记”是原文的筛选/定位方式；用户自己写的笔记反而要从菜单离开会议视图。大面积均分的胶囊标签也放大了工具感。
4. **正在重试时信息量不足。** 页面只显示阶段标题，重要的原音保存事实、失败边界、已有文字和下一步藏在“处理范围”或状态折叠项里。没有转写结果时，正文区域没有单独的解释和可用操作。
5. **核实原话时遮住结论。** 当前 evidence aside 是绝对定位覆盖，用户核对时不能完整并看原结论。此前补的“返回结论”解决了路径，尚未解决宽屏的空间分配。
6. **动作命名重复。** “进一步分析”“就这篇笔记提问”“带到新对话”对新用户相近，却分散在同一个弹层。应明确一个主问答入口，引用片段留在选段上下文中。

截图中央的“Added to clipboard”为系统提示，不计入产品布局问题。图片像素尺寸也不能直接当作 CSS 尺寸：源码里弹层宽度上限是 20rem，高度上限是 38rem/可用视口高度，问题是其内部信息密度和滚动结构。

## 2. 竞品证据与可借鉴之处

### 钉闪会：借鉴会议内容的组织方式

钉闪会是会议协作软件，不能与 A1 录音硬件或 AI 听记混为一个产品。官方 6.5 页面中的历史界面展示了议题导航、讨论材料、结论/待办，以及独立的模板选择和计时工具；7.0 发布页补充了会后填写纪要的能力。[6.5 官方体验页](https://page.dingtalk.com/wow/z/dingtalk/ddhome/zhADPwJ5YttpTXwGZwND)、[7.0 官方更新页](https://page.dingtalk.com/wow/z/dingtalk/default/ZHSIIYW21J8)

对 xopc 的启示是：**把结论和行动放进内容，而不是工具菜单**；模板选择应有自己的配置空间。历史的议题/讨论/结论分区适合主持会议，不意味着个人录音笔记必须默认三栏。

证据等级：官方历史界面。只用于验证组织方式，不当作 2026 年 8.x 客户端的逐像素还原。

### 钉钉 AI 听记：借鉴会后原文与整理结果的分区

国际站官方产品页展示录音转写、章节纪要、行动提取和场景模板。产品图片中，转写区域有自己的编辑/操作入口，整理结果有自己的模板入口，录音控件保持在内容附近。[DingTalk AI Minutes](https://www.dingtalk.io/products/ai-minutes/)

对 xopc 的启示是：**原文工具归原文，整理工具归纪要，播放器保持稳定**。不照搬官网的渐变装饰和模型推荐卡；这些会增加我们的阅读噪声。

证据等级：国际站产品介绍和宣传示意图，不证明中国版当前套餐、准确率、具体权限或全部交互位置。中国版开发者应用说明还提到首页和导出更新，可作为版本方向补充，不能替代桌面界面实验。[钉钉开发者应用说明](https://m.app.mi.com/details?id=com.alibaba.android.rimet)

### 飞书妙记：借鉴内容联动与局部工具栏

官方帮助页明确展示媒体与文字区域，纪要/文字记录在文字区域切换；原文点击可定位播放，搜索、校对和导出靠近文字记录，分享在页面顶部，选段后出现高亮/评论/片段等局部动作，并支持调整分隔栏。[查看妙记](https://www.feishu.cn/hc/zh-CN/articles/022111234449-%E6%9F%A5%E7%9C%8B%E5%A6%99%E8%AE%B0?lang=zh-CN&open_in_browser=true)

对 xopc 的启示是：**同一个阅读任务应就地完成，操作跟着对象走**。音频笔记只需紧凑播放器，无需复制妙记的大视频区域；右侧空间优先给正在核实的原话或问答。

智能纪要帮助说明还把总结、待办、章节和编辑联系在一起；另一篇官方介绍确认了基于妙记直接问答的方向。它们支持内容→追问→行动的流程，但不能据此断言所有账号都有相同界面。[会中使用智能纪要](https://www.feishu.cn/hc/zh-CN/articles/244959839578-%E5%9C%A8%E8%A7%86%E9%A2%91%E4%BC%9A%E8%AE%AE%E4%B8%AD%E4%BD%BF%E7%94%A8%E6%99%BA%E8%83%BD%E7%BA%AA%E8%A6%81)、[智能会议纪要介绍](https://www.feishu.cn/content/article/7594772423082396858)

### 调研过滤规则

- 排除自称官网的近似域名、无依据的下载站介绍。
- `dingtalk.com/qidian/` 中存在标明由通义千问生成的营销页，不用它们证明精确功能、操作步骤或布局。
- 区分“搜索摘要读到了内容”“浏览器打开官方页面”“查看了页面中的产品截图”“登录实际操作”四种证据。本轮完成前三种，未完成第四种。
- 官方 6.5 页面及飞书帮助页在文本抓取中有空正文/缺图现象，已通过浏览器读取正文和图像地址进行核对。

## 3. 三种布局的比较

| 方案 | 默认结构 | 优点 | 代价与适用范围 |
|---|---|---|---|
| A：文档优先，推荐 | 一块正文；原话/AI 按需占用辅助栏；底部一条播放器 | 短录音和长纪要都能先读内容；核实时不遮挡结论；普通笔记心智一致 | 需要统一阅读状态与辅助栏所有权 |
| B：原文对照 | 左原文、右纪要/问答；同一播放器 | 频繁核实、校对、长访谈效率高 | 默认两栏对 19 秒短录音过重；窄屏需回到单栏 |
| C：固定三栏会议工作台 | 左议程、中讨论材料、右结论/行动 | 适合主持会议、协作填议程、控制会议节奏 | xopc 当前主要是个人录音回顾；会引入额外概念和空面板，暂不作为默认 |

**选择：A 作为默认，B 作为宽屏对照模式；C 留给以后独立的会议主持场景。** 比较的是阅读任务，不评判哪款竞品整体更好。

## 4. 推荐方案的页面结构

```text
标题 + 时间 / 时长 / 保存状态             AI 提问   分享   导出   …
纪要    原文    我的笔记                        上下文设置 / 搜索
────────────────────────────────────────────────────────────
主内容：摘要、决定、行动、章节       │ 辅助内容（按需展开）
                                    │ 原话依据 或 AI 提问
用户手写内容独立保留                 │ 一次只显示一种
────────────────────────────────────────────────────────────
播放 / 时间 / 进度 / 倍速 / 标记       （同一播放器）
```

1. 标题区控制在两行信息层级内，保留时长、来源/时间及保存事实，不重复渲染多张状态卡。
2. 标签用内容宽度和轻量下划线，避免三等分的大胶囊。默认纪要；“我的笔记”直接对应现有个人 Markdown。
3. “标记”放到原文内的“仅看重点”筛选及时间轴入口；它是定位内容的方式，不是另一套文档。保留用户可发现的名称和数量。
4. 正文按摘要、决定、行动、章节组织。先降低卡片数量，用排版和细分隔线区分结构。不得为了填满空间生成虚假内容。
5. 宽屏点“原话”后，辅助栏挤出自己的空间，主文档仍可见；每段证据分别回听。AI 提问复用该区域，打开时关闭原话辅助栏，防止形成第三栏。
6. B 模式下，原话定位左侧现有逐字稿，不再弹第三块面板；AI 可替换右侧内容，不同时堆叠。
7. 播放器独立于标签与面板，切换时不重建；来源、播放范围、位置继续由现有 review state 管理。

### 操作应该放在哪里

| 当前操作 | 新位置 | 交互要求 |
|---|---|---|
| 就这篇笔记提问 | 标题右侧 AI 提问 | 后续接入就地问答；未生成文本时解释不可用原因 |
| 进一步分析 | AI 提问中的建议问题/能力 | 保留真实服务差异，不能仅换文案就把催化报告与问答当成同一实现 |
| 添加我的补充 | “我的笔记”标签；原文选段也可添加 | 不离开当前 Note；与派生结果分开保存 |
| 模板选择、重新整理 | 纪要内容区的“整理方式” | 在独立固定尺寸对话框里选择、确认；保留人工编辑 |
| 从原音重新生成 | 整理方式里的高级操作 | 与普通纪要重整明确区分；旧结果保持可读 |
| 分享笔记 | 标题右侧分享 | 明确文字、原音附件、访问范围，沿用既有分享能力 |
| MD / TXT / SRT | 标题右侧“导出”对话框 | 展示格式名称，支持已有内容范围；不要三种缩写永久平铺 |
| 下载原音 | 播放器菜单或简短的更多菜单 | 不与“导出文字”混称，原音不可用时说明原因 |
| 带到新对话 | 选段引用提问；通用引用可留导出/分享次级入口 | 引用的范围和版本可见；不重复一个模糊的聊天按钮 |
| 搜索 | 原文/纪要区域工具 | 保留 Cmd/Ctrl+F 和跨类型搜索，命中可回听 |
| 版本历史、重命名、归档、删除 | 紧凑更多菜单 | 约 4–6 个菜单行，删除单独分组；不放下拉表单和大段说明 |

## 5. 重试和空白状态必须一起改

用户截图只有 19 秒，不能假设一定有长篇逐字稿或完整纪要。按实际可用材料展示：

| 状态 | 页面应该告诉用户 | 可用动作 |
|---|---|---|
| 原音已保存，尚无文字，正在自动重试 | 原音已保存；文字暂不可用；系统会继续尝试；具体错误可展开 | 回听、添加补充、下载原音、稍后回来 |
| 有部分文字，后段失败/重试 | 保留已完成文字，显示实际覆盖/缺口；不显示虚假完成率 | 阅读已有原文、标记可定位部分、等待/继续处理 |
| 原文完整，纪要整理失败 | 原文和原音可用；失败的是纪要 | 看原文、回听、仅重新整理纪要 |
| 原音仍在上传或校验 | 说明上传与可回听的区别 | 不能直接承诺服务端原音已保存 |
| 原音被删除，文字仍在 | 原文可读；回听不可用 | 阅读、导出允许的文字；不恢复播放控件 |
| 加载正在进行 | 用与实际内容结构对应的 skeleton 保留布局 | 不用满页转圈，也不伪装已有内容 |

自动重试等待属于状态解释，不应永远摆一组闪烁 skeleton。只有实际加载才用 skeleton。下次重试时间只取真实 `processing.nextAttemptAt`；没有预计完成时间就不显示倒计时。

继续使用采集/本地保存/原音同步/派生处理四条状态线。状态设计引用当前共享投影，不能凭客户端计时器或一个 completed 标记重新解释原音安全。

## 6. 响应式与可访问性

以下尺寸是建议起点，实施时按**当前笔记容器实际宽度**判断，不按整块显示器或截图像素决定：

- 默认正文阅读宽度约 680–760 CSS px，左右留白随容器变化；不让中文正文跨整屏。
- 可用容器约 1100px 以上才并排主文档与约 340–400px 辅助栏，且主文档保留可读宽度；否则使用单栏和可关闭的独立证据面板。
- 对照模式在可用容器足够时启用，原文约 40–45%、纪要约 55–60%，允许有约束地调节分隔线；窄屏退回标签切换。
- 窄屏辅助内容采用有标题、关闭、内部滚动的 sheet；固定播放器保持可达，不能覆盖正文末行。
- 桌面普通菜单行约 32–36px；触摸设备有效目标至少 44px。正文建议 15–16px、行高 1.7–1.9，辅助文案保留清晰对比度。
- 所有菜单、导出和辅助面板支持键盘；关闭后还原触发焦点；Esc 只关闭最上层。保留低动态效果偏好。

## 7. 结合现有代码的实施顺序

### 第一批：低成本修复当前最明显问题

- 将 `DiscussionTools` 拆为页面常用动作、简短的更多菜单、导出对话框及整理方式对话框。
- 为 `RecordingOutcomeCard` 增加适合 Note 正文的异常状态呈现，显示已有材料和下一步；保留共享状态契约。
- 标签层级收敛，把个人 Markdown 的补充入口前置；让“原文暂无内容”有明确提示。

这批可以先复用现有 onChat/onAnalyze/onShare/onHistory 和导出接口；AI 按钮仍调用原有聊天入口时，必须如实呈现为跳转，不能伪装成已实现就地问答。

### 第二批：宽屏原话并排，保留已经做好的交互

- `DiscussionNoteSections` 改为主文档 + 统一辅助区域，沿用 revision/segment IDs 和播放器状态。
- 保留“结论→原话→原文→返回”的焦点、选中和滚动恢复；辅助栏打开只调整空间，不丢失文档位置。
- `useDiscussionReading` 与 `DiscussionLongReview` 的更新提示保留，并统一更新入口，避免在同一 Note 出现两条互不解释的“查看最新”。

### 第三批：对照阅读与真正的就地问答

- 对照模式复用逐字稿和分析数据，不复制一套证据模型。
- 就地问答需绑定 Note/Discussion 及修订、真实证据检索与会话生命周期。当前 noteActions.onChat 是导航到聊天，不是现成的侧栏问答接口。
- 催化报告、生成摘要、普通问答仍按真实能力区分。选段摘要/待办当前是本地规则，不用新布局包装成新增模型能力。

## 8. 验收

- 原话、提问、分享、导出均有明确入口；“更多”正常桌面高度下不需要滚动，也没有嵌套大按钮。
- 在重试状态，用户能回答“录音是否保住、哪里失败、现在能做什么”，无须翻开多层技术详情。
- 从结论定位到第 70 段，再返回，保持原先阅读位置、焦点及回听进度；旧修订不能定位到新版同号段落。
- 搜索/标签/辅助面板切换不重建播放器；新内容到达不强制滚动或清空选区。
- 正文、对照、证据、重试、菜单及导出在 1440、1024、768、390 CSS px 与深色模式下可用；特别覆盖打开应用其他侧栏后容器变窄。
- 继续遵守网关鉴权、版本冲突、任务幂等、原音恢复和人工内容保护；布局变更不改变业务语义。

本轮原型仅用于比较和验证布局交互，不能当成产品已经完成改版的证明。后续业务接入仍需组件回归、真实 Gateway 与浏览器验收。

## 方案 A 的本次落地（2026-11-05）

- 文档主视图改为「纪要 / 原文 / 我的笔记」轻量页签；标记放回原文内筛选。正文保持最大 46rem 阅读宽度，页面可充分使用大窗口。

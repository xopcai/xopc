## 1. 产品目标

让个人工作者在会议中专心交流，会后快速确认结论、安排下一步，并在后续工作中持续使用会议知识。

首版价值承诺：**会议录得完整，纪要有据可查，下一步可以直接落实。**

优先用户：一人公司经营者、项目负责人、独立顾问及频繁进行客户沟通的个人。首版优先通用会议、项目例会、需求评审、客户访谈。

核心使用故事：从项目开始一场 75 分钟讨论，结束后自动获得带原话依据的纪要；将两条行动加入任务，把其中一条交给助手；后续从任务返回会议证据。

## 2. 范围与优先级

| 阶段 | 交付范围 | 不属于本阶段的内容 |
|---|---|---|
| P0 可信纪要 | 120 分钟麦克风录音、音频文件导入、可靠保存与恢复、逐字稿校正、说话人标签、章节、证据回听、四种纪要模板、任务转换、基本导出 | 会中滚动总结、系统音频、跨会议自动追踪 |
| P1 会中助手 | 会中重点、补听问答、重点标记、桌面系统音频、会议后语音复盘 | 无需用户操作的自动入会机器人 |
| P2 连续工作 | 会前准备、跨会议决定变化、承诺跟进、移动原生后台录音、授权的平台资料导入 | 完整组织管理和自建视频会议服务 |
| P3 扩展 | 图文纪要、多语言阅读、音频简报、自定义模板、团队协同 | 依据使用情况再排优先级 |

P0 的说话人功能包括标签、更名、合并和纠正。自动分离依赖处理服务能力，至少一条经过验收的处理链路才能宣称支持多人识别；不支持的配置显示“未区分说话人”，仍可记录与整理。

首版上限按有效录音时长 120 分钟、导入单文件 1 GiB 设计。达到限制前提示，达到上限自动结束并保存；暂停不计入有效时长。具体支持环境和文件编码由发布验收清单确认。

## 3. 产品原则

1. 录音正常时无需填写表单：开始、结束是主路径的两次操作。
2. 自动生成纪要；不增加必须通过的会议审核环节。
3. 用户更正和 AI 内容分开保存，重新整理不覆盖手写内容。
4. 结论、提议、承诺和 AI 建议分别呈现。
5. 会议录音是材料，用户显式委托才触发执行。
6. 已保存、已转写、已整理分别显示，不能用“处理中”掩盖录音故障。
7. 用当前任务、项目和主动服务承接后续工作，保留一个真实任务状态。

## 4. 入口与信息架构

### 4.1 四个语音入口

| 入口 | 默认行为 | 结果归属 |
|---|---|---|
| 语音输入 | 结束后插入草稿，不自动发送 | 当前编辑框 |
| 与助手通话 | 延续现有 Chat，按通话模式使用工具 | Chat 和已有任务 |
| 记录会议 | 麦克风录音，默认不播报、不执行 | 会议笔记 |
| 导入录音 | 上传并异步整理 | 会议笔记 |

同设备麦克风占用沿用现有互斥管理。冲突时提供“结束当前通话并开始录音”，明确点击才切换；不静默中断。

### 4.2 导航

- 笔记中增加“会议”筛选，不新增顶级菜单。
- 项目页增加“记录会议”“导入录音”和会议列表；默认关联当前项目。
- 全局快捷入口启动录音；未归属项目的会议先保存在笔记。
- 会议详情延续已有笔记入口，以 `noteId` 定位；项目中的入口指向同一条记录。
- 首页使用现有提醒位置展示“可恢复的录音”“纪要生成失败”；恢复前明确列出设备和录制时间。

### 4.3 会议列表

卡片显示标题、日期、时长、项目、来源、处理状态、未转任务的行动数。支持按日期、项目、处理状态搜索和筛选。

空态主操作为“记录会议”，次操作为“导入录音”。加载使用骨架屏；长时间任务显示真实阶段，不使用无限页面转圈。

## 5. P0 用户流程

### P0-01 开始录音

前置：本设备支持采集、有本地存储空间、用户已完成现有录音告知设置。

1. 用户点击“记录会议”。
2. 如需操作系统麦克风权限，显示系统授权；失败时提供重试和设置入口。
3. 权限取得后立即录音和本地保存，不等待模型或网络。
4. 后台创建会议笔记，继承当前项目；标题先用“会议 · 日期时间”。
5. 出现全局悬浮条，用户可以继续浏览其他页面。

没有转写服务时允许先录音，明确“录音正常，配置语音服务后可转写”。本地存储不可用时不宣称录音可恢复，阻止进入长会议录音并显示解决方法。

### P0-02 录音期间

悬浮条显示：标题、有效时长、采集来源、保存状态、暂停、结束。展开可查看转写、重命名、关联项目与设置说话人。

保存状态示例：

- “已保存至 38:10”：已获得服务端持久化确认。
- “本地保存至 38:10，等待上传”：用户离开此设备前应恢复上传。
- “录音已中断，已保存至 38:10”：立即吸引注意，不能继续计时假装正常。

暂停停止采集；恢复继续同一会议。界面显示有效录音时间，历史暂停点在时间轴上可识别。

### P0-03 结束与处理

点击“结束”即停止采集并打开会议详情。关闭详情不影响服务端处理；尚未上传的部分仍依赖当前设备，离开时说明待上传量。

状态顺序：保存录音 → 补齐转写 → 整理纪要 → 完成。已有内容先展示，未完成区域使用骨架与阶段说明。

120 分钟上限前 5 分钟及 1 分钟各提示一次；到时自动保存结束。服务端可拒绝超限，客户端不得隐藏超出范围或伪造时长。

### P0-04 导入

用户选音频文件，支持 WAV、MP3、M4A/MP4 音频、WebM/Opus、Ogg/Opus；扩展名仅用于选择，最终按实际编码校验。首版不承诺提取视频画面。

先检查大小，再读取媒体时长与编码；无法在客户端确认时上传后由服务端检测。检查失败保留错误原因，不能按零时长继续整理。

同一设备重复选取相同文件提示打开已有导入或明确创建副本。网络重试沿用同一导入，不能新增笔记。导入完成后与现场录音使用同一详情页。

### P0-05 恢复

恢复卡列出：时间、项目、本地已保存时长、待上传部分。操作为“恢复上传”“保留稍后处理”“删除本地草稿”。

恢复上传不自动重新打开麦克风。要继续录音必须再次点击，并建立可识别的新采集区间。

删除服务端会议与删除本地草稿分开表述；任一删除不得让另一端悄悄重新上传已删除会议。

## 6. 会议详情页

### 6.1 桌面布局

```text
会议标题                          项目 / 来源 / 日期
75:00 · 整理完成                   导出   更多
-----------------------------------------------------
纪要 | 逐字稿 | 我的笔记
-----------------------------------------------------
主要内容                              原文证据抽屉
一句话结论                            说话人 B · 38:12
关键决定                              原话及前后文
行动项                                定位回听
章节摘要
-----------------------------------------------------
音频播放器：播放 / 进度 / 速度 / 当前时间
```

首屏主动作随上下文变化：录音中为“结束”，完成后有未转换行动时为“加入任务”。其他操作使用次级样式。

详情采用页面；证据抽屉固定响应式宽度，内部滚动。移动端先呈现纪要与行动，证据通过底部面板打开。播放控制常驻，不能遮住底部操作。

### 6.2 纪要

顺序：一句话结论 → 关键变化 → 已决定/待讨论 → 行动项 → 风险与未决问题 → 章节。没有内容的区块折叠或不显示，禁止自动填充“无风险”等未经证实结论。

每条决定、行动、风险可点“原话”，打开证据抽屉。章节可跳到对应逐字稿与音频位置。

切换模板重新整理结构，保留原稿和用户编辑。新结果就绪后展示“查看更新”，由用户应用到当前视图；已经修改的字段保持修改或单独比较，不静默替换。

### 6.3 逐字稿

按说话人和发言段排列，显示媒体时间、文本及待校对标记。支持关键词搜索、上一处/下一处、按说话人筛选、编辑段落与更正说话人。

录音未结束时可校对已完成片段；新转写不能抢回输入焦点。结束后仍可编辑，保存产生新修订。

自动识别仅给“A/B”标签。更名只作用本会议；合并需预览影响范围。拆分时选择具体发言段，不自动推断真实身份。

### 6.4 我的笔记

用户自由填写的内容，与系统纪要分开。重点标记及用户备注可在此汇总，明确哪些属于个人备注，导出默认不包含。

### 6.5 导出与分享

P0 提供纪要 Markdown、逐字稿 TXT、带时间戳字幕 SRT（仅有合格时间轴时），以及原音频下载。导出可选是否包含说话人、证据时间；不得输出服务端内部文件路径或令牌。

沿用已存在的分享能力前，必须验证会议投影是否被包含。若尚不能可靠隔离摘要、原文、音频和私人备注，P0 仅交付导出，不新增会议公开链接。

## 7. 行动项与助手执行

### 7.1 行动卡字段

内容、负责人原话/确认身份、期限原话/解析日期、证据、任务状态。未知字段显示“未明确”，允许创建无日期的个人任务。

“我来做”仅在身份确认后归属本人；模型不能把说话人 A 自动当成当前用户。相对日期按会议发生时间及其时区解析，歧义保留原话。

### 7.2 加入任务

用户勾选行动并点击“加入我的任务”，即可建立真实 Task 及会议来源链接。成功后卡片变成“查看任务”，任务状态从 Task 读取。

同一行动重复点击、请求超时重试、多端同时操作只得到一个任务。重生成纪要不会创建新任务。内容变化时展示差异并允许更新任务，原有任务不静默修改。

误创建可撤销尚未开始的任务；已运行任务使用现有取消/删除语义，说明不能撤回已发生的外部效果。

### 7.3 交给助手

展示任务目标、期望交付物、关联项目与会议证据；缺少必要信息才询问。已有权限继续沿用，录音中的内容不能增加权限。

如果行动已创建任务，委托启动该任务；不另建副本。助手的执行进度和交付物出现在现有任务详情，会议页展示简要状态与链接。

## 8. P1/P2 交互契约

### P1 会中助手

- 当前重点仅基于已处理转写，显示理解截止时间。
- 问答默认文字，引用原话；“没有记录到”与“没有发生”严格区分。
- 补听支持最近 5 分钟/离开之后；时间范围可调整。
- 重点标记不依赖转写完成，保存媒体定位和可选备注。
- 系统音频入口清楚标出“麦克风 + 电脑声音”，两路分别检测；远端声音未采到时明确告警。
- 语音复盘从当前会议开启现有助手通话，带入来源上下文；是否播放和占用麦克风由用户主动控制。

### P2 连续工作

- 会前卡包含会议目标、上次决定、未完事项及资料；没有日历则从项目显式启动。
- 跨会议比较显示“上次决定 → 本次变更”，每条附各自来源。
- 委托跟进后只在有意义的变化时通知；任务完成作为任务事实，不由 AI 自行猜测。
- 原生后台录音单独验收，网页可运行不代表支持锁屏持续录制。

## 9. 错误与降级

| 情况 | 用户看到 | 可用操作 |
|---|---|---|
| 麦克风拒绝/被占用 | 未开始录音及原因 | 重试、打开设置、显式切换占用 |
| 网络断开 | 本地保存正常、待上传时长 | 继续录音、结束 |
| 存储不足/设备中断 | 已停止及最后保存位置 | 保存现有录音、释放空间 |
| 转写失败 | 录音可播放，失败区间 | 重试失败片段、配置服务 |
| 不支持说话人 | 未区分说话人 | 手动标注、更换受支持处理服务 |
| 纪要失败 | 录音、逐字稿可用 | 重试整理、直接导出 |
| 有录音缺口 | 明确标记缺失时段，纪要注明不完整 | 恢复本地文件或接受部分结果 |
| 原音频已删除 | 原文仍在，回听不可用 | 阅读、导出文字 |
| 并发编辑冲突 | 本地修改保留，提示已有更新 | 比较后再保存 |
| 预算耗尽 | 已保存部分不受影响，云处理暂停 | 调整预算、改用允许的处理方式 |

取消处理保留录音；删除需使用删除操作。云端失败不得自动切换到用户未允许的其他云服务商。

## 10. 验收标准

以下为设计目标，尚无本次实测结果。验收基线与技术方案一致。

| 编号 | 可验收结果 |
|---|---|
| A01 | 完成首次设置后，一键开始；路由切换不停止录音 |
| A02 | 120 分钟录音完成，最后一分钟的决定、行动进入纪要 |
| A03 | 断网、客户端崩溃、服务重启后恢复已确认保存部分；缺口明确 |
| A04 | 暂停恢复后证据定位仍正确，定位误差按原始粒度报告 |
| A05 | 决定、提议、否定、未明确负责人各类样本不混淆 |
| A06 | 修改逐字稿后产生新修订，旧纪要证据仍能打开 |
| A07 | 模板切换/重生成不覆盖个人笔记或已确认字段 |
| A08 | 双击、超时重试、并发转换只创建一个任务 |
| A09 | 任务完成后会议卡同步更新，不维护第二套任务完成状态 |
| A10 | 删除音频后原音频和临时块清理，回听不可用但保留文字 |
| A11 | 未授权材料不可检索、导出或通过问答间接泄露 |
| A12 | 会议中的工具指令不被执行；用户主动委托正常进入任务流程 |

人工验收集建议 ≥30 场，保留独立测试部分；关键行动/决定召回 ≥90%、精确率 ≥95%、引用正确率 ≥95%。质量按语言、环境和处理链路分组，不以平均值掩盖弱项。

首个片段云转写目标 ≤20 秒；实时转写已经完整的会议，会后纪要目标 ≤2 分钟。文件导入、纯本地处理单独报告，不适用相同延迟承诺。

产品指标：录音完成率、恢复成功率、每小时修正耗时、行动转任务率、助手交付完成率、会议复用率；不得仅用生成纪要篇数衡量成功。

## 11. 交付拆分

1. **P0-A 可靠输入**：长录音、分块保存、导入、恢复和处理状态。
2. **P0-B 可信理解**：时间轴、说话人、修订、证据、长文完整整理。
3. **P0-C 工作闭环**：会议详情、校对、四种模板、任务转换、导出。
4. 三段合并完成真实录音验收后，发布会议助手首版。

默认取舍已确定：本轮 PRD 覆盖 Web/桌面麦克风与文件导入，系统音频在 P1 发布，但在 P0 开始技术验证。后续若将系统音频提升为首版硬要求，必须同步更新阶段范围与验收清单。

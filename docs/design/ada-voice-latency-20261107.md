# Ada 语音延迟优化与实测

日期：2026-11-07。目标：完整短句说完后 1.5 秒内开始有效回复。**本轮未通过该目标验收。** 已完成代码优化、真实服务排查和隔离快照测试；以下音频指标到客户端收到首帧，不是物理扬声器首声。

## 已落地

- 识别负责静音判停，去掉协调器补足 1200 ms 的隐藏下限；完整 final 的额外缓冲由 350 ms 改为 40 ms。未完成句子的延长等待保留。
- TTS 在识别到用户讲话时预连接，不提前提交文字或执行工具。Cloud 接通预连接并保留独立分段预取，正确区分文本 flush 与音频完成。
- 中文首短分句及时提交；无完整边界的首段等待由 300 ms 改为 120 ms。保留单词、链接、代码和表格保护。
- Web 使用交互式播放延迟，首帧调度由 80 ms 改为 20 ms；插话先可逆降音量，足够长的非回声 partial 稳定 180 ms 后可提前停止旧播报。只有 final 才执行新输入。
- 增加语音专用模型、思考和历史预算。Ada 的口语提示词保留身份、工作区指令、安全、信任、记忆权限和协作契约；文字模型及提示词不被改写。
- 只对提供商请求裁剪较早的完整历史轮次。保留所有系统指令、当前执行及其中途补充指令；完整 SQLite 历史仍可检索。能放下的投影请求跳过无关旧历史的前台压缩。
- 去掉同一轮主模型应用与系统提示构建的重复操作。
- 实时识别支持独立选择已配置的 Alibaba 流式模型，不影响批量转写设置，也不影响 Cloud 的仅流式识别模型。

## 测量方法

测试音频为本地合成的普通话“你好，请用一句话介绍一下你自己。”，16 kHz 单声道 PCM16，按 20 ms 帧实时发送。去掉首尾低能量帧后，有效测试音频约 3.1 秒。从最后一帧语音发送时刻计时，继续发送静音直到回复结束。播放确认使用即时排空的模拟接收端，因此这些数字只用于定位链路延迟。

Ada 测试使用在线 SQLite backup 生成的私有副本，复制必要凭据与 Agent 配置；禁用副本自动化和待处理输入，使用副本的实际个人会话。测试没有删除、重置或向原 Ada 会话追加测试问题。模型比较通过隔离网关的配置保存接口生效。

早期临时会话探针与实际 Ada 会话不是同一上下文，不能将二者直接拼成整体提速百分比。以下最近秩百分位样本很少，不构成生产 SLO。模型、历史预算、冷暖状态和后台构建负载也并非完全相同。

## 判断与后续边界

代码中可控的重复等待、握手串行、首分句与播放缓冲已经缩短。真实 Ada 中，识别仍常需约 0.8–1.1 秒，模型首字仍在约 0.8 秒到数秒间波动，合成约 0.2–0.4 秒；仅靠继续降低本地计时器不能稳定实现完整 1.5 秒目标。

没有用固定“好的”音频充当有效回复，没有预先执行未确认的 partial，没有删除历史或降低现有审批要求，也没有把停止播报伪装成任务取消。下一阶段要按相同口径验证更低延迟的识别/模型服务，或完成保留 Ada 工具能力的原生实时语音桥；直接切换现有无工具的自然语音模式不能算同等能力验收。

实现参数、计时脚本和测量限制见[语音技术参考](../reference/voice-runtime.md)。

## 追加：自然语音行动桥

自然语音已接入现有 `VoiceAgentBroker`：实时模型只有执行、状态、取消三个入口，Agent 继续使用原有工具与授权规则。工具参数完成并且回复成功结束后，仍需等待用户轮次确认和转写落库才提交执行；不执行被中断的推测回复。重复调用 ID 和同一轮相同任务不会重复提交。受理状态立即返回，后台结果在当前说话和播放结束后有界回传；原始工具结果不会整包注入实时上下文。

打断或停止播报不会取消已受理的 Agent 任务。取消执行必须走单独的 `agent_cancel` 或 `task.cancel`。挂断只分离事件订阅。Web 通话保留任务进度、澄清与审批控件，并提供独立取消按钮；澄清问题绑定到后续播报的响应编号，以兼容现有原生客户端。停止播报后即使没有新的用户发言，后台完成结果也能继续播出。

## 追加：身份与记忆一致性

后续验收发现，单有调用 Agent 的能力不等于自然语音具备相同的用户认识。原生提示只有人格和选取的历史；显式用户资料没有独立保留，可选记忆超限会整段跳过，默认会话的 Agent id 也可能错误回落到 `main`。历史中的助手姓名猜测会干扰较小的实时模型。

修复后文字和语音共享已确认资料的读取与权限规则。语音用户资料独立保留在 800 字符预算内；历史之后另有确认身份检查点。只在语音上下文投影中移除历史助手姓名猜测与用户疑问，不改写原始历史。较新的明确称呼更正可覆盖旧资料的本次通话快照，不直接改写已保存资料。确认事实和工作假设分开，小条目不会因另一个条目过大而一起消失。读取本地完成，不为已确认姓名增加模型请求。

另修复原生语音的后台学习漏接：队列、恢复扫描和证据读取现在识别 `voice_omni_transcript` 的逻辑说话人，并兼容默认路由为空的本人聊天。内部和子任务会话不会因缺少路由而自动当作本人发言。保留原始证据编号和私密范围，不把助手发言升级成用户声明，也不重复保存语音历史。实时模型生成的任务说明使用隐藏的 `voice_agent_instruction` 上下文保存，新任务与运行中追加任务均不作为用户姓名声明或后台学习证据。

真实 Higgs 已验证四种合成身份场景：已确认称呼优先于助手猜测、未知姓名保持未知、刚明确自我介绍但尚未写入长期资料时能正确回答，以及较新的明确更正覆盖旧称呼。初次仅加规则、移动检查点的实测仍曾出现猜错与忽略更正；加入历史身份来源过滤和明确更正的本地投影后，四个场景全部通过。不能把仅修改提示词视作充分修复，也不能将四个样本当作所有措辞和模型的准确率保证。

最终回归覆盖 43 个测试文件，41 个通过、2 个选择性跳过；433 项通过、5 项跳过。额外真实服务四场景全部通过。核心类型检查、类型声明与 Node 构建、相关 ESLint 和 diff 格式检查通过。新增真实 AgentSession 集成验证确认：自然语音生成的任务说明可以执行并保存为隐藏上下文，不会保存成普通用户发言。

对实际 Ada 数据库的一致快照进行了本地只读组装检查：361 条上下文消息，用户资料和可选记忆均保留，当时最终提示 7977 字符，身份检查点位于历史之后。没有向该会话追加诊断问句，也没有擅自填写姓名。用户自行补充资料后，已通过认证接口确认已设置称呼，未输出或覆盖其值。最终源码已通过现用开发 Gateway 的完整进程重启加载，确认新进程健康且资料仍可读取；用户需重新发起通话。未进行真机声学延迟复测，因此本次不能新增宣称稳定达到 1.5 秒。


## 追加：持续陪伴通话与选择性主 Chat

实现统一通话入口，普通语音和执行过程留在同一会话的隐藏流中。实时模型用 `chat_publish` 选择有价值的解释、确定结论和用户明确要保留的内容，作为自然助手消息写入主 Chat；不伪造用户总结、不新增通话卡片。实际 Agent 结果独立于通话保存。备用引擎有实际工具执行时同样保留结果，已明确发布的内容不重复写入。发布按转录边界去重，重置后的迟到结果不会混入新记录。

默认自动选择支持行动的实时引擎，兼容场景在拨号前回落到现有 Agent 引擎，高级设置保留显式覆盖。去掉客户端拨号前重复读取状态的串行请求。通话期间本地主 Chat 更新以引用上下文同步，不主动触发回答；刷新期间的新更新会再合并读取。已整理的后台回复可在交流空隙播报，避免再次委派。重拨恢复同一会话／转录内仍运行的语音任务，播放中断和显式任务取消独立。

### 实测与被拒绝的调参

隔离 Gateway 使用全新数据库、临时工作区并关闭消息通道；只复用必要的服务凭据。诊断没有向实际 Ada 会话追加测试问句。

| 场景 | 结果 |
| --- | --- |
| 普通陪聊三轮 | 主 Chat 零条新消息，六条原始语音隐藏保存 |
| 明确要求留下两项建议 | 主 Chat 一条自然助手消息，两条原始语音隐藏保存 |
| 委派历史查询 | 提交约 1.046 秒；Agent 如实报告跨会话隐私限制，主 Chat 一条真实结果、执行过程隐藏；不将其记为查找成功 |
| 明确取消 | 真实运行进入 cancelled，保留取消结果 |
| 挂断再重拨取消 | 找回同一任务并成功取消；只有一条主 Chat 结果 |
| 挂断、不取消 | 任务继续，最终结果仍保存在主 Chat |
| 身份来源四场景 | 真实 Higgs 再次全部通过，未覆盖用户自行填写的资料 |

压缩提示后普通对话的五轮首音频为 1826、1813、1547、1542、1530 ms。最终稳定参数复测为 **1535、1545、1571 ms，p50 1545 ms、p95 1571 ms，0/3 达到 1500 ms**。行动类最终样本提交 1002 ms、首音频 1855 ms、Agent 终态 9734 ms；任务接收不是完成目标的证明。这些都从最后一个有效 PCM 输入帧计到网络收到首音频，不包括扬声器实际出声。

两次将 Higgs 语义断句压到 120 ms 的尝试均出现 INPUT_DROPPED，分别使用 900 ms 和 1500 ms 转写确认期限；均未采用，保留 180 ms。1500 ms 确认期限只用于异常可用性，不是每轮固定等待。某次原生分阶段测量中，断句后 456 ms 出现模型 response、758 ms 确认转写、1074 ms 收到首音频；音频本来就在转写之后，删除确认门槛不能解决该样本的延迟。没有为追数值提前执行未确认输入，也没有用固定应答音频冒充有效回复。

**1.5 秒目标仍未完成。** 当前配置的端到端耗时主要来自服务端判停、实时模型／转写和音频生成，后续需要以同口径验证更快且支持行动的服务或区域；不能仅凭本地计时器宣布达标。

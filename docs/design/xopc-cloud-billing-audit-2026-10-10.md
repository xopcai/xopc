# XOPC Cloud 扣费规则核查

核查日期：2026-10-10。范围：生产数据库中当前启用的 7 个公共服务、实际协议价格、最近 7 天用量与结算记录，以及账本一致性。核查未修改线上价格或账单。统计期间服务仍有实时调用，未结算数量可能变化。

## 当前生效价格

账本使用人民币最小计费单位：1 元 = 1,000,000 atomic。数据库中的 credits 字段存储 atomic，不是“1 credit = 1 元”。

| 服务 | 已发布档位 | 实际扣费规则 |
| --- | --- | --- |
| auto | metered | 输入 ¥1 / 百万 token；输出 ¥4 / 百万 token |
| advanced | metered | 输入 ¥1 / 百万 token；输出 ¥4 / 百万 token |
| image | metered | ¥0.0001 / 实际返回图片 |
| stt | metered | ¥0.0001 / 分钟，每次向上取整，非空音频至少 1 分钟 |
| tts | metered | ¥0.0001 / 千字符，每次向上取整，非空文本至少 1 档；字符按 Unicode code point 计算 |
| realtime | metered | 文本输入、音频输入、文本输出、音频输出四项费率全部为 0，当前实际免费 |
| computer | free | 不扣余额；保留免费请求与 token 配额 |

7 个服务的草稿价格、已发布价格与实际执行表价格一致。auto 与 advanced 当前没有价格差异。图片、STT、TTS 的原始单价都是 100 atomic，换算为人民币后不是 ¥100，也不是 ¥0.01。

Computer Use 当前限额：每分钟 10 次、并发 2、每天 50 次、每天 100,000 token。服务自身输出上限 2,048 token，低于免费策略的 4,096，因此实际按 2,048 执行。

Codex 沿用用户 ChatGPT 授权，不扣 XOPC 模型余额。

## 预占和结算

- 聊天按估算输入与请求输出上限预占余额，成功后使用上游实际输入/输出 token 按已锁定费率计算，合并后向上取整到 atomic。上游没有用量时，成功请求按预占额结算；失败请求实际扣费为 0。
- 图片按请求张数预占，成功后按实际返回张数结算；失败释放。
- HTTP STT 按文件音频时长计费，分钟向上取整；HTTP TTS 按请求字符数计费，千字符向上取整。HTTP 失败释放；HTTP TTS 当前在上游成功响应后结算，不等待客户端完整接收音频。
- WebSocket STT 预占 60 分钟费用，当前为 ¥0.006；WebSocket TTS 根据服务 maxCharacters 预占，当前 600 字符预占 1 档费用 ¥0.0001。结束后按收到的音频字节/文本字符计费，实际扣款不超过预占额；无输入时释放。
- 实时对话按四项 token 用量合并计费，不按通话分钟计费；费率全为 0 时预占和扣费都为 0。非零费率时用量未确认会进入待核对状态。
- 结算扣费封顶为预占金额，剩余余额释放。赠送额度先于购买额度消耗；组织调用只使用赠送额度，不使用个人购买资金。

线上通用金额限制：单次预占最高 ¥5、每用户每日累计已扣与预占金额最高 ¥50、平台每日最高 ¥5,000。首次初始化新余额账户默认赠送 ¥10；不是每次调用追加赠送。

## 核查发现

1. **实时语音当前免费但标为 metered。** 四项费率为 0；是否继续免费需要产品定价决定。不能仅改变档位文案就认为已开始收费。
2. **图片/STT/TTS 单价极低。** 当前 ¥0.0001/张、分钟或千字符，需要确认是否为预期商业价格。此次公共别名迁移保留原价格，核查不擅自调价。
3. **实时 STT/TTS 的失败状态不保证免扣费。** 结算按接收到的输入量进行，未使用 failed 状态控制收费。最近 7 天公共 stt 有 1 条 502 记录实际扣了 100 atomic（¥0.0001）；历史旧 STT 有 60 条失败计费记录，合计 ¥0.01，历史旧实时 TTS 有 15 条，合计 ¥0.0015。断线、主动结束和供应商错误应分别确定结算策略。
4. **用量展示金额与实际账本扣款存在差异。** 最近 7 天发现 19 条，均为计算费额超过预占额：actual_credits 已封顶，model_usage_event.charged_credits 仍记录封顶前计算值。其中 auto 2 条，多显示 ¥0.005671；advanced 10 条，多显示 ¥0.023775；旧 deepseek 7 条，多显示 ¥0.035101。不是余额多扣，但用量报表与账单会不一致，应区分计算费额与实际扣款并校准展示。
5. **待结算状态需要整理。** 核查时有 1 条 advanced 预占已到 expires_at，仍保留 ¥0.652950；现有清理同时要求创建超过 24 小时才释放，因此不是到 TTL 就立即归还。另有 2 条旧实时对话 pending 记录，预占均为 0，不冻结资金。
6. **旧协议表残留一个启用 STT 条目。** qwen-audio-3.0-asr-flash-streaming 不在后台公共服务列表中，已被公共模型白名单屏蔽；保留历史账单不代表允许旧 ID 继续调用。

账本完整性核查正常：余额与资金批次可用额一致，复式账务全部平衡，已结算预占记录与 billing_hold 实际扣款一致，三项不一致数量均为 0。

## 后续处理建议

先统一业务规则：明确 realtime / computer 是否免费，以及图片、STT、TTS 的目标人民币价格；明确实时语音部分输出、主动断线和供应商错误的收费边界。实现上优先让用量记录展示实际账本扣款，完善过期预占释放与待结算核对，再按新的已发布服务版本执行未来请求。历史价格快照和已结算资金记录应保留。

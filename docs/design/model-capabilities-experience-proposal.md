# 模型与能力配置：交互及交付提案

日期：2026-10-16。状态：方案已确认，P1 已实现；交付与验收见 [P1 验收记录](./model-capabilities-p1-acceptance-2026-10-16.md)。P2 为后续设计范围。

## 1. 建议结论

将模型设置首页改为「能力总览」。用户先看到自己能做什么、哪些能力尚未启用，再选择模型、连接必要服务，最后按需调整参数。已连接服务放在独立的「连接的服务」页面。保留熟练用户在总览里快速换模型的能力，避免每次都进入完整接入流程。

主方案为能力总览；替代方案是按使用场景引导。后者适合作为首次使用的辅助入口，不建议成为日常设置的必经步骤。

## 2. 当前问题及代码证据

- `capabilities-settings-panel.tsx` 先展示 Cloud 账户、服务卡片，再展示用途列表；初次用户首先面对服务接入，而不是自己缺少的能力。
- 模型、图片和语音的入口层级不一致：图片是模型页的页签，语音是独立设置项。用途行与详细设置之间也缺少明确的参数入口。
- `image-models-settings.tsx` 同时包含服务、Key、模型和默认模型保存；`voice-settings.tsx` 同时承载引导、服务、设备、实时语音、STT/TTS 和高级参数。接入、分配和参数调整混在一起。
- 当前通用 setup 的语音选项主要投影 Qwen 套餐和 Cloud；传统语音服务和自定义图片服务仍由各自注册表管理。只聚合语言 provider 会漏掉这些能力来源。
- 已保存配置、实际启用、凭据可用和真实调用验证不是同一种状态，不能用一个“已配置”概括。

本提案的信息架构依据上述现状及产品判断。设计技能检索未找到与渐进披露直接对应的有效条目，不将无关的检索结果作为该架构的依据。

## 3. 页面职责

| 页面 | 用户问题 | 主要内容 | 保存范围 |
| --- | --- | --- | --- |
| 模型与能力总览 | 我现在能做什么，还缺什么？ | 文本、图片、语音、后台能力；当前来源、状态、配置与设置入口 | 快速切换单个用途 |
| 某项能力详情 | 这项功能怎么启用和调整？ | 当前模型、适用范围、相关参数、主动测试、高级设置 | 当前用途及该能力参数 |
| 连接的服务 | 我有哪些可用来源？ | 账户、套餐、普通 API、本地来源；支持哪些能力、凭据状态、被哪些用途使用 | 连接与凭据 |
| 服务连接页 | 如何接上这个来源？ | 接入方式/地域、账户授权或 Key、支持能力、返回原能力 | 默认只连接，分配需要明确选择 |

建议导航只保留「模型与能力」和次级入口「连接的服务」。原图片、语音地址先保留并映射至相应详情；搜索服务保留其独立工具设置。声音设备仍在语音设置里单独分区，不伪装成模型。

## 4. 能力分组与用语

| 分组 | 用户看到的能力 | 实际配置含义 |
| --- | --- | --- |
| 文本 | 对话与任务 | 默认聊天；快速/复杂任务模型在详情中展开 |
| 图片 | 看图；生成图片 | 图片理解路由；图片生成路由 |
| 语音 | 录音转文字；文字转语音；实时语音对话 | Recorded ASR/STT；TTS；实时引擎与所需路由 |
| 后台 | 自动与后台任务 | 可无人值守的后台模型；不接受仅限交互的套餐 |

STT、ASR、TTS 保留在说明和高级详情中，主标题用用户能理解的名称。除基础对话外，能力按需启用；“未启用”不计作错误，不要求所有项目填满。

实时语音需区别两种能力模式：自然对话可由一个原生模型完成听和说；执行任务的语音助手可能依赖流式识别、Agent、语音输出。界面只展示所选模式的真实依赖，不能把单独配置 STT/TTS 作为所有实时语音的前提。百炼套餐的录音识别也不等于已支持流式听写。

## 5. 核心交互

### 缺少能力

1. 从总览的“录音转文字 → 配置”进入该能力详情，保留返回位置。
2. 先展示已连接且支持录音识别的模型；若已有合适来源，直接选择，不重复输入 Key。
3. 没有合适来源时，进入带能力筛选的服务选择。候选显示接入方式、地域、能力覆盖和使用范围，不编造性能评分或价格。
4. 连接后回到原能力，恢复选择。默认仅勾选用户当前要配置的用途；复用此服务配置其他用途是可选动作，保存前显示具体差异。
5. “保存并使用”完成路由配置；之后显示“已配置，待验证”，提供主动录音测试。连接成功不代表模型实测通过。

### 已配置能力

- 点击当前模型，可从适用的已连接来源快速切换。只有一个选择时不强迫用户打开无意义的选择器。
- 同行提供“设置”，进入用途详情；TTS 可调整音色并试听，图片可调整模型实际支持的默认尺寸，实时语音可选择适合的模式。
- 切换模型时仅重置新模型不支持的参数，并提前展示差异；其他用途及 Agent、会话独立设置保持原语义。
- 简单模型切换沿用单项即时保存；音色、模型及关联参数用同页“保存”形成明确边界，不在每次选择音色时立即保存或自动播放。
- 参数恢复、预览和试听均说明实际行为。试听、生成和识别测试可能消耗额度，需由明确按钮触发，不随页面加载发生。

### 服务管理

- 服务详情显示“正在用于：对话、录音识别……”，并可跳回对应能力。
- 同品牌的套餐、普通 API、不同地域独立呈现和保存，避免混用凭据或计费来源。
- 移除正被使用的服务前展示受影响能力；不悄悄替换成另一收费来源。
- 本地或内置能力可显示“无需连接服务”，不要求伪造一个 provider Key。

## 6. 状态与失败恢复

读模型、是否启用、来源是否可用、是否验证分别建模，再生成展示文案，避免一个全局布尔值。

| 展示状态 | 含义与动作 |
| --- | --- |
| 未启用 | 用户没有开启可选能力；中性展示“配置” |
| 已配置，待验证 | 路由和凭据检查通过，尚无当前配置的有效调用验证；可主动测试 |
| 可用 | 当前配置已验证；显示验证类型与时间，不承诺未来永远成功 |
| 需要处理 | 凭据失效、所选模型下架、能力不匹配或使用范围受限；显示原因和修复入口 |
| 测试失败 | 保留用户选择，展示本次测试失败原因和重试入口，不等同于永远不可用 |

“可用”验证应绑定能力、连接、模型、影响行为的参数和目录版本。换 Key、模型、地域或音色后使对应验证失效；一次 TTS 成功不能证明 ASR 或实时语音正常。保存成功但运行时重载失败，应明确展示部分成功，避免错误乐观提示。

## 7. 交付设计

### P1：统一入口与闭环

- 总览以能力为第一层，服务列表迁至次级页；现有用途切换复用 preview/apply。
- 以参数/路由携带目标能力和返回地址；从配置能力到服务连接再返回，选择与滚动位置不丢失。
- 语音、图片旧页先收敛为能力详情，移出重复的凭据表单，复用同一个连接入口和凭据服务。
- 后端候选投影覆盖语言、图片、STT、TTS、实时语音的现有注册表，确保传统服务及自定义图片来源仍可用。连接身份与协议适配器 ID 显式映射，不简单按名称合并。
- 先展示真实可判断的未启用、已配置待验证、配置错误状态；已有诊断结果可复用，但不虚构“可用”。
- 保持已保存路由、旧 URL、Agent 覆盖、会话选择、原有高级参数兼容。新服务仍无代码支持的能力不出现在可用列表。

### P2：能力详情与验证

- 统一保存反馈和冲突处理；完善音色试听、图片尺寸、语音模式等详情，显示所选模型真实依赖。
- 统一主动测试入口及配置指纹；复用现有测试端点，并验证实际业务入口，避免诊断接口成功但聊天/录音链路失败。
- 对跨存储保存继续明确两阶段及部分成功语义；不宣称增加前端页面就获得了跨配置文件和 SQLite 的原子事务。
- 如加入“看图跟随对话模型”，需定义真实继承解析和失配处理；不能只在界面显示“跟随”，仍保留一条过期固定路由。无法支持时先显示真实独立选择。

### P3：首次使用辅助

- 可选场景引导：文字工作、图片创作、录音与朗读、自动任务。
- 依据所选场景生成必要能力清单，并提供可解释的服务组合建议；用户逐项确认，不强迫补齐所有能力。
- 保留能力总览作为稳定入口；增加更多套餐只补元数据和已验证适配器，不再新增厂商专用页面。

## 8. 技术边界

- 配置真源继续是现有 Agent 默认模型与语音配置、模型目录和凭据仓储；总览是聚合投影，不新增一份平行“模型分配表”。
- 新的聚合视图至少提供：能力 ID、启用状态、当前路由、来源及凭据状态、候选模型、使用范围、设置与测试动作、继承说明、验证结果。
- 首批可以前端复用多端点读取；跨注册表的可用性、套餐范围和凭据判断由后端统一提供。需要新 API 时同时补鉴权、lazy-bundle 映射及真实 HTTP 回归。
- 参数页的写入适配器复用现有 schema、配置协调器及版本校验，不让 UI 直接拼接任意全量配置。
- 原始 Key 只进入既有授权/凭据接口；总览与候选结果不返回 Key。
- 套餐仅可用于允许的交互场景。后台来源独立校验；范围拒绝为终止错误。跨服务回退默认关闭，开启时列出涉及来源和用途。

## 9. 验收清单

- 新用户只连接聊天即可使用；可选能力不被标红、不阻止完成。
- 已有普通 API、百炼套餐、XOPC Cloud、本地能力及自定义图片服务均能找到正确入口，且 Key 不需重复录入。
- 从缺少能力进入接入，再返回原能力完成保存，全程保留上下文。
- 总览切换仅影响目标用途；详情音色/尺寸变更不污染其他模型或服务参数。
- 同一服务提供多项能力时复用连接；不同接入方式/地域不串 Key、不混计费来源。
- 录音识别与流式听写区别明确；原生实时语音不被错误要求配置独立 STT/TTS。
- 后台套餐别名、跨服务回退、并发写入、部分保存失败、凭据撤销和模型下架均有可理解的恢复路径。
- 七类实际业务路径有相应验证，不只测试诊断按钮；测试请求需用户触发。
- 桌面明暗主题、390px 窄屏、键盘、加载 skeleton、错误与成功反馈均验收。

## 10. 建议本轮讨论的决策

优先确认能力分组、总览第一层、服务第二层以及详情页职责。界面上的“智能推荐”“一键配齐”和继承能力可后置，不影响先把入口、状态、返回路径和单项配置做清楚。

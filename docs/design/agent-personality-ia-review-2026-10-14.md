# Agent 详情页信息架构调研与优化建议

日期：2026-10-14。范围：用户截图、Web 实现、配置与提示词消费路径、Specialist 匹配逻辑。调研未进行用户访谈；后续实现情况如下。

## 实现情况

已实现“概览 / 个性 / 能力 / 工作设置”四项主导航。根据用户后续反馈，桌面端主导航改回左侧纵向排列，小屏使用横向排列；能力下保留“擅长的任务 / 模型 / 技能与工具”。工作设置内部使用横向“工作目录 / 工作规范 / 工具约定 / 运行策略”，附加规则归入工作规范；各子页独立保留滚动位置和草稿。SOUL.md 留在个性，AGENTS.md 与 TOOLS.md 移到工作设置。低频身份字段与执行配置局部折叠；专长常见标识支持中文选择并保留自定义值。概览摘要支持跳转，草稿与滚动位置跨 Tab 保留，文档模板可撤销，统一保存报告部分成功。

验证包含 Agent 相关回归测试、Web 构建、改动文件 ESLint，以及使用模拟 API 的真实组件桌面和 390px 小屏浏览器预览。预览无浏览器错误，小屏弹窗无横向溢出；尚未在真实 Gateway 上进行写入验证。

## 结论

“个性”页承担了身份、行为、专长、文件环境四种用户任务。优先重新划分归属，再做渐进展示。保留现有存储和能力，第一阶段不合并提示词来源、不自动改写角色文件。

建议详情页导航为：**概览 / 资料与个性 / 专长与能力 / 模型 / 工作设置**。删除放在概览底部的独立危险操作区。设为默认保留在概览，不再作为危险操作重复出现。

## 当前架构与真实用途

| 现有位置 | 内容 | 实际用途 | 问题 |
| --- | --- | --- | --- |
| 概览 | 生效模型、技能、工具、工作区、继承信息、设为默认 | 了解配置、开始对话 | 主要总结技术配置，缺少角色和专长摘要 |
| 个性：身份 | 头像、名称、表情、介绍、类型、风格、语言 | 识别 Agent；名称、介绍、类型、风格、语言也进入模型提示词 | 展示资料与行为偏好并列，类型容易被误解为能力分类 |
| 个性：Specialist 能力档案 | 领域、任务类型、输入、交付、专长、边界、示例 | 委派任务匹配；工具、技能、账号可用性另行检查 | 占据个性编辑器之前的位置；用户需手写英文标识 |
| 个性：角色配置 | SOUL.md、TOOLS.md、AGENTS.md；模板、可视化、源码、预览 | 提示词上下文中的个性、工具约定、长期工作规范 | 以文件名组织操作，用户需要学习技术概念 |
| 个性：工作区 | 文件读写目录 | 执行环境 | 与个性没有直接关系 |
| 个性：附加指令 | profile.instructions | 进入 customInstructions | 与工作规范、个性边界存在内容重叠 |
| 模型 | 对话、固定意图、图像与执行策略 | 模型路由 | 保持独立合理 |
| 技能与工具 | 技能配置、工具范围与权限 | 实际执行能力 | 与声明专长分散，难以比较“擅长”和“可执行” |
| 运行限制 | 运行策略、缓存等 | 执行策略 | 可接收工作区和工作规范 |
| 危险区 | 设为默认、删除 | 管理 Agent | 默认操作与概览重复 |

个性页已经有 8 项身份设置、6 组专长列表、最多 4 组请求/交付示例、3 份角色文档、工作区和附加指令。复杂感来自任务与编辑层级混杂；缩小字号和间距只能缓解长度。

### 生效边界

- 身份字段并非都只用于展示。`buildAgentIdentitySection` 注入名称、介绍、类型、风格与语言，因此不能直接移除这些字段或改变含义。
- SOUL.md 被提示词明确要求用于个性与语气；TOOLS.md 是说明而非授权，不能与工具权限合并成同一种设置。
- `assessSpecialist` 对领域、任务类型、输入和输出使用标识匹配，候选排序优先考虑资格状态，再看任务类型和领域匹配。专长文字、适用边界和示例不能被展示为确定的执行保障。
- schema 已有 `SPECIALIST_VOCABULARY` 常见标识，但允许自定义字符串，可直接支持中文标签选择和保留自定义值。
- 保存依次涉及角色文档、头像、Agent 配置，整体不是单一原子写入。角色编辑器在文档保存后更新基线；后续配置失败可能造成部分保存。

## 推荐架构

| 导航 | 默认展示 | 次级入口 |
| --- | --- | --- |
| 概览 | 角色简介、专长摘要、关键生效配置、开始对话、设为默认 | 继承详情；底部删除区 |
| 资料与个性 | 头像与名称、简短介绍、回复语言、表达风格、个性与边界编辑器 | 更多身份设置：角色定位、签名表情；编辑器源码/预览 |
| 专长与能力 | 二级导航：擅长的任务 / 技能与工具 | 任务匹配细节：输入、输出、适用边界、示例 |
| 模型 | 当前对话模型、继承或自定义 | 固定意图、图像、执行策略沿用现有渐进展示 |
| 工作设置 | 工作目录、工作规范 | 工具使用约定、附加规则、运行限制、缓存 |

“专长与能力”的两种内容需要明确区分：**擅长的任务是声明；技能与工具是执行条件**。使用二级切换避免迁移后形成另一张超长表单。

### 资料与个性的主路径

1. 顶部紧凑身份区：头像与名称并排，介绍用两行输入区，语言与风格一行。
2. 下方直接进入“个性与边界”，编辑现有 SOUL.md 正文；默认可视化编辑，不要求理解文件名。
3. “更多身份设置”默认收起，包含现有 creature（改标为“角色定位”）和签名表情。已设置时显示摘要，避免隐藏已生效的信息。
4. 文件名作为次级说明；主标签使用“个性与边界”“工作规范”“工具使用约定”。每份文档只有一个主编辑入口。
5. 模板移入“使用模板”操作，点击后展示会替换的内容范围并提供撤销，避免现有正文被意外替换。

风格建议提供“简洁直接”“耐心解释”等快捷填写，同时允许自由输入。语言使用项目 Select，提供常用语言并保留自定义旧值；不要自动把现有 `en` 改写为其他含义。

### 专长配置

- 领域和任务类型优先显示中文标签，如“软件开发”“修复 Bug”“代码审查”；内部仍保存 `software`、`bug_fix`、`code_review`。
- 使用项目选择组件进行多选；高级入口允许自定义标识，已有未知标识完整保留。
- 输入和交付类型、边界、示例默认收起，但已配置时显示数量或摘要。
- 不新增“是否为 Specialist”开关：当前档案可选，缺失档案不等于不能接任务。
- 不要求用户为了保存个性先补全能力档案，也不通过介绍自动生成并保存任务匹配标识。

### 工作设置与保存反馈

- AGENTS.md 归入“工作规范”，TOOLS.md 归入“工具使用约定”。附加指令保留为高级“附加规则”，不自动拼接进文档或删除。
- 第一阶段沿用全局“保存更改”，清楚显示“未修改 / 有未保存更改 / 保存中 / 保存失败”。未发生修改时不用“所有更改已保存”暗示自动保存。
- 文档局部状态只报告文档状态；若总体写入失败，应说明哪些部分已保存、哪些仍待保存。
- 保留跨分区草稿，收起内容不影响保存；未保存状态显示在相应导航项。
- 保留固定响应式弹窗、固定头尾与内部滚动。优先减少内容任务数量，暂不引入第二套全屏编辑流程。

## 落地顺序与验收

**第一阶段：结构重排。** 移出 Specialist 和工作区；分拆三个文档的入口；主标签改为用户任务；调整保存文案。保持 API 和存储结构。降低风险的同时解决主要复杂来源。

**第二阶段：输入减负。** 基于现有 vocabulary 增加中文多选；隐藏低频身份字段和匹配细节；模板增加覆盖说明与撤销。保留自由文本与自定义标识。

**第三阶段：根据测试决定。** 再评估是否合并风格与 SOUL.md、附加指令与 AGENTS.md。必须先设计数据迁移和明确提示词冲突规则；仅靠视觉合并会制造隐式重复写入。

建议用以下任务进行可用性验收，指标是目标，不是已有测试结果：

- 用户无需滚过能力档案即可找到并修改说话方式。
- 更换头像、名称、语言无需理解 Markdown 文件或 Specialist 标识。
- 为编程专家配置 Bug 修复专长无需手写英文；保存后原标识不变。
- 修改工作目录可以从“工作设置”直接找到；工具约定与工具权限不会混淆。
- 跨分区、折叠、切换编辑模式不丢草稿；文档/头像/配置部分失败时状态准确。
- 旧自定义语言、风格、标识、Markdown front matter 原样保留；移动端无横向溢出。

## 依据与限制

### 补充：外层 Tab 方案比较

用户提出新增外层 Tab 后，结合当前固定弹窗（桌面最大宽度 62rem、高度 48rem）、左栏宽度 13rem，推荐将弹窗主导航改为四个顶部 Tab：**概览 / 个性 / 能力 / 工作设置**。这是对前述五项左导航方案的进一步调整。顶部 Tab 替代原左栏，而不是在六项原左栏之外再叠加一层。

| 方案 | 优点 | 代价 | 判断 |
| --- | --- | --- | --- |
| 保留左栏并重排五项 | 所有分区直达，实施改动小 | 继续占据内容宽度，仍偏配置中心 | 适合最小范围修复 |
| 个性页内部加 Tab | 缩短单页，改动局部 | 专长和工作区仍错误归属个性 | 不作为最终架构 |
| 顶部 Tab + 保留完整原左栏 | 可以增加粗粒度分组 | 三层导航易出现；空间更少，分组重复 | 不建议 |
| 四个顶部 Tab 替代左栏 | 主任务更清晰，内容区更宽；常用与执行配置分开 | 模型等内容需要第二次切换 | 推荐，需验证模型可发现性 |

推荐内容结构：

```text
Agent 头像、名称、ID                       关闭
概览 | 个性 | 能力 | 工作设置

概览：介绍、专长和生效配置摘要、开始对话、设为默认、底部删除
个性：基本资料、语言与风格、SOUL.md 个性与边界；低频身份字段收起
能力：擅长的任务 | 模型 | 技能与工具
工作设置：工作目录、工作规范 AGENTS.md、工具约定 TOOLS.md、附加规则、运行策略

统一状态                                 关闭 / 保存更改
```

只在“能力”下使用一组二级 Tab；“个性”不再增加文件 Tab。工作设置按任务分区展示、低频内容局部折叠，必要时增加分区定位，但不继续堆叠 Tab。折叠应使用局部组件状态，不直接沿用当前会切换全局 advanced 模式的 `SettingsAdvancedSection`。

概览的模型、技能、工作区摘要支持直达对应位置，缓解二级导航的发现成本。顶部 Tab 切换保留草稿、滚动位置与统一保存状态，未保存标记归属到对应 Tab。小屏保持相同四项入口，用文字而非图标区分。这里的可发现性和效率是设计推断，尚未进行原型测试。

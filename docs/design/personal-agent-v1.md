# xopc 个人 Agent V1：产品与交互设计

> 状态：产品方案，待评审 · 2026-10-07  
> 范围：Gateway Web 与桌面应用的个人入口；以当前本地 Gateway 能力为基础。本文不承诺尚未提供的独立云电脑或移动端体验。

## 1. 产品定义

个人 Agent 是用户在 xopc 中持续使用的一个 Personal AI。**首要体验目标是让回应准确、合适，并符合这个用户当下想要的交流方式**：有人需要先被听见，有人希望一起理清问题，也有人在压力下只想听清楚的结论。它通过持续学习、确认和修正用户的偏好，形成稳定的表达方式；同时能承接任务，把经过核对的进展与结果带回对话。情绪价值来自被准确理解、尊重节奏和可靠行动，不以“可爱”或拟人化程度衡量。

它有**一个稳定身份、一个固定的用户可见主会话、一份可编辑的合作档案**。后台 Task、TaskRun、专业 Agent 的会话各自独立，用户可进入详情检查。固定主会话表示同一个 `conversationId` 和持续的对话时间线；个人会话不参与普通聊天的闲置自动重置，也不响应普通“新聊天”入口。模型上下文可以压缩和选择，不表示每次调用都携带全部历史。若用户明确要求清空个人关系，使用有删除范围说明的重建流程。

### 用户承诺

1. **按我的方式回应我**：称呼、温度、幽默、详略、安慰方式和主动频率适合这个用户，也能随当下情境变化。
2. **越来越合拍**：用户明确的偏好立即生效；系统从互动中提出的推断可见、可纠正、可删除。
3. **随时能聊**：派发任务后，主 Agent 不等待执行结果才能继续响应。
4. **事情会回来**：工作状态有持久记录，结果回到主会话；用户可追查执行过程和证据。
5. **边界清楚**：连接信息源、读取数据、在设备上执行和对外行动分别授权。
6. **主会话够快**：主会话固定使用支持 `thinking=off` 的模型；需要深度推理时立即委托执行 Agent。

### V1 目标与边界

| V1 包含 | V1 不承诺 |
|---|---|
| 一个个人 Agent、固定主会话、文字和现有实时语音入口；主会话 `thinking=off` | 自带始终在线的云电脑；本机关闭后仍可执行本地任务 |
| Conductor 式任务分派、Task 回传、活动与产出入口 | 任意工具都能由主 Agent 直接操作 |
| 渐进式风格校准、偏好与记忆管理 | 通过一次问卷推断完整人格 |
| 已支持的连接器、自动化及本机能力的明确授权 | 接入一个应用即默认监控全部内容或取得写权限 |
| 用户设定的持续责任与定时检查 | 未经设定、无限范围的后台自主探索 |

V1 先面向一个 xopc 安装中的个人使用者。未来若支持多个登录用户，个人 Agent、记忆、连接与执行权限必须按用户隔离。

## 2. 调研依据与设计取舍

OpenAI 官方资料显示：dots 有持续责任、后台任务、跨接触方式的身份连续性、活动查看和独立权限控制；其创建流程先介绍能力，再可选连接应用与电脑，创建后在对话中介绍自己并允许修改名称和外观。参考：[Meet dots](https://learn.chatgpt.com/docs/dots)、[Getting started](https://learn.chatgpt.com/docs/dots/getting-started)、[Tasks and memory](https://learn.chatgpt.com/docs/dots/tasks-and-memory)、[Controls](https://learn.chatgpt.com/docs/dots/controls)。

用户提供的截图进一步展示了：固定头像与主会话、通话记录、主动消息、个人资料面板中的电脑/活动/产出，以及创建后由 Agent 发起的介绍、命名、外观定制和一条有来源的工作建议。这些是界面参考，不表示 xopc 已有对应能力。

**xopc 的取舍：**继承“一个人”的连续感和任务可追溯性；首次创建时增加轻量的合作方式校准；主动消息更短；外观不影响能力或权限；本地优先，不照搬云电脑文案。

## 3. 信息架构

```text
侧栏固定入口：我的助手 [头像、名称、待我决定数量]
  ├─ 首次进入 → 初始化向导 → 固定主会话
  └─ 后续进入 → 固定主会话

主会话
  ├─ 时间线：对话、通话摘要、重要任务回报、待决定事项
  ├─ 输入：文字、附件、语音通话
  └─ 个人面板：正在做 / 待我决定 / 已安排 / 最近完成 / 产出

个人设置
  ├─ 身份：名称、头像、颜色、声音
  ├─ 相处方式：语言、详略、语气、主动汇报
  ├─ 记忆：明确偏好、推断、来源、纠正与删除
  ├─ 连接与权限：数据源、工作位置、行动规则
  └─ 管理：暂停、恢复、清除或重建
```

入口放在导航中稳定可见，并与“新任务”分开。普通聊天、项目任务和专业 Agent 仍保持原有入口。个人面板是主会话的二级界面，不把完整 Task 管理界面塞入聊天。

## 4. 首次使用：五个阶段

整个流程支持返回、保存进度、稍后完成。连接器和外观可跳过。已有全局模型/工作空间 onboarding 先完成必要配置，再出现个人 Agent 初始化；不叠加两个全屏向导。

| 阶段 | 屏幕目标与关键文案 | 用户选择 | 结果 |
|---|---|---|---|
| A. 认识它 | “让回应更适合你，也能帮你把事推进。”三个例子：一起理清、交给专业 Agent 做、需要决定时找你 | 设置回应方式 / 了解详情 | 形成准确预期 |
| B. 工作位置 | 展示已配置的本机 Gateway、可用设备及在线状态；说明可访问范围 | 启用具体设备/工作目录，或暂不启用 | 独立的执行授权 |
| C. 了解哪些信息 | 对已可用连接器逐个显示读取范围、可执行动作、连接状态 | 逐项连接或跳过 | 授权记录；不自动创建监控 |
| D. 创建 | 进度为“创建身份 → 建立主会话 → 准备任务入口”，失败可重试 | 等待或重试 | 恰好一个个人 Agent 与主会话 |
| E. 初次相处 | 进入永久主会话，由 Agent 发出介绍和两项轻量校准 | 回复、选快捷项，或直接交代任务 | 合作档案初始版本 |

### 首次对话脚本

消息应像一次真实谈话，不应连续发出七八个气泡。先让用户感到“它在这里”，再说明它能做什么；建议以一段介绍和一个轻问题开始：

> **助手：**你好。想讨论一件事、理清思路，或让我帮你推进工作，都可以直接说。需要深入处理的部分，我会交给合适的 Agent，并把进展和结果带回来。
>
> **助手：**我可以按你习惯的方式回应。你更希望我先听你说、一起理清，还是直接给建议？
> **快捷项：**「先听我说」·「帮我理清」·「直接给办法」·「以后再选」

用户选完或跳过后，可邀请命名和打开外观定制；这些都不能阻挡正常聊天。主动汇报频率可在回应偏好里单独设置。首次任务完成后再问一次“这样的汇报方式合适吗？”，用真实工作校准回答详略和语气。若用户已开始输入任务，立即停止引导并处理任务。

命名和外观放在回应方式之后，均可跳过并随时修改。角色设定优先问**怎样回应才合适**，不要求用户编写长篇人格提示词；提供“直接清楚 / 自然有分寸 / 温和耐心”三个起点，再分别设置支持方式、详略和主动频率。用户可以直接说“先听我说”“叫我 Joyce”“以后先说结论”来细调。幽默是独立的可选偏好，语音音色与说话快慢也独立设置，不从头像推断。

首次对齐最重要的问题不是“你想要一个什么性格的 AI”，而是“**你希望我怎样回应你？**”提供三个可试读的短回复，让用户听到/看到差异，再选择或直接描述。接着只问一项高价值偏好：“你累或受挫时，希望我先陪你缓一下、一起理清，还是直接给办法？”可跳过；不在创建前索取私密经历。用户选定后，马上用其偏好改写下一句欢迎语，让校准产生可感知的效果。

如已连接来源且只读检索得到可靠依据，可出现**一条**具体建议，附来源和“为什么提议”；用户未授权、来源不足或已有活跃任务时不出现。连接应用不等于允许长期监控。

### 初始化异常

- 没有可用模型：提供模型配置入口，保持向导进度；不创建无法工作的身份。
- 连接授权失败：保留已完成步骤，允许跳过；返回时可续接。
- 本机离线：解释哪些工作仍可用，哪些会等待设备上线。
- 创建请求重试：以稳定的初始化键去重，不产生第二个主会话。
- 用户中途关闭：保留阶段状态；不重复播放已确认的介绍。

## 5. 主会话的交互

### 桌面布局

```text
┌ 侧栏 ─────────┬ 我的助手 [头像 名称]                [活动] [•••] ┐
│ 我的助手      │                                              │
│ 新任务        │   日期 · 对话与精选更新                       │
│ 普通聊天      │   用户消息 → 助手响应                         │
│ 项目 / 任务   │   任务状态卡 → 点开 Task/证据                 │
│              │   语音通话摘要                                │
│              │                                              │
│              │   [＋] 给助手发消息…            [通话] [发送] │
└──────────────┴──────────────────────────────────────────────┘
```

主内容宽度以阅读舒适为准，长消息留白，不让头像和装饰抢正文注意力。小屏时活动面板成为全屏抽屉；输入区固定在底部并适配安全区。时间线可按日期分段、分页/虚拟化加载历史，打开页面默认定位到最后未读的有意义更新。

### 一次请求的响应策略

| 请求类型 | 主 Agent 行为 | 用户可见反馈 |
|---|---|---|
| 简单聊天或明确的小问题 | 直接答复 | 普通对话；不创建 Task |
| 需要深度研究/编码/文件工作 | 读取必要上下文，建立任务契约并派发 | 立即确认目标、范围与下一个汇报条件；出现可打开的任务状态卡 |
| 需要用户决定 | 摘要选项与建议，暂停依赖该决定的步骤 | 一张待决定卡；决定后原任务继续 |
| 定时/持续责任 | 明确来源、检查条件、期限、通知条件后创建 | “我会在……检查；出现……才提醒你”，并可从面板修改 |
| 用户改变方向 | 更新既有任务或责任；必要时取消旧运行 | 确认新方向和受影响的工作 |

复杂任务的首次响应目标是迅速承接，不把“创建任务”伪装成“已完成”。主会话的 `thinking=off` 与少量工具共同缩短响应链；它只做轻量判断、必要的上下文读取、派发和表达。需要多步推理、事实核查或深度规划时，由执行 Agent 使用任务适合的模型与推理强度。任务契约至少包含目标、交付物、约束、验收标准、授权范围、来源主会话、去重键。后台 Agent 输出是待核对的数据，不是新的用户授权。

### 消息形态与打扰规则

主会话只推送四类主动消息：**需要决定、重要风险、可验证的重要里程碑、最终结果**。其余进度留在活动面板。重复事件合并，同一问题不反复提醒；安静时段和用户设置决定通知渠道与时间。聊天消息与系统通知分别控制。

推荐格式：**结论一句 → 为什么需要关注一句 → 现在可做的事**。证据、原文、TaskRun 收据、文件和无法验证之处放在展开区。明确区分“执行结束”“验收通过”“尚未核实”。例如额度提醒应说“可能影响搜索，我尚未看到调用失败”，不推断已造成故障。

活动面板提供“正在做 / 待我决定 / 已安排 / 最近完成 / 产出”，每项展示负责人、阶段、最近更新时间和下一步。点击进入 Task 详情；返回后保持主会话滚动位置。

## 6. 实时语音

语音入口是同一个主会话的另一种输入方式。通话开始时显示姓名、连接状态和实时字幕；Agent 可以口头承接任务，并将耗时工作派发到 Task。通话结束留下可读摘要：通话时长、关键决定、创建/修改的任务。用户可修改错误转写；完整录音是否保存应单独设置。

语音答复应短于文字答复，先说“我明白了”和要做的下一步；长证据以文字卡片呈现。允许用户打断播报，保留已确认的任务派发；断线后能从主会话恢复状态。通话结束不自动取消后台任务。

当前实现中通话占用会话时，普通文字输入可能返回 `SESSION_BUSY`。V1 必须至少在界面明确显示“通话中可通过通话窗口发送文字”，并保证文字与语音进入同一输入队列；若后端尚未统一队列，先在通话窗口支持文字，再逐步开放主输入框并发。不得让用户输入后才收到含糊的失败提示。

## 7. 合作档案、记忆和权限

### 合作档案

将偏好分成三类并显示来源：

| 类别 | 示例 | 生效规则 |
|---|---|---|
| 用户明确设定 | “汇报先给结论”“别主动通知普通进度” | 立即生效；可修改 |
| 从对话推断 | “常希望看到测试证据” | 低置信度不强行应用；显示证据，可纠正 |
| 当前情境 | “今天只要简短回复” | 只作用于当前请求/时期，不写成永久特质 |

敏感个人信息不得因一次提及就固定为长期人格；对推断性记忆设置时间、证据和撤回。主会话使用近期对话、相关记忆、活跃责任摘要和任务状态来组装上下文；完整历史保留在 SQLite 并可检索。会话压缩不删除用户可见历史，也不把任务结果无条件写成长期偏好。

### 权限模型

1. **接触方式**：用户从哪里给助手发消息、接收提醒。
2. **信息源**：每个连接器能读取哪些对象；读取不自动允许长期监控。
3. **工作位置**：本机设备、目录、浏览器、沙箱或未来的云环境分别授予。
4. **行动规则**：读取、草拟、修改、发送、购买、删除等按动作分级。

默认可以在授权范围内读取与草拟；对外发送、购买、不可逆更改、扩大访问范围需要明确授权或对应的持久规则。任务派发不得扩大主 Agent 的权限。面板应显示“为什么它能做这件事”与撤销入口。撤销连接后要说明已形成的记忆仍需单独管理。

“暂停助手”“停止一个任务”“取消计划”“清除记忆并重建”是四个不同动作。避免使用含糊的“重启”；清除前明确列出会删除的对话、记忆、责任和计划。

## 8. 人格、情绪价值与流畅交互

### 角色设定：有性格的个人伙伴

默认表达是**自然、可靠、有分寸**：它记得用户怎样称呼它、喜欢先听还是先得到办法；遇到阻塞会坦诚解释并给出下一步。界面提供“直接清楚 / 自然有分寸 / 温和耐心”的语气起点，幽默程度单独设置，默认不加玩笑。事实准确、守时、尊重边界始终优先于角色感。

**默认性格只是起点，用户偏好决定最终口吻。**同一个人也会随场景改变需求：闲聊可以活泼，赶截止时间时要干脆，受挫时可能需要先被理解。Agent 不应在每轮机械套用一个“温柔模板”，而应综合稳定偏好、本轮明确要求、情境和用户刚刚给的反馈来决定回应方式。

### 情绪偏好档案

合作档案中增加可编辑的“相处方式”，记录下面六个维度，均可用自然语言修改；它们是表达偏好，不是对用户人格的诊断。

| 维度 | 用户可选的表达 | 作用于回答 |
|---|---|---|
| 被如何称呼 | 名字、昵称、称谓，以及哪些称呼不喜欢 | 开场和重要回报的称呼 |
| 情感温度 | 克制、亲近、温柔；哪些话会显得敷衍 | 共情句的多少与亲密程度 |
| 轻松程度 | 不开玩笑、合适时轻松一点、更活泼 | 玩笑的频率；不改变事实与任务判断 |
| 受挫时的支持方式 | 先听我说、帮我理清、直接给办法 | 先回应感受还是先行动 |
| 信息密度 | 先结论、先过程、详细解释；语音和文字可不同 | 内容顺序、长度与证据展开 |
| 主动联系 | 只在必要时、重要进展、愿意闲聊 | 通知频率和主动提议的时机 |

每项标明“用户明确设定 / 系统建议待确认 / 临时偏好”，展示最近依据、适用范围和一键撤销。系统可以从多次一致的反馈中提出一句轻问句，例如“你好像更喜欢我先说结论，要改成默认吗？”；不能把一次沉默、一次难过或一条敏感对话直接固化为长期特质。用户说“今天别逗我”只影响当前情境；“以后都这样”才进入长期设置。偏好冲突时，本轮明确要求优先于长期档案。

### 同一件事，因人而异地回答

假设任务延期且需要用户选择。**事实卡完全相同**：延期原因、当前状态、两个选项和截止时间不因口吻变化而省略。

| 已知偏好 | 主会话的表达示例 |
|---|---|
| 简短、先结论、不安慰 | “这项任务会晚约两小时。原因是接口测试未通过。现在可选：继续修复，或先交付已验证部分；我建议先交付已验证部分。你选哪个？” |
| 温柔、先接住情绪、再给办法 | “这个节点卡住了，可能会打乱你的安排。我先把情况说清楚：接口测试未通过，预计晚约两小时。可以继续修复，也可以先交付已验证部分；我建议后者。你想怎么定？” |
| 偏好轻松、仍要高效 | “接口测试挡住了交付，预计晚约两小时。现在有两条路：继续修复，或先交付已验证部分。我倾向后者；你定，我接着推进。” |

这不是三套固定模板。语气与措辞应随着用户的原话、事情轻重和双方已经建立的默契自然变化；严重失误、损失或敏感话题不用玩笑。用户如果要求“别安慰我，直接说怎么做”，下一句就切换，不做多余的情绪分析。

拟人化要有清晰边界：它可以说“我来盯这件事”“这次顺利完成了”，但只有任务已持久创建、状态确实成立时才能这样说；不编造自己的生活经历、真实感情或与用户的排他关系，也不把用户的一次低落永久标记为人格特质。用户需要安慰时先回应当下感受，再按其意愿继续办事；不强行“治愈”或延长情绪话题。

### 三个可感知的产品瞬间

| 情境 | Agent 表达 | UI 反馈 |
|---|---|---|
| 用户刚起好名字 | “好，那以后我就叫阿沐。今天先从哪件事开始？” | 名称、头像预览立即更新；短暂的点头/眨眼动效 |
| 耗时任务已派发 | “收到。我已经把资料核对交给研究 Agent；有结论或需要你决定时，我来找你。” | 任务卡立即出现，显示负责人、当前状态、下一次汇报条件 |
| 工作完成但证据不足 | “整理完成了，但其中两条数据我还没核实。我把出处和待核对项放在这里，你要我继续查吗？” | 产出卡清楚区分已完成与待核实，展开可见来源 |

用户打断、改口或说“别这样说话”时，先停下当前播报或引导，简短确认变化，再执行；不重复解释产品机制。主会话输入后立即出现发送状态；超过短暂等待时显示真实的“正在创建任务 / 等待回复 / 连接中”等状态。头像状态只反映真实事件：倾听、回复、交办、任务进行、等待决定、完成、离线。无事件时安静停留，不持续假装“思考”。

### 打磨规则

- **先回应人，再处理事**：可以有一小句贴合语境的接话，随后马上给出行动或答案。紧急任务直接说结果和下一步。
- **主动要有价值**：不发送“想你了”“我一直在”等空洞消息；每次主动出现都对应用户授权的责任、重要变化或需要决定的事项。
- **表达可纠正**：用户说“太严肃”“别开玩笑”“以后少提醒”时，展示具体将调整的设置，并从下一条消息生效；允许撤回。
- **节奏顺畅**：文字采用流式显示，长任务先承接后执行；卡片与消息共享一条清晰时间线。语音答复短、可打断，详情留在文字里。
- **个性与能力分离**：更换角色形象、颜色或声音不会改变权限、模型、任务策略或记忆内容。
- **一次反馈，立即见效**：对回答的“太冷 / 太肉麻 / 刚刚好”可轻触反馈，也可直接说；系统先调整本轮或下一轮，并让用户决定是否保存为长期偏好。

## 9. 视觉与动效

参考苹果界面的秩序和 dots 的个人感，但沿用 xopc 现有的 **Calm Intelligence** 设计系统：系统字体、浅灰/白与深灰层级、蓝色只用于主要行动和链接、少阴影、清楚的焦点状态。个人头像可有少量可选外观；**颜色、形象、声音**只是表现层，不隐式改变人格或权限。避免复制 dots 的商标化圆环与具体角色素材。

- 桌面：主会话安静、宽留白；活动抽屉宽度固定且内容区滚动。复杂定制弹窗使用稳定的响应式外框、固定标题/底部操作区。
- 小屏：单列主会话；活动、资料、定制分别全屏或底部面板，不遮挡输入。
- 动效：只用于状态转换（任务创建、面板开合、语音连接）；约 150–250 ms，尊重减少动态效果设置。
- 可访问性：文本对比度至少 4.5:1；可交互目标至少 44×44 px；图标按钮有标签；键盘可达、焦点可见；任务状态不可只靠颜色区分；新消息使用克制的屏幕阅读器播报。
- 加载：使用局部骨架和明确步骤；创建和授权失败在发生位置提示，保留已完成选择。
- 表达：像熟悉用户的聪明同事，说具体事实和下一步；不假装有感受、经历或未实际完成的工作。用户说“太啰嗦”“别每一步都通知我”时，把反馈转成可见的合作偏好并立即应用。

设计系统单一来源仍为 `web/src/styles/globals.css`；不因本功能新建第二套 token。设计搜索工具给出的紫色/青色和外部字体建议与 xopc 规范冲突，因此不采用。

## 10. 实现映射

| 需要的能力 | 已有基础 | V1 新增或调整 |
|---|---|---|
| 主 Agent | `src/agent/starter-agents.ts` 中 Conductor 预设；Agent 配置与资料 API | 从预设创建一个用户专属 Agent；限制主工具集；身份与首会话幂等创建、失败可恢复 |
| 固定主会话 | SQLite `conversationId`、SessionStore、压缩与检索 | 用户到个人 Agent/会话的稳定映射；入口永远解析同一个 UUID；跳过普通聊天的闲置自动重置和 `/new` |
| 派发和回传 | Task、TaskRun、origin link、协作板、主更新判定与投递 | 面向个人 Agent 的任务契约、进度合并、通知偏好、证据卡 |
| 语音 | 实时语音、VoiceAgentBroker、通话面板 | 个人入口绑定、通话摘要、文字/语音输入协调与清晰的忙碌状态 |
| 记忆 | `userContext`、用户模型、知识记忆、会话压缩 | 合作档案 UI、偏好来源/置信度/有效期、纠错反馈 |
| 前端 | React 路由、Chat、Task 详情、OnboardingDialog | 个人入口、初始化向导、个人主会话外壳、活动/设置面板 |

个人入口复用 Agent Catalog 与主会话记录：Agent 的稳定 ID 定位身份，带个人标记的 Session 定位固定会话，回应偏好保存在 Agent profile。创建接口幂等，恢复时先查询现有 Agent 和会话；不再增加并行的个人身份表。安全边界仍由服务端策略和权限系统控制，不只写进 `SOUL.md`。任何新认证 API 都要同步注册 Gateway 的 lazy-bundle matcher 并做真实鉴权路径验证。

**主会话模型约束：**初始化时只允许选择 `getModelThinking(model).options` 包含 `off` 的模型，并把该会话的 `thinkingLevel` 持久设为 `off`。所有主会话入口，包括文字、语音、后台任务回传、Gateway 重启后的恢复，都应由服务端统一解析为 `off`；前端隐藏主会话的推理强度选择。更换模型或 fallback 前再次检查该能力；不支持关闭 thinking 时，提示用户选择兼容模型，不悄悄切到启用推理的模型。此约束只适用于个人主会话，专业 Agent 和 TaskRun 独立配置。实现与验证应覆盖现有的会话模型配置、`src/providers/model-thinking.ts` 的能力判断，以及会话创建/追加命令路径；单靠提示词要求“不思考”无法保证这个行为。

运行时流程：用户消息 → 固定主会话输入队列 → 快速判断直接回复或创建 Task → TaskRun 在独立会话执行 → 协作板/收据 → 通知判定 → 主 Agent 基于档案和当前上下文表达 → 同一主会话展示。投递要有幂等键、顺序与重试；主 Agent 忙碌或通话时排队，不让系统更新抢在用户消息前面。

## 11. V1 验收与发布顺序

### 验收场景

1. 新用户跳过所有连接器，仍能创建并和个人 Agent 聊天；下次点击回到同一会话。
2. 交给它一项长任务后，主 Agent 立即确认；用户可继续问另一件事；任务结果回到主会话并可进入证据详情。
3. 用户选择“只说结果和决定”，普通进度不产生新消息；失败、阻塞和完成仍按规则到达。
4. 用户在任务运行中改变方向，任务详情与主会话状态一致，不重复创建工作。
5. 语音交代任务、结束通话后，任务继续；文字会话能看见通话摘要和结果。
6. 用户修改“先给结论”的偏好，下一次汇报生效；删除一条错误推断后不再次从同一证据写回。
7. 断网、连接失效、设备离线、模型不可用和任务失败均有可理解状态与恢复动作。
8. 重试创建、刷新页面和 Gateway 重启均不会产生第二个个人 Agent 或第二条主会话。
9. 主会话每一次文字、语音及任务回传运行均为 `thinking=off`；模型切换和 fallback 不能突破该约束。执行 Agent 可独立选择所需推理强度。
10. 命名、形象与风格选择可跳过、可即时预览并可随时修改；用户纠正说话方式后，下一次回复遵循新偏好，任务事实和授权不变。
11. 角色在任务派发、等待决定、完成和离线时只表现真实状态；减少动态效果模式、键盘与屏幕阅读器均能完成同样操作。

### 衡量指标（发布前设目标值，内部试用校准）

- 首次进入至第一条有效用户消息的完成率与用时。
- 复杂请求到用户收到承接确认、到 Task 建立的 P50/P95 延迟。
- 主会话首字延迟、完整承接响应延迟，以及 `thinking=off` 运行占比（目标 100%）。
- Task 结果成功回传率、重复消息率、无来源结论率。
- 主动通知的“有用/打扰”反馈、需要用户重述背景的比例。
- 偏好修改后下一次回复的符合率、语音任务跨通话延续成功率。
- 按用户已选择的相处方式评估“感觉被理解 / 口吻合适 / 太冷 / 太腻”；统计用户纠正口吻的次数和纠正后再次不合适的比例。

### 发布顺序

1. **内部 V1a**：固定入口、身份创建、轻量首聊、Task 派发与结果回传。
2. **封闭 V1b**：活动面板、偏好与记忆管理、主动消息筛选、语音会话绑定。
3. **公开 V1**：持续责任、定时检查、权限管理、失败恢复与完整验收。

## 12. 评审时需要定下的产品决策

1. 用户入口的正式名称与头像体系：建议先使用“我的助手”，允许用户命名；避免直接使用 dots 名称或图形。
2. V1 首发平台：建议桌面应用和 Gateway Web；移动端在同一身份/权限模型稳定后接入。
3. V1 可承诺的后台在线性：必须由实际部署方式决定文案；本地 Gateway 停止时不得声称持续工作。
4. 首版可用连接器与工作位置：只展示配置成功且经过能力探测的项目。

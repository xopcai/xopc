# 产品体验优化：分阶段开发与 review

日期：2026-09-15。范围：Gateway 后端、PC Web/Electron 共用界面、移动响应式 Web。

这是本轮代码交付记录，不是线上发布或真机验收结论。未改写线上历史任务、笔记或对话数据。

## 阶段一：任务状态与结果可信度（P0）

- 运行协调器校验 taskId、父子运行、sessionKey，禁止把其他任务的运行绑定到当前任务。
- 任务结果列表只收录根运行回执；子运行仍保留自己的回执供内部查询。
- 暂停优先于运行状态，暂停和关闭不再生成待处理提醒；首页和项目概览不再优先推荐无须处理的等待任务。
- 队列领取同时检查任务是否关闭、任务级等待和运行级等待，防止绕过暂停。
- Web 暂停/关闭命令在保存用户决定后请求终止实际会话执行。
- 迟到回执、子运行回执及旧版本任务约定不改变当前生命周期；项目已完成数仅统计 done，不把取消算完成。

Review：测试抓出并修正回执查询排序字段错误；发现运行级等待无法覆盖任务级暂停，已补队列入口保护。暂停不等于回滚已经产生的外部效果。历史错误关联不通过猜测自动迁移。

## 阶段二：验收、结果与行动入口（P1）

- 自动验收必须同时满足：有完成标准、逐项通过且引用已验证依据、目标已达成、没有剩余工作、不需要用户处理。
- 共享 verifiedTaskCriteria 规则用于自动验收、执行上下文和详情页进度，缺少证据的“通过”不计入完成进度。
- 任务约定修订后，旧运行的验证结果不用于新标准。
- 阶段性回执明确说明未必完成整个任务；评价按钮改成“结果有帮助／没帮助”，与“确认完成”区分。
- 增加交付物/证据卡：HTTP 链接单独打开，文件产物进入已有工作区预览；显示证据摘要与验证程度。
- 等待用户卡加入“补充信息／查看并决定”入口，进入任务对话保留任务上下文。
- 创建任务按钮明确“保存待安排任务”；当前版本已有“普通对话与持续任务”的说明，本轮保留其行为。
- 项目结果使用 Markdown 渲染，项目切换器优先显示说明而非内部目录。实际定时等待的 resumeAt 显示为下次检查时间。

Review：人工确认完成仍允许用户最终裁定。评价不会自动关闭任务。未添加自动批准权限请求或自动补充用户信息。外链是否过期不等于产物已删除，当前未实现自动重签。

## 阶段三：移动 Web 与阅读体验（P1/P2）

- 触屏设备不显示 Tab 快捷键建议。
- 手机笔记首页优先最近笔记，创建区域、项目区域后移；保留桌面布局顺序。
- 笔记工具栏在窄屏收起部分文字，保留带标签的操作；正文首个同名一级标题不重复显示。
- 空标题列表用摘要兜底；新笔记优先使用正文标题，或取完整主题句，最多 36 字符，替代固定前 10 字符。
- 主页面加入移动底部导航；聊天编辑与文件预览不额外占用输入空间。
- 非紧急 npm 更新横幅在手机隐藏，更新处理中、错误和需重启状态保留。更新仍可从设置访问。

Review：使用响应式语义样式，未新建第二套设计 token。原生 retired cross-platform client App 未修改，不能把移动 Web 的代码验证等同于 iOS/Android 真机验证。

## 阶段四：信息密度与语音边界（P2）

- 系统来源的收件箱会话放入“系统活动”折叠区，置顶保留原位置。
- 已结束且无失败的执行步骤默认收起，用户展开状态保留。
- 转写最终文本允许与最后一段增量共享版本号；重复最终文本、迟到增量被拒绝。按 utteranceId 隔离，缓存满时只淘汰最旧项。

Review：这只修复转写版本去重边界，不宣称修复历史说话人错标。历史角色问题需要原始语音事件与对应持久化记录复现。

## 同日后续：卡内决策、产物恢复与跟进控制台

以下合并同日后续交付记录，复用 TaskCommand、分享管理与主动跟进接口，适用于 PC 和响应式移动 Web。未发布线上，未修改生产任务或续期真实分享；上述“初次交付时尚未完成”表描述初次交付时的缺口，卡内表单、受限链接恢复与跟进控制台的后续进展以下文为准。

### 卡内决策

- 主动跟进列表卡直接展示决策问题、选项及可编辑的待办表单，无须先打开详情。
- 普通任务的用户输入等待支持自由文本和已有选项，回答持久保存为任务上下文，后续执行指令会读取。
- 带明确 capability 的任务审批提供批准、拒绝并暂停。权限来自服务端等待记录，忽略请求体伪造的 capability；只接受用户主体的批准。
- 批准后满足其他条件时恢复/创建执行；拒绝保留未满足的审批条件并暂停，在 Web 命令路径停止实际会话。
- 请求失败保留表单内容；相同重试复用幂等键。过期等待和关闭任务拒绝提交。
- 卡片身份或版本变化时阻止旧草稿提交，提示载入新版本。跟进要求使用开始编辑时的版本号，避免覆盖其他端改动。

Review：检查了重复请求、空回答、过期等待、批准范围、拒绝后的授权和执行状态，以及卡片在后台切换后的旧草稿问题。连接认证和专用澄清流程仍走其原接口，不能用普通任务表单绕过。

### 产物过期恢复

入口：任务结果的文件证据卡 → “链接打不开？” → 检查链接 → 恢复链接（24 小时）。

- 只匹配当前网关管理的分享 URL 或 LAN URL，要求来源和路径相同，不凭文件名或远端 token 猜测。
- 从持久分享记录恢复同一链接，保留 token、访问范围及访问次数上限。
- 已撤销不能续期；有效期必须符合网关配置。续期前检查工作区边界、文件是否仍存在及 inode 是否被替换。
- 已达访问上限提示前往分享设置；未过期时提示检查网关连接。
- 外部站点链接、已清理记录、丢失或替换的原文件不显示虚假的恢复成功，而是给出重新生成/分享的下一步。
- 笔记与对话快照通过其原始发布面板重发，不把已经清理的快照误当成普通文件续期。

Review：验证同一 token 恢复、访问限制保留、撤销保护、无效 TTL 和严格 URL 匹配。此功能不承诺恢复第三方站点或已删除的文件。

### 跟进控制台

入口：“交给我的事”中的事项详情。

- 汇总配置的来源范围、触发条件、最近检查结果、下一次检查和失败原因；实际依据仍在成果卡展示。
- 项目事项支持修改检查间隔（15–10080 分钟）、提醒方式、关注要求，以及现在检查、暂停、恢复和结束。
- 展示自动重试时间及尝试次数；重试已存在的可重试运行时提前其下次尝试，避免额外创建并行检查。
- 事件驱动事项明确等候来源变化，不显示无效的日历时间承诺；全局暂停提供设置入口，暂停时不承诺自动重试。
- 进展记录定期刷新，操作后刷新记录并展示提交状态；全局禁止时不显示可立即执行的检查操作。

Review：核对了事件/定时触发差异、全局暂停、并发设置更新、重试复用运行以及按 workspace 校验的既有路径。项目可主动重新检查；事件驱动事项在自动重试耗尽后需要来源更新，不重放过期外部动作。

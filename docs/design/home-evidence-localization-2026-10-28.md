# 工作台建议依据：本地化摘要与来源追溯

日期：2026-10-28  
状态：已实施，隔离 Gateway 与浏览器合成样例验收通过

## 1. 目标与当前问题

中文工作台的建议标题和理由已要求模型输出中文，但依据直接展示已有项目、任务、知识和会话内容。这使得中文建议下出现长篇英文、同一事实重复陈述，以及内部状态和绝对路径干扰阅读。

当前路径：

- `src/home-intelligence/snapshot.ts` 将来源内容截取为 `HomeEvidence.observation`。
- `src/home-intelligence/generator.ts` 生成建议文案和 evidence ID，不生成本地化依据摘要。
- `src/home-intelligence/policy.ts` 挂回原始 evidence。
- `web/src/features/tasks/home-advisor-card.tsx` 直接渲染 observation；历史详情也展示原依据。

本次交付：默认按界面语言阅读简明依据，同时能够展开原始记录并打开真实来源。保持原始证据、建议排序、任务创建和授权语义不变。

## 2. 用户体验

依据区域显示“依据摘要”，每个摘要组包含一句事实、来源数量和“查看原始记录”。摘要是 AI 整理内容，区域统一标注“AI 整理，原始记录可核对”。不把整个摘要设为链接；每个来源分别提供可用的打开入口。

以截图为例，目标表达如下；这是展示示例，实施时必须以对应 evidence 为依据：

1. **发布意图存在冲突，尚未确认采用哪一种口径。**
   资料分别将拾光描述为宣传片中的虚构案例和拟向外介绍的产品。来自 2 条记录。
2. **已生成本地发布素材。**
   记录提到发布页 HTML 和宣传卡图片；“素材已生成”不等于“已对外发布”。
3. **本次任务范围仅限本地制作。**
   不对外发布、发送或上传，也不修改已有源文档和发布包。

原始记录展开后显示：记录类型、记录时间、原始 observation、来源打开入口。优先从真实元数据取得来源名称；无法解析时使用“知识记录”“任务”等 i18n 名称，不能由模型编造文件名或链接。

这里的 observation 是系统已保存且可能截断的记录，界面称“原始记录”，不能将其声称为源文件全文或未经加工的原文。打开来源后才能进一步核对原材料；没有链接时明确展示“暂无可打开的来源”。

文件名、产品名、命令和必要技术标识保留。摘要不复述无助判断的内部字段（例如 availability=available）和完整绝对路径；原始记录保留这些内容。否定、权限、时态、主体和不确定性必须保留。

首页和建议记录使用同一个依据展示组件。默认显示最多 3 组，其余通过“展开其余 N 组”展示；首次发布不改现有依据区域的整体展开行为。所有按钮、来源类型、时间和异常提示使用 en/zh 词条。原始记录展示普通文本，不执行 HTML。

## 3. 数据边界

保持 `HomeEvidence` 原样，新增可选的建议展示投影：

```ts
type HomeEvidencePresentation = {
  version: 1;
  locale: 'zh' | 'en';
  groups: Array<{
    summary: string; // 1–2 句，最多 300 字符
    evidenceIds: string[]; // 每组 1–8 个，引用该建议 evidence
  }>; // 1–8 组
};

// HomeOpportunity 新增：
// evidencePresentation?: HomeEvidencePresentation
```

摘要没有独立事实权威，也不替代 `observation`。sourceRef、revision、observedAt、freshUntil、href 继续由宿主产生；模型不能生成或修改这些字段。

投影附属于某个建议及其固定证据快照，语言属于投影本身。原始 evidence 继续用于能力检查、过期判断、任务上下文和审计。投影不参与 ranking score、evidence count、去重键和任务 contract。

## 4. 生成方式

复用当前建议生成请求，不增加首页同步模型调用，也不为每条依据单独调用模型。

1. 快照构建仍保存原始依据。
2. ready candidate 在现有 evidenceIds 外，新增 evidenceGroups，形状为 `{ summary, evidenceIds }[]`。
3. prompt 明确摘要使用请求语言，只整理给定依据，不补充事实；相同陈述可以归组，独立信息不能吞掉。
4. Policy 先完成现有证据过滤，再验证摘要组是否与候选最终有效 evidence 一致。
5. 宿主写入 locale 和 version，将有效摘要投影随建议原子保存。
6. Web 读取本地持久化结果并展示。

模型 schema 中 evidenceGroups 暂设可选，以使展示生成失败不导致有效建议被丢弃。缺失投影的候选仍可通过现有建议筛选，但 UI 使用明确的原始记录回退。摘要字段的错误单独解析，不触发整批建议的结构化纠错重试；非法 candidate 核心字段仍沿用当前修复机制。

## 5. 校验、归并与事实保真

程序校验：

- summary 为非空、长度受限的普通文本；group 数量受限。
- group evidenceIds 必须来自该候选最终有效 evidence，不能跨候选引用或自造 ID。
- 每条最终有效 evidence 必须归属一组，不能遗漏，也不能在不同组重复出现。
- 若证据过滤后摘要覆盖的依据发生变化，丢弃整份 presentation，避免保留已失效来源推导出的文字。
- 中文语言检查应排除路径、标识符和专有名词，识别整段英文 prose；现有“包含一个汉字就通过”的检查不足以作为摘要语言检查。

语义归并由模型提出，宿主只验证引用完整性。相似措辞不能证明是同一事实；禁止仅凭文本相似度删除原始依据。来源冲突必须保留双方主张，旧状态与新状态必须保留时间关系。模型摘要不能把“制作本地素材”改写为“已发布”，不能把“需要确认”改写为“已确认”。

这些程序检查不证明翻译语义完全正确。否定、时态、冲突、权限边界和记录归并需要专门 fixture 与人工样本验收；不能宣称经 ID 校验即可保证摘要真实。

## 6. 存储与历史兼容

实施前核对 repository 当前建议 payload 的序列化、读取和契约解析点。计划优先把可选字段存入现有建议 JSON payload，不新增业务表、不提高数据库版本；若实际存储不支持，另行补充存储变更说明。

旧建议和历史记录缺少字段时正常解析：

- 中文界面遇到无中文投影时，显示“此记录尚无中文摘要，可查看原始记录”，展开保留原 observation。
- 英文或中文投影与当前语言不匹配时也采用该回退，不能把旧投影伪装为当前语言。
- 新生成的建议包含新投影；当前“重新评估”沿用既有刷新入口。文案明确重新评估会产生新建议，不承诺修复原历史记录。
- 首次上线不批量重写历史、不自动翻译全部知识、不因打开历史调用模型。历史本地化补全作为后续独立能力评估。

来源撤权、删除和过期沿用既有可见性规则；presentation 不能绕过权限。实施中复核 active 和 history 读取路径是否均遵守相关规则，存在缺口时补齐，不能仅依赖新增投影引用有效。

## 8. 验收标准

1. 给定截图中的英文依据，中文摘要保留“口径冲突、仅本地制作、尚未确认”的语义；不将素材生成解释为外部发布。
2. 两条重复陈述可归入同一组，展开仍有两条独立原始记录。
3. 相反观点、不同时间状态、不同主体的记录不被错误合并成一致结论。
4. 未知 ID、证据遗漏、跨组重复、过期证据与大段英文摘要使投影失效，但有效建议与原始记录仍可读。
5. 首页与历史呈现一致，zh/en 切换和混合语言来源都有明确行为；旧 JSON 可继续读取。
6. 查看依据、展开记录和打开历史不新增模型请求；正常生成增加的是同一次请求的输出 token，记录增量 token 和耗时。
7. 模型失败、摘要缺失、来源不可打开时不阻断开始、讨论和反馈；过期和授权规则继续约束任务启动。
8. 验证键盘展开、窄屏长文件名换行、屏幕阅读器的展开状态；链接必须指向宿主提供的来源。

测试覆盖契约与 repository 往返、Policy 引用与语言规则、生成字段容错、共用组件与历史兼容。最后通过真实认证 Gateway 验证“生成 → 展示中文摘要 → 查看原始记录 → 打开来源 → 创建任务”的链路，确认任务上下文仍引用原始 evidence。

## 9. 实施顺序

先完成契约与后台生成/校验，再接入共用 UI 和旧记录回退，最后执行端到端及语义样本验收。先交付本方案的有界闭环；历史批量翻译、全局知识语言治理和通用语义去重另行设计。

## 10. 实施与验证记录

- 新增 `HomeEvidencePresentationSchema` 与可选的 `HomeOpportunity.evidencePresentation`，原始 evidence 保持不变。确认现有 JSON payload 可直接持久化新字段，无需数据库迁移。
- 模型在同一请求输出 evidenceGroups；展示字段解析失败单独回退，核心建议沿用既有校验。为额外摘要内容将单次输出上限从 3000 提高到 6000 token，仍受原每日预算约束。
- Policy 校验完整分组覆盖、重复/未知引用、过滤后证据变化、HTML 和语言启发式。语言与引用校验不等同于语义真实性证明。
- 首页与历史共用 `home-evidence-list.tsx`，提供中文/英文投影、明确回退、原始记录时间与来源、前三组与其余组展开。没有模型请求或新的业务 API。
- 后台、契约和 Web 相关测试合计 88 项通过；根 TypeScript、Web TypeScript、修改组件 ESLint 与 Web 生产构建通过。
- `pnpm exec tsx scripts/verify-home-evidence-localization.mts` 在构建 Web 后可复现真实鉴权 Gateway、SQLite 与 Chrome 验收。使用临时状态目录和本地确定性模型，不连接用户账户或执行外部写入。
- 验收覆盖：未鉴权 401 → 生成中文摘要 → 展开两条英文原始记录 → 打开项目来源 → 历史内查看相同摘要和记录 → 创建任务。任务上下文仍引用原始证据 ID、revision 与 sourceRef；查看页面、记录与历史未增加模型调用，总计一次生成调用。
- 桌面、390px 窄屏及历史截图保存于忽略目录 `.xopc-evals/home-evidence/`。窄屏验证等待侧栏响应式动画结束，并检查页面无横向溢出。
- 来源变化沿用当前失效与历史快照机制，新字段随原建议快照保存，不增加读取权限；历史仍为原 owner/workspace 下的历史记录，不额外查取远端源文件。

本轮证明工程链路、引用约束和 UI 行为。摘要的翻译质量及是否正确归并不同事实仍需真实模型与脱敏样本持续评估；本地确定性模型不作为语义质量评测。

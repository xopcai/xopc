# xopc 跟进最小闭环

2026-11-24 · 产品设计 · 承接[主动体验产品审查](./proactivity-product-overlap-audit-2026-11-24.md)

## 1. 首轮只验一个承诺

**用户能把原来要自己反复查看的一件事交给助手。助手知道看什么、何时告诉他、何时结束；用户随时能从原处停下。**

首轮选一个已有的项目或任务、一处已授权且能检查的来源、一个明确条件和一段有效期。每份委托最多产生一次提醒。用户可以从工作台已有详情进入 Personal，也可以在 Personal 原对话里直接交代。工作台保留结果和状态，Personal 承接沟通。场景名、时间和具体条件均来自上下文与用户交代。

Onboarding 已有的授权资料和工作发现可以提供第一份线索或准备结果。用户继续按原流程进入应用，之后在原工作的详情或正常聊天里交代。也可以跳过首次发现，直接用一句话开始。首轮只完善有明确委托的条件跟进，周期产出和持续推进继续由已有 Automation 和 Task 承接。

## 2. 用户看到什么

用一个已有试点事项走查。项目跟进结束于周五 17:00，示例使用用户本地时间。

### 第一步 · 在原处交代一句话

工作台的试点项目已有一份状态或准备结果。用户从详情点「和助手讨论」，Personal 带着该事项的引用打开输入框。用户也可以在正在讨论试点的 Personal 对话里直接说：

> 周五 16:00 如果还要我定试点范围，就告诉我一声。

来源、判断条件和送达条件能够核对，而且跟进已成功启动后，助手回一句：

> 好，我会看试点看板。周五 16:00 还需要你定范围的话，我在这里告诉你。17:00 后这次跟进结束。 〔查看跟进〕

「查看跟进」打开这件事的现有详情。上面能核对来源、条件、送达位置、有效期，启用后就能点「停止跟进」。Personal 回执和工作台都指向同一项。用户重复发相同委托时，回复当前约定，沿用一次跟进。

如果关联不清，只问一个会改变结果的问题，例如「你说的是本周的 Android 试点，还是下周的全量发布？」来源权限不足时，在原处说明缺的是哪一个来源，并提供现有授权入口。来源未就绪时，回执写「待连接」或说明可检查的较窄范围。授权完成并确认检查可用后，在原处给实际启用回执。

### 第二步 · 到点最多提醒一次

| 到了检查时点 | 用户看到什么 |
| --- | --- |
| 条件命中，约定「告诉我」 | **Personal** 收到一条普通消息。工作台原事项同步显示同一结果，无第二个提示。 |
| 条件命中，用户约定「放工作台」 | **工作台**的原事项收到一次提醒，打开即可看结果。Personal 保持原对话。 |
| 条件未命中，或用户已经在任一入口把事情定了 | 详情可查最近成功检查和当前状态。安静结束，避免用「暂无变化」占一条消息。 |
| 候选已排队，用户正在忙或处于免打扰 | 在有效期内等待，投递前重查状态和权限。同一项若已处理、已停止或过期，收回待发消息。 |
| 到点无法确认来源 | 原详情标出「这次检查未完成」和最后一次成功时间。若仍在处理窗口、交付设置允许且用户需要接回，在约定位置用这次唯一的触达告知缺口。证据补齐后更新详情。 |

Personal 实际消息示例：

> iOS 审核通过了，Android 的离线恢复还在复核。17:00 前需要你定试点范围。我把可选方案放在原事项里了。 〔查看试点范围〕

可以在消息下回复「iOS 先发」，或在工作台原事项处理。助手把已经明确的决定记在该事项上，实际发布照原流程走。两处看到的是同一结果和同一处理状态。**静默展示或打开详情属于查看，提醒是一次主动触达。** 已看过准备材料、到点仍待决定时，可以按约说一次。提前做了决定，待发提醒随之失效。同一事实遇到事件重放、重试或两条系统路径同时识别，仍只产生一次提示。交付后这份一次性跟进结束，原事项的待决状态继续由实际决定更新。

### 第三步 · 在看到它的地方停下

- **Personal**：从回执或提醒打开「查看跟进 → 停止跟进」，也可以在有明确事项上下文时回复「这件不用盯了」。回「已停止这次跟进」。多个事项可能匹配时，只问要停止哪一件。
- **工作台**：打开原事项，在跟进状态旁点「停止跟进」。详情立即显示「已停止」，Personal 回执的详情入口也反映同一状态。已经完成或已经停止的请求重复提交，返回当前状态。

停止对这次委托生效，停止新的检查和未送出的提醒。若关闭时后台正在处理，以实际停止结果更新状态，旧结果无论何时返回都失去投递资格。已发生的消息和原始资料可回看；原任务、独立委托和已承诺的其他交付各有自己的状态。重新跟进由用户明确交代。

## 3. 哪些直接复用，哪些确实要补

| 产品环节 | 直接复用 | 必须补齐的衔接 |
| --- | --- | --- |
| **交代** | Personal 正常对话、明确跟进提取、现有项目／任务详情及来源授权。Onboarding 和「交给我」已有的线索按已授权用途使用。 | **把一句话落成可核对的委托**。绑定原事项、实际来源、条件、送达位置、停止时间。只有成功启用后才回「我会看」。详情从原处能打开。 |
| **检查** | 已有 Personal 唤醒，或 Automation 的定时／事件能力，按来源选一条。Proactive Hub 的筛选、准备和已有投递可选复用。 | 为同一委托指定一个检查和交付责任方。用原事项的状态和授权事实核对条件。两条链都看到同一事实时，共用这一委托的判定和结果。 |
| **只提醒一次** | Personal 消息、工作台原详情／现有待处理位置、现有来源链接和提示。 | **共用结果与提醒状态**。以同一委托和业务变化识别重复，成功发出后另一个入口只可引用。正式送出前校验可见范围、已处理、停止、时限、免打扰及用户设置。选定工作台时只在工作台提醒，选定 Personal 时只在 Personal 提醒。 |
| **在原处停** | Personal 现有主题停止反馈或操作；工作台既有的详情、任务和托管控件。 | **共用停止动作和状态**。在 Personal 回执及工作台详情都能指到这一次跟进，停止后旧队列、正在准备的结果和事件重放都无法再触达。 |

第一轮以原对话和现有详情承接所有操作。优先把现有对象和投递状态关联起来。一次性条件跟进、已有可读来源、站内两个入口构成验收范围。兴趣订阅管理、额外的工作流配置、默认汇总和跨渠道覆盖留给后续需求评估。

## 4. 评审与验收

| 走查 | 可以通过的表现 |
| --- | --- |
| **一句话交代** | 正在聊的事项能直接识别，已有权限时用户一句话拿到可核对回执。遇到真正歧义时只需补一问。没有来源时看得出尚未启用。 |
| **按时且一次** | 将任务变化同时送进两个现有路径并重放。约定位置准时出现一条提醒，另一处只更新同一条状态。无变化、已有决定、已到期的对照案例安静。切换到「放工作台」后，提醒确实只在工作台。 |
| **在原处停止** | 分别从回执和工作台停止，另一个入口立即读到同一状态。确认停止后重放事件、让队列恢复、推进时间，均没有新提醒。原任务仍可继续按自己的流程处理。 |
| **换个主题也成立** | 将试点范围换成「评审前材料仍未齐」的一项已有任务，只调整对象和条件。使用同样的委托、提醒和停止操作。 |

首轮价值用一件用户本来会反复检查的事检验。观察他交代后是否还要自己刷新、有没有在窗口内拿到可行动的结果、能否从当前入口直接停下。如果用户依然得去找另一处、收同一事的第二条提示，或担心停止没生效，就先修这条链路。

现有能力证据见[Personal 提取与投递](../../src/personal-agent/proactivity/service.ts)、[Personal 反馈与停止](../../src/personal-agent/proactivity/routes.ts)、[Automation](../automations.md)、[Proactive Hub](./proactive-event-driven-rsi-plan.md)和[工作台](../../web/src/pages/home-page.tsx)。

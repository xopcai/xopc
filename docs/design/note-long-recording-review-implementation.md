# Note 第三批：长录音回顾、统一搜索与阶段性可用

实施日期：2026-10-16。承接 P0、1B 与第二批证据联动。鸿蒙仅做主机测试、静态检查和编译，不做真机验收。

## 用户体验

Web 和鸿蒙 Note 都有统一关键词入口，覆盖已保存的原文、章节标题及摘要、分析结论、行动候选和已同步标记说明。匹配采用 Unicode NFKC 归一化后的字面量大小写无关比较，不执行正则，也不依赖模型。搜索范围仅限当前 Note；尚未转写的音频不可搜索。

结果显示内容类型、时间位置、原文上下文、阶段性/旧版状态和回听操作。Web 在结果时间轴上标出已加载命中位置。搜索分页绑定版本，内容改变后拒绝接续旧版本页面，并提供刷新入口。输入防抖，切换关键词或 Note 后的迟到响应不会覆盖当前结果。

章节显示时间范围、摘要、重点数量和候选行动数量；展开依据使用对应版本的原文。Web 目录默认不展开整段原文，长摘要收起；点击后沿用证据侧栏与同一播放器。鸿蒙使用证据面板，定位原文后展示该段及相邻上下文，并提供返回全部原文的操作。旧版证据不跳转到新版复用的段号。两端都用已有原音时间映射回听，不能验证的时间不猜测。鸿蒙沿用最长 120 秒的受限片段播放。

已保存原音不等待 AI 完成即可播放。后台转写已持久化的分片在正式全文发布前即可阅读、搜索、回听；已经完成的章节在后续章节或总览失败时仍可回顾。阶段性转写使用 processing run 独立 ID，不占用正式 transcript sequence，不提供正式段落校对/标记，避免之后发布时错误绑定。原有已发布原文和分析继续保留。

## 进度与覆盖范围

回顾投影独立显示：原音是否实际可用、本轮累计已处理时长、从零连续处理到的位置、本版已完成分析范围、旧版分析提示及本轮是否完成。原音上传/校验、自动重试和具体失败仍使用已有录音状态提示。

转写进度来自当前原音代次的持久化 checkpoint 范围与可复用确认片段的区间并集，不使用最新分片末尾，也不将重叠时长重复相加。强制从原音再生成时，旧版原文不能充当新一轮的完成进度。经过完整转写封存后，才把本轮处理范围投影为完整音频时长；语音文字范围另行保留，不把无语音区间伪装成文字。

分析覆盖来自对应原文版本的已完成章节范围。原文修订后，旧章节仍可查看及回听，但不计入本版分析覆盖。阶段性章节与旧版完整总览分开标识。处理状态为 completed 也不替代具体覆盖范围说明。

处理中且没有关键词时，两端定时刷新阶段性内容；正在浏览搜索结果时保持结果快照，提供显式刷新，避免自动刷新使分页和浏览位置跳动。原音变化时旧投影与旧播放引用失效。

## 数据与 API

- migration 255 新增 `discussion_chapter_progress`。每个成功校验的分析批次在完成后持久化；缓存命中也恢复其投影。
- 章节投影绑定原音 SHA-256、原文 revision 和全文 SHA-256。写入时核对当前代次，防止旧异步任务写入新内容；重启可直接读取。
- `GET /api/discussions/:id/review?q=&offset=&limit=&version=` 返回章节、搜索/阶段性结果和覆盖范围。默认每页 20 条，最多 50 条；关键词最多 200 字符，返回文本摘要及少量相邻原文。
- 复用 discussions 的认证及懒加载路由，读取需要 `workspace.read`。路径映射和真实监听 HTTP 的认证、只读访问、参数拒绝均已补测。
- 这是当前 Note 的确定性关键词扫描；本批不引入语义问答、向量索引或自动创建任务。

## 验证

新增/扩展测试覆盖：

1. 两小时、1200 段原文的尾部命中、上下文、跨原文/章节/分析/标记搜索、字面量特殊字符及 Unicode 匹配。
2. 区间重叠、未处理缺口、连续进度、强制重跑不虚增进度、部分转写原文不覆盖已发布版本。
3. 分片/章节持久化、数据库关闭重开、模型中途 503 后章节提前可用及重启续跑复用。
4. 原文修改后的历史依据、旧分析不计入当前覆盖、翻页版本冲突、关键词和 Note 切换后的迟到响应。
5. Web 结果映射回听、命中时间轴、阶段性提示、当前/历史依据分离、独立轮询；鸿蒙关键词防抖、结果隔离和远端原文上下文定位。
6. 上一批证据定位、录音故障恢复、真实媒体时钟映射及两小时音频封存 smoke 保留在回归范围。

验收范围区分：两小时原文搜索为合成内容测试；两小时音频 smoke 为生成音频的真实媒体封存/解码测试。本批不宣称完成两小时真实会议录制或鸿蒙真机验收。

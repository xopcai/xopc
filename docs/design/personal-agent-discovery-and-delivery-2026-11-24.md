# xopc 从无感发现到主动交付

2026-11-24 · 产品设计第三轮 · 发现、触达与场景验收

延续[第二轮 Personal 对话与工作台方案](./personal-agent-quiet-proactivity-2026-11-24.md)。本轮进一步明确两处的职责，并补齐从发现到结束的决策。下面的场景取自常见的真实工作与生活流程，人物、时间、记录和消息用于产品走查。

## 1. Personal Agent 接住关系，工作台接住工作

| 入口 | 用户打开它时想做什么 | 默认承接 |
| --- | --- | --- |
| **Personal Agent** | 跟助手商量一件事，交代一个牵挂，听它告诉我需要知道的变化 | 生活、兴趣和个人目标的长期接续；需要一次沟通、一个判断或一项授权的工作或生活事项 |
| **工作台** | 看工作推进到哪儿，接手待办，打开材料继续做 | 项目和任务的结构化状态、已准备好的结果、可处理的待决项、可回溯的交付 |

判断入口时先问 **用户此刻需要一次沟通，还是需要一份能使用的工作结果？** 工作默认有一个原有工作位置。它需要用户拍板时，Personal 只带来需要沟通的部分，材料和决定仍回到原项目。生活话题优先沿原对话接续。用户明确要一份以后还会打开的计划、清单或对照表时，可以把该成果放到用户指定的工作台位置，默认只对本人可见。一般兴趣、生活琐事和健康回顾继续留在 Personal 的关系内。

**发现、委托、交付是三个时点。** 发现意味着助手有理由关注一件事；委托意味着用户允许它在具体范围持续做；交付意味着现在有一条结果值得给用户。前两步都可以发生在普通使用里。Personal 和工作台继续是用户看到结果的两个入口。

### 两组原型素材验证同一套通用能力

试点发布和街拍是原型里两组预设的对话、资料和时间线。产品要理解的基本单位是用户在意的**一件事**。它可以来自 Onboarding 或日常对话，最初可能只有目标和依据。用户真正委托时，再补齐允许看的来源、值得继续检查的条件、交付约定和结束条件。能从上下文确定的内容直接沿用，只有影响承诺的缺口需要问用户。

- **发现看证据。** 用户是否真的关心，事情是否仍有效，以及助手能补上什么。话题名称可以帮助理解语境；归属、依据和价值决定是否形成候选。
- **跟进看约定。** 条件可以是发生某个变化、到一个时间再检查，或者有合适内容时精选一条。内容主题、来源和期限来自用户交代及允许使用的上下文。后台检查需要相应的委托和来源授权。
- **交付看结果和时机。** 需要沟通且符合约定的结果去 Personal，有可用的结构化成果时回到用户预期的工作位置，没有足够增量时保持安静。工作和生活是入口的默认倾向，具体去向随用户约定、结果形态和当下时机决定。

新增主题沿用这条链路。若需要新的数据来源，接入负责提供可核对的事实、更新时间和权限范围，发现、跟进和触达规则继续共用。场景名、示例话术和固定时点只属于走查素材。

## 2. 怎么无感发现一件事

### Onboarding，先从已有上下文找可交付的价值

1. **用户按原流程进入。** 已有引导照常让用户选择和核对上下文。发现关注点在已授权的用途和范围内发生。用户跳过分析或没有合适来源时，直接开始日常使用。
2. **从具体人、事、时间找出未完的一步。** 对用户确认的项目目标、个人目标和授权资料，先辨别是不是这个用户的事、是否仍有效、有什么会变化。诸如「周五试点，Android 还在复核」比「用户在做移动端」更适合跟进。
3. **能先完成一小步，就先交付这一小步。** 从两张已授权的清单里找出会影响交付的一项，工作台出现一条可用结果。用户第一次在 Personal 聊到相关生活目标时，助手用已有信息把这一轮答得更好。一开始拥有很多资料也只挑最值得呈现的一件。仅允许在一次性分析里使用的上下文，按当次用途和保留期处理。
4. **用户在看到价值或表达需要后，自然交代以后怎么做。** 用户说「周五还卡着就叫我」，助手在原处回一句「我会看试点看板，周五 16:00 如果还需要你定范围，我来告诉你。」明确使用哪一来源、什么情况找人和何时结束。只有一个问题会影响结果时，就问这一个。没有可靠检查能力时，告诉用户实际能看什么。

首次工作台最多出现一条额外发现，且它要能独立使用。首次 Personal 沿用普通对话。一个关于摄影的兴趣标签、零散的收藏或一封转来的邮件，最多让助手以后遇到同一主题时理解更准。没有具体发现就维持原样，用户也无需回答兴趣调查来解锁主动功能。

### 日常对话，从用户的意思区分信号

| 用户留出的线索 | 怎么判断 | 当下怎么做 |
| --- | --- | --- |
| 「这周末有补位就告诉我」 | **明确委托**。已有上下文能确定活动和来源时，意图足够窄。 | 说一句承诺，当场确认真正缺的条件。范围清楚且有授权，即可依约检查。 |
| 「我一直在刷新这个页面，怕错过」 | **有代看的需求**。用户描述了负担，持续执行的意思仍需核对。 | 当轮先给当前已知结果。有可靠方案时，在结尾自然补一句「如果你愿意，我可以看这页到周日，有补位再告诉你。」 |
| 近期一个目标加待决项，例如「周五试点，目前还有两项没定」 | **当前有未完事项**。需证据证明事项归属、时间和状态。 | 有工作现状或选项可整理时放到原项目。后续主动联系等用户约定或既有权限明确涵盖。 |
| 用户跨日谈到同一个问题，或直接表达一个稳定目标 | **可能值得长期理解**。例「想系统练街拍」与「我一直拍不出层次」互相支持。 | 下次相关对话可以给更贴合的帮助。看到重复信号可以保留候选；定期找素材或另发消息需要用户明确约定。 |
| 「帮同事比较两款跑鞋」，或来源是转发、引用、模版示例 | **归属或未来意图不充分**。同一来源转存多次也只算一次。 | 完成眼前的问题。以后有本人证据再判断。 |
| 「已经处理了」「不是我的事」「以后别提这个」 | **完成、归属修正或停止**。新的明确说法优先于旧推断。 | 更新事项、收起旧候选，并取消仍在排队的同范围触达。以后重新开启以用户明确交代为准。 |

每个候选都要说明**与谁有关、现在什么还没结束、助手能补什么、依据在哪**。近期事项靠明确状态，清楚的一次表述就可以成立。长期兴趣可以由用户明确声明，也可以从跨日、相互独立的本人表述中判断。用户在同一轮复述、点击一条内容或没点开都不足以建立委托。健康等敏感内容只承接用户明说的具体用途，例如回顾本人选定的活动记录。

### 在哪个时点露出发现

- **现在能帮，先把信息用在当前任务中。** 例如用户在讨论项目范围，直接把已经核对的变化补进这一轮。一次自然回答里确实展示过的同一事实，不再额外作为推送出现。
- **马上多一步也有价值，才提出一句委托建议。** 只在用户正在聊这件事，并且助手知道自己具体能替他查什么时提出。用户自然回复「那你帮我盯到周五」就是交代，必要授权在原处说明。有用的工作结果可以顺手放到工作台，用户以后还可以引用它继续聊。
- **只知道用户可能在意时，安静保留。** 保留在允许的时间和范围内，等下次对话提供机会。碰到新目标、事项已过期或用户纠正，用最新的明确意思更新。用户忽略一次建议时保留选择权，避免隔几天重复问同一个问题。

## 3. 触达顺序，先用当前对话，再看是否需要另开口

先检查权限、归属、时效和事实是否可核对。一个来源返回了相似标题，或检查根本没成功，都不能证明发生了新变化。结论也要对照用户上次已经知道什么。一条够格的更新，至少能改变实际行动、节省一次有意义的检查，或给用户一个具体可试的发现。

| 情况 | 放在哪里 | 判断例子 |
| --- | --- | --- |
| **用户正在聊同一件事，而且结果能帮他完成这一轮** | **融进当前回复**。属于正常对话。 | 用户正在决定试点范围，助手说刚核对到 iOS 已过，顺手带上来源。用户已经看到了这个事实。 |
| **有明确约定的变化发生，或者在用户允许主动联系的范围内，等太久会失去处理机会** | **Personal Agent 主动说一句**，通常带一个下一步。 | 有补位、到了约定决策窗口、原有监控断开且会影响用户眼下的决策。简单确认「已恢复报名」本身就是结果，直接带官方入口即可。 |
| **用户明确约定让助手在 Personal 分享生活或兴趣发现** | **Personal Agent 主动说一句**，按约定的时间、频率和内容门槛。 | 「周五如果有合适的街拍练习就发我」。这一周只有重复教程就保持安静。无需为了发消息而寻找紧急理由。 |
| **有可用的结构化工作价值，用户晚点看仍来得及** | **只放工作台**。进入原项目、任务、交付或待处理位置。 | 可审的周报草稿、完成的对照、无须马上拍板的阻塞变化。足以支持继续工作即可。 |
| **生活或兴趣有好线索，用户还没约定主动说，也没有当前相关对话** | **保持安静，等话题自然回来**。 | 找到一个合适的摄影练习，可以在用户下次问怎样构图时使用。 |
| **没实质变化、推断有疑点、已经告知、处理窗口过了或用户已结束** | **保持安静**。已委托事项留有可查的检查状态。 | 标签反复改、二手转述重复、席位曾补但当前已满、用户已自行处理。 |

### Personal 的最后一道门

1. **他会期待这句话吗？** 明确约定优先。工作上的主动联系可以基于用户已允许的责任范围及明确损失窗口。单凭「它很重要」不足以给用户送一条聊天消息；工作台仍可呈现待决和截止时间。
2. **现在说，他还能做什么？** 说清改变、时限或用户为何会关心。能做准备就把选项备在后面。用户只想知道某件事是否发生时，一句有依据的事实就够。
3. **当前适合开口吗？** 遵守免打扰和主动设置。用户在打字、通话、前台回合或读历史时保留原有操作，等待自然空档。等待后重新检查有没有更近的事实、用户是否已处置、还来不来得及。错过交付窗口时，能帮助工作收尾的结果回到原工作记录，普通生活内容留在事项详情。

工作台先有一条准备，后来到约定决策窗口，可以用同一事项主动说一次。主动消息、工作台结果和用户的处理结果相互引用。读了材料还没做决定，状态仍是「待决定」；同一事实重复刷新，状态不产生新的提示。用户说「这条先放下」「以后这类放工作台」「这件不用盯了」时，分别处理本条、后续交付偏好和整件事。

### 安静可以被核对

用户主动回看跟进时，应能看出「成功查过，暂无变化」「上次只查到一部分」「来源已断开」「已经结束」的区别。覆盖失效本身如果会改变近期决策，还可以成为一次沟通的理由，前提是用户已允许此类联系并还有可采取的补救。长期离开、未读、背景来源暂时无信号，均不推断任务已完成。

## 4. 五条完整体验

### 场景一 · 从 Onboarding 发现试点发布还缺一个决定

| 时刻 | 助手如何判断 | 用户看到什么 |
| --- | --- | --- |
| 周四初次使用 | 已授权的试点计划写着周五发布，用户确认自己负责。两份资料可对照出四项未确认问题，一项会改变发布范围。 | 工作台试点项目下有一条「已对齐 4 项未确认问题，Android 离线恢复可能影响发布范围」。打开时就能看依据和原任务。Personal 保持正常聊天。 |
| 用户看过后 | 用户说「周五 16:00 如果还得定试点范围，你来告诉我」。他授权的是看试点看板并在一个窗口沟通。 | Personal 回「好，我会看试点看板。周五 16:00 还有范围需要你定时，我来告诉你。」 |
| 周五 13:00 | 负责人例行改了一次标签，决定所需的事实没有变化。 | 安静。仍可在工作台查看原材料。 |
| 周五 16:00 | iOS 已通过，Android 仍在复核，17:00 前确实需要定范围。助手备好两个选项。 | Personal「iOS 刚通过。Android 还在复核，17:00 前需要定试点范围。可以先发 iOS，也可以等两端一起发。」下方可查看证据和两个选项。 |
| 用户回复 | 用户回「iOS 先发」。助手将决定记到同一条准备记录，后续实际发布照原流程走。 | 对话回一句「已把 iOS 先发记进试点决定。」工作台同一条变为「范围已确认」。若用户 15:40 已在项目确认范围，16:00 不再来一句。 |

### 场景二 · 工作里反复遇到的周报，可以悄悄准备好

| 时刻 | 助手如何判断 | 用户看到什么 |
| --- | --- | --- |
| 连续两个周五 | 用户都请求对同一项目整理已完成事项、风险和下周计划。两次交付有反馈，来源可持续使用。 | 第二次交付仍按原路径。助手在回复末尾问一句「以后周五我先把这份草稿放到工作台，你过目就行？」 |
| 说清约定 | 用户回「周五下午放项目里，风险单列」。范围是该项目，输出是可审草稿。 | 回「每周五下午放到这个项目，风险单列。」无需访问另一页确认。 |
| 下一周 | 源资料已按时齐备。对照上周有两项完成、一项风险变化。 | 工作台原项目交付位置显示「本周进展草稿 · 2 项完成，1 项风险需看」。Personal 安静。 |
| 工作台看草稿 | 用户将一段改成更短。助手要区分本次编辑与可沿用的长期偏好。 | 默认只改这份。用户说「以后风险都只留一行」后，该项目下一次草稿按一句话更新。若本周源资料缺了两处，草稿或详情写明覆盖，避免把未知写成无进展。 |

### 场景三 · 生活兴趣慢慢变清楚，等聊天自然接上

| 时刻 | 助手如何判断 | 用户看到什么 |
| --- | --- | --- |
| 第一次聊街拍 | 用户问 35mm 怎样拍近一点，也可能只是在帮别人找答案。 | 正常答这一问。后面保持安静。 |
| 过几天 | 用户发两张自己的街拍，说「我想练前后景，但拍起来有点平」。现在有本人归属、持续意图和具体困难。 | 助手先讨论这两张照片，再补一个固定机位的十分钟练习。生活兴趣沿对话接续。 |
| 用户开始用这个办法 | 用户说「这招好用，有类似的周五发我一条」。这是允许在 Personal 上按约定频率分享。 | 助手回「周五有适合 35mm、能在周末试的练习，我发你一条。」 |
| 接下来两周 | 第一周只有同质教程。第二周找到有明确出处、可试的倒影练习。 | 第一周安静。第二周 Personal「上次的路口练习是等人走进前景。这次可以用店窗倒影同时收进两层画面，原练习只要十分钟。」可点开出处。用户回「最近不拍了」即停止。 |

### 场景四 · 等周末活动补位，命中的才说

| 时刻 | 助手如何判断 | 用户看到什么 |
| --- | --- | --- |
| 周三聊天 | 用户说「周末这个陶艺工作坊如果补位就告诉我」，链接已经在对话里。助手确认可检查的官方来源和时效。 | 「我看主办方这页到周日开课前。有仍可报的补位，我来告诉你。」如果实际只能间隔检查，回执说明间隔。 |
| 中间两次变化 | 主办方编辑了文案，转载页面又重复发旧场次，均未产生可报名名额。 | 安静。用户主动问时可回答上次查到的准确覆盖。 |
| 周五出现补位 | 官方入口显示仍可报名，剩余处理窗口足够且用户允许当时联系。 | Personal「周日 15:00 的场次补了名额，现在还能报名。」附原页面。用户报名或说「不用了」后结束。 |
| 反例 | 同一公告在免打扰内出现，恢复后名额已满。或者入口失效，实际余量无法确认。 | 已满时只更新详情。入口失效会影响用户掌握消息且还能补救时，经允许只沟通一次「官方页打不开。我最后一次确认是昨天下午，如果你还想等，可以给我另一个官方入口。」 |

### 场景五 · 用户明确提出的活动回顾

用户日常说「最近有点累」时，助手照常回应当下问题。这句话没有建立健康跟进。后来用户主动说「周日帮我看看我自己记的这几次散步」，并选定三条记录。Personal 回「周日我把你选的记录整理一下，只看这几条。」到约定时给出有日期和记录范围的简短回顾。如果第三条尚未同步，说明「目前看到两条」，用户补完后可以直接接着聊。这次回顾交付后结束；下一周是否继续，由用户来定。所有内容留在已允许的私有范围。

## 5. 设计验收与首轮取舍

- **先验无感发现。** 用同一套场景分别走有上下文、证据不足、来源撤销三条路径。首次有价值时能直接看到结果；没有价值时能直接聊天和工作。用户能用一句话确认是否以及如何长期看。
- **再验入口分工。** 周报准备在原项目，摄影兴趣从个人对话继续，真正需要决定的发布事项只在 Personal 有一次主动提示。看过、完成、过期和已撤权都能得出正确去向。
- **用反例校准安静。** 收集真实时间窗和重复变化。分别问用户「这条值得现在告诉我吗？」和「当时没收到有没有误事？」同时观察多说与漏说。验证偏好修改后下一次交付实际按新约定。
- **观察被省掉的工作。** 代看场景看用户是否少了手动检查、是否在窗口内处理。探索看是否尝试了推荐内容或自然追问。首用看独立配置次数、首条结果的可用性和用户能否说清哪件事已交给助手。
- **用新主题验证泛化。** 将「试点范围在截止前仍待定」换成「活动场地在截止前仍待确认」，将「周五有合适的街拍练习就发一条」换成「周五有适合我水平的吉他练习就发一条」。保持条件与权限相同，两组都应沿用同一判断和控件。再把同一主题的交付约定、待决状态或内容新颖度改变，核对去向随条件变化。

首轮优先走查**工作台里的第一份准备、Personal 在决策窗口的一句话、生活兴趣在没有合适时机时保持安静**。用固定场景对照来源、条件和时机，评审产品与交互体验。

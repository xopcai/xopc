# Personal 对话风格持续迭代方案

日期：2026-11-02。目标：让用户与助理交流时表达顺畅、上下文衔接自然、分寸适当；行动、限制和事实仍准确。风格偏好改善不能靠遗漏内容、迎合错误、虚构执行或强行变短实现。

## 现有基础与证据边界

复用 `evals/personal/style/run.mts`：隔离生产 Personal、鉴权 HTTP/realtime、真实提示与工具工厂、EvalStore/ArtifactStore/TraceEmitter。复用 `compare-p0.mts`：匿名新旧轨迹、双展示顺序、精确 assistant turn/原文证据、顺序分歧保留。既有 FollowBench 中文 style 保护显式约束，EQ-Bench 4 提供社交适应性参考，其描述性 trait 不能当中文交流满意度或官方能力排名。

Muse 作为用户喜欢的产品体验参照，不假定其内部训练方法、提示或 benchmark 已知。不复制第三方未授权私人对话。本阶段不依赖第三方产品 API、没有与 Muse 实测优劣结论。

## 迭代闭环

1. 从授权且脱敏的对话反馈中定位具体问题，保留上下文及适用范围。当前单轮例外、当前会话偏好和明确长期偏好分开，临时情绪不写成永久属性。
2. 用可观察失败定义样本、评分规则和保护项；开发集用于诊断，冻结验证集不用于选择候选。模型不能看到 expectations、裁判提示或隐藏元数据。
3. 预登记一个明确候选、固定模型/推理配置/源码/预算；新旧只允许声明的风格模块不同。先离线检查，再并发运行独立会话；同一会话的轮次串行。
4. 双顺序模型盲评给出整体与自然度偏好，以及可核对的逐轮错误证据。相反顺序结论不一致记 discordant；失败或缺项记 unresolved，不剔除或补成 tie。
5. 人工盲评校准模型裁判，保留人工分歧。仅在独立验证、内容/权限保护、人工复核和延迟约束满足时晋级。每次改变 rubric 都生成新协议身份；旧失败和决定不可覆盖。
6. Dashboard 展示具体新旧文本、分项问题、模型与人工评审状态、时延、用量及证据来源。晋级后小范围采用、监测与可回滚；不自动合并或部署。

## 分阶段计划

| 阶段 | 交付与验收 |
|---|---|
| 第一阶段：中文多轮基线 | 新增 12 个中文 4 轮脚本，覆盖追问/纠正/话题切换/收口/偏好例外/详细回答/授权与事实边界；6 开发、6 冻结验证。真实旧/新候选各一遍、双顺序盲评、人工盲评包、Dashboard 与不可变结论。完整分母和失败保留是必须项；模型偏好不能冒充真人满意度。 |
| 第二阶段：人类校准与真实衔接 | 经用户授权积累真实片段，至少两位独立评审、随机匿名对照、报告一致性与原因；加入任务提交/后台结果/话题变化的真实有工具场景、用户偏好撤回与跨会话隔离。首阶段固定用户脚本不证明实际任务已执行或自适应用户反应。 |
| 第三阶段：持续候选生成 | 从失败聚类生成有限提示/上下文/偏好投影候选；预登记、预算、公平模型条件、独立留出集、回滚。开发集每轮可扩展，验证集暴露后归档并轮换。 |
| 第四阶段：长期体验 | 在授权范围做用户级小流量实验；追踪实际偏好、误解修复、打断/退出、时延及任务可靠性。用户纠正可撤回，长期偏好有来源/作用域/版本。模型训练需另行数据授权与方案。 |

## 第一阶段冻结协议

- 被测：`xopc-cloud/openai-codex/gpt-5.6-sol`；裁判：`xopc-cloud/openai-codex/gpt-6.1-sol`，遵从用户明确指定，不自动回退。
- 复用现有 style 协议 reasoning=off、evaluatorReasoning=low、fresh production profile；隔离真实用户历史/记忆/连接器。同条件配置一致并记录。不会修改用户的生产模型配置。
- 12 场景 × 4 轮 × 2 条件 = 96 个计划用户输入；每场景双展示顺序 = 24 个计划盲评。并发 2，单请求 240 秒、每场景原 48 请求/30 分钟上限；本轮不做按成绩重试/替换。工具或辅助物理请求单独记录，不将用户输入数等同于物理调用数。
- 只比较一个预登记的“当前意图与表达衔接”候选：承接用户刚刚要解决的事、无需重开话题或套固定确认模板；偏好纠正先应用；保留请求细节、事实与必要授权澄清。候选仅在冻结实验源码中覆盖共享 reply-style，未晋级不进入生产默认。
- 新 rubric 增加 conversation_flow（衔接/机械包装/答非所问）与 preference_scope（持续、例外、纠正/撤回的范围），保留全部原风格/内容/权限维度。合法结构、专业细节和自然必要提问不应受罚。整体与 naturalness 分开。
- 晋级门槛：全捕获与双序评审完整、源码和配置一致、验证集整体/自然度候选净胜均至少 1、任一顺序候选无 major、内容/边界及风格错误不增加、验证集 p95 完成时延不得超过基线 1.2 倍，人工盲评至少 2 位独立评审完成且整体与自然度净胜均正。不满足或缺人工就保留 rejected/pending，不自动采用。门槛只适用于本次小样本试点，不作显著性、总体满意度或 SLA 声明。这里的相对 p95 保护只评估风格候选是否带来时延退化，不替代或放宽已有 Personal v7 的提交 20s、首答/ping 5s 验收。
- 报告开发与验证分开、wins/losses/ties/discordant/errors 分开，分母固定。原始输出和 exact quote 留本地 ignored；便携汇总/源码指纹进入仓库。保留模型调用与已观测用量，未知财务金额为 null。

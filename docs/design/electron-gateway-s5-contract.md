## 实施顺序

1. **T0 范围冻结**：核对现有输入/恢复/隔离契约、测试包与Gateway版本、缺失故障项；性能单独追踪。
2. **T1 连接循环**：同一应用保留连接页，交替连接A/B、核验设备能力全禁/历史与草稿隔离、恢复到连接页、确认Shell退出。至少100次完整连接→核验→关闭循环；每次开始间隔至少5000ms，身份签名和API限额不变。少量循环只能验工具，不能记作100次通过。
3. **T2 持续运行**：同一客户端状态运行至少24小时，且至少1200轮成功输入/资源/隔离检查，避免空转或长时间暂停被当作完整验证。固定循环包含空闲、每分钟合成输入及服务器资源读取、定期断线/gap恢复、半开检测及应用重启。每轮断言POST计数、UI状态、无本地数据库/工作区/Host登记；保存单调耗时与资源原始值。短时smoke必须明确标记，不替代24小时，输入间隔也不小于原正常输入节奏5000ms。
4. **T3 故障与回退矩阵**：补充真实网络层50/200/1000ms RTT、1%/5%丢包、10/60秒黑洞与单向故障；凭据撤销/身份更换/版本不匹配；安装包切换及支持的升级/回退。网络代理503/丢应用帧不冒充网络层丢包。真实休眠唤醒与平台/渠道缺口单列，未覆盖不记通过。
5. **T4 阶段核对**：汇总正确性与恢复结果、清理证据、仍未完成矩阵；可继续开发后续功能，但新本机能力开放前须完成独立desktop凭据、逐项本机授权、撤销和对应正确性验证，不借用owner凭据或继承旧批准。

## 不变的正确性门槛

- 输入不得自动重发；未知输入必须保留可核实状态。每个合成输入恰好一次POST，重连、重启、连接循环均不能产生额外POST。
- 连接A/B与epoch隔离，旧响应不得写入新连接。取消/关闭核实Shell本地资源释放，清理未确认不得当作成功切换。
- 远端仍不产生本地Gateway、工作区或会话数据库，不可通过管理路由/完整preload使用本机能力；设备列表保持为空。
- 继承原连接/恢复时限：连接尝试不超过15秒，半开45秒内发现，恢复后30秒内重建或给确定错误，正常清理15秒内完成。故障下允许请求失败，不允许违反隔离、授权和防重复副作用。
- 资源数据持续记录，性能结论待专项；OOM、失控重试、越界缓冲或进程失去监督属于正确性问题，仍立即判失败。
- 24小时只按真实单调时间计，不改时钟、缩短等待或用多个短任务相加替代。后续开发与长测可并行，但长测结果只归属实际被测包；不能算作后续新Host/写能力的持续运行验收。

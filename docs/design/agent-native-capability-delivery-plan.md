# xopc Agent 原生能力架构：分阶段实施与验收

日期：2026-09-21。状态：实施中；具体覆盖与验证记录见[实施账册](./agent-native-capability-progress.md)。架构依据：[最终技术方案](./agent-native-capability-architecture.md)。

“一次性做好”指先固定最终边界，再完成下述连续阶段：不交付临时 PoC、不重复建立中间平台；每阶段有可合并、可验证的产物。本文不是对当前所有运行时能力的完成声明。

## 1. 顺序与发布规则

依赖：S0 → S1 → S2 → S3 → S4 → S5 → S6。S4 的纯上下文协议可在 S2 后开发，但发布须通过 S3 的领域一致性验收。阶段顺序不等于多个新 Runtime，所有阶段共享最终协议。

每阶段保存：变更清单、实际测试命令／结果、行为前后对比、迁移状态、剩余限制。阶段完成前不把后续设计显示为已支持。实现期间遇到当前 Slack 场景开发变更，按最新领域接口接入，保留用户工作树修改。

## 2. S0：冻结契约与迁移账册

交付：

- 枚举 xopc_use 全部 mode/command、对应 HTTP／CLI／Automation／扩展入口及领域服务。
- 对 Notes、Tasks、Projects、Automations、Scenes、TaskRuns、LocalApps、Settings 的操作逐项记录最终 capability ID、读写性质、资源权限、审批、幂等和恢复模式。
- 识别已有 domain_outbox、审批记录、connector receipts 和 endpoint invocation 的责任边界，确定增量字段而不是复制实现。
- 冻结 Zod JSON 子集、结果状态、错误码、版本规则、operation 身份和 SDK 接口。

验收：迁移账册每行都有现有代码位置和目标归属；所有写操作都有恢复模式；多入口映射无缺项。不得用目录数量代替行为覆盖率。

## 3. S1：能力注册与单一执行边界

交付：gateway-contract 公共协议、registry、dispatcher、身份／资源策略适配器、HTTP 和 Agent adapter、typed Web client 生成。

先迁移 Notes 和 Tasks 的读取，直接使用最终 ID、Schema 和调用链。保留原路由和 xopc_use 外形，移除这部分重复校验和业务分支。目录只显示可发现能力，不自动授权调用。

必要验证：

- 同输入通过 HTTP、Agent、直接 dispatcher 得到相同业务结果；非法输入和版本冲突一致。
- 无权限／跨资源读取、伪造主体、伪造 surface、设备低权限、Agent 委托收窄均被拒绝。
- 生成的 Agent JSON Schema 与服务端校验在必填、default、union、additionalProperties 等边界一致。
- 真 Gateway 携带凭证验证新路径、旧路径和 lazy-bundles 正负匹配。

退出条件：上述读取行为进入生产路径，adapter 不重复执行业务逻辑；写操作仍保持原路径直至 S2 完整闭环。

## 4. S2：写入、审批和恢复

交付：operation／invocation SQLite 迁移、幂等和租约、审批适配、恢复器；迁移 Notes create/update 和 Task create/command，复用原领域事务及幂等键。外部 connector/endpoint 的统一恢复适配至少覆盖一个真实支持幂等或回执查询的写能力。

自动故障注入矩阵：

| 故障点 | 必须观察到的行为 |
| --- | --- |
| 同 key 并发请求 | 一个业务操作，多次调用得到同一结果／pending |
| 同 key 改参数或账号 | conflict，不执行 |
| 相同参数但新的明确意图 | 新操作合法执行，不误去重 |
| SQLite commit 前进程退出 | 事务回滚，原 key 可恢复 |
| commit 后响应前退出 | 返回已存结果，业务对象及 outbox 各一份 |
| 外部成功但本地回执未写 | unknown，查询／原 provider key 恢复，无盲目重发 |
| 不支持查询和幂等的外部超时 | 保持 unknown，需要核实 |
| 租约过期后旧执行者返回 | fencing 拒绝旧本地提交；不把外部未决视为未执行 |
| 等待审批时改参数／撤权／换版本 | 原审批失效，无副作用 |
| 成功后结果 Schema 错误 | 保存副作用证据，恢复结果，不重做写操作 |
| 执行中取消 | 区分请求取消、已停止和结果未知 |

测试使用确定性 provider fixture 验证崩溃窗口，并在受控测试账号验证一次真实 adapter 协议；真实外部写仅使用已明确授权的测试对象。缺凭证时记录该发布门禁未通过，不能用 mock 冒充端到端成功。

退出条件：本地事务和外部未知结果均可解释；双重 retry 已消除；审批沿用原用户入口且绑定精确 operation。

## 5. S3：核心领域归一与实时同步

交付：依 S0 账册迁移剩余 Notes／Tasks、Projects、Automations、Scenes、TaskRuns、LocalApps 管理和 Settings 安全导航能力；对应 UI／HTTP／xopc_use／CLI／自动化入口全部经过 dispatcher。底层通用文件、shell、电脑工具继续保留自身执行器，明确标注恢复能力。

domain_outbox 与 operation 关联，规范化资源变更，接入 WebSocket 和 SWR 标签失效。Task／Scene 的状态和 outbox 继续由领域服务生成，移除适配层重复发事件。

验收：

- 每个迁移写能力至少覆盖“UI 发起”和“Agent 发起”的持久结果一致性。
- Agent 创建／修改对象后，已打开页面无需手动刷新即可反映；事件重复／乱序不导致状态倒退。
- 断线后恢复可重新获取正确状态；撤权后事件与结果不可继续泄露。
- 现有移动端／渠道深链、旧 REST DTO、自动化运行、Task lifecycle 和 Slack 场景授权范围回归通过。
- 迁移账册无遗漏的已纳入业务操作，旧分支只有兼容转发而无第二份业务逻辑。

退出条件：每个领域有唯一业务执行路径，兼容层有明确用途和删除条件。

## 6. S4：页面上下文与结构化结果

交付：AppContext provider、客户端/tab 隔离、输入时不可变快照、资源解析、受控导航；在 Notes、Tasks、Projects、Discussions、Scenes、Local Apps 接入。新增 task／approval／table／diff renderer，复用 ProductDeliveryEnvelope。

验收场景：

- 在笔记页面说“总结这个”，读取当前笔记，结果可追溯原 revision。
- 选中内容说“根据这段创建任务”，创建的 Task 关联来源，页面实时出现。
- 提交后切换到另一笔记，本轮仍引用提交时对象。
- 同用户两个 tab／设备同时使用，各自不串上下文；后台自动化不拾取前台选区。
- 原对象已更新／删除／撤权时正确冲突或拒绝；恶意选区文本不能授予权限。
- 卡片按钮与正常业务页面调用同一能力；旧卡版本冲突不会覆盖新内容。
- 重放／刷新 transcript 不重复卡片，无 renderer 的渠道收到文本与深链。
- 导航重试只消费一次；用户已切页时提供链接，不强制抢焦点。

退出条件：上述产品路径可在运行中的 Gateway 浏览器验证，静态单测不足以替代体验验收。

## 7. S5：Local App 能力包与 MCP

交付：扩展 capability contributions、SDK bridge、权限增量、release digest、能力验收；实现显式 capability MCP 接入，保留现有 channel bridge。

选一个使用现有 Notes／Tasks 能力的 Local App 作为完整交付样例。安装、UI 调用、Agent 调用、撤权、升级、回滚均使用生产机制；不编写绕过 registry 的示例后门。

验收：

- manifest 未声明、未授权或版本不符的能力不可发现／不可调用。
- iframe 伪造其他 extensionId、principal 或审批信息失败。
- UI 和 Agent 操作同一对象得到一致状态；一端禁用后另一端不绕过。
- 修改能力绑定或 UI 源码后，旧验收记录不能用于新 release。
- 回滚不破坏业务数据，在途调用不切换实现版本。
- MCP 外部客户端能发现和调用授权目录；无认证、越 scope、撤权、过期审批和未知结果均正确处理。
- Agent 生成 Local App 不包含在 Gateway 直接执行的任意后端 JS。

退出条件：Local App 具备 UI＋能力＋上下文＋验收的完整发布闭环，MCP 能力目录与授权严格一致。

## 8. S6：收口与正式发布

交付：迁移账册最终状态、集成文档、SDK 示例、运行诊断、性能基线、数据备份／升级／回退演练。清理无调用的旧实现，保留仍需兼容的入口，不要求用户为了内部改造迁移会话。

发布门禁：

1. 完整执行 S2 故障矩阵，未决副作用不会在重启时重发。
2. S3 的所有领域操作通过跨入口契约测试及现有相关测试。
3. 新增 Gateway 路由通过真实认证路径和 lazy matcher 验证。
4. S4 页面上下文与结果卡通过浏览器验收。
5. S5 Local App／MCP 完整闭环通过；真实外部测试未执行时对应能力不宣称正式可用。
6. 相关 package typecheck、Web build 和根构建按项目脚本通过；检查差异确保不覆盖并行工作。
7. 升级保留原会话／Task／Scene／数据，回退对未决新操作有明确兼容阻断。
8. 输出耗时、目录规模、事件延迟和恢复统计的实测报告，禁止以主观“更快／更稳定”替代证据。

## 9. 价值验收

| 价值 | 验证方式 |
| --- | --- |
| 降低开发成本 | 新增一个 Notes／Tasks 同类操作，仅声明能力和领域逻辑即可接通已支持入口；记录实际改动点与原模式比较 |
| 能力一致 | 纳入账册的操作跨入口 Schema、权限、审批和结果完全一致 |
| 用户上下文准确 | 所有指定 tab／切页／版本冲突用例通过，能说明每次指代的来源 |
| 防止重复副作用 | 确定性故障注入无重复提交；无幂等保证的系统明确保持 unknown |
| 扩展可交付 | 示例 Local App 无新增宿主业务分支完成安装、双入口使用、升级和回滚 |

不预先承诺百分比效率收益或固定工期。S0 的操作数与外部恢复能力核清后估算投入；最终范围与完成标准由本文固定，阶段用于组织交付而非缩减为临时演示。

## 11. 独立待授权验收

真实第三方写入验收单独保留：测试平台、测试账号和允许创建／修改／删除的测试对象须由用户明确授权，不索取聊天中的密钥。未执行前只能报告本地 fixture、协议和故障注入结果，不能宣称真实 provider 验收完成。该项不阻塞其余本地开发、自我 review、模拟验证、浏览器测试和升级／回退演练；不得把尚未实现的本地阶段归因于缺少此项授权。

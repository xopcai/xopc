# 鸿蒙任务详情交互排查

日期：2026-10-12。范围：原生鸿蒙 App 的任务详情、编辑和状态请求。

结论：原有目标、验收、结果、关联工作分区有价值，但任务管理入口不完整，导致详情页更像只读报告。状态调整需要与 Agent 执行分开，同时让不可执行操作有原因和下一步。

## 发现与处理

| 问题 | 用户影响 | 本次调整 |
| --- | --- | --- |
| 状态标签只读，客户端未支持服务端 `move` 命令 | 无法将任务调整为待规划、就绪、进行中或待验收 | 标签和固定底部“调整状态”打开状态面板，按 `allowedCommands` 决定是否允许切换 |
| `start` 与“进行中”容易混为一谈 | 用户只想改阶段，却可能启动 Agent | 阶段切换明确说明不会启动 Agent；开始执行单独选择 Agent 并确认 |
| 次要操作过滤掉 `close`，主操作又受验收条件限制 | 完成入口消失，用户不知道限制来自哪里 | 状态面板保留完成入口，未满足条件时禁用并解释：缺少标准、验收未通过或还有执行/等待事项 |
| 仅支持 `close(done)` | 无法结束不再需要的任务 | 新增确认后取消任务，使用 `close(cancelled)`；已结束任务可重新打开 |
| 编辑仅有标题、说明和项目 ID | 无法调整优先级和日期，关联项目依赖记忆 ID | 增加优先级、日期选择和按名称搜索项目；可移除项目或日期 |
| 清空项目后序列化省略字段 | 服务端保留原项目，看似保存却未修改 | 清空项目和日期明确发送 `null` |
| 编辑返回离开详情；操作后清空详情重新加载 | 用户失去上下文，失败后缺少恢复入口 | 取消编辑回到原详情；刷新保留详情，失败保留编辑草稿，提供手动刷新 |
| 待处理事项位于较长验收内容之后，详情页缺少明确返回和编辑标题 | 需要用户处理的事项容易被埋没 | 提前展示待处理事项，增加返回入口和任务详情/编辑任务标题 |
| 进展页将 `task_review` 当成写操作，确认后触发 `INVALID_HOME_ACTION`；错误位于长列表底部 | 点击“查看结果并验收”后确认无可见效果 | 补齐动作中的 `taskId`，直接打开对应任务详情，无须确认或写请求；操作错误移到页面顶部，未知动作在确认前拒绝 |

## 页面职责

- **概览**：任务标题、阶段、项目、优先级、截止日期；状态标签可操作。
- **待处理事项**：提前呈现用户需要关注的阻塞或问题。
- **目标与验收、执行结果、产出、关联工作**：保留阅读上下文；执行状态独立于任务阶段展示。
- **固定底部操作区**：调整状态、编辑、任务对话，以及当前阶段的主要动作。
- **状态面板**：阶段切换、明确启动 Agent、完成条件、取消任务；已结束任务选择阶段重新打开。
- **编辑页**：标题、说明、项目、优先级、截止日期，统一保存。日期选择后使用手机本地时区当天结束时间；原有时间未修改时保留。

## 约束与后续缺口

任务修改继续使用 `expectedVersion`，命令继续使用幂等键；冲突不会自动覆盖服务端状态。完成条件对齐服务端规则，包括当前版本验收、根运行和等待事项。

人工验收接口 `/api/tasks/:id/criteria/:index/review` 限定 owner/trusted-proxy 身份，手机设备身份目前无法直接调用。页面说明桌面端验收路径；如需手机完整验收，应单独设计设备授权与审计，再接入该流程。

本次未新增结构化暂停/恢复、等待事项表单、验收标准编辑或产出文件预览。现有任务对话入口继续作为补充上下文入口。项目选择沿用现有最多 100 条项目的列表接口，大项目集仍需服务端搜索和分页。

## 验证

已通过鸿蒙主机完整测试集（新增自动化共享刷新回归前为 112 个文件、721 项测试），以及新增回归的针对性测试与 Debug HAP 编译。覆盖状态命令与契约校验、完成限制、明确清空字段、冲突保留草稿、刷新保留详情，以及共享页面的自动化运行记录刷新。

尚未安装到真机或模拟器进行点击验收；底部安全区、键盘、状态面板滚动和确认弹窗需在设备上继续验证。

进展页回归使用服务端 `HomeActionSchema` 校验过的 `task_review` 动作，验证解析后保留目标任务 ID、只触发任务详情导航、不弹确认且不发写请求。另覆盖缺少目标、普通链接、未知动作、取消确认和写操作失败。

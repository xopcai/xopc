## 3. 建议灰度节奏

先做受邀内部测试，再根据分发渠道实际支持的方式逐步扩大。下列百分比和观察期是项目建议，非平台功能承诺：

1. 内部 3–5 台设备，至少观察 48 小时，核心路径逐条签收。
2. 首批约 5% 受邀用户，观察至少 48 小时；零新增 P0/P1 后扩大至约 20%。
3. 20% 观察至少 72 小时；再做全量决定。样本量不足时延长，不仅依据百分比。

监控建议：配对/刷新成功率、HTTP 错误与延迟、WS 重连/缺口、消息重复/丢失、任务操作失败、崩溃/冻屏、录音/STT 失败、推送接受/点击。指标采集与看板尚需实际部署，当前不是已具备的自动灰度系统。日志仅含匿名操作 ID、错误码、耗时；不上传凭据、消息正文、音频或个人文件。

暂停条件：任何数据丢失/安全问题；可复现的核心阻断；指标显著劣于内部基线。暂停扩量、记录受影响版本，修复并重跑矩阵。

## 4. 发布前材料与操作

- 确认应用名称、图标、介绍、截图、支持范围、版本说明、隐私说明/权限用途、支持渠道。
- 在真实签名 Release 包上重跑安装、升级、权限、配对和通知验证；开发签名/未签名 HAP 不能冒充商店包。
- 发布前再次核对当时 AGC 的审核/分发要求和账号权限。
- 由应用所有者确认发布版本与渠道后再提交。本任务不自动授权公开商店发布。

## 5. 停止与回退

- 保持旧 iOS/Android/Expo 的协议和推送渠道兼容。新增 HarmonyOS Provider 不能将华为 token 发到 Expo。
- 推送出问题可先在客户端关闭通知并撤销对应 Gateway 注册；保留无推送的核心工作路径。
- 客户端回退按平台允许的版本升级策略分发修复版本，不假设可直接降级安装。
- Gateway schema 179 扩展平台约束并保留外键引用。升级前按运维流程制作一致性备份；**不**在已有新数据的数据库上直接运行逆向表重建或回装旧 schema。恢复备份会丢失备份后的写入，必须单独确认。
- 灰度期间固定可追踪版本，保留签名包、测试证据及回退决策记录，不记录服务账号私钥。

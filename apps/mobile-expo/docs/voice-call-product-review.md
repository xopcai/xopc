# 移动端语音通话产品与故障分析

分析日期：2026-09-08。用户反馈平台：Android／鸿蒙，已安装最新 APK，无声时能看到自己的转写与 AI 回复文字。网关为 `https://xl.xopc.ai`。切换“系统音频／扬声器”无效，但同一设备切换到“原生语音”正常，只有“当前助手”无声。基于当前源码、已读取的远程权限日志与本次自动化回归；未连接用户真机，尚未复现其实际无声现象。

## 当前产品形态

语音通话绑定一个已有 Chat，沿用该会话的 Agent、历史和工具能力。入口在 Chat 顶部，通话进行中可收起为全局浮条。前台默认持续采集；后台通话需要提前开启。挂断结束连接，暂停后继续会重新建连并核对会话身份。

| 模式 | 实际链路 | 产品特点 |
| --- | --- | --- |
| 原生语音（Omni） | 麦克风 → 网关 → 实时语音模型 → PCM 播放 | 适合自然交谈；有历史上下文，但不执行 Agent 工具 |
| 当前助手（Agent） | 麦克风 → 流式转写 → 句末等待 → 普通 Agent turn → 文本分句 → 流式 TTS → PCM 播放 | 能做任务、调用工具和请求确认；每一层都可能增加等待 |
| 语音输入 | 录音或转写 → 可编辑草稿 | 不等同于通话，不会自动发送草稿 |
| 试听声音 | 网关 TTS → 完整 PCM 转 WAV → expo-audio 播放 | 验证音色与合成服务；未覆盖通话的原生双工播放器、通信路由或通话音量 |

关键源码：[`ChatScreen.tsx`](../src/features/chat/ChatScreen.tsx)、[`voice-call-controller.ts`](../src/features/voice/voice-call-controller.ts)、[`agentEngine.ts`](../../../src/voice/realtime/agentEngine.ts)、[`voice-preview.ts`](../src/features/voice/voice-preview.ts)。

Agent 模式已经有单次 turn 的语音表达提示，要求简短口语、先说明工作再调用工具。但它仍是逐轮执行：服务端等待句末、执行 Agent、按语句串行发起 TTS，不是一个统一模型直接完成端到端语音交互。`ConversationTurn` 至少保留 350 ms 的转写收尾窗口；结合 STT 已等待的静音时间，以约 1.2 秒作为普通停顿目标，未说完的句式还会延长等待。上述时间不包含模型、工具、TTS 和网络延迟。

## 问题一：Android／鸿蒙没有声音

### 当前可以确定的事实

- 审批查询失败只显示提示，不会触发播放器停止；只有实际待审批记录才会通过 `setApprovalPending` 暂停麦克风输入。
- 通话通过自定义 `XopcVoice` 模块播放 24 kHz 单声道 PCM16。Android 使用 `AudioTrack` 的 `USAGE_VOICE_COMMUNICATION`，音量键绑定的是通话音量。
- 当前源码默认在没有外接输出时选择扬声器，连接耳机时交给系统选择。界面“系统音频”表示自动选择策略，并不是实际输出设备的名称。
- 当前源码已包含短音频起播阈值修复、非阻塞写队列和输出路由修复。原先短回复写入成功但播放进度为零的现象，在仓库已有模拟器回归记录中得到复现和修复。
- 用户已确认安装最新 APK，因此不再把旧安装包作为当前无声问题的主要解释。
- 同一设备“原生语音”可听，“当前助手”无声；二者复用手机端 `XopcVoice` 播放器。这使通用播放器／扬声器故障的可能性降低，优先检查 Agent 的分句、独立流式 TTS、下行音频与自动打断。
- 远程语音设置页面显示使用 XOPC 托管服务。但尚未取得故障响应对应的 TTS 详细错误，不能据此断言是鉴权、模型配置、空流或打断中的某一项。

历史原生验证记录见 [`voice-native-probe.md`](../scripts/voice-native-probe.md)。这些是先前的验证记录，不是本次重新运行的真机测试。

### 仍需区分的故障位置

用户已确认能看到自己的转写与 AI 回复，说明本次通话的识别与文本生成链路已经工作。结合原生语音正常的对照，排查重点进一步缩小到 Agent 独有的 TTS 是否产出音频、手机是否收到音频，以及是否在播放前被打断。字幕并不包含上述环节的成功证据；审批查询 403 也不能解释播放无声。

| 观测结果 | 优先检查 |
| --- | --- |
| 连用户转写都没有 | 麦克风权限、原生采集、上行网络、STT |
| 有转写，没有 AI 回复文字 | Agent 启动、模型或工具执行、打断与错误事件 |
| 有 AI 文字，未收到音频 | 文本分句是否尚未输出、TTS 是否返回空流或失败 |
| 收到音频，原生播放字节一直不前进 | AudioTrack 起播、写队列、原生构建版本 |
| 播放字节前进但耳朵听不到 | 真机通信设备路由、通话音量、蓝牙与厂商音频策略 |

播放进度只能证明播放器在消耗音频，不能证明物理扬声器可听。不能用模拟器的进度回执替代鸿蒙真机听感验收，也不能仅凭文字回复判断 TTS 已成功。

本次新增“复制声音诊断”：保留最近五次回复的响应 ID、文本字符数、收到／入队／播放字节、PCM 峰值、异常帧计数、结束与取消原因和错误码；不保留录音、转写原文或凭证。诊断可在挂断前复制，内存计数在下一次通话开始时重置。

本次增加了生成、等待播放和有原生播放进度的状态区分。收到音频后连续 5 秒没有新增播放进度，会暂停并给出播放故障提示；这比网关的 15 秒播放回执超时更早暴露问题。没有待播放字节时不会因为 Agent 工具执行时间较长而误判播放器卡住。纯文字回复、回复生成失败和播放器失败也有各自提示。

## 问题二：一直显示“无法获取或提交确认”

远程日志在 00:27–00:28 连续记录 `Hono:Scopes — Scope check failed: missing gateway.admin`，频率与三秒轮询一致。结合接口源码，确认是权限映射错误：

1. Agent 通话一连接，移动端就每 3 秒请求 `GET /api/connectors/approvals`。
2. 手机默认配对权限包含 `sessions.read`、`sessions.write`，不包含 `gateway.admin`。
3. 审批列表和提交接口没有显式权限映射，均落到默认的 `gateway.admin`，所以正常手机也会收到 HTTP 403。
4. 界面将查询失败与用户点击提交后的失败合用一条文案，因此即使没有工具审批，也会持续显示“无法获取或提交确认”。

本次修复：

- 只为审批列表 GET 和审批响应 POST 映射会话读写权限；其他 Connector 管理接口继续要求管理员权限。
- 普通设备读取必须限定 `local-owner` 的具体会话。提交必须携带会话键，并匹配审批记录的会话和主体。
- 客户端提交携带 `sessionKey`；查询权限失败、查询不可用、提交失败分别提示。
- 403／404 停止自动轮询，提供手动刷新；错误仅显示在有效的 Agent 通话中，新通话清除旧的提交错误。

网关测试使用默认手机 scopes 并经过真实权限中间件，覆盖查询、允许／拒绝，以及无会话、错会话、错主体和只读设备的拒绝路径。

## 尚未完成的产品闭环

### 确认完成不等于任务自动继续

Connector 返回 `confirmation_required` 后，工具调用会返回结果，Agent 可以结束本轮。审批接口只更新决定；移动端成功后只刷新审批列表、恢复输入，不会自动启动新的 Agent turn。

因此用户点击“允许执行”后可能还需要说“继续”。当前“允许执行”文案容易被理解为点击即已执行。后续应把审批与原任务的继续机制关联起来，明确展示“已允许，等待继续”与“正在执行”；重放必须使用原 `approvalId` 和未改变的参数，并防止重复执行。本次只修复审批访问，没有新增自动执行行为。

参考：[`composio-provider.ts`](../../../src/agent/external-tools/composio-provider.ts)、[`connectors.ts`](../../../src/gateway/hono/routes/connectors.ts)。

### 通话中的控制意图还不够明确

- “停止回复”会取消当前响应及其 Agent signal，已经完成的工具动作不会撤销。应让用户能分清“停止播报”与“停止任务”。
- 自动打断依赖 STT 的 speech-start／final 事件。回声或背景语音误触发时，可能在回复真正播出前就取消响应；真机需验证回声消除及打断记录。
- 原界面忽略语音开始、结束和实时转写 delta，只显示最终转写；用户难以判断是否正在被听见。
- 原生系统输出策略没有回传实际设备名，用户无法直接确认是手机扬声器、听筒还是耳机在播放。
- 审批依赖轮询，存在最长约 3 秒的发现延迟；等待确认时麦克风被关停，应明确说明需要点击操作。

### 后续优先顺序

1. 优先取得 `xl.xopc.ai` 中失败响应的 `Voice:Agent`／TTS 日志，与手机诊断的 responseId、取消原因和音频计数对齐。已有原生语音正常的对照，不再把切换扬声器作为主要排查步骤。
2. 建立通话内的声音诊断，复用真实 `XopcVoice` 播放路径，展示实际输出设备。保留当前试听作为音色预览。
3. 补齐审批后的任务继续，以及听见、转写、思考、工具执行、播报、等待确认的状态交互。
4. 再优化 Agent 首句延迟、跨句 TTS 衔接和自动打断策略。若“生硬”指的是停顿或韵律，这一层才是主要优化方向。

## 发布与验收范围

本次修改位于网关权限／审批校验和移动端 TypeScript，不涉及新 Kotlin／Swift 修改。需要更新网关，并发布包含本次客户端修改的 App。用户当前安装的是最新已发布 APK，本次本地修改尚未包含在该版本，也未部署到远程网关。

本次自动化检查验证权限行为、审批查询、播放状态与超时、取消和恢复等逻辑。用户已确认安装最新 APK；物理设备音量、听感、回声消除和当前失败通话的音频收发记录，仍未得到验证。

验证结果：网关权限／审批路由 15 项测试通过，移动端语音与审批查询 91 项测试通过；根项目 typecheck、移动端 typecheck（含 agent-stream-client）和移动端 lint 均通过。

远程排查限制：浏览器曾成功读取权限错误与语音服务设置，随后日志页面刷新后持续空白，且出现过计算机读取错误；重连和刷新未恢复。未取得对应 TTS 错误，因此无声根因仍未闭环，不能把新增诊断和错误提示表述为已恢复声音。

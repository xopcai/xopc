# 技术方案：移动端关于你与用户理解

> Plan ID: `mobile-user-understanding`
> 状态: confirmed
> 涉及平台: Gateway、HarmonyOS、Android、iOS

## 一、背景与边界

用户理解会影响 Agent 的回答与执行，移动端目前只读取姓名和角色，无法审阅或纠正。新增“我的 → 关于你”，提供轻量概览、分页理解列表、依据详情、修改和删除；工作记忆仍归资料库，来源连接和模型驱动刷新仍留在桌面端。

成功标准：三端入口与信息层级一致；默认移动设备可按读写权限访问；列表不下载完整用户模型；刷新只重新读取数据，不触发模型调用；修改和删除有明确反馈与确认。

## 二、现状

- WebUI 的“你”包含画像、共同理解和工作记忆，桌面布局信息密度较高。
- HarmonyOS `PersonalView` 与 Expo `PersonalScreen` 只消费 `/api/user-model` 的资料摘要。
- `/api/user-model` 默认回退到 `gateway.admin`，而默认移动设备没有该权限。
- 完整响应最多包含 1000 条理解和 1000 条工作记忆，不适合作为移动端资料卡接口。

## 三、整体设计

### v1.1 信息架构调整（2026-09-29）

- “我的”不再承载连接、通知、分享等低频系统管理入口，首屏改为直接呈现个人资料、当前重点、理解统计、最近理解和协作方式。
- 连接、通知、分享记录、语言、外观和版本信息统一收敛到“设置”，按“连接与通知 / 数据与共享 / 偏好 / 关于”分组。
- “我的”保留右上角设置入口，并提供进入完整“关于你”管理页和具体理解详情的深链。
- 调整只复用现有移动摘要接口，不增加自动模型调用，也不扩大数据读取范围。

### v1.2 近期目标（2026-09-29）

- “我的”首屏信息顺序调整为“个人资料 → 近期目标 → 用户理解”。目标是 Loop 后续持续规划和跟进的明确输入，视觉优先级高于一般理解。
- 近期目标展示最多 5 条未结束目标，当前重点优先，其余按状态、截止时间和更新时间排序。每条展示标题、期望结果、状态与可选截止日期。
- 用户可以直接新增、编辑、暂停、恢复或完成目标。标题和期望结果必填，截止日期可选；保存后立即刷新“我的”和“关于你”。
- 目标编辑为结构化表单，直接调用 Goal API，不使用模型；自然语言修改仍走已有对话入口。
- 已完成和已放弃目标不占据“近期目标”首屏，但保留在底层 Goal 历史中，供执行上下文和后续目标管理页使用。

### v1.3 理解列表工具布局（2026-09-29）

- 搜索入口收进理解页 Header，默认以图标呈现，点击后在 Header 内展开；返回操作优先退出搜索，再退出页面。
- “通过对话修改”作为持续可达的主要操作固定在页面底部，不随理解列表滚动，也不再占用首屏内容空间。
- 分类筛选保留在列表顶部，形成“Header 搜索 → 内容筛选 → 底部对话修改”的清晰操作层级。

```text
我的
  ├─ 个人资料
  ├─ 近期目标（一级信息）
  │   ├─ 新增目标 → POST /api/user-model/goals
  │   └─ 编辑/状态 → PATCH /api/user-model/goals/:id
  └─ 用户理解
```

```text
我的个人卡片
  -> GET /api/user-model/mobile-summary
  -> 关于你概览
      -> GET /api/user-model/assertions?view=mobile&cursor&limit
      -> 理解详情（依据、范围、时间）
          -> PATCH /api/user-model/assertions/:id
          -> DELETE /api/user-model/assertions/:id
      -> PATCH /api/user-model/profile
      -> 资料库（工作记忆深链）
```

### API 契约

- `GET /api/user-model/mobile-summary`：资料、显式/学习/待处理计数、当前关注、最近理解、协作规则、工作记忆数量。
- `GET /api/user-model/assertions?view=mobile&filter=all|explicit|learned|review&cursor=<recordedAt:id>&limit=20`：仅返回全局、非资料字段理解，稳定排序并分页。
- 用户模型 GET 使用 `workspace.read`，PATCH/POST/DELETE 使用 `workspace.write`；不授予 `gateway.admin`。
- DTO 与 Zod schema 放在 `@xopcai/gateway-contract`，HarmonyOS 维护等价 ArkTS 模型并做运行时边界校验。

### 移动端信息架构

- “我的”个人卡片整卡可点击，并展示理解数量与待处理提示。
- “关于你”二级页使用“概览 / 理解”两段式结构。
- 概览：基本资料、当前关注、两类理解计数、待处理、最近理解、协作规则、工作记忆跳转。
- 理解列表：筛选、按语义类别分组、点击查看依据；修改使用编辑面板，删除二次确认。
- 二级页不显示快捷 Chat Input，避免编辑键盘冲突；不提供触发模型生成的刷新。

## 四、子任务与依赖

1. Gateway contract 与权限映射 → 轻量接口和分页测试。
2. Expo 共享 Android/iOS 页面、查询层、路由、文案和测试。
3. HarmonyOS 模型、ViewModel、页面、导航、资源和测试。
4. 构建、三端 UI/日志验证；真机可用时执行 HarmonyOS 覆盖安装验证。

依赖链：`contract -> gateway routes -> Expo/Harmony clients -> build -> verify`。

## 五、切流、监控与应急

- 入口仅在接口成功时展示数量，接口异常时保留个人卡片和重试，不影响聊天。
- 关注 403、分页解析失败、修改/删除失败率；日志不得包含理解正文。
- 回滚可隐藏移动入口并保留向后兼容接口；不迁移或删除用户数据。
